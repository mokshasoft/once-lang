## 2. ⬜ THE OPEN ROW — and it is a design question, not a bug

`Knot/Judge/IwfKappa` (the object-level `iwf-κ` rule) fails. The kernel says

    iwf-κ : … (κ : RTm Δ) → ICodeWf κ → Θ ⊢ renTm (thinR ρ) κ ∷ U → …

`ICodeWf` is the ONLY judgement indexed by a SCOPE (`Cx`), and the merged
judgement family gives every judgement a `Ctx` slot. Until now the generator
handed `ICodeWf` the telescope `Θ` — a "deliberate strengthening" that was
harmless while `κ` lived in `⌊Θ⌋`. Under A-math `κ` lives in `Δ`, one
variable shorter, and there is no `Ctx` for `Δ`. The row states `ICodeWf`
at the wrong depth → a real type error.

Options, as I see them:

- **(C) Delete `ICodeWf` — the RECORDED decision of 2026-09-11** (`FUTURE.md`
  "AND THEN IT INVERTED — THE CHANGE IS A *REMOVAL*"; `HANDOFF-2026-09-13`
  item 1), never executed. The κ field's member carries its own `⊩₀`
  (existential in `ILift`; `⊩₀` is in `Set`; positivity spiked green).
  Deletes `IKPred`/`IDPred`/`IKInterp`/`IDInterp`/`iκW`/`interpIK` and the
  whole object-level `ICodeWf` family — the Knot gets SMALLER, and the
  scope question disappears instead of being encoded. One unverified link
  recorded there: a `Π-dom` lemma for `iliftPay`'s caller.
- (A) Give the object row an existential `Ctx`-of-depth-`Δ` witness for
  `ICodeWf` (the object judgement is uniform in its context). Works, but
  adds a binder the kernel rule does not have — not 1:1.
- (D) Restate the kernel premise as `ICodeWf (renTm (thinR ρ) κ)`. Rejected:
  `ICodeWf` is about the constructor's code in ITS scope.

⛔ **(C) IS REFUTED** (checked the same night, before any refactor): the
existential `ILift` clause is NOT strictly positive once `⊩₀` has its real
`Π` clause — `bootstrap/tmp/ExistLiftPi.agda` rejected, control accepted.
The 09-11 spike omitted `⊩₀Π`. Recorded in `FUTURE.md`. The spike branch
`ocp-0009-icodewf-removal` holds nothing beyond this handoff.

Remaining options:

- **(E) Reify a Cx-indexed judgement at a DEPTH with the CANONICAL context**
  of that depth (`ctxAtK d`, an object program: `d` copies of `Nat`). The
  object `ICodeWf` rows bind a depth instead of a `Ctx`, and the `iwf-κ` row
  cites `ICodeWf` at `dΔ`. Faithful because the object family is UNIFORM in
  its context (nothing in the three rows reads it); it replaces the old
  "hand it whatever `Θ` is in scope" strengthening with a determined one.
  Kernel unchanged.
- (G) Restate the kernel premise at the telescope's scope,
  `ICodeWf (renTm (thinR ρ) κ)`, and derive `ICodeWf`'s model key back at
  `Δ` through a SECTION of the thinning (`σ' ∘ thinR ρ = σ`). `ICodeWf` is
  renaming-invariant, so this is equivalent — but it states a syntactic
  class of the code at a scope that is not the code's own.
- (A) An existential `Ctx`-of-depth-`Δ` BINDER in the object row. Not 1:1.

**Recommendation: (E)** — kernel untouched, 1:1 up to a determined witness,
and it makes the reification rule for Cx-indexed judgements explicit
instead of incidental.
