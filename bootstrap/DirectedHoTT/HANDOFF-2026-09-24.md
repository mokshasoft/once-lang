## 2. The diagnosis (`KNOT-LESSONS` §10)

The Knot encodes **syntax and rules only** — no metatheory. So why is any
of it a proof?

```agda
data _⟶_  : {Γ : Cx} → RTm Γ → RTm Γ → Set where   -- Spec/Typing:238
agree : szsTm i ⌈ t ⌉  ⟶*  num (sz t)              -- Knot/SzAgree:5
```

★★★ **Reduction is a RELATION and there is no evaluator anywhere in the
20 583-line metatheory**, so adequacy is a *chain* that must be BUILT,
not an equation that is CHECKED. Measured: adequacy stated as `⟶*` **84
times**, as `≡` **3 times**; **14 702 hand-built steps against 209
`refl`s**.

⇒ Agda does not have this burden — not because it is more powerful, but
because its conversion checker **runs its functions** and this kernel has
nothing that runs.

## 3. ⛔ WHAT WAS REFUTED — and why each failed

★★★ **ONE CRITERION EXPLAINS ALL FOUR, and it is the session's most
transferable result:**

> **The axis-style "compute the relation" move works EXACTLY where the
> SUBJECT IS CONCRETE.**

Adequacy quantifies over abstract `t`, `i`. Every route below dies on an
abstract head; every route that succeeded had concrete subjects.

### 3.1 Adequacy as an equation on normal forms — ⛔
`nf lhs ≡ nf rhs` would let a complete normaliser do the work.
`tmp/GateEq.agda`: `refl` fails, stuck at `evF1 i .Σ.fst`.
`tmp/StuckWhy.agda` separates the causes — structure concrete/argument
abstract **reduces** (rc=0); a bare abstract term **sticks** (rc=42).
⇒ an evaluator is a STRUCTURAL RECURSION and cannot reduce a term whose
HEAD is abstract; 30 exhaustive clauses would not help, because a bound
variable of type `RTm Γ` matches **no constructor pattern**.
★ **And that is why the chain shape exists**: a chain never normalises the
abstract parts. It is the correct representation, not an accident.

### 3.2 `⟶*-at F p = subTm-monoˢ (single-mono p) F` — ⛔
The one-liner reads beautifully and **does not typecheck at a use site**:
`subTm (single t) (renTm vs u) != u` — a term-with-a-free-variable context
forces a weakening round-trip, which is §7's stuck `wk-single`.

### 3.3 One-hole context as a DATATYPE — ⛔ (typechecks, still loses)
`plug` computes structurally, so no `wk-single` (`tmp/CxtProbe`, rc=0).
But vocabulary goes 22 → **9** (the 8 context constructors are vocabulary
too), tokens go UP, and `plug _C_131 t = app t u (blocked on _C_131)` —
**Agda cannot invert `plug`**. Hand-converting a file would be a
REGRESSION in the metric that matters.

### 3.4 `cong!` — the macro ⚠ works, and still cannot be used here
Agda cannot infer the position, so **we wrote the unification ourselves**
— not as a function (every `dec*` sticks: `decVar vz a != nothing`) but as
a MACRO, at elaboration time where the goal's SYNTAX is concrete.
`Lib/CongMacro` is sound: `t1`/`t2` close three-deep, controls fail
correctly (`u != t`; `Γ ∙ != Γ`).
⛔ **But every Knot site fails**, even one: `blocked on _t_80, _ihs_55`.
The macro needs the goal DETERMINED when it elaborates, and **`SzAgree`
alone has 207 `_` placeholders against 79 congruences** — the Knot is
written in a `_`-heavy style whose inference happens AFTER macros run.
⇒ to use `cong!` you would have to write those terms out, costing more
than 22 → 1 saves.

### 3.5 `decTm` — ⛔ do NOT build it
I recommended it, then tested the premise: `decVar vz a != nothing`.
The whole `dec*` family sticks on abstract arguments. The 19 existing ones
work because they are applied to *structurally concrete* generator-built
terms. **~30 clauses that would not have paid.**

## 4. ⬜ YOURS — the one lever left

★ **The bidirectional type checker** (`SIMPLIFY-KNOT` §8.2). It is the
only untried route, and it attacks the problem from the other end:
instead of ABBREVIATING derivations, it REMOVES them.

The wf burden splits (measured over `RedWfA`+`RedWfB`+`TyRedWf`+`Wf`,
9 944 lines ≈ 19% of the Knot):

| | tokens | share |
| --- | --- | --- |
| de Bruijn lookup | 14 256 | 62% | ✅ **done this session** |
| `⊢var` wrapper | 3 101 | 13% | ✅ done |
| genuine typing constructors | 5 583 | **24%** | ⬜ needs the checker |

✅ **Its eligibility is already established**: the subjects are CONCRETE
generated rows, so a checker WOULD compute on them — unlike everything in
§3. And `wfCon`'s abstract `D` was probed and does **not** block
(`tmp/WfCompute`, q1/q2/q3): `D` is THREADED (`Θ ▹ IMu D I j`), never
scrutinised.

★★ **And it is not only about wf**: `KNOT-LESSONS` §8 shows
`gen-knot.py`'s `infer_sorts` IS type inference, approximated in Python.
Writing the checker once, in Agda, retires **both** the generator's
inference and the hand-built `⊢…` derivations.

⚠ It is the largest single piece identified anywhere in these notes —
plausibly larger than everything in §1 combined. **Do not start it on a
stub's evidence.**

## 5. ⚠ PROCESS — five self-inflicted failures, all recorded in code

These cost real time and every one is a repeat-risk.

1. **A generator crash TRUNCATED `SzAgree.agda` by 383 lines.** A
   generator that writes as it goes turns any exception into DATA LOSS.
   ⇒ **test the transform standalone, against invariants, BEFORE the
   generator writes.** Now in `gen-knot.py`'s own comments.
2. **A converter matched ZERO of 962 towers and reported success.** The
   real shape is `there here` innermost, not `there (here)`. Only a
   before/after count caught it.
3. **"Is this file generated?" got answered wrong TWICE** — the header
   test (`grep GENERATED`) and a literal write-site regex, which cannot
   see `write_judgement`'s COMPUTED `J.mod + "Wf.agda"`. The sweep
   REFUSED (and exits 0). ⇒ **ground truth is: run the generator and
   diff**, which is what `sweep.sh` already does.
4. **`rc=143` on three modules was NOT the change.** All died inside
   `Knot/RenTm`, untouched; `RenTm` alone reproduced it. Regeneration
   invalidated interfaces, so a cold `check.sh` absorbed the whole
   closure. Reading 143 as "too expensive" would have abandoned a working
   migration.
5. **`pgrep`/`pkill -f` self-matched, four times** — three stalled
   watcher loops and one command that killed itself. ⇒ wait on the LOG
   MARKER, or `ps -C agda` (a process NAME cannot self-match).

⚠ A measurement that disagrees with a hand-read example is WRONG: the
factoring count was measured FOUR times (14 → 0 → 183 → 188) and
`row-lam` was right every time.
