## 1. ★★★ THE DEFECT, AND WHY NO TYPE COULD SEE IT

`Knot/Occ`'s header justified the constant rows as

> `Mu D` → `0`, because `Desc` is a closed sort with no variables

`Desc` is closed **with respect to `Γ`**. It is not variable-free —
`dκ : RTy ε → DCon → DCon` takes a closed type, and a closed type binds
its own variables:

```agda
leaky = Π Nat (El (var vz))                        -- : RTy ε
occTy vz (Mu (dκ leaky dι ◃ dnil)) ≡ false         -- refl
-- but occK answered 1: enVar {Γ ∙} vz = Var-vzK (num (len Γ)), len ε = 0,
-- so a description's own `vz` IS the level-0 node occVz matches.
```

⇒ `agree-ty`/`agree-tm` were **false as stated**. No proof closes that.

★★ **THE SIMPLIFICATION WAS THE DEFECT.** `Lib/IOccRed`'s header
advertised the missing filter as an advantage — *"every recursive field
counts, none of `ISzRed`'s `sameSortAt` cases exist"*. `Lib/ISzSort` kept
the filter and is sound; `IOcc` dropped it and became unfaithful. And
`IOcc`'s instantiation comment was HALF-RIGHT, which is why it was wrong:
*"an occurrence in a cross-sort child is still an occurrence"* is true,
but "not same-sort" is not "everything". `occ` needed a THIRD filter and
took the nearest existing one.

⚠ **The row typechecked green and `check-formers.sh` passed.** The defect
was in what the program COMPUTES, which no type here mentions. **The
adequacy lemma is what caught it** — the faithfulness gap doing its job.

## 2. ★★ THE FIX IS ONE CLAUSE, AND THE REDESIGN WAS NOT NEEDED

The proposed design fix was `FUTURE.md` D′ — *index by the SCOPE rather
than its LENGTH* — a rewrite of `Knot/Map` and every `⊢…K` signature.
**A spike tested the cheaper hypothesis first and it held.**

```agda
scopeAt _ j with depthAt j
... | someℕ _ = false   -- literal depth ⇒ a FRESH scope ⇒ do not descend
... | noℕ     = true    -- mentions the ambient index ⇒ same scope
```

The information was **already in the depth index**; only `pick` failed to
consult it. Exactly four of the knot's 82 recursive children restart a
scope, and each is pinned to a literal by its own typing rule:

```agda

knot-keeps     : keepD KnotD ≡ 78                                   -- refl
knot-skip-rows : skipRows 0 KnotD
               ≡ rcons 10 (rcons 39 (rcons 45 (rcons 47 rnil)))     -- refl
--   10 cTy-IMu   39 cTm-cIMu   45 cDCon-kap   47 cIDesc-cons
```

Controlled (changing one index gives `45 != 44`), and the generator's own
field table agrees independently: those four are exactly the `lit(0)` /
`lit(1)` children.

⚠ **Do not read this as "D′ was wrong."** D′ is about `wkK`, where two

## 3. ★★★ `agree-var` — THE OBVIOUS STATEMENT IS UNPROVABLE


about `suc (len Γ)` and the IH about `len Γ`. Generalise over a SLACK and

### ⇒ G. ON BATCH SIZE — the risk is EDITS TO SHARED MODULES, not size

~4–6s while developing, so a red sweep is almost never a wrong proof —

is then nearly free, and batches of 1 and 4 — as in this session — are
