## Gap C — DONE

`gcd (2,1) = 1` runs through **two** recursive turns, exercising both branches:

```
(2,1)  2∸1 = 1 ≠ 0  ⇒ a>b branch ⇒ recurse at (2∸1 , 1)   -- gcd-gt-term
(1,1)  1∸1 = 0      ⇒ a≤b branch ⇒ recurse at (1 , 1∸1)   -- gcd-le-term
(1,0)  base case    ⇒ return 1
```

`gcd-2-1` and `gcd-1-1` are in `NbEPDirDBExamplesGcdLib`. Each turn is one
`aux-cycle` plus a reduction computing the recursive argument; nothing between
turns is bespoke. `gcd-2-1` checked green **first try**, which is the evidence
that the cycle is a loop and not a one-off.

### What made it possible (`NbEPDirDBLibAmrec`)

`amrec-step-s` could describe the *first* unfolding and no other. Three defects,
each fatal alone:

1. **The bound was pinned.** `amrecTm` is `aAuxTm m` — the auxiliary at bound
   `μ x` only. But `ihS`'s head is `var (vs⁴ vz)`, the `natrec`'s *own* IH
   variable, so a recursive call lands on `auxIH x k`, never back on `amrecTm`.
   ⇒ `aux-unfold-z/-s`, `aux-step-s` take the bound as a parameter.
   `amrec-step-s` is now **derived** from them — the faithfulness check.
2. **`P` was flat**, quantified outside `ih`, so it structurally could not
   mention the recursive call. ⇒ `aux-step-sF` takes `P : RTm → RTm`.
   Same bug one level down for the certificate ⇒ `q` is a family too.
3. **Index and argument were conflated.** Measured: `auxIH x k ≡ auxIH y k` is
   **not** `refl` — the measure family really does mention the carrier slot.
   After one turn the auxiliary specialised to `x` is applied to a different
   `y`. With them identified, turn 2's source can never match turn 1's target.

`aux-cycle²` composes two turns abstractly with no transport between them.

⚠ **Measured trap:** stating the loop-closer with an *existential* certificate
OOM-kills the module (exit 143 under the cgroup cap) — `with`-abstracting over a
5-fold substitution term does it. Naming it (`descS-at`) checks in ~12s.

Both 3 and 4 have non-vacuity witnesses (`gcd-gt-at-1`, `gcd-le-at-1`) **and**
are consumed by the gap-C run — the strongest available check that they are
usable. The vacuous `gcd-gt-gen`/`gcd-le-gen` were deleted.

### Why 3/4 cannot reach variables as reductions

`monusTm m n = natrec m (predTm (var vz)) n` recurses on its **second**
argument, and `⟶*` only fires on constructor-headed scrutinees. Eq 3 demands
`⟶* nsuc d`, satisfiable by `a := suc d` with `d` a variable. Eq 4 demands
`⟶* nzero`, which forces `a ⟶* zero` — and a variable never reduces, so eq 4's
witnesses are ground. This is a property of reduction, not of the formulation.

### THE NEXT DELIVERABLE — `amrec-unfold-Id`, in the WF library

```agda
amrec-unfold-Id : Δ ⊢ p ∷ IdN μx (nsuc k) →
                  Δ ⊢ ? ∷ IdN (app amrecTm x) (app (app stp x) ih)
```

Every unfold lemma in `NbEPDirDBLibAmrec` is `⟶*`-valued; that is exactly what
confines them to concrete measures. Statements for the consumers already
type-check in `NbEPDirDBExamplesGcdLib`: `gcdGtB`/`gcdLeB` and the internalised
hypotheses `gcdGtH`/`gcdLeH`. With an Id-valued unfold they follow by `jsub`.

**Strategy — transport FIRST, then reduce.** The opposite order from every
existing unfold lemma, which is why none of them generalise:

1. `⊢jsub` (`NbEPDirDBType.agda:599`, general form `gen-jsub`
   `NbEPDirDBSubj.agda:1371`) transports along `p`, rewriting the measure inside
   the auxiliary from the stuck `μx` to the literal `nsuc k`.
2. The `natrec` scrutinee is now constructor-headed, so `amrec-unfold-s` fires.
3. `red→≅ᵀ` / `⟶ᵀ*-Idˡ` (`NbEPDirDBInj`) bridge that reduction back to `Id` —
   the same bridge `⊢gcd-b0-Π` already uses.

**Traps to expect.** `amrecTm` β-reduces to
`app (app (natrec Z S μx) x) (reflTm μx)` — `μx` occurs **twice**, in the bound
*and* in the certificate `reflTm μx : Hom Nat μx μx`. The `jsub` motive must
abstract the right occurrence or the certificate's type will not follow.

⚠ **Two corrections carried forward, both mine.** (i) The `AmTΠ` cycle work does
*not* unlock eqs 3/4: `aux-cycle` needs `n ⟶* nsuc k`, and at a variable pair
the measure `plusTm (fst (a,b)) (snd (a,b))` is stuck on the neutral `a`, so no
bound premise ever exists. (ii) `⊢gcd-b0-Π` is not a template: it never uses its
IH, because `gcd (a,0) = a` holds by the outer `natrec`'s *zero* branch. Eqs 3/4
are the recursive branches — their content *is* the recursive call.

## Tools built this session (reusable)

- **`_⟫_` and `one`** (`NbEPDirDBExamplesGcdStep`) — right-associative
  `⟶*-trans`, an Elm `|>` for reductions. An 8-step derivation is 8 lines with
  **zero** nesting parens. Miscounting the old closing-paren run cost a
  debugging cycle; prefer this for every new chain.
- **The peel family** `pk2`…`pk6`, `peel4`, `peel6`, `wkS2e`, `wkS3e` — N nested
  `natrec` successor branches leave N stacked substitutions over N weakenings.
  Built by **naturality** (`wk-sub-tm`, one `extS` layer at a time), *not* by the
  collapse recipe `wkS2` uses: fusing the renamings leaves a pointwise goal that
  is **false at `vz`**.
- **`mhAt` / `redAt` / `appAt` / `cong₃g`** — a `subst` motive containing `_`
  under a binder is unsolvable; the same equation as a first-order argument lets
  the use site supply everything.
- **`RecCall` + `recCert`/`recRed`** — "the step recurses at `(A,B)` with some
  certificate", plus projections so the certificate can be fed to `aux-cycle` as
  a **family** in `ih`.

## Standing lessons

- **Agda cannot invert `subTm`.** Anything occurring only under a substitution
  must be **named**, never left as `_`. The signature of this failure is an
  *unsolved meta*, never a wrong solution.
- **Green ≠ meaningful.** `--safe`, zero holes and a green build still prove
  nothing if the premise is unsatisfiable. For every conditional lemma, ask
  whether the premise is dischargeable *at the arguments it is stated for*, and
  write the witness. `check-formers.sh` check 6 is the review list — but note it
  reads a mere **mention in a comment** as a consumer, so a named-but-deleted
  lemma is the honest way to retire one.
