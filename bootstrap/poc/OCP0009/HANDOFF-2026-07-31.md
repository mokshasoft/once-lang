## 1. ★ THE RULE THAT CHANGED, and what it invalidates

> **The POC owns its own syntax.** No dependence on `bootstrap/normalizer/**` —
> that is **another POC**, not shared infrastructure — and none on
> `formal/Once/**`. (PLAN §1.2.)

**Why it matters more than it sounds.** Borrowing a peer POC's object language
couples our design decisions to their accidental ones, and then *their limits
get recorded as our constraints*. That is not hypothetical — it happened this
session, twice, and cost real work:

- **W0d was scoped as "port the real IR to the linear core".** That framing is
  bottom-up by construction: it takes the existing target as authoritative and
  measures what the source can be squeezed into. Every wall it hit
  (`no ν`, `no Int`, `List Int is out`) got written down as a limit on the POC.
  None were findings about the right shape. The module that made the error
  (`NbEPLinIR`) is deleted.
- **Then the replacement made the same error one level down**, breaking the
  dependency but keeping the *vocabulary* — `Fix`/`fix`/`unfix`. `Fix` reads as
  a general fixpoint, which Once explicitly rejected (OCP-0003 removed
  `fold`/`unfold` from the IR). Caught by review, not by Agda.

**Corollary, worth internalising:** *"port the real X to Y" is almost always the
wrong scoping for POC work.* The port is downstream compiler work, gated on the
shape being settled.

**Second new standing constraint (PLAN §1.2): NO GENERAL FIXPOINT.** `μ`/`ν` are
the initial algebra and final coalgebra of a polynomial code, eliminated by
`cata` and one observation. No `fold`/`unfold`, no fixpoint combinator, no
`Hylo` as a primitive. Name things `Mu`/`Nu`/`inμ`/`outμ`/`inν` after Once's own
`In`/`out-μ`/`Out`/`in-ν`.

**Where the rule is still violated.** `NbEPLinPass`/`NbEPLinQTT` borrow a
cartesian SOURCE language (`Syntax.CCC.Term`) and `eval` from the normalizer
POC. ⚠ Note this is a PROVENANCE violation, not a shape one: D063/D070 say
point-free is correct, so `Pass`'s source shape was right all along. See §4.

### 4.1 🔴 SCOPED — WHAT INHABITS `Hom`, FORMER BY FORMER

The question `SpikeHom` named. Answered per former below, with what is DECIDED,
what is a CHOICE, and what is genuinely UNKNOWN kept apart.

**The organising principle.** In a directed theory every type is a CATEGORY, and
`Hom A x y` is its hom. So "what inhabits `Hom` at `A`" is "what category is
`A`". Read that way each former has a forced or near-forced answer — except one.

| at | `Hom A x y` is | status |
|---|---|---|
| `U` | `El x ⇒ El y` — the universe is the category of types | ✅ decided (`SpikeHom`; `NbEPDirV`'s `Homₜ`) |
| `base` | identities only (discrete) — **or** a carried order | ⚠ **a CHOICE**, see below |
| `Π A B` | dependent natural transformations | 🔴 **the crux** |
| `Σ' A B` | pairs of morphisms, second transported | ✅ forced, once `Π` is settled |
| `El c` | reduce `c` and recurse; NEUTRAL when `c` is | ✅ decided |

**`U` — decided.** `Hom U c d = El c ⇒ El d`. This is directed univalence, and
`SpikeHom`'s `fee-is-real` is its witness: the two codes there decode to `base`
and `Π base base`, and a path between them is a map.

**`base` — a genuine design CHOICE, do not let it default silently.**
- *(i) discrete*: `Hom base t u` inhabited only by identities. The right default
  for an OPAQUE base type — nothing generates non-identity morphisms — and it
  makes `base` a discrete category, where `Hom` coincides with `Id`.
- *(ii) ordered*: base types in Once are not really opaque (`Int`, `Str`,
  `Buffer` have operations). `Hom Int m n = m ≤ n` is a coherent and interesting
  reading — a base type carrying a partial order as its hom.
- Recommendation: **(i) for the kernel**, and record (ii) as available. The POC
  should not commit Once's base types to a categorical structure it has not
  needed yet. But this is the owner's call, not a forced move.

**`Π A B` — THE CRUX, and where the variance judgment is actually consumed.**
For functors `f g : A → B`, the exponential of categories is the FUNCTOR
category, whose morphisms are NATURAL TRANSFORMATIONS. So

    Hom (Π A B) f g  ≈  (a : A) → Hom (B[a]) (f a) (g a)   + NATURALITY

and stating naturality requires transporting along `Hom A a a'`, which requires
**`B` covariant**. ★ That is the real consumer of W3 — not (only) `J`'s motive,
but the FORMATION of `Hom` at `Π`. It also explains `NbEPDirV`'s `_⇒→_`
contravariance: the functor category is contravariant in its domain.

⚠ **The unknown, stated precisely:** naturality is an EQUATION, so the naive
reading makes `Hom` at `Π` a Σ-type carrying a proof — which is a much heavier
former and probably not decidable. The alternative is the SEGAL-TYPE route,
where naturality is automatic from the type's own structure rather than carried.
**Which of these the kernel can afford is the open research question**, and it
is the one to spike first. Everything else above is bookkeeping by comparison.

**`Σ' A B` — forced.** `Hom (Σ' A B) (a,b) (a',b')` = a morphism `p : Hom A a a'`
together with a morphism from `b` transported along `p` to `b'`. Needs the same
covariance of `B`. Nothing new once `Π` is settled.

**`El c` — decided, and it is the structurally important one.** `Hom` must
COMMUTE with decoding: `Hom (El ⌜base⌝) ⟶ᵀ Hom base`,
`Hom (El (⌜Π⌝ c d)) ⟶ᵀ Hom (Π (El c) (El d))`, and so on. When `c` is NEUTRAL
the type is stuck and `Hom (El n) x y` is a genuine neutral type — so the
logical relation needs a clause for it, exactly as `⊩ne` already handles `El n`.
