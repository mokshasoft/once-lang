## 3. ★ NEXT TASK: `ordtr` — READ `ARCHITECTURE.md` FIRST

    ordtr : RTm Γ → RTm Γ → RTm Γ → RTm Γ → RTm Γ → RTm Γ   -- a t u p q

    ⊢ordtr : Γ ⊢ a ∷ Nat → Γ ⊢ t ∷ Nat → Γ ⊢ u ∷ Nat →
             Γ ⊢ p ∷ Hom Nat a t → Γ ⊢ q ∷ Hom Nat t u →
             Γ ⊢ ordtr a t u p q ∷ Hom Nat a u

    ordtr nzero      t         u         p q ⟶ unit
    ordtr (nsuc a')  nzero     nzero     p q ⟶ p
    ordtr (nsuc a')  (nsuc t') nzero     p q ⟶ q
    ordtr (nsuc a')  nzero     (nsuc u') p q ⟶ absurd (⌜Hom⌝ ⌜Nat⌝ a' u') p

D's first real customer — the code works out exactly:
`absurd (⌜Hom⌝ ⌜Nat⌝ a' u') p : El (⌜Hom⌝ ⌜Nat⌝ a' u')`, which reduces

### What Conf taught

`_⁺`'s clauses cannot discriminate three arguments POSITIONALLY.  On
`ordtr (nsuc n) t (var x) p q` with `t` a variable, Agda cannot decide
the `t ≡ nzero` clause, `_⁺` does not reduce, and no congruence row
typechecks.  Fixed by single-argument dispatch with a catch-all at each
level — `ord⁺` → `ordZ⁺`/`ordS⁺`, the same shape as the existing
`trH⁺`/`trHK⁺`/`apH⁺`.  With that in place a generator driven off Agda's
own "Missing cases" closed the remaining 168 congruence rows in ONE
iteration.  ⚠ the generator must keep NULLARY constructor names as
patterns (`z0@p⌜base⌝`); renaming them to variables emits a bogus
fully-generic catch-all (cost three debug cycles).

`Subj` was easy by comparison — `gen-ordtr` has nothing existential to
recover (the result type `Hom Nat a u` is fixed by the rule), and the

⚠ `occ-red`'s rows must write out every `∨-false₁`/`∨-false₂` summand.

### `ordstk?` — DESIGNED AND LANDED (the §3b open problem is CLOSED)

`ordtr` is NOT like `absurd`.  `absurd` has no root rule and is
unconditionally neutral, so every classifier gives it a blanket `true`.
`ordtr` FIRES once its bounds are numerals, so a blanket `true` makes
`spine?-red (ordtr-z …)` demand `false ≡ true`.  The classifier is:

    ordstk? nzero t u    = false
    ordstk? (nsuc a) t u = ordS? (natstk? t) u
    ordstk? a t u        = natstk? a
    ordS? true  u = true
    ordS? false u = natstk? u

★ two decisions, both load-bearing:

  1. under a `nsuc` bound the order fires exactly when BOTH remaining
     bounds are literal, so that case is a plain DISJUNCTION — no
     dispatch on `t`/`u` at all.  An earlier version dispatched on `u`
     and it just pushed the enumeration onto `u`.
  2. the dispatch stays OUT of the `nsuc` clause, so `ordstk? (nsuc a) t u`
     and `ordstk? (nsuc a') t u` are the SAME TERM.  That is what makes
     `ordstk?-redᵃ`'s `ξ-nsuc` row just `h` — and it is the ONE row where
     `ordstk?-redᵃ` differs from `natstk?-red`, which it otherwise
     mirrors verbatim (60 rows, derived mechanically).

All five root rules are then refuted DEFINITIONALLY in every classifier
(`()` rows), because each fires only on numeral bounds and `natstk?` of
a numeral is `false`.

**Option A (Boolean-keyed `ordK?` + `subst`) was considered and
REJECTED — do not revisit it.**  The existing `-red` lemmas are 51-row
enumerations over the REDUCTION, not the term, which is why their rows
are trivial (23 `h`, 6 `refl`, 3 delegations).  A `natstk? a` key does
not reduce to a literal in most of those rows (for `a = app f x` it is
`spine? f`), so the `subst` never fires and the key has to be resolved
per row anyway.  The Conf precedent does not transfer: there the key was
resolved once, at one spot, by `pw⊥stkA`.

`ordstk?-redᵗ`/`-redᵘ` DO need the ~44-row enumeration on `a`'s head —
this is irreducible, not a formulation artifact.  A reduction of `t` or
`u` leaves `a` inert, so nothing pins `a`'s head, and any function on
`RTm` with a catch-all is stuck on a variable.  Every such row is `h`
(the catch-all value `natstk? a` is untouched); only `nzero` (`()`) and
`nsuc` (two three-line Boolean lemmas, `ordS?-monoᵇ`/`ordS?-monoᵘ`)
differ.  Agda's own "Missing cases" generated all 44 in one pass.

⚠ bind the implicits at every delegation site
(`ordstk?-redᵗ {a = a} {t = t} {t' = t'} {u = u} r h`).  Bare
`ordstk?-redᵗ r h` leaks metas — 33 sites needed this.
