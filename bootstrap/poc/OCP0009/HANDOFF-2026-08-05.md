**Step 0 — RETRACT `tr-J-Nat`. This is the decision, and it is made.**
An earlier note in this session called the spike's risky point 1 "settled
cheaply" because `stkC? ⌜Nat⌝ = true` typechecked. That was premature and is
**retracted**: `tr-J-Nat` breaks subject reduction. The counterexample is
written out in `SPIKE-WF.md` §7; the one-line reason is that `Hom-Nat-z`
reads `Hom Nat nzero n ⟶ Unit` for **any** `n`, so a reflexivity at `⌜Nat⌝`
NO LONGER PINS ITS ENDPOINTS, and J is exactly the rule that assumes it does.

So: delete `tr-J-Nat`, set `stkC? ⌜Nat⌝ = false`. Keep `⌜Unit⌝` J-able —
`Hom Unit t u` has no computation rule, so only `Nat` is poisoned. The sharp
statement is **"ORDERED types cannot be J-able, because their path space is
proof-irrelevant"** — not "datatype codes are exotic".

Two consequences to budget for, both real theorem changes rather than rows:
- `⌜Nat⌝` is now neither `pw?` nor `stkC?` — the third code kind the spike
  predicted. G2's `codeCanon` split must go THREE-way (`NbEPDirDBCanon`).
- The **tt-path rule becomes load-bearing, not optional**: with J disabled at
  `⌜Nat⌝`, a closed `tr` at a `hrefl ⌜Nat⌝ s` path has nothing to fire, so
  `trProgress` is FALSE until order-transport exists. Design it as
  ≤-coercion, following the same endpoint case tree as the order rules.

**Step 1 — the convergence.** Stage B left TWO guards for one phenomenon:
`NoNat` (ambient-keyed, in Subj) and `homnat?`/`sh-NatH` (endpoint-keyed, in
LR). Stage C kills the ambient one — `nonat-red nn-El El-⌜Nat⌝` is an
unfillable hole, because `El c` now reduces to `Nat` and `NoNat` is no
longer preserved by `⟶ᵀ`. `stamb-red` wants `StkAmb Nat`/`StkAmb Unit`
arms for the same reason. So: **re-key Subj's Hom-inversion lemmas
(`Hom-to-Hom`, `hom-to-Π`, `hom-shapeN`, `homred-inv`) off the ENDPOINTS,
exactly as `⊩₁Hom`'s witness already is.** One notion instead of two.

**Step 2 — the tt-path rule** (scoped in Step 0 above). Note WHY stage B was
safe without it: `tr-amb-nonat` (Canon) proved the `tr` ambient is never
`Nat`, using "`El c` never reaches `Nat`". That lemma was **load-bearing for
SOUNDNESS, not merely for proof convenience** — it was blocking exactly the
counterexample above. Stage C removes it, so the rule must land here.

Concretely, a `NoNat` recipe that does survive: replace the blanket
`nn-El : NoNat (El c)` with per-code-head arms (`nn-El-base`, `nn-El-Σ`,
`nn-El-Id`, `nn-El-Hom`, `nn-El-Unit`, …). `nonat-red` then becomes provable
again, because constructor-headed codes are stable under reduction, and every
one of Subj's four `sr` call sites already knows its code head concretely
(they are the `tr-J-base`/`-Σ`/`-Id`/`-Hom` cases). Only a `⌜Nat⌝`-headed
ambient is excluded — which is the true statement.

**Step 3 — level 0 gains the datatype interps.** `El (⌜Hom⌝ ⌜Nat⌝ a b)`
decodes to `Unit`, so the SMALL types now include `Unit`/`Nat` for the first
time: `⊩₀Unit`/`⊩₀Nat` plus their clash-matrix rows (the ~50 rows stage A
was able to skip). Then Fund, Canon, and a stage C acceptance file.

## 4. WHAT THIS UNLOCKS (why the axis was chosen)

The user's framing, worth keeping in view: the WF axis exists to kill the
highest-frequency everyday pain in Agda/Idris/Coq — fuel, `Acc`-plumbing and
`TERMINATING` boilerplate. Once itself suffers it.

Two follow-ups the user has raised and wants kept alive:
1. **Dogfooding** — transcribe some of this POC's own Agda induction proofs
   into the kernel to test ergonomics. Free, and the strongest evidence for
   the axis: "this needed `Acc` plumbing in Agda and doesn't here."
2. **Bootstrap, not circularity** — depending on those transcribed proofs
   for the kernel's OWN consistency would be circular. The non-circular
   version is the standard bootstrap: the Agda proof stays as the frozen
   seed, and Once re-verifies independently once it has a checked kernel.
   Two mutually independent proofs beat one. Relevant because the computing
   order is what makes ℕ usable as a decreasing measure when porting Once
   from Agda to Once.

Deferred, recorded elsewhere: the observational axis ("give `Id` the
computing rules `Hom` has") is the strongest later candidate; smart-case is
deferred with a decidability caveat; option E (HomOver) stays re-judged
behind `Id`. See `ARCHITECTURE.md`'s axes ledger.
