# Plan 0.30 — Abstract `case-on-tag` branches (real loop+case Corresponds)

## Goal

Make the abstract machine's `instr-case-on-tag` actually **branch** on the
scrutinee's tag (instead of halting). This lets `exec-loop` truly *fold* a
heap-μ-value at the abstract level, so the per-instruction `Corresponds`
edge for both `instr-loop` and `instr-case-on-tag` becomes a **real proof**
rather than a both-halt vacuity. Outcome:

- Discharge the pre-existing `case-codegen-faithful-phase1` postulate
  (its TODO: "Phase 5 supersedes by emitting real branches and proving
  correspondence through the meta-tag-driven branch").
- Discharge the Plan 0.29 M3 `instr-loop` / `instr-reg-op` `SMP.!!` holes
  with real `Corresponds` proofs (no new postulates).

User decision (2026-06-03): chosen over the cheaper named-postulate path
precisely because it keeps the Corresponds pattern honest and proves the
fold in the abstract machine, not per-target.

## The change (SMCore `exec-abstract`)

Current (halts):
```
exec-abstract (instr-case-on-tag f g) s alloc = record s { halted = true } , alloc
```

New (branches on `*Input1` tag, matching the x86 `compile-trace-cnt`
dispatch `cmp [rdi],0 ; je inl ; <g> ; jmp end ; inl: <f>`):
```
exec-abstract (instr-case-on-tag f g) s alloc =
  branch-on-tag (readLoc s =<< sv-as-loc (readReg (regs s) Input1)) f g s alloc
  where  tag 0  → exec-trace f s alloc   -- inl
         tag≥1  → exec-trace g s alloc   -- inr
         _      → halt                    -- malformed scrutinee
```

`exec-trace` is mutually defined with `exec-abstract`; `f`/`g` are strict
subterms of the instruction, so the recursion is structural (no new
`TERMINATING`). `exec-loop` keeps its fuel `TERMINATING`.

## Blast radius (61 `instr-case-on-tag` clause sites)

The instruction's effect was "halt"; it becomes "the effect of `f` or `g`".
Every per-instruction lemma whose `case-on-tag` clause assumed halting must
be lifted to reason about the chosen sub-trace. Affected:

- `SMCore`: the clause itself.
- `SMPrimitives` (~12 lemmas): `TraceNoHeapWrites`, frame/slot
  preservation, `exec-abstract-preserves-halted-WF`,
  `exec-abstract-state-next-slot-invariant`, output determinism, etc.
  Strategy: each already has an `exec-trace`-shaped sibling (used for
  `instr-loop` body); route the `case-on-tag` clause through the
  sub-trace lemma for the taken branch (case split on the tag read).
- `DirectSimulation` (×3 targets): real `instr-sim (instr-case-on-tag f g)`
  + `instr-sim (instr-loop _)` + `instr-sim (instr-reg-op _)`.
  `instr-reg-op` is a genuine no-op on tracked state (Corresponds tracks
  neither Scratch/rbx nor Input2/rsi) → provable directly once `exec-x86`
  gets no-op clauses for `mov/sub/add` on `rbx`/`rsi`.
- `IRTraceCorrect` / `IRToTrace`: case-on-tag trace-shape clauses.
