# Plan 0.69 — the x86-32 / riscv64 runtime regression (the post-flip frame)

**Status**: OPEN, written 2026-08-11 alongside the C1 merge. This is the ONLY
thing between the `plan-0.54-rung-d` line and master parity on the exit tests.

    x86-64    55 passed,  0 failed     (restored by C1 / D101, 2026-08-11)
    x86-32    35 passed, 20 failed     ← this plan
    riscv64   18 passed, 37 failed     ← this plan
    master    55 / 0 / 0 on all three

**It is NOT a proof gap and NOT the cata.** C1 moved these two counts by exactly
zero tests. Nothing here is discharged by plans 0.65/0.66 either: a
correspondence proof for an arch does not fix its emitter, and 0.66 says so in
its own words. This is codegen, found and fixed the way codegen is: read the
emitted assembly.

## Why the proofs cannot see it

On x86-32 and riscv64 the ENTIRE simulation is one postulate
(`x86-32-conc-flat-sim`, `riscv64-conc-flat-sim`) plus a loader axiom. There is
no theorem relating either arch's instructions to the flat machine, so every
lowering defect below is invisible to `certified` and to all three
`ccc-<arch>` clusters — all of which are green with these 57 tests failing.
Same lesson as D101, one layer down: **a postulate does not merely leave work
undone, it removes the ability to be wrong.**

**Read the pattern, it is the plan's main clue**: on x86-32 the failing set is
exactly the programs that emit CONTROL — `case`, closures, cata. Those are the
constructs the 0.63 flip moved INLINE into the main trace (body between a
`c-thunk`/`c-ret` bracket, parent jumping over it). Programs with no inline
body pass on both arches.

## The x86-32 defect — CONFIRMED, read off the emitted assembly

`compiler/test/layer2-case-inl-direct.once`, `--target x86_32 --alloc heap
--no-optimize --save-temps`:

    once_4main:
        pushl %ebp
        subl $36, %esp          ← the FUNCTION's frame: 9 slots
        movl %esp, %ebp         ← the slot base, anchored ONCE
        …
        movl %eax, 16(%ebp)
        jmp .Lonce_once_4main_1
    .L_thunk_once_4main_0:
        subl $120, %esp         ← the BODY's frame … and nothing else
        …
        movl %eax, 16(%ebp)     ← writes the CALLER's slot 4
        …
        movl %eax, 40(%ebp)     ← offset 40 in a 36-byte frame

Two facts, both fatal:

1. **`%ebp` is anchored once, at function entry, and the `c-thunk` lowering
   never re-anchors it.** x86-64 gets this right by accident of addressing:
   its slots are `n(%rsp)` and the body's `subq $N, %rsp` re-anchors them for
   free. x86-32 addresses `n(%ebp)`, so an inlined body's slots ALIAS its
   parent's — every body clobbers the frame it was called from.
2. **The enclosing function's `subl` does not cover the inlined body's
   slots**, so writes run off the end of the frame. That is the SIGSEGV.

Before the flip this could not happen: bodies were a separate `ir-to-bodies`
walk with their own function prologue. The flip inlined them and x86-32's
lowering was never taught.

**The fix, and the choice to make first**: either (a) make x86-32 address slots
off `%esp` the way x86-64 does, so `c-thunk`'s `subl` re-anchors them and
`c-ret`'s `addl` unwinds — the smaller and more uniform change, and it deletes
a difference between the arches rather than adding one; or (b) keep `%ebp` and
have `c-thunk` push/re-anchor it and `c-ret` pop it. Prefer (a): it makes the
three arches share one frame model, which is also what plans 0.65/0.66 need.
Record the decision in the decision log either way.

## The riscv64 defect — PRIME SUSPECT, evidence below, not yet confirmed

`compiler/test/layer1-swap.once`, `--target riscv64`:

    once_4main:
        addi sp, sp, -80
        sd   ra, 72(sp)         ← the return address, at a FIXED offset
        …
        j .Lonce_once_4main_3
    .L_thunk_once_4main_2:
        addi sp, sp, -176       ← the body moves sp …
        …                       ← … and 72(sp) now points somewhere else
    .L_thunk_once_4main_4:
        addi sp, sp, 0
        ld   a0, 8(t0)
        call once_…_4exit       ← a `call` inside a body CLOBBERS ra
        addi sp, sp, 0
        ret                     ← returns to the clobbered ra

RISC-V has no push: `call` writes the return address into `ra`, so a body that
performs any call destroys its own return address unless it saved it. A `ret`
to a stale `ra` that points back into the same body is an infinite loop —
which is exactly the symptom (36 of 37 failures are hangs, not crashes). The
second half of the suspicion is the same one as x86-32: the function's `ra`
slot is at a fixed offset from the ENTRY `sp`, and inside a body `sp` has
moved, so the epilogue reloads from the wrong address.

**Confirm before fixing** — run one hanging test under `qemu-riscv64 -g` and a
gdb, or single-step in qemu's `-d in_asm` trace, and look at where the `ret`
goes. Do not fix on the strength of a plausible story; that is how the C1
setup bug got shipped.

The `arith-*` and `infer-lambda` failures are in the same list but may be a
DIFFERENT cause (they need no closure body). Bisect them separately — if they
share the ra/sp story, good; if not, they are a second defect and deserve their
own section here.

## The method that worked on x86-64 — use it, do not reinvent it

C1's own first emitter was green on all four Agda clusters and returned the
fold of ZERO layers (D101). This is how it was found, in about twenty minutes,
and it is the recipe for the two arches:

1. **Take the smallest failing test in the family** (`layer5-cata-nat`,
   `layer2-case-inl-direct`, `layer1-swap`) — not a representative one, the
   SMALLEST, so the whole function fits on a screen.
2. **Emit the assembly, do not read the emitter**:

       ONCE=$(cd compiler && cabal list-bin once)
       $ONCE build --exe --save-temps --target <arch> --alloc heap \
             --no-optimize --strata Strata -I:<arch> I.Linux.Syscalls \
             compiler/test/<t>.once -o /tmp/scratch/<t>

   `--save-temps` keeps the `.s` beside the binary. Without `--exe` you still
   get an executable; the `.s` is the artefact you want.
3. **Read it against the abstract trace's BLOCK STRUCTURE**, not
   instruction-by-instruction. Every block in `IRToTrace` (`cata-call-setup`,
   `cata-call`, `cata-nat-I₁`, `cata-body`, the `curry` bracket) appears
   verbatim and in order. Find the block boundary where a register or slot
   stops meaning what the next block assumes.
4. **Ask what each block ASSUMES on entry and LEAVES on exit** — that is where
   both bugs found so far live. C1's was `cata-call-setup` pointing `Input1`
   at the closure record to write its cells and never handing it back, so the
   descend loop read the record's tag instead of the μ-value. x86-32's is a
   body assuming its slot base is its own when the arch anchored it once, in
   the caller.
5. **Fix in the ABSTRACT emitter when the contract is abstract** (C1: the
   setup block now takes the spare slot `k` and restores `Input1` through it),
   **and in the per-arch lowering when the contract is the ISA's** (x86-32's
   frame anchor, riscv64's `ra`). Getting this split wrong means fixing the
   same bug three times.
6. **Follow the red through the six codegen walks.** Changing a block's length
   or slot use ripples into `SlotBudget`, `AllocMin`, `FrameFreeTrace`,
   `CataIRSlotStable`, `LabelScope`, `LabelRange` — all mechanical
   per-instruction lists, all cheap, all caught by the typechecker. Judge them
   on EXIT CODES (`timeout 300 formal/scripts/agda-safe.sh agda
   MODULE=Once/CCC/Codegen/X.agda`), never on grepping the log.
7. **The exit tests are the oracle, and the only one.** Re-extract and re-run
   after every emitter change; a green `certified` says nothing here.

## The extraction bookkeeping, so nobody rediscovers it either

ONE extraction after ALL Agda edits (MERGE.md step 4):

    rm -rf formal/_build/malonzo/MAlonzo && make -C formal malonzo
    cd compiler && systemd-run --user --scope -p MemoryMax=5500M \
        -p MemorySwapMax=2G -- cabal build     # and `cabal test`

Two things bite every time:

- **MAlonzo NameId drift.** `compiler/src/Once/Compile/Bridge.hs` hardcodes
  mangled names (`MC.T_Stage_714`, `MC.d_compile_766`). Adding or removing ANY
  Agda definition shifts them. GHC's own "Perhaps use `MC.T_Stage_778`" IS the
  mapping — apply it with `sed`, do not hand-count.
- **New extracted modules must be registered** in `compiler/once.cabal`'s
  module list or the link fails with `undefined reference to …`. This branch
  needed `EmittedWF`, `LabelClash`, `ValidAtWFHalted`.

Also: the qemu suites drop `compiler/qemu_*.core` files on every SIGSEGV. Some
older ones are TRACKED in git — delete only the ones your run created.
