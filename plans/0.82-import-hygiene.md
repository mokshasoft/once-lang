# Plan 0.82 — Import hygiene: stop the silent rot

## The finding

**Agda only WARNS when a `using (…)` directive names something the module does
not export.** So every time a definition is deleted or renamed, every import
list that mentioned it goes stale — silently, forever. Nothing fails.

Measured on one apex build (`Once/Certified.agda`, which re-checks only part of
the tree, so these are LOWER BOUNDS):

  * `ModuleDoesntExport` — **48 sites across ~30 modules, 224 stale names**
  * `DuplicateUsing` — 3
  * `UselessPublic` — present

Worst offenders: `Once/TypeCheck/Completeness.agda` (6 sites),
`Once/Spec/Meaning.agda` (4), `Once/Adequacy/MeaningBridge.agda` (4),
`Once/Adequacy/CPU/X86-64.agda` (4).

The names are archaeology: `bbc-*` (D136), `m-case`/`m-compose`/`m-curry`/
`m-pair`/`m-named` (the `⊢ᵐ` realm D127 deleted), `realize-morph`/
`realize-global`, `t-morph-lift`/`t-value-lift`/`t-closed-lift`, a dozen
`*-info` SigOp constructors.

## Why it matters (it is not tidiness)

**A stale import list hides real breakage.** The list is the reader's — and the
reviewer's — statement of what a module depends on. When a third of it names
things that no longer exist, nobody can tell a deliberate dependency from a
fossil, and a genuinely wrong import looks like more of the same noise.

It also defeats the one mechanism that would otherwise make a rename safe:
delete a definition, and Agda tells you every USE — but not every mention in an
import list. This is exactly how `Once.TypeCheck.Judgment` kept importing
`Once.IR` and `Once.TypeCheck.Morph` long after D134 removed the last rule
using them, which plan 0.81 found only by enumerating the spec by hand.

## Step 1 — make it fail (do this FIRST)

Cleaning without a gate just resets the clock.

`-W error=ModuleDoesntExport` does **not** work on this Agda (2.8.0): the flag
is accepted, the warning still exits 0. Verified. `-W error` (all warnings) is
not usable either — `CoverageNoExactSplit` alone fires 596 times and several are
deliberate.

So: a `make lint-imports` target that builds the apex (or `Everything.agda`),
captures the output, and FAILS if `ModuleDoesntExport`, `DuplicateUsing` or
`UselessPublic` appears. Roughly:

    lint-imports:
        @$(AGDA_CMD) Everything.agda 2>&1 | tee $(LINT_LOG); \
         if grep -qE 'ModuleDoesntExport|DuplicateUsing|UselessPublic' $(LINT_LOG); \
         then echo "stale import directives — see above"; exit 1; fi

Caveat that shapes the design: **Agda only warns for modules it actually
re-checks.** A warm `_build` will under-report, so the lint must run on a build
that covers the tree — `Everything.agda` (the filtered island backstop already
used for type sweeps) rather than `Once/Certified.agda`, and CI should not
prime the cache first.

## Step 2 — clean the 224

Mechanical, and safely scriptable BECAUSE the warning names both the module and
the missing names. Parse the lint log, drop those names from the corresponding
`using (…)`, re-run until clean.

Two traps found while doing this by hand in plan 0.50:

  * a name can appear in SEVERAL import lists in one file, and the warning
    reports it per-directive — edit by (file, directive) span, not by name;
  * removing a name from a `using` list can leave `(…; )` or `(; …)`. Normalise
    the separators, and re-run the type-check after each file rather than at the
    end.

## Step 3 — the neighbouring rot, same shape

`UselessPublic` and `DuplicateUsing` come free with the same lint. Also worth
one pass while in the area: `Once/Spec/**`'s re-export lists are now explicit
(plan 0.81 step 0) and are the ONE place where a stale name is actively
dangerous rather than merely noisy — a name that vanishes from the boundary
should be a review event, and the lint is what makes it one.

## Sizing

Step 1 is an afternoon. Step 2 is mechanical once step 1 gives the list. The
value is not the 224 deletions — it is that the 225th cannot happen.
