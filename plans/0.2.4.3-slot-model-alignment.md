# Plan 0.2.4.3: Slot model alignment (no-frame)

## Context

Plan 0.2.4.2 catalogued the closure-codegen defects (B1: stack-frame
lifetime violation; B2: code-pointer slot self-reference; B3: AllocMode
ignored; B4: apply ABI). Its locked decision **D2** said "closure body
has its own SysV frame (`pushq %rbp; mov %rsp, %rbp; …; leave; ret`)."
This plan **supersedes D2**: closures share their parent's stack frame
under the slot-frontier-threading model.

The motivation came from a 2026-05-04/05 audit while chasing a runtime
segfault on `(id . id . id) 42`. Three independent layers must agree
on the call/closure model for proofs to compose:

| Layer | What says how IRs execute |
|---|---|
| Slot model spec | `Once.CCC.Machine.SMCore.exec-abstract`, `Once.CCC.Machine.IR.*WF` |
| Abstract trace | `Once.CCC.Codegen.IRToTrace` |
| Target trace (per-arch) | `Once.CCC.Target.<arch>.AbstractToX86` + `Once.Target.<arch>` |

Today these disagree: the slot spec (`ApplyWF`) used to push a child
frame; `IRToTrace.apply` emits no frame; the target's `emit-thunk-body`
adds a SysV envelope at text level. Bugs hid in the gaps between these
layers, bridged only by load-bearing postulates
(`ir-to-trace-correct-curry`, `ir-to-trace-correct-apply`).

## Goal

Drive all three layers to the same model: **no per-thunk frames; closures
live in the curry's caller's slots; bodies inherit the caller's frame
with the slot frontier advanced past their reservation.**

This makes the typechecker carry the proof through structural identity
instead of per-IR postulates papering over shape mismatches.

## Locked architectural decisions

### D1 (supersedes 0.2.4.2 D2): No per-thunk frames at any layer

The slot model spec, abstract trace, and target codegen all run a
closure's body in the parent's frame. There is no per-thunk
`pushq %rbp / leave / ret` envelope. A `call .L_thunk_<n>` lands in
the body, body executes its trace using the slot frontier handed in,
and `ret` returns. The slot frontier is the only "stack" abstraction.

### D2: Curry pre-reserves body's scratch in caller's frontier

Curry at frontier `n` lays out `[n, n+1] = (env, code-ptr)` and
recursively traces the body with starting frontier `body-base = n + 2`.
The body's max slot becomes the post-curry frontier — i.e. the body's
scratch is pre-reserved in the caller's frame.

Apply at frontier `m ≥ post-curry-frontier` allocates the (env, arg)
pair at slots `m, m+1`. Because `m ≥ body-base + body-cap`, apply's
pair never aliases body's region. Sequential closures use disjoint
slot regions by construction.

### D3: Each layer threads `n` consistently

- **Slot model spec (`ApplyWF`)**: body executes with
  `child-alloc = alloc { next-slot = next-slot alloc + pair-slots }`,
  same frame as parent.
- **`CurryStackWF`**: closure-loc lives in caller's slots; the trace stores
  `(env, encode-code-addr body-label)` at `[closure-slot, closure-slot+1]`.
- **`IRToTrace.curry`**: body's IR-to-trace called with
  `body-base = n + 2` (currently `0` — the gap).
- **Target codegen**: `_start` ordering ensures `%rbp` anchors at the
  bottom of the reserved buffer; slot offsets are
  `(slot * 8)(%rbp)` which land inside the buffer.

## Compose-test as live regression

The runtime test `(id . id . id) 42` is the canonical regression for
this plan + 0.2.4.4. Current state under the partial fix:

- `id 42` → exit 42 ✓
- `(id . id) 42` → exit 42 ✓ (was broken under SysV-frame model)
- `(id . id . id) 42` → segfaults at RIP=0x2a (the integer literal 42)
  — different bug from the original saved-rbp/return-address
  corruption. Exposes a closure-escape-from-temp-frame issue that the
  remaining D2/D3 work closes.

When 0.2.4.3 + 0.2.4.4 are fully landed, all three should produce
exit 42, and the spec layer's `ir-to-trace-correct-curry` /
`ir-to-trace-correct-apply` postulates should be discharged
(possibly to small named lemmas, not wholesale).

## Out of scope

- Layer 5+ recursion. The no-frame model is sound for Layer 0–4
  (bounded slot frontier per program). For μ-recursion, the static
  bound breaks; that's a future plan.
- The `instr-load-code-addr`/`closure[1]`-pinning gap — see 0.2.4.4.
- `AllocMode` semantic interpretation — see 0.2.4.5.
- Layer 0 success criterion is `(id . id . id) 42 → 42` running on
  x86-64; X86-32 / RiscV64 mirrors of the slot-addressing changes
  are deferred.
