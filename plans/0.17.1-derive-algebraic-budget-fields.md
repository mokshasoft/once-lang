# Plan 0.17.1 — Derive Algebraic Budget Fields from Bump

## Once Compiler Formal Verification

**Status:** Open — extends Plan 0.17. Replaces remaining Plan 0.17 Phase 3 work for unmigrated producers.

**Date:** 2026-05-20

---

## Motivation

Plan 0.17 surfaced that `IRResultBase.final-alloc` was a free field
that algebraically should be derived from a declared `bump`. The same
critique applies to several fields in `IRStackBudget` and
`IRHeapBudget`: they're algebraic consequences of `bump` + the
absolute budget values, not independent claims.

| Current free field | Algebraic from `bump` |
|---|---|
| `IRStackBudget.slot-monotone : next-slot alloc ≤ next-slot final-alloc` | `m≤n+m (next-slot-delta bump) (next-slot alloc)` |
| `IRStackBudget.max-slot-geq-final : next-slot final-alloc ≤ max-slot-written` | Derivable from `bump` + `max-slot-written ≥ next-slot-delta bump + next-slot alloc` |
| `IRStackBudget.slot-stays-in-budget : next-slot final-alloc ≤ next-slot alloc + stack-budget` | Derivable from `bump` + `stack-budget ≥ next-slot-delta bump` |
| `IRHeapBudget.heap-monotone : next-heap-ref alloc ≤ next-heap-ref final-alloc` | Same shape as slot-monotone |
| `IRHeapBudget.max-heap-ref-geq-final` | Same shape |
| `IRHeapBudget.max-heap-usage-bound` | Derivable from heap-budget + bump |

Producers currently write all of these by hand, with no type-level
forcing function for consistency. Same drift risk as before
Plan 0.17.

## Goal

Move the algebraic budget fields to derived projections of
`IRStackBudget` / `IRHeapBudget`. Producers declare the **absolute
budget values** (`stack-budget : ℕ`, `max-slot-written : ℕ`,
`heap-budget : ℕ`, `max-heap-ref-written : ℕ`) plus the **consistency
checks** (`stack-budget ≥ next-slot-delta bump`, etc.); the algebraic
fields derive mechanically.

## Design

### Core change — `IRStackBudget`

```agda
-- Before
record IRStackBudget (alloc final-alloc : AllocState) trace s : Set where
  field
    slot-monotone : next-slot alloc ≤ next-slot final-alloc
    max-slot-written : ℕ
    max-slot-geq-final : next-slot final-alloc ≤ max-slot-written
    stack-budget : ℕ
    max-slot-usage-bound : max-slot-written ≤ next-slot alloc +ℕ stack-budget
    slot-stays-in-budget : next-slot final-alloc ≤ next-slot alloc +ℕ stack-budget
    frontier-slot-stable : ...
    trace-writes-above : TraceWritesAbove (next-slot alloc) trace
    trace-slot-reads-above : TraceSlotReadsAbove (next-slot alloc) trace
    trace-writes-below : TraceWritesBelow max-slot-written trace
    trace-slot-reads-below : TraceSlotReadsBelow max-slot-written trace
    scratch-budget : ℕ
    scratch-bounded : ...

-- After (Plan 0.17.1)
record IRStackBudget (alloc : AllocState) (bump : AllocBump) trace s : Set where
  field
    max-slot-written : ℕ
    stack-budget : ℕ
    -- NEW: bump-budget consistency
    bump-fits-stack-budget : next-slot-delta bump ≤ stack-budget
    -- Existing claims (genuine semantic obligations):
    max-slot-usage-bound : max-slot-written ≤ next-slot alloc +ℕ stack-budget
    -- max-slot-geq-final now derives from max-slot-written + bump:
    max-slot-geq-final : next-slot alloc +ℕ next-slot-delta bump ≤ max-slot-written
    frontier-slot-stable : ...
    trace-writes-above : TraceWritesAbove (next-slot alloc) trace
    trace-slot-reads-above : TraceSlotReadsAbove (next-slot alloc) trace
    trace-writes-below : TraceWritesBelow max-slot-written trace
    trace-slot-reads-below : TraceSlotReadsBelow max-slot-written trace
    scratch-budget : ℕ
    scratch-bounded : ...

  -- Derived projections (for consumer backward-compat):
  slot-monotone : next-slot alloc ≤ next-slot (apply-bump bump alloc)
  slot-monotone = … via m≤n+m

  slot-stays-in-budget : next-slot (apply-bump bump alloc) ≤ next-slot alloc +ℕ stack-budget
  slot-stays-in-budget = … via +-monoʳ-≤ bump-fits-stack-budget
```

Same shape for `IRHeapBudget`.

### Knock-on for `IRResultBase`

`IRStackBudget` and `IRHeapBudget` now take `bump` rather than
`final-alloc`. `IRResultAWF.stack-inv` and `heap-inv` need their type
parameters updated:

```agda
record IRResultAWF ... where
  field
    base       : IRResultBase m ir x s alloc
    stack-inv  : IRStackBudget alloc (IRResultBase.bump base) (IRResultBase.trace base) s
    heap-inv   : IRHeapBudget  alloc (IRResultBase.bump base) (IRResultBase.trace base)
```

`final-alloc` derives consistently through `apply-bump`.

### Updated `mk-IRResultAWF-via-bump`

The smart constructor's signature contracts — fewer arguments to
provide because more fields are derived. Producers' producer-side
records shrink correspondingly.

## Refactor Steps

### Phase A — `IRStackBudget` / `IRHeapBudget` refactor (1 commit)

1. Change `IRStackBudget` / `IRHeapBudget` to take `bump : AllocBump` instead of `final-alloc : AllocState`.
2. Move `slot-monotone`, `slot-stays-in-budget`, `heap-monotone`, `max-slot-geq-final`, `max-heap-ref-geq-final`, `max-heap-usage-bound` (where mechanically derivable) to derived projections.
3. Add `bump-fits-stack-budget` and `bump-fits-heap-budget` consistency check fields.

### Phase B — `IRResultAWF` / smart constructor update (1 commit)

1. Update `IRResultAWF` to thread `bump` into stack-inv / heap-inv.
2. Update `mk-IRResultAWF-via-bump`'s signature to take the contracted stack-inv-local / heap-inv-local records.

### Phase C — Producer migrations (continues Plan 0.17 Phase 3)

For each unmigrated producer:

1. Compute `bump` from sub-IR bumps + own deltas (Plan 0.17 step).
2. Prove `final-alloc-eq : alloc' ≡ apply-bump bump alloc` (Plan 0.17 step).
3. Prove `bump-fits-stack-budget : next-slot-delta bump ≤ stack-budget` and the heap analog (NEW).
4. Provide the shrunk stack-inv-local / heap-inv-local records (NO slot-monotone, NO slot-stays-in-budget, NO heap-monotone — derived).
5. Call `mk-IRResultAWF-via-bump`.

Already-migrated producers (SimpleWF, SumInl/Inr/CurryHeap, CurryStackWF, PairAllocWF, ApplyWF) need their stack-inv-local / heap-inv-local records to drop the derived fields.

### Phase D — Verify (1 commit)

- `make compiler-x86-64` clean.
- `cabal test -p /Layer/` 8/8.
- Confirm SMP.!! count is unchanged or reduced.

## Connection to Plan 0.16 / 0.17

- **Plan 0.16 Pattern 1** (drop `instr-alloc-stack` from heap producers): Plan 0.17.1 enforces it structurally — heap-result producers declare `next-slot-delta bump = 0`, and `bump-fits-stack-budget` becomes trivial (stack-budget ≥ 0). The trace MUST not bump next-slot, else `alloc-correct` fails.
- **Plan 0.17 Phase 3 remaining producers**: subsumed by Phase C here. The smart constructor's contracted signature means each producer's migration is even simpler.

## Acceptance Criteria

- `IRStackBudget` and `IRHeapBudget` derive `slot-monotone` / `heap-monotone` / `slot-stays-in-budget` etc. as projections.
- Producers declare absolute budgets + consistency checks; no redundant monotonicity claims.
- All 14 producers migrate cleanly via `mk-IRResultAWF-via-bump`.
- Build + Layer tests pass.

## Why this is principled

The same "single source of truth" argument from Plan 0.17 applies to
the algebraic budget fields. Today these fields can drift between
producers (one writes `slot-monotone = ≤-refl`, another writes
`slot-monotone = m≤m+n`, another writes a derived `≤-trans`). After
Plan 0.17.1, they all derive from the SAME `bump` declaration —
no drift possible.

The producer's `IRStackBudget` / `IRHeapBudget` contracts down to
exactly the semantic content: budget bounds, trace shape, scratch
accounting. Algebraic monotonicity / bump-consistency is type-level.
