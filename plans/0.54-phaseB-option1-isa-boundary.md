# Plan 0.54 Phase B / Option 1 — make the arith island load-bearing at the apex

## The gap (precise)

The apex field `asm-trace-correct` (`Adequacy/ArchCorrectness/FlatFromObs.agda:69`,
`Adequacy/Compile.agda:189`) is ONE postulate asserting
`asm-sem asm n ≡ flat-trace (moduleToIR m) n`, where
`asm-sem = run-trace ∘ decode ∘ assemble` and all three are **opaque postulated
fields** of `ArchSemantics` (per-arch: `run-trace-x86-64` etc. are `postulate`s).

For the **arith slice**, this hides two claims about each emitted
`once_arith.block.<digest>` subroutine:
1. **value:** it computes `block-semM e` into the result register (`%rax` / io).
2. **non-interference:** it does not clobber CCC-live state — the flat model
   treats the arith SigOp as an atomic `pure-preserves` (`CCC/SigOp/Helper.agda`),
   so the real subroutine must actually preserve CCC registers/memory.

Claim (1) is Phase A, **already PROVEN**: `block-correct : exec-x86 (compile-abs e)
≡ block-semM e` (`Arith/Backend/Correct.agda`), but the proof is ORPHAN.

## Why full elimination is out of scope (→ option 2, a separate plan)

`assemble`/`decode`/`run-trace` are opaque. No property of the real CPU is
provable without an in-Agda assembler + ISA model. So Option 1 does NOT reach
zero postulates; it **reshapes** the trust: proves everything that is the
*compiler's* responsibility, and reduces the residual to a minimal, explicit,
per-instruction ISA axiom (the honest boundary every asm-emitting verified
compiler keeps — cf. CompCert's assembler/linker trust).

## Structure — ONE generic obligation, discharged per arch (the apex stays generic)

The apex must NOT mention any concrete arch. It already parameterizes over
`ArchSemantics` / `FrameSemantics` / `RegConvention`; the arith correctness is
the same shape: **one generic obligation the apex depends on, each arch
instantiates.** No per-arch wiring in `Adequacy/`.

```
-- Once/Arith/Backend/Adequacy.agda  (the generic interface the apex consumes)
record ArithBackendCorrect (RC : RegConvention) (as : ArchSemantics) : Set where
  open RegConvention RC
  field
    -- ① preserves-CCC: the emit's clobber footprint is CCC-disjoint.
    writes    : XInstr → List Reg
    confined  : ∀ i → All (λ r → owner r ≢ ccc) (writes i)   -- x86-64/riscv64: refl;
                                                             -- x86-32: restore-correctness
    -- ② ISA faithfulness (the honest residual axiom, shared with CCC codegen):
    --    the CPU runs the emitted arith asm as `exec-x86` says, writing ⊆ `writes`.
    isa-faithful : <the per-arch ISA seam>
```

- **Arch-neutral, PROVEN once:** `block-correct : exec-x86 (compile-abs e) ≡
  block-semM e` (`Backend/Correct`, width-generic — done). The compiler LOGIC.
- **Generic discharge (once):** `Backend/Adequacy` derives the arith slice of
  `asm-trace-correct` from `ArithBackendCorrect` + `block-correct` +
  `pure-preserves` — uniformly, for any arch.
- **Per-arch instance:** each `Arith/Backend/<arch>/Confine` supplies `writes` +
  `confined` (field ①); each declares its `isa-faithful` axiom (field ②).
  `X86-64/Confine.agda` is the x86-64 witness for ① — it is NOT apex-wired.
- **Apex:** `FlatFromObs`/`Compile` take `ArithBackendCorrect` as a parameter and
  discharge the arith slice generically. A fourth arch = one new instance, zero
  apex edits.

`confined` is stated over the shared `RegConvention` (`owner`/budget), so field ①
is itself generic; each arch only provides `writes` + the witness.

## The one structural obstacle + fix

`instr-text : XInstr → String` emits strings, so register footprints are not
inspectable ⇒ confinement can't be stated. **Fix (the "shared/structured emit"):**
interpose a concrete physical-instruction AST:
`XInstr → PhysAsm Reg → String`, where `PhysAsm` carries register operands
structurally and `render : PhysAsm → String` is a pure printer. Then:
- `phys-writes : PhysAsm Reg → List Reg` is readable, and
- `confined : ∀ i → All (λ r → owner r ≢ ccc) (phys-writes (lower i))` is
  structural (`arith-reg` image ⊆ arith, rax ∈ io).
- `instr-text i ≡ render (lower i)` keeps the emitted text identical (`refl`),
  so no codegen/test change. This structured layer is also exactly what option 2
  (in-Agda assembler) would build on.

## Three-arch obligations

- **x86-64 / riscv64:** confinement is definitional — `phys-writes ⊆ arith ∪ io`,
  `owner` distinguishes `ccc` by distinct constructors ⇒ `refl`/`()`.
- **x86-32 (k=0):** arith BORROWS ccc registers (`arith-borrows : owner
  (arith-reg x) ≡ ccc`). Confinement is FALSE here; instead prove
  **restore-correctness**: the emit brackets borrowed regs with save…use…restore
  so their net footprint is empty. A bounded induction over the emitted bracket.

## CORRECTION (2026-07-17) — the concrete machine EXISTS; the gap is bounded

Earlier this plan overstated the gap as a months-long "build a machine." Re-audit:
**`X64.run = exec defaultFuel` IS a concrete state machine** (fetch → `execInstr`
→ loop over a concrete `State` = RegFile + `Memory : Word → Maybe Word` + flags +
pc + halted). And `Preserve.agda`'s `write-nonccc-agrees`/`step-of` already run on
its REAL `RegFile` (`X64.Semantics.writeReg`) — so **register-preservation is
already proven over the actual machine**, not a mock.

What's actually missing is bounded:
1. `execInstr syscall = halt`, `call-sym = halt` — `run` STOPS at the first SigOp.
   `run-trace` = a variant that RECORDS the event (from register args) and
   CONTINUES. A bounded instrumentation of the existing loop at TWO instruction
   clauses (Plan 0.44 emit-and-continue), not a new machine. Arith blocks are
   Pure (no syscall/call-sym), so they emit nothing and only transform state.
2. Arith's instructions live in its own `XInstr` (the "spread-out" half). Unify by
   giving `XInstr` a concrete interpretation over the SAME `X64.State`
   (`exec-arith-instr : XInstr → State → State`) — register writes via the real
   `writeReg` (preservation already done), scratch via `writeMem` at `rsp-offset`.
3. Memory-preservation = a disjointness argument mirroring register-ownership:
   arith scratch writes at `< rsp`; CCC memory at `≥ rsp`; `a ≢ addr` ⇒
   `readMem (writeMem …) a ≡ readMem … a` (writeMem is a one-address update).
4. Residual: `assemble`/`decode` (text↔program, GNU-as/decoder) — the honest
   external boundary, kept as an axiom or a concrete encoder later.

So the path is UNIFY (arith onto X64.run) + INSTRUMENT (run-trace) + the
assemble/decode residual — all bounded, reusing X64.run. Not months.

# ARCHITECTURE REVISION (2026-07-19) — the four-machine diagnosis + the top-down spine

## Why the old plan kept producing orphan bottom-up work

An investigation pass (three parallel readers over the flat machine, the
concrete↔flat bridge, and the concrete arith machine) found the real problem:
**arith has FOUR machines and every arith proof is an orphan island on a
different one.** The old plan aimed all effort at reducing `asm-trace-correct`
(the concrete↔flat seam) and never noticed the flat model is itself wrong for
arith — a gap that sits ABOVE that seam.

| # | Machine | Arith is… | Proof on it | Wired to apex? |
|---|---------|-----------|-------------|----------------|
| 1 | `FlatState` (`flat-events`, the APEX machine) | a `Pure instr-sigop`, output = **sentinel `0`** | `traces-agree` (pure slice real; cata/rest postulated) | yes — but arith VALUE is a sentinel |
| 2 | `ArithAbsState` (word-level XInstr) | `exec-xprog` | **`block-correct`** (value, 0 postulates) | **no** — zero importers |
| 3 | `X64.State` + `val` (concrete registers) | `exec-arith-block`/`dispatch-arith` | 5 cores → **`dispatch-arith-preserves`** | **no** — orphan; `run-events` uses the *function*, never the *proof* |
| 4 | asm text | `emit-arith-block` string | — | what actually runs |

Decisive facts:
- **`flat-sim` does not exist** — it is a comment-only name. The real
  concrete↔flat bridge is the postulate pair `asm-trace-correct` + `ir-flat-correct`
  over an **undefined** `flat-trace`; `flat-from-obs` even DISCARDS the abstract
  theorem it is handed. No real proof depends on the concrete machine.
- **`val` (concrete per-XInstr semantics) is a postulate** (`val-x86-64`). Machine
  #3 — the one now wired into `run-trace` — rests on admitted semantics.
- **`block-correct` is on machine #2, not #3** — it proves the WORD machine, not
  the concrete `val` machine, so it does not even mention the state `run-trace`
  runs on. `block-correct` and `dispatch-arith-preserves` are both orphan.
- **The sentinel is a real correctness gap, not mere opacity.** Arith is `Pure`,
  so it emits `[]` on BOTH machines ⇒ its TRACE contribution is trivially `[]`.
  Arith's value matters to the observable ONLY when it feeds a downstream
  Emits/Halts SigOp argument — and there the flat machine decodes the sentinel
  `0`, not the true result. That discrepancy is what's swept into the
  `cata-correct` / `obs-correct-rest` postulates. So `block-semM` is needed to
  FIX the flat model, not merely to bridge to concrete.

Root cause: the arith verification was built **bottom-up as independent
islands** — each layer got a bespoke machine and a locally-sound proof, but no
**spine** was built to compose value → registers → asm → apex-trace. Classic
`feedback_prove_in_real_path_not_pocs` at architectural scale.

## Target architecture — one spine, ONE trusted boundary

```
source obs
  ≡  traces-agree           ← RUNG A: arith value = block-semM at the ABSTRACT layer (kill the sentinel)
flat-events (abstract, REAL arith values)
  ≡  concrete↔abstract refinement; arith slice = dispatch-arith-preserves + block-correct(on val)   ← RUNG B
run-events / concrete asm execution
  ≡  ISA / printer / loader trust — SHARED with all non-arith code (the ONE honest external seam)
hardware
```

Four principles:
1. **Kill the sentinel (rung A).** Give the flat arith SigOp a real value from the
   `SigOpInfo.semM` (`block-semM`) it already carries — read the input registers,
   apply `semM`. This unifies machines #1 and #2; arith value correctness now
   lives WHERE THE APEX REASONS, and `block-correct` becomes the load-bearing
   content of `traces-agree` for arith-fed observables.
2. **Define `val`, don't postulate it.** The concrete XInstr semantics must be a
   real function; then re-target `block-correct` (or a companion) to prove the
   `val`-machine arith equals `block-semM`, moving it off orphan `ArithAbsState`.
3. **Define `flat-trace` and decompose `asm-trace-correct` (rung B).** Replace the
   wholesale axiom with a real concrete↔abstract refinement whose ARITH slice is
   discharged by `dispatch-arith-preserves` + the value equality, and whose
   NON-ARITH slice is the ISA/printer/loader trust shared with every instruction.
   This is where the preservation tower stops being orphan.
4. **One trusted boundary** — the same one all non-arith code already relies on.
   No arith-specific trust.

## RUNG D — THE MEMORY LAYOUT MODEL (2026-07-28) + THE OPEN DECISION

### Why this section exists

Two findings, in order of severity.

**(1) The residual WF postulates were inconsistent, so the apex was VACUOUS.**
Probed in Agda (a scratch module that typechecked `⊥`; deleted after the fix):

| postulate | why it derived ⊥ |
|-----------|------------------|
| `dealloc-stack-full : ∀ fs n → stackSlot ≡ n` | `n` had no site condition ⇒ `stackSlot ≡ 0` AND `≡ 1` |
| `slot-read-in-frame : ∀ … slot i → fetch ≡ just i → slot < stackSlot` | `slot` unrelated to `i` ⇒ take `slot ≡ stackSlot` |
| `store-indirect-stack-disj : ∀ s hl → ∀ k → rsp s + 8k ≡ haddr hv hl → ⊥` | `s` arbitrary/unrelated to `fs` ⇒ pick one with `rsp ≡ haddr hv hl` |

One defect throughout: a fact about the state AT A SITE, stated over arbitrary
states/indices. **Suspect shape: a universally quantified variable that appears
ONLY in the conclusion.** All are now conditioned on the SITE
(`fetch prog (fpc fs) ≡ just <instr>`), the CORRESPONDENCE (`CompiledCorr`, which
pins `%rsp` to the current frame base) wherever an x86 state appears, the
instruction's OWN payload (the enumerated `slot-of`), and heap liveness (`HDom`).
**Re-run the probe whenever a residual is added** — instantiate the cluster at
`x86-64-frame-semantics refl`, apply the residual twice at different indices (or
at a hand-built `X.mkstate`), and try to typecheck `⊥`.

**(2) There was no memory-LAYOUT model at all.** `entry-view` put the heap at
address 0 and `entry-frame-base` put the stack at 0, so entry stack slot `k` and
heap cell `(block 0, offset k)` were the SAME x86 address — every heap/stack
disjointness assumption was false in the apex's own instantiation.

### The model: opposing growth (decided 2026-07-28)

The heap bumps UP from its base (`add r15, n*8`; `FlatCorr.r15-eq` already says
`%r15` IS the frontier), the stack grows DOWN (`sub rsp, n*8`), and they grow
towards each other. Consequences, all of them deliberate:

- **No maximum stack depth is needed** — and it is not knowable anyway: frame
  sizes are static but recursion depth is not, and a SigOp/interpretation's stack
  use is outside the model entirely.
- **No address is pinned** — only the ORDER matters, so the same proof serves
  systems with different memory sizes.
- The cost is a per-allocation ROOM premise, i.e. **memory exhaustion** (OOM /
  stack overflow) — a real runtime failure mode, the same honest class as the
  `conc-fuel` step budget.

### Step 1 — the entry layout (LANDED, `4e70eec3`)

`X64.initState` has `%rsp ≡ X64.stack-top`, one opaque postulated constant (what
the loader hands `main`; `_start` likewise points `%r15` at `once_heap_base`).
The heap base stays 0 WLOG (addresses are ℕ; only the order matters), which is
why `0 ≤ stack-top` needs no assumption. `entry-frame-base` now says the abstract
entry frame's base IS `stack-top`. Opacity is also what keeps the room premises
consistent: "n words fit" cannot be refuted.

### Step 2 — carry the separation, derive the disjointness (LANDED, `cb5b73b5`)

`FlatCorr` gains ONE field:

    sep : hfront hv ≤ X.readReg (X.State.regs s) rsp

With `HeapView.dom-below` (a live cell is strictly below the frontier) every
disjointness fact is transitivity: live heap `< hfront ≤ %rsp ≤ %rsp + 8k`.

- DERIVED, no longer postulated (4): `store-indirect-stack-disj`,
  `store-indirect-suc-stack-disj`, `store-at-slot-stack-disj`,
  `push-frame-heap-disj` — `above-frontier-disj` + two wrappers in ConcFlatSim.
- ASSUMED instead (4): `heap-room`, `stack-room`, `frame-room`, `pop-room`.
- Re-established once per step: 32 `sim-*` (all but five transport it unchanged),
  10 inline `FlatCorr`s in FlatSimulation, 4 block-steps thread a room premise,
  apex exhibits `sep = z≤n`.

### Step 3 — LANDED 2026-07-30: option (a), the ghost high-water mark

Decided as recommended, and CHEAPER than estimated: the mark lives INSIDE the
carried view instead of becoming a new index, so the ~40-site index pass never
happened. `HeapView` is now the whole MEMORY view.

- `HeapView` gains `lo` (the lowest `%rsp` ever reached) + the law
  `front-lo : hfront ≤ lo`. `FlatCorr.sep` is REPLACED by `lo-le : lo ≤ %rsp` plus
  `untouched : hfront ≤ a → a < lo → readMem a ≡ nothing`; the old `sep` survives
  as a DERIVED top-level function (`≤-trans front-lo lo-le`), so every
  disjointness consumer is untouched.
- `descend-view hv lo'` lowers the mark; `instr-alloc-stack` and
  `instr-push-frame` now land at the DESCENDED view (`BlockStepAt hv (descend-view
  …)`, `ccc-step-bs` was already view-polymorphic — dropping the explicit `{hv}`
  at those two dispatch sites is the whole wiring). The dispatcher picks
  `lo' = lo hv ⊓ rsp-post` and spends `stack-room` / `frame-room` on
  `hfront ≤ lo'` via `⊓-glb`. Lowering is a WEAKENING of `untouched`, which is why
  the prologue may write below the old `%rsp` (the saved `%rbp` lands at or above
  the new mark).
- `untouched` is preserved by every writing step: heap writes are below `hfront`
  (`dom-below` — `untouched-heap-store`), stack writes at or above `lo`
  (`untouched-stack-store`). `enc-desc` / `enc-desc-maybe` (all `refl`) carry the
  encoding across a descent — needed because `enc-sv hv v` on a VARIABLE `v` is
  stuck and stuck applications compare argument-wise.
- **`alloc-heap-fresh-x86` RETIRED (33 residuals, was 34)**: `heap-room` is now
  measured against `lo` instead of `%rsp`, which puts the fresh block inside the
  virgin region, so its concrete freshness is a THEOREM (`sim-alloc-heap` derives
  the old `fresh-x86` premise internally).
- **PROBE FINDING (the 2026-07-28 recipe, applied to step 3)**: `pop-room` as
  `lo ≤ rbp + slot-size` would have been INCONSISTENT with `pop-frame-saved`
  (a mapped cell at `[rbp]`) at `rbp ≡ lo ∸ 8` — the cell would be mapped and
  virgin at once. It is now stated at `%rbp` itself, which is also the true fact
  (the mark is below the callee's `%rsp ≤ %rbp`).
- **`alloc-stack-fresh-{abs,x86}` STAY, deliberately.** They are not consequences
  of the mark: a RE-ENTERED frame is below it and keeps the previous callee's
  values on both sides. They are false together (they agree), and deriving the
  agreement needs the abstract stack memory to be ADDRESS-keyed rather than
  `(Frame, Slot)`-keyed — the natural successor step, bigger than this one.

Green: the whole flat↔x86 cluster + `ArchCorrectness.agda` (all three arches) +
`agda-safe.sh certified`. `make malonzo` / `cabal test` / exit tests stay the
pre-merge gate (proof-only change).

### Step 3 (superseded by the above) — the OPEN DECISION as it stood

The original step 3 ("turn the freshness pair into the AGREEMENT form via
`stack-eq`") **does not work as stated**. The problem is not the live window: it
is that **dead memory keeps its contents on both sides**, and neither `sep` nor
`stack-eq` says anything about that region.

- A deep call that returns leaves written cells BELOW the current `%rsp`. The
  heap can later bump into that region, so `alloc-heap-fresh-x86` ("the fresh
  block is unmapped") is false in general — and the fresh cells ARE in the
  extended view's domain, so `heap-eq` demands exactly that.
- A re-entered frame is the SAME `Frame` value abstractly, so both machines see
  the previous callee's values: `alloc-stack-fresh-abs` and `-x86` are false
  TOGETHER (they agree, which is why nothing has broken yet).

**Option (a) — ghost high-water mark (RECOMMENDED).** Index the correspondence by
`lo`, the lowest `%rsp` ever reached (monotone); replace `sep` with
`hfront ≤ lo ≤ rsp`; add `untouched : hfront ≤ a → a < lo → readMem a ≡ nothing`.
Kills `alloc-heap-fresh-x86` outright once the room premises are measured against
`lo` instead of `rsp`. The alloc-stack pair still needs either a dead-cell
agreement clause or to stay a premise. Cost: another index through
`FlatCorr` / `BlockStep` / `CompiledCorr` (~40 sites), mechanically the same shape
as the `sep` pass. This is the CompCert treatment: unwritten memory is a property
of the memory model, not of the domain.

**Option (b) — domain-on-first-write.** A heap cell enters `HDom` when the
abstract machine first WRITES it, not when its block is allocated. Then `heap-eq`
never mentions a fresh cell and `alloc-heap-fresh-x86` disappears with no new
index. Cost: the store sims must EXTEND the domain (today only `alloc` does), and
reads of unwritten cells become the already-handled `*-bad` divergence. Leaves the
alloc-stack freshness pair postulated.
