# Plan 0.36 — General catamorphisms, proven by SigOp-trace preservation

> **Strictly top-down. No middle-out.** We define the cata at its *full*
> generality — **effectful algebra, arbitrary polynomial functor** — from the
> very first line, because that is the only *correct* definition. A "pure cata"
> is not a first milestone; it is the degenerate case where the emitted event
> list is empty and the fold's value is consumed by an outer SigOp. Narrowing the
> definition first (pure / exit-code-only) and widening later is exactly the
> shifting-definition disease that caused the existing mess: the machine model
> and the cata definitions were rebuilt three times under the proofs, so every
> "successful" proof died with the definition it was written against.
>
> **No parallel structures.** We work only in the real codegen/proof path;
> codegen and proof move together; every module is consumed by the theorem above
> it; obligations are allowed only if sound, provable, on the path, and
> named/visible (never a catchall sink).

## Why M1-first (pure cata) would repeat the mistake

If correctness is first defined over the narrow observable (exit code, no
events), then `obs`'s Cata clause, the machine trace, the correctness statement,
and even "what a finished codegen is" all get shaped around that narrow case.
Widening to effectful later means *redefining* them — i.e. the earlier proofs
were about the wrong definition. **Define once, at full generality, and prove
against that.** This is the whole lesson of the cata mess.

## The mess we are replacing (verified fossils, all to be deleted)

- `CataLayer` / `RecTrace` — ~2500-line WF proof of `IRResultAWF(Cata)` over
  **loop-blind `exec-trace`** (`exec-abstract (instr-ctrl _) = identity`); stands
  only on **12 + 11 `SMP.!!` holes**; reached only for nested catas.
- `ir-to-trace-correct (Cata …)` → `{-# CATCHALL #-}` →
  `ir-to-trace-correct-non-layer0` postulate — what the live grand theorem
  actually leans on for a top-level cata.
- `rec-scheme-semantic = SMP.!!` (`RecSchemePostulates.agda:76`).
- `StraightIR` precondition on `compile-correct-flat`
  (`CompileCorrectFlat.agda:128`) — **excludes Cata from the apex theorem**.
- `obs n c x = ([] , just (eval c x))` (`TraceDenote.agda:70`) — catchall gives
  Cata an **empty** trace (wrong for an effectful cata).
- `ir-to-trace' (Cata _ alg)` (`IRToTrace.agda:429`) — **ignores the functor
  witness**; hard-wired to the Nat/list shape (one recursive child, binary tag);
  **wrong for any non-Nat functor** (e.g. a tree with two recursive positions).
- Orphans imported by nothing: `NatCataProof`, `RecSchemeProof`.

The one survivor we build on: **`exec-flat`** (0.32) — a flat pc/fuel/jump
machine that matches the targets and *runs the loop*. It is the final machine
model. No new machine model will be introduced.

## North star — the correctness statement (full generality)

Correctness is **SigOp-trace preservation**, the apex claim of
`Once.Verified.Compile.correct` (see `Once.Verified.Behavior`: programs don't
return; the observable is the *ordered sequence of SigOp calls with their
arguments*; exit code = arg of `linux.exit`). The cata is a node that must become
covered under this theorem, **at the full `List SigOpEvent` level**:

For every `wf : WellFormedF F`, algebra `alg` (possibly effectful), and input `x`:
```
machine-trace (exec-flat (compile (Cata wf alg)) … x)   ≡   obs (Cata wf alg) x
        -- events (name+arg, in fold order) AND the resulting value
```
stated over `exec-flat`, heap mode, by μ-induction on `x`. The existing apex
`Behavior = Maybe ℕ` connects via the `exitCodeOf` projection — the cata theorem
itself lives at the richer trace level so it is **non-vacuous for effectful
algebras**.

`obs` already returns `List SigOpEvent × Maybe value` — it is *already*
trace-valued; only its Cata clause is wrong. The machine side is *not* yet
trace-valued; making `exec-flat` emit `SigOpEvent`s is foundational here.

## "General" has TWO axes: functor AND algebra (corrects a recurring confusion)

`Cata : WellFormedF F → IR (⟦ F ⟧T A) A → IR (μ-type F) A`. The algebra is **any
closed `IR (⟦ F ⟧T A) A`** — i.e. **any function of type `⟦ F ⟧T A → A`**. So
"general cata" means general along *both* axes:

1. **General functor** `F` — the codegen issue (`ir-to-trace` is Nat-shaped).
2. **General algebra** — the algebra is an ordinary function: a named top-level
   definition, an arith expression, a `case`/`compose`, an **effectful** body
   that calls a SigOp, even another `cata`. Anything that elaborates to a closed
   `IR (⟦ F ⟧T A) A`.

**The backwards design we are correcting (recurring confusion — settled
2026-06-07).** The frontend currently elaborates `cata alg` only when `alg`
matches a hard-wired point-free morphism *vocabulary* — `morphRaw?` in
`Once.TypeCheck.Morph` accepts exactly `id`/`fst`/`snd`/`inl`/`inr`/`terminal`/
`initial`/`case`, nothing else (`checkCataC` then runs `morphToIR`). Anything
else → `BuiltinTypeMismatch "cata"`. **This is implementation-driven spec, upside
down:** it lets a fixed grammar dictate what an algebra may be, instead of "any
function of the algebra type." It is *also* fundamentally incompatible with
effectful-from-the-start — an algebra that calls `emit.int` (or any SigOp, or
references a named helper, or does arith) can **never** be a `morphRaw?` form, so
the two issues share one root.

**This is exactly what the Phase-0 baseline confirmed (2026-06-07):** all nine
value-into-effect programs **parse**, then fail at elaboration with `cata:
expected type mismatch` — because their algebras (`case zeroI incI`,
`case id addPair`, …) use named arith helpers, which `morphRaw?` rejects. The
programs are *correct*; the frontend is *backwards*. The north-star tests did
their job — they drove the confusion out before any proof was built on it.

**The fix (top-down — the algebra is an ordinary function).** `cata`'s argument
is **not special**: it is an expression of type `⟦ F ⟧T A → A`, elaborated by the
**general elaborator** like any other function — a named top-level definition
(`cata sumAlg`), a partial application (`cata (foldWith x)`), a `case`/compose,
arith, an **effectful** SigOp-calling body. It is made **closed** by the
compiler's **existing inlining/resolution pass `resolveExpr`** (`Compile.agda`),
which already substitutes named definitions, specializes, and reduces partial
applications of known values to closed terms — exactly the inlining that turns
`cata sumAlg` / `let x = … in cata (func x)` into a closed algebra. `morphRaw?` is
retired as the gate (it may survive only as an internal point-free fast-path).

**The one real restructure (why this is architectural, not a trivial edit):**
today the algebra-IR is built *during* elaboration (`checkCata` emits
`lift-morphism (Cata wfF algIR)` from the `morphRaw?` vocabulary), but inlining
happens *after* (`resolveExpr`). So `cata sumAlg` can't work until the **`IR.Cata`
node is built in the surface→IR lowering pass (post-resolution)**, not in
`checkCata`. That is the move: elaborate+resolve the algebra as a normal closed
function, then lower it to `IR.Cata` on the **same path the whole program uses**
(no parallel lowering, no special vocabulary). `cata`'s realm follows the
algebra's (pure→pure, effectful→effectful).

**Parametrized folds and runtime closures — NOT an IR-level gap.** An algebra
that depends on an outer runtime value (e.g. `λ x → cata (λ l → l + x) xs`, `x` a
runtime arg) is a *valid and common* structured-recursion pattern, but in a CCC
it is **derived, not primitive**: it is a **closed-algebra cata whose carrier is
an exponential** `X ⇒ A` — *fold to a function* with a closed algebra
`F (X ⇒ A) → (X ⇒ A)`, then `apply … x` (the captured value becomes the result
function's argument, not a free variable). So the IR cata algebra is **always
closed**; parametrized folds are expressible *today* (once general algebras work)
in fold-to-function form. The **only** deferral is optional **surface sugar** that
would auto-lift a captured-variable lambda into that form — not a codegen or
closure-realm-in-the-loop need, and nothing the 0.36 test matrix requires.

**Anti-pattern (added):** ✗ gating the cata algebra on a fixed morphism
vocabulary, or treating the algebra slot as anything other than a normal
function expression. The algebra is *any* function `⟦ F ⟧T A → A`, made closed by
the standard inliner.

## Phase 0 — The north-star test suite (FIRST; the coverage contract)

Before any definition or proof, write the covering set of cata `.once` programs
with their expected observables. These are the contract everything is judged
against; they start RED. They must be **correct and covering** across two axes:
**(i) functor shape** and **(ii) effect behaviour**.

### Prerequisite wiring (so effect-emitting catas are writable) — test-harness-local

Today only `arith.*` (Pure) and `linux.exit` (Halts) are registered SigOps; **no
`Emits` op exists** (`classify-name` maps only `linux.exit`). Effect-emitting
catas need one — but it does **not** belong in `Strata/Interpretations` (don't
pollute Strata with test-only ops). Define a **test-harness-local** minimal
`Emits` op `emit.int : Int → Unit` (`classify-name {Unit} "emit.int" = Emits
refl`):

- **Runtime = nop.** The abstract machine already handles `Emits`
  (`exec-sigop-output-of (Emits _) _ _ = unit-storedvalue` — output unit, don't
  halt); no real syscall needed.
- **Contract = postulated `PreservesCCC`.** A nop genuinely preserves CCC state,
  so the 6-field `PreservesCCC` (`SigOp/Helper.agda:66`) is trivially true; we
  *postulate* it for the test op (sound, on the path — consumed by the test
  programs' compile-correctness, named/visible; admissible under the discipline
  below).
- **Observable = the trace, not stdout.** The effect shows up as a `SigOpEvent`
  in `obs` (source) and in the trace-valued `exec-flat` (machine). The
  effect-emitting test asserts the **source trace** `obs (program) tt ≡ [emit
  x₁, …, emit xₙ]` at the Agda level (and the binary runs to a clean exit); the
  machine-trace ≡ source-trace equivalence is what Phase 3 proves generally. No
  stdout-capture harness, no real write syscall.

The one piece that *does* stay foundational: making **`exec-flat` trace-valued**
(record a `SigOpEvent` when it executes `instr-sigop`) — the depth-dependent
event sequence of a fold is only knowable by observing the loop run, so this
cannot be read off the static trace.

Organized by the dimension the traversal codegen turns on (number/placement of

## Effectful algebras = grade-polymorphic composition (D032, NO new decision)

> Settled 2026-06-08 by reading D032 + D046, not by inventing anything. The
> effect-emitting catas hit "effectful algebra realm"; the principled answer was
> already decided.

**The mathematics.** The IR is **one** category `C`: the free (bi)CCC-with-μ
generated by the CCC structure **plus the SigOps as morphism generators**. There
is **one** composition `∘`. "Pure" is a **wide subcategory** `C_pure ↪ C`
(identity-on-objects, closed under `∘`): the CCC structure **plus the
Pure-`EffectShape` SigOps** (`arith.*`). The effectful generators are the
non-Pure shapes (`Emits`, `Halts`). A morphism's purity is membership in
`C_pure`; it is **not** a separate hom-set, monad, or Kleisli category — so it
needs no separate composition.

**This is literally D032's stated rationale** (#2 "uniform composition, no need
for two operators"; #4 "one unified category, not pure vs Kleisli"; #5 "Arrows ⊃
Monads"; #1 lists `compose=>>>`, `pair=&&&`, `case=|||` as the arrow ops). **D046
(Plan 0.5.1)** then merged the `Eff` type constructor into the graded arrow
`A ⇒[ mk-kind q π ] B`. What drifted is the old-branch *implementation* (D045
added `>>>`/`effCompose` as a *second* operator beside `.`, contradicting D032
#2) — **not** the decision. So: **no `effCompose`, no `>>>`, no cata-specific
decision.** We implement D032 faithfully.

**`EffectShape` IS the per-generator grade.** `EffectShape` (Pure/Halts/Emits)
is simultaneously (i) the abstract machine's per-generator observable classifier
(for the trace) and (ii) D032's type-level purity, per morphism, via the join.
Same classification at two scales. So the purity grade is *derived* from
`EffectShape`: `Pure → pure`, `Emits/Halts → eff`; a morphism's grade is the
**join** over the generators it uses. (Correction to an earlier slip: "uses a
SigOp ⇒ effectful" is WRONG — `arith.*` are Pure generators in `C_pure`, which
is why the value-folding catas are pure and exit fine.)

**The implementation (frontend only — no IR, codegen, or proof change).** The IR
is grade-erased (`∘`/`case`/`Cata` already operate on SigOp-containing
morphisms), so:
1. Make the surface combinators **grade-polymorphic**: `compose`, `case`, `pair`,
   and **`cata`** currently pin their arrows to `⇒[q pure]` (e.g. `cata`'s
   algebra at `Surface/Syntax.agda`); generalise to `⇒[q π]` with the result
   grade = **join** of the parts'. `cata`'s realm follows its algebra's grade.
2. **Derive the grade from `EffectShape`** when typing a SigOp: `Pure → pure`,
   else `eff` (via `classify-name`). `arith.*` stay pure; `emit` is `eff`.
3. **Wire the test-local `emit`** (Phase 0 prereq): `classify-name {Unit}
   "test.emit" = Emits refl` (`Once.Arith.SigOp.Builders`);
   `Strata/Interpretations/Test/Emit.once` (`signature emit : Eff Int Unit`) +
   `Emit.x86_64` (`once_test.emit:` nop `ret` — runtime = nop, observable = the
   trace). Runtime codegen is the existing `call once_<sym>` (identical to the
   arith SigOps that already work).
4. **Rewrite the two `*-emit` tests point-free** in morphism style (no `effApp`
   suspension): `emitCons = compose emit fst`, `emitNil = const unit`-style, so
   `cata (case emitNil emitCons) : Mu F ⇒[eff] Unit` — a truthful contract. The
   effects are *sequenced* into `main`, not discarded (an `eff` morphism may not
   be dropped by `const`; the grade forbids exactly the law that would erase the
   trace — which is the smell in the original `const 7 (emitAll xs)`).

Catas inherit all of this — a cata is a morphism builder, the grade joins
through. No `cata-correct` change; effectfulness is just `instr-sigop` nodes
already in `at`. This is the "go for the abstraction, don't fight the proof"
move: parametrise over the grade the IR already erases.

**IMPLEMENTATION STATUS (2026-06-08).** DONE + green: `Purity` join (`_⊔p_`),
and the **surface half** — `Surface.cata` node grade-polymorphic (`⟦F⟧A ⇒[Many π]
A → μF ⇒[Many π] A`), all 4 surface modules thread π by inference (`curry`/`apply`
already kind-polymorphic), `cata-elaborate-correct` restated π-poly. The typing
RULES (`t-cata/case/compose-check`, single-π) also typecheck.

**BLOCKER (real, needs a design step — stopped here).** The **TypeCheck-side
elaborator** can't yet build an effectful cata algebra, because **effectful
point-free morphisms have no uniform surface representation to extract an `IR`
from.** `extract-morph` (the morphism-realm bypass that `checkCase`/`checkCompose`
use to emit `lift-morphism (IR.case / m∘m)`) only matches a **pure**
`lift-morphism m : Expr (A ⇒[Many pure] B)`. But an eff arm is heterogeneous —
`emit` elaborates to a `sigOp` node, `arr f` to `arr'`, a compose-result to
`app`/`effApp` — with **no eff-`IR` extraction path**. So `case (arr emitNil)
(compose emit (arr fst))` can't be lowered to a closed `IR (⟦F⟧Unit) Unit` by the
current machinery. This is exactly `docs/design/effect-composition.md`'s open
area (point-free effect composition) hit concretely. The grade-poly *typing* is
settled; the *eff-morphism surface representation* is the open design piece —
options: (a) a uniform eff-morphism surface form + `extract-morph`-for-eff
(peel an `arr'`/canonicalise sigOp/compose into an extractable `IR`), or (b) eff
closure-realm combinators (`specCase`/`specCompose`/apply at `eff`). Neither is
mechanical; needs a focused representational design before the elaborator +
completeness can be finished.

**DESIGN CHOSEN (2026-06-08): (a), derived-by-threading — purity is the sibling
of quantity.** The arrow kind is `mk-kind Quantity Purity`; purity must be
handled exactly like quantity/usage, the template already proven to work:
- **Source at the leaves.** A SigOp's surface grade = its `EffectShape`
  (`emit` = eff, `arith.*` = pure) — the analog of a variable being the leaf of
  the usage discipline. `emit : Eff Int Unit` already declares eff via its
  signature.
- **Thread + join through combinators.** `compose`/`case`/`cata` join the grades
  (`_⊔p_` is the purity analog of usage's `⊔ᵘ`). One category, one composition —
  no `effCompose`, no closure-realm bifurcation (that would be "linearity gets
  its own category", which Once rejects).
- **Erased downstream.** The IR carries no grade (as the runtime carries no
  quantity); the grade is a compile-time refinement read for effect-law reasoning.
- **Soundness = the leaf grade is fixed.** `emit`'s leaf grade *is* eff, so an
  effectful morphism can never typecheck at a pure arrow — D032's guarantee from
  the same machinery as linearity. NOT a post-hoc `ir-purity` scan, and NOT a
  grade inferred from the expected type (that would let eff masquerade as pure —
  unsound).
- **Representation.** Pure morphisms keep `lift-morphism` (the pure-subcategory
  injection, grade pure). Effectful ones get an eff sibling / grade-indexed
  morphism node wrapping the *same* grade-erased `IR.case`/`∘` — **fused, not
  closures**; `extract-morph` handles both. Elaborator selects by the threaded
  grade; the type system forces it. Best codegen (direct dispatch + `call
  once_<sigop>` per layer, as the green pure catas), cleanest proofs (one fused
  path), most ergonomic (no `arr` ceremony).
Order: (1) source the SigOp leaf grade from `EffectShape`; (2) eff morphism node +
grade-poly `extract-morph`; (3) grade-poly `compose`/`case`/`cata` elaborator
clauses producing the fused eff node; (4) completeness/correct threading; (5)
emit wiring + point-free tests + `obs` fold. Keep pure `lift-morphism` sites
byte-identical.

### CURRENT UNDERSTANDING — concrete representation (building 2026-06-08)

The representation is a **grade-indexed `lift-morphism`** (purity as an index, like
quantity — NOT a separate constructor, NOT a closure):
`lift-morphism {π} : IR A B → Expr Γ zeroUsage (A ⇒[ mk-kind Many π ] B)`. Today
it is pinned `pure`; the index makes it carry the threaded grade. Pure sites
infer `π = pure` (byte-identical). `extract-morph` generalizes to any `π` and
returns the grade.

**Key sub-finding (the real depth):** an effectful SigOp used as a *morphism
value* currently elaborates to a **closure** `curry (SigOp si ∘ snd)` (for
first-class/apply use), which `extract-morph` can't see. For point-free morphism
use (cata algebras), it must instead be the **direct** morphism
`lift-morphism {eff} (SigOp si)` (the `SigOp si : IR Dom Cod` IS already a direct
morphism; just wrap it as an eff lift-morphism). The leaf grade `eff` is FIXED by
the SigOp's signature (`emit : Eff Int Unit`) / `EffectShape` — never inferred
from the expected type (that would let eff masquerade as pure). Then:
- `arr` on a pure `lift-morphism {pure} m` → `lift-morphism {eff} m` (same IR).
- `compose`/`case` fuse `lift-morphism {πf} m_f` + `lift-morphism {πg} m_g` →
  `lift-morphism {πf ⊔p πg} (IR.∘ / IR.case)`.
- `cata` wraps the fused algebra; grade flows to the cata's realm.

So the threading is: SigOp signature/`EffectShape` fixes the leaf `π`; `arr`/
`compose`/`case` join; `lift-morphism {π}` carries it; the IR stays grade-erased.
This is exactly the usage discipline with `π`/`⊔p` in place of `Ψ`/`⊔ᵘ`.

### METHODOLOGICAL LESSON (2026-06-09) — "which postulate hid the bug?"

When a *verified* program typechecks but returns the wrong result (the eff test
exited 64, not 7), the discipline is NOT to debug the `.s` — it is to find the
**false postulate that laundered the bug past the proof**. Here it was
**`generic-semI`/`generic-semM`** (`Once/Arith/SigOp/Builders.agda`, `postulate`).
A short-lived `extract-morph-eff` clause `sigOp name → IR.SigOp (generic-info
name)` turned an INTERNAL user function (pre-resolve also a `Surface.sigOp`) into
an EXTERNAL SigOp with those postulated semantics — so "this denotes `seven`"
became "`generic-sem "seven"` ≡ `seven`", unrefutable (postulate) and false
(`once_seven` is a closure-returner). Removed the clause → the unsoundness became
an honest type error (the fusion now only extracts genuine `lift-morphism`s).
Formal green; all 9 pure cata shapes still run correctly (no regression).

### FAITHFUL COMPLETION (the remaining work, no postulate-laundering)

The effectful cata now does NOT compile (honest — `emit` isn't faithfully
extractable yet). Two faithful pieces remain:
1. **Genuine external sigOps → direct `lift-morphism (SigOp …)`.** A *qualified*
   ref (`emit@E`, `exit@S`) IS a real external SigOp; `SigOp (generic-info name)`
   is its faithful IR and `generic-sem` its *legitimate* postulated contract (the
   plan already sanctions postulating the test op's `PreservesCCC`). Emit it as a
   direct `lift-morphism` (at `t-var-qualified`, arrow case) instead of the
   closure `curry (SigOp ∘ snd)`. RUNTIME-EQUIVALENT (both elaborate to the same
   `curry (SigOp ∘ snd)` as a value; fusion uses the bare `SigOp` = `call
   once_<name>`), so `exit` is unaffected (validate via the pure-cata regression).
   This is the faithful version of the removed hack — it works for external
   sigOps precisely because they're genuinely external (the postulate is their
   honest contract), and is BANNED for internal functions (the postulate would
   lie). Makes the cata ALGEBRA fuse `emit` faithfully.
2. **`main` effect-sequencing / internal-function composes.** `main` point-free-
   composes internal functions (`emitAll` the cata, `getXs`, `seven`), which
   compile to closure-returners — not fusable. Faithful options: inline them
   before fusion, or an eff closure-apply fallback (`specCaseEff`/`specComposeEff`
   + apply-at-eff) that genuinely calls the closures. This is the broader
   effect-composition.md "point-free effectful program structure" area (value

### Why the linear scheme doesn't extend

Linear folds have a single spine: descend pushes a payload list, ascend pops it
once. A branching node has 2–3 recursive children, so the fold is a genuine
**post-order tree traversal**: every child must be fully folded before its
parent combines. The descend/ascend pair can't express "fold all children, then
combine" for a tree.

### Scheme: iterative post-order with two linked stacks

The canonical iterative catamorphism. `cata alg x = alg (fmap_F (cata alg) x)`
(`out` = identity, heap-identity `In`). Two heap-linked stacks (same no-ISA
principle as Tier-1; **not** `lea-indexed`):

- **task stack** — 3-cell nodes `[phase-tag, node-ptr, prev]`; `phase-tag` 0 =
  VISIT, 1 = EVAL. Bottom sentinel `prev`/top init = `SV-Tag 0` (null) for
  empty-detection.
- **value stack** — 2-cell nodes `[folded-A, prev]`; holds children's `A`
  results awaiting their parent's combine.

```
push VISIT(root)
loop:
  if task-stack top is null  → break          -- empty ⇒ done
  pop (phase, node)
  if phase == VISIT:                            -- c-branch-tag-zero on phase cell
     push EVAL(node)
     for each recursive (Id) child c of node, in REVERSE position order:
        push VISIT(c)
  else: -- EVAL(node)
     pop one value-stack result per Id child (REVERSE order: rightmost first)
     rebuild the ⟦F⟧A layer = node's constructor with K-payloads copied from
        `node` and Id-positions filled by the popped results
     r := alg(layer) ; push r onto value-stack
result := pop value-stack                       -- the root fold; → Output
```

Reverse-order child push ⇒ children VISITed left→right ⇒ results land so that
EVAL popping rightmost-first reconstructs left→right positions. Verified for
binary (pop r,l → `[l,r]`) and ternary (pop c,b,a → `[[a,b],c]`).

### The crux: functor-directed VISIT / EVAL codegen

Both VISIT (locate Id children) and EVAL (rebuild layer) are **compile-time
recursions over `F`** that emit runtime **tag-dispatched** node walks. Generated
per `F`:

- **sum `F ⊕ G`** → `instr-case-on-tag <F-branch> <G-branch>`; each branch does
  `load-indirect-suc ∷ mov-to-input` (descend into the payload pointer) then
  recurses into F / G. Nested sums (multi-ctor) ⇒ nested `instr-case-on-tag`,
  giving >2-tag dispatch + per-branch differing rec-counts (#8).
- **product `F ⊗ G`** (left-assoc, so the node is a pair `[F-part, G-part]`;
  `K`/`Id` leaves sit at pair cells, deeper products chase sub-pair pointers via
  `load-indirect`/`-suc`) → handle the F-part then the G-part; thread cell
  offsets (`sucLoc` chains for the left-assoc nesting).
- **`Id`** (a recursive child pointer): VISIT pushes it as a task; EVAL writes a
  popped value-stack result into this position of the rebuilt layer.
- **`K c`** (a payload word): VISIT ignores it; EVAL copies it from `node` into
  the rebuilt layer unchanged.

So a `Functor`-indexed helper produces, for each constructor leaf, straight-line
access (VISIT: push the Id children) and straight-line rebuild (EVAL: alloc the
sum/product cells, copy K-payloads, splice popped results), with the sum levels
wrapped in `instr-case-on-tag`. This is the bulk of the work.

### Registers / control (ISA-compatible — no extension)

- Loop is stack-emptiness-driven (no countdown), so **Scratch is free** for
  empty-detection: load task-top into Scratch, `c-branch-scratch-zero` → break.
- Phase dispatch: `c-branch-tag-zero` on the popped task's phase cell.
- Slots: task-top ptr, value-top ptr, node cursor, plus per-build temps
  (`pstash`/`sstash`-style). All within the function frame budget (`ir-stack-budget`).
- `alg` runs on the rebuilt layer exactly as in Tier-1 (`at`, duplicated per
  constructor branch — label-free for the test algebras; nested-cata algebras
  remain the shared known limitation).

### Open sub-decisions to settle during implementation

1. **EVAL re-dispatch vs recorded shape.** EVAL re-reads `node`'s tag to pick the
   rebuild (idempotent, simplest) — chosen over recording arity in the task.
2. **node-tree (#6) payload-between-children** `Id*(K Int*Id)`: confirms the
   product walk must interleave K-copy and Id-splice by position, not assume
   "payload first" — the per-leaf straight-line rebuild handles this naturally.
3. **Layer alloc count.** Each EVAL allocs the constructor's sum+product cells
   (O(nodes) total). Acceptable; a Plan 0.37-style chunk/reuse pass is a later
   optimization, not correctness.

### Validate (runtime, x86-64)

`leaftree-sum`→42 (40+2), `ternarytree-sum`→42 (40+0+2), `nodetree-sum`,
`multictor-size`→ its node count; deep tree (heap path); then the effect-emitting
tree (pre/in-order) once Phase 1 trace-valued `exec-flat` lands.

**Phase 2b — functor-general codegen.** Make `ir-to-trace' (Cata wf alg)`
traverse an arbitrary `WellFormedF F` (K / Id / ⊕ / ⊗, **multiple recursive
positions**), driven by the functor witness, heap-mode allocation, lowering to
flat `instr-ctrl`. Codegen and the Phase-1 spec move together.

Validate at runtime against Phase 0 (this changes the **live binary**):
- All value-into-effect rows reach their exit codes (Nat/List/Tree).
- All effect-emitting rows emit the **correct ordered event stream** (tree

- Deep inputs run (heap allocation path exercised).

## Allowed proof obligations (the discipline)

A `postulate`/`SMP.!!` is admissible **only if** (1) sound and provable from
context, (2) on the real path — consumed by the theorem above it, (3) named and
visible — never a catchall. Planned standing obligations: `cata-correct`
(transient — discharged in Phase 3) and **alloc-heap block-step** (external —
= 0.35 M6, cited; the cata's ascend allocates `In` nodes).

## Anti-patterns — explicitly banned (each caused the mess)

- ✗ A pure-first / exit-code-only milestone (middle-out; narrows the definition).
- ✗ A second machine model (`exec-flat` is final).
- ✗ A WF-layer bolt-on stating cata over loop-blind `exec-trace`.
- ✗ A standalone `Examples/` POC ([[feedback_prove_in_real_path_not_pocs]]).
- ✗ A catchall absorbing cata into one postulate.
- ✗ Codegen and proof drifting apart — they move together.
- ✗ Gating the cata algebra on a fixed point-free morphism vocabulary
  (`morphRaw?`). The algebra is *any* closed function `⟦ F ⟧T A → A` (named,
  arith, effectful, nested cata). Implementation must not dictate spec.
