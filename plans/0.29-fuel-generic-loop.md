# Plan 0.29 — Fuel-based generic loop construct for structural recursion

## Goal
Give the **abstract machine** a generic, fuel-bounded **loop construct**, prove
its semantics there once, lower it to each target, and bridge to targets with
the existing **`Corresponds`** simulation. Then wire `Cata` (and, later, the
other recursion schemes) through it so a real fold runs in the **live** codegen
path (`once build`). Concrete acceptance: `compiler/test/layer5-iseven.once`
exits **42** through `ir-to-trace → AbstractToX86 → Emit` (not the dead
`compile-ir` path), with no new parallel structure and no new trust postulate
beyond the existing recursion-scheme boundary.

## Why (the regression this fixes)
Plan 0.28 made catamorphisms surface-reachable: `layer5-iseven.once` now
**parses, type-checks, and compiles**. But it runs to the wrong exit code (99,
not 42) because the **fold loop is a stub in the live path**. Investigation
found **three parallel `Cata` structures**, which is exactly the pathology to
stop accreting:

| | What | `Cata` status | Binary uses it? |
|---|---|---|---|
| **A** | `compile-ir` (`CodeGen/Compile.agda`, r14 loop) + `CataIsEvenInduction` | **proven ∀-n** via x86 `Semantics` + `StepLemmas` (`isEven-2/3 = refl`) | **No** — retired path (`Target/X86-64.agda:24-30`) |
| **B** | `ir-to-trace → AbstractToX86 → Emit` | **`ir-to-trace' (Cata _ _) = []`** stub; `worklist-*` lowering also `[]` | **Yes** |
| **C** | `Dispatcher.run-wf → CataLayer.cata-dispatched-new` (abstract SlotMachine) | folds via meta-recursion, gated by **`rec-scheme-semantic = SMP.!!`** (`RecCoreWF.agda:234`) | the live `EndToEnd.compile-correct` is about **C** |

The fix is **not** to revive A (a bespoke `StepLemmas` proof per target breaks
the `Corresponds` pattern and must be re-proven for x86-64 / x86-32 / riscv64).
The fix is to put the loop **in the abstract machine** and refine to targets via
`Corresponds` — the same uniform bridge every other instruction uses.

## The pivot: fuel (per the SigOp precedent)
Fuel is what unlocked the SigOp trace-correctness proofs. The x86 model already
is fuel-based:

```
exec : ℕ → Program → State → Maybe State          -- Semantics.agda:370
exec zero    _    s = just s
exec (suc n) prog s = if halted s then just s else exec-cont n prog (step-not-halted prog s)
run = exec defaultFuel                            -- 10000
```

`execInstr` has a real `pc`, and `jmp/je/jne` resolve **label** targets via
`find-label`, including **backward** (loop) edges (Semantics.agda:189-275). So
the loop-capable execution model already exists on the target side. The abstract
side is the gap: `exec-trace`/`exec-abstract` (SMCore) are **total and
straight-line** (no fuel, no back-edges), and `DirectSimulation.exec-prog` (the
target side of `Corresponds`) is **also straight-line — it does not follow
jumps**. To put a loop under `Corresponds`, **fuel must become the shared
currency on both sides**.

## Design

### D1. Fuel-bounded abstract execution (mirror the x86 `Semantics` shape)
Introduce a fuel-bounded abstract execution that structurally parallels x86
`exec`: fetch-at-pc / step / `exec-cont` / fuel decrement, over `AbstractTrace`
treated as a label-addressable program. The abstract machine and the target then
have the **same execution shape** (pc + labels + back-edges + fuel), which makes
`Corresponds` a clean per-fuel-step simulation rather than a bespoke proof.

Considered (a) a full PC-based abstract machine vs (b) a localised fuel loop
construct. **DECISION (M1, settled): (b).** `exec-trace`/`exec-abstract` have
**43 consumer files**; changing `exec-trace`'s signature (option a) cascades
across all of them. Option (b) leaves `exec-trace` **unchanged**:

```
exec-abstract (instr-loop body) s alloc = exec-loop defaultFuel body s alloc
-- new mutual helper (with exec-trace), keeping exec-abstract total:
exec-loop : ℕ → AbstractTrace → LocState → AllocState → LocState × AllocState
exec-loop zero    body s alloc = record s { halted = true } , alloc   -- fuel-out
exec-loop (suc n) body s alloc =
  let (s' , alloc') = exec-trace body s alloc in
  if loop-break? s' then (s' , alloc') else exec-loop n body s' alloc'
```

- `exec-trace` and its 43 consumers are untouched (no signature change).
- The loop body sets a designated **break flag** (a register/slot) each
  iteration; `loop-break?` reads it; the x86 lowering's conditional back-edge
  tests the same flag, so abstract and target iterate in lock-step at matching
  fuel — the `Corresponds` per-fuel-step simulation closes (M3).
- Blast radius is the **new `AbstractInstr` constructor** (its exhaustive-match
  sites), NOT the 43 `exec-trace` consumers.

**Reuse the existing `defaultFuel`/`exec`/`StepLemmas`** — no second fuel model.

### D1b. Loop-private state lives in a `Scratch` register, not a slot (M2 decision)
The loop's counter/flag is **loop-private state that must persist across algebra
invocations**. Two homes were considered:
- **Slot below the frontier** — preserved by `PreservesCCC.prior-preserved` for
  free, but entangles with the frame-slot-budget/reclamation discipline. That is
  a **stack-mode** problem (in heap-only mode the stack scratch nets to zero);
  it also collides with an algebra that itself uses stack scratch.
- **Dedicated `Scratch` register** (mapped to callee-saved `rbx`, exactly what
  `compile-ir`'s proven loop assumed) — **DECISION**.

Why the register, and why it's cheap (measured):
- `Registers` gains one `scratch` field: **~zero cascade** (0 positional
  `mkRegs` sites outside SMCore; all other sites are record-updates).
- **No existing instruction writes a 4th register** → "every non-loop
  instruction preserves `Scratch`" is one trivially-true uniform lemma, not a
  per-SigOp obligation; `PreservesCCC` either gains a `preserves-scratch = refl`
  field (~11 trivial prover sites) or stays unchanged with the uniform lemma.
- `AbstractReg` +`Scratch` → `≟R` (10 localized cases) + `readReg`/`writeReg`;
  `Corresponds` +`rbx-val`/`rbx-eq` (it currently tracks only `rax`/`rdi`).
- **Mode-independent** (no frame-slot-budget entanglement) and the algebra
  provably can't clobber it. **Nested** schemes save/restore `Scratch` at loop
  boundaries (callee-saved `rbx` discipline — one transient slot at entry/exit,
  not state-across-iterations).

### D2. Generic loop construct (NOT cata-specific)
Add one **generic** structured-loop carrier to the live `AbstractInstr`
vocabulary (the live path is flat `AbstractTrace`; `TreeTrace` stays proof-side
to avoid promoting a second live structure). Shape, mirroring `instr-case-on-tag`
(which already carries sub-traces and lowers to `cmp/je/jmp/label`):

```
instr-loop : AbstractTrace → AbstractInstr    -- body re-entered until break
```

Reusable by `Cata`, `Para`, `Ana`, `Hylo` — each supplies a body; the
loop/label/back-edge lowering and the fuel semantics are shared.

### D3. Per-target lowering + `Corresponds` (the bridge we must NOT break)
- `compile-abstract`/`compile-trace-cnt` lower `instr-loop body` to
  `label L ∷ <lowered body> ∷ <conditional back-edge to L>`, reusing the exact
  `cmp/je/jmp/label` emission `case` already uses (x86-64; `unimp`/`ud2` stubs
  for x86-32 / riscv64 initially).
- Prove **`Corresponds`** between the abstract loop's fuel execution and the
  target's fuel execution, **once per target**, via `DirectSimulation`. This is
  the layer that currently uses straight-line `exec-prog`; D1 makes both sides
  fuel-based so the loop case closes.

### D4. abstract-loop ⟷ `eval` (prove the fold once)
Prove the abstract loop computes the catamorphism (`eval (Cata …)`) **once at
the abstract level** — ideally *discharging* `rec-scheme-semantic` rather than
adding a sibling postulate. The proven ∀-n structure already exists
(`CataIsEvenInduction`, `NatCataProof`, `RecTrace.cata-tree-μ`); port that
reasoning to the new abstract loop instead of to A's raw x86.

### D5. Wire `Cata` through the generic loop
`ir-to-trace' (Cata _ alg)` emits the NatF cata as: (1) **descend** —
`instr-loop` whose body is `case-on-tag` at `Input1`: `inl`→set `Scratch:=0`
(stop), `inr`→`Input2`++ (count) and follow child (`load-indirect-suc ∷
mov-to-input`, both existing); init `Scratch:=1`, `Input2:=0`; (2) `Scratch :=
Input2`, build the base `inl` layer, apply `alg`; (3) **ascend** — `instr-loop`
(break on `Scratch=0`) whose body rebuilds the `inr` layer `[1, Output]`, applies
`alg` (spliced trace), and `Scratch`--.

Implementation note: all the register pokes (`Scratch:=1/0`, `:=Input2`, `--`;
`Input2:=0`, `++`) fold into **ONE** new instruction `instr-reg-op : RegOp →
AbstractInstr` — register-only / no-heap-write, so its whole cascade **mirrors
`mov-to-output`** (trivial: `nothing/⊤/refl` + an `nhw-` constructor). x86
lowering: `mov/add/sub` on `rbx` (Scratch) / `rsi` (Input2). The pointer-follow
and tag-dispatch reuse existing instructions. So M5's new machinery is one
trivial-cascade instruction + the trace emission.

**Key realization (sharpens M3):** the descend body uses `case-on-tag`, which
*halts at the abstract level* (`exec-abstract`), so the abstract `exec-loop`
does NOT actually fold — it halts at the first tag dispatch. The **binary**
folds correctly because `compile-trace-cnt` lowers both `case-on-tag` and
`instr-loop` to real x86 (dispatch + back-edge); the abstract machine is the
straight-line/halt-on-control-flow model. So: **M5 (the binary running → exit
42) depends only on the x86 lowering, not the abstract `exec-loop` semantics.**
The abstract `exec-loop` earns its keep at **M3/M4** (giving the loop a real
abstract denotation to correspond to / discharge `rec-scheme-semantic`) — and
M3 must reconcile that the abstract body halts on `case-on-tag` while x86 folds
(i.e. M3 needs the fuel `Corresponds` over the *whole* `compile-trace-cnt`
lowering, not the per-instruction `compile-abstract` sentinels). Arbitrary-
functor traversal stays deferred (Plan 0.27 lineage); this targets linear `NatF`.

### D6. Consolidate — retire the dead `compile-ir` path
Once the live path folds and is proven, retire structure **A**: remove
`EntryPointCCC.compile = compile-ir` / `compile-correct` (the old verified-path
wire-up), keeping `compile-extracted`/`compile-correct-extracted` and the shared
helpers (`compile-sigOp`/`compile-const`) `AbstractToX86` still needs. Migrate or
delete `CataIsEvenCodegen`/`CataIsEvenInduction` so no example pins the dead
loop. **Order matters:** do this only after M4 (the live loop is proven), since
A holds the reference reasoning.

### D5b. Concrete `ir-to-trace (Cata _ alg)` trace (worked out, ready to wire)
With `instr-reg-op` (DONE, green machine-wide) the cata trace is:
```
-- DESCEND (Input1 = root μ-node; count into Input2; Scratch = continue flag)
  instr-reg-op scratch-one          -- Scratch := 1
  instr-reg-op input2-zero          -- Input2  := 0
  instr-loop                        -- break when Scratch = 0
    [ instr-case-on-tag             -- dispatch on tag at *Input1
        [ instr-reg-op scratch-zero ]                 -- inl: stop
        [ instr-reg-op input2-inc                     -- inr: count++
        , load-indirect-suc , mov-to-input ] ]        -- Input1 := *(Input1+8) (child)
  instr-reg-op scratch-load-count   -- Scratch := Input2 (depth → ascend counter)
-- BASE: build inl layer [0,0], Input1 := layer, apply alg → Output
  <build-inl-layer>  ++  alg-trace
-- ASCEND (break when Scratch = 0)
  instr-loop
    [ <build-inr-layer [1, Output]> , <Input1 := layer>
    , alg-trace                                        -- apply alg → Output
    , instr-reg-op scratch-dec ]                       -- Scratch--
```
`alg-trace = proj of (ir-to-trace alg)` (the algebra compiles to its own trace,
spliced at base + each ascend step — `Scratch`/`rbx` survives it since CCC code
never touches `rbx`). `<build-inl/inr-layer>` reuse the existing `inl`/`inr`
ir-to-trace codegen (alloc-heap + tag/payload stores). **Open detail to nail at
M5:** the algebra-input convention — the layer the algebra reads must be the
`Unit + A` sum node whose tag/payload the algebra's `case-on-tag` expects; align
with how `inl`/`inr` ir-to-trace builds sum nodes. Runtime-verify via re-extract.

(`readReg : StoredValue` in a `ValueLocation` position, since Plan 0.13.2) — it
was stale-cached green and is only used by `RelaxedPOC` (not in the build

## Discipline / non-negotiables
- **One fuel model.** Reuse `Semantics.exec`/`defaultFuel`/`StepLemmas`; do not
  fork a second fuel mechanism.
- **Keep `Corresponds`.** Every target bridges via the uniform per-instruction
  simulation; no per-program, per-target `StepLemmas` proof (that is structure A).
- **No fourth structure.** The loop lives in the live flat-`AbstractTrace`
  vocabulary; `TreeTrace`/`compile-ir`/`CataLayer` are not extended in parallel.
- **Generic, not cata-specific.** The construct is `instr-loop`; `Cata` is its
  first client.
- **Land green at milestone boundaries**; per-module checks under the
  timeout/OOM wrapper; MAlonzo re-extract only at M5.

## Risks / open questions
- **R1 — `exec-prog` vs `Semantics`.** `DirectSimulation.exec-prog` is
  straight-line; M3 likely needs it (or the abstract side) to become
  fuel/jump-aware. Settle in M1 whether `Corresponds` retargets onto
  `Semantics.exec` or `exec-prog` gains pc/jumps.
- **R2 — cascade size.** ~50 `instr-case-on-tag` match sites across SMCore,
  SMPrimitives, 3× DirectSimulation, 3× AbstractToX86, IRTraceCorrect. Mostly
  trivial mirrors (case-on-tag halts at the abstract level), but voluminous; budget it.
- **R3 — discharging `rec-scheme-semantic` (M4).** May remain confined rather
  than fully discharged this plan; acceptable if it is the *single* recursion-
  scheme boundary, not one-per-structure.
- **R4 — descend loop measure.** "loop until tag = 0" is unbounded; fuel covers
  it (bounded by input depth ≤ fuel). Arbitrary-functor traversal deferred (D5).
