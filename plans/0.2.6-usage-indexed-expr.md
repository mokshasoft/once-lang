# Plan: Usage-Indexed `Expr` — Linearity by Construction

## Problem Statement

The ground-inference refactor (0.2.5) eliminated every postulate and the
`TERMINATING` pragma from the type-checker pipeline. But it left the
linearity discipline of QTT enforced *operationally*, not *intrinsically*:

- `Surface.Expr Γ A` carries the typing information but not the per-variable
  usage. A value of type `Expr Γ (A ⇒[ One ] B)` does *not* witness that the
  parameter is used exactly once.
- `checkNew`/`inferNew` compute a `Usage n` vector on the side and check
  `paramUsage ≤q q` at each lambda binder. A bad program is rejected, but
  the *good* `Expr` emitted doesn't carry the evidence.
- Anyone who builds an `Expr` directly via the smart constructors, bypassing
  `checkNew`, can produce a non-linear term typed as linear. No theorem
  rejects it.

Beyond the proof-theoretic principle, this is a concrete optimization blocker:
*every* use-site analysis that downstream passes want (in-place update,
erasure of `Zero`-graded values, parallelizable composition, move-vs-borrow
discrimination at codegen) is re-deriving information that should have been
an indexed fact of the Expr's type.

## Goal

Reindex `Expr` so the usage vector is part of its type, making linearity
*by construction*:

```agda
data Expr : ∀ {n} → Ctx n → Usage n → Type → Set where
  var  : ∀ {n} {Γ : Ctx n} (i : Fin n)
       → Expr Γ (singleUse i One) (lookup Γ i)
  lam  : ∀ {n} {Γ} {Ψ : Usage n} {A B} (q : Quantity)
       → Expr (Γ , A) (q ∷ Ψ) B         -- body uses x exactly at grade q
       → Expr Γ Ψ (A ⇒[ q ] B)
  app  : ∀ {n} {Γ} {Ψ₁ Ψ₂ : Usage n} {A B q}
       → Expr Γ Ψ₁ (A ⇒[ q ] B)
       → Expr Γ Ψ₂ A
       → Expr Γ (Ψ₁ +ᵘ (q *ᵘ Ψ₂)) B    -- arg scaling by grade
  pair : ... → Expr Γ (Ψ₁ +ᵘ Ψ₂) (A * B)
  case : ... → Expr Γ (Ψs +ᵘ (Ψₗ ⊔ᵘ Ψᵣ)) C   -- branches take max (one runs)
  let' : ... → Expr Γ (Ψ₁ +ᵘ dropHead Ψ₂) B
  unit : Expr Γ zeroUsage Unit
  -- literals/primitives: zeroUsage (no variable consumed)
```

The `checkNew` LAM rule becomes: the LAM constructor *only accepts*
`Expr (Γ, A) (q ∷ Ψ) B`, so the inferred body usage must present exactly
`q` at its head. The `if paramUsage ≤q q` runtime check is replaced by
a type-level pattern match that rejects mismatched usage at construction.

## Non-Goals (deferred)

- **Carrying usage into the IR**. IR is point-free; grading in its types
  would be a separate design (morphism gradings) and is not required to
  get the surface-level proof. Phase 4 strips usage at elaboration.
- **Sub-usage / "at most q" lambdas**. For this plan, LAM requires exact
  usage `q`. If we later want `λ^ω x. x` accepted as `λ^1 x. x`, we'd add
  a sub-usage coercion. Phase 1 uses exact-use for simplicity.

## Phases

### Phase 0: Usage arithmetic theory (prerequisite)

**File**: `Once/Surface/UsageArith.agda` (new) or inline at bottom of
`Once/Surface/Syntax.agda`.

The Phase 1 datatype depends on small operational lemmas:

```agda
-- Per-position maximum for case branches (one of two runs)
_⊔ᵘ_ : ∀ {n} → Usage n → Usage n → Usage n

-- Drop the head binding (used when a let or lambda closes scope)
dropHead : ∀ {n} → Usage (suc n) → Usage n
dropHead (q ∷ Ψ) = Ψ

-- Laws (proved)
+ᵘ-identityʳ : Ψ +ᵘ zeroUsage ≡ Ψ
+ᵘ-identityˡ : zeroUsage +ᵘ Ψ ≡ Ψ
+ᵘ-assoc     : (Ψ₁ +ᵘ Ψ₂) +ᵘ Ψ₃ ≡ Ψ₁ +ᵘ (Ψ₂ +ᵘ Ψ₃)
+ᵘ-comm      : Ψ₁ +ᵘ Ψ₂ ≡ Ψ₂ +ᵘ Ψ₁          -- may or may not be needed
*ᵘ-identityˡ : Many *ᵘ Ψ ≡ Ψ                 -- ω * x = x
Zero-*ᵘ      : Zero *ᵘ Ψ ≡ zeroUsage         -- 0 * x = 0
*ᵘ-distribʳ  : q *ᵘ (Ψ₁ +ᵘ Ψ₂) ≡ (q *ᵘ Ψ₁) +ᵘ (q *ᵘ Ψ₂)
```

`Quantity` already has `_+q_` and `_*q_`; `_≤q_` is decidable. `_⊔q_`
(maximum of two quantities) needs to be added. Use the QTT lattice:
`Zero ⊔q One = One`, `Zero ⊔q Many = Many`, `One ⊔q Many = Many`, diagonal
cases return the shared value.

**Deliverable**: lemmas + definitions compile cleanly. Nothing else uses
them yet.

### Phase 1: Reindex `Expr` by `Usage n`

**File**: `Once/Surface/Syntax.agda`.

All 20+ constructors grow a `Usage n` index. Detailed per-constructor
shapes:

```agda
-- Variable: single use at its own position
var : ∀ {n} {Γ : Ctx n} (i : Fin n) → Expr Γ (singleUse i One) (lookup Γ i)

-- Abstraction: body's usage at position 0 determines its grade; drop that
-- position for the outer usage
lam : (q : Quantity) → Expr (Γ , A) (q ∷ Ψ) B → Expr Γ Ψ (A ⇒[ q ] B)

-- Application: outer usage is fun's usage + scaled arg usage
app : {q : Quantity} → Expr Γ Ψ₁ (A ⇒[ q ] B) → Expr Γ Ψ₂ A
    → Expr Γ (Ψ₁ +ᵘ (q *ᵘ Ψ₂)) B

effApp : Expr Γ Ψ₁ (Eff A B) → Expr Γ Ψ₂ A → Expr Γ (Ψ₁ +ᵘ Ψ₂) B

-- Pair: both components used
pair : Expr Γ Ψ₁ A → Expr Γ Ψ₂ B → Expr Γ (Ψ₁ +ᵘ Ψ₂) (A * B)

fst' : Expr Γ Ψ (A * B) → Expr Γ Ψ A
snd' : Expr Γ Ψ (A * B) → Expr Γ Ψ B

inl' : Expr Γ Ψ A → Expr Γ Ψ (A + B)
inr' : Expr Γ Ψ B → Expr Γ Ψ (A + B)

-- Case: scrutinee used, plus per-branch-max (exactly one branch runs)
case' : Expr Γ Ψs (A + B)
      → Expr (Γ , A) (q₁ ∷ Ψₗ) C
      → Expr (Γ , B) (q₂ ∷ Ψᵣ) C
      → Expr Γ (Ψs +ᵘ (Ψₗ ⊔ᵘ Ψᵣ)) C
-- Note: branch's head-grade is a per-branch quantity; the outer usage
-- doesn't care about it (the bound variable goes out of scope).
-- Whether to also enforce (q₁ ⊔q q₂ ≤q Many) or some discipline here is a
-- design nuance — TBD.

unit   : Expr Γ zeroUsage Unit
absurd : Expr Γ Ψ Void → Expr Γ Ψ A

let'   : Expr Γ Ψ₁ A → Expr (Γ , A) (q ∷ Ψ₂) B → Expr Γ (Ψ₂ +ᵘ (q *ᵘ Ψ₁)) B
-- Let is sugar for immediately-applied lambda; same accounting as app.

int, str : Expr Γ zeroUsage _     -- literals use no variables
add/sub/mul/div/mod' : Expr Γ Ψ₁ Int → Expr Γ Ψ₂ Int → Expr Γ (Ψ₁ +ᵘ Ψ₂) Int
neg : Expr Γ Ψ Int → Expr Γ Ψ Int
lt/le/gt/ge/eq/ne : Expr Γ Ψ₁ Int → Expr Γ Ψ₂ Int → Expr Γ (Ψ₁ +ᵘ Ψ₂) _
arr' : Expr Γ Ψ (A ⇒ B) → Expr Γ Ψ (Eff A B)
prim : String → Expr Γ zeroUsage A
```

**Key design decisions**:

1. **`app` uses `q *ᵘ Ψ₂`**: this encodes QTT's argument-scaling rule.
   Calling a linear function once means the argument is consumed once;
   calling an ω-function means the argument can be duplicated/discarded
   freely, so its usage is multiplied by `Many`.

2. **`case'` uses `⊔ᵘ`**: exactly one branch runs at runtime; the runtime
   usage is whichever branch was taken. Taking the max over positions is
   the standard QTT discipline for branching.

3. **Literals and primitives use `zeroUsage`**: they don't consume any
   variable from the context. Pure morphism / constant computation.

**Verification**: after Phase 1, `Once.Surface.Syntax` compiles but
nothing downstream does (all sites of `Expr` need adjusting). This is
expected and accepted as an intermediate state that we unblock in later
phases.

### Phase 2: Usage-aware thinning / weakening

**File**: `Once/Surface/Thinning.agda`.

`weaken`, `rename`, `exchange` and all derived operations need to handle
the usage index. Core signatures become:

```agda
-- Weakening inserts Zero at the new position (the fresh variable is unused
-- in the weakened term).
weaken-usage : ∀ {n} → Usage n → Usage (suc n)
weaken-usage Ψ = Zero ∷ Ψ

weaken : ∀ {n} {Γ : SCtx n} {Ψ : Usage n} {A B q}
       → Expr Γ Ψ B → Expr (Γ S, A ^ q) (Zero ∷ Ψ) B

-- Thinning: usage rearranges along the thinning
thin-usage : ∀ {n m} {Γ : SCtx n} {Δ : SCtx m}
           → Γ ⊆ Δ → Usage n → Usage m
-- For each "keep" position: copy the usage. For each "skip" position:
-- insert Zero.

rename : ∀ {n m} {Γ : SCtx n} {Δ : SCtx m} {Ψ : Usage n} {A}
       → (θ : Γ ⊆ Δ) → Expr Γ Ψ A → Expr Δ (thin-usage θ Ψ) A
```

For each `rename` clause, the usage index of the output must match what
`thin-usage θ` computes — forcing an explicit propagation through the
constructor-by-constructor recursion. The `lam` and `case'` and `let'`
clauses need to show that `thin-usage (keep θ) (q ∷ Ψ) ≡ q ∷ thin-usage θ Ψ`
(structural lemma, provable by pattern match).

**New lemmas**:

```agda
thin-usage-keep-cons : ∀ θ q Ψ
                     → thin-usage (keep θ) (q ∷ Ψ) ≡ q ∷ thin-usage θ Ψ
thin-usage-skip      : ∀ θ Ψ
                     → thin-usage (skip θ) Ψ ≡ Zero ∷ thin-usage θ Ψ
thin-usage-preserves-+ᵘ : thin-usage θ (Ψ₁ +ᵘ Ψ₂) ≡ thin-usage θ Ψ₁ +ᵘ thin-usage θ Ψ₂
thin-usage-preserves-*ᵘ : thin-usage θ (q *ᵘ Ψ) ≡ q *ᵘ thin-usage θ Ψ
thin-usage-preserves-⊔ᵘ : thin-usage θ (Ψ₁ ⊔ᵘ Ψ₂) ≡ thin-usage θ Ψ₁ ⊔ᵘ thin-usage θ Ψ₂
thin-usage-singleUse    : thin-usage θ (singleUse i One) ≡ singleUse (thin-var θ i) One
```

These are all structural inductions on the thinning. Ballpark ~80 lines.

**Verification**: `Once.Surface.Syntax` + `Once.Surface.Thinning` both
compile. Nothing above does yet.

### Phase 3: Rewrite `inferNew` / `checkNew`

**File**: `Once/TypeCheck/Elaborate.agda`.

The change merges the current external `usage` field into the `Expr`'s
type index. `InferElabResult`/`CheckElabResult` become:

```agda
data InferElabResult {n : ℕ} (Δ : SCtx n) : Set where
  success : (T : Type) → (Ψ : Usage n) → SExpr Δ Ψ T
          → (depth : ℕ) → (fresh : ℕ)
          → InferElabResult Δ
  failure : String → InferElabResult Δ

data CheckElabResult {n : ℕ} (Δ : SCtx n) (T : Type) : Set where
  success : (Ψ : Usage n) → SExpr Δ Ψ T
          → (depth : ℕ) → (fresh : ℕ)
          → CheckElabResult Δ T
  failure : String → CheckElabResult Δ T
```

`Ψ` now lives on the expression's type; the separate `usage` record field
is gone.

Per-constructor translation of `inferNew` / `checkNew`:

- `RInt n`: `success Int zeroUsage (Surface.int n) 0 (freshCtr ctx)` — literal.
- `RVar "id"` (local): `success T (singleUse i One) (Surface.var i) …`
- `RApp f x` (generic): infer f with `Ψ₁`, infer x with `Ψ₂`;
  produce `Surface.app fE xE : Expr Δ (Ψ₁ +ᵘ (q *ᵘ Ψ₂)) B`.
- `RApp (RVar "id") arg`: infer arg with `Ψ`; produce `specId T` wrapped in
  `Surface.app`; combined usage is `Ψ` (since `specId` has `zeroUsage`).
- `RLam x body` in check mode against `(A ⇒[ q ] B)`: check body with
  extended context; the body's type tells us its usage `(q' ∷ Ψ)`. If
  `q'` does not definitionally equal `q`, fail. (Replaces the old
  operational `≤q` check — type-directed.)

**The lambda rule is where "linearity by construction" pays off**:
`lam q body` only type-checks when `body : Expr (Γ, A) (q ∷ Ψ) B`. So if
the body's head-usage isn't `q`, the lam can't be built. The `paramUsage`
computation disappears from the runtime check; the type checker now
returns "failure with message" at construction attempt when the usage
doesn't match.

For flexibility (e.g., accepting a `Many`-use parameter used only once
as linear), we'd need sub-usage coercion. Exact-use is the baseline; a
`subUsageCoerce : Ψ sub-covers Ψ' → Expr Γ Ψ A → Expr Γ Ψ' A` helper can
be added later if needed.

**`FunProjection`/`IntProjection` helpers**: adapt to carry the usage
vector through:

```agda
data FunProjection {n : ℕ} (Δ : SCtx n) : Set where
  isFun  : (A B : Type) (q : Quantity) (Ψ : Usage n)
         → SExpr Δ Ψ (A ⇒[ q ] B) → ℕ → ℕ → FunProjection Δ
  notFun : String → FunProjection Δ
```

**Per-builtin specializers**: `specId T : SExpr S∅ zeroUsage (T ⇒ T)`, etc.
All 13 specializers are closed terms with `zeroUsage` (they reference no
free variables). After `weakenFromEmpty`, they become
`SExpr Γ zeroUsage _`.

**Verification**: `Once.TypeCheck.Elaborate` compiles. Linearity
enforcement is now at type-level; runtime `if … ≤q …` tests gone.

### Phase 4a: Elaboration strips usage

**File**: `Once/Surface/Elaborate.agda`.

Change `elaborate` to accept the usage-indexed Expr:

```agda
elaborate : ∀ {n} {Γ : SCtx n} {Ψ : Usage n} {A}
          → Expr Γ Ψ A → IR ⟦Γ⟧ᶜ A
```

The `Ψ` index is ignored at the type level (IR is point-free). The
structural recursion stays identical — every pattern match on `Expr`
just picks up an extra `{Ψ …}` binding that's unused.

**Correctness note**: the theorem "elaborate is semantics-preserving"
still holds; it's stated for any Expr regardless of usage.

`compileExpr` / `compileExprTyped` are unchanged externally: they
still return `Maybe (IR Unit A)`. Internally they `Σ`-unpack the
usage index from the result.

**Verification**: `Once.Surface.Elaborate` compiles. Entry-point API
stable.

### Phase 5: Downstream proof updates

**Files**: `Once/Surface/Correct.agda`, `Once/Surface/Semantics.agda`,
`Once/Surface/Desugar.agda`, `Once/Surface/Desugar/Correct.agda`,
`Once/Optimize.agda`, `Once/Optimize/Correct.agda`, `Once/Escape.agda`,
`Once/Escape/Correct.agda`, `Once/Fusion.agda`, `Once/Fusion/Correct.agda`.

For each file, audit how `Expr`/`SExpr` is used:

1. **Theorems stated over `Expr Γ A`**: rewrite to `Expr Γ Ψ A` for some
   implicit `{Ψ}`, or rewrite to `∃[ Ψ ] Expr Γ Ψ A`. Usually the former
   is cleaner (just parameterize over the usage too).

2. **Pattern matches on `Expr`**: add `{Ψ}` to irrelevant positions (or
   explicit `Ψ` bindings where needed).

3. **`case`/`let`/`lam` semantic proofs**: these must now preserve the
   `Ψ` index through the semantic equivalence. For most passes (desugar,
   optimize) the semantics doesn't touch usage, so the proofs stay
   structurally identical — they just pipe the `Ψ` through.

4. **`escape`**: escape analysis may find natural use for the usage info!
   If so, it becomes a consumer of the new indexing. Worth checking
   during this phase what it can simplify.

**Expected effort**: ~200-300 lines of changes across the 10 files, mostly
mechanical. A few places may need non-trivial proof updates where the
usage arithmetic interacts with the semantic preservation.

1. `Phase 0: Usage arithmetic theory for QTT`
2. `Phase 1+2: Usage-indexed Expr and usage-aware thinning`
   (These two commit together because Phase 1 alone leaves Thinning broken.)
3. `Phase 3: Rewire inferNew/checkNew to produce usage-indexed Expr`
4. `Phase 4a: Elaborate over usage-indexed Expr (strip usage at IR)`
5. Downstream phase (possibly split per file):
   - `Phase 5a: Surface/Correct + Surface/Semantics`
   - `Phase 5b: Desugar + Desugar/Correct`
   - `Phase 5c: Optimize + Optimize/Correct`
   - `Phase 5d: Escape + Escape/Correct`
   - `Phase 5e: Fusion + Fusion/Correct`

Between commits, the downstream modules typecheck with the "old" Expr
shape if we stage carefully. Specifically: Phase 4a deliberately strips
the usage before elaboration, so downstream proofs still see ground
`IR ⟦Γ⟧ᶜ A` as before — they don't all *need* Phase 5 immediately to
keep working.

If Phase 5 becomes too costly, we can pause at 4a: the surface proof is
complete, and downstream proofs can be updated incrementally.

## Risks & Open Questions

1. **`case'` head-grade discipline**: the two branches' head-usage
   quantities (`q₁`, `q₂` for the left-bound `xL : A` and right-bound
   `xR : B`) — how are they related? Options:
   a. Same grade required (`q₁ ≡ q₂`) — strict.
   b. Combined via `q₁ ⊔q q₂` at the outer — branch "uses" max.
   c. Independent per branch — each carries its own grade.

   Current `polyCheckImpl` discards these via `tailUsage`, which aligns
   with option (c). I'd default to (c) for this plan and revisit if
   real programs reveal a cleaner answer.

2. **Sub-usage**: currently `checkNew` allows `paramUsage ≤q q`
   (sub-usage), so `λ^ω x. x` (using x once) is accepted against an
   ω-typed arrow. Phase 3's type-level exact-match rejects this. We
   likely need a sub-usage coercion eventually. The clean way: add a
   `sub-usage : Ψ ≤ᵘ Ψ' → Expr Γ Ψ A → Expr Γ Ψ' A` data constructor
   (a "usage-weakening"), similar to how `weaken` exists for contexts.

3. **`_≤ᵘ_` relation**: already defined in `Once.Surface.Syntax`; Phase 1
   should reuse it for the sub-usage operation if we add it.

4. **Usage inference vs. checking**: `inferNew` returns the inferred Ψ.
   In cases where usage can be ambiguous (rare in practice — only
   polymorphic-generator-application has this shape), we pick the
   canonical one and let check-mode override. Should not be an issue
   for Once's bidirectional discipline.

5. **`let'` accounting**: the plan uses
   `Ψ₂ +ᵘ (q *ᵘ Ψ₁)` where `e₁` is the RHS and `Ψ₂` is the body's
   tail-usage. This matches `app`'s rule since `let x = e₁ in e₂` is
   sugar for `(λ^q x. e₂) e₁`. Confirm the grade `q` on the let binding
   is explicit syntactically — may need to be added to `Raw.RLet`.

6. **Haskell/MAlonzo compatibility**: the top-level API
   (`compileExpr`, `compileExprTyped`) return signatures unchanged, so
   MAlonzo extraction stays compatible. The `Ψ`-existential is hidden
   in the Σ-pack at the call boundary. Haskell consumers see no change.

7. **Elaborate.agda size**: the per-builtin specializers get a
   `zeroUsage` annotation. That's mechanical but touches all 13.

8. **Escape/Fusion use of linearity info**: worth reading these modules
   during Phase 5 to see if they can now statically prove what they
   currently assume. If yes, this plan unlocks real proof simplifications
   downstream. If no, they just ignore the new index.

## Deliverable

After all phases:

- Linearity is proven by construction at the surface level: any
  `Expr Γ Ψ A` you hold is guaranteed to respect Ψ's usage discipline.
- Downstream passes can pattern match on `Ψ` to derive optimization
  information (e.g., "this variable has usage One, thus in-place
  update is sound"). The proof that optimizations are correct can
  lean on these indices.
- The operational `paramUsage ≤q q` check is replaced by type-level
  pattern matching — no more "operational enforcement".
- QTT erasure (`Zero`-graded values) becomes a derivable structural
  property of the Expr.
- Ground type inference (from 0.2.5) stays intact; this plan is
  orthogonal to PolyType concerns.
