# Plan 0.12: Categorical Layer 1 — Products

## Goal

Bring Layer 1 (Products: `⟨_,_⟩`, `fst`, `snd`) to the same status
as Layer 0: full runtime correctness across a representative test
suite, with verification gaps tied to specific follow-up plans.

Layer 1 in `docs/design/ir-stack-layout.md` table:

| Layer | Name | Morphisms |
|-------|------|-----------|
| 0 | Category | `id`, `∘` |

## Current state (2026-05-08)

The IR primitives `⟨_,_⟩`, `fst`, `snd` already exist and work for
ground-mode user expressions. Manual smoke tests landed in this
session (none committed yet as `compiler/test/layer1-*.once`):

| Program | Result |
|---|---|
| `exit@S (fst (42, 99))` | exit 42 ✓ |
| `exit@S (snd (id 1, 42))` | exit 42 ✓ |
| `exit@S (fst (id (42, 7)))` | exit 42 ✓ |
| `exit@S (fst ((snd (1, 42)), 99))` | exit 42 ✓ |
| `exit@S (snd (snd (snd (1, (2, (3, 42))))))` | exit 42 ✓ |
| `exit@S (fst (snd (fst ((((1, (2,3)), (42,99)), (8,9))))))` | exit 42 ✓ |
| `exit@S ((id . snd . id . snd . id . snd . id) (1, (2, (3, 42))))` | exit 42 ✓ |
| `exit@S ((snd . snd . snd) (1, (2, (3, 42))))` | exit 42 ✓ |

So Layer 1 is *partly green* at the runtime level for ground
expressions in `main`'s body. Two real gaps below.

## Gap #1 (BLOCKER): Thunk-label collision across top-level functions

**Symptom.** Any source with more than one top-level user function
fails at the assembler stage:

```
swap : Int * Int -> Int * Int
swap p = (snd p, fst p)

main : IO Unit
main = exit@S (fst (swap (99, 42)))
```

```
Assembly failed (as): /tmp/swap.s: Assembler messages:
/tmp/swap.s:81: Error: symbol `.L_thunk_0' is already defined
```

**Cause.** `formal/Once/CCC/Codegen/IRToTrace.agda`'s `ir-to-trace'`
threads a label counter `l` that always starts at `0`:

```agda
ir-to-trace ir = proj-trace (ir-to-trace' 0 0 ir)
ir-to-bodies ir = proj-bodies (ir-to-trace' 0 0 ir)
```

`formal/Once/Compile.agda`'s `compileFunWithTarget` calls these
once per top-level `CompiledFun`. Each call's thunk labels
restart at 0. The module-level concatenation produces
`.L_thunk_0`, `.L_thunk_0`, … duplicates.

The minimal-repro `myfn x = x; main = exit@S (myfn 42)` triggers
the same bug — `myfn`'s body lowers to `curry (id ∘ snd) Heap`,
which emits a thunk; `main`'s body emits another. Both labelled
`.L_thunk_0`.

Note: this is a Layer-0-or-greater bug that the Layer 0 test
suite happens not to exercise. `layer0-id.once` and
`layer0-compose.once` only define `main`; `layer0-neg.once`
defines a constant (`seven : Int = 7`, no thunk). User functions
of any layer trigger it.

**Fix sketch (principled).** Thread the label counter across
top-level functions in `Compile.agda`:

1. Expose `ir-to-trace-from : (l : ℕ) → IR A B → ℕ × AbstractTrace`
   and `ir-to-bodies-from : (l : ℕ) → IR A B → ℕ × List (…)` — both
   take a starting label counter and return the next-available one.
2. Update `Target` record's `irToAsm` / `irToBodies` to thread `l`.
3. `Compile.agda`'s `compileAllWithTarget` becomes a left-fold
   carrying the counter:
   ```
   foldl (λ (l, asm) cf →
            let (l', new-asm) = compileFunWithTarget target l cf
            in (l', asm ++ new-asm))
         (0, "")
         cfs
   ```

Per-arch impact:
- `Once.Target.X86-64`: `x86-64-irToAsm` / `x86-64-irToBodies`
  signatures gain `ℕ →`. Internal use of `ir-to-trace`/`ir-to-bodies`
  threads through.
- `Once.Target.X86-32`, `Once.Target.RiscV64`: parallel updates.
- The abstract `instr-load-code-addr n` already takes the label as
  data; no abstract-instruction change needed.

**Estimate**: ~½ day. Mostly mechanical signature plumbing.

## Gap #3 (potential, not yet observed): runtime-sized pair components

Per `docs/design/ir-stack-layout.md` Products section, layout for
runtime-sized components uses pointers:

| A | B | Layout |
|---|---|--------|
| static | static | `AAA BBB` |
| static | runtime | `AAA ptr→B` |
| runtime | static | `ptr→A BBB` |
| runtime | runtime | `ptr→A ptr→B` |

Layer 1 is conceptually static-only (no μ-types yet), so this gap
is empty for Layer 1 proper. Mentioned only because the codegen
will need to honour the layout when Layer 5+ μ-types arrive.

## Scope for this plan

**In scope:**

1. Fix Gap #1 (thunk-label threading). Block until landed.
2. Land `compiler/test/layer1-*.once` test cases covering:
   - Ground pair construction + projection: `fst (a, b)`, `snd (a, b)`.
   - Nested pairs (3+ levels deep).
   - User-defined functions over pairs (`swap`, `dup`, `pair-id`).
   - Compose chains over pair-handling morphisms (`(snd . snd . snd) …`).
3. Wire the test suite into `Layer1Spec.hs` (mirror `Layer0Spec.hs`).
4. Update `plans/README.md` Live regression table to include Layer 1.

**Out of scope:**

- Sum types (`inl`, `inr`, `case`) — Layer 2.
- `terminal`, `initial` — Layer 3 in the doc's table; already
  partially covered by Layer 0 work.
- Closure-realm ABI fix — orthogonal, tracked in
  `0.2.4.5-morphism-realm-split.md`. Layer 1 ground programs don't
  hit it.
- `ir-to-trace-correct-pair` discharge — tracked in
  `0.2.4.7-irtracecorrect-frontier.md`.

## Open question

**Numbering.** This plan is named `0.12` because `0.10` and `0.11`
are taken. If Layer 1 is conceptually a sibling of `0.2.4`
(Layer 0), the cleaner number would be `0.2.4`'s next sibling —
but that path is occupied by closed plans (`0.2.5`, `0.2.6`).
`0.12` keeps the numbering linear at the cost of breaking the
"sibling = same prefix" pattern. Revisit if this becomes load-
bearing.
