## 0. Where this starts (2026-10-22)

**A server crashes.** Layer5Spec's group "a server never ends" (`compiler/test/loop-forever-emit.once`,
`loop-forever-silent.once`, added in the merge review) fails on all three arches: each round allocates its
next state on the bump heap, nothing reclaims it, the 64 KiB heap (`.skip 65536` after `once_heap_base`,
`CCC/Target/*/File.agda`) fills after a few thousand rounds, and the next allocation writes past its end. The
binary segfaults (gdb: the faulting store in `once_next` is at `0x412000`, exactly the heap's end).

**The proof does not see it.** The apex takes, per arch, `HeapRoom`, `StackRoom` and `CallRoom`
(`Adequacy/ArchCorrectness/<arch>/ResourceBounds.agda`, parameters of `Once.Certified`): at every allocation
or frame reservation there is room. Their comment says a linker could discharge them by sizing the image for
the program. For a loop whose rounds allocate, no finite size does: the hypotheses are false and the theorem
says nothing about servers. It is D326's argument against the step budget, applied to memory.

**Two gaps against GOAL.md.**
1. *"Running out is a defined, observable outcome, never undefined behaviour."* Running out is an unchecked
   write past the region: undefined behaviour.
2. *"Memory is managed by the compiler from the program's structure."* Nothing is ever freed. The allocator
   subsystem (`Once/Allocator/{Interface, AbstractInstance, BumpAllocator, Mempool, Slab, Malloc,
   ReuseFreshness}`) is proved but wired to nothing: allocation is an inlined bump of the frontier register
   (`r15` / `esi` / `s2`), and four of the modules are on `backstop.islands`.

The two parts below fix one gap each. Part A is small and makes the theorem honest for every program. Part B
is large and makes servers run.

## 0′. seL4 runs out silently (2026-10-28, plan 0.127)

A root task that walks the bootinfo's 93 untypeds (`findRAM`, an `ana` into `Eff`) runs out of the 64 KiB heap
before it finds RAM: a round of the search allocates about 2.3 KiB (closure records, application cells and

unmapped page; in the seL4 Host the root task's stack follows the heap, so the heap runs into the stack

ends `exhausted` (the seL4 Host's `once_exhausted`); with B its search rounds reclaim and it fits.

## Part A — Running out is an observable end

### A.1 The decision (to write as a D-entry, with the Spec patch)

1. **The source meaning is unchanged.** A source program never runs out: the Spec's model has unlimited
   memory (GOAL.md's hypothesis). Only a compiled program runs out.
2. **Running out is an end the compiled program may observe.** `Spec.Trace`'s `End` gains a third
   constructor, next to `returned` and `halted`: `exhausted` (name to settle). A source trace never ends
   `exhausted`.
3. **Correctness allows it, and only it.** `correct` relates the compiled behaviour to the source behaviour
   by an asymmetric relation: weakly bisimilar, except that where the compiled trace ends `exhausted`, it
   matches whatever the source does from there on. Everything the program did before it ran out is exactly
   what the source does. (CakeML's `extend_with_resource_limit`.)
4. **What it costs, stated in the entry.** A compiler that ran out at once on every program would satisfy
   `correct`. That is the price of a finite machine; the separate guarantee that a program does NOT run out
   is a space theorem (Part B's `heap-conservation`, then a bound for programs whose rounds reclaim). The
   apex keeps its claim about the calls; it loses no program.

### A.2 How the user is told: the Host's third entry

D320's Host has `enter` and `leave`; a run is `enter ; main ; leave`. Running out gets its own entry,
because what "the program ran out of memory" looks like differs per platform exactly as "the program ended"
does, and the compiler must stay Host-agnostic (D320 item 3):

- **`exhaust`** (name to settle; symbol `once_exhausted`, outside every program's name space like
  `once_leave`, `Once.Target.SymbolFresh`): the compiler calls it when an allocation or a frame reservation
  does not fit. It never returns. Its contract, a named hypothesis like `leave`'s (D320 item 4): calling it
  ends the run, and that end is observed as `exhausted`.
- **Per Host** (each a model of the contract; open per platform):
  - Linux (all three arches, the first instance): SIGABRT to itself (user, 2026-10-28), as C's `abort()` and
    Rust do. No exit status can be reserved (`exit@S` passes any `Int`, Linux keeps 8 bits), but death by a
    signal is distinct from every exit status to the parent (`WIFSIGNALED`). The Host may first write its own
    line to stderr (its bytes are the Host's, not a Once string).
  - seL4: report to the parent/monitor through the fault endpoint, then suspend.
  - FreeRTOS: the out-of-memory hook, then delete the task.
  - bare metal: a defined stop (halt loop, LED/serial where the board has one).
  - a VM: trap to the embedder.
- The Host's code lives in `Strata/Hosts/<platform>/Host.<arch>`, beside `once_leave`.

### A.3 The compiler

- Room checks call `once_exhausted` when a reservation does not fit. **Where they go is Part C** (2026-10-28):
  one check per loop round, closure entry and program start, each covering the heap and stack its code needs
  until the next check (`frontier + need ≤ stack pointer`); not one per allocation or frame.
- The compiler no longer emits the heap (`.skip 65536`): the Host supplies the region (C.5).
- Per arch, in `CCC/Target/<arch>/AbstractToX86*.agda` / `AbstractToRiscV.agda`, with the files' externs
  naming the symbol.

### A.4 The proof

- The machines' observable gains the end `exhausted` (the CPU interface, `Denotation.Behavior`), as D320 added
  `returned`.
- At each check the per-arch simulation splits: room (today's proof, the check's `false` branch taken, and
  the invariant "room ≥ what the budget still allows until the next check" carried to every allocation and
  frame step after it, C.3) or no room (the run reaches `once_exhausted`, the Host's contract makes the end
  `exhausted`, and the new case of the relation closes it).
- `HeapRoom`, `StackRoom`, `CallRoom` (three per arch, nine) leave `Once.Certified`'s parameters (they
  never had a `NonVacuous` model; `Certified.Models` lists them as not covered).
- Emptiness probe and model for the Host's new contract, as for `leave`.

### A.6 The drafted Spec patch (2026-10-28, awaiting the user's approval)

The patch is the appendix; both modules type-check alone with it. Nothing outside the Spec is changed yet.

- `Spec.Trace`: `End` gains `exhausted`; `EndRel` gains `exhausted≈` (so `≈ᵗ` stays an equivalence on
  every trace); new `t ⊑ᵗ⟨ R ⟩ s`, coinductive, two fields: *sound* — each visible step of t is
  `exhausted`, or s takes a step `StepRel`-related to it; *complete* — for each visible step of s, t ends
  `exhausted` or takes a related step. So t may stop by running out anywhere (even where s goes on silently
  forever), but never stops silently where s goes on, never goes on where s ends, and every call before it
  runs out is s's.

  up to running out; not symmetric. The apex instance (`Adequacy/SpecApex.agda`) then picks
  `b ⊑ m = b ⊑ᵗ⟨ _≡_ ⟩ m`.
- `Spec.Observation` and `Spec.Source` are unchanged: the source meaning only builds `returned` and
  `halted`. "A source trace never ends `exhausted`" goes in `Spec.Metatheory` as a statement, its proof
  under `Once/Metatheory`.
- The D-entry is D347.
- Not settled: the names (`exhausted`; `⊑`; the Host entry `once_exhausted`). (Each Host decides how running out looks: Linux SIGABRT, A.2.)

## Part B — The proven allocators reclaim (from plan 0.35)

### B.0 The invariant first (user, 2026-10-28)

Part B starts by stating its invariant, before any allocator or `free` code, so that it guides every proof
that follows. It is a codegen "Spec": not in `Once.Spec` (the Spec's model has unlimited memory), but a named
claim about the emitted code, beside `correct`. Over every run of the abstract trace:

1. **Every allocated block is freed**, exactly once, by the code at its owner's last use (D6). A run that
   ends has nothing live (M7's corollary).
2. **No block is read or written after it is freed**, and none is freed twice.
3. **A loop round ends with only the next state live** (M4): everything else the round allocated is freed
   by then. So a server's memory is bounded by its state, round after round.
4. **Only an owner frees or writes a block** (D6): a borrowed block is never freed or written by its
   borrower. This is what keeps in-place update of linear values sound.

These are properties of the emitted code, decided at compile time; nothing is tracked at run time.

M7's `heap-conservation` is its statement as an equation over the IR. It is written down and type-checked
first (with its predicates: live set, footprint, freed-once), stated and unproved; each milestone then
proves its part (M5: an IR's frees hit dead blocks it produced; M6: the call boundary; M7: the induction).

### B.1 Design decisions (settled with the user in plan 0.35; still valid)

- **D1 — Calling convention: `call`/`ret`, leaf, frameless.** `instr-alloc-heap` / `instr-free-heap` lower to
  `call <allocator-label>`. A leaf allocator needs no frame. `call`/`ret` is net-zero on the stack pointer,
  so the simulation sees the call as atomic: registers in, result out, allocator-private state advanced. No
  inlining: the allocators that matter (`Mempool`/`Slab`/`Malloc`) carry free-list logic that must not be
  duplicated per site. **Open (2026-10-28):** a call per allocation costs; blocks freed in reverse order of
  allocation (much of Once's code may have that shape) need only the bump pointer moved back, inline. Decide
  in M3 which allocations go through the allocator and which are bump-and-pop.
- **D2 — Place stamps the allocator and emits `free`**, for escaping outputs at their last consumer and for
  transient / locally-consumed outputs inside the IR. `free` is a trace-level instruction. (The IR's
  `free-heap` constructor already exists as a semantic no-op, `IRObsCorrect.Simple`.)
- **D3 — Two contract levels; `PreservesCCC` stays untouched.** `free` reclaims a block before the frontier,
  which `PreservesCCC`'s `prior-preserved` / `heap-monotone` forbid, so alloc/free get their own lighter
  boundary contract: abstractly, all live blocks are preserved; concretely, the encoding relation and the
  calling convention are preserved and allocator-private state is hidden.
- **D4 — Free with reuse, in lockstep through the interface.** Abstract and concrete allocation go through
  the same interface, so a freed ref is reused as the same ref on both sides; `heap-eq` holds throughout and
  needs no live set. Disjointness is the interface's `blocks-disjoint` field, strengthened to live blocks
  and proved by each implementation, never postulated. Machine-checked in isolation:
  `Once.Allocator.ReuseFreshness`. The fixed-size allocators (`Mempool`, `Slab`) satisfy it; variable-size
  `Malloc` with coalescing is the deferred case (B.2 M8).
- **D5 — SigOps that free** data they return: out of scope, rides with M8.
- **D6 — Ownership is static (user, 2026-10-28).** No ownership information at run time: no reference
  counts, no tags, no shared flags. Every decision is made by the compiler and emitted. Each heap value is
  handled in one of three ways:
  - *owned*: exactly one owner, which frees the block at its last use, or reuses it in place (a new value of
    the same size written into it, instead of a `free` and an `alloc`);
  - *borrowed*: read only; never freed or written. At a duplication (`pair f g`: `f` runs first), `f`
    borrows when the compiler proves it does not keep the value (not in its result, not in a closure), and
    `g` owns it;
  - *copied*: when both sides keep it, each gets its own copy (copy code generated from the type), owned.
  Structures are freed by code generated from their type (a fold); a closure frees its captured
  environment when it is freed. **In-place update must stay possible:** a linear value (QTT quantity 1) is
  always owned, so writing it in place is sound with no run-time check; nothing in the design may make
  uniqueness a run-time fact or let a borrowed value be written. (Copy-on-write was considered and set
  aside: it needs a run-time shared flag.)
- **`alloc` stays total in the interface** (user, 2026-06-05): it is the "enough memory" idealization;
  bounded allocators are finite refinements. **Changed by Part A:** the gap between the total interface and a
  bounded allocator is no longer an assumption — a bounded allocator that has no block calls
  `once_exhausted`, and Part A's end closes the proof.

### B.2 Milestones (re-based on today's code)

- **M1 — done** (`250abade`): `free` and `alloc-fresh` in `AllocatorInterface`, discharged in
  `AbstractInstance`.
- **M2 — the abstract `free`.** `instr-free-heap` in the flat machine (`SMCore`), memory-non-destructive,
  and the alloc/free boundary contract (D3). The old sequencing constraint (wait for the flat path and the
  `compile-ir` deletion) is met: the flat path is the only path.
- **M3 — wire codegen through the interface, one allocator per arch.** Lower alloc/free to calls in the three
  `AbstractTo*` modules; one allocator implementation per target, mirroring the target tree. `--alloc`
  selects which allocator backs the calls (bump, mempool, slab, malloc) — plan 0.86's step F, moved here.
  Rename `AllocMode`'s `Allocator` constructor when plan 0.86 has removed the index.
- **M4 — Place: last use and `free` emission.** Classify each heap output as transient, locally consumed, or
  escaping, and each use as owned, borrowed or copied (D6: at a duplication, borrow where the compiler proves
  the first side keeps nothing, copy where both keep it); stamp the allocator, emit `free` at the owner's last
  use, and the copy and free code generated from the type. **The loop's round is a reclamation
  point** (D317): after a round, only the next state is live, so everything else the round allocated is
  freed there — the structural reason a server can run in bounded memory.
- **M5 — per-IR free correctness**: the frees an IR emits target blocks it produced that are dead there.
- **M6 — the call-boundary simulation, per allocator and arch**: `call alloc` preserves the correspondence,
  stack net-zero, IR-live registers and heap preserved, a fresh disjoint block in the result register; the
  same for `free`. The `instr-alloc-heap` simulation steps (`sim-alloc-*`) consume it instead of tracking
  the frontier register.
- **M7 — leak-freedom (the crown).** Over the abstract trace, the live set grows by exactly the escaping
  footprint:

  ```
  heap-conservation : ∀ (ir : IR A B) s alloc →
    live-set (exec-trace (compile ir) s alloc) ≡ live-set-before ⊎ escaping-footprint ir
  ```

  Proved by induction on the IR. Its corollaries: for a terminating `main`, the live set at the end is empty
  (a program returns nothing; heap only flows into SigOp arguments, which are locally consumed); for a loop,
  the live set after each round is the next state's footprint — **a space bound per round**, which is the
  guarantee Part A's relation does not give.
- **M8 — deferred: variable-size `Malloc`** (coalescing; the ref↔address map is not fixed), and SigOps that
  free (D5).

### B.3 Done when

1. B.0 holds, postulate-free: `heap-conservation`, freed exactly once, never touched after free, only owners
   free or write; the per-round space bound follows.
2. The emitted code carries no ownership information (no counts, tags or flags), and nothing in it stops a
   later in-place update of linear values (D6).
3. Layer5Spec's "a server never ends" is green on all three arches.
4. The emitted binaries run valgrind-clean on the layer5 cata tests (with mempool client requests for our own

5. The allocator modules leave `backstop.islands`; plan 0.64 Group AL closes (wired, not deleted).

## Part C — Where the room is checked (2026-10-27 and 2026-10-28, with the user)

A.3 as first written puts a compare-and-branch at every allocation, frame reservation and call. The proof
needs only that each reservation fits, so the checks can be coarser. What is checked is the one region the
proof already models (`HeapRoom`, `StackRoom`: `[hfront, lo)`): the heap frontier grows up into it, the
stack grows down into it, and running out is the two meeting. One comparison covers both:
`frontier + need ≤ stack pointer`, else `once_exhausted`.

1. **Per loop round (chosen, 2026-10-28).** Once has no general recursion, so allocation is unbounded only
   where something repeats. Straight-line code has a static worst case and needs no check of its own. A
   check goes at each loop round's head (covering the round's worst case; nested loops check their own), at
   each closure body's entry (an unknown callee's need is not known at the call), and once at program start
   (covering everything before the first loop or closure). Cost: one compare per round or closure call,
   never per allocation; a program with no loop gets one check, and the compiler can show statically that it
   fits. Needs a static bound per round across known calls (`ir-stack-requirement`, extended) and its
   soundness proof.
2. **Per block (the fallback, as GHC does).** One check per block entry for its frame, its call's return slot
   and its straight-line allocations: a local proof, run more often.
3. **The invariant is stated in 1's form from the start:** "room ≥ what the budget still allows until the
   next check", carried by the simulation; 2 is its case where a budget covers one block, so starting with
   2's placement changes only where checks go, not the proof's structure.
4. **Guard pages: REJECTED (user, 2026-10-27).** No check on the normal path, but they need an MMU (bare
   metal is a goal), a new OS/MMU assumption on the apex, stack probes for frames larger than a page, a fixed
   stack/heap split instead of the shared region, and they do nothing for the heap.
5. **The Host supplies the region.** The check is sound only if `[frontier, stack pointer)` is one real
   region. Today it is not: the compiler emits a 64 KiB `.skip`, and on Linux `rsp` is the OS stack far
   above it (`r15 + n ≤ rsp` would always pass while the heap runs off its end). The compiler stops emitting
   the heap; each Host's `enter` provides one region (heap at the bottom, stack at the top, its size the
   Host's choice) and sets the stack pointer and frontier. On seL4, one region per program.
6. **SigOp impls are counted by rule, not syntax.** Under the SigOp ABI an impl allocates only its answer at
   the frontier, and the answer's type fixes its size; its stack use is bounded by a fixed per-arch budget in
   the ABI (e.g. 256 bytes). Every check adds both at the call sites it covers. An impl that needs more
   breaks its contract, as clobbering a register would. The Host's own code (`enter`, `leave`,
   `once_exhausted`) has a fixed reserve at the region's top.

+-- which never runs out. A run that ran out at once matches every s; that a
+-- program does NOT run out is a separate, space claim (D347).
+
+record _⊑ᵗ⟨_⟩_ {X : Set} (t : Tr X) (R : X → X → Set) (s : Tr X) : Set where
+  coinductive
+  field
+    -- t's next visible step: it ran out, or s takes a step related to it
+    sound    : ∀ a → next t ⇓ a →
+               a ≡ inj₁ exhausted ⊎ ∃[ b ] (next s ⇓ b × StepRel R (λ u u′ → u ⊑ᵗ⟨ R ⟩ u′) a b)
+    -- s's next visible step: t runs out, or takes a step related to it
+    complete : ∀ b → next s ⇓ b →
+               next t ⇓ inj₁ exhausted ⊎ ∃[ a ] (next t ⇓ a × StepRel R (λ u u′ → u ⊑ᵗ⟨ R ⟩ u′) a b)
+open _⊑ᵗ⟨_⟩_
+
+infix 4 _⊑ᵗ⟨_⟩_
+
 -- The calls a trace makes first.
 data Calls {X : Set} : Tr X → List Event → Set where
   none : ∀ {t} → Calls t []
