## 0. Where this starts (2026-10-22)

**A server crashes.** Layer5Spec's group "a server never ends" (`compiler/test/loop-forever-emit.once`,
`loop-forever-silent.once`, added in the merge review) fails on all three arches: each round allocates its
next state on the bump heap, nothing reclaims it, the 64 KiB heap (`.skip 65536` after `once_heap_base`,
`CCC/Target/*/File.agda`) fills after a few thousand rounds, and the next allocation writes past its end. The
binary segfaults (gdb: the faulting store in `once_next` is at `0x412000`, exactly the heap's end).

**The proof does not see it.** The apex takes, per arch, `HeapRoom`, `StackRoom` and `CallRoom`
(`Adequacy/ArchCorrectness/<arch>/ResourceBounds.agda`, parameters of `Once.Certified`): at every allocation
or frame reservation there is room. Their comment says a linker could discharge them by sizing the image for
the program. For a loop whose rounds allocate, no finite size does: the hypotheses are false and the theorem
says nothing about servers. It is D326's argument against the step budget, applied to memory.

**Two gaps against GOAL.md.**
1. *"Running out is a defined, observable outcome, never undefined behaviour."* Running out is an unchecked
   write past the region: undefined behaviour.
2. *"Memory is managed by the compiler from the program's structure."* Nothing is ever freed. The allocator
   subsystem (`Once/Allocator/{Interface, AbstractInstance, BumpAllocator, Mempool, Slab, Malloc,
   ReuseFreshness}`) is proved but wired to nothing: allocation is an inlined bump of the frontier register
   (`r15` / `esi` / `s2`), and four of the modules are on `backstop.islands`.

Part A below fixes the first gap and makes the theorem honest for every program. The second gap is plan
0.126 (D341).

## Part A — Running out is an observable end

### A.1 The decision (to write as a D-entry, with the Spec patch)

1. **The source meaning is unchanged.** A source program never runs out: the Spec's model has unlimited
   memory (GOAL.md's hypothesis). Only a compiled program runs out.
2. **Running out is an end the compiled program may observe.** `Spec.Trace`'s `End` gains a third
   constructor, next to `returned` and `halted`: `exhausted` (name to settle). A source trace never ends
   `exhausted`.
3. **Correctness allows it, and only it.** `correct` relates the compiled behaviour to the source behaviour
   by an asymmetric relation: weakly bisimilar, except that where the compiled trace ends `exhausted`, it
   matches whatever the source does from there on. Everything the program did before it ran out is exactly
   what the source does. (CakeML's `extend_with_resource_limit`.)
4. **What it costs, stated in the entry.** A compiler that ran out at once on every program would satisfy
   `correct`. That is the price of a finite machine; the separate guarantee that a program does NOT run out
   is a space theorem (plan 0.126's `heap-conservation`, then a bound for programs whose rounds reclaim). The
   apex keeps its claim about the calls; it loses no program.

### A.2 How the user is told: the Host's third entry

D320's Host has `enter` and `leave`; a run is `enter ; main ; leave`. Running out gets its own entry,
because what "the program ran out of memory" looks like differs per platform exactly as "the program ended"
does, and the compiler must stay Host-agnostic (D320 item 3):

- **`exhaust`** (name to settle; symbol `once_exhausted`, outside every program's name space like
  `once_leave`, `Once.Target.SymbolFresh`): the compiler calls it when an allocation or a frame reservation
  does not fit. It never returns. Its contract, a named hypothesis like `leave`'s (D320 item 4): calling it
  ends the run, and that end is observed as `exhausted`.
- **Per Host** (each a model of the contract; open per platform):
  - Linux (all three arches, the first instance): write a one-line diagnostic to stderr (`once: out of
    memory`), then `exit_group` with a reserved status. The status must differ from `leave`'s 0 and from
    what a program can pass to `exit@S` — settle whether a reserved value exists (`exit@S` takes any `Int`
    and Linux keeps 8 bits) or whether the diagnostic alone distinguishes it.
  - seL4: report to the parent/monitor through the fault endpoint, then suspend.
  - FreeRTOS: the out-of-memory hook, then delete the task.
  - bare metal: a defined stop (halt loop, LED/serial where the board has one).
  - a VM: trap to the embedder.
- The Host's code lives in `Strata/Hosts/<platform>/Host.<arch>`, beside `once_leave`.

### A.3 The compiler

- Every heap allocation checks the region bound before it bumps: the frontier plus the size against the
  region's end (a symbol beside `once_heap_base`), and calls `once_exhausted` when it does not fit.
- Every frame reservation checks against the heap frontier the same way (`StackRoom`'s
  `hfront + slots b ≤ %rsp`), and a closure call's room (`CallRoom`) likewise.
- Per arch, in `CCC/Target/<arch>/AbstractToX86*.agda` / `AbstractToRiscV.agda`, with the files' externs
  naming the symbol.

### A.4 The proof

- The machines' observable gains the end `exhausted` (the CPU interface, `Denotation.Behavior`), as D320 added
  `returned`.
- At each allocation and frame step the per-arch simulation splits: room (today's proof, with the check's
  `false` branch taken) or no room (the run reaches `once_exhausted`, the Host's contract makes the end
  `exhausted`, and the new case of the relation closes it).
- `HeapRoom`, `StackRoom`, `CallRoom` (three per arch, nine) leave `Once.Certified`'s parameters (they
  never had a `NonVacuous` model; `Certified.Models` lists them as not covered).
- Emptiness probe and model for the Host's new contract, as for `leave`.

## Part C — the cost of the room checks (2026-10-27, with the user)

A.3 as first written puts a compare-and-branch at every allocation, frame reservation and call. The proof
needs only that each reservation fits, so the checks can be coarser:

1. **Coarse checks (the baseline).** One check per block entry covering its frame, the return slot its call
   pushes, and its straight-line heap allocations, as GHC does. The proof shape is A.4's with a bigger room
   check.
2. **Static depth where it is provable (later, an optimisation).** Once has no general recursion and Cata/Iter
   loop rather than nest, so a block that cannot lie on a cycle of closure calls has a static stack bound
   (`ir-stack-requirement`, extended across calls). Such blocks need no check; one check at program start
   covers the bounded part. Higher-order code can nest calls to a data-dependent depth (folding `compose`
   over a list), so blocks that may lie on a cycle keep their check. Needs a call graph over block labels and
   a proof that a block off every cycle has bounded depth. A program with a static bound then also gets a
   theorem: with N bytes of stack it never ends `exhausted`.
3. **Guard pages: REJECTED (user, 2026-10-27).** No check on the normal path, but it needs an MMU (bare metal
   is a goal), a new OS/MMU assumption on the apex, stack probes for frames larger than a page, a fixed
   stack/heap split instead of the shared `[hfront, lo)` region, and it does nothing for the heap.

Running out stays modelled behaviour: the source never runs out, and the compiled program may end
`exhausted` (A.1). Plan 0.124's abstract stack has no floor and relies on exactly this split: the concrete
machine has room (the simulation's proof) or reaches `once_exhausted`.
