# Plan 0.152 — The whole-program checks fit in this machine's memory

## Summary

Two checks type-check the whole proof in one program run: the final check of the certified result, and
the dump that records what the proof depends on. After plan 0.151 they need 6.8 GB and 12 GB of memory
respectively, on a machine with 7.6 GB. Every single file checks in under 4 GB on its own, so the cost is
in holding everything at once. This plan measures where that memory goes and changes the two checks so
they fit with room to spare.

## 1. Why

`make certified` runs out of memory at its default 5.5 GB cap since 0.151 (it passed at 6.8 GB), and
`run-ast-dumps.sh` gave up at 6 GB on `Once.Metatheory.Laws.Combinators` for master and the branch alike
(it passed at 12 GB, through swap). Both are merge gates (MERGE.md §5, §6). A gate that only passes by
raising caps past the machine's RAM will stop passing as the proof grows.

## 2. Where we are (2026-11-17)

- Per module, in its own process (backstop profile, `make profile-report`, 867 modules): peak RSS ≤ 3.8 GB;
  the largest is `Once.Certified` itself, 3775 MB RSS / 2187 MB max residency, 69 s, with every import's
  interface already written.
- Interfaces on disk: 280 MB over 836 modules (the AST staging tree of 0.151).
- `make certified` is one `agda Once/Certified.agda` with `-c` in `formal/`: it checks every stale module
  in the same process.
- `run-ast-dumps.sh` checks each ref with the fork in one process per attempt, resuming from the
  interfaces written so far.

Hypothesis (REFUTED by step 1's first measurements): the single-process peaks come from checking many
modules in one process (each checked module's state stays live).

Findings:
- Live data does not grow with the number of modules checked: ~3 GB at 0, 1 or ~100.
- `-c20` fails at 6 GB with "Heap exhausted" while 3.9 GB is in use; `-c` (compact every major GC) passes at
  the same cap in the same time. The 12 GB default of c49fb6f49 is not needed: `-M6G -c` suffices.
- Memory in use is ~2× live under every setting: GHC's heap-growth factor `-F` (default 2) lets the heap
  grow to twice the live data before a major GC. Next: measure `-F` below 2 (e.g. 1.5, 1.2).
- `make certified` (stock Agda, `-M4800m -c` under the 5.5 GB cgroup) not yet measured: the run (e6) was
  stopped by Claude Code for low system memory after 155 modules while another session's Agda ran.
  Measurements need a quiet machine.
- Done (ee518eec3): `run-ast-dumps.sh` defaults to `-M6G -c` instead of `-M12G -c20`.

### The import graph (2026-11-18, `~/.cache/once-0.152/metrics.py`; 830 modules in the apex cone)

The whole-program peak is not an accumulation: it is the cost of loading a closure's interfaces (the apex
loads all of them: 2.2 GB live) plus the heaviest module's own work, paid together in one process. So the
pieces matter, and so does their import structure, which also decides what a change rebuilds.

- The back end depends on the front end. Of 468 back-end modules (CCC, Adequacy, Arith, Memory, Semantics,
  IR), 378 have `Spec.Surface.Syntax` (expressions, declarations, literals) in their closure; it has 595
  dependents, `Spec.Surface.Generators` 597, `Spec.Float.Decimal` 632. Plan 0.151 changed the generator
  table and ~600 modules rebuilt, the code generator among them. No CCC file uses a surface type.
- Not one edge: cutting `Once.Type → Spec.Surface.Syntax` alone changes nothing. Routes: `Once.Type.Poly`
  (`Ground` over the surface's `PolyType`), `Semantics.ValueIR` (→ SMCore and the machines),
  `Denotation.ValueDomain` (→ `Denotation.Program`, 123 importers).
- The root: `Spec.Surface.Syntax` holds the types as written (`PolyType`, `PolyFunctor`) together with the
  expression syntax, so whoever needs a type as written gets the whole surface language.
- Baseline: 9982 direct edges, sum of closure sizes 58956; 55 `open import … public` left.

### Step A results (2026-11-18)

- A(1), dead imports (bfc94a7f1, 6868a05e0): 570 modules edited by the fork's `--remove-dead-imports`
  (two fork bugs fixed on the way: D14 nested qualifiers, D15 a later open does not scope an earlier
  `M.x`). Direct edges 9982 → 9499 (imports per module 11.6 → 11.0), sum of closures 58956 → 57125
  (average closure 68.4 → 66.3), `Spec.Surface.Syntax` dependents 595 → 581, `Once.Type` 449 → 415.
  Three modules left unreached and were deleted (`CCC.IR.Stack`, `IR.Size`, `Parser.Module.FunDef`).
  Dead imports were the cheap 5 %: the closures are real dependencies (steps C, D).
- Cost of a closure (backstop profile, one module per process): the cheapest module of a closure size
  costs ~2.7 MB live data and ~0.06 s per module in its closure; closure size and live data correlate
  0.76, closure size and wall time 0.39. Not yet split into deserialization vs own work
  (`--profile=modules` in `agda-profile.py` would).
- A(3) premise measured and refuted: making definitions private does not shrink an interface. Agda
  2.8 serializes every definition a public one reaches (a 300-helper module: 207 KB with the helpers
  private or public, `opaque` or not); only private definitions nothing public reaches are dropped
  (82 KB vs 196 KB) — and those are dead code. So "fewer exports" is really "delete dead definitions",
  which needs the fork's `--dead-code` from every root (apex, extraction root, metatheory carrier,
  tests) in a whole-program run, and each unreachable item classified per MERGE.md (superseded /
  unwired prize / metatheorem) — not mechanical.
- Verification cost: `make backstop` (one module per process) re-loads ~57 000 interfaces and took
  ~3 h for A(1). From A(2) on: fast gates per commit, one stock-Agda check in multi-module chunks at
  the end.

## 3. Decisions

- 2026-11-18, the user: the target is two sessions at once on this machine (§5).
- 2026-11-18, the user: tighter imports first, for faster builds as much as for memory; start with the
  mechanical work (dead imports, the remaining re-exports, fewer exports), unattended, stopping only at
  principled blockers. Separating the types as written from the expression syntax changes the Spec: a patch
  for the user's approval.

## 4. Steps

A. **Mechanical, unattended.** (1) The fork's `--remove-dead-imports` over the apex cone minus the Spec
   (frozen); gate; commit. (2) The remaining `public` re-exports with `--repair-reexports`, then dead imports
   over the touched modules; gate; commit. (3) Interfaces: fewer exported definitions where that drops
   imports. Measure edges, closures and dependents after each.
B. **Layering rule + gate:** the back end and the Spec's type/semantics parts import no surface or front-end
   module; a gate beside `lint-imports` reports forbidden edges and the dependents of the surface modules.
C. **Types as written apart from the expression syntax** (e.g. `Spec.Surface.Type`): Spec patch, user approval.
D. **Cut the remaining direct edges** (`Semantics.ValueIR`, `Denotation.ValueDomain`, …) one at a time.
E. **`make certified` per module first** (as the backstop), then the apex on fresh interfaces; `-c` and a
   lower `-F`; lower agda-safe's default cap; measure on a quiet machine (§2 step 1 table).

## 5. Done when

Two sessions can type-check at the same time on this 7.6 GB machine (the user, 2026-11-18): every Agda
run — one module (the backstop), `make certified` from a cold `_build`, and `run-ast-dumps.sh` — passes
under a cap of about 3.3 GB, agda-safe's default is lowered to it, and the measurements are recorded in a
decision entry.
