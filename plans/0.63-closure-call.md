# Plan 0.63 — Model the closure call in the flat machine

**STATUS: SCOPED 2026-08-03, not started.** The last COVERAGE-class gap in
the flat↔x86-64 correspondence: `events-running-call`.

**NEXT ITEM: step 1 below (bodies into the flat program).** Everything else
depends on it.

## The gap

`exec-abstract instr-call-closure = s , alloc` — the IDENTITY — while the
compiled code does `call *0x8(%r12)`: it transfers control to the closure's
code address and later returns. No proof can bridge that; the abstract
machine has to model the call.

`instr-call-closure` IS emitted (`ir-to-trace' n l apply` ends with it), so
this is not a fossil route like `instr-loop`/`lea-indexed`/`case-on-tag` —
it is the lowering of `apply`, a core CCC generator. The residual is
conditioned on the run context, so it is not vacuous; but it is unproven
and unprovable as the model stands.

## Why it is structural, not a proof (verified 2026-08-03)

`ir-to-trace` returns the MAIN trace only — closure bodies come from a
SEPARATE `ir-to-bodies`, which the per-arch emitter emits as its own
labelled blocks (`Once/Target/X86-64.agda` uses both). So the FLAT
machine's program does not contain the bodies at all: there is nothing for
a modelled call to jump to. Inlining is not an option in general — a
closure value's code pointer is only known at runtime (that is what the
`SV-Code` cell is for).

## The work, in dependency order

1. **Bodies into the flat program.** `ir-to-trace` becomes
   `main ++ concat (map (λ (lbl , _ , t) → instr-ctrl (c-label lbl) ∷ t ++ [ret]) bodies)`
   (or equivalent). RIPPLES: `x86-off`/`find-label` correspondence
   (`FlatComposition`), `ir-stack-budget` (each body has its OWN budget —
   the current single-budget `Reachable`/`RunAt` indexing assumes one
   frame), and every emitter walk (`FrameFreeTrace`, `AllocMin`,
   `SlotBudget`, `CataIRSlotStable`, and Plan 0.62's `ShapeTable` walk).
   Do this FIRST and follow the red — the type errors are the work list.
2. **A return-address stack in `FlatState`.** New field; `instr-call-closure`
   reads `SV-Code lbl` from the closure record (cell 1 — which Plan 0.62's
   `shape-closure` already guarantees is there!), pushes `suc (fpc fs)`,
   jumps to `find-label prog lbl`; a new `instr-ret` pops. The concrete
   side already does exactly this with the machine stack, so the
   correspondence gains a stack-of-return-addresses component (and `%rsp`
   moves at call/ret — the layout invariants must accommodate it, cf. the
   `stackSlot` discipline).
3. **The per-body frame.** Each body has its own `body-budget`; the
   prologue/epilogue bracket is per-body. `RunAt`'s single
   `ir-stack-budget run-ir` must become "the budget of the frame we are
   currently in", i.e. the return stack carries budgets too. This is what
   makes `run-stack-slot` (currently "the window never moves") a
   per-frame statement.
4. **The block-step + routing.** With 1–3 in place, `block-step-call-closure`
   is an ordinary two-part correspondence (call ↦ push+jump, ret ↦ pop+jump)
   and `events-running-call` is routed like every other instruction.

## Honest size

Bigger than item 6 (case→flat control), because it adds STATE to the flat
machine rather than relaying out a trace. Step 1 alone is a session; steps
2–3 interact with every layout invariant landed in rung D (`FlatStackSlot`,
`FlatStackPtr`, `FlatPtrBounds`, the `lo`/high-water mark). Budget 3–5
sessions and expect to re-run the vacuity probe afterwards (a new state
component means new residual shapes).

CHANGES THE EXTRACTED COMPILER (step 1 changes `ir-to-trace`) ⇒ the full
malonzo + cabal + exit-test ×3 cycle applies.

## Non-goals

  `events-running-fetch` is open.
- This plan does NOT touch the D061 FFI trust base (see D080) — an
  external SigOp's `call-sym` is a different mechanism from a closure call.
