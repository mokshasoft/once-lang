# Handoff — `compose <effectful> <pure-morphism>` does not typecheck (frontend gap)

## Status (2026-07-01, after rebase onto master)

The branch `plan-0.53-per-arch-flat-swap` has been **rebased onto `origin/master`**,
which carries the Plan 0.52 **compose/case pure-eff subsumption** (35ec00eb,
d691c562, 258be3f6). That fix is present but **does NOT resolve this** — the 8
emit/trace tests still build-fail on all three arches. It handles grade-poly
**builtins** but not the specific case the fixtures hit (below). Apex green,
both backends verified intact post-rebase.

## One-line (refined)

Composing an **effectful SigOp** (`exit@S`, `emit@E`) with a **user-defined
pure morphism** does not typecheck. In check mode `compose`'s arm is forced to
a **pure** arrow, and an eff SigOp does not fit:

```
-- main : IO Unit ; main = compose exit@S c    (c : Unit -> Int)
Type mismatch: expected (Int ω→ Unit) but got Eff Int Unit
```

Contrast — these DO typecheck (so the machinery is partly there):
```
main = compose exit@S id      -- id is a grade-poly builtin  → OK
main = exit@S (c unit)        -- application form            → OK
```

The gap is specifically **a `compose` whose effectful-SigOp arm is composed
with a user-defined (non-builtin) pure morphism**: `compose` must be grade-poly
there — accept the eff arm and yield an eff result — as it already is for `id`.
Plan 0.52 grade/subsumption territory (surface typechecker); no backend change
fixes it.

## Minimal reproduction

```
-- fails: "Cannot infer type: compose: expected type mismatch"
import I.Linux.Syscalls as S
c : Unit -> Int
c u = 5
main = compose exit@S c
```

```
-- works (application form, not compose):
main = exit@S 5
```

Build to reproduce (any arch; it is a frontend/typecheck error, arch-independent):
```
once=$(cd compiler && cabal list-bin once)
$once build --exe --target x86_64 --alloc heap --no-optimize \
  --strata "$PWD/Strata" /path/to/repro.once -o /tmp/x
```

`exit@S : Eff Int Unit`, `c : Unit → Int`. `compose exit@S c : Unit → Unit`
should typecheck: `c`'s codomain `Int` matches `exit`'s domain `Int`, and the
pure `c` should **subsume** into the effectful position (pure→eff is
subsumption per D068). Today it is rejected as a type mismatch.

Historically this was written `compose exit@S (arr c)` — the `arr` lifted `c`
into the effect realm. **`arr` was retired (D068), and the subsumption that was
supposed to replace it is not applied in `compose`'s argument position.** Both
`compose exit@S (arr c)` (arr no longer in scope) and `compose exit@S c`
(subsumption gap) fail.

## Where to look (frontend)

- `formal/Once/TypeCheck/Classify.agda` — `composeArgB` / `composeArgB-rvar`
  (~line 250–300): computes the intermediate type `B` of `compose f g` by
  finding `g`'s codomain and threading it to `f`. This is grade/purity-blind;
  it likely needs to accept a pure arm where an eff arm is expected (or the
  mismatch check downstream must subsume). `terminal`/`fst`/`snd`/`id` are
  special-cased here — note `terminal` is exactly the builtin that also errored
  in the cata-emit fixture (`arr terminal` → "Unbound … terminal").
- `formal/Once/TypeCheck/Judgment.agda` — the subsumption machinery
  (`embedOrSubsume`, `t-subsume`, `classifyEffArrow`, D068/D069). The
  pure→eff subsumption lives here; the fix is presumably to route `compose`'s
  arms through it.
- `formal/Once/Surface/Elaborate.agda` / `formal/Once/TypeCheck/Elaborate.agda`
  — where `compose` is elaborated to IR (`m-compose`, D032 grade-poly compose).
- `formal/Once/TypeCheck/Error.agda:163` — the `": expected type mismatch"`
  message being emitted; trace back its caller to find the exact rejection site.
- Decision log context: **D065** (bare morphisms grade-free), **D068** (pure→eff
  is subsumption, arr retired), **D069** (effect-free intros grade-poly),
  **D032** (compose/case/cata grade-poly). Plan `0.52-pure-eff-subsumption-retire-arr`.

## Note / caution

Do **not** "fix" this by special-casing the fixtures to application form —
`compose <eff> <pure>` is legitimate surface and the emit-ordering tests
(`TraceSpec`) specifically exercise compose chains + effect ordering. The right
fix is the subsumption in `compose`, per Plan 0.52's own design (D068).
