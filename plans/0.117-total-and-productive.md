# Plan 0.117 — Once is total and productive, and a server is an ordinary function

## 0. Why

GOAL.md requires servers, and it asks termination only of PURE computations; of effects it asks
productivity. Under D311 `Eff A B` meant `A → T B` with `T` inductive, so an effectful program had
to stop — and a program that must stop is not truly productive (the user). D312: `Eff` is the free
completely iterative monad. A pure computation is a value (total); an effectful one reaches each
next event after finite work and need not stop (productive); `main : Eff Unit Unit` is a server as
well as a program that ends.

## 1. The mathematics (what a reader of the Spec should find)

* `T X` — the free monad on the call/halt signature `Σ`: the INITIAL algebra of `Y ↦ X + Σ Y`.
  Finite trees. It stays as the IR's finite denotation and as the shape of one guarded round.
* `T∞ X` — the free completely iterative monad: the FINAL coalgebra of the same functor; possibly
  infinite trees, no silent node. `Eff A B = A → T∞ B`. Equality is bisimilarity (D201).
* Grades, the chain `pure ⊑ act ⊑ eff` (D314): `M pure X = X`, `M act = T`, `M eff = T∞`;
  sequencing's product is the join, so a shared grade is the graded bind.
* `μ` initial (`fold`/`cata`), `ν` final (`unfold`/`ana`). The loop (D314): a step
  `f : A → T (B + Req A)`, `Req A = Σ_op Arg_op × (Ans_op → A)` (the signature functor `H_Σ`), a
  `T ∘ F`-coalgebra as GOAL.md says; `iter f : A → T∞ B` is the unique map into
  `νY. T (B + Req Y)` flattened into `T∞` (every round that continues has a call at its root:
  guardedness is the functor's shape). `T∞` is completely iterative as a consequence of finality.
* T+P: `M pure X = X`; every `T∞` tree is productive by the shape of its functor (no silent
  node); `Behavior n` of any program is computed by a total function of `n` (`events∞`).

## 1a. The principle (user, 2026-10-14) — every F/G/H decision answers to it
* A program is a composition of natural transformations and structured-recursion morphisms; the
  composition is what it is. So the MEANING of `g ∘ f` is determined by `g` and `f` alone, and so
  is its TYPE: the composite's grade is COMPUTED from its arms — the graded monad's bind
  `M π₁ A × (A → M π₂ B) → M (π₁·π₂) B` — never chosen by context.
* A signature only CONFIRMS that result (D007: an assertion, not a coercion). A name's type is its
  body's principal type; a signature that differs from it is an error. So CHECKING A BODY AGAINST
  A SIGNATURE WITH SUBSUMPTION GOES: it is what lets a signature change the type (closes
  language.md "Open" item 2 in D007's favour).
* Consequence: the surface type language must be able to WRITE every principal type, or a
  definition cannot be named or abstracted over (`echoOnce : Act Unit Unit` would be rejected and
  the right signature unwritable).
* Applied (D314, user-approved 2026-10-14): option D — guardedness is in the loop's FUNCTOR, not
  a grade, so no type ever says "guarded" and `echoOnce : Act Unit Unit` is exact. Option B (a
  fifth grade `act⁺`, call-count intervals) would have made `Act⁺` the principal type of every
  one-call helper. The CompGrades draft is on branch `attic/f3b-compgrades`.
