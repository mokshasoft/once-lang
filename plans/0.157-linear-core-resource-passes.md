# Plan 0.157 — The linear core's resource passes: values owned once, updated in place, checked only where they can grow

## Summary

Plan 0.146 made every program run through a linear core whose memory behaviour is proved (every cell
allocated is freed exactly once). It kept the code simple so the proofs stand on something stable, and the
code is not yet clean: against master (2026-11-24, D487) `.text` is 2.5×, run time 2.4× per program,
room checks 9.3×, and a list carried through a loop is copied every round (`bench/list-build-sum` is
quadratic). This plan says what Once's memory model SHOULD be, and gets there in steps, each proved and
measured, guided by two invariants beside `NoLeak` (§4: `NoCopy`, a linear program runs without a copy, D6;
exclusive writes, D7):

* a value has ONE owner, and only the owner may change it: values are updated in place (a dying cell
  reused for its replacement, a layer built where it will live, memory freed at its last use);
* a read is a BORROW, whose scope ends before the owner's next write; a copy is made only where two owners
  genuinely outlive each other;
* the stack and the heap are bounded statically where the program allows it, and a program whose bounds
  are known runs WITHOUT runtime checks, still verified (CakeML's model: running out is an allowed
  outcome, stated in the theorem; checks only where memory can grow).

It is merged together with plan 0.146 (the user, 2026-11-24): the state after 0.146 alone is not the state
to merge.

## 1. Why

GOAL.md: "memory is managed by the compiler from the program's structure", at speed parity with master and
towards C. Today the structure is lost on the way down: the bridge from the Spec's calculus treats every use
of a variable as owning (`FromExpr.split` puts a `dup`, a deep copy, wherever two parts of an expression use
it), builds both arms of a `case` combinator as closures before choosing (`Lq` of `copair'`), and the
lowering then checks the heap against the stack at every block entry and after every call, because heap and
stack share one region and nothing is known statically about either. Each of these is correct and proved;
none is what the language calls for.

Reasoning is from the model this plan reaches, not from today's code: today nothing mutates, so "who frees
it" looks like the whole of linearity. With in-place update it is "who may overwrite it", and the bridge's
`dup`s are then not waste but the price of having made two owners where the program has one.

## 2. The model (what Once should be)

1. **Ownership is the right to overwrite.** A value has exactly one owner. The owner may consume it, free
   it, or reuse its cells in place (a fold rebuilding a node, `r-cata-reuse`; a constructor replacing a
   dying node of the same size; a pair updated field by field). Nobody else can observe that, so in-place
   update preserves the meaning.
2. **A read is a borrow** (D422: `lend : BTm E A B → LTm (E ⊗ A) (E ⊗ B)`, `bfst`, `bsnd`, `bcopy`). The lent
   value sits in the frame while the borrower runs; `E` is no core type, so a borrow cannot escape into a
   result, a closure or a seed. **The borrow rule**: no write, reuse or free of a value while it is lent. In
   the core it holds by construction (the owner's context is not reachable inside `lend`'s scope; the frame
   rule of `exchange` makes it a theorem), and every in-place pass is proved against it (§4 D2).
3. **A copy only for two surviving owners.** `dup` (a deep copy) is the core's one way to make a second
   owner. The bridge emits it only where the program keeps two values alive that will both be owned on —
   never for a read (a borrow), never for two arms of which one runs (the arms share the context: `⊔`, not
   `+`). Reference counting of data that can be updated in place is against this model (copy-on-write
   undoes in-place update); not part of this plan.
4. **Bounds, then checks** (CakeML: `MakeSpace` reserves per stretch, a pass merges reservations; the
   theorem allows "out of memory"; the space cost semantics proves when it cannot happen). The stack and the
   heap get their own regions. A program's stack bound is computed from the call graph (closures are
   labelled at compile time, D424, so the graph is static; loops are iterative; only recursion over data,
   a fold, has a data-dependent depth). Its heap bound comes from the space claim (D430) over a cost model,
   once frees and reuse make loops allocation-neutral. Where both bounds are known, the start checks once
   that the regions hold them (a premise of the theorem) and the code has no checks. Where a bound is
   unknown, checks stay only where memory grows: a fold's entry (stack), the allocator routine (heap).
5. **`--unchecked`** removes the remaining checks, for comparison with master and for trusted inputs. The
   compiler states, when a bound is unknown, that the verification no longer covers running out of memory.
   (Open: whether it also removes the allocator's heap check; recommendation in §4.)

## 4. Decisions

Decided:
* **D468** (the user, 2026-11-19): resource passes live in the linear core or its lowering, each proved to
  keep the core's meaning and `NoLeak`; nothing in the Spec's calculus knows about cells.
* **The merge** (the user, 2026-11-24): this plan and 0.146 merge together.
* **The order** (the user, 2026-11-24): S1, S2, S3, S4 below.

Open (each gets a D-entry, recommendation first):
* **D1. Regions.** Heap and stack in separate regions (the Host's contract and the seL4 layout change:
  two regions handed to the program, each with its size). Recommended: yes; everything in S1 depends on it.
* **D2. The borrow rule's statement.** As a property of the core's runs (no event on a lent value but
  reads), proved once, which each in-place pass cites. Recommended: state it in `Events` with S2, before the
  first pass of S3.
* **D3. `--unchecked`'s scope.** Recommended: stack checks only; the allocator keeps its heap check (a full
  heap unchecked is silent corruption, and the check is one comparison per allocation, inside a call).
* **D4. A `case` over closure-building arms** (D481's B2): compile `app (copair' f g) x` as a branch when
  each arm is a closure construction; for an arm that is a partial application of a definition, carry
  "this definition's body is a `lam`" through the bridge's references (`Rs`, `RefOK`). Recommended: B2
  (no surface change; the alternative, inlining, is behind a flag).
* **D5. Layers in place: how far** (from the first version: D455's destination passing vs a fusion at the
  image). Recommended: decide after S2, from the measurement.
* **D6. `NoCopy`, beside `NoLeak`** (decided by the user, 2026-11-24: "make the linearity and no copy an
  invariant just like NoLeak … if linear then no copying, not enforcing linearity everywhere"; the form
  agreed the same day). Linearity is not enforced on every program; a linear program is GUARANTEED no copy:
  ```agda
  NoCopy : Set₁
  NoCopy =
    ∀ (FS : FrameSemantics) (m : Resolved) (srcs : List CompiledSrc) → srcModule Heap false m ≡ inj₂ srcs
    → ∀ {T : Type} (pm : T <: EffUU) → mainOf srcs ≡ just (T , pm)
    → Linear srcs pm                                     -- the program is linear
    → ∀ (fs₀ : FlatState) → EntryLike fs₀ → …            -- as NoLeak's
    → Run.CopyFree FS (EmittedImage FS srcs pm) fs₀      -- no state of the run is inside a copy block
  ```
  * **Where**: `Once.Implementation`, beside `NoLeak` (same quantification, same image, same runs), listed in
    `Certified`, proved by the same apex.
  * **`Linear`**: a decidable predicate on the checked program (the compiler's `Expr`, which carries the
    Spec's grades): a statement about how the program uses its values, not about compiler choices.
    (Clarified 2026-11-26, the user: NoCopy, like NoLeak, is a codegen guarantee, not meaning; the Spec's
    meaning is indifferent to copies. The Spec term ↔ `Expr` bridge is a meaning claim and is not needed.)
    It refines QTT's `Many`: a variable read many times and owned once is `Many` in the Spec but linear here.
    No variable of a CELL-OWNING type is owned more than once on any path:
    * a use is OWNING when it consumes the value or moves it into a result, a cell or a closure that runs;
      it is a READ when it only projects to a copyable value, compares, inspects a tag, or passes the value
      to a function that only reads it (computed over the whole program: Once compiles whole programs);
    * the arms of a case are alternatives (`⊔`), including a `case` combinator over closure-building arms
      (D4: only the chosen arm is built);
    * reads are pure, so they are scheduled before the owning use whatever their textual order.
    COPYABLE types (no cells: `Int`, `Float`, `Unit`, sums and products of them) are exempt: their copy is
    words, not cells. Every other type can be linear: μ and ν types and closures are what the claim is about.
    The exemption is by type, not by representation (D455's frame-local nodes change nothing).
  * **No change to the Spec**: its grades stay `Zero | One | Many` (`Spec.Grade`); `Linear` refines `Many`
    by classifying the extra uses. A read grade or read-only arrows in the Spec (linearity modular and
    visible in types) is a later language decision, not needed for the theorem. A program that is not
    linear compiles as today, with a copy exactly where a value is owned twice; the compiler names those
    places (a warning, "copied here").
  * **`CopyFree`**: no state of the run is inside a copy block (a type's `kcopy` block, its trampoline):
    the machine-level form of "no copying", as `LeakFree` is of "no leak".
  * **The proof, in steps**: `Linear` → the bridge emits no `dup` (by induction beside `Lq-ok`) → the image
    calls no copy block → no run enters one.
  * **Later, with the space claim (S4)**: the cost form, every allocation of a run a construction of the
    source (each `In`, closure, `ana` layer), exactly once.
  * `step p = case (next p) (stop p) (fst p == 0)` is linear (`fst p == 0` a read; one owning use per path,
    the arms alternatives), so after S2 `list-build-sum` copies nothing by the theorem, not by measurement.
* **D7. Exclusive writes** (what makes in-place update sound, beside `NoLeak` and `NoCopy`): every write,
  reuse or free of a cell happens with no live borrow of it, by its one owner. The count proof of `NoLeak`
  extends: a borrow count per cell (`lend` opens and closes one), a write or reuse needs owner count 1 and
  borrow count 0. In the core it follows from `lend`'s scoping (the frame rule, D422); every pass of S3
  preserves it. Recommended: stated in S2, before the first in-place pass.

## 5. Steps

Each step: a D-entry, `make certified` (every module under 60 s), the exit tests on three arches (each
compile under 5 s), the seL4 tests, `cabal test`, `tests/perf-compare.sh` against the step before and
against master, and the acceptance tests (§6).

* **S1. Regions, the stack bound, `--unchecked`.** (D488 and its amendments.) One region split by a stack
  limit `L` (record word 0) that the start sets after its own check; heap checks in the allocator against
  `L`. **Every program's stack is statically bounded** (the user, 2026-11-24): a fold's *algebra* runs on the
  stack (its frame is static, and folds nest only as deep as the text), its *recursion* — the pending level
  per node, the only part that grows with the data — lives on the heap as a worklist, freed as the fold
  climbs (with S3's linearity, by pointer reversal in the consumed input's own cells: no allocation). So `B`
  is exact for every program, the start sets `L = sp − B`, and there are **no stack checks at all**; the only
  exhaustion is the heap's, in the allocator. Where no bound is certified, the start reserves nothing and
  every call is checked (D491 stage 4; `start-stack-words` is only the producers' placeholder, no
  `--stack-words N`). `start-fits`/`room-fits` are proved by a pipeline gate, not assumed.
  `--unchecked` (D3, D489). Work order: (a1), (a2), the fits gate, (a3) `instr-room h s` and the budget
  split — done (a uniform slack `K` was built and measured, no gain: D488 amendment 3, not taken); the
  flagged calls' frames to the heap (D491: one rule for fold, copy, free and closure chains); the static bound `B` (`Codegen.StackDepth`: per-function depth,
  a checked certificate, over the then-acyclic call graph); the stack checks removed. Measured against
  master with and without the flag.
* **S2. Owned once.** The bridge: a `case` applied to arguments as a branch (D4; B1 LANDED 2026-11-26,
  D481: arms that evaluate at once, `FromExpr.Im`; `list-build-sum` linear, 1.73M at N = 1000); a read-only use as a
  borrow wherever the bridge can see it (generalizing D477's scrutinee and pair cases: a variable read in
  some sub-expressions and owned in at most one gets `lend`, no `dup`). `Linear` defined and `NoCopy`
  proved (D6); the borrow rule stated (D2, D7).
  `list-build-sum` copies nothing, by `NoCopy`.
* **S3. In place.** First, the data-deep recursion off the stack (D491, the user 2026-11-26): a fold over
  owned data by pointer reversal in the consumed input's cells, `kfree` in the cells it frees, `kcopy`
  through the copy's new cells, a fold over borrowed data by a heap worklist; the arrow-carrier fold's
  closure chain to be worked out. Then the depth table flags no call, every stack is static, `L` never
  moves (a server's large request no longer lowers it for later rounds). Measured on runtime, code size and
  memory against the flagged calls it replaces. Then the resource passes, in the order measurement shows they pay: layers in place (D5;
  D455/D469), free at last use (D430), reuse of a dying node's cell for its replacement (beyond
  `r-cata-reuse`), a pair or sum updated in place by its owner. Each proved against the core's meaning,
  `NoLeak` and the borrow rule.
* **S4. The heap bound.** The space claim (D430) over a cost model of the core: a program whose live heap
  is bounded (a loop that replaces its state) gets its bound; with S1's stack bound, its code has no
  checks and the theorem's premise is the start's check.

## 6. Acceptance tests (how clean a decision is)

* **`bench/loop-sum`**: after S3 no allocation per round; after S4 no runtime check, still verified.
* **The corpus against master**: `.text`, run time, checks, frames, calls (§3's table) at each step.
