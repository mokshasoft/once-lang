# Plan 0.19: Surface `sigOp` / `closure` ABI split

## Goal

Eliminate the conflation of two distinct asm-level ABIs under a single
Surface constructor (`sigOp`). Make the Surface type of every named
top-level reference match the asm signature of its entry-point routine,
so the typechecker mechanically rejects the bug-shape that currently
exits with the low byte of a closure pointer.

## Diagnosis (session 2026-05-23)

`myid = id; main = exit@S (myid 42)` exits **80** instead of 42 under
`--alloc heap`. Side-by-side asm vs the working `exit@S (id 42)`
(exits 42) shows:

- `id 42` (works): typechecker classifies head as `ahv-id`, emits
  `morph-app id 42`. Elaborates to `id ∘ const 42 ∘ terminal` — pure
  CCC compose, no `apply`, no closure record.
- `myid 42` (broken): typechecker classifies head as `ahv-other`,
  emits `app (sigOp "myid") 42`. Elaborates (via the function-typed
  `sigOp` clause in `Surface/Elaborate.agda:272`) to
  `curry (SigOp myid ∘ snd) Heap`. At runtime the curry's body
  invokes `once_myid(42)` and uses the returned value as the
  application result. But `once_myid` was compiled from `myid = id`
  as a *curry-wrapped Unit-input closure-allocator*: it ignores its
  input and returns a heap closure pointer. `apply` then forwards
  that pointer to `once_exit`, which exits with the low byte (80).

Both cases route through `sigOp` (the working case also calls
`once_exit` via a sigOp). So "goes through sigOp" is not the
distinguishing axis. **The distinguishing axis is whether the
asm-level entry-point ABI matches the Surface type that was declared
for it.**

| Entry | Surface type | asm signature | Match? |
|---|---|---|---|
| `exit` (syscall) | `Int → Unit` (eff) | `once_exit(Int)` runs syscall | ✓ |
| `myid` (user-defined morphism alias) | `Int → Int` | `once_myid(Unit) → Closure(Int → Int)` | ✗ |
| `make-adder` (user-defined w/ capture) | `Int → (Int → Int)` | `once_make_adder(Unit) → Closure(Int → Closure(Int → Int))` | ✗ |

The mismatch is invisible at typecheck time because both ABIs are
funnelled through the same `sigOp` constructor.

## The postulate hiding the bug

`formal/Once/Surface/Correct.agda:281-284`:

```agda
elaborate-correct ρ (sigOp {A = Dom ⇒[ k ] Cod} name) =
  sigOp-arrow-eta {Dom} {Cod} name
  where
    postulate
      sigOp-arrow-eta : ∀ {Dom Cod} (name : String) →
        evalSurface ρ (sigOp {A = Dom ⇒[ k ] Cod} name)
          ≡ eval′ (elaborate (sigOp {A = Dom ⇒[ k ] Cod} name)) (interpEnv ρ)
```

The postulate is inline in the proof body — it has never appeared in
`Once.Postulates`, never been audited as part of the trusted base,
and never been narrowed to its actually-defensible scope (external
primitives where the asm-level routine genuinely implements the
declared arrow). It silently covers user-defined arrow-typed
top-level fns whose asm signature is `Unit → Closure(…)` — exactly
the bug class.

Backing axiom: `generic-semI : ∀ {A B} → String → ⟦A⟧ → ⟦B⟧`
(`formal/Once/Arith/SigOp/Builders.agda:115`). Untyped and
unconstrained — provides a function value at every type for every
name, so `sigOp-arrow-eta`'s pointwise equality always typechecks.

## Why prior fix paths are insufficient

Three previously-proposed paths only patch the symptom for a subset
of programs and leave the postulate (and the conflation) in place:

- **"Substitute morphism aliases inline"** (the *open item* in
  `plans/0.2.4.5-morphism-realm-split.md`, fix path A3 in
  `plans/0.13-layer-survey-2026-05-09.md`, fix path (b) in
  `plans/0.12-categorical-layer-1.md` Gap #4). Rewrites `myid 42` →
  `id 42` via `lift-morphism` substitution at use sites. Fixes the
  symptom for pure morphism aliases (`myid = id`) but does nothing
  for closures with captures (`make-adder n = …`) — which still
  end up as `sigOp` with mismatched ABI. `sigOp-arrow-eta` stays.
- **"Heap-pool returned closures"** (A1 in 0.13). Patches the
  dangling-pointer angle of the closure-ABI but keeps `sigOp` as
  the universal carrier; the type/asm mismatch survives untouched.
- **"Caller-pre-allocated out-param"** (A2 in 0.13). Same — ABI
  reshape that doesn't address the Surface/asm type alignment.

None of these makes the typechecker *refuse* the encoding that
produces exit=80; they just make some encodings less wrong by accident.

## Design

Carve the design space so each Surface constructor has exactly one
asm ABI and the Surface type matches:

| Constructor | Represents | asm signature | Surface type |
|---|---|---|---|
| `lift-morphism m` | Inline CCC morphism (no name) | pure compose, no ABI | `A ⇒ B` |
| `sigOp name` | External pure morphism (syscall, intrinsic) | direct arrow `A → B` | `A ⇒[k] B` matching asm |
| `closure name` *(new)* | User-defined entry returning a closure value | `Unit → Closure(A → B)` | matches asm exactly |

Resolution rules:

1. **External primitives** (entries declared via `signature foo :
   …` in a `Strata/Interpretations/…` module) → `sigOp name`. Asm
   `once_<name>` genuinely implements the declared arrow.
   `sigOp-arrow-eta` narrows to this case only and becomes
   defensible — or dischargeable per-primitive via PreservesCCC
   instances tied to actual asm behavior.

2. **User-defined fns whose elaborated body has the form
   `lift-morphism m`** (= pure morphism realm, no captures) →
   `resolveExprWF` substitutes the body inline at use sites. The
   reference never reaches the elaborator as a named entry; no
   `sigOp` or `closure` involved. Generalises today's `poly`
   substitution path beyond polymorphic defs (a rename of `poly`
   or an extension of `polys : PolyCtx` to cover non-polymorphic
   morphism aliases is part of this work).

3. **User-defined fns with captures** (closures proper) →
   `closure name`. The Surface type is the *asm-curry* shape
   (`Unit ⇒ (Dom ⇒[k] Cod)` for nullary top-level; richer for
   parameterised cases). Use-site syntax `make-adder n` desugars
   in the typechecker to `apply (closure "make-adder") n` —
   double-apply that matches the asm ABI. No postulate.

After the split, the typechecker has the information it needs to
refuse the bug-shape: a user-defined fn with arrow type can only
appear as `lift-morphism m` (via substitution) or `closure name`
(with explicit asm-matching Surface type). It cannot become
`sigOp` with a Surface type that mismatches its asm signature.

## Conceptual claim being enforced

> A `sigOp name : SExpr Γ Ψ A` is well-formed only if the asm-level
> routine `once_<name>` genuinely implements a function of type
> `A` (where `A = Dom ⇒[k] Cod` means a first-order arrow taking
> `Dom`-shaped input in the standard input register and producing
> `Cod`-shaped output, without intermediate closure allocation).

External primitives satisfy this by virtue of being hand-written asm
with that contract. User-defined fns do *not* satisfy this in general
— the compiler generates them as Unit-curry-returning-closure
routines. Hence they cannot be `sigOp`.

## Implementation

### Phase 1 — Surface constructor split

`Once/Surface/Syntax.agda`:

```agda
sigOp   : ∀ {n} {Γ : Ctx n} {A} → String → Expr Γ zeroUsage A
closure : ∀ {n} {Γ : Ctx n} {Dom k Cod}
        → String → Expr Γ zeroUsage (Unit ⇒[ mk-kind Zero pure ] (Dom ⇒[ k ] Cod))
```

`Once/Surface/Semantics.agda`, `Thinning.agda`, `Elaborate.agda`,
`Correct.agda`: add clauses for `closure`.

`closure` elaboration: `elaborate m (closure name) = SigOp ext-info-for-closure ∘ terminal`
— matches what `sigOp` currently does at the *non-arrow* case (because
the Surface type *is* now Unit-curry, which is itself a function type,
but elaborated as a direct entry-point reference). The crucial
difference vs today's `sigOp` at arrow type: no double-curry wrap.

### Phase 2 — Narrow `sigOp-arrow-eta`

Move `sigOp-arrow-eta` from inline-postulate to a named entry in
`Once.Postulates` (matching the disclosure discipline). Narrow its
type to range over external primitives only (e.g. via a `IsExternal :
String → Set` predicate the `signature` desugaring witnesses). User-
defined names cannot inhabit the precondition, so the postulate is
unreachable from user code.

### Phase 3 — Resolver extension for morphism aliases

`Once/TypeCheck/Resolver.agda` (or wherever `resolveExprWF` lives):
extend the polys table (or rename to `aliasCtx` with a Bool field
distinguishing polymorphic from morphism-alias) to carry entries for
user-defined fns whose elaborated body is `lift-morphism m`. The
resolver substitutes those references inline. Same machinery as today's
poly substitution — just a wider eligibility check.

### Phase 4 — Typechecker dispatch for `closure`

`Once/TypeCheck/Elaborate.agda`:

- `inferElabV-RVar-lookup-aux`: when looking up a user-defined name
  that did NOT take the resolver path (Phase 3 ineligible — captures
  present), return `Surface.closure name` with the Unit-curry Surface
  type, instead of `Surface.sigOp name` with the user-declared arrow
  type.
- `inferElabV-RApp-other-aux`: when the head is `Surface.closure name`,
  emit the double-apply: `Surface.app (Surface.app (closure name)
  Surface.unit) argE`. (Or a dedicated `closure-app` constructor if
  the proof obligations are cleaner that way.)

### Phase 5 — Codegen `closure name`

`Once/CCC/Target/X86-64/Codegen.agda` (and per-arch peers): `closure
name`'s IR is `SigOp (closure-info name) ∘ terminal` (same shape as
external `sigOp` for a non-arrow result type — because the Surface
type is `Unit ⇒ (Dom ⇒ Cod)`, treated as a value-of-function-type, and
direct-entry reference produces the closure value the asm routine
returns).

`Bridge.hs`: MAlonzo wiring for the new constructor.

### Phase 6 — Compile-time registration

`Once/Compile.agda` (Haskell driver): after elaborating each top-level
`f = e`,

- If `elaborate e` has the form `lift-morphism m`, register `f` in the
  alias table (resolver substitutes references).
- Else, emit `f` as a `closure`-class entry. The compiled body is
  `curry … Heap` as today; this is exactly the asm signature now
  documented in the Surface type of `closure name`.

External `signature` declarations register as `sigOp`-class with the
declared arrow type.

## Cascade scope

- `Once/Surface/Syntax.agda` — 1 new constructor (~10 lines)
- `Once/Surface/Semantics.agda` — 1 eval clause (~5 lines)
- `Once/Surface/Thinning.agda` — 1 rename clause (~5 lines)
- `Once/Surface/Elaborate.agda` — 1 elaborate clause (~5 lines);
  narrow the arrow-`sigOp` clause to external-only
- `Once/Surface/Correct.agda` — narrow `sigOp-arrow-eta`, add
  `closure-correct` (likely `refl` by construction, mirroring
  non-arrow `sigOp`)
- `Once/TypeCheck/Elaborate.agda` — lookup distinguishes
  external/user; user-fn dispatch emits `closure` + double-apply
- `Once/Compile.agda` (Haskell) — registration logic
- `Bridge.hs` — MAlonzo constructor wiring
- Resolver — extension (or rename) of poly substitution to cover
  morphism aliases
- `Once/Postulates.agda` — move and narrow `sigOp-arrow-eta`

Estimate: 4-6 days, with the typechecker dispatch + proof updates
being the bulk.

## Test predictions

After the split:

- `exit@S (id 42)` → exit 42 ✓ (already works; no change)
- `exit@S ((id . id . id) 42)` → exit 42 ✓ (already works)
- `myid = id; exit@S (myid 42)` → exit 42 ✓ (NEW PASS via Phase 3
  resolver substitution)
- `swap p = (snd p, fst p); exit@S (fst (swap (99, 42)))` → exit 42
  ✓ (NEW PASS — `swap` elaborates to `lift-morphism (⟨ snd , fst ⟩)`
  ish, eligible for resolver substitution)
- `make-adder n = \x -> x + n; exit@S (make-adder 5 37)` → exit 42
  ✓ (NEW PASS via Phase 4 double-apply; `make-adder` is genuinely a
  closure with capture, so it takes the `closure` constructor path)
- `let f = if cond then (+1) else (+2) in f 42` — still requires the
  closure-realm ABI work (returned closures from branch arms); the
  Surface/asm alignment fix here doesn't address the
  branch-returned-closure dangling-pointer problem, which is a
  separate codegen issue tracked in `0.2.4.5-allocmode-semantic-
  clarification` and related.

## Why this is the principled fix

1. **Eliminates the conflation.** Each Surface constructor encodes
   exactly one asm ABI. There is no longer a single constructor
   that means "external syscall *or* user-defined closure
   depending on context."
2. **Narrows the trusted base.** `sigOp-arrow-eta` becomes
   reachable only from external primitives, where it states a
   provable-per-asm-routine fact (and could itself be discharged
   per-primitive in a follow-up). The user-defined case becomes
   structurally impossible — no postulate masks it.
3. **Surface types tell the truth.** A `closure name` declares
   its asm-curry shape openly; readers don't need to know "the
   elaborator silently wraps function-typed sigOps in a curry".
4. **Mechanical bug rejection.** The exit=80 encoding is
   unrepresentable: there is no way to construct a Surface AST
   where a user-defined fn appears under `sigOp` with a non-
   asm-matching Surface type.
