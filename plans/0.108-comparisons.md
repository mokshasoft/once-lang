# Plan 0.108 — Comparisons

## 0. The property

> `a < b` (and `≤ > ≥ == !=`) on `Int` MEANS the signed word comparison, as a value of
> `Bool = Unit + Unit` with **true = inr**, and the compiled program COMPUTES that value — with no
> postulate on the meaning, the correctness or the link.

## 1. The measurement (2026-10-04)

Three gaps, one per layer, all the same six SigOps (`arith.{lt,le,gt,ge,eq,ne}.int`):

* **Meaning** — `lt-semM … ne-semM` are POSTULATED (`Arith/SigOp/Builders.agda`: "comparisons
  need a Bool encoding decision"). The spec does not say what `a < b` is.
* **Correctness** — their codomain `Unit + Unit` is not a register value, so the SigOp clause
  routes them to `obs-correct-sigop-rest` (plan 0.88's row).
* **Link** — the arith recogniser lifts only `Int`/`Float`-codomain trees, so a comparison stays
  a `call-sym arith.lt.int` that nothing defines: `FileWF.file-wf` (D262) is FALSE for it, exactly
  as `program-symbols-resolvable` was. No exit test uses a comparison, which is why nothing failed.

## 2. The decision: Bool = 1 + 1, true = inr

`Bool` is the coproduct `1 + 1`; a predicate is a morphism into it, and which injection is "true"
is a convention fixed once. **true = inr (tag 1)**: the machine's sum tag then equals the C truth
value, so a comparison's tag IS the `setcc`/`slt` result with no inversion, and `if` (a `case` on
the tag) takes the `inl` branch for false, exactly as `c-branch-tag-zero` already branches on tag 0.

## 3. Design (top-down)

* **A. Meaning.** Comparisons become compiler primitives by identity (D255): `ArithPrim` gains
  `p-lt … p-ne : ArithPrim (Int * Int) (Unit + Unit)` with `primSem` the signed word comparison
  (`Once.Word._<ˢ_`, `_≡ʷ_`) mapped to `inr tt` / `inl tt`. `lt-info … ne-info` carry `primV`.
  The six postulates are deleted. Follow the red (Meaning, MeaningBridge, Coherence…).
* **B. A comparison is a TAG, then an INJECTION.** Factor `cmp : Int×Int → 1+1` as
  `bool-of ∘ cmp₀₁` where `cmp₀₁ : Int×Int → Int` is the 0/1 tag (a register value) and
  `bool-of : IR Int (Unit + Unit)` injects a tag: 0 ↦ `inl tt`, otherwise `inr tt`. The rewrite
  pass emits this factoring; `cmp₀₁` lifts into an arith block like any `Int`-codomain tree (so it
  links), and `bool-of` is ONE new IR morphism.
* **C. The block side.** `XInstr` gains a compare-into-register instruction (x86 `cmp; setcc;
  movzx`, riscv64 `slt`/`xor`/`seqz`/`snez`); its per-arch lowering and simulation join the arith
  sim core (ArithSimCore: x86-64, riscv64, x86-32).
* **D. `bool-of` in the CCC.** Lowering = `inl`/`inr`'s, with the tag read from `Output` instead of
  a literal (`instr-alloc-heap 2`, store tag, store the unit payload). Its `IRObsCorrect` clause is
  `inl`/`inr`'s with a dynamic tag; every IR walk gains its clause (follow the red).
* **E. Gate.** `obs-correct-sigop-rest` no longer receives comparisons; `FileWF.file-wf` is TRUE
  for them; exit tests with comparisons on all three arches (`if a < b …`); extraction, `cabal
  test`, apex.

## 4. Risks

* `bool-of` touches every IR walk (the same blast radius as any IR constructor).
* The arith recogniser must recognise `cmp₀₁` trees; the block emitter and the three arith sims
  need the compare instruction.

## 5. Refined design (2026-10-04, while implementing B)

* **Phase A LANDED** (D263, ec76b1ec8): `p-lt … p-ne`, defined meanings, Spec witness `int-prim`.
* **Why a machine step is unavoidable in `bool-of`.** A sum's tag cell must hold `SV-Tag 0/1`
  (`valid-inl-wf`/`valid-inr-wf`, and `sv-is-zero` recognises only tags; `FlatRegTag` keeps
  Scratch/Count tags), while a block leaves an `SV-Lit Int` in `Output`. Reinterpreting the word
  as a tag would need "the word is 0 or 1" at the engine — a state-premise residual. So `bool-of`
  NORMALISES: a new register op `out-nz : Output := SV-Tag (Input1 ≠ 0)` (a morphism reads
  `Input1`, writes `Output`), lowered as real
  instructions — x86 `test r,r; setne r8; movzx r,r8`, riscv `sltu rd, zero, rs` (`snez`). Its
  engine premise "Input1 holds an Int" comes from the shape discipline (`ShapeTable.step-expect`),
  like every other dataflow fact.
* **`bool-of`'s trace** = `out-nz`, then `inl`/`inr`'s allocation with the tag taken from a slot
  instead of `instr-load-tag-lit`: `out-nz; store-at-slot t; alloc-heap 2; store-at-slot p;
  mov-to-input; load-from-slot t; store-indirect; load-tag-lit 0 (the unit payload filler);
  store-indirect-suc; load-from-slot p`.
* **The compare** lives in the arith block: `MArithIR.acmp : CmpOp → … NInt → … NInt → … NInt`
  (0/1), `XInstr.Xcmp-rrr op dst a b` (meaning-level, like `Xdiv-rrr`), per-arch emit text
  (x86 `cmp; setl/setle/…; movzx`, riscv `slt`/`xori`/`sltiu`).
* **The rewrite** lifts every comparison SigOp on its own (its operands are the block's input
  pair, whatever computed them): `SigOp cmp ↦ bool-of ∘ block (acmp op (input fst) (input snd))`
  — so every comparison links, unconditionally.

## 6. Correction (2026-10-04): no `bool-of` in the IR — the factoring is in CODEGEN

Tried and backed out: `bool-of : IR Int (Unit + Unit)` as an IR morphism. Its IR-level
correctness (`IRObsCorrectF bool-of`) must hold for EVERY input residence, and an `Int` input may
be LOCATION-resident (`InputAt.in-loc` + `valid-int-wf`: `Input1` points to a cell holding the
int). No machine step can tell a pointer from a word, so a word→tag step on `Input1` is wrong
exactly there. (Arith blocks have the same ambiguity, hidden in the postulated
`arith-sigop-contract`.)

So the comparison stays ATOMIC in the IR (`SigOp lt-info`), and "tag, then injection" is its
LOWERING: `instr-sigop cmp-block` (the arith block, `Output := 0/1`), `instr-reg-op out-nz`
acting on **Output** — the register the block itself just wrote, so the word is never behind a
pointer — then `inl`/`inr`'s ten-instruction sum build with the tag stashed. The rewrite keeps the
SigOp node and registers the comparison's block (`walk (SigOp cmp)` returns its block), so the
file defines it and the call links. `out-nz`'s engine premise ("Output holds an Int") comes from
the shape discipline: `step-expect` after an `Int`-codomain internal SigOp claims `e-repr Int`,
and `site-ok` at `out-nz` requires it.

Landed so far (uncommitted, green modules): `RegOp.out-nz` + `sv-nz`; `sbb` (x86-64, x86-32) and
`sltu` (riscv64) in the ISA models with printers; the three `out-nz` lowerings; `TenStepPresAt`
(TenStepPres generalized over its first, register-only step).

## 7. Landed (2026-10-04, D264)

The comparison is one IR node; its lowering is block → `out-nz` → sum build (`IRToTrace.cmp-trace`),
proved by `IRObsCorrect.Compare.cmp-obs`; `cmp-of` is the single "is a comparison" decision for codegen
and the rewrite, which registers the block so the call links. Arith layers: `acmp`/`cmp-rrr`/`Xcmp-rrr`
with `CmpOp.cmp-bit`. Apex, `Once.Compiler` green. Next: plan 0.107 phase d (`FileWF.file-wf`).
