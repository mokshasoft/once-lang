# Plan 0.17.2 — Type-Level Mode/Bump Discrimination

## Once Compiler Formal Verification

**Status:** Open — depends on Plan 0.17 (landed). Sibling to Plan 0.17.1.

**Date:** 2026-05-21

---

## Motivation

Plan 0.17 introduced `bump : AllocBump` on `IRResultBase`, with
`alloc-correct : proj₂ (exec-trace trace s alloc) ≡ apply-bump bump alloc`
binding the declared effect to the runtime trace. This gives one
direction of mode-purity for free (memory `[[allocmode-discriminates]]`,
plan 0.17 Pattern 1):

- A **Heap-mode** producer that declares `bump = mkBump 0 1` and
  emits `instr-alloc-stack n` fails `alloc-correct` — the trace would
  bump `next-slot` by `n`, contradicting the declared
  `next-slot-delta = 0`. Type error.

The **other direction is not enforced**: a Stack-mode producer can
legally declare `bump = mkBump 0 1` and emit `instr-alloc-heap` — the
trace and bump agree, `alloc-correct` discharges, but the producer
heap-allocates while being typed `IRResultAWF Stack ir x s alloc`.
There is no relation in the type between the `m : AllocMode` parameter
and the `bump` shape.

The symptom in 2026-05-21: changing the CLI default to `--alloc heap`
silently switched Layer 0/1/2 to heap-emitting assembly even though
the formal-side stack producers are still well-typed. The error has
no static catch — both modes type-check the same.

Companion design statements:

- Memory `[[allocmode-discriminates]]`: "Stack-mode IRs are heap-invariant
  by construction" — documented convention, not enforced.
- Plan 0.2.4.6 (Place pass, design): the upstream stage that *decides*
  which mode to emit per IR site. Place's choices are only binding
  downstream if the CCC layer guarantees mode purity.
- Plan 0.17 Pattern 1 covers the heap→stack direction via
  `alloc-correct`; the stack→heap direction is unaddressed.

## Goal

Make AllocMode a load-bearing index: an `IRResultBase Stack ir x s alloc`
cannot be constructed by a producer that bumps `next-heap-ref`. Surface
the convention as a type-level obligation discharged at the producer
site, so Place's per-site mode choice is binding through to codegen.

## Design

### Asymmetric constraint

Per the 2026-05-21 user clarification: Stack-mode is strict (never
touches the heap, even for scratch). Heap-mode is the dual where
"never stack-allocates a *value*" is already enforced indirectly by
`ResultPlace B Heap …` requiring the result location to be
`AtDynamic _`. Heap-mode is allowed to bump `next-slot` for scratch
(PairHeapWF reserves 4 scratch slots before allocating the heap
pair). Asymmetric encoding:

```agda
StackPure : AllocMode → AllocBump → Set
StackPure Stack b = next-heap-ref-delta b ≡ 0
StackPure Heap  b = ⊤
```

The Heap dual ("value lives on the heap") is *not* re-expressed at the
bump level; it stays at `ResultPlace`. This avoids splitting the bump
into value-bump and scratch-bump (rejected in
[AskUserQuestion 2026-05-21]).

### Field placement

Add to `IRResultBase`:

```agda
record IRResultBase (m : AllocMode) … where
  field
    …
    bump : AllocBump
    bump-respects-mode : StackPure m bump
    …
```

### Discharge per producer

| Producer | mode | bump.next-heap-ref-delta | discharge |
|---|---|---|---|
| `SimpleWF` (6 sites) | Stack/Heap (m polymorphic) | 0 (bump-0) | `refl` for Stack branch; `tt` for Heap |
| `CurryWF` Stack | Stack | 0 | `refl` |
| `CurryHeapWF` | Heap | 1 | `tt` |
| `PairWF2` Stack | Stack | 0 (sub-IRs are Stack by mode propagation) | `refl` |
| `PairHeapWF` | Heap | 1 + sub-IRs' heap deltas | `tt` |
| `SumRecWF.run-inl/inr` Stack | Stack | 0 | `refl` |
| `SumRecWF.run-In/in-ν` | mIn-polymorphic | 0 (mkBump 1 0) | `tt` (these are heap-result wrappers) |
| `SumRecWF.run-out-μ/Out` | Heap | 0 (bump-0) | `tt` |
| `SumRecWF.run-case` inl/inr | mF/mG (sub-IR) | inherited | sub-IR's `bump-respects-mode` direct |
| `SumInlHeapWF`, `SumInrHeapWF` | Heap | 1 | `tt` |
| `ApplyWF` | body's output mode (existential) | pair-slots + body's | sub-IR `bump-respects-mode` via inductive case on body mode |
| `ComposeWF` | g's output mode (existential) | f.bump + g.bump | sub-IR `bump-respects-mode` chained via `+-≡-0` lemma when both 0 |
| `RecCoreWF.run-fuse/hylo-core` | Heap | 0 (mkBump 1 0) | `tt` |
| `ParaWF.run-para-core` | Heap | 0 (mkBump 1 0) | `tt` |
| `AnaWF.run-ana-core` | Heap | 0 (mkBump 1 0) | `tt` |
| `RecTrace.cata` | Heap | TBD (bump still SMP.!! pending Plan 0.17 Phase 5) | `tt` once bump declared concretely |

Compositional producers (ApplyWF, ComposeWF) need an arithmetic
lemma for the Stack branch:

```agda
+-≡-0 : ∀ {a b} → a +ℕ b ≡ 0 → (a ≡ 0) × (b ≡ 0)
```

(or use Agda's pattern-matching on `zero +ℕ b ≡ 0 → b ≡ 0` directly).
When the parent is Stack, both sub-IRs must be Stack (mode propagation),
their `bump-respects-mode` give zero heap deltas, sum = 0.

### Place pass interaction (forward-looking)

Once Plan 0.2.4.6 lands, the Place pass picks each IR's mode. The
field added here makes that choice load-bearing: Place selects Stack
→ CCC layer guarantees the trace is heap-pure → codegen emits stack-
only assembly without trusting Place's annotation.

Without Plan 0.17.2, a buggy Place that picks Stack for an
escaping closure would compile, type-check, and silently emit broken
code.

## Refactor Steps

### Phase A — Add `StackPure` + field

1. Add `StackPure : AllocMode → AllocBump → Set` to `Allocation.agda`
   (next to `AllocBump`, `bump-+`, `apply-bump`).
2. Add `bump-respects-mode : StackPure m bump` field to
   `IRResultBase` in `ClosureWellFormed.agda`.
3. Update `mk-IRResultAWF-via-bump` to take a `StackPure m bump`
   argument; package it into the constructed `IRResultBase`.

### Phase B — Discharge per producer

Walk the 14 producer files. For each producer site:

- Stack-mode (m = Stack): pass `refl` if bump is `mkBump _ 0`. The
  type-check of this `refl` catches any producer accidentally
  emitting heap allocation: their `next-heap-ref-delta bump` is
  non-zero, so `0 ≡ 0` won't type-check against the actual value.
- Heap-mode (m = Heap): pass `tt`.
- m-polymorphic (SimpleWF, sub-IR-mode-inheriting): pattern-match
  on m or thread the sub-IR's `bump-respects-mode` directly.

### Phase C — Sanity build

- `make agda MODULE=Once/CCC/Machine/IR/SimpleWF.agda` (foundation smoke test).
- `make compiler-x86-64` (full clean).
- `make malonzo` (extraction unchanged at the type level — discharge
  fields drop out).
- Layer 0/1/2 binary tests with `--alloc stack` and `--alloc heap`
  to confirm no runtime regression.

### Phase D — Adversarial test

Add a deliberate violation in a sandbox file to confirm the type
error fires:

```agda
-- BAD: Stack-mode producer claiming heap bump.
bad-stack-producer : IRResultAWF Stack id x s alloc
bad-stack-producer = record
  { base = record
      { bump = mkBump 0 1                  -- claims a heap-ref bump
      ; bump-respects-mode = ???            -- must be `refl : 1 ≡ 0` → fails
      ; …
      }
  ; …
  }
```

Confirm Agda rejects this. Remove the sandbox before commit.

## Acceptance Criteria

- `StackPure` defined in `Allocation.agda`.
- `IRResultBase` has `bump-respects-mode : StackPure m bump`.
- `mk-IRResultAWF-via-bump` threads the new field.
- All 14 producers discharge the field.
- `make compiler-x86-64` clean.
- Layer 0/1/2 tests pass under both `--alloc stack` and `--alloc heap`.
- Adversarial sandbox confirms type error fires (then remove).
- Memory `[[allocmode-discriminates]]` updated to note the type-level
  enforcement.

## Risks & Mitigations

- **Risk:** Stack-mode producers with `bump = SMP.!!` (PairWF2,
  RecTrace cata; see Plan 0.17.1 deferred work) can't discharge
  `bump-respects-mode` either — `StackPure Stack SMP.!!` is opaque.
  **Mitigation:** Pair with Plan 0.17 Phase 5 (concrete bump
  declaration). Until those land, Stack-mode for PairWF2 / RecTrace
  cata stays under `SMP.!!`. The remaining 12 producers gain real
  enforcement.

- **Risk:** Compositional producers (ApplyWF, ComposeWF) require
  inductive `bump-respects-mode` chaining. Cost: one arithmetic lemma
  (`a +ℕ b ≡ 0 → a ≡ 0`).
  **Mitigation:** lemma is two lines. Discharge follows directly
  from sub-IRs' fields.

- **Risk:** mode-polymorphic producers (SimpleWF: m flows through
  unchanged) need branch-on-m in the discharge.
  **Mitigation:** Agda dependent pattern-matching on `m` gives
  `refl`/`tt` per case in one line each.

- **Risk:** Place pass (Plan 0.2.4.6) is design-only. Adding the
  field now without a Place implementation seems premature.
  **Mitigation:** the field has bite *without* Place — it currently
  catches manual mismatches in IR construction (e.g. surface
  elaborator emitting `pair Stack` where the body has heap-allocating
  sub-IRs). Place's correctness story strengthens further when it
  lands.

## Connection to Plan 0.17 / 0.17.1

- **Plan 0.17 Pattern 1** (heap producer can't bump next-slot via
  `alloc-correct`): unchanged. Plan 0.17.2 adds the dual direction.
- **Plan 0.17.1** (derive algebraic budget fields): independent.
  0.17.2 can land before, after, or interleaved with 0.17.1's
  remaining PairWF2/RecTrace discharges.
- **Plan 0.17 Phase 5** (concrete bump for PairWF2/RecTrace): blocks
  full enforcement for those two files. The other 12 producers gain
  enforcement immediately.

## Why this is principled

Today, `m : AllocMode` and `bump : AllocBump` are independent indices
on `IRResultBase`. A producer can pick any combination. The
discrimination invariant — *Stack-mode means never touches the heap;
Heap-mode means value lives on the heap* — is documented but not
type-enforced.

After Plan 0.17.2, the discrimination is a typed obligation:
constructing an `IRResultAWF Stack` *requires* a producer whose bump
respects Stack purity. Place's choice of mode becomes a hard guarantee
for downstream consumers (codegen, runtime), not a convention that
could silently drift.

Same "single source of truth" argument as Plan 0.17: the mode
discipline is one typed quantity declared by the producer, checked
once, propagated through subst. Inconsistency becomes a type error,
not a runtime postulate.
