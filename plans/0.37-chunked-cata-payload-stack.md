# Plan 0.37 — Chunked cata payload/work stack (ISA extension)

> **Deferred optimization, NOT a correctness gap.** Plan 0.36 Tier-1 ships a
> simple **2-cell linked payload stack** (one `instr-alloc-heap 2` per list
> element). It is unbounded, abstract-provable, and needs **zero** ISA change.
> This plan amortizes its allocation cost. Do it only after the Tier-1 (and
> ideally Tier-2) fold path is green and proven — it is a localized refinement
> of the push/pop steps, not a re-architecture.

## Goal

Replace the per-element 2-cell linked stack with a **chunked linked stack**: a
linked list of fixed-size blocks (a `(K+1)`-cell `instr-alloc-heap` block — `K`
payload cells + 1 link cell). Allocation count drops from `O(n)` to `O(n/K)`.
This is also what finally makes the already-committed `lea-indexed` primitive
(commit `aa081e61`) pay off — `lea-indexed` indexes *within* a single fixed-size
chunk soundly (`offsetHL` stays within one `heap-ref`).

## Why it needs an ISA extension (the blocker that deferred it)

Chunking must track **two independent quantities** simultaneously — *which
chunk* (the linked-list cursor) and *position within the chunk* (the index for
`lea-indexed`) — and detect the chunk boundary (`pos == K`). The current
abstract ISA cannot express this:

- **Branches are `== 0` only:** `c-branch-scratch-zero` (Scratch's tag) and
  `c-branch-tag-zero` (`*Input1`'s tag). There is **no `== K`** test, so the
  chunk-full / chunk-empty boundary can't be detected on the fast (non-zero)
  side.
- **Reg-ops have no arithmetic:** only `Scratch := 0/1`, `Scratch := Scratch-1`,
  `Scratch := Input2`, `Input2 := 0 / ++`. No add, no `div/mod`, no
  `Scratch ↔ slot` move — so `chunk = idx div K`, `pos = idx mod K` are
  uncomputable.
- **`lea-indexed` monopolizes `Scratch`** for its index, but `Scratch` is the
  *only* flexible loop counter. So array-indexing and loop-control contend for
  the one register; push alone is encodable (detect `pos == 0` after a store),
  but reverse **pop is not** (needs a `== K-1` boundary + a second counter).
- `store-indirect`/`-suc` only reach offsets 0 and 1, so unrolling intra-chunk
  access can't avoid `lea-indexed` for cells `≥ 2`.

## The ISA extension (the actual work)

Add a **second index-counter register** and the ops to drive a chunked index,
mirroring how `Scratch`/`Input2` were added (Plan 0.29 M5 reg-ops). Concretely:

1. **A second counter register `Idx`** in `SMCore`'s register file (alongside
   Input1/Input2/Output/Scratch), with `readReg`/`writeReg` clauses + the x86-64
   register mapping (pick a free callee-saved reg, e.g. r12).
2. **Reg-ops for `Idx`:** `idx-zero`, `idx-inc`, `idx-set-k` (load the
   compile-time chunk size K), and have `lea-indexed` read its index from `Idx`
   instead of `Scratch` (frees Scratch for loop control). Add as new `RegOp`
   constructors (MAlonzo ctor-index stability: append last).
3. **A `== K` / `Idx`-zero branch:** either `c-branch-idx-zero` (count `Idx`
   down from K, detect 0 → chunk boundary) — reuses the `== 0` machinery for the
   new register, the cheapest option. Then `pos` counts down K-1..0 within a
   chunk and the boundary is `Idx == 0`, symmetric for push and pop.
4. Cascade (the ~10 files, mirror `lea-indexed`/`restore-input`): `SMCore` exec
   + `SMPrimitives` predicates/proofs + the 3 backends (`AbstractToX86` etc.) +
   `FlatSimulation`/`FlatSim`. Add new `AbstractInstr`/`RegOp` constructors LAST
   for MAlonzo index stability.

## Codegen change (small, once the ISA exists)

In `IRToTrace.agda`'s `cata-trace-linear` (and the Tier-2 worklist/result
stacks): change only the **push** and **pop** inner steps:
- **Chunk layout:** `instr-alloc-heap (K+1)`; cells `[0..K-1]` payloads, cell
  `[K]` link to previous chunk.
- **Push:** if `Idx == 0` → alloc new chunk, write link cell := old chunk,
  `Idx := K`; then `Idx-- ; lea-indexed(chunk-slot) ; store-indirect` (writes
  cell `[Idx]`); fill direction K-1..0.
- **Pop:** symmetric — read cell `[Idx]` via `lea-indexed`; on chunk exhaustion
  hop to the link cell and reset `Idx`. Loop count stays the `Scratch`
  `n`-countdown (now free of indexing duty).
- Pick `K` (e.g. 8 or 16) as a `private` constant for easy tuning.

## Validate

Same Phase-0 runtime targets as 0.36 (list-sum → exit 42, deep inputs, tree
folds for the Tier-2 stacks), plus: confirm the `O(n/K)` alloc count and that
deep inputs still run. The abstract proof (`cata-correct`, Plan 0.36 Phase 3)
must still go through — each chunk is a real single heap block, chunk links are
ordinary heap pointers, so the chunked stack stays fully modelable.
