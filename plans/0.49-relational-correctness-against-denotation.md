# Plan 0.49 — Relational correctness against the denotation (kill the cancellation)

## The flaw being fixed

Today (0.48) `correct` relates `exec (compile src)` to `⟦ src ⟧⊥ = evalᴰ (moduleToIR src)`.
The front-end (`moduleToIR` = typecheck + elaborate) appears on **both sides**, so it
**cancels**: a front-end bug produces a wrong IR on both sides and `correct` still holds.
So 0.48 forces only *codegen*. `accept-sound`/`⟦⟧⊥-sound` patched soundness back on as
**corollaries** — forgettable, not structural.

The denotation (`Once.Denotation`: `evalᴰ`, `SD.⟦_⟧ˢ`) **is** the authored spec — the one
legitimate, reviewed trust point. The fix is structural: state `correct` against that
**independent** denotation, with a **declarative judgment** (not `checkElab`) choosing the
typed program, so nothing cancels.

## The relational spec (DONE — `Once.Adequacy`, committed `f97a04a2`)

```
Typed : Set                         -- the space of typed programs (instance: Once's)
_⊢_   : Source → Typed → Set        -- DECLARATIVE judgment "src denotes tp" (NOT the elaborator)
⟦_⟧ˢ  : Typed → Behavior            -- INDEPENDENT denotation of a typed program
correct : ∀ arch doOpt src →
    -- soundness + trace
    ( ∀ bytes → compile arch doOpt src ≡ just bytes → Σ tp, (src ⊢ tp) × (exec arch bytes ≈ ⟦ tp ⟧ˢ) )
  × -- completeness
    ( ∀ tp → src ⊢ tp → Σ bytes, compile arch doOpt src ≡ just bytes )
```

**Two conjuncts, ONE field** — the relational analogue of 0.48's single `Pointwise` over
`Maybe Behavior` (whose `just`/`nothing` constructors already bundled both directions). It
is *not* a regression to separable corollaries: you cannot inhabit `correct` without proving
both halves, and you cannot drop either without editing this reviewed spec. The second
conjunct (completeness) is the front-end obligation made **structural** — in 0.48 it was
"free" only *because the meaning cancelled against the compiler* (the freeness was the bug).

## The sharp insight (2026-06-23) — the front-end is THREE forcing rows

Forcing "the front-end" is not one thing. It splits into three independent obligations, and
they are NOT equally hard — two are already proven:

| row | obligation | forced by | status |
|---|---|---|---|
| **1. typecheck** | accept/reject is correct | `AcceptSound` (sound: accept ⇒ `ModuleTyped`/`⊢ᶜ`) **+** `Once.TypeCheck.Completeness.check-complete` (complete: `⊢ᶜ ⇒ checkElab success`) | **PROVEN, total** |
| **2. elaborate** | `SExpr → IR` preserves meaning | `faithful` (`SourceFaithful.agda:100`: `evalᴰ(elaborate e) ≡ SD.⟦e⟧ˢ`) | **PROVEN** |
| **3. checkElab term-choice** | `RawExpr → SExpr` picks the right TERM (not just right type — e.g. `exit 13` ↦ wrong `exit 14`-term) | — | **the open hole** |

> **Correction to earlier drafts.** Completeness is **NOT** a rotted postulate. The rot
> (`ErrorProofs.agda:273`) is *error-message* preservation, a different module. Real
> completeness lives in `Once.TypeCheck.Completeness` (`check-complete`, total, green).

The genuine cancellation 0.49 targets is **row 3**: a meaning that is itself computed from
`checkElab`'s term can never catch a wrong-term elaboration. To force row 3, the meaning must
reach the program term **independently of `checkElab`**. The judgments (`_⊢ᶜ_`/`_⊢ᵢ_`/`_⊢ᵍ_`)
are **term-free** (no constructor carries an `SExpr`), so a derivation *can* denote
independently in principle.

## Three routes to force row 3 — costs differ enormously

1. **`erase` (the original Phase-1 plan) — DEAD.** Link `tp` to source syntactically
   (`erase tp ≡α main-raw`). Forces row 3, BUT point-free combinators (`id`/`fst`/`compose`)
   elaborate to `lift-morphism`/`morph-app` over raw `IR` with **no source inverse** → the
   round-trip is **false**, not merely unproven. (Aside: `RCata` is a non-issue — cata enters
   as `RApp (RVar "cata") alg`, ana as `RAna F coalg`; both erase with existing ctors. The
   killers are non-injective point-free elaboration + de-Bruijn name loss.)

2. **`realize` / derivation-denotation — the principled end state (Phase 2, future).** A
   *second, independent* elaborator over derivations (`realize : ⊢ᶜ → SExpr`, or `⟦D⟧ˢ` by
   recursion on `D`), then a bridge `SD.⟦se⟧ˢ ≡ SD.⟦realize D⟧ˢ`. Forces row 3, handles
   point-free cleanly (rule `t-id-check` ↦ `lift-morphism IR.id`). **Cost ≈ elaborator
   verification**: ~60 derivation rules to realize + an agreement induction. A multi-week
   milestone, on the order of the hard T0/T2 work.

3. **`check-complete`-based meaning — the landable intermediate (Phase 1, NOW).** Set
   `⟦tp⟧ˢ = SD.⟦ check-complete's term ⟧ˢ`. Because that term *is* `checkElab`'s `se`, **row 3
   cancels** — but rows 1+2 + codegen are ALL forced, from already-proven lemmas. Strictly
   stronger than 0.48 (which forced only codegen). Honest: zero false postulates; the residual
   row-3 gap is **named**, not hidden.

**Decision (user, 2026-06-23):** land route 3 now (Phase 1), name the residual row-3 gap, do
route 2 (Phase 2) as the next milestone. Route 1 is abandoned.

## Phase 1 — route 3 (DOING NOW)

### Instance design (`Once.Adequacy.Compile.WithCPU` + apex `Once.Compiler`)

- `Typed` = an **executable typed module**:
  `Σ[ m ∈ P.Module ] (ModuleTyped m × HasValidMain m)` — `ModuleTyped` (from `AcceptSound`,
  every function has a `⊢ᶜ` derivation) plus the fact that `m` has a `main : Eff Unit Unit`
  (so it actually builds; libraries have no runnable meaning, cf. 0.48 "executables only").
- `src ⊢ tp` = `gmoduleToModule src ≡ just (proj₁ tp)` (parse links source to the module;
  parse is the verified relational parser, independent of typecheck/elaborate).
- `⟦ tp ⟧ˢ` = `SD.⟦ mainTerm tp ⟧ˢ tt`, where `mainTerm tp` is the intrinsic main `SExpr`
  recovered from `tp`'s main `⊢ᶜ` derivation via `check-complete` (= `checkElab`'s `se`, by
  function-determinism). This routes the meaning through `SD` (surface denotation), making
  `faithful` load-bearing (row 2 forced) — NOT through `evalᴰ(moduleToIR)` (which would be
  0.48 again).

## Phase 2 (route 2) — force checkElab term-choice (row 3). STARTED 2026-06-24.

Goal: a wrong-but-well-typed `checkElab` (e.g. `13 ↦ int 14`) becomes a type error.

> **DESIGN PIVOT 2026-06-24 — D063 (the morphism realm `⊢ᵐ`).** Writing `realize`
> exposed a latent spec/proof inconsistency: the judgment's `t-compose-check` /
> `t-case-copair-check` are grade-polymorphic over **arbitrary** check-derivation arms,

> dual of `⊢ᵍ` — the CCC trichotomy: values `⊢ᵍ` / morphisms `⊢ᵐ` / closures `t-lam`). The

> `t-cata-check`/bare `t-{inl,inr,initial,arr}-check`) **collapse** into one bridge

> `IR.Cata`/…). This makes `realize` total + elaborator-free, **deletes** the two false
> postulates (now provable), and — because the meaning routes through `realize-morph`'s
> direct IR — makes `correct`+`realize-agrees` force the categorical laws (one clause per
> combinator). **The "fallback `app (app spec*) f g`" map below is SUPERSEDED for
> compose/case/pair.** See decision-log **D063** for the full `⊢ᵐ` constructor list and the
> rationale; D056 (one morphism realm) is what this completes at the judgment+denotation level.
