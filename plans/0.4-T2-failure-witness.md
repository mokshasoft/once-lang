# Plan 0.4 T2 — Verified-failure elaborator

**Branch:** `plan-0.4-T2-failure-witness` (forked from `plan-0.4-T1`).

**Goal:** discharge 13 of the 16 remaining typechecker postulates by
making `inferElabV` and `checkElabV` typed-by-construction *on both
sides* — success carries a typing derivation (today), failure carries
a structural witness of why the elaborator rejected (new).

The remaining 3 postulates (`completeness-gap-arr-check`,
`-apply-check`, `-arg-driven-app-check`) live in Completeness.agda and
need a separate WF-on-derivation-depth refactor; they are explicitly
out-of-scope for this branch.

13 postulates discharged total. Net postulate count after this branch:
3 (Completeness) + 0 (Elaborate, Soundness, ErrorProofs) = **3**.

## The new top-level type

```agda
-- Failure witnesses parallel typing rules: each failure carries
-- structural proof of the conditions that triggered it.
data InferFailureWitness : (ctx : NamedCtx) (e : RawExpr) (err : TypeError) → Set where
  -- RVar failures
  iv-unbound :
    ∀ {ctx x}
    → ¬ (x ≡ "unit")
    → lookupLocal ctx x ≡ nothing
    → lookupImport (NamedCtx.imports ctx) x ≡ nothing
    → lookupPoly (NamedCtx.polys ctx) x ≡ nothing  -- distinguishes from bbc-other poly path
    → InferFailureWitness ctx (RVar x) (UnboundVariable x)

  iv-qual-unbound :
    ∀ {ctx name alias}
    → lookupImport (NamedCtx.imports ctx) (alias ++ "." ++ name) ≡ nothing
    → InferFailureWitness ctx (RQualified name alias) (UnboundQualified name alias)

  -- RLam in infer mode is unconditionally rejected (no premise).
  iv-lam-infer :
    ∀ {ctx x body}
    → InferFailureWitness ctx (RLam x body) LambdaInInferMode

  -- RUnaryOp Neg failure: arg succeeded at non-Int type.
  iv-neg-not-int :
    ∀ {ctx e A Ψ eE d fr}
    → ¬ (A ≡ Int)
    → InferSuccessWitness ctx e A Ψ eE d fr  -- inner witness
    → InferFailureWitness ctx (RUnaryOp OpNeg e) (TypeMismatch Int A)

  -- ... (one constructor per `failure …` site in inferElabV; ~25 total)

data CheckFailureWitness : (ctx : NamedCtx) (e : RawExpr) (T : Type) (err : TypeError) → Set where
  cv-lam-non-arrow : ∀ {ctx x body T}
                   → ¬ (T is-pure-arrow)
                   → CheckFailureWitness ctx (RLam x body) T LambdaRequiresFunctionType
  cv-lam-usage    : ∀ {ctx x body A B q q' Ψ eE d fr}
                  → CheckSuccessWitness (extendNamedCtx ctx x A) body B (q' ∷ᵘ Ψ) eE d fr
                  → ¬ ((q' ≤q q) ≡ true)
                  → CheckFailureWitness ctx (RLam x body) (A ⇒[mk-kind q pure] B)
                                         (UsageViolation x q q')
  -- ... (one constructor per `failure …` site in checkElabV; ~30 total)

-- New verified result types (replaces existing Σ-pair).
data VerifiedInferResult (ctx : NamedCtx) (e : RawExpr) : Set where
  vsuccess : ∀ {A Ψ}
           → (eE : SExpr (NamedCtx.debruijn ctx) Ψ A)
           → (depth fresh : ℕ)
           → ctx ⊢ᵢ e ∶ A ⨾ Ψ                     -- success witness (existing)
           → VerifiedInferResult ctx e
  vfailure : (err : TypeError)
           → InferFailureWitness ctx e err          -- failure witness (new)
           → VerifiedInferResult ctx e

data VerifiedCheckResult (ctx : NamedCtx) (e : RawExpr) (T : Type) : Set where
  vsuccess : ∀ {Ψ}
           → (eE : SExpr (NamedCtx.debruijn ctx) Ψ T)
           → (depth fresh : ℕ)
           → ctx ⊢ᶜ e ∶ T ⨾ Ψ
           → VerifiedCheckResult ctx e T
  vfailure : (err : TypeError)
           → CheckFailureWitness ctx e T err
           → VerifiedCheckResult ctx e T

-- PolyContext invariant baked into NamedCtx.
data WellTypedPolyCtx : Imports → PolyCtx → Set where
  []  : ∀ {imps} → WellTypedPolyCtx imps []
  _∷_ : ∀ {imps x schema body rest}
      → (∀ {T} → SchemaInstantiates schema T  -- T is a valid instantiation of schema
                → (ctxWithImportsAndPolys imps rest) ⊢ᶜ body ∶ T ⨾ zeroUsage)
      → WellTypedPolyCtx imps rest             -- prior entries (cycle prevention via removePoly)
      → WellTypedPolyCtx imps ((x , schema , body) ∷ rest)

record NamedCtx : Set where
  field
    size       : ℕ
    named      : Ctx
    debruijn   : SCtx size
    freshCounter : ℕ
    imports    : Imports
    polys      : PolyCtx
    polysWT    : WellTypedPolyCtx imports polys  -- NEW
```

## Phased implementation plan

### Phase 1 — failure witness datatypes

- Define `InferFailureWitness` and `CheckFailureWitness` in
  `Once.TypeCheck.Elaborate` (or a new submodule).
- One constructor per failure path in current `inferElabV`/`checkElabV`.
- Sanity: types compile, no callers updated yet.

### Phase 2 — migrate inferElabV/checkElabV to new result types

- Change `VerifiedInferResult`/`VerifiedCheckResult` to data types
  (currently Σ-pairs).
- Walk every `failure err , tt` in the bodies; replace with
  `vfailure err <inline-constructed-witness>`. Each is local — the
  premises that justified the rejection are in the `with` context.
- Walk every `success ... , w` similarly to use `vsuccess`.
- Update `proj₁`/`proj₂` consumers (`inferElab`, `checkElab` projections).

### Phase 3 — bbc-X aux extraction

- Pull each `checkElabV ctx (RVar x) T | bbc-X | failure ...` branch
  into a top-level `checkElabV-RVar-bbc-X-failure-aux` taking
  `(eqLoc : lookupLocal ≡ nothing)`, `(eqImp : lookupImport ≡ nothing)`,
  `(¬unit : ¬ (x ≡ "unit"))`, plus the type-matching eqs as explicit
  args. Eliminates `with...in eq` opacity in those branches.
- bbc-other failure-then-poly branch becomes
  `checkElabV-RVar-bbc-other-poly-aux` taking `(eqPoly : lookupPoly ≡ just (schema, body))`.

### Phase 4 — polyContext invariant

- Define `WellTypedPolyCtx`; add `polysWT` field to `NamedCtx`.
- Update `ctxWithImportsAndPolys`, `extendNamedCtx`, `bumpFresh`,
  `ctxWithImportsAndSelfAndPolys` to preserve/construct `polysWT`.
- `compileFun` / `compileAllFuns` (in `Once.Compile`) build `polysWT`
  incrementally — each function's typecheck contributes one
  `WellTypedPolyCtx._∷_` entry.

### Phase 5 — discharge the postulates

With Phases 1–4 in place, each remaining postulate becomes a
straightforward proof:

- `inferElab-RVar-fail-{local,import}`: project the lookup eqs from
  `iv-unbound`.
- `checkElab-fallback-RVar-X` (×8): case-split `inferElabV` failure,
  destructure `iv-unbound`, call the bbc-X aux helper.
- `bbc-other-poly-witness` & `checkElab-fallback-RVar-poly`: invoke
  `t-var-poly-instantiate` with the body verification produced by
  `polysWT eqPoly`.
- `checkElab-fallback-RApp-compose`: split `checkCompose` into
  `checkCompose-typed` (uses inferElab-success premise → t-compose-check
  with t-embed) and `checkCompose-poly` (uses composeArgB-derives-B
  premise → relaxed t-compose-check). Each fallback discharges its
  own path.

### Phase 6 — verify and clean up

- `make typecheck` green at zero typechecker postulates.
- Strip the stale `bbc-other-poly-witness` and other postulate blocks
  from `Elaborate.agda`.
- Remove `Acc`-style scaffolding that's no longer needed (if any).
- Verify `Verified.agda` and downstream consumers still typecheck
  unchanged (the postulate signatures they referenced should now resolve
  to provable lemmas with the same external interface).

## Phase 3 outcome (2026-05-03 progress)

The bbc-X aux extraction landed (8 top-level helpers). Compile checks.

**However:** Phase 5 (discharging the 8 `checkElab-fallback-RVar-X`
postulates) ran into deeper layered with-helper opacity than initially
scoped. The aux helpers eliminate `with...in eq-loc/eq-imp` opacity at
the *innermost* level, but the elaborator's main `checkElabV` body
still uses `with classifyBareBuiltin x` and `with inferElabV ctx (RVar x)`
which are themselves opaque. External proofs trying to reach the aux
must navigate three nested with-helpers, each blocking distinct
substitutions.

**True principled fix:** lift *every* `with` in `checkElabV`'s RVar
dispatch to a top-level aux. That means:

1. `checkElabV-RVar-aux ctx x T (cls : BareBuiltinClass x) (eqCl : classifyBareBuiltin x ≡ cls) → ...`
2. Per-bbc-X dispatcher: `checkElabV-RVar-bbc-X-aux ctx x T (inferRes : InferElabResult ...) (eqInfer : inferElab ctx (RVar x) ≡ inferRes) → ...`
3. Per-bbc-X failure aux (already done): `checkElabV-RVar-bbc-X-failure-aux ctx T err (locLhs) eqLoc (impLhs) eqImp`

Each layer adds ~9 helpers (one per bbc-X). Total: ~27 new aux helpers
for the RVar dispatch alone. Similar for RApp / other expression
shapes if their failure paths need external reasoning.

This is a much larger restructure than fits "Phase 3 of T2"; deferred
to a follow-up `plan-0.4-T2.5-zero-with-elaborator` if pursued.

**Decision for T2:** ship Phase 3 (aux helpers as architectural
cleanup) without Phase 5 (RVar-X postulate discharge). The auxes are
useful regardless: they provide a structured place where the
verification logic for each bbc-X failure case lives, and they'll be
the targets for the future zero-`with` refactor.
