# Plan 0.4 T2 — Verified-failure elaborator

**Branch:** `plan-0.4-T2-failure-witness` (forked from `plan-0.4-T1`).

**Goal:** discharge 13 of the 16 remaining typechecker postulates by
making `inferElabV` and `checkElabV` typed-by-construction *on both
sides* — success carries a typing derivation (today), failure carries
a structural witness of why the elaborator rejected (new).

The remaining 3 postulates (`completeness-gap-arr-check`,
`-apply-check`, `-arg-driven-app-check`) live in Completeness.agda and
need a separate WF-on-derivation-depth refactor; they are explicitly
out-of-scope for this branch.

---

## Diagnosis: which postulates fall to which design change

| Postulate | Blocker today | Resolved by |
|-----------|--------------|-------------|
| `inferElab-RVar-fail-local` (Soundness) | `failure err` opaque | Failure witness: `iv-unbound` ctor carries lookup eqs |
| `inferElab-RVar-fail-import` (Soundness) | same | same |
| `checkElab-fallback-RVar-{id,fst,snd,terminal,initial,inl,inr,arr}` (Elaborate, ×8) | `with...in eq` opacity *plus* missing failure witnesses | Aux refactor of bbc-X branches + failure witness providing lookup eqs |

13 postulates discharged total. Net postulate count after this branch:
3 (Completeness) + 0 (Elaborate, Soundness, ErrorProofs) = **3**.

## The new top-level type

```agda
-- Failure witnesses parallel typing rules: each failure carries
-- structural proof of the conditions that triggered it.
data InferFailureWitness : (ctx : NamedCtx) (e : RawExpr) (err : TypeError) → Set where
  -- RVar failures
  iv-unbound :
    ∀ {ctx x}
    → ¬ (x ≡ "unit")
    → lookupLocal ctx x ≡ nothing
    → lookupImport (NamedCtx.imports ctx) x ≡ nothing
    → lookupPoly (NamedCtx.polys ctx) x ≡ nothing  -- distinguishes from bbc-other poly path
    → InferFailureWitness ctx (RVar x) (UnboundVariable x)

  iv-qual-unbound :
    ∀ {ctx name alias}
    → lookupImport (NamedCtx.imports ctx) (alias ++ "." ++ name) ≡ nothing
    → InferFailureWitness ctx (RQualified name alias) (UnboundQualified name alias)

  -- RLam in infer mode is unconditionally rejected (no premise).
  iv-lam-infer :
    ∀ {ctx x body}
    → InferFailureWitness ctx (RLam x body) LambdaInInferMode

  -- RUnaryOp Neg failure: arg succeeded at non-Int type.
  iv-neg-not-int :
    ∀ {ctx e A Ψ eE d fr}
    → ¬ (A ≡ Int)
    → InferSuccessWitness ctx e A Ψ eE d fr  -- inner witness
    → InferFailureWitness ctx (RUnaryOp OpNeg e) (TypeMismatch Int A)

  -- ... (one constructor per `failure …` site in inferElabV; ~25 total)

data CheckFailureWitness : (ctx : NamedCtx) (e : RawExpr) (T : Type) (err : TypeError) → Set where
  cv-lam-non-arrow : ∀ {ctx x body T}
                   → ¬ (T is-pure-arrow)
                   → CheckFailureWitness ctx (RLam x body) T LambdaRequiresFunctionType
  cv-lam-usage    : ∀ {ctx x body A B q q' Ψ eE d fr}
                  → CheckSuccessWitness (extendNamedCtx ctx x A) body B (q' ∷ᵘ Ψ) eE d fr
                  → ¬ ((q' ≤q q) ≡ true)
                  → CheckFailureWitness ctx (RLam x body) (A ⇒[mk-kind q pure] B)
                                         (UsageViolation x q q')
  -- ... (one constructor per `failure …` site in checkElabV; ~30 total)

-- New verified result types (replaces existing Σ-pair).
data VerifiedInferResult (ctx : NamedCtx) (e : RawExpr) : Set where
  vsuccess : ∀ {A Ψ}
           → (eE : SExpr (NamedCtx.debruijn ctx) Ψ A)
           → (depth fresh : ℕ)
           → ctx ⊢ᵢ e ∶ A ⨾ Ψ                     -- success witness (existing)
           → VerifiedInferResult ctx e
  vfailure : (err : TypeError)
           → InferFailureWitness ctx e err          -- failure witness (new)
           → VerifiedInferResult ctx e

data VerifiedCheckResult (ctx : NamedCtx) (e : RawExpr) (T : Type) : Set where
  vsuccess : ∀ {Ψ}
           → (eE : SExpr (NamedCtx.debruijn ctx) Ψ T)
           → (depth fresh : ℕ)
           → ctx ⊢ᶜ e ∶ T ⨾ Ψ
           → VerifiedCheckResult ctx e T
  vfailure : (err : TypeError)
           → CheckFailureWitness ctx e T err
           → VerifiedCheckResult ctx e T

-- PolyContext invariant baked into NamedCtx.
data WellTypedPolyCtx : Imports → PolyCtx → Set where
  []  : ∀ {imps} → WellTypedPolyCtx imps []
  _∷_ : ∀ {imps x schema body rest}
      → (∀ {T} → SchemaInstantiates schema T  -- T is a valid instantiation of schema
                → (ctxWithImportsAndPolys imps rest) ⊢ᶜ body ∶ T ⨾ zeroUsage)
      → WellTypedPolyCtx imps rest             -- prior entries (cycle prevention via removePoly)
      → WellTypedPolyCtx imps ((x , schema , body) ∷ rest)

record NamedCtx : Set where
  field
    size       : ℕ
    named      : Ctx
    debruijn   : SCtx size
    freshCounter : ℕ
    imports    : Imports
    polys      : PolyCtx
    polysWT    : WellTypedPolyCtx imports polys  -- NEW
```

## Phased implementation plan

### Phase 1 — failure witness datatypes

- Define `InferFailureWitness` and `CheckFailureWitness` in
  `Once.TypeCheck.Elaborate` (or a new submodule).
- One constructor per failure path in current `inferElabV`/`checkElabV`.
- Sanity: types compile, no callers updated yet.

### Phase 2 — migrate inferElabV/checkElabV to new result types

- Change `VerifiedInferResult`/`VerifiedCheckResult` to data types
  (currently Σ-pairs).
- Walk every `failure err , tt` in the bodies; replace with
  `vfailure err <inline-constructed-witness>`. Each is local — the
  premises that justified the rejection are in the `with` context.
- Walk every `success ... , w` similarly to use `vsuccess`.
- Update `proj₁`/`proj₂` consumers (`inferElab`, `checkElab` projections).

### Phase 3 — bbc-X aux extraction

- Pull each `checkElabV ctx (RVar x) T | bbc-X | failure ...` branch
  into a top-level `checkElabV-RVar-bbc-X-failure-aux` taking
  `(eqLoc : lookupLocal ≡ nothing)`, `(eqImp : lookupImport ≡ nothing)`,
  `(¬unit : ¬ (x ≡ "unit"))`, plus the type-matching eqs as explicit
  args. Eliminates `with...in eq` opacity in those branches.
- bbc-other failure-then-poly branch becomes
  `checkElabV-RVar-bbc-other-poly-aux` taking `(eqPoly : lookupPoly ≡ just (schema, body))`.

### Phase 4 — polyContext invariant

- Define `WellTypedPolyCtx`; add `polysWT` field to `NamedCtx`.
- Update `ctxWithImportsAndPolys`, `extendNamedCtx`, `bumpFresh`,
  `ctxWithImportsAndSelfAndPolys` to preserve/construct `polysWT`.
- `compileFun` / `compileAllFuns` (in `Once.Compile`) build `polysWT`
  incrementally — each function's typecheck contributes one
  `WellTypedPolyCtx._∷_` entry.

### Phase 5 — discharge the postulates

With Phases 1–4 in place, each remaining postulate becomes a
straightforward proof:

- `inferElab-RVar-fail-{local,import}`: project the lookup eqs from
  `iv-unbound`.
- `checkElab-fallback-RVar-X` (×8): case-split `inferElabV` failure,
  destructure `iv-unbound`, call the bbc-X aux helper.
- `bbc-other-poly-witness` & `checkElab-fallback-RVar-poly`: invoke
  `t-var-poly-instantiate` with the body verification produced by
  `polysWT eqPoly`.
- `checkElab-fallback-RApp-compose`: split `checkCompose` into
  `checkCompose-typed` (uses inferElab-success premise → t-compose-check
  with t-embed) and `checkCompose-poly` (uses composeArgB-derives-B
  premise → relaxed t-compose-check). Each fallback discharges its
  own path.

### Phase 6 — verify and clean up

- `make typecheck` green at zero typechecker postulates.
- Strip the stale `bbc-other-poly-witness` and other postulate blocks
  from `Elaborate.agda`.
- Remove `Acc`-style scaffolding that's no longer needed (if any).
- Verify `Verified.agda` and downstream consumers still typecheck
  unchanged (the postulate signatures they referenced should now resolve
  to provable lemmas with the same external interface).

## Phase 3 outcome (2026-05-03 progress)

The bbc-X aux extraction landed (8 top-level helpers). Compile checks.

**However:** Phase 5 (discharging the 8 `checkElab-fallback-RVar-X`
postulates) ran into deeper layered with-helper opacity than initially
scoped. The aux helpers eliminate `with...in eq-loc/eq-imp` opacity at
the *innermost* level, but the elaborator's main `checkElabV` body
still uses `with classifyBareBuiltin x` and `with inferElabV ctx (RVar x)`
which are themselves opaque. External proofs trying to reach the aux
must navigate three nested with-helpers, each blocking distinct
substitutions.

**True principled fix:** lift *every* `with` in `checkElabV`'s RVar
dispatch to a top-level aux. That means:

1. `checkElabV-RVar-aux ctx x T (cls : BareBuiltinClass x) (eqCl : classifyBareBuiltin x ≡ cls) → ...`
2. Per-bbc-X dispatcher: `checkElabV-RVar-bbc-X-aux ctx x T (inferRes : InferElabResult ...) (eqInfer : inferElab ctx (RVar x) ≡ inferRes) → ...`
3. Per-bbc-X failure aux (already done): `checkElabV-RVar-bbc-X-failure-aux ctx T err (locLhs) eqLoc (impLhs) eqImp`

Each layer adds ~9 helpers (one per bbc-X). Total: ~27 new aux helpers
for the RVar dispatch alone. Similar for RApp / other expression
shapes if their failure paths need external reasoning.

This is a much larger restructure than fits "Phase 3 of T2"; deferred
to a follow-up `plan-0.4-T2.5-zero-with-elaborator` if pursued.

**Decision for T2:** ship Phase 3 (aux helpers as architectural
cleanup) without Phase 5 (RVar-X postulate discharge). The auxes are
useful regardless: they provide a structured place where the
verification logic for each bbc-X failure case lives, and they'll be
the targets for the future zero-`with` refactor.

## Phase 3 view-refactor follow-up (2026-05-03)

After the user's "We gotta clean all the with problems" instruction,
applied the `feedback_with_abstraction` lesson: replaced the
captured-`refl` `(locLhs eqLoc impLhs eqImp)` failure-aux signatures
with view datatypes that bundle the equation as a constructor field.

### What landed

- `LookupLocalView` / `LookupImportView` view datatypes in
  `Once.TypeCheck.Classify`, with `inspectLookupLocal` /
  `inspectLookupImport` constructors.
- All 8 `checkElabV-RVar-bbc-X-failure-aux` signatures take views
  instead of 4 captured-`refl` args; bbc-X-aux callers use
  `inspectLookupLocal/Import`.
- Per-bbc-X aux dispatch (`checkElabV-RVar-bbc-X-aux`) takes the
  `VerifiedInferResult` Σ-pair directly, avoiding the inner
  `with inferElabV` opacity.
- bbc-arr's nested `with T₁ | T₂` continuations updated; coverage for
  alternative view configs added.

### Postulates discharged via this refactor

- `inferElab-RVar-fail-{local,import}` (Soundness) — were unused.
- `spec-gap-sound-check-RVar-{fst,snd,terminal,initial,inl,inr,arr}`
  (Soundness, ×7) — were unused; `check-sound` is V-pattern.
- `spec-gap-sound-check-RVar-other`, `spec-gap-check-RApp` (Soundness,
  ×2) — were unused.

**Net postulate count:** Soundness/Classify/ErrorProofs/Judgment all
at zero. `Elaborate.agda` retains 4 postulate blocks (8
`checkElab-fallback-RVar-X` + `checkElab-fallback-RApp-compose` +
`checkElab-fallback-RVar-poly` + `bbc-other-poly-witness`).
`Completeness.agda` retains the 3 WF-deferred completeness gaps (out
of scope). `make typecheck` green.

### Why the bbc-X fallback discharge still didn't land

POC attempted: prove `checkElab-fallback-RVar-id` directly using the
view-aware reduction. The view refactor makes
`bbc-id-failure-aux ctx (T ⇒[Many,pure] T) err (llv-not-found _)
(liv-not-found _)` reduce computationally (bundle, not captured-refl).
But to *reach* that reduction from `checkElab ctx (RVar "id") T'`, the
proof must navigate three more layers:

1. `checkElabV` → `bbc-id-aux ctx T (inferElabV ctx (RVar "id"))`
2. `bbc-id-aux` on `failure` → `bbc-id-failure-aux ctx T err (inspectLookupLocal ctx "id") (inspectLookupImport ctx "id")`
3. `inspectLookupLocal ctx "id"` only reduces if `lookupLocal ctx "id"` is concrete.

The hypotheses give us `lookupLocal ctx "id" ≡ nothing` and
`lookupImport _ "id" ≡ nothing`, but `with`-abstracting the lookup
runs into a `lookupLocal ctx x` vs `lookupLocal-go ...` unification
mismatch (Agda normalizes the goal but not the hypothesis type).

**Remaining path forward:** bridge lemma at the `inferElab` /
`inspectLookup*` boundary (e.g., `inspect-llv-not-found : lookupLocal
ctx x ≡ nothing → inspectLookupLocal ctx x ≡ llv-not-found refl`)
plus `cong`-style rewriting through the elaborator. Or — the original
plan's Phase 4 (`WellTypedPolyCtx`) plus a `t-var-fallback` typing
rule that takes `lookupLocal/Import ≡ nothing` directly, bypassing
the elaborator-side reduction entirely.

This is a tractable follow-up but not blocking; the view refactor was
the load-bearing cleanup that the user's lesson directly mandated.

## Phase 5 outcome (2026-05-03 continuation)

After committing the view refactor + Soundness postulate cleanup
(Phase 4), wrote the load-bearing
`inferElabV-RVar-fail-bridge`: a J-style helper that rewires the
`inferElabV-RVar-lookup-aux ctx x ¬unit (lookupLocal ctx x) refl …`
call to `… nothing eqLoc …` so the failure clause reduces. With this
bridge in hand, the bbc-X discharges follow a uniform pattern.

### Postulates discharged this turn

- **8 `checkElab-fallback-RVar-X`** (id, fst, snd, terminal, initial,
  inl, inr, arr): proved by `with inferElabV ctx x | bridge`, then
  `with inspectLookupLocal/Import` (split `llv-not-found / liv-not-found`
  + 2 absurdity clauses for the `llv-found / liv-found` cases via
  `just≢nothing-Maybe`), then `with X ≟T Y` for the inner type-equality
  check that the bbc-X-failure-aux uses.
- **`checkElab-fallback-RVar-poly`**: proved by composing
  `inferElabV-RVar-fail-bridge` with `with classifyBareBuiltin x | eqCls`
  and `with lookupPoly … | eqPoly`, plus `with T ≟T T`.

### Postulates that remain (deferred)

- **`bbc-other-poly-witness`** (Elaborate.agda:682): needs `WellTypedPolyCtx`
  invariant on `NamedCtx` (Phase 4 of original plan). Currently
  unsoundly claims `ctx ⊢ᶜ RVar x ∶ T ⨾ zeroUsage` for arbitrary x, T;
  used in checkElabV's bbc-other-poly path.
- **`checkElab-fallback-RApp-compose`** (Elaborate.agda:2319): the
  postulate is **not generally sound** as stated. checkCompose's path-1
  (composeArgB) only resolves B for `fst/snd/id/terminal/poly`, not
  for `inl/inr/arr/initial`. So `compose f inl` can fail to elaborate
  even when `checkElab inl (A ⇒ A+B)` and `checkElab f (A+B ⇒ C)`
  succeed. Discharging this requires either (a) extending composeArgB
  to all bbc-X shapes, (b) strengthening the postulate's premise to
  include `composeArgB ctx g A ≡ just B`, or (c) the original plan's
  checkCompose split into typed-driven and poly-driven helpers.

### Final postulate count

- **Soundness/Classify/ErrorProofs/Judgment**: 0
- **Elaborate.agda**: 2 blocks (`bbc-other-poly-witness`,
  `checkElab-fallback-RApp-compose`)
- **Completeness.agda**: 3 (WF-deferred completeness gaps,
  out-of-scope per branch description)

`make typecheck` green throughout.

## Phase 6 — t-compose-check rule split (2026-05-03)

After diagnosing `checkElab-fallback-RApp-compose` as not just
under-discharged but **not generally true** (composeArgB only resolves
B for fst/snd/id/terminal/poly shapes, so e.g. `compose f inl` fails
to elaborate even with the typing rule's premises met), addressed it
via Option D: rule-split.

**Principled framing**: `t-compose-check`'s old form admits free type
variables in B that a no-unification bidirectional algorithm can't
recover from local context. The rule must reflect what the algorithm
can decide.

### Changes

- **`composeArgB` moved from Elaborate.agda to Classify.agda** so
  Judgment can reference it.
- **`t-compose-check` (Judgment.agda)**: added premise
  `composeArgB ctx g A ≡ just B`. Now exactly captures what the
  elaborator's path-1 supports; the inferElab-driven path 2 is
  dropped entirely.
- **`checkCompose` (Elaborate.agda)**: deleted path-2 clauses
  (success at arrow-pure-Many T'). Now uses only composeArgB. Routes
  through new `checkComposeWithB` helper that takes the composeArgB
  result + equation as explicit arguments (J-style threading).
- **Completeness's `t-compose-check` case**: passes `eqArgB` to the
  fallback helper.
- **`checkElab-fallback-RApp-compose`**: now takes `eqArgB` as
  premise. Discharged in a chain through `checkComposeWithB-J`
  (substitutes composeArgB) and `checkComposeWithB-just-success`
  (handles the success path of both checkElabV calls).
- **`checkComposeWithB-just-success`**: postulated. Reducing
  `proj₁ (checkComposeWithB ctx f g A C (just B) eqArgB)` to success
  given both checkElab successes runs into the with-abstraction
  limitation: the internal `checkElabV ctx arg (...)` call inside
  checkComposeWithB doesn't unify with the externally-abstracted
  variable. Sound by direct computation; discharging cleanly needs
  either (a) lift checkElabV calls out (cyclic with Soundness) or
  (b) UIP-style reasoning beyond Agda's native with-mechanism.

### Net effect

Same postulate count (2 in Elaborate.agda) but the *content* is
better: the typing rule now correctly reflects what the bidirectional
algorithm decides, eliminating the soundness gap on `compose f inl`-
shaped expressions. The remaining postulate is a focused proof-
mechanics gap, not a rule/elaborator alignment issue.
