# Plan 0.39 — Trace-correct optimizer

## 0. Where this starts (2026-10-28 survey; supersedes the 2026-06 text where they differ)

**The prize.** `opt-trace` (`Once/Adequacy/Compile.agda`, `WithCPU`) is a postulate in the apex's trust base
(path: `once-certified → once-compiler → SpecApex.correct → soundness → sound-trace`). It is the whole
correctness of the default build: `once build` optimizes unless `--no-optimize`. `correct` splits on `doOpt`:
`false` is `file-correct` (proved), `true` is `opt-trace`.

**What `doOpt` does.** Exactly one thing: `if doOpt then optimize ir else ir` on each function's elaborated IR
(`Compile.compileFunBody-aux`, `compileFunBodyI-at`). Nothing else in compilation reads it.

**The optimizer.** `Once.Optimize` (live, apex cone): `optimize = optimize-n 10` passes of `optimize-once`;
view-driven rules; drops guarded by `has-effect?` (`apply`, `SigOp`, `Call`, `Iter` count as effects).
`Once.Optimize.Correct` (its June value-level proof) is a RED island over the deleted pure `eval` (D-entry at
plan 0.98: `eval` is refuted under `⟦ Void ⟧ = ⊥`). The seven `Optimizer.*`/`Optimize.Shape`/`Category.Laws`
modules (plan 0.64 Group O) are islands not imported by the live optimizer.

**The meaning.** IR means `T∞` runs (`evalᴰ fmt ρ`, a call environment `ρ`); runs are compared step for step
(`RelS`) under the value relation `RelD` — never `≡`. The template is `Adequacy.RewritePreserves` (the arith
pass, also IR → IR): `rewrite-rel : RelD a a′ → RelS (RelD B) (E (rewrite ir) a) (E′ ir a′)`, then the table
entry by entry (`table-rel`), the program (`program-rel`), the trace (`RelS-tr`). The 2026-06 text's `obs` is
this.

**The codegen chain.** `ArchCorrect.file-wf`/`file-tr` and the per-arch proofs are stated at
`compileFileFromModule IR.Heap false`; `moduleTable`/`moduleToIR` are defined at `false` (169 sites name
`false`). The concrete half (`conc-tr`) is already generic over the IR program; `false` enters through
`file-is-emit`, `file-wf` and the two definitions.

## 0.1 The route (2026-10-28)

`opt-trace` = the codegen chain at the OPTIMIZED program (C) ∘ the optimized program has the source program's
trace (A), joined by the optimized module being the source module with `optimize` mapped over its functions (B).

* **A — the optimizer keeps the trace** (`Adequacy/OptimizePreserves`, after `RewritePreserves`):
  1. *Quiet terms return at once.* `has-effect? f ≡ false → force (evalᴰ ρ f a) ≡ ret (inj₁ v)` for some `v`
     (a sibling of `LiftSound.lift-now`). If `evalᴰ` takes silent steps for a quiet term (`Cata`?), the drop
     rules need the weak relation instead — settle this FIRST (it decides A2's relation).
  2. *One pass.* `opt-once-rel` by the rule structure: trace-transparent rules by the monad laws (`relS-ret`,
     `RelS-bind`), drop rules (`terminal ∘ f`, `fst`/`snd ∘ ⟨g,h⟩`) by A1 on the dropped part, every other former
     a congruence (the `walk-rel` cases).
  3. *Ten passes.* `optimize-n` chains passes, so the relation must compose: `RelD` a PER (symmetric,
     transitive, by induction on the type; arrows need a self-related argument, which a PER gives) and `RelS`
     transitive. Then `opt-rel` for `optimize`.
  4. `table-rel`/`program-rel`/`optimize-program-trace` exactly as in `RewritePreserves`.
* **Findings, 2026-10-28 (A1/A3 settled by reading the semantics):**
  - *No silent steps on quiet terms.* `_>>=∞_` passes a finished block's value straight on
    (`bindBlock (ret (inj₁ x)) k = force (k x)`); `seqF∞`, `fmap∞` and `sem-cata` only bind; only `iter∞`
    steps silently (and `Iter` is an effect). So A1 holds at the STRONG relation `RelS`; the drop rules need
    no weak bisimulation.
  - *`Out` is not quiet at the IR.* `evalᴰ (Out w) v = fmap∞ … (forceᴵ v)` forces a stream, and an `act` stream's
    `forceᴵ` runs its coalgebra (`anaFᴵ` stores `evalᴰ coalg`), which may emit. IR types are ungraded
    (`ν-type F` is one type for `pure` and `act`), so A1 cannot hold with `has-effect? (Out _) = false`. In
    elaborated code an `act` `Out` sits under the `act` lambda of `outActᶜ` and runs only under an `apply`
    (an effect), and the optimizer has no rule across `apply`/`curry`, so no shipped program is known to lose
    an event; but the guard is not what the proof can use. Fix (principled, sound): `has-effect? (Out _) =
    true`. The cost is dropping a pure stream's `Out` under `terminal`; F may recover it with a grade-aware
    predicate.
  - *Composition.* Neither `RelD` nor `RelS` has symmetry or transitivity yet. A3 needs the PER, which `Denotation/ValueRelPER` (plan 0.119 D5) already proves.

## Why

`Once/Optimize.agda` was written when "correct" meant **value correctness**:
`optimize-once-correct : eval′ (optimize ir) x ≡ eval′ ir x`
(`Once/Optimize/Correct.agda`). But for Once, **correctness is SigOp-trace
correctness** — the apex claim of Plan 0.36 (`machine-trace (compile ir) ≡
obs ir`). `evalSurface`/`eval′` is *empty as an observable for effects*
([[feedback_programs_dont_return]]): every `_ → Unit` morphism denotes `tt`,
so a value-level proof cannot see a dropped `linux.exit` or `emit`.

That gap was a real, shipped soundness bug: the degenerate rules
(`B ≡ Unit → terminal`, `terminal ∘ f → terminal`, `fst/snd ∘ ⟨g,h⟩ →
g/h`) silently dropped effectful SigOps, so **every** default-optimized eff
program exited 0 while the proofs stayed green (diagnosed 2026-06-09; the
`exit 42 → 0` regression). It was patched (commit: `has-effect?` guards +
`apply` treated as effectful) — a *conservative* fix that blocks the drops
but (i) is justified only by hand-reasoning, not the proof, and (ii) loses
real optimizations (any `apply`/`free-heap` now counts as effectful).

This plan replaces the patch with the **principled** statement: the
optimizer may rewrite freely **as long as the trace is preserved**. The
trusted/proven property becomes trace equality, and the side-conditions
(when a drop is allowed) fall out of the proof instead of being asserted.

## The principle

The optimizer sits between elaboration and codegen: the compiled artifact is
`compile (optimize ir)`. The grand theorem wants
`machine-trace (compile (optimize ir)) ≡ obs ir`. Compiler correctness
(0.36) already gives `machine-trace (compile e) ≡ obs e`, so the optimizer's
obligation is exactly

```
optimize-trace-correct : ∀ ir x → obs (optimize ir) x ≡ obs ir x
```

where `obs` is the **SigOp-trace observable** from 0.36 (trace events +
result), NOT `eval′`. A rewrite is valid iff it preserves `obs`.

Under this lens the rules re-sort cleanly:

- **Trace-transparent rewrites** — `id ∘ f = f`, `g ∘ id = g`, eta
  (`⟨fst,snd⟩ = id`, `[inl,inr] = id`), `Void`-source → `initial`
  (vacuous), associativity/fusion. These preserve `obs` *by construction*;
  proofs stay essentially as cheap as today.
- **Drop rewrites** — `terminal ∘ f → terminal`, `fst/snd ∘ ⟨g,h⟩ → g/h`,
  `B ≡ Unit → terminal`. These delete a sub-term, so they preserve `obs`
  **iff that sub-term emits no trace event**. The precondition is a real
  proof obligation, and it is *exactly* what `has-effect?` approximates. So
  the patch's guard is not a hack — it is the trace-correctness side-
  condition, and the plan's job is to make the proof *demand* it rather than
  the code assert it.

## What changes

1. **State the observable.** Reuse 0.36's `obs` (the trace semantics already
   defined for `compile-correct-flat`). Confirm `obs` is total over all IR
   the optimizer sees (it is — it's the same IR the codegen consumes).
2. **Replace the theorem.** `optimize-once-correct` / `optimize-n-correct` /
   `optimize-correct` are re-stated over `obs`. The value-level lemma stays
   only as a corollary if useful (`obs` determines the result component).
3. **A precise trace-emptiness predicate.** Define `emits-nothing? ir`
   (≡ `obs ir` has empty trace for all inputs) — provably, via the per-SigOp
   `EffectShape` (`Pure` ⇒ no event; `Halts`/`Emits` ⇒ event). This is the
   *exact* condition the drop rules need, and it is finer than today's
   `has-effect?`:
   - a **`Pure` SigOp** (e.g. `arith.block.<digest>`) emits nothing, so it
     *may* be collapsed — recovering an optimization the patch forbids;
   - `apply`/`free-heap` need only be opaque when their trace is unknown,
     not unconditionally effectful.
4. **Discharge per rule.** Trace-transparent rules → direct. Drop rules →
   guarded by `emits-nothing?` of the dropped sub-term, with the trace-
   equality proof discharged from `EffectShape`.
5. **Retire the conservative `has-effect?` guards** in favour of the proven
   `emits-nothing?` side-condition (or keep `has-effect?` as a sound, now
   *proven*-sufficient decider for it).

## Phasing

- **A — Observable + restated theorem (skeleton).** Re-state `optimize-*-correct`
  over `obs`; leave drop-rule cases as holes. Build green with holes flagged.
- **B — Trace-transparent rules.** Discharge the pure/eta/vacuous rewrites
  (the bulk; cheap).
- **C — `emits-nothing?` + drop rules.** Define the predicate from
  `EffectShape`; discharge the three drop rules under it.
- **D — Relax + measure.** Replace the conservative guards with the precise
  predicate; re-run `tests/run-exit-tests.sh --alloc heap` (optimization ON)
  — target 39/39 (modulo (a) below) and confirm recovered optimizations.
- **E — Cleanup.** Drop the value-level theorem (or demote to corollary);
  update the decision log (value-correct → trace-correct optimizer).

## Note on (a): `nestedprod-sum` miscompiles under optimization

Symptom (2026-06-09): with optimization ON, `layer5-cata-nestedprod-sum` →
**208** instead of 42 (the effect *fires* now — not an effect drop — but the
value is wrong). The optimizer is verified value-correct, so the rewritten
algebra is value-equal; the wrong result means the **cata codegen miscompiles
a value-equal-but-reshaped algebra** — a cata-codegen incompleteness (Phase 3
of 0.36), not an optimizer bug per se. It is the *only* one of the 9 functor
shapes affected, and only under optimization; the canonical `--no-optimize`
path is clean.

A trace-correct optimizer (this plan) does not by itself fix (a) — it would
still rewrite the algebra. Two principled options, to settle when Phase 3
lands: (1) prove the cata codegen robust to value-equal algebras (the real
fix, Phase 3 `cata-correct`); or (2) have the optimizer **not rewrite
recursion-scheme algebras** until their codegen is trace-verified (a sound,
documented restriction — `optimize-once-structural (Cata wf alg) = Cata wf
alg`, proof → `refl`). Track (a) against Phase 3; do not patch it blind.
