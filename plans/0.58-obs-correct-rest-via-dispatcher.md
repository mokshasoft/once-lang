# Plan 0.58 — Discharge `obs-correct-rest` via the canonical Dispatcher (Option 3)

status: active (2026-07-04)
branch: `discharge-obs-correct-rest`

## Goal

Remove the `obs-correct-rest` **catch-all postulate** in
`Once/CCC/Codegen/IRObsCorrectFlat.agda` — the one that currently covers
every non-`Cata`, non-`SigOp` IR constructor's `MachineRefinesObsF` — by
routing each constructor's `value-realized` through the **one canonical
abstract `Dispatcher`** (which already proves `IRResultAWF` for *every* IR),
bridged to the flat machine by the now-live `lift-validAtWF-flat`
(`FlatSemanticLift`). End state: `ir-obs-correct` is a total, postulate-free
dispatch **except** `cata-correct` (the genuinely-effectful recursion, owned
by Plan 0.36).

This is **Option 3** of the design fork (see the decision below). One source
of truth for allocation + value-flow reasoning; robust to a future change of
the allocation model.

## Why Option 3 (design record)

The composite constructors (`∘`/`⟨,⟩`/`case`/`curry`/`apply`) need the
sub-IRs' correctness *composed*. Three ways to get it:

1. **Flat-native** — compose `MachineRefinesObsF` directly over the flat
   machine. Self-contained, but **re-derives** allocation reasoning in the
   flat track (a second place to fix when the allocator changes).
2. **`SigOp`-free shadow dispatcher** — a restricted recursion over the
   existing `run-*`. Reuses value-flow but is a **parallel dispatcher** to
   keep in sync — exactly the kind of fossil we are otherwise deleting.
3. **Canonical `Dispatcher`** (this plan) — use the single dispatcher that
   already proves `IRResultAWF` for all IRs, then `lift-validAtWF-flat`.

Deciding factors:
- **Allocation churn**: `AllocMode`/`bump`/`apply-bump`/`alloc-correct` live in
  `IRResultAWF`/`run-*`. Option 3 keeps allocation reasoning in **one** place;
  the obs track consumes it through the stable `result-place`/`alloc-correct`
  interface. Option 1 duplicates it; Option 2 keeps a duplicate recursion.
- **Cost is real work, not a wart**: Option 3's dependency — a concrete
  **total `Provider`** — is exactly *SigOp totality*. We owe it anyway.

## Prerequisite — Phase 0: assemble a concrete total `Provider` (SigOp totality)

The `Dispatcher` (`Once/CCC/Machine/Dispatcher.agda`) is parameterized by
`sigOp-proof : Provider`. `Provider` is now **total** (`∀ si → ∃ Contract`,
no `Maybe`) — done this session ("force it"). But the apex still threads
`sigOp-proof` **abstractly**; no concrete provider is assembled. To use the
Dispatcher in the obs track we must instantiate it.

Steps:
- Build the whole-program provider by composing domain `PartialProvider`s via
  `_<|>_` and closing with `close … residual` (`Once/CCC/SigOp/{Contract,Compose}.agda`):
  - arith: `Once/CCC/SigOp/PureProvider.agda` (`pure-prim-provider`, done this session — covers `arith.block.*` / any `Pure`+fits-in-reg).
  - lit / syscall / other domains: their `PartialProvider`s (build or locate).
  - `residual`: the ONE explicit, named producer-of-last-resort postulate for
    the open `CanonicalName` tail (documented, greppable — not a hidden escape).
- Thread this concrete `Provider` through `IRObsCorrectFlatness` → the
  arch-correctness chain (`Once/Adequacy/ArchCorrectness/*`) so the apex's
  `sigOp-proof` becomes concrete. This turns the apex `correct` from
  "for any total provider" into an **unconditional** theorem.
- This is Plan **0.38**'s domain (per-producer SigOp contracts). Coordinate.

Note: for `EmitsNoSigOp` IRs the SigOp branch is never reached, so the
`residual` postulate is *not* on the pure-constructor path — but the total
provider is structurally required to instantiate the Dispatcher.

This subsumes the per-constructor `ev-[]`/`mach-[]`/`denot-[]` already hand-written
for `id`/`fst`/`snd`/`terminal`.
