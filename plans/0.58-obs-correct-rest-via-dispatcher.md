### PRINCIPLED BLOCKER on value-realized (2026-07-04) — RESOLVED 2026-07-11 → option (c)-as-parity

The deleted `ComposeWF` was 841 lines; `run-compose` (git 58611579~1) shows two coupled issues:
 1. It takes `rec-wf : RecDispatcherWF (ir-size (g∘f))` — the abstract recursion `∀ smaller-IR
    → IRResultAWF` (the Dispatcher's core, part of the deleted fossil). Rebuilding value-realized
    means reconstructing that recursion (RecDispatcherWF, or a fresh well-founded abstract-value
    carrying the same IRResultAWF invariants: BeforeFrontier/halted/rdi at each intermediate).
 2. Its hand-off is `inter-rax-f : readReg (regs s₁) Output ≡ SV-Ptr inter-loc-f` — assumes a
    POINTER intermediate. `at-reg` (register-resident arith result, this session) writes the
    SENTINEL not a pointer, so `g ∘ f` with `f` producing a register value (any Pure SigOp /
    arith block) breaks `g`'s pointer-shaped `rdi` precondition.
DESIGN QUESTION (was): how does a register-resident (`at-reg`) intermediate thread into a
downstream IR expecting a pointer input?
 (a) SPILL at-reg results to a stack slot before composition (uniform pointer model);
 (b) restrict the composable fragment to NO-SigOp (avoids at-reg, but arith can't sit inside ∘);
 (c) give the compose hand-off a register path (dual hand-off).

DECISION (2026-07-11, evidence-based): **(c), reframed as "bring the INPUT precondition to
parity with the OUTPUT `ResultPlace`"** — with **(b) as the first milestone**. Rationale from
ground-truth codegen + invariants:

 * **Codegen never spills → (a) rejected.** `ir-to-trace' n l (g ∘ f) = … (ft ++ mov-to-input ∷
   gt) …` (`IRToTrace.agda:450`); `mov-to-input` is a verbatim `Output→Input1` register copy — NO
   store, NO deref. `SigOp si` = `instr-sigop si ∷ []` (`:638`), result in `Output` as a register
   value. So (a) would require EDITING `ir-to-trace` to emit a spill the compiler does not emit
   (a codegen change + re-proof), and it REGRESSES the generated code: an arith chain `f∘g∘h`
   becomes store/load round-trips at every `∘`, negating the whole point of `at-reg`. Rejected.
 * **The output side is already generalized; only the input side is stale.** `ResultPlace`
   (`ClosureWellFormed.agda:337`) already carries `at-loc` (pointer: `Output ≡ SV-Ptr loc`) AND
   `at-reg` (register: `Output ≡ unit-storedvalue`), unified via `place-sv`/`place-rax`; BOTH
   carry a `ValidAtWF … loc` witness. The blocker is that the INPUT precondition — in the LIVE
   `IRObsCorrectF` (`IRObsCorrectFlat.agda:171`) *and* in the fossil `RecDispatcherWF` — is still
   hard-wired `readReg Input1 ≡ SV-Ptr input-loc`. The fix is symmetric: state the input hand-off
   as `readReg Input1 ≡ place-sv (f's result)` (an `InputPlace` mirroring `ResultPlace`), so the
   boundary is `place-sv`-shaped on BOTH ends — exactly what `mov-to-input` transports.
 * **Aligns with the other IRs (placement is TYPE-directed).** `fst`/`snd` = `load-indirect`/
   `load-indirect-suc` (`:433-434`) deref `Input1` as a pointer because a product is always
   heap-resident; `pair`/`curry`/`inl`/`inr` leave a pointer. ONLY a Pure SigOp leaves a
   register-resident `Int`. So the generalization is conservative and only ACTIVATES for
   primitive/register-eligible input types: pointer-typed inputs keep the `SV-Ptr` precondition
   unchanged; `Int`-from-SigOp gets the register path. Follows the grain (shape follows type).
 * **RecDispatcherWF: do NOT revive the FOSSIL, but its ROLE must be rebuilt at the `run-*` level.**
   REFINED 2026-07-11 during recon: the first instinct ("drive the composite recursion off
   `ir-obs-correct`'s own IH") is WRONG — `IRObsCorrectF` (`IRObsCorrectFlat.agda:167`) pins
   `next-slot alloc ≡ 0` (entry frontier only), so the IH is NOT composable for the SECOND operand
   `g`, which runs at `f`'s BUMPED frontier. The frontier-GENERIC layer is `SimpleWF.run-*`
   (`run-fst` takes any `alloc`, no `next-slot≡0` — `SimpleWF.agda:144`). So the value recursion
   must live THERE: rebuild `run-compose` as a clean, frontier-generic recursive abstract-value
   producer at the `IRResultAWF` level (leaves → existing `run-id`/`run-fst`/…, composites →
   `exec-trace-append` split + recurse + `mov-to-input` hand-off). That producer plays
   `RecDispatcherWF`'s ROLE (a well-founded "run any smaller IR") but is fresh/minimal, NOT the
   841-line fossil `ComposeWF`. `obs-correct-compose` (entry level) then calls it ONCE and
   `lift-validAtWF-flat`s to the flat post-state for `value-realized`. Use the deleted
   `run-compose` (git `58611579~1`) ONLY as a structural template.
 * The `place-sv`/`InputPlace` input-parity generalization therefore lands on the `run-*` INPUT
   precondition (`readReg Input1 ≡ SV-Ptr input-loc`, `SimpleWF.agda:150`) FIRST — that is what
   lets `run-compose` feed an `at-reg` intermediate into `run-g`. `IRObsCorrectF:171` is the same
   precondition at the entry level (program input is a pointer, so it can stay `SV-Ptr` there).

 * **Performance:** (b) and (c) are purely proof-side → ZERO runtime cost (`ir-to-trace`
   unchanged; arith stays register-resident, each `∘` a single `mov-to-input`). Only (a) touches
   the compiler and regresses output. Principle and performance agree.
