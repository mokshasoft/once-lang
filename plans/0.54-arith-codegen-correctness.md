# Plan 0.54 — verify the arith compiler's codegen (discharge `refine-*`, wire into the apex)

## Goal

Close the arith compiler's one real proof gap: its **codegen is trusted, not
proven**. The abstract spec (`step`), the lowering (`compile-abs`), the emitters
(`Emit`), and the block meaning (`block-semM`) are all defined and total, but the
link "*the emitted code implements the spec*" is postulated (`refine-*`) and not
even apex-wired. End state: the arith compiler is verified end-to-end, with trust
reduced to the honest boundaries only (CPU primitives, external-SigOp semantics,
div/mod-by-zero axioms).

## Why this is the whole gap (and where it hides in the apex)

The apex theorem `exec(assemble(asm)) ≡ obs` ranges over the *whole* emitted asm,
which **includes** the `once_arith.block.*` subroutines (`Target/<arch>.agda`
concatenates `programToText prog ++ … ++ emit-arith-blocks …`). The flat machine
(`FlatEvents`) treats each arith SigOp **atomically** — one `SigOpEvent` via its
declared `block-semM`, never running the subroutine. So the field

```
asm-trace-correct : asm-sem asm ≡ flat-trace (moduleToIR m)   -- ArchCorrect, Once/Adequacy/Compile.agda
```

is exactly the claim "*executing the real arith subroutine ≡ the atomic
`block-semM`*". It is a field of the `ArchCorrect` record produced by the
apex-reachable postulate `<arch>-flat-from-obs` — so **`asm-trace-correct` is the
postulate hiding the arith codegen's correctness.** The theorem is sound and does
cover arith; the correctness is asserted, not proven. Closing the gap = proving
the arith slice of `asm-trace-correct`.

## Key architecture fact (already reflected in the code)

The arith compiler is **arch-neutral except for the final `Emit`**: `Machine/`
(`step`, `compile-abs`), `Backend/XInstr/` (`Syntax` = the `XInstr` IR + abstract
`XReg`; `CodeGen` = `emit`) are shared by all three backends; only
`Backend/{X86-64,X86-32,RiscV64}/Emit` (register map + word offset) is per-arch.
The old misleading `X86` submodule was already renamed to the neutral `XInstr` in
Plan 0.53 (the split). **No frontend involvement:** the only `TypeCheck` import
under `Once/Arith/` is in the orphan `Boundary.agda` (dead code); the
codegen/refinement path imports only `IR`/`Type`/`Word`/`SigOp`/`Denotation`.

## Current trust surface (postulates, from the 0.53 audit)

- `Backend/Correct` + per-arch `Correct`: `XState`/`concretise`/`exec-x86`
  (abstract concrete machine) + `refine-load-input … refine-move-to-out` (9) —
  **postulated, and orphan** (not apex-wired). ← the target.
- `SigOp/Builders`: `generic-semM`/`generic-semI` (opaque external-SigOp
  semantics — honest boundary, NOT closed here), `div-semM`.
- `Semantics.agda`: `ℤ-div`/`ℤ-mod` (total int div/mod; div-by-zero deferred —
  honest boundary, NOT closed here).
- `SigOp/RelaxedPOC.agda`: POC postulates (orphan).

## Plan

### Phase 0 — rename `X86` → `XInstr` (DONE, Plan 0.53 split)

The neutral compiler is already `Once/Arith/Backend/XInstr/{Syntax,CodeGen}`;
per-arch `Emit`/`Correct` under `Backend/{X86-64,X86-32,RiscV64}/`.

### Phase A — discharge `refine-*` against a real machine (100% in `formal/Once/Arith/`) — ✅ DONE (2026-07-02)

**COMPLETE, funext-free, width-generic.** `Backend/Correct.agda` (renamed from the
scratch `CorrectProof`, replacing the old postulated scaffold) now:
- **defines** the concrete XInstr machine `exec-xinstr`/`exec-x86` (XState =
  `ArithAbsState`, `concretise = id` — the XInstr machine runs on the same state
  type, `XReg → {0,1,2,3}` via `xreg-idx`);
- **proves** all 9 `refine-*` — single-write ops as full `≡`, double-writing ops
  (`neg`, `sub` dst≡b via neg+add, binary else-case) as a **pointwise state
  equivalence `~`** (NOT full `≡` — that would need funext; `~` mirrors
  `CompileGoInv`'s pointwise style). Aliasing handled via width-generic Word
  algebra (`⊕`/`⊗`-comm, `sub-identity` from `norm-absorb-left`), `double-write`
  collapse, and `store-write-same/other`;
- **proves** `refine-program` (fold: `exec-x86 (emit-program prog) ~ run-abstract
  prog` for reg-bounded `prog`, via `exec-xinstr-cong`/`step-cong`/`exec-x86-cong`
  + `exec-x86-++`), `compile-abs-bound` (compile-abs stays in regs 0,1), and
- **`block-correct`**: `output-of (exec-x86 (emit-program (compile-abs e)) (init
  env)) ≡ just (eval-arith-W e env)` — composes the concrete refinement with the
  abstract `abs-validity`.

To keep it width-generic, `Machine/Compile.agda` was split: the width-agnostic
compiler (`compile-go`/`compile-abs`/`required-scratch`) stays there; the
correctness (`compile-go-correct`/`abs-validity`) moved to the new
`Machine/CompileCorrect.agda (bits)`. The 3 per-arch `Correct` are now one-line
`open import Backend.Correct <width> public` — **zero postulates** (the machine
+ refine-* postulates are gone). `NO funext, NO new axioms.`

Original plan (all steps discharged):

Replace the postulated concrete machine + refinement with definitions + proofs.
Self-contained: no frontend, no apex, arch-generic.

1. **Define `XState`** — a concrete register-file (`XReg → Word`) + spill memory
   (scratch slots) + the input value, indexed by `InputShape`.
2. **Define `exec-x86 : XProgram → XState → XState`** — operational semantics of
   `XInstr` (the `Xmov-*`/`Xadd`/… ops over `XState`).
3. **Define `concretise : ArithAbsState sh → XState sh`** — map the abstract
   arith state to the concrete machine.
4. **Prove the 9 `refine-*`** — `exec-x86 (emit i) (concretise s) ≡ concretise
   (step i s)`, per `AbstractInstr`. Register/memory reasoning; mirrors `step`.
5. **Lift to programs** — `refine-program`: fold the per-instr refinement over
   `compile-abs e` ⇒ `exec-x86 (emit-program (compile-abs e)) (concretise s₀) ≡
   concretise (run-step (compile-abs e) s₀)`.
6. **Abstract machine computes the value** — `step*`/`run-step` over
   `compile-abs e` yields `eval-arith e` (= `block-semM`). (Check whether this
   already exists in `Machine/`; if not, prove it — arith-local.)
7. **Block codegen correctness (arith-local conclusion):** compose 5+6 ⇒
   `exec-x86 (emit-program (compile-abs e)) (concretise s₀)` reads off
   `block-semM e`. This is the real theorem "the compiled arith block implements
   its meaning," now proven at the `XInstr` level.

Deliverable: `Backend/Correct` (+ per-arch instantiations) with `refine-*` and
the block-correctness **proven**, `XState`/`exec-x86`/`concretise` **defined** —
`refine-*` no longer postulated. All within `formal/Once/Arith/`.

**Survey findings (2026-07-02) — Phase A is smaller than the audit suggested:**
- **Step 6 is already DONE.** `Machine/Compile.agda` proves `compile-go-correct`
  (+ `aadd/asub/amul/aneg-correct`): `run-abstract (compile-go d e) s` lands
  `eval-arith-W e (input s)` in reg 0. So the abstract machine over `compile-abs`
  already computes `block-semM` — no new work for steps 5–7's abstract side; just
  compose the concrete bridge with the existing `compile-go-correct`.
- **`emit` is a clean per-instruction mapping** (`Backend/XInstr/CodeGen.emit :
  AbstractInstr → XProgram`, dispatch on `abs-reg r`: 0..3 → r12-r15, ≥4 → `[]`).
  So `refine-*` is a per-instruction bridge over a faithful lowering ⇒ provable by
  case analysis, each clause mirroring the corresponding `step` clause.
- **Reduced Phase A:** (1) define `XState` mirroring `ArithAbsState` (regfile
  `XReg → Word` + scratch + input), `concretise` via `abs-reg`, `exec-x86`
  mirroring `step` at the `XInstr` level; (2) prove the 9 `refine-*` (case
  analysis); (3) `refine-program` (fold via the existing `run-abstract`/`++`
  lemmas); (4) compose with `compile-go-correct` ⇒ `exec-x86 (emit-program
  (compile-abs e))` computes `eval-arith-W e`. All `formal/Once/Arith/`-local.

### Phase B — connect `XInstr` exec to the real asm/CPU, wire into the apex (`formal/Once/Adequacy/`, no frontend)
