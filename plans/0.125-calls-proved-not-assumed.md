# Plan 0.125 — Calls are proved, not assumed

## 0. Where this starts

* **The apex is vacuous.** `once-certified` takes `BlockRunsHyp-<arch>`, i.e.
  `BlockRunsT = ∀ ir → BlockRuns (image ir)`, and that type is empty (D340: a fresh-label state refutes
  `CoalgRuns` for every program). D218 turned D213's false postulate into this hypothesis; that hid the ⊥
  without removing it.
* **No state premise can repair it.** `BlockRuns` concludes facts about the PROGRAM from a STATE
  (D213). Weakening it fails two ways (D340 addendum): an unresolved call halts, so `apply`/`Out` need
  the resolution, and one cell can be valid at two denotations (D217), so no state says which function
  a block computes. Four designs died this way: `block-runs`, `CodeResolves` (D216), `CodeWF`,
  `BlockAt`-in-witness.
* **Every call is assumed today.** `apply` (`BlockRuns.closures`), `Out` (`.coalgs`) and `Call`
  (`.functions`) take the callee's whole run as a `CalleeRun` that nothing constructs. `ana` looks proved
  only because `Out` assumes its coalgebra's run. `cata-correct` has nothing to assume it from, so it is
  the one call left as a postulate.

Progress is one number: postulates plus empty hypotheses in the machine-correctness layer. It goes down
only when what they stand for becomes provable.

## 1. The fixed point

Correctness is the effectful-SigOp trace (`Behavior = ℕ → List SigOpEvent`, indexed by event count).
Everything else is a prior decision and may be revised.

## 2. The design (from plan 0.93 §2–§4, still right)

`ValidAtWF` is a `data` indexed by the type, so a constructor can only assert facts about cells. It cannot
recurse on the type, so a closure witness cannot pin the function it denotes. The relation must be a
FUNCTION on types, as `Once/Adequacy/MeaningRelation.agda` already is one layer up:

```agda
RelV : ∀ (A : IRTy) → ⟦ A ⟧ᴰ → StoredValue FS → LocState FS → Set
RelT : ∀ (B : IRTy) → T ⟦ B ⟧ᴰ → FlatState → Set

RelT B comp fs      = ∀ n → (events of the run from fs ≡ projTrace comp n)
                          × RelV B (valueT comp n) (the result) (the settle state)
RelV (A ⇛ B) f sv s = ∃[ ℓ ] ( sv holds code ℓ × find-thunk prog ℓ ≡ just j
                             × ∀ a av s′ → RelV A a av s′
                                         → RelT B (f a) (entering block ℓ with av from s′) )

ir-correct : ∀ {A B} (ir : IR A B) {x av s} → RelV A x av s → RelT B (evalᴰ ir x) (run of `emitted ir` from s)
```

To copy from the template exactly: recursion on the type, mutual and forward-declared; the arrow is a Π
over related inputs; the computation relation is indexed by the event budget only; the recursion stops at
`μ` (layout) and `ν` (the suspension relation), which is why no `TERMINATING` pragma is needed.

* `apply` discharges from the arrow clause: no lookup, no `CalleeRuns`.
* `curry` establishes the arrow clause from its IH on `body`, a real subterm.
* `Ana`/`Out` are the same at ν, and `Call` is the same for the table's functions.
* Labels stay labels. Where ℓ sits in the linked image is a separate, state-free layout lemma.

S0 findings that bind the statement (plan 0.93 §6, kept): `_*_` is needed to state `apply`; the arrow
clause carries `find-thunk prog ℓ ≡ just j`, discharged by `curry` from its `BlocksAt`, since
`blocks n l apply ≡ []`; relation locations are heap locations; `RelT` carries a resume pc and return
stack fixed before the budget; `RelV` takes the allocator.

**Placement:** superseded by §2a. There is no new relation, so 0.89 C1 stays a separate change.

**Since 0.93 was written:** D337 (any return stack), D338 (`frames-pres`) and D339
(`next-slot alloc ≡ 0`) are true facts about returning runs and become obligations of `RelT`. The caller's
own stack slots (pair's saved slot, D208/D210) still need the callee-frame fact, so heap-only locations do
not avoid plan 0.124.

## 2a. S0 RESULT (2026-10-27): port the design, not the file; keep the computation half

`Once/Spike/RelSpike.agda` (3085 lines) is in the tree: deleted at the island pass (`318e29b37`) and
restored by `745b77de4`, and since then kept in step by import sweeps only. It is on `backstop.islands` as
red. It cannot be revived as it stands, because it is built on the trace model before plans 0.105–0.107:
its `RelT` is "∀ bud → take bud events ≡ … × RelV … (TM.valueT comp bud)" (41 `valueT`/`projTrace` uses),
with a total `valueT`. Today `valueT ι h m {p}` needs an `Interp`, a history and a `Returns?` proof. A
computation is a tree `T` whose calls an `Interp` answers, `evalᴰ` returns `T∞` (iterative, for servers),
and observations are approximations `⟪ comp ⟫ k` read by `eventsAt`/`resultAt`/`stopsAt`
(`returns (done v r)`, `cut`, `stopped`), with halting SigOps and the run's `left`. Its S3 content (8
clauses) has not moved since 2026-09-18.

What that changes:
* **The computation half already exists, in today's model, proved for every clause.**
  `MachineRefinesObsF`/`ValueRealized`/`CalleeRun` are exactly a "related computation" in the current
  observation shape, with D320/D337/D338/D339 folded in. A new `RelT` would re-prove fourteen clause
  modules (about 20k lines) to arrive at the same statement. **Keep them.**
* **Only the VALUE half is wrong**, and only at `⇛` and `ν`. So S1 makes `ValidAtWF` a FUNCTION on the
  type (the spike's Q1 showed recursion on the type is accepted with no pragma), with:
  * every first-order case as today (cells, layout, `μ` stops at the layout relation);
  * `A ⇛ B`: the code cell names `ℓ`, `find-thunk prog ℓ ≡ just j`, and for every caller state entering
    `j` with a VALID `A` input, a `CalleeRun … B (f a)`. That is today's `CalleeRuns`, moved from a premise
    about all states into the value, where `curry` can prove it. The recursion is at `A` and at `B`
    (inside `ResultPlace`), both smaller;
  * `ν F`: a coinductive record, as the spike's `RelNu` was: forcing (`Out`'s block) gives a `CalleeRun`
    whose result is a layer of `ν F` values that are again valid.
  `apply` and `Out` then read the `CalleeRun` off their input. `BlockRuns.closures`/`.coalgs` have no
  consumer and are deleted. D217's one-cell-two-denotations cannot be stated any more, because the arrow
  case says what the block does.
* **`FnRuns` is not about values.** A table function is called by name. It is discharged along the table
  by induction, each entry from its body's `ir-correct` and the S2 block-call lemma. So S5 removes all of
  `BlockRuns`.
* **The cost moves to the witness sites.** `ValidAtWF` has 237 uses in 32 files and about 420 constructor
  uses (`valid-inl(-reg)-wf` 93, `valid-inr(-reg)-wf` 80, `valid-closure(-reg)-wf` 74, `valid-ν-susp-wf` 36,
  `valid-pair-wf` 36, scalars 86). A `data` becoming a function turns constructor applications into
  Σ/record builds and constructor matches into a match on the type first. Mechanical but wide, and the
  transport lemmas (`validityWF-*`) are re-proved by recursion on the type. S1 measures it on one module
  before the sweep.
* **`Str`/`Buffer` are gone from `IRTy`** (5fef8ec42, plan 0.106). Plan 0.93 §11's invariant no longer has
  anything to guard (stale comment at `IRTy.agda:64` to delete).
* Plan 0.89 C1 (block-map inclusion) no longer comes free with a new relation, since there is none. It
  stays 0.89's, as a separate change to `IRObsCorrectF`'s placement premise.

#### S1a — the encoding (probe, 2026-10-28)
A standalone probe (mini `IRTy` with `*`, `+`, `⇛` and one first-order μ, `--guardedness -W error`)
settles how "a function on the type" is written so that the sweep stays narrow:

* **A naive mutual `record ArrowV` fails positivity**: `ArrowV` reaches itself through `Valid A`, which is
  to the left of an arrow (`NotStrictlyPositive`, checked).
* **Green, with no pragma:** each case is a NON-recursive `data`/`record` *parameterised by the component
  validities*, and the function only dispatches:
  `Valid p (A + B) = SumV (Valid p A) (Valid p B)`, `Valid p (A ⇛ B) = ArrowV p (Valid p A) (Valid p B)`,
  where `ArrowV`'s `runs` field takes `VA a al st` as a premise and returns `CalleeRunP VB fs (f a)`.
  A negative occurrence of a *parameter* is allowed; the recursion is structural on the type.
* **Constructor names survive.** At a known type the function reduces, so `valid-inl-wf …` still builds
  and still matches (checked on a consumer of `Valid p (A + B)` and on `(A ⇛ B) ⇛ C`). Only sites that are
  generic in `A` (the `validityWF-*` transports, `valid-primitive-wf`-style dispatchers) must case on the
  type first. That is far fewer than the ~420 constructor uses.
* **`ResultPlace`, `CellAt` and `CalleeRun` must follow the same pattern** (parameterised by a validity
  `VB`), because the arrow case contains `CalleeRun`, which contains `ResultPlace B`, which contains
  `Valid B`. Kept as data indexed by the type they would be negative in themselves through `(X ⇛ Y) ⇛ Z`.
  Today's names become abbreviations: `ResultPlace B … = ResultPlaceP (ValidAtWF … {B}) …`.
* **μ is not structural** (`⟦ F ⟧TI (μ-type F)` contains `μ-type F`), but `WellFormedFI` limits `K` to
  `IsBaseTypeI`, so a μ never contains `⇛` or `ν`. The μ case is a separate first-order inductive relation
  (today's first-order constructors, unchanged), with a bridge to `ValidAtWF` at base types for
  `In`/`out-μ`/`Cata`.
* **The program becomes an argument of `ValidAtWF`** (the arrow case says `find-thunk prog ℓ ≡ just j`),
  and `prog` is quantified per clause in `IRObsCorrectF`. So every signature that mentions `ValidAtWF`,
  `InputAt`, `ResultPlace` or `CellAt` gains `prog`. That is the wide part of the sweep, and it is
  mechanical. `CalleeRun` (and what it needs from `FlatMachine`) moves below `ClosureWellFormed`.
* **ν is still open.** Forcing yields a layer containing `ν F` again, so ν needs a coinductive record, and
  its `runs` field must not take a `ValidAtWF T seed` premise for a seed type `T` that can contain `ν`
  (that is the same negative self-occurrence). Candidate: the record carries the seed's `CellAt` as a
  FIELD and `runs` quantifies over states that agree with the construction state on the seed's cells.
  Look at the spike's `RelNu` before deciding.

### S2 — The block-call lemma
One lemma for every called block. If the body satisfies `IRObsCorrectF` and is entered from
`enter-call pre` with a valid input, it gives a `CalleeRun`: the run returns and leaves the caller's frame,
frame stack and live memory as they were. The run (call, `c-thunk`, body, `c-ret`) and the input transport
are §5. Uses plan 0.124's `shift-≺` (done, D342).

* `cata-correct` runs its algebra through S2 (`IRObsCorrectF alg` is its IH). That closes the postulate.
* `Call`: `FnRuns` discharged along the table, by S2 per entry.

## 5. The algebra's call, worked out (from plan 0.88, 2026-10-26)

* `do-call-at (just j)`: `falloc := enter-call pre` (pushes `(current-frame , frame-slots)` on
  `saved-frames`, shifts the frame by 1, `frame-slots = 0`, `next-slot` kept), `fret := suc pc ∷ rs`,
  `flink := just _`, `fpc := j`, on the `c-thunk`.
* `c-thunk bb` = `do-thunk bb`: `clear-frame` of the callee region, `grow-frame bb` (shift, set
  `frame-slots`, no push), `flink := nothing`, `pc + 1`. The state is then exactly
  `entry-flat (suc j) s′ (grow-frame bb (enter-call pre)) cl (ret-pc ∷ rs)`, the body's entry at `n = 0`.
* The body's proof gives its run; at its end the pc is on `c-ret bb`; `do-ret` pops `ret-pc`,
  `fret := rs`, and `leave-frame` restores `pre`'s frame (D337, D338). `next-slot ≡ 0` is `pre`'s,
  unchanged (D339).
* Still to do: memory and frontier preservation over the caller's `pre` (caller slots become
  `stack-ancestor`s; `clear-frame` touches only the callee region, `SMCore.clear-frame-just`), events
  through the two control steps, progress (+2 control steps).
* Input: `ValidAtWF` depends on the allocator only through `BeforeFrontier`, so
  `validityWF-with-bf-transfer` + `validityWF-mem-preserved` move the caller's input to the callee, given
  `BeforeFrontier pre → BeforeFrontier callee`. Heap locations map as they are; with `next-slot ≡ 0` the
  caller has no `stack-before` locations; stack locations are `stack-ancestor`s and map by
  `Allocation.parent-before-child`, whose premise `callee-frame ≺ current-frame pre` is plan 0.124's
  `shift-≺`. (Under S1 the same transport is needed for `RelV`, with the same premise.)
