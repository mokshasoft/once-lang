# Plan 0.146 — Memory by a linear core: every block is freed because the core is linear

## Summary

Compiled Once programs never give memory back today, so a program that runs forever (a server)
eventually runs out. Plan 0.123 made running out an observable end and began proving, step by step
on the existing machine, where each value's memory lives. That path was closing in on what a
LINEAR core gives by construction: if every value is used exactly once, except where the program
explicitly copies or drops it, then where memory is freed is decided by the program's structure, and
"nothing leaks" is a theorem about the core rather than a pass proved clause by clause. This plan
compiles through such a core. It is attempted before the DirectedHoTT (DT) work.

**Gate: the ana server tests pass** ("a server never ends" in `compiler/test`: a server that emits
each round, and a silent server, on x86-64, x86-32 and riscv64). They fail today, because each round
allocates and nothing is freed.

## 1. Why

GOAL.md's memory hypothesis: a verified compiler for long-running programs must reclaim memory, and
must do it without run-time ownership information (no counts, flags or tags: plan 0.123 D6). Plan
0.123 tried to get there on the machine model directly: footprints (D400, L1/L2), then a footprint
frame per clause (L3, D401), destination passing (β3–β6), then frees (γ/R6). L3 turned out to be the
per-clause proof of what linearity gives structurally: a result uses its input's cells and fresh
ones, frees sit at the IR's discards, and destinations are linear resources. The OCP-0009 line
proves the factorization this needs: cartesian = linear SMC + a `dup`/`drop` comonoid
(`NbEPLinFox`), a meaning-preserving pass into the linear core (`NbEPLinPass`), "dup-free allocates
nothing" (`NbEPLinDyn.dyn-linear`, with ν), ν liveness (`NbEPLinLive`), and grades
(`NbEPLinQTT`). The user's call (2026-11-06): linearization will likely win; scope it, then build it.

- (decided, the user, 2026-11-08) **The invariant**: each allocation is matched by a deallocation of that
  block, except when the program exits. Master's `Once.Implementation.NoLeak` (`Run.LeakFree`) already

- (decided, the user, 2026-11-08) **Borrows, at least** (A2): read-only scopes cost nothing. And the two
  heaps of D402 stand: values that follow the stack pattern go to frames; only the rest to the cell heap.
- (decided, the user, 2026-10-28/29: D402) Ownership is static, two heaps, a result never shares a
  borrowed input; a linear core meets these by construction.
- (open, the user, 2026-11-08) **The space claim.** `⊑` (D374) is met by a compiler whose every run ends
  `exhausted` at once (one call of `once_exhausted`), and `NoLeak` does not exclude it either. The claim
  that closes it: a run ends `exhausted` only when what it keeps live does not fit the region. Its form
  (live data of the source or of the IR, the region the Host supplies, the per-round room) is decided here.
- (open, A2 decides) The shared environment of `Cata`/`Ana`/`Iter`, and of a closure applied more
  than once: a scoped read-only borrow (used many times for the scheme's duration, freed once after),
  or a `dup` per use (a copy per node: a regression from today's pointer read). QTT's ω grade says
  how often, not how it is shared.

## 4. Steps

### A. The shape, in `Spikes/LinCore/` (the user, 2026-11-08)

`Spikes/LinCore/NbEPLinCore.agda` starts as a verbatim copy of `origin/plan-ref`'s
`bootstrap/poc/OCP0009/NbEPLinCore.agda` (`bb22f30a8`; only the module name changed), so every change is a
diff against the POC. It imports nothing (not even the stdlib) and checks in seconds
(`Spikes/check.sh`). Each step extends that one core; the steps are the spikes of plan 0.123's scoping,
reordered so the gate example can be written early.

- **A1. Effects (spike 5).** `SigOp` with Once's three kinds: Pure (consumes its argument, gives a
  fresh result; a word operation allocates nothing), Emits (an event), Halts (the run ends). A server's
  round is `Act`, so the gate example needs this first.
- **A2. Borrows (spike 2, the deciding one).** A read-only environment beside the linear input, in two
  places (D402): the shared environment of `Cata`/`Ana`/`Iter` and of a closure applied many times
  (read at every layer, freed once when the scope ends), and `pair f g` where `f` keeps nothing of the
  value. Choice A: what a result keeps of a borrowed value is copied out. Its meaning, and the pass from
  the IR's parameterized schemes into it; or the evidence that it cannot be had, and the cost of `dup`
  per use.
- **A3. Events over two heaps.** The cost semantics becomes a trace of alloc/free events with sizes:
  frame push/pop for values whose type fixes their size, cell alloc/free per node size for μ/ν
  structures and closures that outlive their frame (D402, D384). Not counts: `NoLeak` and the space
  claim are statements about this trace, and in-place reuse (A8) rewrites it.
- **A4. `Iter` and the flat layout (spike 3).** `Iter` with a linear state (built, consumed, rebuilt).
  A cell-size model of the flat layout, so that `fst`/`snd` of a flat block (free the rest, or copy out)
  is a question the POC can answer.
- **A5. ν observation (spike 4).** `Out`/`in-ν`, `Ana`'s environment owned by the ν it builds (an
  unfold runs when the ν is observed, so the borrow is not lexical), against `NbEPLinLive`.
- **A6. The gate examples in the core**: the server of `loop-forever-emit` (an `Int` state), and a
  server whose state is heap-shaped and rebuilt each round (a list).
- **A7. The invariants, proved in the POC.** `NoLeak` in the form of master's `Once.Implementation`
  (`Run.LeakFree`: every free hits a live block; every live block is freed later unless the run stops
  other than by returning), and the per-step form "the blocks allocated and not yet freed are exactly the
  cells of the live values", which implies it, is the space claim, and needs no "eventually" for a run
  that never ends.
- **A8. In-place reuse** as a local rewrite of the trace (`free b ; alloc n` → reuse `b` when the sizes
  match), shown to keep A7. Not built into the compiler here; the POC shows the core keeps it a local
  step (D402: "in-place update stays possible").

When A1–A7 settle, the core, its events and its theorems are written up as a D-entry for the user's
review before B starts.

### B. The migration, into the compiler

1. **The compilation**: the IR, through the linear core, to the existing machine; frees at the core's
   `drop`s; destinations as linear resources (what β3–β6 were for); values whose type fixes their size in
   frames (D379/D380).
2. **The space claim**, stated beside `NoLeak` in `Once.Implementation` (and owed until proved): a run
   ends `exhausted` only when its live data does not fit the region, over the core's live values.
3. **The proof**: `NoLeak` (the apex's second claim) from the core's linearity; the three invariants of
   D400 (every allocation freed, no read of an unwritten cell, no dead store of the compiler's own beyond
   the IR's discards: plan 0.123's R7).
4. **The allocator modules** (`backstop.islands`, plan 0.64 Group AL) and `--alloc` (plan 0.86 F): wired
   for the cell heap the core needs, or deleted.

**The boundary** (`ev-<arch>`/`ret-call` by `Spec.ABI`, ledger row 4; plan 0.123's R5) is plan 0.138's.
Its S4 (the Interpretations' code, with the emitters' marshalling at `call-sym` and `ev-<arch>`, D382/D383)
can run beside this plan if ownership at a call stays as it is (the caller keeps its argument; the answer
is fresh) until this plan decides it. Its S3 (the value relation's concrete cases by `Spec.ABI`) goes with
this plan's destinations (B1): plan 0.138 §5 ties it to plan 0.123's D7, which is here now.

**The gate (an observation, for the user to decide).** Both gate servers keep a single `Int` across
rounds; each round's heap values (a pair, an `inr`) are dead by the round's end. Frames alone (D379/D380)
would pass them without freeing anything. A server whose state is heap-shaped and rebuilt each round
(A6's second example, as a `compiler/test` program) would make the gate test reclamation; proposed, not
added.

## 5. Done when

1. The ana server tests pass on all three arches (the gate).
2. `NoLeak` holds postulate-free: every allocation of every run of every compiled program is freed
   exactly once. (This is not a space claim: a program that keeps everything live meets it and still
   runs out.)
3. The space claim is stated: a run ends `exhausted` only when what it keeps live does not fit the
   region (a bound in terms of the source's live data). It is what `⊑` (D374) needs beside it, since `⊑`
   alone is met by a run that runs out at once. Proved if the linear core makes live data a statement;
   otherwise stated and owed, as `NoLeak` is today.
4. The emitted code carries no ownership information, and nothing in it stops a later in-place update
   of linear values.
5. No regression: `cabal test`, the exit tests on three arches, `make merge-gate`.
6. The emitted cost is re-measured (`tests/codegen-measure.sh compare`) against plan 0.123's merge. That
   merge made every program dearer, with no stack residency yet: flat values copied out of heap boxes,
   room checks. Totals over 112 programs: instrs 40380 → 60904, heap-cells 4932 → 8344, .text x86_64
   345 → 474 KB, x86_32 137 → 251 KB, riscv64 416 → 528 KB. The heap cells come back down, and the
   measurement names every program still above its pre-0.123 cost.
