# Plan 0.114 — The Spec stands on its own

## Why

Where the Spec calls a compiler function, a bug in that function moves BOTH sides of the
correspondence together, and no proof can see it ("self-validating definitions"). The theorem is
not empty — accepted programs exist and soundness ties them to the Spec — but the Spec is weaker
than it reads exactly at those points, and completeness ("every Spec-typed program is accepted")
becomes partly a tautology there.

## The four borrowings (2026-10-09, branch plan-0.91-program-facts)

1. **Monomorphic definitions** — `Spec/Module.agda:100` `mono` takes the definition's type from
   `C.resolveFunType … ≡ inj₂ ty` (incl. inferring a type for a signature-less definition);
   `ModuleTyped` still ranges over `Parser.extractFunctions (extractAliases m)` (the module's header
   names this defect; plan 0.59 owned it).
   Target: with a signature, a `⊢ᶜ` derivation at it; without one, any `ty` with an `⊢ᵢ`
   derivation — the Spec's own judgment, no resolver.
2. **Module → program translation** — `Spec/Core/Translate.agda:43–45,103–165` builds on
   `Compile.FunCtx`/`buildPolyCtx`, `Parser.FunInfo`, `Classify.lookupImport`, and picks "the first
   `main`, exactly as the compiler's `findMain`" (:15,185).
   Target: state `ImpSig`/`TeleSig` over `Spec.Module`'s own `Scope`/`ModTele`; `main` by its
   unique name (D249).
3. **The meaning's laws** — `Adequacy/Compile.agda:515`: `⟦_⟧ˢ` becomes a `Behavior` via
   `behavior-by (⟦ moduleToProgram … ⟧IR …) (core-run …) (ir-core …)`, i.e. through the compiler IR
   and `moduleToIR-complete`. (`≈` compares `at`, the core run, so correctness is not weakened —
   the trust architecture is inverted.)
   Target: the three `Behavior` laws from `runProgram` directly (`take n ∘ eventsT`;
   `take-pf`/`projTrace-pf` in `TraceMonad` already give them).
4. **`t-var-own`'s negative premise** — `TypeCheck/Judgment.agda:164` requires
   `lookupImport sig x ≡ nothing` only to stay disjoint from `t-var-resolved`.
   Target: `t-var-resolved` ranges over FFI-tagged canonical names, so Σ (generators) and Γ
   (definitions) are disjoint by construction (D274's own argument).

## Found in the per-edit Spec walk-through (2026-10-10)

5. **A fifth borrowing: `sigOpRefᵛ`** — `Denotation/GradedOps` builds the meaning of an effectful
   FFI operation through `Arith.SigOp.Builders.arrow-info` and `DenotTrace.sigOpT` (compiler side).
   Target: state it from `Spec.Contract` (`contractOf`, `Impl`) alone.
6. **Surface `case` charges `Ψ₁ + Ψ₂`; the core charges the join** — `t-case-copair-check` and
   `d-case` add the arms' usages, while the core `⊢case`
   (`Spec/Core/Typing.agda:106`) types both arms in one context (the additive `&`: only one arm
   runs). Sound, but stricter than the Spec's own core: a linear variable used in both arms is
   rejected. Target: the surface rule takes both arms at one `Ψ` (with `⊢sub-use`), as the core
   does; elaboration becomes the identity on usage. Relaxes the language — a decision entry.
7. **`d-lam`'s premise `(q' ≤q Many) ≡ true` is vacuous** — always true; delete it.

## 8. The import closure: no compiler module (measured 2026-10-11, master c4ab694a5)

The seven items above are the semantic borrowings. This one is the goal that shows they are
gone: **`Once.Spec`'s full import closure contains no compiler module.** Today it is 187
modules and reaches `Once.Compile`. The edges that leave the public closure into compiler code:

| Closure module | Imports | Item |
|---|---|---|
| `Spec.Module` | `Once.Compile` (as `C`), `Once.Parser` | 1 |
| `Spec.Core.Translate` | `Once.Compile`, `Once.Parser`, `TypeCheck.Classify` | 2 |
| `Denotation.GradedOps` | `Denotation.DenotTrace` (→ `Once.IR`), `Arith.SigOp.Builders` | 5 |
| `Spec.Core.Meaning` | `Arith.SigOp.Builders` (the `*-info` of `+`, `<`, …), `Denotation.PhaseV` | new |
| `TypeCheck.Judgment`, `Spec.Metatheory`, `Spec.Module` | `TypeCheck.Classify` | 4 |
| `Denotation.GradedDomain`, `GradedOps` | `Semantics.Machine` (the value domain, under a machine name) | rename (0.60) |
| `Spec.Grammar.*`, `Spec.Lexing`, `Spec.Parsing`, `Spec.Program`, `Spec.Resolution` | `Parser.*` relation and token modules | namespace only |

`Builders` itself only packages the primitive meanings (`Arith.Prim`, `SigOp.Info`). The fix is
to state the core's primitive meanings from `Arith.Prim`/`Spec.Contract` and leave `SigOpInfo`
to the compiler. The last two rows are naming: those modules are meaning or relation
definitions under an implementation namespace. Moving them is part of plan 0.60 and is not a
trust issue.

**Gate.** When items 1, 2 and 5 land, extend `metatheory-gate.sh` (or add a
`spec-closure-gate`) so that it fails if the full import closure of `Once.Spec` contains
`Once.Compile`, `Once.Parser`, `Once.IR`, `Once.CCC.*` or `Once.Adequacy.*` except
`Once.Adequacy` (= `Spec.Correct`). A ratchet with the measured list lets this land item by
item. Measure with `python3 formal/scripts/spec-import-closure.py`: it prints the closure size,
the import chain to each compiler target, and the edges leaving the public closure.

## Steps

Top-down, one borrowing at a time, Spec first and follow the red; each with a decision entry and
the merge-gate checks (Spec closure proof-free, apex + backstop green). 3 is small, 4 small–medium,
2 medium, 1 is the large one (it changes what "well-typed module" means; coordinate with 0.59's
oracle work).
