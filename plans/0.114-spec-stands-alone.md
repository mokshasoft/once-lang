# Plan 0.114 — The Spec stands on its own

## Goal

`Once.Spec` is the language definition and nothing else:

* **its import tree is the Spec**: the full import closure of `Once.Spec` is `Once.Spec.*` plus
  the standard library, so a reviewer reads exactly that set and no compiler change can move it;
* **no wholesale re-exports**: every `public` in the Spec names what it exports (`using`), and
  nothing re-exports an implementation module, so the surface is a list someone chose;
* **proof-free all the way down**: not just the public closure (D140) but the import closure
  has no lemma that the definitions do not need in order to type-check;
* **the implementation imports the Spec**, never the reverse;
* **tidy**: everything else depends on the Spec, so it is written to be read. Each module's
  header says what it defines, not how it got there (plan numbers, D-entries and history go in
  the decision log). One concept per module, a consistent layout, no dead or duplicated
  definitions, names that read as the language's names (plan 0.112's renames apply here first).

## Why

Where the Spec calls a compiler function, a bug in that function moves BOTH sides of the
correspondence together, and no proof can see it ("self-validating definitions"). The theorem is
not empty — accepted programs exist and soundness ties them to the Spec — but the Spec is weaker
than it reads exactly at those points, and completeness ("every Spec-typed program is accepted")
becomes partly a tautology there.

## The borrowings: where the Spec calls compiler code

### Found 2026-10-09 (branch plan-0.91-program-facts)

1. **Monomorphic definitions** — `Spec/Module.agda:100` `mono` takes the definition's type from
   `C.resolveFunType … ≡ inj₂ ty` (incl. inferring a type for a signature-less definition);
   `ModuleTyped` still ranges over `Parser.extractFunctions (extractAliases m)` (the module's header
   names this defect; plan 0.59 owned it).
   Target: with a signature, a `⊢ᶜ` derivation at it; without one, any `ty` with an `⊢ᵢ`
   derivation — the Spec's own judgment, no resolver.
2. **Module → program translation** — `Spec/Core/Translate.agda:43–45,103–165` builds on
   `Compile.FunCtx`/`buildPolyCtx`, `Parser.FunInfo`, `Classify.lookupImport`, and picks "the first
   `main`, exactly as the compiler's `findMain`" (:15,185).
   Target: state `ImpSig`/`TeleSig` over `Spec.Module`'s own `Scope`/`ModTele`; `main` by its
   unique name (D249).
3. **The meaning's laws** — `Adequacy/Compile.agda:515`: `⟦_⟧ˢ` becomes a `Behavior` via
   `behavior-by (⟦ moduleToProgram … ⟧IR …) (core-run …) (ir-core …)`, i.e. through the compiler IR
   and `moduleToIR-complete`. (`≈` compares `at`, the core run, so correctness is not weakened —
   the trust architecture is inverted.)
   Target: the three `Behavior` laws from `runProgram` directly (`take n ∘ eventsT`;
   `take-pf`/`projTrace-pf` in `TraceMonad` already give them).
4. **`t-var-own`'s negative premise** — `TypeCheck/Judgment.agda:164` requires
   `lookupImport sig x ≡ nothing` only to stay disjoint from `t-var-resolved`.
   Target: `t-var-resolved` ranges over FFI-tagged canonical names, so Σ (generators) and Γ
   (definitions) are disjoint by construction (D274's own argument).

### Found in the per-edit Spec walk-through (2026-10-10)

5. **A fifth borrowing: `sigOpRefᵛ`** — `Denotation/GradedOps` builds the meaning of an effectful
   FFI operation through `Arith.SigOp.Builders.arrow-info` and `DenotTrace.sigOpT` (compiler side).
   Target: state it from `Spec.Contract` (`contractOf`, `Impl`) alone.
6. **Surface `case` charges `Ψ₁ + Ψ₂`; the core charges the join** — `t-case-copair-check` and
   `d-case` add the arms' usages, while the core `⊢case`
   (`Spec/Core/Typing.agda:106`) types both arms in one context (the additive `&`: only one arm
   runs). Sound, but stricter than the Spec's own core: a linear variable used in both arms is
   rejected. Target: the surface rule takes both arms at one `Ψ` (with `⊢sub-use`), as the core
   does; elaboration becomes the identity on usage. Relaxes the language — a decision entry.
7. **`d-lam`'s premise `(q' ≤q Many) ≡ true` is vacuous** — always true; delete it.

### Found measuring the import tree (2026-10-11)

8. **The core's primitive meanings come from the arith lowering.** `Spec/Core/Meaning.agda:50`
   imports `add-info`, `lt-info`, … from `Arith.SigOp.Builders`, and `restrictᵛ`/`bindᵛ` from
   `Denotation.PhaseV`. `Builders` only packages `Arith.Prim` and `SigOp.Info`.
   Target: state the primitive meanings from `Arith.Prim`-level definitions moved under the Spec;
   `SigOpInfo` stays compiler-side.
9. **The front-end relations are phrased with the implementation's helpers.** `Spec.Lexing`
   imports `Parser.Lexer` wholesale (its classifiers `headK`, `dashClass`, collectors
   `collectDigitsB`; its own header admits it). `Spec.Parsing` uses `skipNewlines`, `parseDeclB`
   (as a negative premise) and `allTrailing`, and `Spec.Grammar.Decl` uses `eqHead`, `colDrop1`,
   `colonHead`. A parser bug moves the relation with it.
   Target: the lexical and declaration grammar stated over characters and tokens with
   Spec-side definitions; the bridges (`LexerBridge`, `FrontEndBridge`) do the work.
10. **A proof module in the import closure.** `Spec/Core/PolyTyping.agda:23` imports
   `Metatheory.SubLaws` for `<:-refl` (in `<:ₚ-⟪⟫`). Several `Spec/Core/*` modules state and
   prove lemmas (`Abstract`, `AbsTy`, `DerivedTyping`, `Schema`, `Rename`, `Subst`). Target:
   a lemma stays only if a DEFINITION needs it to type-check; the rest moves under
   `Once/Metatheory` or to the bridges.

## Phases

Top-down: the gate goes in first, as a ratchet on the measured closure, and every later phase
lowers it. Each phase is a branch with the merge gates; a phase that changes what is typable or
what a program means takes a decision entry.

**A — The gate (DONE 2026-10-11, branch merge-md-rules).** `make spec-gate`
(`spec-import-closure.py --gate`, in `make merge-gate`): computes the full import closure
of `Once.Spec` and fails on any module outside `Once.Spec.*` and the stdlib, any re-export of an implementation
module, and any `public` without `using`, unless listed in `spec-gate.baseline`; the baseline only
shrinks. Baseline = today's 151 non-Spec modules, 23 implementation re-exports and 9
wholesale ones; a line that no longer applies fails the gate until deleted.

**B — Cut the compiler edge (items 1, 2, then 5, 8).** `Spec.Module`'s `ModuleTyped`/`mono` and
`Spec.Core.Translate` stated over the Spec's own scope and telescope. This alone should remove
CCC, Arith, Memory, Allocator, Optimize, Compile and most of Parser/Grammar from the closure. Then
`sigOpRefᵛ` (5) and the primitive meanings (8) from `Spec.Contract`/`Arith.Prim`, which removes IR.
Large (item 1 is the large one; coordinate with 0.59).

**C — Name the surface.** Replace each wholesale re-export with a `using` list of the language
definition: grammar constructors, judgment rules, the meaning. Deciders, `show*`, `*EqBool`,
`fits-in-reg?` and the like drop out of the Spec's surface. Each importer that relied on getting
them through `Once.Spec` imports them from their module (`reexport-remove.py` verifies). Medium,
mechanical.

**D — Move the definitions under `Once/Spec`, reverse the imports.** The definitions the Spec
consists of move into `Once/Spec/**`, and the implementation modules import them:
* `Once.Type` splits: the type grammar and its order (`Type`, `Quantity`, `Purity`, `ArrowKind`,
  `_<:_`) → `Spec.Type`; deciders and show functions stay in `Once.Type` (absorbs plan 0.85);
* `TypeCheck.Raw` → `Spec.Syntax`, `TypeCheck.Judgment` → `Spec.Typing` (with `Classify`'s
  premises, item 4, and `Surface.Context`'s context type);
* `Denotation.{Admissible,Trace,Behavior,TraceMonad,GradedDomain,GradedOps}` → `Spec/Meaning/*`,
  and the value domain (`Semantics.Value`, the part of `Semantics.Machine` the meaning uses) →
  `Spec/Value` (overlaps plan 0.60);
* the AST and token types the grammar relations are over (`Parser.Module.Core`'s `Decl`/`Module`,
  `Parser.Token`) → `Spec/Syntax`;
* `Adequacy`'s `CorrectCompiler` → `Spec.Correct`.
No shells are left behind: an old module either keeps implementation content or is deleted, and
importers are rewritten with a tree-wide exact-token script (memory: bulk scripts, no tidy). Large
in churn (`Once.Type` has 232 importers), small in risk. Re-extraction needed.

**E — The front end (item 9).** Lexing and the declaration grammar restated without parser
helpers. Medium; the bridges' proofs carry the cost.

**F — Proof-free import closure (item 10), and the remaining borrowings (3, 4, 6, 7).**
Then the baseline is empty: the gate's allowlist is `Once.Spec.*` and the stdlib.

**G — Tidy.** A read-through of every `Once/Spec/**` module, as the language's reference
document: headers rewritten to say what is defined, history moved to the decision log, one
concept per module, a uniform layout (the grammar, then the judgment, then the meaning),
consistent naming. Nothing semantic changes, so the merge analysis can be checked by the gate
plus an empty diff of what the definitions say.

**H — Metatheory joins.** Coherence and the meaning-domain laws (below) move into
`Spec.Metatheory`, as the gate now allows.

## Order

A first (it is the measuring stick). Then the cheap items 7, 3, 4 to warm up on the judgment.
Then B (it removes most of the tree), C, D, E, F, G, H. C before D: naming the surface first shows
exactly what D has to move.
