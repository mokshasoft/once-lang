# Plan 0.150 — Every number type has the same operations, by construction

## Summary

A program can write `-1.5` and `0.0 - x` for a floating-point `x`, but not `-x`. Negation of `Int` and of
`Float` are defined by different rules, and they drifted apart: one negates anything, the other only a
written number. Comparison drifted the same way: `<` works on `Int` only. This plan makes the language
define its operations once, for "a number type", with one table per type that the checker forces to be
complete. A number type that lacked negation or comparison would then not compile. Negation becomes an
ordinary operation for both types, and `-1.5` is negation applied to `1.5`, as `-5` already is. This also
fixes `-0.0`, which today means `+0.0`.

## 1. Why

**The drift.** The Spec's typing (`formal/Once/Spec/Surface/Typing.agda`) has one rule per (operator,
type) pair, each written by hand:

| Operator | Int | Float |
|---|---|---|
| `-e` | `s-neg`: any operand, `prim p-neg` | `s-neg-float`: a literal only, folded (D124) |
| `+ - * /` | `s-arith` over `IntArith` | `s-arith-float` over `FloatArith`, plus `-il`/`-ir` for an `Int` operand (D125) |
| `%` | `s-arith` (`ia-mod`) | none (D128: no float meaning) |
| `< <= > >= == /=` | `s-compare` (`Int * Int` only) | **none** |

D124 limited float negation to literals because float arithmetic had no lowering. Float arithmetic got one
(D128) and its rules, but negation and comparison were not revisited, because nothing ties them to the
arithmetic. Seven rules carry the numeric operators, and nothing makes them cover the same types.

**The literal fold is wrong at zero.** `s-neg-float` folds `-i.f` to the literal `negate (decimalOf i f
l)`, a `Decimal` whose significand is `ℤ` (`Spec/Float/Decimal.agda:61`). `ℤ` has no `-0`, so `-0.0`
folds to `0 /10^ 1`, and `round` gives `+0.0` (`Decimal.agda:255`, the sign bit is `signBit (sig d)`).
IEEE 754 says `-0.0` is negative zero. Negation as an operation does not have this problem: the Spec's
`fneg` (`Spec/Float/Arith.agda:372`, a sign-bit flip, "not a decode/round round-trip … would collapse
`−0` to `+0`") is right at zero and on NaN. It is defined and has no caller.

**Int is already the principled shape.** `-5` is `prim p-neg (lit 5)` in the Spec. Only the target-fit
check reads it as the literal `-5` (`negLits`, `Spec/Source.agda:102`, so `-9223372036854775808` fits). The
elaborator's `checkElabV-neg-int-aux` builds exactly `neg (int n)`.

## 3. Design

**One index for "a number type", and one total table per operator.**

```agda
data Num {m} : Ty m → Set where
  num-int   : Num Int
  num-float : Num Float

negOf : Num A → Prim                      -- p-neg, p-fneg
cmpOf : Num A → CmpOp → Prim              -- p-lt … at Int, p-flt … at Float
arithOf : Num A → ArithOp → Prim          -- + - * /
data Rem : Num A → Prim → Set             -- % : num-int only (D128)
```

They are functions, not relations: Agda's coverage checker refuses a `negOf` without a `num-float`
clause. A third number type gets every operator, or the Spec does not compile. That is the guarantee that
the operators cannot drift apart again. Where an operator really is partial (`%`), the exception is a
named table with a comment, not a missing rule.

**One rule per operator form**, over `Num`:

```agda
s-neg     : (n : Num A) → L ⊢ e ⇒ A ↝ t → L ⊢ RNeg e ⇒ A ↝ prim (negOf n) t
s-arith   : (n : Num C) → <operands at C> → L ⊢ RBinOp op e₁ e₂ ⇒ C ↝ prim (arithOf n op) (pair t₁ t₂)
s-compare : (n : Num C) → <operands at C> → L ⊢ RBinOp op e₁ e₂ ⇒ Unit + Unit ↝ prim (cmpOf n op) (…)
```

`s-neg-float`, `s-arith-float`, `-il`, `-ir` go. The seven numeric rules become three (plus `%`).

**Literals are unsigned, negation is an operation.** `-1.5` is `prim p-fneg (lit 1.5)`, as `-5` is
`prim p-neg (lit 5)`. Folding a negated literal into one constant is an optimisation, outside the Spec,
justified by a law stated once for every `Num`:

```agda
neg-lit : (n : Num A) (l : Lit n) → ⟦ prim (negOf n) (lit l) ⟧ ≡ ⟦ lit (negLit n l) ⟧
```

in `Spec.Metatheory`, proved under `Once/Metatheory`, with its `LawsApply` instance (MERGE.md). For
`Float` it holds only where the literal can carry the result, so the law states the side condition (`l ≠ 0`,
or a literal that carries its sign; D3). The fit check (`negLits`) is unchanged: it is about which written
integers fit the target, and an `Int` literal must fit while a `Float` one rounds (D116). That difference is
in the types, not in the operators.

## 4. Decisions

- **D1, the shape above** (a `Num` index, total operator functions, three rules, literals unsigned and the
  fold outside the Spec). The alternative is to keep a rule per (operator, type) and add the missing ones
  (`s-neg` at Float, float comparison). That is smaller today, but it leaves drift possible. Recommended:
  D1 as above. **Open, the user's: a Spec change.**
- **D2, widening (D125) in the new rules.** The operands of `s-arith`/`s-compare` at `C`: each synthesises
  `A` with `Num A`, and widens to `C` by a two-case relation `Widen A C t t′` (`refl`; `Int → Float` by
  `p-i2f`), with `C` the least such type (so `1 + 2` is `Int`, not `Float`). This replaces `-il`/`-ir` and
  gives `1 < 2.5` for free. Negation does not widen: its operand's own type decides, so `-x` at `x : Int`
  is `Int` negation, then any widening the context asks for. Recommended: as stated. Open.
- **D3, the `-0.0` literal.** With negation as an operation, `-0.0` is `fneg (+0.0)` = `-0.0`, correct. The
  only question is the optimiser's fold. (a) Do not fold a negated float zero. (b) Give `lit-float` a sign
  so `-0.0` is a literal. Recommended: (a), the smaller change. Record the bug in the decision entry
  (today's `-0.0` is `+0.0`). Open.
- **D4, comparison at Float in this plan.** It is the same drift, and D1's `cmpOf` would not compile
  without it. Needs float comparison semantics (IEEE: NaN is unordered, so `NaN == NaN` is false and `/=`
  is true) and its lowering. (a) In this plan. (b) `cmpOf` for `num-float` deferred with an explicit
  `Cmp : Num A → …` table that lacks it, like `%`. Recommended: (a). A table that lacks it is the drift
  this plan removes. Open.

## 5. Steps

1. Decision entry (D1–D4), superseding D124. The Spec patch: `Num`, `negOf`/`arithOf`/`cmpOf`/`Rem`, `p-fneg`
   and the float comparisons in `Core/Syntax` (`primDom`/`primCod`) and `Core/Meaning` (`fneg`; the float
   comparison over `decode`), `Widen`, the three rules, `s-neg-float` and the float/`-il`/`-ir` rules
   deleted. User approval (`make spec-approve`). Gate: `make spec-gate`, the Spec modules.
2. The law `neg-lit` (statement in `Spec.Metatheory`, proof under `Once/Metatheory`, `LawsApply`).
3. Implementation primitives for `p-fneg` and the float comparisons: `Arith.Prim`, `SigOp.Words`, the
   builders, the recogniser, and the other modules `p-fsub` runs through. Gate: `make backstop`.
4. Elaborator: `RNeg`, `RBinOp` dispatch over `Num` (one path per operator, not per type). Soundness and
   completeness cases follow the three rules. Gate: `ElaborateSound`, `Completeness`, `make certified`.
5. The optimiser's negated-literal fold (D3), justified by `neg-lit`.
6. Backends: `fneg` (x86_64/x86_32 SSE sign-mask `xorps`/`xorpd`, riscv64 `fsgnjn`), float compares
   (`ucomis*`, `flt`/`fle`/`feq`), on all three arches, bit for bit against the Spec.
7. Tests: `-x`, `-0.0` (observed as bits), `-(-x)`, NaN sign; `1 < 2.5`, NaN comparisons; the D407
   rejection test for `-x` at `Unit`; existing `-5`, `-9223372036854775808` stay green.
8. Extraction, `cabal test`, exit tests ×3, `make merge-gate`, `codegen-measure.sh` (the `-1.5`
   literals: same code after the fold, or a measured difference), AST dumps.

## 6. Done when

The Spec has one rule per numeric operator form over `Num`, with total operator tables; `-x` and the
comparisons work for every `Float` on all three arches; `-0.0` is negative zero; `neg-lit` is proved and
applied; D124 is superseded.
