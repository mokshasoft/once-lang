# Plan 0.150 — `-x` negates any `Float`, not only a literal

## Summary

A program can write `-1.5` and `0.0 - x` for a floating-point `x`, but not `-x`: that is refused with
"expected Int but got Float". The restriction dates from when floats had no arithmetic at all. Floats now
have addition, subtraction, multiplication and division, so negation is the one operation left out. This
plan adds it, as a real negation (flipping the sign), because `0.0 - x` is not the same thing for zero and
for NaN.

## 1. Why

D124 pinned float negation to a literal on purpose: "a rule with no lowering is a promise the backend then
has to break", and float arithmetic had no lowering then. Since D128 and plan 0.75 F4, `+ - * /` at `Float`
type, lower and are proved (`FloatArith`, `p-fadd` … `p-fdiv`). D124's reason is gone, and what is left is
a non-uniformity: `0.0 - x` is accepted and `-x` is not. It is also not a fair rewrite. IEEE 754 negation
is exact and defined on every pattern: `-(+0.0)` is `-0.0` where `0.0 - (+0.0)` is `+0.0`, and negating a
NaN flips its sign without canonicalising it.

## 2. Where we are

Checked 2026-11-12 on `0.139-squashed` with `once check`:

| Program | Result |
|---|---|
| `g : Float; g = -1.5` | accepted (`s-neg-float`, literal only) |
| `f : Float -> Float; f x = -x` | rejected: "Type mismatch: expected Int but got Float" (the premise of `s-neg`) |
| `h : Float -> Float; h x = 0.0 - x` | accepted (`p-fsub`) |

- Spec typing, `formal/Once/Spec/Surface/Typing.agda:153–154`: `s-neg` (operand `⇒ Int`, `prim p-neg`) and
  `s-neg-float` (only `RNeg (RFloat i f l)`, folded to a literal with `negate ∘ decimalOf`).
- Core primitives, `formal/Once/Spec/Core/Syntax.agda:71–80`: `p-neg : Int → Int`, `p-fadd p-fsub p-fmul
  p-fdiv : Float * Float → Float`. There is no `p-fneg`. Meaning, `Spec/Core/Meaning.agda:176–184`.
- **The semantics already exists**: `fneg : FloatFormat → ℕ → ℕ` in `formal/Once/Spec/Float/Arith.agda:372`,
  a sign-bit flip, with the comment explaining why it is not a decode/round round-trip. It has no caller.
- The implementation side of a primitive: `Once.Arith.Prim` (`ArithPrim`, `primSem`), `Once.SigOp.Words`
  (`semM-of-word`), `Once.Arith.SigOp.Builders` (`neg-info` "arith.neg.int", `fsub-info`
  "arith.sub.float"), `Once.Arith.Machine.Recognise`. `p-fsub` appears in 16 Agda modules. They are the
  list of places a new float primitive touches: Adequacy, Metatheory's Coherence, TermModel and
  Parametricity, and `IRObsCorrect.Compare`.

## 3. Decisions

- **D1, the rule.** (a) Generalise: a new rule `s-neg-flt : L ⊢ e ⇒ Float ↝ t → L ⊢ RNeg e ⇒ Float ↝ prim
  p-fneg t`, and keep `s-neg-float` for literals (so `-1.5` stays one folded literal). Then a literal's
  negation has two derivations, and the elaborator must take the literal one; the Spec's determinism
  (if it is stated) has to allow it, or (b). (b) One rule for every `Float` operand, with the literal fold
  done by the optimiser instead of the Spec. Recommended: (a) with `s-neg-float` kept: it matches how
  D124 reads `-3.14` (one literal), and the overlap is the same as `s-neg`'s with Int literals (check how
  `negLits` handles that). Open, the user's, since it changes the Spec.
- **D2, how `Int` widening interacts.** D125 widens `Int` to `Float` implicitly. `-x` at a checked `Float`
  type with `x : Int`: negate as Int then widen, or widen then negate. They agree except at the Int
  minimum (`-minInt` wraps). Recommended: the synthesised operand type decides (`x : Int` ⇒ `s-neg`, then
  the widening). This is what bidirectional checking does already. Open.

## 4. Steps

1. Decision entry (D1, D2). Spec: `p-fneg` in `Core/Syntax` (`primDom`/`primCod`), its meaning
   `primᵛ p-fneg a = FA.fneg float-format a` in `Core/Meaning`, the rule in `Surface/Typing`. Spec patch
   approved by the user (`make spec-approve`). Gate: `make spec-gate`.
2. Implementation primitive: `ArithPrim`/`primSem` (`fneg-semM`), `semM-of-word`, a SigOp builder
   (`fneg-info`, "arith.neg.float"), the recogniser. Follow `p-fsub` through its 16 modules and fill each
   case. Gate: `make backstop`, `make certified`.
3. Elaborator: synthesise `RNeg e` at `Float` when `e` synthesises `Float` (literal first, D1). Soundness and
   completeness cases. Gate: `ElaborateSound`, `Completeness`.
4. Backends: lower `arith.neg.float` on x86_64 (SSE sign mask `xorps`/`xorpd`), x86_32 (the same, or x87
   `fchs`, whichever the float ABI uses), riscv64 (`fneg.s`/`fneg.d`, which is `fsgnjn`). Check against the
   Spec's `fneg` bit for bit.
5. Tests: accept `f x = -x` at `Float`; exit/trace tests on all three arches for `-x` at `+0.0` (gives
   `-0.0`, observed as the bit pattern), at a negative and a positive value, and for `-(-x)`. The D407
   rejection test for `-x` at `Unit` stays.
6. Extraction, `cabal test`, exit tests ×3, `make merge-gate`, AST dumps. `codegen-measure.sh` shows only
   programs with a float `-x` change (there are none today, since they are rejected).

## 5. Done when

`-x` type-checks and runs for every `Float` operand on all three arches, with `-0.0` and NaN signs as IEEE
says; the Spec's `fneg` has its caller; D124 is superseded by a decision entry that says so.
