# Plan 0.140 — Named data types and lawful structures, with no new mathematics

## Summary

Programmers expect to declare their own data types with named constructors (`data List a = Nil | Cons a
(List a)`) and to write code that works for any type with some structure, such as sorting anything that
can be compared. Haskell does the second with type classes. This plan collects what has been settled about
both for Once and what is still open. Named data types turn out to be only a nicer way of writing types
Once already has. Structures such as monoids and monads are ordinary values that must come with proofs of
their laws: for now the proofs are written outside the language, the way an Interpretation's contracts
are, and later in Once itself once it has dependent types. Everything that dependent types give for free
(GADTs, indexed families, nested types, proofs inside the language) waits for them.

## 1. Why

GOAL.md asks for two things that pull in different directions here. The programmer should find a surface
that "feels like Haskell or Agda", and today's surface has only anonymous sums and products, positional
`case`, and `Fix (Unit + A * X)` for lists. The mathematician should find a Spec that "looks principled",
which rules out Haskell's unlawful, globally searched type classes. The task is to give the programmer
named data types and generic code over structures without adding anything to the Spec's meaning that a
category theorist would not recognise.

## 2. Where we are (2026-11-03)

- **Data types are structural.** `Strata/Derived/Initial.once` declares `type Bool = Unit + Unit`,
  `type Maybe A = Unit + A`, `type Nat = Fix (Unit + X)`, `type List A = Fix (Unit + A * X)`. A `type` is
  an abbreviation; there are no constructor names, and `case`/`destruct` branches are positional
  (`docs/decisions/language.md` §11, D042).
- **Polymorphism is rank 1** with kinds `base` and `any` (D238). There are no higher kinds: nothing ranges
  over `Type → Type`.
- **A type's functor action exists on a branch**: `mapᶜ` (D369, branch `0.79-categorical-laws`, not yet
  merged), a type's action on effect-free arrows. Once merged, a "derived `fmap`" for every type is in
  the Spec.
- **Structures are explicit record values** (D307, for the Agda formalisation; plan 0.112). For Once the
  language, OCP-0010 R7 says "explicit argument passing; no instance search".
- **Principal types** (D007, D323) are argued from "no type classes" among other things (decision log,
  D007's rationale and the D323 context).
- **The meaning is a function of the judgment** (D310, D308): any implicit resolution would have to keep it.
- **Parametricity is being stated** (the parametricity plan, branch `0.141-parametricity`): its audit found nothing in the core inspects a type
  variable.
- **Polymorphic definitions are monomorphised.** "A schema is instantiated at its uses and never emitted"
  (plan 0.136 §1, measured 2026-10-31). Library exports are concrete types only (plan 0.137).
- **Concrete values become flat** (plan 0.138): `A * B` and `A + B` at concrete types are C-layout
  structs; closures and `μ`/`ν` values stay pointer cells.

## 3. Settled (the user, 2026-11-03)

1. **Named data types are surface sugar over `μ` of a polynomial functor.** `data List a = Nil | Cons a
   (List a)` names the functor `F X = 1 + a × X` and its initial algebra. Constructors are the components
   of `in : F(μF) → μF` (`Nil = in ∘ inl`, `Cons = in ∘ inr`), matching is `out` followed by `case`, and
   recursion is `cata`. Named record fields are named projections of a product. The core and the meaning
   do not change; the surface judgment gains rules that elaborate to `roll`, `case` and `fold`.
2. **GADTs are not a feature of their own.** They are indexed inductive families with an index at
   quantity 0, and they arrive with OCP-0009 (§5).
3. **No unlawful structures.** A structure (monoid, monad, …) comes with its laws. Until Once has
   dependent types, the laws are discharged **off-line in Agda** by the structure's author, by proof or by
   an explicit, named postulate, exactly as an Interpretation's SigOp contracts are (GOAL.md, "Three
   compile times", time 1). The compiler cannot check them at a program's compile time; it assumes them,
   and the assumption is a named hypothesis. With dependent types, the laws are proved in Once.
4. **`Once.Spec` is about meaning only.** How polymorphism is realised at run time (a type argument's
   layout passed or not, specialisation) changes no meaning. It belongs to the implementation Spec, beside
   `NoLeak` and plan 0.138's layout invariant. The only place it reaches the Spec is the boundary:
   `Spec.ABI`, if a polymorphic definition is ever exported.
5. **Type arguments are parametric in the meaning.** Once has no typecase; `∀` means the family of its
   instances (D238), natural by the parametricity plan (branch `0.141-parametricity`). Nothing here changes that before dependent types.
6. **Generic code should not cost code size per type**: the goal is one compiled body for a polymorphic
   definition (one `sort`, not one per element type), without raising run-time cost where it matters. The
   strategy is §4 F.

## 4. Open decisions

Each one with its options, what it implies, and a recommendation. None is decided.

### A. Nominal or structural data types

- **(A1) Structural.** `data Bool = True | False` is `Unit + Unit` with names for its injections; two
  declarations with the same shape are the same type.
  Implies: pure sugar, no new type former, no Spec meaning change. `Celsius` and `Fahrenheit` are
  interchangeable, and a second monoid on `Int` (sum and product) cannot be distinguished by type.
- **(A2) Nominal.** A declaration makes a new type `N` with an isomorphism `N ≅ μF` that only the
  declaring module can use (categorically: an abstract type, `∃N. N ≅ μF`).
  Implies: a new type former (a name) in the Spec's types, with its own meaning (the same set as `μF`) and
  a rule for where the iso is visible; `Same`, subtyping (`<:`) and principal types have to say how a
  name relates to its representation. It is what makes `newtype`-style wrappers mean something, which
  §4 D needs if two structures on one carrier must be told apart.
- **(A3) Structural `data`, plus a separate nominal `newtype`** later, when a use needs it.

Recommendation: A3 — start with A1 (no Spec meaning change) and add nominality only when a concrete use
needs it, likely together with D.

### B. The surface syntax of data types

- Constructor declarations, named fields, and matching by constructor name. How it sits beside `case`
  (the coproduct generator, positional) and `destruct` (D042): sugar over them, or replacing `destruct`.
- **Exhaustiveness**: a match on a `data` type must cover every constructor (totality, GOAL.md). Since
  matching elaborates to `case`, a missing branch is a type error, not a run-time failure.
- **Recursive declarations**: `data List a = … (List a)` mentions itself; it elaborates to `Fix` with the
  recursive position as `X`. This is self-reference at the type level only, which D241 (no self-reference
  of definitions) does not forbid, but the decision state should say so.
- **Mutual data types** (`Tree`/`Forest`): the initial algebra of a functor on `C × C`. Needs no
  dependent types, but needs either a new functor-code former or an encoding as one `μ` over a tagged sum.
  In this plan, or a later one?
- Whether `type` abbreviations stay beside `data` (they do no harm under A1).
- Positivity: a `data` declaration must be strictly positive (it is a polynomial functor); a
  non-positive one is rejected with a named reason (plan 0.139 diagnostics).

### C. How a structure is declared, and where its laws live, before dependent types

The settled shape (§3.3) leaves the mechanics open:

- **A theory** (Monoid, Ord, …) is a Once record type of operations. Its **laws** cannot be written in
  Once yet, so they are stated in Agda, against the Spec's meaning of the record's fields (as a SigOp's
  contract is stated against its signature).
- **A model** (the sum monoid on `Int`) is a Once value of that record type, plus an Agda proof (or a
  named postulate) that its meaning satisfies the theory's laws.
- **The link between the two** is the open part. Options: (C1) the model's canonical name (D328, plan
  0.50's CanonName) keyed to its Agda certificate, with a digest of the Once definition, so editing the
  definition invalidates the certificate; (C2) models are declared only in strata (like Interpretations),
  each with its Agda module; (C3) laws are not linked at all and only documented (rejected by §3.3).
- **Who uses the laws.** The trace correctness of a compiled program never depends on them unless the
  optimizer rewrites by them. So: (C-i) the optimizer never uses structure laws (they serve the
  programmer's reasoning only; no new hypothesis); or (C-ii) it may, and `correct` becomes conditional on
  "every model the program uses satisfies its laws", a new hypothesis that GOAL.md's list must then name
  (an open GOAL.md change, like the Interpretations' contracts).

Recommendation: C2 first (structures in strata, like Interpretations, one mechanism), C-i until a measured
optimization needs a law.

### D. Implicit resolution ("type classes") or explicit arguments

From least to most implicit:

- **(D1) Explicit only.** A structure is passed and named like any argument: `sort ordInt xs`. Today's
  rule (D307, R7). Nothing new to prove; the cost is plumbing.
- **(D2) Canonical models.** A model may be marked canonical only where its carrier or its theory is
  declared (no orphans); resolution looks at the type head only; at most one canonical model per theory
  and carrier. The elaborator fills the argument.
  Implies: revisiting R7; a surface rule stated as a property ("the unique canonical model"), not as a
  search (D316: no decider premises); a **coherence** metatheorem so D310 still holds; a decider proved
  sound and complete against the rule; principal types now carry constraints (qualified types), and D323's
  argument must be redone.
- **(D3) Modular implicits** (resolution by what is in scope). Scope-dependent meaning; conflicts with
  OCP-0010 R1.
- **(D4) Haskell classes.** Global search, overlap, defaulting. Conflicts with §3.3 and D310.

A useful distinction for deciding: **property-like structure** (unique when it exists: products,
coproducts, exponentials, initial algebras, a polynomial type's `map`) is already resolved implicitly in
Once, by the generators and `mapᶜ`, and needs no class. Only **genuine structure** (a choice: `+` or `*`
on `Int`, an ordering, a monad on a carrier) is at stake, and implicit resolution of a choice hides it.

Recommendation: D1 now; revisit D2 after there is real Once code using structures, to measure the
plumbing D2 would remove.

### E. Higher kinds

`Functor`, `Monad`, `Traversable` as theories need a carrier of kind `Type → Type`. Without higher kinds,
only theories over a carrier of kind `Type` (Eq, Ord, Monoid, Semiring) can be declared generically; a
monad can be written per carrier, not abstracted over.

- **(E1) Postpone to dependent types.** `Type → Type` is a function type there; nothing is built twice.
  Implies: no generic `Monad` theory until OCP-0009.
- **(E2) Applicative higher kinds now** (Haskell-style: type constructors as constants, kinds
  `Type → Type`, no type-level λ). Inference stays first-order and decidable.
  Implies: a kind system change in the Spec's types (D238), and a second design that dependent types
  later replace.
- **(E3) Higher kinds restricted to functor codes.** Variables range over strictly positive codes, so
  positivity and folds stay by construction.

Recommendation: E1, by the rule "what dependent types solve naturally waits for them"; note that `map`
for every polynomial type exists already (`mapᶜ`), so the gap before dependent types is the abstraction
over monads, not functor actions.

### F. How polymorphic code is compiled (implementation, not `Once.Spec`)

| Strategy | Code size | Run-time cost | Fit |
|---|---|---|---|
| (F1) Monomorphise (today) | one copy per instance | none | no polymorphic library exports; impossible for polymorphic recursion (§5) |
| (F2) Uniform boxing | one copy | every value behind a pointer, allocation | conflicts with plan 0.138's flat values and with no GC |
| (F3) Layout passing (Swift's value witness tables) | one copy | dynamic size arithmetic; a structure's operations are indirect calls | one body per definition |
| (F4) F3, plus specialisation as an optimization | one copy, plus hot copies | low | the end state |

Under F3, `sort : ∀a. Ord a → List a → List a` compiles once and receives `a`'s layout (size,
alignment, copy) and the `Ord` record. The dictionary is an ordinary record value (D307), so it needs no
new codegen; the layout argument is new.

Implies:
- The correspondence (plan 0.138 S3's value relation) must hold for every layout: one compiled body,
  proved once, for all instances. New proof work in the value relation.
- Specialisation is a type substitution plus inlining; its correctness rests on the Spec's
  type-substitution metatheorem, and it must not change the trace (an optimization, plan 0.129).
- A polymorphic export (beyond plan 0.137's "concrete types only") would add the layout and dictionary
  arguments to `Spec.ABI`.
- The real run-time cost is a structure's operation called indirectly in an inner loop (`qsort` vs
  `std::sort`); F4's specialisation recovers it.

Recommendation: F4, after plan 0.138 (it changes what a value's layout is) and plan 0.137. Until then F1
stays.

## 5. Postponed to dependent types (OCP-0009)

Each of these is naturally solved there; doing it earlier would build it twice.

- **GADTs and indexed families**: an inductive family with indices at quantity 0, erased at run time.
- **Nested types** (`data Nest a = Nil | Cons a (Nest (a × a))`). They stay within structured recursion
  (an initial algebra of a higher-order functor on `[C, C]`; its fold terminates), but:
  - the fold's algebra is a natural transformation (rank 2: `∀a. 1 + a × G(a×a) → G a`), and Once is
    rank 1;
  - the recursion is polymorphic (each layer at a new type), so F1 cannot compile it (the number of
    instances is known only at run time) and F3/F4 must: the layout doubles at each layer;
  - a fold to a fixed type (`sum : Nest Int → Int`) needs the Kan-extension trick (fold into
    `G a = (a → Int) → Int`; Johann and Ghani);
  - most real uses (perfect trees, well-scoped terms, finger trees) are indexed families with an erased
    index, whose folds are first-order.
- **Laws proved in Once**: a theory's laws become record fields at quantity 0 (checked, erased, no
  run-time cost); a model that cannot prove them states a named postulate. The Agda certificates of §4 C
  move into Once.
- **Higher kinds** (if E1).
- **Intensional type analysis** (a function computing on a type's structure, such as `map` polymorphic
  over a functor code): the code becomes a relevant (quantity ω) argument, and only then would a
  quantity on a type mean something in the Spec.
- **Refinement types** (`{x : A | P x}`, a Σ-type with an erased proof; already OCP-0009's plan).

## 6. Steps (provisional, after §4 is decided)

1. **Measure.** How a polymorphic definition is compiled today (where F1 happens, in which module), how
   `Fix`/`case`/`destruct` elaborate on the surface, and which Strata and example types would become
   `data` declarations. Record in §2.
2. **Decide A, B** (the user). Then the Spec patch for the surface rules of `data` (user approval, one
   patch): declarations, constructors, matching, exhaustiveness, positivity.
3. **Elaborator and front end** for `data`, against the surface rules; tests for each rule, including the
   rejections (plan 0.139's named reasons). `Strata/Derived/Initial.once` rewritten with `data`.
4. **Decide C, D, E** (the user). Then the first theories (Eq, Ord, Monoid) as Once record types in the
   strata, with their Agda law statements and the first certified models, by C's mechanism; the hypothesis
   named in `Once.Certified` if C-ii.
5. **F**: after plans 0.138 and 0.137, a separate plan for layout passing and specialisation.

## 7. Done when

- A Once program can declare `data` types with named constructors and match on them, with exhaustiveness
  a type error, and the core and meaning unchanged.
- Eq, Ord and Monoid exist as lawful structures: each model in the strata carries an Agda proof or a named
  postulate of its laws, listed where the trust base lists hypotheses.
- Every item of §5 is recorded as waiting for OCP-0009, with the reason.
