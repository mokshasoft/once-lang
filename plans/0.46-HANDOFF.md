## THE TWISTS AND TURNS (so we never re-walk them)

### Detour 1 — "the algebra's setup trace fires N× per node; the machine does N×; so `⟦cata⟧ˢ` must replay (option A)" — WRONG
- Claimed: `closure "f"` emits when obtained; `elaborate(cata)` re-obtains the algebra
  per node (`E = apply ∘ ⟨ elaborate alg ∘ terminal, id ⟩`); the backend runs the
  algebra block inside the fold loop (`cata-trace-nat`'s `ascend-body`); therefore the
  spec should emit N× to match. Changed `⟦cata⟧ˢ`/`cata-ev-algˢ` to bind the algebra
  per layer.
- **Why wrong:** built on the premise that obtaining a `closure` emits. It does not
  (see Detour-3-adjacent VERIFIED fact below). And the "setup trace" is a monadic
  category-error (Detour 2). Reverted.

### Detour 2 — "no, obtain-once; the correct count is 1×; fix `elaborate` to hoist (option B)" — WRONG FRAMING
- Claimed: math says obtain the algebra once (monadic `do f ← ⟦alg⟧; return (fold f)`),
  so both 0× (original) and N× (option A) are wrong; fix the compiler to hoist.
- **Why wrong:** still organized around a "setup trace" that **does not exist**. In
  CCC+SR there is **no "evaluate the expression to a value" step** where effects could
  hide — a function value is a *global element* (a morphism); obtaining it is pure;
  effects are arrows *inside*, fired on application. "Setup trace" is monad/operational
  thinking imported into an arrows-only language. **There is no Once program with a
  non-empty setup trace.**

### VERIFIED FACT that dissolved Detours 1–2: obtaining a function is Pure
- `emit-D si x` dispatches on `effect si`; `effect (generic-info name) = classify-name
  name`; `classify-name _ = Pure` for every name except `"linux.exit"`; `emit-D … |
  Pure = []`. So `closure`/`poly`/`sigOp`-via-`generic-info` **emit `[]`**. The "setup
  trace" is always empty. **[VERIFIED:** `Builders.agda:176`, `DenotTrace.agda:116`.]**
- Consequence: the whole 0×/1×/N× debate was about an always-empty list. Moot.

### Detour 3 — "`⟦_⟧ᴰ` computing the value via `eval` is a seam/bug; remove it, take the value from the fold's `proj₂` (M3a)" — WRONG (and the user caught it)
- Claimed: `⟦_⟧ᴰ` carries two evaluators (`eval` for value, trace-fold for trace); that
  seam is the whole source of the `cata` fusion obligation; unify by dropping `eval`.
- **Why wrong:** `eval` is **the established value semantics**, the thing the compiler
  has always been proven against. `⟦_⟧ᴰ` using it is *correct*, not a seam. Dropping it
  would discard the value meaning and *manufacture* a reconciliation proof (new `proj₂`
  value vs `eval`) — more work, not less. **Retract M3a.** The plan file
  (`0.46-denotational-…md`) still contains the wrong M3a and must be corrected.

### What actually causes the `cata`/`ana` proof obligation — current best diagnosis [HYPOTHESIS, unverified]
- `⟦_⟧ᴰ` takes its result value from the established `eval` (value and trace as two
  clean components — the historical split). `⟦_⟧ˢ` takes its result value from **`proj₂`
  of its trace-fold** — a *different* route to the value than the established semantics.
  `faithful` must then reconcile "value-from-trace-fold" with "value-from-`eval`" — and
  *that* is the fusion lemma. It is an artifact of `⟦_⟧ˢ` not following the established
  value semantics, **not** of `eval` being a seam.
- **Proposed fix [HYPOTHESIS — NOT typechecked]:** make `⟦_⟧ˢ`'s *value* component a
  separate `sem-cata` over the pure algebra value (mirroring `eval (Cata) = sem-cata wf
  (eval-of-alg)`), with the trace staying the trace-fold's `proj₁`. Then both halves of
  `faithful (cata)` are `cong (sem-cata … x)` over the algebra IH (`faithful alg`) —
  structural, no fusion lemma, and `eval`/`Semantics.Core` stays the value meaning
  untouched. **This is the fourth "clear" fix proposed this session; treat it as a
  hypothesis until it typechecks.**

### A genuine, separate finding (NOT a detour) — effect-by-name vs effect-by-type
- `classify-name "linux.exit" = Halts; _ = Pure` is a **hardcoded string match**
  (`Builders.agda:176`), and `generic-info` routes every named op through it. So "the
  only effectful op is `linux.exit`" is a Layer-0 stub, not a language fact. The type
  system already tracks the effect (the arrow kind's `π`); the trace semantics **ignores
  `π` and recomputes from the name.** Effect should be **read from `π`** (the type),
  closing the Plan 0.25/0.26 `EffectShape` intent. **[VERIFIED finding; fix not done.]**
