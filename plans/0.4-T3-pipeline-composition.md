# Plan 0.4 T3 — Verified.Compile pipeline composition

## Context

`Once.Verified.Compile.correct` was a **wholesale postulate**:

```agda
postulate
  correct :
    ∀ (arch : Arch) (src : Source) (bytes : List Byte) →
    compile arch src ≡ just bytes →
    exec arch bytes ≡ ⟦ src ⟧
```

A wholesale axiom absorbs every codegen / parser / elaborator bug in
one opaque step. There's no surface for the typechecker to refuse.

## Methodology: compositional pipeline correctness

> "Each step proves its own correctness; the top-level glues them
> with composition proofs."

This was the user's explicit framing for the restructure. Each stage
of the pipeline gets a **named** correctness postulate (or eventually
theorem); the wholesale `correct` is replaced by a transitivity proof
chaining them. A buggy stage now surfaces as an *undischarged* named
goal at the corresponding postulate, instead of being absorbed silently
by the previous monolith.

## Goal

Decompose `Verified.Compile.correct` into a transitivity proof over
three named per-stage postulates:

```
GModule  ──gmoduleToModule──▶  Module
Module   ──compileFromModule──▶  CompileResult (Built asm | …)
asm      ──string-to-bytes────▶  bytes               (B2 trust)
bytes    ──exec arch──────────▶  Behavior            (CPU semantics)
```

## What landed (commit `4dd740cc`)

- `Verified.Compile.correct` is now a *proof* by transitivity, not a
  postulate. The proof typechecks today against three named
  obligations:
  - `gmoduleToModule-correct` — GModule→Module preserves observable
    behavior. Discharge: structural conversion. Small.
  - `module-to-asm-correct` — Module→asm (typecheck + elaborate +
    codegen) preserves behavior. **Load-bearing.** Discharge chains
    through 0.10's `compile-correct-extracted` plus 0.4-T0/T2's
    elaborator-soundness work.
  - `string-to-bytes-correct` — asm-text → bytes. **B2 GNU `as`
    trust** (named, removable when in-Agda assembler / B1 lands).

- Two intermediate semantic layers (`⟦_⟧M` for Module, `⟦_⟧A` for
  asm-text-on-arch) bridge the stages. Postulated as adapters; not
  trusted-base.

The wholesale `correct` postulate is gone. A regression at any stage
surfaces as a named undischarged goal, not a silent absorption.

## What's pending

- **Discharge of `gmoduleToModule-correct`** — a structural argument
  over `Once.Grammar.ExprConvert` plus a Decl-level walker. Mostly
  mechanical.
- **Discharge of `module-to-asm-correct`** — the substantive piece.
  Requires 0.10 (extracted = verified) and the ApplyWF/CurryWF
  alignment from 0.2.4.3 + 0.2.4.4 to chain cleanly.
- **`string-to-bytes-correct`** stays postulated until B1 (in-Agda
  assembler) lands. The signature stays the same; only the body
  changes.

## Compose-test as live regression

The per-stage decomposition doesn't fix runtime bugs by itself — it
makes them surface at the right named postulate. Today's runtime
status under the in-progress no-frame model (0.2.4.3) plus closure-
pointer pin (0.2.4.4):

- `id 42` → exit 42 ✓ (regression baseline preserved across the
  pipeline-composition restructure).
- `(id . id) 42` → exit 42 ✓ (was broken pre-restructure).
- `(id . id . id) 42` → segfaults at RIP=0x2a (the integer literal
  42) — **different bug** from the original saved-rbp/return-address
  corruption; it's the closure-escape-from-temp-frame issue that
  0.2.4.3's no-frame model + 0.2.4.4's closure[1] pin should close.

When 0.2.4.3 + 0.2.4.4 land fully, all three should produce exit 42.
At that point `module-to-asm-correct` becomes dischargeable end-to-end
for Layer 0 programs.
