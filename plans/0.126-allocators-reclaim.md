# Plan 0.126 — The proven allocators reclaim

## 0. Where this starts

**A server crashes.** Layer5Spec's group "a server never ends" (`compiler/test/loop-forever-emit.once`,
`loop-forever-silent.once`) fails on all three arches, six tests: each round allocates its next state on the
bump heap, nothing reclaims it, the 64 KiB heap fills after a few thousand rounds, and the next allocation
writes past its end. After plan 0.123 the same programs end `exhausted` instead of segfaulting: defined,
still red. This plan turns them green.

GOAL.md: "Memory is managed by the compiler from the program's structure." Nothing is ever freed today. The
allocator subsystem (`Once/Allocator/{Interface, AbstractInstance, BumpAllocator, Mempool, Slab, Malloc,
ReuseFreshness}`) is proved but wired to nothing, and four of its modules are on `backstop.islands`.


## 1. Design decisions (settled with the user in plan 0.35; still valid)

- **D1 — Calling convention: `call`/`ret`, leaf, frameless.** `instr-alloc-heap` / `instr-free-heap` lower to
  `call <allocator-label>`. A leaf allocator needs no frame. `call`/`ret` is net-zero on the stack pointer,
  so the simulation sees the call as atomic: registers in, result out, allocator-private state advanced. No
  inlining: the allocators that matter (`Mempool`/`Slab`/`Malloc`) carry free-list logic that must not be
  duplicated per site.
- **D2 — Place stamps the allocator and emits `free`**, for escaping outputs at their last consumer and for
  transient / locally-consumed outputs inside the IR. `free` is a trace-level instruction. (The IR's
  `free-heap` constructor already exists as a semantic no-op, `IRObsCorrect.Simple`.)
- **D3 — Two contract levels; `PreservesCCC` stays untouched.** `free` reclaims a block before the frontier,
  which `PreservesCCC`'s `prior-preserved` / `heap-monotone` forbid, so alloc/free get their own lighter
  boundary contract: abstractly, all live blocks are preserved; concretely, the encoding relation and the
  calling convention are preserved and allocator-private state is hidden.
- **D4 — Free with reuse, in lockstep through the interface.** Abstract and concrete allocation go through
  the same interface, so a freed ref is reused as the same ref on both sides; `heap-eq` holds throughout and
  needs no live set. Disjointness is the interface's `blocks-disjoint` field, strengthened to live blocks
  and proved by each implementation, never postulated. Machine-checked in isolation:
  `Once.Allocator.ReuseFreshness`. The fixed-size allocators (`Mempool`, `Slab`) satisfy it; variable-size
  `Malloc` with coalescing is the deferred case (B.2 M8).
- **D5 — SigOps that free** data they return: out of scope, rides with M8.
- **`alloc` stays total in the interface** (user, 2026-06-05): it is the "enough memory" idealization;
  bounded allocators are finite refinements. **Changed by Part A:** the gap between the total interface and a
  bounded allocator is no longer an assumption — a bounded allocator that has no block calls
  `once_exhausted`, and Part A's end closes the proof.

## 2. Milestones (re-based on today's code)

- **M1 — done** (`250abade`): `free` and `alloc-fresh` in `AllocatorInterface`, discharged in
  `AbstractInstance`.
- **M2 — the abstract `free`.** `instr-free-heap` in the flat machine (`SMCore`), memory-non-destructive,
  and the alloc/free boundary contract (D3). The old sequencing constraint (wait for the flat path and the
  `compile-ir` deletion) is met: the flat path is the only path.
- **M3 — wire codegen through the interface, one allocator per arch.** Lower alloc/free to calls in the three
  `AbstractTo*` modules; one allocator implementation per target, mirroring the target tree. `--alloc`
  selects which allocator backs the calls (bump, mempool, slab, malloc) — plan 0.86's step F, moved here.
  Rename `AllocMode`'s `Allocator` constructor when plan 0.86 has removed the index.
- **M4 — Place: last use and `free` emission.** Classify each heap output as transient, locally consumed, or
  escaping, stamp the allocator, emit `free` at the last consumer. **The loop's round is a reclamation
  point** (D317): after a round, only the next state is live, so everything else the round allocated is
  freed there — the structural reason a server can run in bounded memory.
- **M5 — per-IR free correctness**: the frees an IR emits target blocks it produced that are dead there.
- **M6 — the call-boundary simulation, per allocator and arch**: `call alloc` preserves the correspondence,
  stack net-zero, IR-live registers and heap preserved, a fresh disjoint block in the result register; the
  same for `free`. The `instr-alloc-heap` simulation steps (`sim-alloc-*`) consume it instead of tracking
  the frontier register.
- **M7 — leak-freedom (the crown).** Over the abstract trace, the live set grows by exactly the escaping
  footprint:

  ```
  heap-conservation : ∀ (ir : IR A B) s alloc →
    live-set (exec-trace (compile ir) s alloc) ≡ live-set-before ⊎ escaping-footprint ir
  ```

  Proved by induction on the IR. Its corollaries: for a terminating `main`, the live set at the end is empty
  (a program returns nothing; heap only flows into SigOp arguments, which are locally consumed); for a loop,
  the live set after each round is the next state's footprint — **a space bound per round**, which is the
  guarantee Part A's relation does not give.
- **M8 — deferred: variable-size `Malloc`** (coalescing; the ref↔address map is not fixed), and SigOps that
  free (D5).

## 3. Done when

1. `heap-conservation` holds, postulate-free, and the per-round space bound follows from it.
2. Layer5Spec's "a server never ends" is green on all three arches.
3. The emitted binaries run valgrind-clean on the layer5 cata tests (with mempool client requests for our own
   allocators).
4. The allocator modules leave `backstop.islands`; plan 0.64 Group AL closes (wired, not deleted).
5. No regression: `cabal test`, the exit tests on three arches, `make merge-gate`.
