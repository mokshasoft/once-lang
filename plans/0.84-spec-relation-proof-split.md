# Plan 0.84 — The spec closure holds relations only; proofs move out

**Rule this enforces:** `Once.Spec` re-exports only what a reviewer must read
to know WHAT IS CLAIMED. A `-sound`/`-complete` proof is evidence that the
implementation meets the claim — it is never part of the claim, and it does not
belong in the closure.

## 0. The finding

The merge analysis measured all 23 modules of the `Once.Spec` re-export
closure for proof content. **Eighteen are clean** — `Type`, `Raw`, `Judgment`,
the five `Denotation/*`, `Adequacy.agda` (there for the `CorrectCompiler`
record, i.e. the theorem statement itself), and the eight `Spec/*`. Zero
`≡`-typed declarations across all of them. No proof lives in `Once/Spec/`.

**Five are contaminated**, and they are contaminated because each file defines
a relation AND proves the bridge to the executable in the same module:

| module | lines | relations | `sound`/`complete` proofs |
|---|---|---|---|
| `Once/Adequacy/LexerBridge.agda`    | 304 | 2 | 14 |
| `Once/Adequacy/FrontEndBridge.agda` | 219 | 4 |  8 |
| `Once/Adequacy/AcceptSound.agda`    | 208 | 3 |  6 |
| `Once/Adequacy/ModuleComplete.agda` | 362 | 4 |  2 |
| `Once/Grammar/DeclBridge.agda`      | 108 | 1 |  2 |
| **total** | **1,201** | **14** | **32** |

The closure is majority *proof* by line count. An audit instruction that says
"read 1,201 lines, most of which you do not have to trust" is one nobody
executes — which is how an audit surface rots.

## 1. The second defect: the closure UNDER-reports too

`formal/scripts/spec-closure.py:12` follows a re-export only when the `open
import` carries `public`. `Once/Grammar/DeclBridge.agda` imports its six
sub-relations WITHOUT `public`:

    open import Once.Grammar.ImportBridge using (ParsesImport; …)

`ParsesDecl`'s constructors MENTION `ParsesImport`, `ParsesTypeAliasDecl`,
`ParsesSignature`, `ParsesFunDef`, `ParsesOpDecl`, `ParsesPolyType`. A reviewer
reading `ParsesDecl` must read all six to know what it says. They are in the
true trust surface and the report does not list them.

So the closure **over-reports** (module granularity drags proofs in) and
**under-reports** (only `public` propagates) at the same time. Fixing only the
first would leave a number that is smaller AND still wrong.

**Consequence to accept up front: the honest closure GROWS.** It goes from 23
modules to roughly 30 — but every one of the ~30 is proof-free, and the total
line count a reviewer is pointed at goes DOWN. The number getting bigger is the
plan working, not failing. Do not "fix" it by re-hiding relations.

## 2. The precedent — this pattern already exists in-tree

`Once/Parser/Generic/` is already split exactly this way:

    Relation.agda   598 lines, 0 proofs   <- the spec
    Sound.agda      181 lines             <- the bridge
    Complete.agda    84 lines             <- the bridge
    Parser.agda     144 lines             <- the executable
    PolyInst.agda    97 lines             <- the instantiation

**Plan 0.84 is: apply the `Once/Parser/Generic/` pattern to the grammar and
adequacy bridges.** This is not a new idea to be invented, it is an existing
convention to be finished.

## 3. Target layout

Relations move under `Once/Spec/`; proofs stay exactly where they are and gain
an `import`. Nothing is relocated OUT of `Once/Spec/` because nothing that is
a proof is in there today — the operation is one-directional.

    Once/Spec/Lexing.agda           <- LexesChars, Lexes
    Once/Spec/Grammar/Import.agda   <- ParsesModulePath, ParsesImport
    Once/Spec/Grammar/TypeAlias.agda<- ParsesTypeAlias, ParsesTypeAliasDecl
    Once/Spec/Grammar/Signature.agda<- ParsesEffAnnot, ParsesSignature
    Once/Spec/Grammar/FunDef.agda   <- ParsesParams, ParsesAlloc,
                                       ParsesFunBody, ParsesFunDef
    Once/Spec/Grammar/OpDecl.agda   <- ParsesOpChars, ParsesOpDecl
    Once/Spec/Grammar/Decl.agda     <- ParsesDecl
    Once/Spec/Parsing.agda          <- ParsesDecls, ParsesModule, ParsesText
                                       + thin public facade over the above,
                                       so the reviewer has ONE entry point
    Once/Spec/Module.agda           <- AllFunsTyped, ModuleTyped-ef,
                                       ModuleTyped, AllMainEffUU, MainExists,
                                       HasValidMain-decl

**Stays behind (proof machinery, NOT spec):** `SkBnd` (a bound used only in the
`sound-*`/`complete-*` signatures), `FindResult`, `parseDecls-total`,
`parseModule-total-at`, and every `sound-*`/`complete-*`.

`Once.Parser.Generic.Relation` already satisfies the rule; it is re-exported
through `Once/Spec/Grammar/Decl.agda` (as `ParsesPolyType`) rather than moved.

## 4. Order of work — bottom-up, leaves first

Agda forces dependency order, and a leaf validates the pattern cheaply.

* **A. `Once/Spec/Lexing.agda`** — `LexerBridge` is the only true leaf
  (`LexesChars` depends on `Token`/`Lexer` alone). Smallest possible test that
  the split typechecks and that `Spec/Program` still resolves. **Do this first
  and stop to confirm before proceeding.**
* **B. The five `Once/Spec/Grammar/*` leaves** — Import, TypeAlias, Signature,
  FunDef, OpDecl. Mechanical once A validates.
* **C. `Once/Spec/Grammar/Decl.agda`** — needs all of B.
* **D. `Once/Spec/Parsing.agda`** — needs C; add the public facade.
* **E. `Once/Spec/Module.agda`** — the typing half, from `AcceptSound` +
  `ModuleComplete`.
* **F. Re-point `Once/Spec/Program.agda`** at the new modules and re-run
  `spec-closure`.

## 5. The typing half will NOT come out clean, and that is the point

`ModuleTyped-ef` takes `String ⊎ (List FunInfo × List PolyFunInfo)` — the front
end's own output — so `Once/Spec/Module.agda` will import `Once.Compiler`
types, and `ModuleTyped m = ModuleTyped-ef m (extractFunctions (extractAliases
m) m)` defines "well-typed" by RUNNING the front end.

This plan does not fix that; **D137 recorded it and plan 0.59 owns it.** The
split relocates the dirt to a file whose name promises it is spec, where a
reviewer trips over it. Expect `Spec/Grammar/*.agda` to look clean and
`Spec/Module.agda` to look bad. That asymmetry is honest reporting, not a
defect in the split.

## 6. Risks

1. **A relation's constructors mention executable helpers.** `ParsesDecls`
   mentions `skipNewlines` and `parseDeclB`; `ParsesText` mentions
   `allTrailing`. These MUST come along — a relation defined against the
   executable is a pre-existing weakness (0.59's territory), not something to
   launder by leaving it behind. Move it and let the import show.
2. **Import cycles.** A proof module importing its own relation module is fine;
   a relation module reaching back into a proof module is a design error —
   if it happens, the declaration was misclassified. Re-check, don't `public`
   your way out.
3. **Regression to a smaller number.** If someone later drops `public` to make
   the closure look smaller, §1 is the argument against it.

## 7. Gate

Judgment sweep, 7 gate roots, `make lint-imports`, `make spec-closure`.
**No extraction gate:** relations are types, no executable code moves. Confirm
with `git diff --name-only` against the extracted-cone list before skipping it.

## Exit

`make spec-closure` lists ~30 modules, **every one proof-free**, and the six
sub-relations `ParsesDecl` depends on appear in it for the first time. Update
MERGE.md's hand-written closure list (currently stale at "16 modules today")
in the same commit.
