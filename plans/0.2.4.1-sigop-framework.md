# Plan 0.2.4.1: SigOp Framework for Effectful Operations

## Context

Plan 0.2.4 (Categorical Layer 0) attempted to compile and run programs
using only the CCC structural morphisms (`id`, `∘`) plus a handful of
signature operations (`exit`, integer literals). Running
`compiler/test/layer0-neg.once` (which prints exit code 7 via the
signature keyword's `exit`) produced a binary that SIGILLs on `ud2`
— the codegen stubs for both integer literals *and* the `exit`
syscall are unimplemented, emitting `ud2` in place of real code.

Investigation revealed that the gap is architectural, not local:

1. `SigOp : String → IR A B` (post-D047 rename from `Prim`) is an
   opaque escape hatch indexed by a string, but there is **no
   machinery for actually discharging its contract at any call site**.
2. The existing `Once.CCC.SigOp.Contract` defines a total
   `Provider = ∀ name → ∃[ m ] Contract ... name`, which no concrete
   provider can honestly satisfy — every `SigOp` handler becomes a
   postulate.
3. The semantic function for each SigOp lives outside the IR in a
   postulated `defaultEvalSigOp : String → ⟦A⟧ → ⟦B⟧`. Frontend
   correctness proofs (`desugar-correct`, `elaborate-correct`) thread
   through this postulate unconditionally.
4. There is no scaffolding for **families** like `lit.int.<N>` whose
   names are parameterized by a value, nor for **syscalls** whose
   semantics cannot be formally defined inside Agda (`read`, any IO).

This plan designs and lands the SigOp framework so:

- Every SigOp carries its semantic function alongside its name (the
  `SigOpInfo` record), removing the `SigOpSem` postulate.
- Codegen-time contracts are partial and target-specific, composable
  via `<|>`.
- Postulates for environment-reading syscalls are explicit, localized,
  and auditable.
- At the end of the plan, a program like `main = exit 42` compiles
  and runs, producing exit code 42. Optionally `print "hello"` and
  `readline` reach the same end-to-end validation.

Arithmetic SigOps (`add`, `neg`, `abs`, ...) are **out of scope**
for this plan — they continue going through the existing (convoluted)
CCC encoding. A follow-on plan (0.2.4.2-arith-to-sigop) will migrate
arithmetic to emit real x86 instructions via this framework.

## Scope

**In scope:**

- Refactor `SigOp` to carry a `SigOpInfo` (name + semantic function).
- New `Once.CCC.SigOp.Info` module defining `SigOpInfo`.
- Revise `Once.CCC.SigOp.Contract`: partial `Provider` via `Maybe`,
  composition via `<|>`.
- Remove `Once.CCC.Eval.SigOpSem` record and the
  `defaultEvalSigOp` postulate — semantics now lives with the SigOp.
- New provider modules:
  - `Once.CCC.SigOp.IntLit` — the `lit.int.<N>` family.
  - `Once.Platform.Linux.SigOp` — Linux syscalls (at minimum: `exit`;
    stretch: `print`, `readline`).
- Wire providers into `Once.CCC.EntryPointCCC` and the x86-64
  dispatcher.
- Compiler bridge: when a surface-level `signature NAME : TY`
  declaration is elaborated, pick the matching `SigOpInfo` from a
  registry (or construct it from a family-matching provider).
- End-to-end smoke test: `test/layer0-exit.once` compiles, runs,
  exits with expected status code.

**Out of scope:**

- Arithmetic migration — deferred to 0.2.4.2.
- Other targets (x86-32, RiscV64) — same architecture applies; this
  plan's implementation covers x86-64 only.
- seL4 / Windows / macOS platform SigOps — mirror Linux structure,
  but not included.
- User-defined providers declared via the surface language (currently
  `Strata/Interpretations/...` files are parsed but do not contribute
  runtime behavior — that wiring is a future plan).
- Formal semantics of syscalls (exit-actually-terminates, etc.).
  These are runtime axioms the kernel satisfies.

## Locked architectural decisions

These came out of the design discussion on 2026-04-24. Locked before
implementation begins.

### D1a′: SigOp carries SigOpInfo (name + sem), not just a string

```agda
record SigOpInfo (A B : Type) : Set where
  field
    name : String            -- decidable-equality identifier + surface link
    sem  : ⟦ A ⟧ → ⟦ B ⟧     -- target-independent semantic function

data IR : Type → Type → Set where
  …
  SigOp : ∀ {A B} → SigOpInfo A B → IR A B
```

Rationale:

- **Semantics travel with the node.** `eval (SigOp si) x = si.sem x`
  is direct — no threaded `SigOpSem` parameter.
- **Decidable IR equality** stays: `_≟SigOpInfo_ si₁ si₂` compares
  `name` fields only. Two SigOps with the same name are equal by
  convention (enforced by the surface-to-IR lookup being a function).
- **Target-independence** preserved: `sem` is a plain function over
  denotational semantics, unrelated to machine instructions.
- **Postulates are local**: `read-sem : Unit → Int` is one postulate
  in the Linux provider module. Every other SigOp has a concrete
  Agda function.

The surface-to-IR elaborator binds each surface `signature NAME : TY`
to a specific `SigOpInfo`. Providers export registered `SigOpInfo`
instances (or family-matchers for parameterized names like `lit.int.*`).

### D4a: One Contract shape; semantics may be definitional or postulated per SigOp

Effects are carried by the type (`Eff A B = A ⇒[ mk-kind Many eff ] B`
per D046). The Contract machinery does *not* bifurcate on pure vs.
effectful — one record shape serves both.

Per-SigOp, the semantic function is:

- **Definitional** for pure operations: `add-sem (a,b) = a +ℤ b`,
  `lit-int-sem n _ = n`.
- **Unit-valued trivial** for effect-termination operations:
  `exit-sem _ = tt`. The "actually terminates" property is an axiom
  about Linux, outside Agda.
- **Postulated** for environment-reading operations: `read-sem`,
  `getPid-sem`, etc. Each postulate lives in a `postulate` block at
  the top of the provider module, clearly marked.

The compiler-correctness theorem has the shape:

```
∀ (tp : TargetProvider FS) (prog : Program) →
  tp-covers (sigOpsIn prog) →
  exec (compile tp prog) (encode x) ≡ encode (evalSurface prog x)
```

- Compiler correctness is *unconditional* — true for any valid
  TargetProvider.
- Program runtime correctness is conditional on the provider's
  postulates matching reality (the kernel contract).

## Implementation phases

Each phase ends with `make compiler && make malonzo && cabal build`
green. Commit per phase.

### Phase A — `SigOpInfo` and core refactor

1. Add `Once.CCC.SigOp.Info` module with the record definition.
2. Change `SigOp` in `Once.CCC.IR` to take `SigOpInfo A B`.
3. Update every case-analysis of `SigOp` across the tree:
   - Eval: extract sem from Info.
   - Optimizer: `_≟IRH_` compares names via `SigOpInfo.name`.
   - Size / Stack / Escape / Fusion: treat as opaque as before;
     dispatch on `name` where needed.
4. Remove `SigOpSem` record and `defaultEvalSigOp` postulate.
5. Update Surface.Elaborate's `intLit`, `strLit`, `prim`, `addIR`,
   etc. builders to produce fully-filled `SigOp`s. For this phase,
   arithmetic builders still use placeholder sem functions — the real
   math lives elsewhere and migrates in 0.2.4.2.

**Estimated cost:** ~80 files touched (mostly mechanical). One
commit. `make compiler` green.

### Phase B — Partial Provider + composition

1. Change `Provider` in `SigOp.Contract` to return `Maybe`.
2. Add `_<|>_` on `Provider` in new `SigOp.Compose` module.
3. Update `EntryPointCCC` to take a `TargetProvider` parameter
   (the composed thing). Add a `coverage` premise structure — a
   function that, given a program, produces a proof every used name
   is covered or returns a concrete "not covered: NAME" error.
4. Arithmetic proof updated to new shape (just signature; content
   unchanged).

**Estimated cost:** medium commit. `make compiler` green.

### Phase C — `IntLit` provider

1. Create `Once.CCC.SigOp.IntLit`:
   ```agda
   lit-int-info : ℤ → SigOpInfo Unit Int
   lit-int-info n = record { name = "lit.int." ++ showℤ n
                           ; sem = λ _ → n }

   intLitProvider : TargetProvider
   intLitProvider {A = Unit} {B = Int} si with stripPrefix "lit.int." (name si)
   ... | just suffix with parseℤ suffix
   ...   | just n = just (Stack , lit-int-contract n)
   ...   | nothing = nothing
   ... | nothing = nothing
   intLitProvider _ = nothing
   ```
2. Codegen contract: emits `mov $N, %rax` (or `mov imm64, %rax` for
   large N). Protocol-compliance proof via `mkPurePrimResult`.
3. The elaborator's `intLit` builder now picks this `SigOpInfo`.

**Estimated cost:** ~100 lines. `make compiler` + Layer 0 integer
literals work (observable in disassembly: literals now `mov $N`
instead of `mov $0; ud2`).

### Phase D — Linux `exit` SigOp

1. Create `Once.Platform.Linux.SigOp`:
   ```agda
   exit-info : SigOpInfo Int Unit
   exit-info = record { name = "linux.exit"
                      ; sem = λ _ → tt }  -- trivial Unit sem

   linuxProvider : TargetProvider
   linuxProvider si with name si ≟String "linux.exit"
   ... | yes _ = just (Stack , exit-contract)
   ... | no _ = nothing
   ```
2. Codegen contract for `exit`:
   - Input register holds exit code. Convention: `%rdi` on Linux
     x86-64, which matches the CCC's `Input` register alias.
   - Emit: `mov %rdi, %rdi ; mov $60, %rax ; syscall`.
     (The `mov %rdi, %rdi` is a no-op but keeps the protocol wrt
     `Input`/`Output` register semantics.)
   - Protocol-compliance proof: syscall never returns, so
     post-syscall CCC state is vacuously preserved. Formally: the
     contract ends with a `syscall` instruction; `IRResultAWF` is
     constructed with `final-state = <terminated>` (definable via a
     Unit-valued placeholder).
3. Surface `signature exit : Eff Int Unit` elaborates to
   `SigOp exit-info`. Name convention: qualified via import path
   (`I.Linux.Syscalls.exit` → IR name `"linux.exit"`; or simply
   `"exit"` if unqualified; TBD during Phase D).

**Estimated cost:** ~150 lines including contract proof. End-to-end
milestone: `compiler/test/layer0-exit.once` compiles, binary runs,
exits with code 42.

```once
-- compiler/test/layer0-exit.once
signature exit : Eff Int Unit
main : IO Unit
main = exit 42
```

### Phase E — Provider composition + coverage

1. Compose: `once-x86-64-provider = intLitProvider <|> linuxProvider`.
2. Compute coverage for each test program: a function
   `sigOpNames : Program → List String` that walks the IR.
3. Prove `sigOpNames prog ⊆ recognizedBy provider` as a concrete
   Agda proposition per test. For `layer0-exit.once`, this reduces
   to `{"lit.int.42", "linux.exit"} ⊆ {...}` — a decidable check.

**Estimated cost:** small commit. Locks in the compiler-correctness
theorem structure from D1a′.

### Phase F — Stretch: `print` and `readline` (optional)

Only pursue if Phase A–E land cleanly. If skipped, push to 0.2.4.3.

1. `print-info : SigOpInfo Str Unit`:
   - Codegen: `mov $1, %rax ; mov $1, %rdi ; mov <buf>, %rsi ;
     mov <len>, %rdx ; syscall` (write to stdout).
   - Semantic function: `λ _ → tt` (trivial Unit sem; the side
     effect is outside Agda).
   - Tricky bit: `Str` in Once is not yet a known runtime
     representation. May need to postulate a `Str → (Buf, Len)`
     encoding.
2. `readline-info : SigOpInfo Unit Str`:
   - Codegen: Linux `read` syscall into a buffer, return buffer.
   - Semantic function: `read-sem : Unit → Str` — **postulated**.
     Explicit `postulate` block in `Once.Platform.Linux.SigOp` with a
     comment: "read's return value depends on the environment; we
     axiomatize it."
3. Smoke test: a program that does `print (readline)` (or similar
   composition) and exits.

**Estimated cost:** uncertain. May reveal gaps in Str representation.
Punt to 0.2.4.3 if risk is high.

### Phase G — Documentation + decision log

1. Decision log entry **D048: Two-level SigOp architecture
   (SigOpInfo in IR, TargetProvider at codegen)**. Documents D1a′
   and D4a; cross-references D046 (kind-unified arrow) and D047
   (rename Prim → SigOp).
2. Update `plans/README.md`: mark 0.2.4.1 active / completed as
   appropriate.
3. Close 0.2.4 layer-0 plan if Phases A–E close its remaining
   blockers (Layer 0 smoke test passes).

## Success criteria

- `SigOp` carries `SigOpInfo` (name + sem). `SigOpSem` record gone.
- `defaultEvalSigOp` postulate eliminated.
- `Provider` is partial (returns `Maybe`) and composable via `<|>`.
- `make frontend`, `make compiler`, `make malonzo`, `cabal build`
  all green.
- `./layer0-exit-binary; echo $?` prints `42`.
- Coverage proof concrete and automatic for tested programs (no
  postulate besides environment-dependent syscall semantics).
- Decision log D048 written and cross-referenced.

## Risks

1. **SigOpInfo refactor cascades widely.** ~80 files reference
   `SigOp name` patterns. Mitigation: Phase A is mechanical; do it
   in one commit with rigorous grep to avoid missed sites.

2. **IR-with-embedded-function affects optimizer equality.** The
   optimizer's `_≟IRH_` uses name-only equality on SigOpInfo; we
   rely on the convention "same name ⟹ same sem." If surface-to-IR
   elaboration accidentally produces two different SigOpInfos with
   the same name but different sems, behavior is undefined.
   Mitigation: a lint/test that verifies every surface name resolves
   to exactly one SigOpInfo.

3. **Linux syscall calling convention correctness.** The `exit`
   codegen must match the Linux x86-64 ABI (rdi = exit code, rax =
   60, syscall instruction). Any mismatch produces wrong behavior at
   runtime, not detected by Agda.
   Mitigation: the binary-level test catches this — if exit code is
   wrong, the test fails obviously.

4. **Str representation for `print`.** If Phase F is attempted,
   strings need a concrete runtime layout (pointer + length vs.
   null-terminated). The IR treats Str opaquely; the codegen needs
   to know. Mitigation: punt Phase F if representation work is
   substantial; treat 0.2.4.3 as the place for string handling.

5. **Coverage proof boilerplate.** For each program we need
   `sigOpNames prog ⊆ recognizedBy provider`. If many test programs
   get added, this can get tedious. Mitigation: derive coverage
   automatically via a decision procedure (Phase E's work).

## Relationship to other plans

- **Parent: 0.2.4** (Categorical Layer 0). This plan is Layer 0's
  real unblocker — Layer 0's end-to-end test depends on `exit`
  working. Phases A–E should close 0.2.4's remaining blocker list.
- **Sibling/follow-on: 0.2.4.2** (to be written) — arithmetic
  SigOps migrate to the same framework. `add.int`, `neg.int`, etc.
  become first-class SigOpInfos with x86 codegen contracts rather
  than being routed through the current opaque-Prim encoding. Stays
  in `formal/Once/Arith/SigOp/Proofs.agda` (ArithCompiler-owned,
  compiler-intrinsic). Separately, the user-facing math
  `Strata/Interpretations/Math/Int.once` may also grow a proof
  companion, but that is a separate concern — the ArithCompiler's
  proofs are not an "interpretation" in D009's sense.
- **Builds on D046** (kind-unified arrow): effects are already carried
  in the type; this plan preserves that and does NOT reintroduce
  effect bifurcation at the contract layer.
- **Builds on D047** (SigOp rename): vocabulary is correct.
- **Prerequisite for 0.4.2** (end-to-end connector): that plan's
  composed theorem `exec (compile prog) ≡ encode (evalSurface prog)`
  depends on having concrete TargetProviders, which this plan
  delivers for x86-64.

## Non-goals

- Generalizing the provider architecture to a user-extensible
  plugin system. Providers are defined in Agda modules, compiled
  with the rest of the compiler, and composed statically. Dynamic
  loading / runtime extension is out of scope for the foreseeable
  future.
- Implementing additional targets (x86-32, RiscV64) against the new
  framework. Follows the same shape; deferred.
- Modeling the kernel contract formally. We assume Linux syscalls
  behave per their man pages; that assumption is an explicit
  `postulate` block per provider, not a proved theorem.

## Open questions (to resolve during Phase A)

- **Naming convention for qualified SigOps.** Should
  `signature exit` in a module imported as `I.Linux.Syscalls` produce
  the IR name `"linux.exit"`, `"I.Linux.Syscalls.exit"`, or just
  `"exit"`? Picking `"linux.exit"` is short and unique (no other
  module owns `linux.`); `"I.Linux.Syscalls.exit"` is fully
  qualified but verbose. TBD during elaborator changes in Phase A.
- **Where does the elaborator get its SigOpInfo from?** For
  `signature exit : Eff Int Unit`, the elaborator needs to know
  `exit-info`. Options: (a) a compile-time registry indexed by
  name; (b) the surface module carries a reference to an Agda
  module exporting the SigOpInfos. TBD during Phase A or D.

**Layering principle:**

- **CCC layer** (`formal/Once/CCC/SigOp/`) contains the abstract
  machinery — Info, Contract, Helper, Compose. Zero knowledge of
  specific type constructors; no Int, no Float, no Linux.

- **ArithCompiler** (`formal/Once/Arith/`) is compiler-intrinsic
  infrastructure for arithmetic expressions, including literals.
  Content here is **not user-imported** — the compiler emits these
  SigOpInfos internally when it encounters numeric literals or
  built-in arithmetic expressions. Writing `42` in source is a
  language primitive, not a module import.

- **Strata/Interpretations** (per D009, D016): user-imported
  interpretations. Each interpretation directory co-locates `.once`
  (declarations), `.x86_64` / `.c` / other target impls, AND
  `.agda` (formal proof). One module, multiple artifacts, same
  directory. Users `import Linux.Syscalls`, `import Math.Int`, etc.

- The distinction is **how the SigOp enters a program**: a literal
  `42` enters via compiler emission (ArithCompiler); a call to
  `exit` enters via an explicit user import (Strata interpretation).
  Both produce `SigOp : SigOpInfo A B → IR A B` nodes and share the
  same contract machinery.

- Providers compose into the final provider at
  `EntryPointCCC.agda` via `_<|>_`. Adding a new interpretation
  (seL4, Windows) is a new directory under `Strata/Interpretations/`
  + one line of composition; no change to CCC or ArithCompiler.
