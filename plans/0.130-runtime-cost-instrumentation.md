# Plan 0.130 — what a run costs: run-time instrumentation of emitted code

status: NOT STARTED (written 2026-10-30, at the user's request). Next step: §3 A, after a decision on §2.

relates: MERGE.md §1 "Emitted code and its cost" (the static half, `once stats`, `tests/codegen-measure.sh`),
plan 0.129 (the optimizer whose effect on memory nobody has measured), plan 0.123 (memory runs out observably),
OCP-0009 (dependent types, QTT erasure), the Agda fork's reports (`run-ast-dumps.sh`, `--counters-file`).

## 1. Why

MERGE.md asks what a codegen change costs. Code size is measured (`.text` per arch) and so are static counts over
the program image (`ImageStats`: heap allocation sites and cells, frames and their slots). What a RUN costs is not:
cells allocated per run, peak heap, peak stack, instructions executed, calls made. Plan 0.129's closure beta (D350)
removes a two-cell closure record and an indirect call wherever it fires, and right association changes which
pairs are materialised; the static counts see the sites, not how often they run.

The instrumentation is built once and has to last: Once is getting dependent types (OCP-0009), where what a
definition costs depends on its indices (`Vec n` allocates `n` cells), and the Agda fork already reports
reachability and per-site profile counters for the PROOF side. One report shape should serve all of it.

## 2. Decisions to make first

1. **Where the counts come from.**
   - (a) **The flat machine** (recommended, primary): a cost-counting run of the abstract image under
     `exec-flat`, defined in Agda and extracted (`once run --costs`). Arch-free, and it counts in the semantics the
     proofs are about, so a later theorem can relate the static and the run-time numbers. The ghost stack
     high-water mark the layout model already keeps (`FrameFree`, `EventDispatch`) is the peak stack.
   - (b) **The real binary under an emulator**: QEMU TCG plugins (instructions, memory accesses) on all three arches.
     Per-arch truth, no change to the binary; the cross-check for (a).
   - (c) Counters compiled into the binary: rejected, it changes the code being measured.
2. **Whether costs ever become proof obligations** (a static bound ≥ every run's count), or stay measurements.
   Recommended: measurements now; keep the report's static and run-time numbers keyed alike, so a bound can be
   stated later without changing the format.

## 3. Steps

**A. One report shape, shared with the Agda fork.** The fork's reports (`--write-ast`, `--counters-file`,
`--duplicate-types`) are JSON with a `{"schema": n, "report": "…"}` header, a `provenance` block (repo, ref, commit,
entry point), rows keyed by name AND source range (a name alone is ambiguous), each row's own share and the share
including what is nested in it, folded stacks for flame-graph tools, and a report written as INCOMPLETE when the run
stops (out of heap, interrupted). Once's reports take the same shape:
- `codegen-static` (`once stats --json`): one row per definition (canonical name, source range): its image's
  `Once.Measure.Image` counts, and the program's total.
- `codegen-run` (§B): one row per definition: cells allocated, peak heap and stack reached inside it, steps, calls;
  own and inclusive; folded stacks by call path.
- One comparison tool reads two reports of the same kind and lists, per row and in total, what grew;
  `tests/codegen-measure.sh compare` becomes a client of it, and so can the proof-side reports (reachability,
  profile counters), which is where MERGE.md §6 compares dumps by hand today.

**B. Counting runs on the flat machine.** `exec-flat` with a cost record threaded beside the state (cells allocated,
heap high-water, stack high-water, steps, calls, and the call path for the folded stacks), extracted. SigOps are
answered by the test interpretation the exit tests use. A run that runs out of heap or fuel writes its report marked
incomplete, naming where it stopped (plan 0.123 makes running out a Spec end; the report must say so, not lose it).

**C. Emulator cross-check.** A QEMU plugin per arch counting instructions and peak stack; `tests/run-exit-tests*.sh`
gain `--costs`. Where (a) and (b) disagree on a count both define (calls, heap cells), one of them is wrong.

**D. MERGE.md.** The *Memory* item moves from static to run-time counts; the static ones stay as the cheap signal.

**E. Ready for dependent types.** Nothing in A–D may assume a definition has one cost:
- Rows are keyed by the definition AND the values of its runtime (non-erased) parameters that the cost depends on;
  today that is none, so every row has an empty key and today's reports are the degenerate case.
- A static row may hold a cost EXPRESSION over the definition's index parameters instead of a number (`cells = n`
  for `replicate : (n : Nat) → A → Vec n A`); a run row records the index values it was run at, so a sample can be
  checked against its expression.
- Erased parameters (QTT multiplicity 0, OCP-0009 rung 5) cost nothing at run time: the report lists them as erased,
  which doubles as a check that erasure happened.
- The fork's side is already per-definition with ranges; when Once's elaborator produces Agda-checked terms for
  dependent definitions, a Once definition and the Agda definitions that check it can share a key.

## 4. Done when

`once run --costs` and `once stats --json` write `codegen-run` / `codegen-static` reports; the comparison tool diffs
two of them; MERGE.md's *Memory* item reads run-time counts; the reports carry the keys §3 E names (empty today).
