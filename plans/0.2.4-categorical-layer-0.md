# Plan: Implement Categorical Layer 0

## Goal

Implement a minimal stack-allocated compiler for categorical layer 0 (Category) + layer 1 (Products) with Prim support, then extend layer by layer.

## Context

After completing the core invariants refactoring (007), the IR stack layout is now well-understood. Rather than fixing the entire compiler for all IRs at once, we implement layer by layer starting from the simplest.

## Categorical Layers (from ir-stack-layout.md)

| Layer | Name | Morphisms |
|-------|------|-----------|
| 0 | Category | `id`, `∘` |
| 1 | Products | `⟨_,_⟩`, `fst`, `snd` |
| 2 | Coproducts | `inl`, `inr`, `[_,_]` |
| 3 | Terminal/Initial | `terminal`, `initial` |
| 4 | Exponentials | `curry`, `apply` |
| 5 | Initial Algebras | `In`, `cata` |
| 6 | Final Coalgebras | `Out`, `ana` |

## Layer 0 + Prim

With just `id`, `∘`, and `Prim`, we get:
- Linear pipelines of unary primitives
- No data construction/destruction
- Single-input, single-output programs

**Example programs:**
```
negNeg : Bool → Bool
negNot = Prim "not" ∘ Prim "not"

add3 : Int → Int
add3 = Prim "succ" ∘ Prim "succ" ∘ Prim "succ"
```

## Layer 0 + 1 + Prim

Adding products enables:
- Binary primitives: `Prim "add" : Int × Int → Int`
- Tuple manipulation: `swap`, `dup`, `fst`, `snd`
- Useful data plumbing

**Example programs:**
```
swap : A × B → B × A
swap = ⟨snd, fst⟩

dup : A → A × A
dup = ⟨id, id⟩

addThenDouble : Int × Int → Int
addThenDouble = Prim "double" ∘ Prim "add"
```

## Implementation Strategy

### Phase 1: Layer 0 + Prim (Minimal)
1. Implement IR handlers for: `Id`, `Compose`, `Prim`
2. Prove all invariants for these handlers
3. Test with simple pipeline programs

### Phase 2: Layer 1 (Products)
1. Add IR handlers for: `Pair`, `Fst`, `Snd`
2. Prove invariants
3. Test with tuple manipulation programs

### Phase 3: Layer 2 (Coproducts)
1. Add IR handlers for: `Inl`, `Inr`, `Case`
2. Prove invariants
3. Test with branching programs

### Phase 4: Layer 3 (Terminal/Initial)
1. Add IR handlers for: `Terminal`, `Initial`
2. Prove invariants

### Phase 5: Layer 4 (Exponentials)
1. Add IR handlers for: `Curry`, `Apply`
2. Prove invariants
3. Test with higher-order programs

### Phase 6: Layer 5 (Initial Algebras)
1. Wire existing `Cata` implementation
2. Ensure all postulates are proven

### Phase 7: Layer 6 (Final Coalgebras)
1. Add IR handlers for: `Ana`, `Out`
2. Prove invariants
