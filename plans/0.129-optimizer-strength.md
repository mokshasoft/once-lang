## 0. Where this starts

**The optimizer** (`Once.Optimize`): ten passes of `optimize-once`. Type-directed rules first (a quiet term into
`Unit` is `terminal`; a term out of `Void` is `initial`), then structural ones: `id ∘ f`, `g ∘ id`, `terminal ∘ f`,
`g ∘ initial`, `fst`/`snd ∘ ⟨g,h⟩`, `case h k ∘ inl/inr`, `⟨fst,snd⟩ → id`, `[inl,inr] → id`, and recursion into
`curry`/`Cata`/`Ana`/`Iter`. Drops are guarded by `has-effect?` (`apply`, `SigOp`, `Call`, `Out`, `Iter`).

**What the tests showed** (D348): elaborated code reaches only `Unit → terminal`, `Void → initial`, `id ∘ f` and
`fst`/`snd ∘ ⟨g,h⟩`. Three defects:
1. The `Unit` rule runs before eta: `<id . fst, snd>` (source `Unit * B`) becomes `<terminal, snd>`, which the
   eta rule does not see as `id`.
2. Nothing reassociates composition, so `fst . (<a, b> . k)` stays: a redex hidden behind a left-nested `∘`.
3. The structural `inl`/`inr` out of `Void` → `initial` clauses never fire (the type-directed `Void` rule runs
   first: they are only reached when the source is not `Void`).

**The earlier optimality work (2026-01 to 2026-03, deleted as islands in D347).**
- *Discovery tool* `compiler/tools/discovery/` (`once-discover`): enumerates IR terms over `Unit`/`A`/`B` to a
  depth, groups them by QuickCheck value-equivalence (Haskell `Once.Eval`), and either proposes rules (`ccc`) or
  reports classes with more than one optimizer normal form (`completeness`). Results, in commit messages only:
  depth 2 complete; depth 3 had 118 misses, all the missing pair fusion `⟨f,g⟩ ∘ h = ⟨f∘h, g∘h⟩` (e54bb168a);
  depth 4: "89000+ terms collapse to ~13 unique normal forms" (8a395813b), no verdict. Unbuildable since
  d30e4afa7 (it used the removed `Once.MAlonzo`; `once.cabal` keeps a note).
- *Proofs* (`Optimizer/{Normal,IRReducible,PairCaseNormal,Cost,Depth}`): `IsNormal` = no `CompReducible`
  (id-left/right, fst/snd-pair, case-inl/inr, apply-curry, terminal, initial, assoc), `PairReducible` (eta,
  `⟨fst∘h, snd∘h⟩`), `CaseReducible` (eta, `[h∘inl, h∘inr]`) redex. Proved: `optimize-normal` (the output has no
  redex). `optimize-optimal` (cost-minimal among equivalent terms) was reduced to the postulate `normal-unique`
  (equivalent normal forms are equal), which is FALSE: `fst`, `snd`, `terminal : Unit * Unit → Unit` are distinct
  normal forms (`docs/formal/core/normal-unique-analysis.md`). The type-directed rules were the proposed fix, but
  they cover only a direct `Unit` target / `Void` source; defect 1 above is the nested case they miss.
  Everything was stated over the value evaluator `eval`, which plan 0.98 deleted.
- *Rules lost* in 841d7e1bd (OCP-0003, 2026-03): assoc, `apply ∘ ⟨curry f, g⟩ → f ∘ ⟨id, g⟩`, pair/case
  uniqueness, pair fusion (`safe-pair-distrib` and `wants-coprod` are still defined in `Optimize.agda`, unused).

## 1. Principles

- **Every rule keeps the trace** and is a case of `OptimizePreserves.opt-once-rel`. A rule that drops or duplicates
  a subterm needs that subterm quiet (`has-effect? ≡ false`, `OptimizeQuiet.quiet-now`); a rule that duplicates one
  also needs a cost argument (no code growth).
- **Every rule has a test**: an `Optimize.Examples` refl check, and, when elaborated code reaches it, a definition
  in `compiler/test/opt-rules.once` checked through `once elaborate`/`once optimize` (`OptimizeSpec`).
- **Measured**: each rule's effect on the corpus — IR size summed over all functions (`once optimize`), and the
  binary size — recorded in the decision entry. A rule that never fires on elaborated code still may be kept for
  completeness (part D), but says so.
- **Optimality is about the trace.** Two terms are equivalent when they have related runs (`RelS`), not equal
  values; effects fix an order, so fewer terms are equivalent than under the old `eval`.

**B (as planned).**
1. Delete the dead `inl`/`inr` out of `Void` clauses (and their `OptimizePreserves` cases). Keep the `SigOp` one
   (an effect into `Unit` reaches it).
2. Eta up to `Unit`/`Void`: in `optimize-pair`, a component counts as `fst` when it is `fst` or a quiet term into
   `Unit` whose source is `Unit * B` (and symmetrically for `snd`); in `optimize-case`, a branch counts as `inl` when
   it is `inl` or any term out of `Void`. Proof: `quiet-now` and `Unit`'s single value (`Void`: no input).
3. Reassociation: `(h ∘ g) ∘ f → h ∘ (g ∘ f)`, and the beta rules read through a right-nested chain
   (`fst ∘ (⟨a,b⟩ ∘ k) → a ∘ k` when `b` is quiet; `case h k ∘ (inl ∘ m) → h ∘ m`). Proof: associativity of the
   trace monad's bind (`TraceMonadInfLaws`; add `≈∞-assoc` if missing).

**C — the rules lost in 841d7e1bd, each measured before it stays.**
1. `apply ∘ ⟨curry f, g⟩ → f ∘ ⟨id, g⟩` (closure beta; `apply` is an effect only because its closure is unknown —
   here it is known). Probably the largest win on elaborated code (`let`, lambdas applied in place).
2. `⟨fst ∘ h, snd ∘ h⟩ → h`, `[h ∘ inl, h ∘ inr] → h` (uniqueness; `h` quiet for the pair form).
3. Pair fusion `⟨f,g⟩ ∘ h → ⟨f ∘ h, g ∘ h⟩` only where it exposes a redex and `h` is quiet and cheap (it duplicates
   `h`); the old `safe-pair-distrib` is the starting point.
4. `out-μ ∘ In → id`, `In ∘ out-μ → id` (Lambek), if the `wf` indices can be matched (the old comment says
   `UnificationStuck`; try a view).

**D — find what is still missing: the discovery tool again.** Rebuild `once-discover` on what the CLI runs: the
extracted IR and optimizer (the `Bridge` route, not the removed `Once.MAlonzo`), and equivalence by TRACE, not by
the Haskell `Once.Eval`. Decide the evaluator: extract a fuelled `evalᴰ` into a tool-only root (proofs stay out of
extraction, D334), or keep the enumeration to quiet terms where value and trace agree. Run `completeness` at depths
2, 3, 4 (and 5 if it fits); every class with two normal forms is a missing rule or a wrong rule order. Record the
results in the decision log this time, not only in commit messages.

**E — optimality, restated.** Over the trace relation, in this order, each a theorem or a recorded reason why not:
1. `optimize-normal`: the output has no redex of the rule set (`IsNormal` restated for the current IR, with the
   `Unit`/`Void` cases of B2 inside it).
2. Idempotence: `optimize (optimize t) ≡ optimize t` (follows from 1 if a pass is the identity on normal terms).
3. Uniqueness on a fragment, never as a postulate: start with the first-order fragment without effects
   (products, sums, `Unit`, `Void`; no `curry`/`apply`, no μ/ν), where βη-normal forms are known to be unique up to
   the Unit/Void degeneracies — and those are exactly what B2 and the type-directed rules normalize. Sums with η
   are the known hard part (extensional normalization with sums); bound the claim to what is proved.
4. Then `optimize-optimal` on that fragment: cost-minimal among trace-equivalent terms. Widen the fragment only as
   far as D's tool finds no counterexample.
