# Plan 0.54 — Cata's Algebra Is a Morphism (clean `realize-morph`, discharge `cata-morph-strong`)

**Supersedes Plan 0.53** (bracket-abstraction-into-`⊢ᵐ` — walled: `⊢ᵐ` is a
fixed point-free vocabulary indexed by RawExpr, can't host an arbitrary
bracket-abstracted lambda; `m-lam`-wrap still needs body faithfulness).

## Principle

IR point-free + denotation-as-independent-spec are the invariants that must stay
clean. The ONLY thing that violates cleanliness today is `realize-morph (m-cata)`:

```agda
realize-morph (m-cata _ dalg) =
  Cata wfF (apply ∘ ⟨ elaborate Heap (realize dalg) ∘ terminal , id ⟩ Heap)   -- ⊢ᶜ algebra
```

Every OTHER `realize-morph` clause builds DIRECT categorical IR (`∘`/`⟨⟩`/`case`/
`curry`). This one alone round-trips through `elaborate` (the compiler) because
the algebra is `⊢ᶜ` (possibly a lambda). That round-trip is the source of the
`cata-morph-strong` gap (syntactic `elaborate algE ≡ elaborate (realize dalg)`).

## Decision (extends D070 → the clean realization)

**Make cata's algebra a morphism (`⊢ᵐ`), not a general `⊢ᶜ`.** Then:

```agda
realize-morph (m-cata _ dalg) = Cata wfF (realize-morph dalg)   -- dalg : ⊢ᵐ
```

Direct, uniform with every sibling, NO `elaborate` in the reference semantics. IR
stays point-free; denotation stays clean; `cata-morph-strong` discharges cheaply
via `morph-realize` (the algebra is a morphism, syntactic — like `m-compose` et
al.). No postulate, no 45-case `elab-realize-faithful` induction.

Lambdas are NOT lost mathematically (Curry–Howard–Lambek: every lambda algebra
has a point-free equivalent). They become **surface sugar** that bracket-abstracts
to a morphism before the algebra slot — deferred; point-free algebras only to
start. Non-morphism (lambda) algebras are rejected by the elaborator meanwhile.

## Top-down execution order (change the spec, cascade fixes, red until it lands)

1. **Judgment** (`Once.TypeCheck.Judgment`): `m-cata`'s algebra premise
   `⊢ᶜ … ⨾ zeroUsage` → `⊢ᵐ (⟦F⟧T A) ⇨[ π ] A`. This is the spec change; every
   consumer breaks below.
2. **`realize-morph (m-cata)`** (`Once.Denotation.Realize`): → `Cata wfF
   (realize-morph dalg)`. Drop the `apply/⟨⟩/elaborate` wrapper (and the
   `elaborate`/`realize` imports if now unused).
3. **Elaborator** (`Once.TypeCheck.Elaborate` `checkCataGo` / `extract-morph-eff`
   cata clause): elaborate the algebra, require it be a morphism
   (`extractMorphWitness` / the `⊢ᵐ` witness), emit `Cata wfF <algebra-IR>`
   directly (no `apply` wrapper); reject non-morphism algebras with a clear error.
4. **`cata-morph-strong`** (`Once.TypeCheck.Completeness`): discharge — algebra is
   now `⊢ᵐ`, so `morph-realize`/structural equality closes the `StrongElab` realize
   field like the other combinators. Remove the postulate.
5. **Downstream**: `RealizeAgrees` (cata `agree` case — was `⊥-elim`; keep or
   simplify), soundness (`m-cata` case), `IRTraceCorrect`/`CataLayer` if they read
   the old cata IR shape, apex `make certified`.
