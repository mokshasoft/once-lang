# Plan 0.118 — The simplest Spec

## 0. Why

The user (2026-10-14): the Spec should be the simplest mathematical statement of what Once is — readable
by a categorical mathematician (GOAL.md), with no implementation things in it ("iteration", "Honest",
encodings, proof helpers). Starting F3′1 (D314) showed the problem: one grade change touched ~25 files,
because the Spec presents the same things several times and carries the compiler's machinery.

## 2. The target: what a categorist expects to read

One object language, one signature functor, one core judgment, one meaning, one equality. In reading
order (plan 0.114's target order, kept):

**I. Objects**
- `Type` — Unit, Void, ×, +, graded ⇒, μF, νF (graded), Int, Float; type variables by de Bruijn index
  (`Ty m`), ground = `Ty 0`. No `rigid`, no deciders.
- `Type.Grade` — Quantity {0,1,ω} (semiring, order as a relation); Purity the chain `pure ⊑ act ⊑ eff`.
- `Type.Sub` — `<:` and `⊑π`, one rule per head.
- `Type.WellFormed` — base types, first-order functors, and `WellFormedSig`: an FFI operation has a
  first-order type, an arrow into `Unit`/`Void` is effectful, no FFI constant at `Unit`/`Void`
  (today's `Honest`, ~10 lines, no deciders).
- `Numerics` — the target parameter: `Int` is the width-n word (two's complement); `Float` is the
  format's values, exact-then-round arithmetic, decimal literals rounded half-even. Bit encodings out.

**II. Signature, effects, observation**
- `Signature` — Σ: operations with base argument and answer types; the functor
  `H_Σ X = Σ_op ⟦Arg⟧ × (⟦Ans⟧ → X)` (an empty answer halts); an event = operation + argument.
  Defined ONCE.
- `Effect` — `T X = μY. X + H_Σ Y` (returns), `T∞ X = νY. X + H_Σ Y` (need not stop), `embed : T ↪ T∞`;
  `M pure = Id`, `M act = T`, `M eff = T∞`; bind per grade, `sub` the monad morphisms along the chain
  (3 + 3 clauses; D307's "family of monads with morphisms"). Equality of `T∞` is bisimilarity.
- `Observation` — an interpretation (a history-dependent `H_Σ` handler), the first `n` events of a run,
  observational equality. This is GOAL's "correctness is the trace".

**III. The core**
- `Context` — contexts over `Ty m`, usage vectors (+, scaling, join, order).
- `Core.Syntax` — Church-annotated de Bruijn terms; the definitions signature and schemas.
- `Core.Typing` — ONE judgment `Δ ⊩ Γ ⊢[Ψ] t ∷ A ! π`. The server is not "iteration": it is the
  anamorphism into `Eff`, because `T∞ B` IS the final coalgebra of `B + H_Σ(−)`. Its coalgebra returns
  one layer, so the type language has that layer as a type, `Req A = H_Σ A` (D314); the rule and its
  law are fold/unfold's, not a new concept.
- `Core.Derived` — the categorical combinators (compose, curry, cata, ana, …) as λ-terms.
- `Core.Meaning` — `⟦_⟧ : ⟦Γ⟧ → M π ⟦A⟧` on derivations (one clause per rule; ∀ as the family of its
  closed instances); `⟦_⟧ᵛ` the one value domain; one graded ν.
- `Core.Program` — a program is a telescope of definitions (each typed once over its kinds, in its
  prefix) and a `main` whose type is `<: Eff Unit Unit` (D315); running it = its trace. ~40 lines.

**IV. The surface** (what a programmer writes, and what it denotes)
- `Syntax` — the resolved surface terms.
- `Grammar` — text → module, as a grammar over the Spec's OWN AST (not transcribed from the parser).
- `Resolution` — what each reference denotes (D136 shadowing), over the Spec's AST.
- `Elaboration` — ONE declarative relation `e ↝ t` (surface term to core term) whose side conditions are
  core typing; a definition's signature equals its principal type (D314). This replaces the 3-mode
  `Typing`, `Typing.Scope`, the `View` machinery and `Core.Translate`.

**V. Claims**
- `Correct` — unchanged.
- `Metatheory` — term model (let-β), subtyping/purity laws, effects, coherence, Freyd, fold/unfold
  universal properties (the server's included), totality as GOAL's guards (the server typed and running;
  no self-reference). The 7 mode-agreement fields go with the modes.

**Moves out** (to `Once.Metatheory`, `Once.Elaboration`, `Once.Adequacy`, …; never deleted while used):
everything in the "Machinery" row of §1, `Value`, `Res`, `Stream`, `Iterative`'s duplicate layer,
`GradedOps`' bridges, `Contract`'s key/list machinery (the Spec keeps "an interpretation implements Σ"),
the bidirectional checker's judgment (it becomes the CHECKER's specification, proved sound and complete
against `Elaboration`). **Deleted**: Guarded, every `eff⁺` clause, the F3a rules, `IOUnit`, the vacuous
totality predicates.

Rough size: I–III and V ≈ 2 000–2 500 lines; IV ≈ 1 000–1 500. (Estimate, not measured.)

## 3. Decisions (all approved by the user 2026-10-14, D316; 4 changed to one patch in one go)

1. **Does `correct` keep talking about source TEXT?** (D137, plan 0.114 kept it.) Recommended: yes —
   it is what "trust nothing" means — but with a grammar written over the Spec's own AST, so no
   `Once.Parser` import remains. Alternative: the Spec starts at the parsed module and the parser is
   trusted (smaller Spec, weaker claim).
2. **One declarative elaboration relation instead of the bidirectional surface judgment?** Recommended:
   yes. Cost: `correct`'s completeness half then needs the checker complete for a declarative relation;
   D314's principal types (signatures equal them) are what make that provable. Changes
   `Spec.Metatheory.TypeSystem`.
3. **One polymorphic core (`Ty m`, ground = `Ty 0`), no `rigid`?** Recommended: yes (deletes a full
   duplicate judgment). Touches D243's "typed once at rigid parameters" wording, not its meaning.
4. **Phasing and the in-flight F3′1 edits.** Recommended: make this plan the vehicle for D314/D315 —
   phase 1 = parts I–III (+ the server as unfold into Eff, + `main <: Eff Unit Unit`), phase 2 = part IV,
   phase 3 = the grammar. Each phase: Spec diff → user approval → `spec-approve` → one red commit →
   follow the red. Of the uncommitted F3′1 edits, the grade chain (Grade, Sub) is kept; `Req`/`ReqD` in
   `Value`/`Honest`/`DecEq`/… is reverted and re-done once, in `Signature`.

## 4. Not changed by this plan

**Drift ledger — every change in meaning or accepted texts (all decided):**
* Grades are the chain; the old `·p` table equals the join on it (D314). `fold`'s `pure ⊑ π` premise
  always holds now and is gone.
* `iter` (seeded, guarded step) → `anaEff c : A ⇒[eff] B`, the anamorphism of a round
  `A ⇒[act] (B + Req A)`; `request` is `Req`'s former (D314/D316). Surface syntax for them: F2 (names open).
* `⊢sigop⁺`, `t-var-resolved-guard`, `eff⁺`, `T⁺`, `ν⁺` deleted (D314).
* A declaration reference is typed by its `DeclType` in Σ; honesty is a property of the program's signature
  (`WellFormed Σ`), not a premise per reference. A call into `Unit` is answered `tt` by the Interpretation
  (the old run did not ask) — the same trace.
* Definitions: a signature must be the body's principal type (no strictly smaller type checks; D314); `main`
  is the definition named `main` with type `<: Eff Unit Unit` (D315). `IO` no longer parses (D315).
* Surface: usage is no longer bookkept in the surface rules (its only constraint, `q′ ≤ q`, is the core's);
  every global reference is resolved before typing (the old `RVar`/`RQualified` typing rules became
  resolution); an unknown alias `x@a` resolves to the canonical name `a.x` (the old key lookup, same result).
* Syntax tree: no string literals (never typed), no `RAna` (never parsed), no float offsets, `RNeg`, owner-free
  `DSignature`, alias bodies as `PolyType`.
* Unchanged: every other typing rule and the core term it elaborates to; `let`, weakening, the fold's and
  unfold's evaluation order; the numerics.

**Claims (`Spec.Metatheory`)**: all old claims restated over the new definitions, plus the server's universal
property (`unfoldEff-unfold`/`-unique`, replacing `iter-unfold`/`-unique`). Dropped: the surface claims about
usages (the surface no longer has them) and the vacuous `finite`/`productive` predicates (true by
construction of `T`/`T∞`).

**Moved out**: the old Spec is preserved verbatim under `Once.Legacy.Spec.*` (imports renamed; the shared
`Name`, `Word`, `Numerics`, `Bool`, float modules and `Correct` are the Spec's), for the implementation to
migrate from while the red is followed; then it is deleted.
