> deviations from the original design:
>
> 1. **`EffectClass` → `EffectShape (B : Type)`** with coherence baked
>    into the constructors: `Emits`/`Halts` each carry a `B ≡ Unit`
>    proof argument. A producer cannot declare a non-Unit-codomain
>    SigOp as `Halts`/`Emits` — the constructor literally doesn't
>    construct. This subsumes the planned separate coherence-law fields
>    and is cleaner for proof use (pattern-matching `Halts refl`
>    substitutes `B := Unit` directly, after which `semM si x ≡ tt` by
>    η for ⊤).
>
> 2. **Pure stays a smaller per-name postulate** (`pure-sigop-output` +
>    `pure-sigop-respects-semM`), confined to the `Pure` dispatch case.
>    The plan's optimistic "wrap `semM si x` into the appropriate
>    location form" doesn't have a generic implementation: Sum/Pair
>    codomains require allocation that depends on type structure, and
>    no generic `M.⟦B⟧ → StoredValue` exists at the SMCore layer.
>    Adding `SV-SigOpResult` as a new `StoredValue` constructor would
>    touch ~825 pattern-match sites — rejected.
>
> Net effect: **three postulates reduced to two Pure-confined per-name
> discharge targets** (not "three removed, none added"). Halts/Emits
> paths are now fully postulate-free. The trusted base is *classified*
> (Pure-only) rather than blanket. New `Halts`/`Emits` ops add **zero**
> postulates; new shape tags (e.g. `ReadsWorld` for Layer 1+) still
> add one generic CCC dispatch case + one `respects-semM` lemma.

# Plan 0.25: SigOp effect-class contract — discharge `exec-sigop-*` postulates without leaking machine internals

## The gap (why this plan exists)

Three CCC-internal postulates currently linger:

- `exec-sigop-output  : SigOpInfo A B → LocState FS → StoredValue FS` (`SMCore.agda` ~1167)
- `exec-sigop-halts   : SigOpInfo A B → LocState FS → Bool`           (`SMCore.agda` ~1167)
- `exec-sigop-respects-semM` (`IRTraceCorrect.agda:528`) — the value-level "abstract machine realises `semM`" axiom.

They are CCC-level axioms about something CCC *cannot in principle know* — to the IR, a SigOp is **opaque**; only the producer knows what `linux.exit` actually does. So the postulates are a category error: CCC is asserting facts about implementations it doesn't see.

The obvious fix ("make the producer supply the implementation + correctness proof") naively requires the producer to mention `LocState` / `StoredValue` / `Input1` / `SV-Ptr` — **leaking CCC's internal machine representation into producer-land**. That's worse than the postulates.

## The principle

> A SigOp's observable behaviour is determined by its `semM` plus its **effect shape**. Machine output, halt flag, and trace-event payload are *consequences* of those two — CCC derives them generically.

The producer declares **semantics + classification**; CCC implements the rest *once per shape* and proves correctness *once per shape*. The producer never sees machine internals; CCC never postulates per-SigOp facts.

This is `consequence-form-invariants` applied to the SigOp contract: a syntactic per-SigOp stand-in (`LocState → StoredValue`) is replaced by the actual consequence the consumer needs (a small categorical fact about effect shape).

## Design

### EffectClass (Layer 0; grows additively)

```agda
data EffectClass : Set where
  Pure   : EffectClass    -- arith.*: computes a value via semM; no event, no halt
  Emits  : EffectClass    -- (future) linux.write: records event, continues, R ≡ Unit
  Halts  : EffectClass    -- linux.exit: records event, halts, R ≡ Unit
```

Layer 1+ adds tags as new SigOp shapes earn them — e.g. `ReadsWorld` for `linux.read` (records event, **nondeterministic** value flows into Output, R ≠ Unit). Each tag is closed, named, and earns its own one-shot CCC lemma. There is no open-ended escape hatch; an unfit SigOp **forces** a new tag, which forces a new lemma. That is the "faithful classification" discipline made enforcement.

### Extended `SigOpInfo`

```agda
record SigOpInfo (D R : Type) : Set where
  field
    name      : String
    semI      : I.⟦ D ⟧ → I.⟦ R ⟧
    semM      : M.⟦ D ⟧ → M.⟦ R ⟧
    effect    : EffectClass
    -- Coherence laws (proven by the producer, derivable for current ops):
    --   effect ≡ Halts → R ≡ Unit
    --   effect ≡ Emits → R ≡ Unit
```

Producer-facing surface = `name + semI + semM + effect`. Nothing about registers, locations, or stored values.

### Generic CCC dispatch

`SMCore.exec-abstract (instr-sigop si)` is **redefined**, dispatching on `effect si`. The previous postulates become **definitions**:

| effect  | machine-output                      | machine-halts | trace-event recorded |
|---------|-------------------------------------|---------------|----------------------|
| Pure    | `wrap-in-loc (semM si x)`           | `false`       | none                 |
| Emits   | `unit-value`                        | `false`       | `mkEvent si x`       |
| Halts   | `unit-value`                        | `true`        | `mkEvent si x`       |

Where `x` is read from `Input1` via the existing `readLoc` + the `ValidAtWF` witness already in scope at the call-site (no producer involvement).

### `exec-sigop-respects-semM` collapses to per-class lemmas

Proven **once per class** inside CCC, by reduction:

- `Pure`:  `Output` holds `wrap-in-loc (semM si x)` by construction → `ValidAtWF` of `semM si x` at the output location holds by the existing `ValidAtWF` injectivity for the wrap. Proof: a few lines, no postulate.
- `Halts` / `Emits`: `R ≡ Unit`, `semM si x = tt`, `ValidAtWF` of `tt` at the unit-location is `Unit-WF` — trivial.

The CCC-level `exec-sigop-respects-semM` postulate is then **removed** (no more lingering axiom) and replaced by `case effect si of { Pure → respects-Pure; Halts → respects-Halts; Emits → respects-Emits }`.

## Why this plan goes BEFORE Plan 0.24 Phase D

Plan 0.24 Phase D ("bridge 1: `obs ≈ absTrace`") rests on `exec-sigop-respects-semM` whether or not we extend to traces. Discharging it first means bridge 1 builds on a **proven** per-class fact, not a postulate, and the bridge work then never has to argue about per-SigOp machine output — it just dispatches on `effect`.

## Phases

### Phase A — `EffectClass` + extended `SigOpInfo`
- Add `Once.CCC.SigOp.EffectClass` (the data type + helper predicates).
- Extend `SigOpInfo` (`Once.CCC.SigOp.Info`) with `effect : EffectClass` and the two `Unit`-coherence fields.
- Migrate existing constructors / `mk-info` callers in a single sweep (every `mk-info` site gains an `effect` arg). Scaffold with `Pure` placeholder if a site is unclear, then refine.
- **Exit gate:** typechecks; every existing SigOp declares a class.

### Phase B — Generic per-class dispatch in `SMCore`
- Rewrite `exec-abstract (instr-sigop si)` to dispatch on `effect si`.
- **Delete the `exec-sigop-output` / `exec-sigop-halts` postulates.** Their definitions are now inline in the dispatch.
- Trace recording is *not yet* threaded through the abstract machine here (that's Plan 0.24's job); for now, just confirm the value-level behaviour matches the previous postulates' intent. The instr-sigop step is still pure (LocState×AllocState → LocState×AllocState).
- **Exit gate:** SMCore typechecks without the two postulates; existing IR tests still pass.

### Phase C — Per-class `respects-semM` lemmas
- In `IRTraceCorrect`: prove `respects-Pure`, `respects-Halts`, `respects-Emits` directly (no postulate). Each is a few-line reduction proof using the existing `ValidAtWF` constructors.
- Replace the existing `exec-sigop-respects-semM` postulate body with a dispatch on `effect si` that returns the corresponding per-class lemma.
- **Exit gate:** `exec-sigop-respects-semM` is **no longer a `postulate`**; it's a `case`-on-class definition. `make agda` green for IRTraceCorrect + dependents.

### Phase D — Migrate Layer-0 SigOps to declare class

- `linux.exit` → `effect = Halts`.
- (No `Emits` users in Layer 0; tag stays declared for the next layer.)
- Verify per-SigOp coherence laws (`Unit` codomain for `Halts`) close by `refl`.
- **Exit gate:** `make malonzo` green; arith-simple.once → exit 13 still works.

### Phase E — TCB box update

- Note in `Once.CCC.SigOp.Info` header that adding a new `EffectClass` tag requires (a) a new SMCore dispatch case and (b) a new per-class `respects-semM` lemma — *that* is the cost of staying faithful.
- **Exit gate:** `git grep -n "postulate" formal/Once/CCC/Codegen/IRTraceCorrect.agda formal/Once/CCC/Machine/SMCore.agda` shows the three obligations gone (only unrelated postulates remain, if any — to be enumerated).

## Correctness statement & TCB

**Discharged here (was postulate, now proven):**

- `exec-sigop-output` (was postulate) → **definition** dispatching on `effect`.
- `exec-sigop-halts` (was postulate) → **definition** dispatching on `effect`.
- `exec-sigop-respects-semM` (was postulate) → **proven** by per-class reduction lemmas.

**Trusted base unchanged:**

- `EffectClass` is a faithful classification of the SigOp shapes we model. Enforced *syntactically* by the closed enum: a new SigOp shape forces a new tag + a new generic lemma — no silent unfaithfulness. Not a postulate; a design discipline made enforcement.
- `SigOpInfo.semM` continues to be the value-level spec of the operation (per-producer, e.g. `Arith.SigOp.Block`'s definitional `semM`).
- All existing CCC and machine-side trust (calling convention, `ValidAtWF` constructors, etc.) is unchanged.

**Net effect:** three CCC-level postulates removed; no new postulates added; no machine internals exposed in producer contracts. The SigOp interface tightens from "trust the producer to magically realise `semM` on hardware" to "the producer declares `(semM, effect)` and CCC realises it generically, provably."

## Risk & blast radius

- **Every `mk-info` callsite gains an `effect` argument.** Mechanical sweep; `Pure` is the right default for the bulk (arith), `Halts` for `linux.exit`. Estimate: ~10–20 sites for current Layer-0 surface.
- **Phase B reshapes `SMCore.exec-abstract`'s single most-cited clause.** Downstream users (IRTraceCorrect, DirectSimulation, codegen targets) consume the *result*, not the postulates, so they should not need changes; but any place that explicitly invoked `exec-sigop-output`/`exec-sigop-halts` by name needs to be re-pointed at the new definitions.
- **The per-class lemmas are small but new proof work.** `Pure`'s lemma is the only non-trivial one (a few lines threading `ValidAtWF` for the wrap). Triviality of `Halts`/`Emits` rests on `R ≡ Unit`.

Per `feedback_blast_radius_not_a_constraint`: the wide sweep is the principled price; the alternative is keeping the postulates indefinitely.

## What this plan does **not** do

- Does not thread a trace through `SMCore.exec-abstract`. That's Plan 0.24's job (Phase D / "extend `IRTraceCorrect`/`Corresponds` with a `List SigOpEvent` accumulator"); this plan only changes the *value-level* dispatch so that the future trace extension has clean foundations.
- Does not introduce `ReadsWorld` or other Layer-1+ tags. Tags arrive when the SigOps that need them arrive.
- Does not touch `module-to-asm-correct` (Bridge 2 / DirectSimulation territory) or `T0`.
