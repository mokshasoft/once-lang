# Plan 0.93 — The machine relation is a FUNCTION ON TYPES, not a datatype

## 0. The one measurement

`block-runs` is FALSE and load-bearing. Four designs to replace it have been
refuted or shown impossible, each for a different reason, each only visible
after the previous died:

    block-runs      state → syntactic, hypothesis determines nothing   FALSE   D213
    CodeResolves    state → the body's TEXT                            FALSE   D216
    CodeWF          state → the label alone                            sound, WRONG HALF
    BlockAt-in-witness                                                 NO-GO   (supplies
                    layout where a BEHAVIOURAL fact is needed; and
                    `block-runs` is the ONLY producer of a `CalleeRun`
                    in the development — `grep -rn 'callee-run'` returns
                    one hit, the constructor declaration, never applied)

Progress is ONE number: the count of postulates in the machine-correctness
layer. It goes DOWN only when the thing they stand in for becomes provable,
never by moving an assumption somewhere else.

## 1. THE ONE FIXED POINT

**Correctness is the effectful-SigOp trace.** `Behavior = ℕ → List SigOpEvent`,
indexed by EVENT COUNT (D058's content, which survives regardless of what else
in the log is revised). The compiled binary's sequence of effectful SigOp events
must equal the source's. That is the claim; it cannot move.

Everything else in the decision log is a prior decision, and prior decisions get
reverted — D057 was corrected by D058, and D216 was corrected by D216 the same
day it was written. **Do not treat the log as axioms.** Treat it as evidence
about what was tried and what happened.

## 2. THE DEFECT

    data ValidAtWF : AllocMode → AllocState {FS} →
         {A : IRTy} → ⟦ A ⟧ → ValueLocation FS → LocState FS → Set where

`ValidAtWF` is a **`data`** — an inductive family INDEXED by the type. A data
constructor can only ASSERT facts; it cannot RECURSE ON THE INDEX. So the
closure constructor is structurally incapable of saying anything beyond
syntactic facts about cells, and therefore **cannot pin the function a closure
denotes**.

That is not a quirk. It is machine-checked (D217,
`Once/Probe/ClosureAmbiguous.agda`): two `ValidAtWF` witnesses at the SAME cell,
state and label, for `const fits-int (+ 0) ∘ terminal` and
`const fits-int (+ 1) ∘ terminal`, both typecheck. **One cell, two denotations.**

Everything else follows from that one choice:

* `BodyCorrect` tried to put behaviour on a constructor — a genuine cycle,
  because `data` cannot recurse on its index. Removed (D170), correctly.
* `program-bound` / `ir-size` tried to well-found it by SIZE — false, because a
  closure can name a body bigger than the code that built it. Deleted (D214).
* `block-runs` axiomatised the resulting hole — false (D213).
* `CodeResolves`, `CodeWF`, `BlockAt`-in-witness all tried to recover a
  BEHAVIOURAL fact from a relation that structurally cannot carry one.

**The missing thing was never a premise. It was that the relation should have
been a function on types.**

### Why the earlier 0.93 draft was wrong

It proposed splitting `AbstractTrace` into unlinked/linked forms and lowering
labels to ADDRESSES so `do-call` could jump instead of scan. Rejected: the
general layer is ALREADY label-addressed — `SV-Code : LabelId → StoredValue`,
`find-thunk` returns a FETCH INDEX into the abstract trace (pinned by
`find-thunk-sound`), and every address is minted arch-side (`AddrMap.cmap`,
`lea rax (rip+label n)`). Lowering belongs in the arch backend and the
assembler, and it is already there. Labels stay labels all the way up.

## 3. THE TEMPLATE — and it is already in this repo

`Once/Adequacy/MeaningRelation.agda` does the right thing one layer up:

```agda
RelV : ∀ (A : Type) → ⟦ A ⟧ᴰ → ⟦ A ⟧ᴰ → Set
RelT : ∀ (A : Type) → T ⟦ A ⟧ᴰ → T ⟦ A ⟧ᴰ → Set   -- forward-declared, mutual

RelT A t₁ t₂        = ∀ n → (projTrace t₁ n ≡ projTrace t₂ n)
                          × RelV A (valueT t₁ n) (valueT t₂ n)
RelV Unit    _ _    = ⊤
RelV Int     x y    = x ≡ y
RelV (A * B) (a₁ , b₁) (a₂ , b₂) = RelV A a₁ a₂ × RelV B b₁ b₂
RelV (A ⇒ B) f g    = ∀ {a b} → RelV A a b → RelT B (f a) (g b)
RelV (μ-type F) x y = x ≡ y
RelV (ν-type F) x y = x ∼ᵈ y
```

Four properties to copy exactly:

1. **Recursion on the TYPE**, mutual value/computation, forward-declared.
2. **The arrow is a Π over related inputs** — "related arguments map to related
   computations", never an equality of functions.
3. **The computation relation is indexed by the EVENT BUDGET** (`∀ n`), which is
   the observable's own index. No steps, no size, no fuel.
4. **At `μ` and `ν` the recursion STOPS** — `≡` and `∼ᵈ`. That is why the whole
   definition typechecks with NO `TERMINATING` pragma. The machine instance must
   stop at the same two places.

## 4. THE TARGET

The same shape, one instance lower: semantics versus MACHINE.

```agda
RelV : ∀ (A : IRTy) → ⟦ A ⟧ᴰ → StoredValue FS → LocState FS → Set
RelT : ∀ (B : IRTy) → T ⟦ B ⟧ᴰ → FlatState → Set

RelT B comp fs      = ∀ n → (events of the run from fs ≡ projTrace comp n)
                          × RelV B (valueT comp n) (the result) (the settle state)
RelV (A ⇛ B) f sv s = ∃[ ℓ ] ( sv holds code ℓ
                             × ∀ a av s′ → RelV A a av s′
                                         → RelT B (f a) (entering block ℓ with av from s′) )
```

and the theorem is ONE induction on the IR:

    ir-correct : ∀ {A B} (ir : IR A B) {x av s}
               → RelV A x av s
               → RelT B (evalᴰ ir x) (run of `emitted ir` from s)

* **`apply`** discharges FROM the arrow clause. No lookup, no `find-thunk`, no
  `CalleeRuns`, no `block-runs`. The relation IS the fact.
* **`curry`** ESTABLISHES the arrow clause from its IH on `body` — a genuine
  subterm, so the recursion is honest.

**Labels stay labels.** The arrow clause says *entering block ℓ behaves*. WHERE
ℓ sits in the linked image is a separate, purely SYNTACTIC layout lemma — S2's
`BlocksAt` / `entry-blocks` shape, state-free, discharged once by induction over
`blocks-layout`. That obligation survives this plan and is the only syntactic
one left.

## 5. TOP-DOWN ONLY

Same rule as 0.91, and it earned its place there (D214):

> Change a TYPE, never blank a BODY. A hole suppresses the module interface, so
> consumers fail to LOAD rather than to typecheck — one import error, no
> work-list. A changed statement fails at every CALL SITE, and that list is the
> work-list, free.

And the rule this plan exists to enforce:

> **No short-cut abstractions.** A postulate is admissible only where the thing
> it stands for is genuinely outside the system (the assembler, the loader). A
> postulate standing in for something the system SHOULD be able to say is a
> defect in the abstraction, and it will not be dischargeable later — the four
> refuted attempts in §0 are what that looks like.

## 11. `Str` / `Buffer` — OUT OF SCOPE, and why that is safe (2026-09-18)

**Decision (project owner): leave them out completely. Pretend they do not exist.
Proof gaps related only to them may be postulated.** S3 does NOT need a
representation decision first; an earlier note in this plan said it did, and that
note is withdrawn.

Why it is safe, checked rather than assumed:

    strLit s = SigOp (str-lit-info s) ∘ terminal : IR Γ Str   Surface/Elaborate.agda:70-71
    data FitsInReg : Type → Set where
      fits-int   : FitsInReg Int
      fits-float : FitsInReg Float                            Type.agda:383-385
    obs-correct-sigop {A} {B} si with fits-in-reg? B | readable? A
    ... | nothing | _ = obs-correct-sigop-rest si             SigOp.agda:293-295

`FitsInReg` has no `Str` constructor, so `fits-in-reg? Str` is `nothing` and every
string routes to `obs-correct-sigop-rest` — an existing NAMED POSTULATE. There is
no PROVED path that reaches `RelV` at `Str`, so nothing in the tree is vacuously
true today.

**THE INVARIANT THIS RESTS ON, and it must be restated whenever it is relied on:**

> `RelV Str = RelV Buffer = ⊥` is sound ONLY while no theorem is instantiated at a
> string-containing type. It is NOT conservative. `RelV` occurs NEGATIVELY in the
> arrow clause, so a discharge at `Str ⇛ B` would be VACUOUSLY TRUE rather than
> hard — D217's defect, re-entering at the one constructor this plan exists to
> fix. The same leak reaches `μ` through `K Str`
> (`μ-type (K Str ⊕ (K Str ⊗ Id))` is a string list).

So: if a future clause proves something at `Str`, IT MEANS NOTHING. That is not a
reason to avoid the decision forever — it is the reason the decision, when it
comes, is a REPRESENTATION decision (what can a `StoredValue` hold?) and not a
proof task.

### AND A CORRECTION TO §11's FIRST DRAFT

It said strings route to "an existing named postulate", which reads as though
`obs-correct-sigop-rest` were about strings. It is not. The DISPATCH is properly
enumerated — five rows, no variable catch-all (SigOp.agda:293-299) — but FOUR
distinct reasons route to that ONE postulate:

    fits-in-reg? B ≡ nothing     the result is not register-resident
    readable? A ≡ nothing        the input cannot be materialised
    Emits _                      effectful SigOp
    Halts _                      halting SigOp

and `FitsInReg` has only `fits-int`/`fits-float`, so the first row is "B is not
Int or Float" — covering `Unit`, `Void`, pairs, sums, closures, `μ`, `ν` AND
strings. Strings are a small corner of a large residual.

**OWED (not scheduled): split `obs-correct-sigop-rest` by reason.** The four are
different obligations with different futures — a representation gap, a
readability gap, and two effect-shape gaps — and one name for all four means the
ledger cannot say which part is which. This is the `enumerate over catch-all
postulate` rule applied to the DESTINATION rather than the dispatch: enumerating
the rows is not enough if they all land on one axiom.
