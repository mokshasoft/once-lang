# Plan 0.59 — Oracle principality + coverage (the D072 ledger)

Status: DRAFT (created 2026-07-13 at plan-0.58 close). Prereq: D072 landed
(decision-log D072 + its Implementation section; branch `ocp-0006-once-spec`).

## SCOPE GREW 2026-09-02 (found by plan 0.81) — read this first

    ModuleTyped m = ModuleTyped-ef m (C.extractFunctions (C.extractAliases m) m)

**The spec's notion of "this module is well-typed" is DEFINED BY RUNNING THE
FRONT END.** `extractFunctions` calls `siglessSchema`, i.e. this plan's oracle
(`Once/TypeCheck/Principal.agda:616`), so the oracle sits inside `Typed` — the
`CorrectCompiler` field that says WHAT the theorem is about.

That makes this plan bigger than "prove the oracle principal". It is also
**"make `ModuleTyped` independent of the front end"**: `ModuleTyped` should be
an ∃ over declarative derivations plus a declarative account of which
definitions are polymorphic, not the result of running `extractFunctions`.

Two consequences already visible:

  * Plan 0.81 could not specify the resolver's initial scope independently.
    `polyDefNames` (which stays bare) is the same classification, sharing
    `siglessSchema` by construction, so `_⊢R_` uses it — the oracle enters the
    boundary ONCE rather than twice. Specifying it separately would have cost
    an abstract `HasSchema` plus two bridge residuals to protect `⊢R` from a
    dependency `ModuleTyped` already has. Recorded, not papered over: see
    `Once/Spec/Program.agda`'s header note and plan 0.81.
  * The same argument applies to `ParsesText`, one layer down: it is the
    independent grammar relation, but its leaves still mention executable
    helpers (`skipNewlines toks ≡ just …`, `headK c ≡ hkWS`). Extracting the
    front-end relations from their bridge modules is the sibling arc.

Sizing note: this is the LAST place an executable appears inside the trust
boundary's own statements. Closing it is what would let `Once/Spec/**` be read
without following a function into the implementation.

## Goal

Upgrade the D072 principal-type oracle from "untrusted but validated" to
"provably complete on its fragment", and widen the fragment. The certified
soundness story is already unconditional (check-after-infer); this plan buys
the DIAGNOSTIC guarantee — "rejection ⇒ provably untypeable (in the fragment)"
— and closes the v1 coverage gaps.

## Why this is its own plan (sizing, from the 2026-07-13 assessment)

- The naive statement ("∃T typeable ⇒ principal finds the mgu-type") is FALSE
  for v1 — cata/In/ana bodies are typeable but declined. The theorem must be
  stated over a DEFINED FRAGMENT; formalizing the fragment is part of the work.
- mgu-completeness of first-order unification is a known paper-sized Agda
  development (cf. McBride's structurally recursive unification); our
  fuel-bounded `unify` additionally needs a fuel-sufficiency bound (fuel ≥
  f(problem size) ⇒ no spurious failure).
- The completeness induction relates `pInfer` to EVERY kernel derivation
  (~40 rules over ⊢ᵢ/⊢ᶜ/⊢ᵐ/⊢ᵍ, plus t-subsume and the quantity order).

## Milestones

- **C1 — coverage: functor metavariables.** Extend the metavariable language
  with PolyFunctor metas so cata/In/ana bodies infer (the last with-shape the
  oracle declines). Un-PEND / add tests.
- **C2 — coverage: prefix-context routing.** `siglessSchema` currently runs in
  the EMPTY context, so sig-less bodies referencing earlier USER defs don't
  generalize. Thread the accumulated schema prefix through
  `extractFunctions-go`/`pdn-go` (mirror-proof cost: the D071/D072 routing
  pattern, 3 Canon mirrors).
- **C3 — coverage: RQualified leaves** (pre-resolver qualified refs) via the
  same import-key the elaborator uses.
- **P1 — unifier metatheory.** `unify` soundness (result unifies), then
  mgu-ness, then fuel-sufficiency. Self-contained module; consider porting the
  structural-recursion presentation instead of proving fuel bounds.
- **P2 — fragment definition + pInfer completeness.** `InFragment e` predicate;
  theorem: kernel-typeable ∧ InFragment ⇒ pInfer succeeds with a type that
  subsumes the derivation's type (needs P1).
- **P3 — principality.** Substitution ordering; `principal` returns the most
  general type up to renaming; corollary: `principal ≡ nothing ∧ InFragment ⇒
  no kernel derivation exists` (the diagnostics guarantee).
- **P4 — wire the corollary** into the error message ("provably untypeable"
  vs "outside the inference fragment — add a signature").
