# Plan 0.23: Word-based arith semantics + parameterised CPU bridge

> Revised 2026-05-28 to reflect **D054** (`Int` = signed, modular
> `Word`; mathematical integers are a separate future `BigInt`) and
> **D055** (`/` and `%` are total, RISC-V semantics, no trap). Those
> decisions reshaped this plan substantially: the ℤ↔Word *encode*, the
> *no-overflow* side conditions, and most of the *refinement proofs*
> are gone. What remains is (a) moving the arith machine off ℤ onto
> `Word`, (b) the division guard for trapping targets, and (c) the
> parameterised-bridge plumbing for multi-target + `--safe`.

## Goal

Make the arith pipeline's semantics match D054/D055 and discharge the
remaining arith postulates.

D054 collapses most of the old work: once Once's `Int` *means* the
CPU's `add` (modular `Word`), source `+`/`-`/`*` and machine
`add`/`sub`/`mul` are the **same operation**, so the per-op refinement
statements reduce to (essentially) `refl` and there is no encoding and
no no-overflow precondition. The genuine remaining proof content is
**division** (D055): on trapping targets (x86, ARM) the backend emits
a guard that produces RISC-V's defined values; that guard must be
shown to refine the total `/` semantics.

The bridge record survives, but as *plumbing* — it injects each
target's `State` / `emit` / `exec-target` (so the pipeline is generic
over the target and `--safe`-clean), not a stack of hard arithmetic
proofs.

User-observable signals:

1. The arith machine's registers are `Word`, not ℤ. `Int`'s
   denotation is `Word`; the ℤ `eval-arith` survives only as the
   parked spec of a future `BigInt`.
2. `Once.Arith.Backend.Correct` ships with zero `postulate` blocks for
   x86-64.
3. Stub backends (x86-32, RISC-V) exist with postulated bridges.
4. `mkPurePrimResult` (Helper.agda) ships with zero `SMP.!!` holes.
5. `make agda-safe` type-checks the designated subtree.
6. Arith tests still pass; the emitted binary is unchanged for
   non-dividing programs, and division gains a guard on x86.

## Context

Plan 0.20 landed the arith block recogniser + abstract machine +
Validity proof, all in **ℤ**. D054 says that was the wrong type for
the *machine* layer: ℤ is the meaning of a future `BigInt`, while
`Int` is a modular `Word`. So:

- **Abstract machine (ℤ → `Word`).** `AbsState` / `AbsInstr` / `IR`
  move their register/scratch type from `Maybe ℤ` to `Maybe Word`, and
  the ops become modular. `eval-arith` (ℤ) is re-pointed to a `Word`
  evaluator. The Validity proof (`compile-go-correct`) re-points with
  it — verified to be a **mechanical operator swap** (the proof is
  op-agnostic: pure `trans`/`cong`/`cong₂` plumbing, no ℤ algebra).
- **Refinement layer.** With source op = machine op, the 9 per-op
  refinement statements in `Once.Arith.Backend.X86.Correct` collapse;
  the only non-trivial one is division (D055).
- **Boundary layer.** `mkPurePrimResult` has two `SMP.!!` holes hiding
  a `mov-to-output ∷ []` vs `instr-sigop si ∷ []` trace mismatch. This
  is **orthogonal** to D054/D055 and still needs the fix.
- **block-semM (Block.agda):** 6 per-ctor postulates, now dischargeable
  as a `Word` evaluator (Phase 0).

### What CPU semantics already exists

```
formal/Once/CCC/Target/X86-64/Semantics.agda
formal/Once/CCC/Target/X86-32/Semantics.agda
formal/Once/CCC/Target/RiscV64/Semantics.agda
```

Each provides `State`, `execInstr`, `step`, `exec`, clause-by-clause
against the ISA (CompCert / Sail convention). These are the trust
point; this plan wires the arith machine into them, it does not add a
parallel semantics.

## Decisions

### D-cpubridge-1: `BackendBridge` is a target-parameterised record (plumbing)

Lives in `Once/Arith/Backend/Bridge.agda`. Post-D054 its fields are:

```agda
record BackendBridge : Set₁ where
  field
    State       : Set
    concretise  : ∀ {sh} → ArithAbsState sh → State   -- Word → State, plumbing
    emit        : AbstractInstr → ProgramFragment
    exec-target : ProgramFragment → State → Maybe State
    -- per-op refinement; for add/sub/mul these are ~refl on x86-64
    reg-add-correct : … ; reg-sub-correct : … ; reg-mul-correct : …
    -- division: backend emits the D055 guard; this field is the real
    -- proof that the guard refines total Word division.
    div-correct : …
```

Gone vs. the pre-D054 design: the two's-complement `encode`, the
`*-fits` no-overflow predicates, and the `NoOverflow` preconditions.
`concretise` is now `Word → State` plumbing with no numeric
conversion.

### D-cpubridge-2: `Once.Arith.Backend.Correct` parameterised on the bridge

`module Once.Arith.Backend.Correct (b : BackendBridge)`. `refine`
dispatches each `AbstractInstr` to the matching bridge field. No
`NoOverflow` argument; no `postulate`.

### D-cpubridge-3 / -4: per-target instances; stubs postulate

```
Once/Arith/Backend/X86/Bridge.agda      real  (--safe)
Once/Arith/Backend/X86-32/Bridge.agda   stub  (postulates, not --safe)
Once/Arith/Backend/RiscV64/Bridge.agda  stub  (postulates, not --safe)
```

x86-64 proves its fields; add/sub/mul are near-`refl`, `div-correct`
is the real work (the guard). Stubs postulate their fields in their
own non-safe module.

### D-cpubridge-5 / -6: `--safe` boundary + multi-target driver

Interface, `Correct`, `Boundary`, and the x86-64 bridge are `--safe`.
`Once.Compile.compileFunWithTarget` dispatches on the `Target` tag to
select the bridge instance; the driver is non-safe (imports stubs).

### D-cpubridge-7: `block-semM` over `Word` (Phase 0)

Structural recursion mirroring the `Word` evaluator (modular ops; `/`
`%` per D055). Closes Block.agda's 6 postulates.

### D-cpubridge-8: `mkPurePrimResult` reworked for `instr-sigop`

Unchanged by D054/D055. Change `trace` to `instr-sigop si ∷ []`,
re-derive the trace effects from a bridge `sigop-instr-effect` field,
collapse the two `SMP.!!` holes.

### D-cpubridge-9 (NEW): division guard (D055)

Total `/` `%` need RISC-V's defined results on every target.

- **RISC-V:** emit `div`/`rem` directly; matches by spec.
- **x86 / ARM:** emit a guard (test divisor; detect `INT_MIN / -1`)
  that produces `a / 0 = -1`, `a % 0 = a`, `INT_MIN / -1 = INT_MIN`,
  `% -1 = 0` instead of the trapping `idiv`. `div-correct` proves this
  guard refines the total semantics. Guard elidable when the divisor
  is statically nonzero and not the overflow case.

## Implementation phases

Each phase ends with `make agda` green and tests passing.

### Phase 0 — `Word` type + `block-semM`

1. Define `Word` (lean residues: ℕ in `[0, 2ⁿ)` with `mod` per op —
   CompCert-style, keeps ring algebra; revisit vs `Fin`/`BitVec`).
2. Define the `Word` evaluator and discharge `block-semM`'s 6
   postulates over it.

### Phase A — Move the abstract machine ℤ → `Word`

1. `AbsState` / `AbsInstr` / `IR`: registers/scratch `Maybe Word`;
   ops modular; `/` `%` per D055.
2. Re-point `eval-arith` to the `Word` evaluator.
3. Re-point `compile-go-correct` — mechanical operator swap (proof is
   op-agnostic). Retain the ℤ `eval-arith` as the parked `BigInt` spec.

### Phase B — `BackendBridge` interface

New `Once/Arith/Backend/Bridge.agda` per D-cpubridge-1. `--safe`.

### Phase C — x86-64 bridge

`concretise` plumbing; add/sub/mul refinement ~`refl`; **`div-correct`
guard proof** against `X86-64.Semantics.execInstr`. No postulates.

### Phase C' — stub bridges (x86-32, RISC-V)

`concretise` defined; refinement fields postulated in their own
non-safe modules.

### Phase D — `mkPurePrimResult` rework (Helper.agda)

Per D-cpubridge-8.

### Phase E — Parameterise `Correct` + `Boundary`; `--safe` boundary

Convert both to `(b : BackendBridge)`; add `{-# OPTIONS --safe #-}` to
the safe subtree; add the `agda-safe` make target.

### Phase F — Multi-target driver

`compileFunWithTarget` selects the bridge by `Target` tag. Emit the
division guard on x86 (Phase C); native `div`/`rem` on RISC-V.

### Phase G — Test alignment

Arith tests pass (`arith-simple → 13`, etc.). Add a division test
exercising `a / 0`, `INT_MIN / -1` and confirm the RISC-V-defined
results on x86 (no SIGFPE).

## Risks / open questions

1. **`Word` representation.** Residues vs `Fin 2ⁿ` vs `BitVec n`.
   Lean residues for proof ergonomics; decide in Phase 0.
2. **Validity re-point.** Asserted mechanical (op-agnostic proof);
   confirm when Phase A lands — if any case secretly used ℤ algebra it
   surfaces here.
3. **Division guard codegen.** New emit path on x86/ARM; the
   `INT_MIN / -1` case is easy to forget. Test explicitly.
4. **Agda module-as-value.** Threading the bridge through a
   target-dispatching `Once.Compile` may need sibling instantiations
   rather than one polymorphic function. Phase F decides.
5. **MAlonzo extraction.** The per-target dispatch must extract into
   the existing Haskell shape; may need a `target-tag` field.

## Non-goals

- `Fin 2ⁿ` encoding tax on every literal (residues instead).
- `BigInt` / unbounded integers (separate future plan, D054).
- `UInt` (separate future plan, D054).
- Modelling x86 flags / control flow / SIMD beyond what arith needs.
- Replacing stub backends' postulates with real proofs (per-target
  future plans).
- Migrating `extensionality` / `funext` / `generic-semI/M` to wired
  form (follow-up plans).

## Relationship to other plans / decisions

- **Parent: 0.20.** Discharges the postulates 0.20 deferred.
- **D054 / D055.** This plan implements both for the arith pipeline.
- **Future:** full x86-32 / RISC-V backends; `UInt`; `BigInt`.

## Why this is the principled fix

- **One numeric model.** `Int` = modular `Word` everywhere on the
  machine path (D054); ℤ stays the spec of a future `BigInt`. No
  straddle, no no-overflow debt.
- **Total arithmetic.** `+`/`-`/`*` and now `/`/`%` (D055) are total
  value-returning ops — no traps, uniform across targets.
- **No new CPU semantics.** Wires the arith machine into the existing
  per-target `Semantics.agda`.
- **Multi-target by construction + first `--safe` beachhead.** The
  bridge record keeps the pipeline generic and `--safe`-clean.
