# Plan 0.111 — The interpretation's machine-level obligation is in the Spec

## 0. The property

> **What an interpretation's author owes, offline, is stated in the Spec, both halves: the
> MEANING of each declared operation (`Impl Σ`, there today) and, per target, that its machine
> code honours the calling convention at every call (missing today).** The proof's per-arch
> external-call facts are then CONSEQUENCES of that Spec-stated obligation plus the compiler's
> own invariants. None of them is a free postulate, and none mentions the compiler's internal
> correspondence.

## 1. The measurement (2026-10-06)

**The Spec has the semantic half only.** `CorrectCompiler` quantifies `∀ I → exec arch (sigOf tp)
I bytes ≈ ⟦ arch ⟧ˢ tp I` with `I : Implementation (sigOf tp)`, which is `Spec.Contract.Impl`
(`answerI`, `pureI`). Nothing in the Spec says what the interpretation's ASSEMBLY must do when
called.

**The machine-level half is spread over three trusted places, none in the Spec:**
1. **The machine model's external-call step** (`Arith/Backend/<arch>/RunTrace.ret-call`, D257
   amendment): `ret-call answer h lbl s = record (ret-past s) { regs = writeReg (regs s) rax
   (answer h lbl s) }`. So the callee returns past the call, writes the answer in the return
   register, and changes NOTHING else: no register, no memory.
2. **Per-arch postulates** (`Adequacy/CPU/<arch>`): `ev-<arch>` (which event a call to a symbol
   is, and its argument) and `call-at-<arch>` (which answering call, and its argument).
   D080 item 3: "the symbol ↦ SigOp denotation … is the irreducible part".
3. **The per-arch engine axiom** `external-sigop-contract` (`ArchCorrectness/<arch>/ConcFlatSim`,
   a field of `FlatCore.EventEngine`). It concludes: the env does not name the symbol, the
   extracted event is the abstract one, AND `CompiledCorr` holds after `ret-call`.

**Three defects.**
* **The compiler's invariant inside a trust point.** (3) concludes `CompiledCorr`, the
  compiler's own correspondence. D257 rejected exactly this as an apex hypothesis ("would put the
  compiler's own invariant inside an axiom", D161/D165), and chose (1) instead. But (3) still
  states it.
* **Invisible to a reader of the Spec.** An interpretation author reading `Once.Spec` sees half
  of what they owe.
* **(1) may assume MORE than a real callee gives.** `ret-call` preserves every register. The
  interpretation assembly honours SysV (`Syscalls.x86_64` header: "rbx, rbp, r12–r15:
  callee-saved"), and the `syscall` instruction itself clobbers `rcx` and `r11`. On x86-64,
  `PhysReg.owner` classes `rcx` and `rsi` as `ccc` (live in the CCC machine). If compiled code
  keeps a value in `rcx`/`rsi` across an external call, the model says it survives and the
  hardware says it does not. **To measure in S0, not assumed to be a bug:** the emitter may save
  them around `call-sym`, or never keep them live there.

## 2. The design

1. **State the calling convention in the Spec, per target**, as a property of a machine-level
   callee. New Spec module `Once.Spec.ABI` (exported from `Once.Spec`, under the "three times"
   header plan 0.107 §9 adds). For a call to the symbol of declared key `k` from state `s`:
   * the argument is in the argument register(s), in the compiler's VALUE REPRESENTATION. That
     representation (words, pair cells, tags; D187) must be stated here too, because it is what
     the callee reads;
   * the callee produces exactly the event of `k` at that argument (emit / answer), or halts (a
     `Void` codomain), per `contractOf`;
   * it returns to the return address with the answer, ENCODED, in the return register;
   * it preserves the callee-saved registers, `sp`, and memory outside its own frame and the heap
     cells it was given; caller-saved registers are UNSPECIFIED afterwards.
2. **An interpretation's obligation = semantic + ABI.** `Implementation S` (in `CorrectCompiler`)
   becomes `Impl S` together with, per arch, that the interpretation's code conforms to
   `Spec.ABI` for every key of `S`, measured against `Impl S`'s answers. Still `∀ I`, still
   discharged offline, by proof or postulate, per (SigOp × target) exactly as D061 says. The
   difference is that the Spec now SAYS it.
3. **The model's external step follows the Spec.** `ret-call` becomes "any state the ABI permits":
   caller-saved registers arbitrary (an opaque value, as plan 0.110 does for boot registers), the
   answer in the return register, the rest preserved. It is no longer "nothing changes".
4. **`external-sigop-contract` becomes a theorem**, D080's split carried through:
   * `env sym ≡ nothing` is internal: the symbol is not one of the file's arith blocks (the
     `ArithTable` relation, D262);
   * the event's value half is the compiler's calling convention (the argument register vs the
     abstract `event-of`), proved;
   * the event's identity half (symbol ↦ key) is the resolved `CanonicalName` (plan 0.107 §9
     makes it one value) plus the CLI's symbol rename, the remaining trusted step;
   * `CompiledCorr` after the call is PROVED from the ABI's guarantees. Where it needs a
     caller-saved register to survive, that is the S0 finding, fixed in the EMITTER (save/restore
     around `call-sym`), not assumed.

## 3. Steps (top-down)

* **S0 — Measure.** Per arch, which `ccc`-owned registers are caller-saved in the target ABI
  (x86-64: `rcx`, `rsi`; x86-32 and riscv64 to list), and whether any is live across an emitted
  `call-sym`. Read every interpretation's assembly for its actual clobbers. Record the result here
  before S1.
* **S1 — The Spec module `Once.Spec.ABI`** (decision-log entry: a Spec addition). Value
  representation + the per-call conditions, per arch.
* **S2 — `Implementation` gains the ABI half.** Follow the red into the instance (`Once.Compiler`)
  and the engine.
* **S3 — `ret-call` reads the ABI.** Caller-saved registers become unspecified after a call. Any
  red that follows is either an emitter fix (save/restore) or a proof using a fact it should not.
* **S4 — `external-sigop-contract` → theorem**, by D080's split, ×3 arches. `ev-<arch>` and
  `call-at-<arch>` lose their mechanical content; what stays trusted is the symbol table read and
  the CLI rename.
* **S5 — Gate.** Apex + backstop, extraction, `cabal test`, exit tests ×3. Regression probe:
  make the x86-64 emitter keep a value in `rcx` across `call-sym`; the apex must go RED.

## 4. Risks

* **The value representation is large to state.** Pairs, sums and closures as the callee sees
  them (the interpretation headers describe "Once tuple layout"). Keep it to what crosses the
  boundary: concrete FFI types only (`IsConcrete`, plan 0.105).
* **x86-32's convention** passes arguments on the stack; its ABI clause has a different shape.
* **Overlap with plan 0.110:** both make the model assume what the boundary guarantees, with
  unspecified registers. Do 0.110 first and reuse its opaque-register device.
