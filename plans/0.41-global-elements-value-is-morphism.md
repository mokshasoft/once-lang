# Plan 0.41 — Global elements: a value is a pure morphism from Unit

## The realization

In a CCC, a value `v : A` **is** a morphism `1 → A` (a global element;
`Hom(1, A) ≅ A`), and application `f x` **is** composition `f ∘ x`. There is
no "lift" in the mathematics — application is composition.

Once's history forked away from this:
- **D018** (2025-12-09) added value→const-morphism lifting so `puts "hello"`
  reads naturally. Correct instinct.
- **D032** (2025-12-12) *removed* the implicit lift because it let effectful
  code masquerade as pure: `println "hello" : Unit` (println mis-typed
  `String→Unit`) silently lifted to `Unit→Unit`. The real fix D032 shipped was
  **arrow-based effects** (`Eff A B`) — making the effect visible in the type.
  Removing the lift was the *pre-grade* safety measure.
- **D046** (2026-04-23) made purity a **grade** on the arrow
  (`A ⇒[ mk-kind q π ] B`). Effects are now visible in the grade, not in the
  value-vs-morphism distinction.

**So the masquerade is prevented by the grade, and D032's value/morphism
separation is a vestige.** With D046, composing a pure global element with an
effectful morphism propagates the grade: `println ∘ "hello"` is
`Unit ⇒[eff] Unit` — the effect stays visible. A pure value can only become a
**pure** morphism; an effect stays eff-graded. No masquerade.

The residue of the fork is everything we've been fighting in Plan 0.36/0.40:
the `effApp` suspension, the value-vs-morphism gap in `composeArgB`, the
"can't write `compose f 7`", and the eff-action composition usage obstacle.

## The principle (the decision to record, post-validation)

**A value `v : A` is the pure global element `v : Unit ⇒[ mk-kind Many pure ] A`,
and application is composition.** Concretely:

- `f x` elaborates to `f ∘ x` (`x` a global element), uniformly for pure and
  effectful `f` — **`effApp` is eliminated.** `exit 7` is `exit ∘ 7`,
  `Unit ⇒[eff] Unit`; the runtime entry runs `main` by applying it to `unit`.
- A value in *any* position (argument, `compose`-arm, binding) is the same
  global-element morphism. `exit 7`, `compose exit 7`, and `sevenM = 7` all
  type-check by the *same* rule — no special "value-lift", no `const` generator.
- Masquerade safety is **the grade**: the global-element coercion is allowed
  only `A → Unit ⇒[pure] A` (pure); an effect is never silently made pure
  because its grade is `eff` and grade propagates through `∘`.

This is D018's instinct, made sound by D046's grade — not the D032-banned
untyped lift.

## What it unifies / eliminates

- **`effApp` (the suspension)** — gone; application is composition.
- **The value/morphism distinction at use sites** — a value is a (pure)
  morphism, so `composeArgB`, `extract-morph(-eff)`, and the point-free path
  treat it like any morphism. The eff-action composition obstacle (Plan 0.40)
  **disappears** — there are no suspended actions to compose, only morphisms
  fused via `IR.∘`.
- **The "value-lift vs const" dilemma** (Plan 0.40 Gap 1) — moot.

## Design choice

The math says identity (`A ≅ Unit ⇒[pure] A`), but Once's `Type` has distinct
constructors for base types and arrows, so a *definitional* `A ≡ Unit⇒[pure]A`
is invasive. The pragmatic form is a **typed, grade-restricted coercion**: a
value at a base/data type is usable where `Unit ⇒[ mk-kind q pure ] A` is
expected, elaborating to its global-element morphism (`intLit` for literals,
the structural construction for `Mu`/sums/pairs, `curry` for closures). The
coercion is **only** to a *pure* arrow — the grade is the guard. This is
exactly D018's lift, reinstated under the grade restriction that makes it safe.

## Blast radius (accepted — principality over blast radius)

Touches the arrow-vs-value discrimination across the frontend: the `≟T`
clauses, `classifyAppHead`, `checkElabV`/`inferElabV` dispatch, `composeArgB`,
and Soundness/Completeness. Revisits D032 (records the separation as a vestige)
and refines D046 (the grade is the masquerade guard). `effApp` removal also
touches `Surface.Syntax`/`Surface.Elaborate`/`Surface.Correct` and the entry
stub (run `main` by applying to `unit`).

## POC gate (two-gate discipline — do NOT refactor before this)

Because this revisits a core decision (D032), gate the refactor on:
1. **Load-bearing claim POC.** Prove (small, in the real path) that the
   grade-restricted global-element coercion is **masquerade-safe**: a value
   coerced to `Unit ⇒[pure] A` composed into an eff chain stays eff-graded, and
   no eff morphism is reachable as pure. The grade-propagation lemma
   (`eff ∘ pure = eff`) is the crux.
2. **Integration-cost estimate.** Count the arrow-vs-value discrimination sites
   (× per-site overhead) and the `effApp`-removal sites. A passing POC does not
   license proceeding if integration exceeds budget — present the number first.

## How it finalizes the eff cata

The eff cata becomes ordinary point-free morphism composition, with values as
global-element morphisms and the cata as a `Cata` morphism:

```
main = compose exit@S (compose 7 (compose emitAll xs))
```

`7` and `xs` are pure global elements (fused, not applied); `exit@S`/`emitAll`
are eff morphisms; `compose` is `IR.∘` throughout. No `effApp`, no suspended
actions, no usage obstacle. `emit` fires in fold order (verified at the trace
level, Phase 3); the binary exits 7.

## BLAST-RADIUS ANALYSIS + CORRECTION (2026-06-09)

The blast-radius pass corrected an over-claim above. **"`effApp` eliminated /
application = composition" is wrong:** application *is* `f ∘ x` only when
applying a **morphism** to a value (`x : 1→A`). Applying a **closure-value**
(`(f x) y`, `f x : B⇒C`) does **not** compose — it needs `apply` (exponential
eval). So **`effApp`/`apply` is irreducible** (closure/higher-order
application), and **Phase D is dropped** — not achievable, and it would be the
~10-file application-semantics rewrite.

**The principled, aligned, bounded solution is the coercion (Phases B/C):** a
value is usable as a **pure** morphism via `Hom(1,A) ≅ A` (grade-restricted to
`Unit ⇒[pure] A`) — D018's lift under D046's grade guard. It realizes "a value
is a morphism" **without** touching application. Blast radius: additive
`checkElabV`/`composeArgB` clauses + their completeness; it does **not** change
`Int ≠ Unit→Int`, so `≟T`/dispatch/`effApp` are untouched — no global cascade
(~3 files: `Elaborate`, `Completeness`, `Classify`). The earlier "principle"
and "phasing" sections that say `effApp` is eliminated are superseded by this
note; `effApp`/`apply` stays for closure application.

## Scope split (refinement, 2026-06-09): cata needs B/C, not D

The eff cata's point-free form uses **`compose`**, so it needs only the
**global-element coercion** (values as pure morphism arms — Phases B/C).
**`effApp` removal (Phase D) is separable** — it's the full one-structure
endgame (application = composition, ~10 files), not a cata prerequisite. So
finalize the cata after B/C + the POC; do D as a follow-up. The POC's
load-bearing claim is design-level and small: the coercion is **data-value-type
→ pure arrow only** (an `Eff` value is already a morphism, never coerced), so no
effect becomes pure — the grade is the guard. Implementing B (literal coercion)
and showing the pure suite unchanged **is** that POC.

## `globalElem` design (refined 2026-06-09)

Not "reuse `elaborate`": `elaborate : … → IR ⟦Γ⟧ᶜ A` has its **domain fixed to
the context**, so it can't supply the *parametric* `IR X A` the lift needs
without scoping to an empty context (an awkward match). The clean form mirrors
`intLit` (which is parametric: `∀{Γ} → IR Γ Int`):

```
globalElem : (X : Type) → SExpr Γ Ψ A → Maybe (IR X A)
globalElem X (int n)     = just (intLit n)             -- leaf: reuse intLit (per-type)
globalElem X (str s)     = just (strLit s)             -- leaf: reuse strLit (per-type)
globalElem X unit        = just terminal
globalElem X (pair a b)  = ⟨_,_⟩ Heap <$> globalElem X a <*> globalElem X b
globalElem X (inl a)     = (inl Heap ∘_) <$> globalElem X a   -- structural: generic generators
globalElem X (inr a)     = (inr Heap ∘_) <$> globalElem X a
globalElem X (In wf m)   = (In wf Heap ∘_) <$> globalElem X m
globalElem X _           = nothing   -- var/app/sigOp/closure/… : not a closed value
```

Key properties answering the design questions:
- **No new per-type CCC knowledge.** The per-type bits live only in the **leaves**
  (`intLit` knows `Int`/`FitsInReg`; `strLit` knows `Str`) — **reused, not
  re-derived.** `intLit`/`strLit` **stay**.
- **Structure is generic** — `⟨_,_⟩`/`inl`/`inr`/`In` are the polymorphic
  generators, no per-type knowledge.
- It's a small recursion **parallel** to `elaborate`'s value-cases, but
  **parametric in the domain** `X` (that's the only reason it's separate from
  `elaborate`). Minor duplication of the *structural* cases; the per-type leaves
  are shared.
- **Scoped to closed values** by construction: `var`/`app`/`sigOp`/`closure`
  return `nothing` — so no open terms, and **no value-def laundering** (a
  `sigOp`/`closure` name is never turned into a SigOp).
- **Phase B is superseded**: the `RInt`-specific `checkElabV` clause + `t-int-lift`
  + the `intLit` import are replaced by one general clause
  `lift-morphism (globalElem X eE)` + `t-value-lift`. The typechecker becomes
  type-agnostic about values; all per-type knowledge sits in the leaves.

## Phasing

- **A — POC** the masquerade-safety load-bearing claim + the integration-cost
  estimate. Gate.
- **B — Global-element coercion** for literals (the cheap case): a literal at a
  `Unit ⇒[pure] A` position elaborates to `lift-morphism (intLit n)`. Validate:
  `compose exit@S 7` works; pure suite unchanged.
- **C — Structural global elements** for `Mu`/sums/pairs (the `xs` case).
- **D — Eliminate `effApp`**: application elaborates to composition uniformly;
  retire the suspension; entry runs `main` by applying to `unit`. Validate the
  whole exit-code suite under both optimize modes.
- **E — Decision + cata finalize**: record the decision (value = pure global
  element; D032 separation retired as a vestige; `effApp` removed); finalize
  Plan 0.36's eff cata as point-free composition; runtime-validate.
