# Plan 0.18 — PairWF2 where-block flatten (branch rescue)

## Goal

Get `make compiler-x86-64` green on `heap-only-pivot` by eliminating the
PairWF2 OOM. Target: `Once.CCC.Machine.IR.PairWF2` and each of its
companion modules typechecks in **under 30 seconds** individually.

## Hard rule for this work

**Every Agda command must be wrapped in `timeout 30`.** If a module
doesn't finish in 30 s, that IS the OOM signal — abort, diagnose, do
not let it run. We have a 7.5 GiB box and the kernel will OOM-kill if
agda crosses ~5.5 GiB. Use the cgroup wrapper as a belt-and-braces:

```bash
timeout 30 formal/scripts/agda-safe.sh agda MODULE=Once/CCC/Machine/IR/PairWF2.agda
```

Per-file targets:
- `Once/CCC/Machine/IR/PairWF2/Bounds.agda` — <30 s
- `Once/CCC/Machine/IR/PairWF2/Assembly.agda` — <30 s
- `Once/CCC/Machine/IR/PairWF2/Validity.agda` — <30 s (current size: 1940 lines)
- `Once/CCC/Machine/IR/PairWF2.agda` — <30 s

Do NOT run `make compiler-x86-64` until every PairWF2 piece is under
budget. Even healthy, the full build takes ~8 minutes.

## Diagnosis (settled)

PairWF2's `run-pair` has a where-block with **9 module instantiations**
(VVal / VL2 / VL3, VBnd0 / VBnd1 / VBnd2, VAsm0 / VAsm1 / VAsm2) plus
two `record-with-with-clauses` (FstFacts, SndFacts). Comparable
producers — ComposeWF, ApplyWF, SumRecWF, SimpleWF — have **0** module
instantiations.

Confirmed via experiments in the prior session:
- `run-pair = SMP.!!` (no where-block at all): PairWF2 typechecks
  in seconds.
- Records stubbed to `SMP.!!` (where-block intact): still OOMs.
- Therefore the cost is the where-block module instantiation chain
  building accumulating ambient context, not the record construction
  or the `SMP.!!` placeholders.

Per memory `feedback_extract_proofs_from_where`: companion module
extraction was a partial fix (PairWF2 already has Validity / Bounds /
Assembly companions), but it doesn't shrink the *consumer's*
where-block when the consumer still does the L2/L3 instantiation chain
itself. The remaining principled step is to flatten the instantiation
into top-level functions.

The line 144 type-error (`pair-frontier-stable` named function with
`apply-bump SMP.!! alloc` unification) was masking the OOM by aborting
elaboration before the heavy path. With the inline lambda
(`λ _ _ _ _ _ → inj₂ (inj₂ tt)`) the error goes away and agda OOMs.

## Refactor plan

**Pattern**: top-level functions (members of `PairWF2Impl` module) take
explicit parameters and do the work in a fresh small scope. They
**replace** the where-block module instantiation chain.

### Step 1 — `pair-finalize` (top-level helper, biggest win)

New function inside `PairWF2Impl`, declared *before* `run-pair`:

```agda
pair-finalize :
  ∀ {A B C} (f : IR A B) (g : IR A C) (x : ⟦ A ⟧)
    (s : LocState FS) (alloc : AllocState {FS})
    (not-halted : halted s ≡ false)
    -- result-f side
    (mF : AllocMode)
    (result-f : IRResultAWF mF f x <s-after-setup> <alloc-after-pair-slots>)
    (f-tnhw : TraceNoHeapWrites (IRResultAWF.trace result-f))
    -- FstFacts projections (computed by run-pair via with-clause)
    (fst-loc : ValueLocation FS) (fst-rax-eq : ...)
    (fst-valid : ValidAtWF mF ...) (fst-before : BeforeFrontier ...)
    (fst-rec-valid : ...) (fst-rec-before : ...)
    -- result-g side
    (mG : AllocMode)
    (result-g : IRResultAWF mG g x <s-after-middle> <alloc-after-f-reclaim>)
    (g-tnhw : TraceNoHeapWrites (IRResultAWF.trace result-g))
    -- SndFacts projections
    (snd-loc : ValueLocation FS) (snd-rax-eq : ...)
    (snd-rec-valid : ...) (snd-rec-before : ...)
    -- Witness from Assembly.L2
    (middle-restore-input-witness : ...)
  → IRResultAWF Stack (⟨ f , g ⟩ Stack) x s alloc
pair-finalize ... =
  let module VBnd0 = BImpl.Bounds alloc
      module VBnd1 = VBnd0.L2 f x s-after-setup mF result-f f-tnhw
      module VBnd2 = VBnd1.L3 g s-after-middle mG result-g g-tnhw
      module VAsm0 = AImpl.Assembly f g x s alloc not-halted
      module VAsm1 = VAsm0.L2 mF result-f f-tnhw
      module VAsm2 = VAsm1.L3 mG result-g g-tnhw middle-restore-input-witness
      module VVal  = VImpl.Validity mIn f g x input-loc s alloc not-halted rdi-eq
                                     input-valid-wf input-before
      module VL2   = VVal.L2 mF result-f fst-loc fst-rax-eq fst-valid fst-before
                              fst-rec-valid fst-rec-before f-tnhw
      module VL3   = VL2.L3 mG result-g snd-loc snd-rax-eq snd-rec-valid snd-rec-before
                              g-tnhw VAsm2.s-final VAsm2.s-final-eq
      pair-bump : AllocBump
      pair-bump = mkBump
        (3 +ℕ (next-slot-delta (IRResultAWF.bump result-f)
               +ℕ next-slot-delta (IRResultAWF.bump result-g)))
        (next-heap-ref-delta (IRResultAWF.bump result-f)
         +ℕ next-heap-ref-delta (IRResultAWF.bump result-g))
      pair-bump-eq : VAsm2.alloc-final ≡ apply-bump pair-bump alloc
      pair-bump-eq = SMP.!!
  in mk-IRResultAWF-via-bump
       VAsm2.s-final VAsm2.alloc-final VBnd2.pair-trace pair-bump pair-bump-eq
       SMP.!! refl VAsm2.alloc-correct-pair
       (at-loc pair-loc VL3.pair-valid-wf-final pair-before VAsm2.rax-eq
               VL3.pair-valid-wf-final pair-before)
       VAsm2.not-halted-final
       (mem-preserved-from-tnhw alloc VBnd2.pair-trace s VAsm2.s-final refl
          VBnd2.pair-trace-writes-above VBnd2.pair-trace-no-heap-writes)
       VAsm2.pair-trace-twf
       (exec-trace-preserves-halted-WF VBnd2.pair-trace)
       (record { ... 13 fields ... })
       (record { ... 5 fields ... })
  where
    pair-loc = AtStack ...  -- whatever it was
    pair-before = stack-before refl VBnd2.fst<reclaim-g
```

The key: the 9 module instantiations live inside `pair-finalize`'s
body, in a scope that contains *only* `pair-finalize`'s explicit
params. That's the fresh-context fix.

### Step 2 — Shrink `run-pair`'s where-block

`run-pair` now does only:
1. Compute setup state (s-after-setup, alloc-after-pair-slots) — needs
   to instantiate `VImpl.Validity` once just to derive these. Or hoist
   the setup derivations into another small top-level helper.
2. Call `rec-wf f` to get result-f.
3. Compute FstFacts via with-clause (still needed; see Step 3).
4. Compute middle state (s-after-middle, alloc-after-f-reclaim) and
   middle-restore-input-witness.
5. Call `rec-wf g` to get result-g.
6. Compute SndFacts via with-clause.
7. Call `pair-finalize` with everything.

### Step 3 — If `pair-finalize` alone isn't enough

Then the FstFacts/SndFacts with-clauses and the
`VVal/VL2`/`VAsm0/VAsm1` instantiations in `run-pair`'s where are also
contributing. Extract them to additional top-level helpers:

- `compute-fst-facts : ... → FstFactsRecord`
- `compute-snd-facts : ... → SndFactsRecord`
- `pair-setup : ... → SetupRecord`
- `pair-middle : ... → MiddleRecord`

Each takes minimal params and returns a record.

## Anti-patterns to avoid (memory-backed)

- Adding `abstract` blocks inside the same where-block as a fix
  (`feedback_extract_proofs_from_where` says EXTRACT, don't abstract).
- Trying to flatten the L2/L3 chain *inside* companion modules (the
  L2/L3 chain is fine there; the problem is only when PairWF2's
  where-block also does the chain).
- Running `make compiler-x86-64` without a timeout cap (will burn
  ~10 minutes and possibly OOM the session).
- Reverting the `pair-bump` concretization to `SMP.!!` — concrete
  `pair-bump` is load-bearing for `apply-bump pair-bump alloc` to
  reduce; `pair-bump-eq = SMP.!!` is fine to leave.
