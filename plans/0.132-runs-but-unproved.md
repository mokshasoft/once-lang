# Plan 0.132 — what runs, and what of it is unproved

status: OPEN on branch `runs-but-unproved` (opened 2026-10-30). Next step: §3 A.

relates: MERGE.md §6, `run-ast-dumps.sh`, D352 (tools beside the compiler), plan 0.92/D277 (apex-live scope), the
Agda fork's `--write-ast` (github mokshasoft/agda, `dead-code-2.8.0`), plan 0.130 (shared report shape).

## 1. Why

`run-ast-dumps.sh` dumps what is reachable from ONE root, `Once.Certified.once-certified`: what the proof depends
on. MERGE.md §6 compares that set between master and a branch, so the trust base cannot grow silently.

It does not see what the CLI RUNS. The extraction root `Once.Extract.Root` is a list of imports, not a
definition, so it cannot be a `--write-ast` root. Run code that no theorem mentions is invisible: `Once.Measure`
(declared a measurement, D352), the warnings (`Once.Warnings.warningsFor`), the printers, the `Extract.Names`
helpers. Proof code that nothing runs is visible only as reachable. The question a merge should answer — "which
code runs without a theorem about it, and did that grow?" — has no tool.

The Haskell bridges call 14 MAlonzo names today (`Compile.Bridge`, `Inspect.Bridge`, `Measure.Bridge`,
`Format.Bridge`); `Once.IR`/`Once.Eval` (the arith evaluator) and `tools/discovery` call more. Nothing checks that
this list matches the extraction root.

## 2. Target

1. **One definition is what runs.** `Once.Extract.Root` defines a record value `runs : Runs` whose fields are
   exactly the functions the Haskell side calls (the compiler, the front end, each tool). The bridges call
   through its fields (MAlonzo projections), so a function the CLI calls and the record lacks is a compile
   error in Haskell, not a silent omission.
2. **Two roots per ref.** `run-ast-dumps.sh` dumps `once-certified` (PROVED) and `runs` (RUNS) — two `--write-ast`
   passes over the same interfaces, or one if the fork takes several roots.
3. **Three sets, by declaration and by module**: PROVED, RUNS, and RUNS ∖ PROVED ("runs but unproved"). Each
   member of RUNS ∖ PROVED is classified:
   - *declared*: a tool that is a measurement or a report by decision (`Once.Measure`, the warnings, printers
     only a tool prints with), listed with its decision in `runs-unproved.allow`;
   - *gap*: anything else.
   And PROVED's postulates/pragmas reachable from RUNS (run code that rests on an assumption) are listed apart.
4. **A ratchet.** MERGE.md §6 compares RUNS ∖ PROVED between master and the branch, like the trust base: a gap
   appearing needs a decision entry; the allowlist only shrinks unless a decision raises it.
5. **The report shape is the fork's** (`{"schema":1,"report":…}`, keys `counts`, `reachable`, …), with the root's
   name in it, so plan 0.130's run-time report and this one read alike, and a future dependent-types root (a
   proof term that also runs) is one more root, not a new tool.

Out of scope, and said so in the report: the Haskell side itself (`Once.CLI`, import I/O in `loadAndResolve`,
invoking `as`/`ld`, the Host objects) — trusted, listed in the residual ledger's tool rows.

## 3. Steps

**A. The `Runs` record.** Fields for: `parseSourceToModule`, `module-imports`, `module-has-main`, `resolveImports`,
`rmodule`, `warningsFor`, `assemblyFromModule`, `Inspect.signatures`/`check`/`dumpIR`, `Measure.statsOf`,
`Format.formatSource`, and what `Once.IR`/`Once.Eval` read. Decide whether `tools/discovery` is in (a second
record, `tools-runs`, if it stays a separate executable). The bridges call through `runs`; extraction, cabal,
tests unchanged in behaviour.

**B. The fork.** Check whether `--write-ast` accepts several roots in one run; if not, add it on
`dead-code-2.8.0` (one type-check, one dump with a `roots` key), or run the dump twice from the same interfaces.

**C. `run-ast-dumps.sh`.** Both roots; write `ast-once-certified-…json` and `ast-runs-…json` (or one file with
both); a `compare` mode that prints, master → branch: trust base, PROVED left/joined, RUNS ∖ PROVED by class, and
assumptions reachable from RUNS.

**D. The first census.** Run it on master; classify every member of RUNS ∖ PROVED; write `runs-unproved.allow`
with the decision for each declared entry; every gap becomes a row in a plan (or in plan 0.133 for `check`).

**E. Closing.** MERGE.md §6 gains the RUNS ∖ PROVED comparison and its rule; decision entry and `internal.md`
line; the residual ledger points at the report.

## 4. Done when

`run-ast-dumps.sh` reports, per ref, what runs and what of it is unproved, every unproved run declaration is
either allowed by a decision or listed as a gap in a plan, and MERGE.md §6 fails a branch that adds an
undeclared one.

## 5. Questions

- Is a printer (`showIR`, `showType`) "declared" or a gap? A printer's correctness is a round-trip with a parser
  (as `once fmt` proves); for the IR there is no parser. Proposal: declared, unless a tool's theorem reads it.
- Does `tools/discovery` count as "what runs"? It ships in the repo but not in the `once` binary.
