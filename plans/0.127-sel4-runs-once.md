## 0. Where this started

- **No Once code had ever run on seL4.** The example flake's default package built hand-written C; its
  `once build` steps used the C backend (removed, D341) and ended in `|| true`.
- **The `.once` programs did not type-check**, and the rootserver never gave its threads an entry or a
  stack; Once has no value naming a definition's code address.
- **No seL4 Host**: seL4 gives the root task no stack; the compiler's `_start` needs one.
- **The SeL4 impl files had never run.** Written by hand in Dec 2025 (`53eb040d8`, `d643f5f4b`): syscall
  numbers wrong and inconsistent (`seL4_Call` as `-6`, Send `-1`, Recv `-3`), bootinfo offsets one word
  off (no `extraLen`), a hard-coded bootinfo address, results returned in registers instead of as tuples.

## 1. The goal

`nix build` in `examples/seL4` boots seL4 under QEMU with Once programs, and the test reads what they
printed. No hand-written C in the path that is tested. Reached on x86_64.

## 2. Phases

### A. A Once root task on seL4 x86_64 — done 2026-10-28
1. The Host supplies the entry, as seL4's `sel4runtime` does for C (`_sel4_start` sets a static stack and
   calls `__sel4_start_root(bootinfo)`; the kernel starts the root task at the ELF entry with the bootinfo
   pointer in `rdi` and no stack). Decision entry deferred by the user.
2. `Strata/Hosts/SeL4/Host.x86_64`: `once_sel4_enter` (a 64 KiB stack, `rdi` saved to
   `once_sel4_bootinfo`, jump to `_start`) and `once_leave` (prints `Once: returned` with
   `SysDebugPutChar`, suspends the thread's own TCB). The entry was first named by a Host linker script;
   since D376 the compiler emits only `once_main`, so the seL4 Host defines `_start` as the Linux Hosts
   do, on every architecture. No linker script and no compiler change.
3. `I.SeL4.Debug.putChar : Act Int Unit`.
4. The x86_64 impls of `BootInfo`, `Untyped`, `TCB`, `IPC` rewritten against the pinned kernel: syscall
   numbers from its generated `syscall.h`, invocation labels from `api/invocation.h`, layouts from
   libsel4 (`bootinfo_types.h`, `seL4_IPCBuffer`, `object-api.xml` parameter order). The SigOp ABI they
   follow: the argument in `rdi` (a tuple is one flat block of words, D381), the
   answer in `rax` (a tuple answer is a flat block allocated at `r15`, advanced); every other register preserved — `r15`
   is both Once's heap pointer and seL4's fourth message word. Object invocations put words 4.. and extra
   caps in the root task's IPC buffer. `Types.once`'s syscall numbers fixed; `seL4_TCB_Write/ReadRegisters`
   removed (they take a pointer); `bootinfo_emptyStart/End` added.
5. (A Hello program was not needed: the echo's root task is the first run.)
6. `examples/seL4/flake.nix` rewritten: `seL4-kernel-x86_64` (pc99, debug, printing, seL4_tools'
   simulation settings: no PCID, FS/GS base by MSR, no IOMMU, FXSAVE), `echo-image`, `echo-test` (boots
   QEMU, checks the console), `simulate`. The C packages and the `|| true` steps are gone.
   `make -C examples seL4` runs `echo-test`.

### B. Root task, echo server and client — done 2026-10-28
1. Decided by the user (2026-10-28): **several programs, one image.** (Closures as thread bodies were the
   first choice; rejected by `IsConcrete`: a signature is first-order, the world cannot run Once code.)
   Each program has its own `main`, run, stack and heap; `link-image.sh` builds each alone and renames
   program n's `_start` (its only global) to `once_program_<n>`; the Host's table names programs 1-3
   (weak), keeps a stack per program and the TCB and Int each was started with; `once_sel4_self` finds
   the calling program from `rsp`. `I.SeL4.Program.start : Act ((Int * Int) * Int) Int` (tcb, program,
   arg) is `seL4_TCB_WriteRegisters` of rip and rsp with resume; `arg : Act Unit Int`. The programs share
   the root task's VSpace and CSpace for now. Decision entry deferred by the user.
2. `examples/seL4/Echo/{Root,Server,Client}.once`: the root task finds RAM untyped, retypes two TCBs and
   an endpoint, configures them (its CNode and VSpace, no IPC buffer), starts the server and the client;
   the server is `ana` forever over `seL4_Recv` / `seL4_Reply`; the client `seL4_Call`s 65..90 and prints
   each answer. The old `Rootserver/`, `EchoServer/`, `once-echo/` (C), `scripts/`, `config/` deleted.
3. Passes: the console shows `0000000` (the root task's seven invocations) and
   `ABCDEFGHIJKLMNOPQRSTUVWXYZ` (the echoed Ints).

### B′. The seL4 numbers are checked — done 2026-10-28
At the user's request ("do something about the wrong system-call numbers"). Every seL4 number in the
Host and the Interpretations is in a `seL4 numbers` block (`.equ NAME, VALUE [# = EXPR]`, or in `.once`
`NAME = VALUE [-- = EXPR]`), named by the kernel's name or with the C expression it must equal;
`examples/seL4/check-numbers.sh` compiles them against the pinned kernel's headers (its generated
`gen_headers/`, `generated/` bitfields and `autoconf.h`, libsel4's sources) and fails on any difference;
the flake's `numbers-check` runs it over every x86_64 file (each must have a block) and every `.once`
with one. 106 numbers; it found `seL4_SlotBits` (5, not 4) and `seL4_CanRead`/`seL4_CanWrite` swapped.
The message info words are checked with the kernel's constructor, so the label/extra-caps/length layout
is checked too. `CNode.x86_64` and `Notification.x86_64` rewritten in the A.4 pattern (number-checked,
not yet run); the invocation routines moved into the Host (`once_sel4_copy_arg`, `once_sel4_answer`,
`once_sel4_invoke`). The `.c` (D341) and unchecked SeL4 files deleted.

### C. Other architectures
What differs per architecture is the kernel's entry register (`rdi`, `ebx`, `a0`), the syscall and its
message registers (x86_64 four, ia32 two, riscv64 four), the layouts, the word size (`wordBits`, a CNode's
depth) and how QEMU boots an image. `flake.nix` has one row per architecture.
1. Done 2026-11-08: riscv64 (qemu-riscv-virt): the Host and impls, the kernel, `riscv64-boot/` (seL4's
   elfloader around the Once image, started by QEMU's OpenSBI). The Host sets `gp`, which the linker relaxes
   addresses against.
2. Done 2026-11-08: x86_32: the pinned kernel's ia32 (not verified). Message words 2 and 3 go in the IPC
   buffer, which only the root task has; a started program has the two register words.
