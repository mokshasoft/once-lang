# Plan 0.103 — Every definition is typed once: the module telescope, then rank-1 `∀`

## 0. The property

> **A module is well-typed iff every definition is typed exactly once, at its declaration,
> in its prefix.**

A module is a TELESCOPE over a context of FFI signatures:

    Σ ⊢ d₁ : T₁ = e₁ ; d₂ : T₂ = e₂ ; … ;  main : IO Unit = eₘ
    well-typed  ⟺  for every i:  Σ, d₁ : T₁, …, dᵢ₋₁ : Tᵢ₋₁ ⊢ eᵢ : Tᵢ

A reference to an earlier definition is a VARIABLE of that context, at its declared type. It
does not re-check the body, because the body's typing is a module-level fact.

A polymorphic definition `d : ∀ā. T = e` is typed by ONE parametric judgment `ā ⊢ e : T`, and
each use at `T[σ/ā]` is typed by instantiation, justified by the type-substitution lemma:

    Γ, ā ⊢ e : T   ⟹   Γ ⊢ e : T[σ/ā]

That lemma is a METATHEOREM, not a Spec rule, and today it is not proved (the Spec's `Type`
has no type variables). **Until it is proved, "checked once, instances for free" is not a
valid argument**, and polymorphic definitions stay checked per use (sound per use). The lemma
is the gate of phase 5.

## 1. Where things stand (2026-09-28, found while landing D231–D233)

`extractFunctions` (`Once/Parser.agda:288`) splits the module into two lists and loses
their interleaving:

| signature | route | typed where |
|---|---|---|
| ground and FFI-concrete | `FunInfo` | once, at the declaration (`AllFunsTyped` ⊂ `ModuleTyped`) |
| ground, NOT concrete (every `Mu`/`Nu` def) | `PolyFunInfo` ("telescope") | at use sites only |
| polymorphic `∀ā. T` | `PolyFunInfo` | at use sites only |

Defects against §0:

1. **An unused telescope definition is never typed.** `f : Nu (K Int); f = 5` is accepted.
2. **A used ground telescope definition is not checked.** Its reference infers through the
   POSTULATED witness `bbc-other-poly-infer-witness` (`Once/TypeCheck/Elaborate.agda:759`).
3. **A telescope body is typed in the USE site's import context** (dynamic scoping), not in
   its declaration's prefix.
4. **The route is chosen by FFI concreteness, an ABI property.** Typing must not depend on it
   ("cata is not concrete"; D071).
6. **(found 2026-09-28) The apex rests on an INCONSISTENT postulate.**
   `ResolveFaithful.resolveExpr-poly-splice-faithful` equates the meaning of a spliced
   body with the meaning of the `poly x A` placeholder for an ARBITRARY elaborated body
   `eE`. Instantiating `eE` with `inl' unit` and with `inr' unit` derives `⊥` (probe
   typechecked). It is on the apex path (ResolveFaithful → MainRealizeAgrees → Compile),
   so `correct` is currently vacuous. The chain it props up — SD⟦resolve se⟧ = SD⟦se⟧
   (placeholder meaning) = SD⟦realize w⟧ (`infer/check-agreeV-RVar-poly-todo`) — uses the
   placeholder's meaning, an opaque internal call, as a pivot. It cannot be repaired as
   stated; phase 1c rebuilds it (below).
7. **(found 2026-09-28) `Elaborate.bbc-other-poly-witness` is INCONSISTENT.** It postulates
   `ctx ⊢ᶜ RVar x ∶ T` for every `ctx`, `x`, `T`; `check-complete` on it for an unbound name
   derives `⊥` (probe typechecked). It is the check-mode witness for POLYMORPHIC telescope
   references: the elaborator emits `poly x T` at any `T` without checking the body, so an
   ill-typed polymorphic use also passes the checker. Nothing short of honestly typing the
   polymorphic use (per use, or once with the substitution lemma — phases 3–6) removes it.
5. **Check-mode `t-var-poly-instantiate` accepts any type the body checks at**, with no link to
   the schema. The schema is decorative and mode agreement is unprovable. This blocks D230's
   argument-driven inference for polymorphic heads: `exit@S (myId 0)` no longer infers,
   6 exit tests fail.

## 3. Phases

**1. The ground telescope (closes defects 1–4).**
* **a. The module is one ordered telescope.** `extractFunctions` keeps source order: entries
  are FFI signatures, monomorphic definitions (ground, concrete or not) and schema
  definitions, each in its declaration position.
  * `ModuleTyped` is defined over that sequence: every monomorphic entry
    `Σ, prefix ⊢ᶜ e ∶ T`, typed ONCE, whether used or not.
  * A cycle is a rejected module (Plan 0.58's topological sort stays the implementation).
* **b. Routing by ground vs polymorphic only.** A ground definition is a telescope VARIABLE at
  its declared type for typing. Concreteness is consulted only by codegen: a concrete
  definition gets a direct-call symbol, a non-concrete one is δ-reduced as today.
* **c. The reference rule loses its body premise.** A reference to an earlier monomorphic
  entry is typed by its declared type (like `t-var-import`). The body typing lives in
  `ModuleTyped`. `t-var-poly-instantiate-infer` becomes a plain telescope-variable rule for
  ground entries, and `bbc-other-poly-infer-witness` (a postulate) is DELETED.
  * *The meaning of a context with definitions is an ENVIRONMENT.* Today a reference MEANS its
    body (`⟦ t-var-poly-instantiate-infer … bodyD ⟧ᵢ = ⟦ bodyD ⟧ᶜ tt`), so the premise is
    load-bearing for the meaning. Without it, `⟦_⟧` and `realize` take the telescope's
    environment `ρ : DefEnv (NamedCtx.polys ctx)`, one entry per telescope position (a
    function of `Ground schema`, vacuous for a non-ground one), and a reference is a LOOKUP
    along `lookupPolyPrefix`'s path. The non-ground check rule (still per-use until phase 6)
    runs its body in the prefix's environment (the tail of `ρ`).
  * The environment of a module is built from `PolysTyped` by structural recursion on the
    telescope: each entry's meaning is its declaration-time derivation's meaning in the
    tail's environment. Hence `PolysTyped` is stated STRUCTURALLY (each entry typed at its
    list tail, in `funCtxAt` its declaration position), not by name lookup.
  * Meaning and runtime do not change: the environment holds exactly what δ-reduction
    inlined.
  * *Compile once, and agree at the RESOLVED level (closes defect 6).* The implementation
    elaborates each ground entry ONCE, in its declaration context, and `resolveExpr`
    splices that closed term at every ground reference, instead of re-elaborating the
    body per use in the use site's context. The agreement theorem is stated directly
    between the resolved elaborator output and the reference elaboration in an
    environment: `SD⟦ resolve ρE se ⟧ ≡ SD⟦ realize w ρR ⟧`, given entrywise agreement of
    the two environments (built by recursion on the telescope, using derivation
    independence for the entry's body). The `poly` placeholder's own meaning is never
    used, so `resolveExpr-poly-splice-faithful` and the ground half of
    `infer-agreeV-RVar-poly-todo` are DELETED. Polymorphic (non-ground) references keep
    their per-use path until phase 6.
* **d. Red tests first:**
  * `f : Nu (K Int); f = 5` is rejected;
  * `compiler/test/PuritySpec.hs` "an effectful coalgebra cannot build a pure stream" turns
    green;
  * an unused ill-typed ground definition is rejected.

**2. Polymorphic uses are instances (closes defect 5).**
* **a. Principal-instance premise:** `t-var-poly-instantiate` requires the checked type to
  be an INSTANCE of the schema (`instantiate schema T ≡ just σ`). The elaborator's
  check-mode path already instantiates. This makes the Spec say so.
* **b. `d-poly`:** local type inference (Pierce–Turner) for a polymorphic head in
  argument-driven position.
  * Given the domain `A`, `σ = match(dom(Tₛ), A)`, output `B = cod(Tₛ)[σ]`, and the body
    is checked at `A ⇒ B` (per use, sound per use until phase 5).
  * Determinacy: FV(cod Tₛ) ⊆ FV(dom Tₛ); otherwise the head needs an annotation (D230's
    stated cost).
* **c. Mode agreement for `d-poly`:** `agree-dd`, and `agree-dc` against the
  principal-instance check rule, via a lemma relating `instantiate` on an arrow to matching
  its domain.

*Gate:* the 6 `infer-id`/`infer-poly-alias` exit tests green, `ModeAgreement`
postulate-free, Certified green.

**3. Type variables in the core** (`Once.Spec.Core`).
* A core type syntax `CTy n` (`n` type variables), with ground `Type` embedded as `CTy 0`,
  and type substitution `CTy n → (Fin n → CTy m) → CTy m`.
* The judgment becomes `Δ ; Γ ⊢[Ψ] t ∷ A ! π`.
* Decision to record: `Δ` as a judgment PARAMETER or as an index. Recommended: a parameter,
  so the rules do not double.

*Gate:* the existing core rules are unchanged at `n = 0`.

**4. The core telescope with `∀`.**
* Entries `d : ∀Δ. T = e`, an instantiation former `inst d σ`, and the meaning of `∀` as a
  family `Π(σ : Δ → Type). ⟦T[σ]⟧`. Parametricity is NOT claimed.
* This is the non-dependent fragment of OCP-0009's `Π (A : U)`, with `U` a universe of
  monotypes.

*Gate:* the core meaning of a telescope, with `main` at `IO Unit`.

**5. The type-substitution lemma (THE GATE for polymorphism).**

    Δ ; Γ ⊢[Ψ] e ∷ T ! π   ⟹   Δ′ ; Γ[σ] ⊢[Ψ] e[σ] ∷ T[σ] ! π

* It comes with its semantic counterpart `⟦e[σ]⟧ = ⟦e⟧ at σ`, and uses the POC's strict
  substitution (K0).

*Gate:* postulate-free. Only after it may a proof argue "a use is an instance, so it is
typed".

**6. Polymorphic definitions typed once.**
* Surface schemas elaborate to core `∀`, and uses elaborate to instantiations.
* `ModuleTyped` types every polymorphic entry parametrically. The per-use check is sound by
  phase 5 and becomes the implementation's.
* The D072 oracle's schema is checked once, at the definition.

*Gate:* unused ill-typed polymorphic definitions are rejected (red test first), Certified
green, and `cabal test` green.

## 4. Risks

* **Phase 1a restructures `ModuleTyped`,** so every consumer changes: `MainMeaning`,
  `ModuleComplete`, `AcceptSound`, `MtIndep`, `FunBundle`, `MainMeaningBridge`. Budget it as
  the plan's largest phase.
* **Mutual references between monomorphic definitions and telescope entries** that today work
  only because telescope bodies see the use site's imports become rejected if they point
  forward. That is correct (§0), but check the exit tests and examples for forward
  references.
* **Codegen δ-reduces non-concrete entries.** Moving their typing into `ModuleTyped` must not
  change what `resolveExpr` splices.
* **The type context in every core rule** (phase 3): keep `Δ` a parameter.
