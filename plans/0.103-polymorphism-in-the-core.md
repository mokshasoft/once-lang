# Plan 0.103 — Polymorphic definitions are typed once: rank-1 `∀` in the core

## 0. The property

> **A module is well-typed iff every definition is typed exactly once, at its declaration,
> in its prefix. A polymorphic definition `d : ∀ā. T = e` is typed by the ONE parametric
> judgment `ā ⊢ e : T`. Every use `d` at `T[σ/ā]` is typed by instantiation.**

Instantiation is justified by the **type-substitution lemma**:

    Γ, ā ⊢ e : T   ⟹   Γ ⊢ e : T[σ/ā]        (σ : ā → closed types)

The lemma is a METATHEOREM, not a Spec rule. **Until it is proved, "checked once, instances
for free" is not a valid argument.** Proving it is this plan's central gate (§4 C). The Spec
states the rules; the lemma is what makes per-use re-checking redundant.

## 1. Where things stand (2026-09-27)

* `Type` is ground: it has no type variables. `PolyType` (with `TVar`) is separate syntax that
  is only ever INSTANTIATED to a `Type` (`instantiate`, `applySubst`).
* A polymorphic definition is a telescope entry (`PolyFunInfo`). It is checked at each USE:
  `t-var-poly-instantiate` types the body at the use's type. That is sound per use. It is not
  module well-typedness, for three reasons:
  * an unused polymorphic definition is never checked;
  * the same body is checked once per instance;
  * an error in the definition surfaces at a use.
* `t-var-poly-instantiate` (check mode) does not require the use's type to be an INSTANCE of
  the schema, so the schema is decorative. (Items (1)/(3) of the 2026-09-27 decision
  point add the instance premise for the ground and argument-driven cases. This plan
  makes it structural.)
* The sig-less path (D072) gets its schema from an untrusted oracle, and each instantiation
  is checked. A wrong schema is a rejected use, never unsoundness. That stays true.

## 2. The target

1. **The core gets rank-1 (prenex) polymorphism** as the non-dependent fragment of OCP-0009's
   `Π (A : U)`:
   * type variables `α` in core types (a well-scoped de Bruijn type context `Δ`, beside the
     term context `Γ`);
   * a definition-level `∀`: a telescope entry `d : ∀Δ. T = e`, typed by
     `Δ ; Γ ⊢[Ψ] e ∷ T ! π` (the core judgment, `Once.Spec.Core.Typing`, extended with `Δ`);
   * instantiation at use: `d [σ]`, typed `T[σ]`, a core term former (type application) with
     no body check.

   Rank-1 only: no `∀` inside arrows, no impredicativity. That is what HM needs, and it is
   exactly the fragment that later becomes `Π (A : U)` with `U` a universe of monotypes. The
   dependent kernel then generalizes the same judgment; nothing is replaced.
2. **The meaning:** a `∀`-definition denotes a family indexed by closed types,
   `⟦∀Δ. T⟧ = Π(σ : Δ → Type). ⟦T[σ]⟧`, and instantiation is application of the family.
   Parametricity is NOT claimed: the family need not be uniform. That is a later, separate
   claim, if ever.
3. **The surface:** a schema `∀ā. T` elaborates to a core `∀`. The elaboration relation
   (plan 0.102 C) maps each use to an instantiation. The surface judgment keeps its
   per-use rules as the IMPLEMENTATION (sound and complete against the core), or drops
   them once the core owns the Spec.
4. **Module well-typedness (`ModuleTyped`)** quantifies over EVERY definition: monomorphic
   ones at their type, polymorphic ones parametrically. An unused ill-typed definition is
   rejected.

## 3. What changes for programs

* Accepted programs: every program accepted today whose polymorphic definitions are
  well-typed at every instance is still accepted. NEWLY REJECTED: a polymorphic definition
  that is ill-typed parametrically but typed at every instance actually used. An example is
  a body that only type-checks for `a = Int`, used only at `Int`. That is the point: it was
  never a `∀a` definition.
* Meaning and runtime are unchanged. Instantiation is still specialization in codegen
  (monomorphization); the core `∀` is a typing and meaning device.

## 4. Phases

**A. Type variables in the core.**
* `Type` gains no `TVar` constructor. Instead, the core gets its own type syntax
  `CTy n` (`n` type variables), with an embedding of `Type` as `CTy 0`, and type substitution
  `CTy n → (Fin n → CTy m) → CTy m`.
* `Δ ; Γ ⊢[Ψ] t ∷ A ! π` over `CTy`.
* Decision to record: whether `CTy` replaces `Type` in the core or embeds it.
  Recommendation: embed. The surface and the IR keep the ground `Type`.

*Gate:* the judgment with `Δ` is written, and the existing core rules are unchanged at `n = 0`.

**B. The definition telescope with `∀`.**
* Core programs are telescopes of entries `d : ∀Δ. T = e`.
* Instantiation former `inst d σ`.
* The meaning as a family.

*Gate:* the core meaning of a telescope, and `main` typed at `IO Unit`.

**C. The type-substitution lemma (THE GATE of this plan).**

    Δ ; Γ ⊢[Ψ] e ∷ T ! π   ⟹   Δ′ ; Γ[σ] ⊢[Ψ] e[σ] ∷ T[σ] ! π      (σ : Δ → CTy Δ′)

* It is proved by induction on the derivation, with the POC's strict-substitution
  discipline (K0: substitution on the nose).
* It comes with its semantic counterpart: `⟦e[σ]⟧ = ⟦e⟧ at σ`.

*Gate:* both are postulate-free. Only after C may any proof argue "the use is an
instance, so it is typed".

**D. Surface ↔ core.**
* Schemas elaborate to `∀`. Uses elaborate to instantiations.
* The surface's per-use rule is SOUND by C: a use of a parametrically typed definition is
  typed at the instance.
* The oracle path (D072): its schema is checked ONCE, at the definition.

*Gate:* the elaboration bridge covers polymorphic definitions.

**E. Module well-typedness over every definition.**
* `ModuleTyped` requires a typing for every telescope entry.
* Unused ill-typed polymorphic definitions are rejected, with a red test first.

*Gate:* Certified green, `cabal test` green, and the new rejection tests green.

## 5. Risks

* **The type context in every core rule:** it doubles the core's size unless `Δ` is a
  parameter of the judgment rather than an index. Decide in A.
* **Codegen monomorphizes:** the `∀` must stay erased before IR, so check that nothing
  downstream needs the family.
* **Interaction with plan 0.101 (capturing algebras):** a polymorphic algebra captured in
  a `cata` is an instance at the capture site, so no new case is needed, but verify it.
* **Sig-less schemas (D072):** a wrong oracle schema becomes a REJECTED DEFINITION rather
  than a rejected use. That is a user-visible change in error location, and the better one.
