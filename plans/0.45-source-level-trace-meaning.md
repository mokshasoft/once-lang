# Plan 0.45 — Source-level trace meaning (make the typechecker load-bearing)

> **One sentence.** Re-anchor the source's meaning `⟦ src ⟧` from `obs (elaborate
> src)` (IR pivot) to a **source-level SigOp-trace reference** computed *before*
> elaboration, commit that (broken) spec, and then make it true — so the **whole
> compiler, typechecker included, is verified to preserve the source trace**.

## Why this plan exists (the IR-pivot hides the typechecker)

Plan 0.44 fixed the observable *type* (`Behavior = ℕ → List SigOpEvent`) and the
apex statement (`exec arch bytes ≈ ⟦ src ⟧`). But the *meaning* is still
`⟦ src ⟧ := obs (elaborate src)` (`SourceTrace.agda`). That **anchors the spec at
the IR**: the elaborator is baked into the spec, so if the typechecker elaborates
`src` to the *wrong* IR, both sides of `correct` move together and it still holds.
The typechecker literally **cannot be caught** — which is exactly why its proof
structure never showed up as a constraint. The statement looks top-level
(`compile` runs every stage), but the spec is middle-out.

`correct` is only meaningful if `⟦ src ⟧` is defined **independently of the
elaborator**. Then `compile` (typecheck + elaborate + codegen + assemble) must be
*proven* to preserve it, and a meaning-changing elaboration breaks the theorem —
the typechecker becomes **load-bearing**.

## The redefinition

```agda
-- WAS (IR pivot — SourceTrace.agda):
--   ⟦ src ⟧ = obs (elaborate src)        -- spec moves with the elaborator
-- NOW (source-level reference, independent of elaboration):
--   ⟦ src ⟧ = sourceTrace src            -- the program's intended SigOp trace
```

`sourceTrace : Source → Behavior` is a **direct reference interpreter** over the
surface that says "these are the SigOp calls this program makes, in order" — *not*
obtained by running the elaborator. It becomes the spec, and a new (smaller) TCB.

The staging seam already exists: `Compile.module-to-asm-correct` is the postulate
spanning `Module → asm`, so it simply **absorbs** the elaborate step. No new
plumbing — its discharge now necessarily includes `elaborate-preserves-trace`
(`obs (elaborate src) ≈ sourceTrace src`), which is where the typechecker becomes
load-bearing.

## Method — definition-first, break the build (as in 0.44)

Commit the re-anchor with `sourceTrace` **undefined**, so the build is red and the
gap is explicit and unignorable. Then fix top-down.

- **Phase 1 — Re-anchor (break the build).** In `SourceTrace.agda`, replace
  `⟦ src ⟧ = obs (elaborate src)` with `⟦ src ⟧ = sourceTrace src`, where
  `sourceTrace : Source → Behavior` is **declared but not defined**. Commit this
  ALONE. Build red (missing definition). The spec is now honestly source-anchored;
  the IR pivot is gone.

- **Phase 2 — Part A: define `sourceTrace`.** Write the source-level trace
  reference (size proxy: `evalSurface` is 199 lines, `obs` 155 lines — expect
  ~150–300 lines, `evalSurface` as a near-template but tracking SigOp calls
  instead of discarding their args). Build green again, with
  `elaborate-preserves-trace` *named and load-bearing* inside
  `module-to-asm-correct` (still postulated). **At this point the spec is correct
  and honest; the elaborator-correctness is an explicit named obligation, not a
  hidden trust.**

- **Phase 3 — Part B: discharge `elaborate-preserves-trace`.** Prove the whole
  `Module → IR` lowering preserves the trace — `TypeCheck.Elaborate` (`checkElabV`
  & co., ~2400 lines) + `Surface.Elaborate.elaborate` (330 lines) + desugar. A
  structural induction relating each surface construct's trace to its elaborated
  IR's `obs`. This is the **large** project: it is "verify the frontend," and it
  **subsumes** the `ErrorProofs`-style fixes (`with`-opacity, value-lift clause
  overlaps) — those proof-structure problems are this phase's bulk, so there is no
  point polishing them in isolation first. Multi-session.

## What it exposes / discipline

- The typechecker's proof structure (`with`-opacity, clause overlaps) becomes the
  body of Phase 3 — *correctly*, because that is what verifying the elaborator
  requires.
- **TCB honesty:** the win is real only if `sourceTrace` is *simpler* than the
  elaborator (a direct recursive interpreter, no type-directed elaboration /
  closure conversion / slot allocation / codegen). Keep it small and obviously
  correct by inspection; otherwise we just moved the trust.
- **Definition-first, no IR pivot, no middle-out.** The spec is committed before
  the discharge; the discharge follows the typechecker the build forces on us.

- **Phase 1 ✓** — re-anchored `⟦ src ⟧ = sourceTrace src` (committed broken, then fixed).
- **Phase 2 Part A ✓** — `Once.Verified.SourceSemantics.runTrace` (154 code lines): a
  defunctionalised + fuel-indexed reference interpreter over `RawExpr`. Arith faithful
  (div/mod + comparisons mirroring `evalSurface`); SigOp = one event, sole emitter; cata
  via `In`-position detection. Recorded as **D057**.
- **Phase 2 done** — `⟦_⟧M = runTrace` (module meaning is the source trace, no longer
  opaque); `gmoduleToModule-correct` **discharged** (J-style `sourceTrace-aux` +
  `⟦⟧-via-module`, the with-opacity fix); `module-to-asm-correct` is now a **theorem**
  factored into:
  - `elaborate-preserves-trace` (factor 1, frontend — NAMED, load-bearing, postulated);
  - `codegen-asm-correct` (factor 2, backend — postulated, `compile-correct-flat`'s target).
- **Phase 3 (Part B) — in progress** — discharge `elaborate-preserves-trace`: the
  structural induction over `checkElabV` + `Surface.Elaborate` relating `obs (moduleToIR m)`
  to `runTrace m`. Multi-session; this is where the `ErrorProofs`-class proof structure
  surfaces *inside* the grand theorem.

## Non-goals

- The parser / lexer / `GModule` layer — `Source = GModule` is `compile`'s input;
  text→`GModule` stays trusted. (A later plan could push the anchor up further.)
- Phase 3 (the frontend-lowering discharge) — deferred after Phase 2; it is the
  major frontend-verification project and the home of the `ErrorProofs`-class work.
