# Plan: Core Invariants Refactoring

## Goal

Transform IRResultAWF from 26 fields with mixed positive/negative invariants to a minimal set with positive-only reasoning, as specified in `stack-model-design.md`.

**End state:**
- Two core invariants: `output-monotone`, `scratch-bounded`
- Positive write bounds: `trace-writes-above`, `trace-writes-below`
- All preservation derived from writes-region (not stored)
- No frame-capacity, no reclaim fields
- Perfect scratch reclaim enforced

## Current State vs Target State

### Current Invariants (IRResultAWF)
```agda
-- Bounds relative to INPUT frontier
max-slot-usage-bound : max-slot-written ≤ next-slot alloc + ir-stack-requirement
slot-stays-in-budget : next-slot final-alloc ≤ next-slot alloc + ir-stack-requirement

-- Negative invariants (stored)
mem-preserved-before : ∀ loc → BeforeFrontier alloc loc → readLoc final loc ≡ readLoc s loc
frame-preserved : current-frame final-alloc ≡ current-frame alloc
capacity-preserved : frame-capacity final-alloc ≡ frame-capacity alloc
```

### Target Invariants (from design document)
```agda
-- Core positive invariants
output-monotone : next-slot alloc ≤ next-slot final-alloc
scratch-bounded : max-slot-written ≤ next-slot final-alloc + ir-scratch-requirement

-- Positive write bounds (already have)
trace-writes-above : TraceWritesAbove (next-slot alloc) trace
trace-writes-below : TraceWritesBelow max-slot-written trace

-- Derived (not stored): preservation follows from writes-region
```

## Key Insight

The design's `scratch-bounded` bounds scratch relative to **output** (final frontier), not input. This cleanly separates:
- **Output**: unbounded, runtime-determined (how much frontier advanced)
- **Scratch**: bounded, static (temporary space above output)

## Implementation Phases

### Phase 1: Add New Invariant (Non-breaking)
Add `scratch-bounded` field to IRResultAWF alongside existing fields.

### Phase 2: Create Derivation Functions
Create `derive-mem-preserved` function that derives preservation from trace bounds.

### Phase 3: Remove frame-capacity
Remove `frame-capacity` field from AllocState and related fields.

### Phase 4: Switch to Derived Preservation
Remove `mem-preserved-before` field, use derivation instead.

### Phase 5: Remove Redundant Fields
Remove `max-slot-usage-bound`, `slot-stays-in-budget`, rename `ir-stack-requirement` → `ir-scratch-requirement`.

### Phase 6: Enforce Perfect Scratch Reclaim
Add invariant: `next-slot final-alloc ≡ output-boundary`.

### Phase 7: Remove Redundant Reclaim Fields
Remove all `reclaim-*` fields once perfect reclaim is enforced.

## Dependency Graph

```
Phase 1 (add scratch-bounded)
    ↓
Phase 2 (create derivation functions)  ←── Phase 3 (remove frame-capacity) [parallel]
    ↓
Phase 4 (switch to derived preservation)
    ↓
Phase 5 (cleanup: max-slot-usage-bound, slot-stays-in-budget)
    ↓
Phase 6 (enforce perfect scratch reclaim)
    ↓
Phase 7 (remove reclaim fields)
```

## Build & Test Strategy

**Command:** `timeout 120 make agda`

**Verification after each phase:**
1. Run `timeout 120 make agda` on modified files
2. Ensure `Dispatcher.agda` still type-checks
3. Check no new holes introduced

## Summary

This plan transforms IRResultAWF from 26 fields to a minimal set:
- `result-loc`, `final-state`, `final-alloc`, `trace`, `trace-correct` (core)
- `result-valid-wf`, `result-before`, `rax-is-result`, `not-halted` (validity)
- `output-monotone`, `scratch-bounded` (core invariants)
- `trace-writes-above`, `trace-writes-below` (positive bounds)
- Derived: `mem-preserved`, `frame-preserved` (from writes-region)

Removed:
- `frame-capacity`, `capacity-preserved`, `trace-preserves-capacity`
- `max-slot-usage-bound`, `slot-stays-in-budget` (subsumed)
- `reclaimable-slot`, `reclaim-*` (after perfect reclaim)
- `mem-preserved-before`, `frame-preserved` (derived instead)
