# Plan 0.2.4.7: Discharge IRTraceCorrect frontier-mismatch postulates

## Goal

Discharge the four `ir-to-trace-correct-{compose,pair,curry,apply}`
postulates in `formal/Once/CCC/Codegen/IRTraceCorrect.agda` (lines
237–256). These are the only `ir-to-trace-correct-*` cases still
postulated; the trivial cases (id/fst/snd/terminal/initial/arr/
free-heap/out-μ/Out) are all proved.

## Why these are postulated today

`ir-to-trace ir = ir-to-trace' 0 0 ir` hardcodes the slot frontier to
0. `IRTraceCorrect` is stated for arbitrary `alloc` with arbitrary
`next-slot alloc`. The WF helpers (`run-pair` / `run-curry` /
`run-apply` / `run-compose`) build traces using slots starting at
`next-slot alloc`, not 0.

For non-trivial IRs (those that emit slot-bearing instructions:
`store-at-slot`, `lea-slot`, `restore-input`), the trace from
`ir-to-trace` and the trace inside `IRResultAWF.trace (run-X …)`
diverge whenever `next-slot alloc ≠ 0`. So the existing theorem
statement is conditionally false — the postulates are unprovable as
stated.

`ir-to-trace-correct-compose` has an additional structural issue:
even if the precondition `next-slot alloc ≡ 0` were added, after
`f` runs `next-slot alloc' = n1 ≠ 0`, so the IH on `g` cannot use
the same precondition. Compose's recursion *fundamentally* needs a
frontier-parameterised theorem.

## Why the runtime is green despite this

Layer 0 binaries (`(id . id . id) 42`, `(snd . snd . snd) (1, (2,
(3, 42)))`, etc.) all enter the codegen at `next-slot alloc = 0`,
where `ir-to-trace`'s frontier-0 trace coincides with what
`run-X` would produce. The discrepancy only matters for the
formal correctness theorem at non-zero frontier, which doesn't
arise in current programs. The 4 postulates are therefore an
audit-visible verification gap, not a runtime bug.

Plan 0.2.4.5 D2 (morphism realm split, commit `eb639573`) keeps
Layer 0 programs in the morphism realm, where compose chains
collapse to pure `_∘_` IR — no `apply`, no `pair`, no `curry`. The
4 postulates only fire on closure-realm IR (effApp's `arr ∘ curry
((apply ∘ ⟨…⟩) ∘ fst)`, entry wrap's `apply ∘ ⟨main, terminal⟩`,
sigOp arrow case's `curry (SigOp ∘ snd)`), all of which currently
execute at frontier 0.

## Design space

Three principled options surveyed (2026-05-08):

### Option 2 — Parameterise `IRTraceCorrect` on frontier `n`

```agda
IRTraceCorrect : ℕ → IR A B → Set
IRTraceCorrect n ir =
  ∀ mIn x input-loc s alloc →
  next-slot alloc ≡ n →     -- new precondition
  ValidAtWF mIn alloc x input-loc s →
  …
  let trace = proj-trace (ir-to-trace' n 0 ir)   -- frontier-aware
      result = exec-trace trace s alloc
  in ∃[ mOut ] ∃[ result-loc ]
     ValidAtWF mOut (proj₂ result) (eval ir x) result-loc (proj₁ result)
```

- All 8 trivial discharges generalise trivially (their traces don't
  depend on `n`).
- The 4 postulated cases discharge by lining up `ir-to-trace' n 0 ir`
  with `run-X`'s trace (both use the same frontier).
- Compose's IH passes `n1` (post-f frontier) to `g`'s recursive call.
- Top-level callers (`compile-correct`, per-arch `CompileCorrect`)
  thread `n = 0`.

**Pro**: smallest signature change. No public-interface churn.
**Con**: still only valid at the precondition; `IRTraceCorrect` is
no longer "for any alloc" but "for alloc whose frontier matches".

### Option 3 — `ir-to-trace` takes `AllocState`

```agda
ir-to-trace : AllocState → IR A B → AbstractTrace
```

The codegen function and the WF spec consume the same alloc state,
so they can't drift.

**Pro**: most honest about the dependency. Public `compile = …`
becomes `compile alloc ir = …`, no hidden default.
**Con**: propagates to `compile-trace`, three arch
`CompileCorrect.agda`s, the Haskell extraction, and any test that
calls `compile`. Larger refactor than Option 2.

### Option 5 — Slot-shift lemma + Option 2 signature

Same signature as Option 2, plus a structural lemma:

```agda
ir-to-trace'-shift :
  ∀ {A B} (n l : ℕ) (ir : IR A B) →
  ir-to-trace' n l ir ≡ shift-result n (ir-to-trace' 0 l ir)
```

where `shift-result n` adds `n` to the resultant frontier and shifts
slot offsets in the main trace (bodies are unchanged — they recurse
with frontier 0 internally). With this lemma, per-IR proofs go via
`ir-to-trace ir = ir-to-trace' 0 0 ir`'s frontier-0 form and
shift-by-n at the boundary.

**Pro**: localises frontier-handling into one structural lemma. Once
proved, future IR additions just extend the shift lemma's case
analysis.
**Con**: still needs **exec-trace translation invariance** as a
companion lemma — running `shift-trace n t` on alloc with `next-slot
= p` must correspond (in register state and output value) to running
`t` on alloc with `next-slot = p − n`. This is non-trivial induction
on trace length covering every slot-bearing instruction's
`exec-abstract` clause.

## Recommended approach

**Hybrid Option 2 + 5:**

1. Adopt Option 2's signature (`IRTraceCorrect : ℕ → IR → Set` with
   `next-slot alloc ≡ n` precondition and `ir-to-trace' n 0 ir` as
   the trace). This is the load-bearing structural change.
2. Phase the discharges:
   - **Phase A**: signature change + generalise the 8 trivial
     discharges. ~½ day. `make typecheck` should still pass.
   - **Phase B**: prove `ir-to-trace'-shift` + `shift-trace`
     correctness (exec-trace translation invariance). ~1 day.
   - **Phase C**: discharge `ir-to-trace-correct-compose` (uses both
     phases). ~½ day.
   - **Phase D**: discharge `ir-to-trace-correct-pair`,
     `-curry`, `-apply` (similar pattern, additional alloc-state
     threading). ~1 day.
3. Top-level wiring: `compile-correct` passes `n = 0` matching the
   public `ir-to-trace ir` shape. Three per-arch `CompileCorrect.agda`
   updates. ~½ day.

**Total estimate: 3-4 days focused work.**

## Implementation order

1. **Phase A — signature change**:
   - `IRTraceCorrect.agda`: add `n` parameter to `IRTraceCorrect`.
     Trace becomes `proj-trace (ir-to-trace' n 0 ir)`. Add
     `frontier-eq : next-slot alloc ≡ n` precondition.
   - Update each of the 8 trivial discharges (id/fst/snd/terminal/
     initial/arr/free-heap/out-μ/Out) to take `n` and pass it
     through. Their proofs don't change because their traces are
     `n`-independent.
   - The 4 postulated cases get `n` added to their signatures.
   - `compile-correct`'s caller of `ir-to-trace-correct` instantiates
     `n = 0` (since `compile = … ∘ ir-to-trace = … ∘ ir-to-trace' 0 0`).
   - Per-arch `CompileCorrect.agda` (×3): same wiring update.
   - **Gate**: `make compiler-x86-64` green.

2. **Phase B — shift lemmas in `IRToTrace.agda` (or new module)**:
   - `shift-instr : ℕ → AbstractInstr → AbstractInstr` adding `n` to
     `store-at-slot`, `lea-slot`, `restore-input`, `load-from-slot`,
     `instr-reclaim-to`, `worklist-{init,push,pop,check}`. Identity
     on the rest.
   - `shift-trace : ℕ → AbstractTrace → AbstractTrace` (lift to
     lists).
   - `shift-bodies : ℕ → List (ℕ × ℕ × AbstractTrace) → … → …`
     **identity** (bodies recurse with frontier 0; their slot
     offsets are independent of parent's frontier).
   - `ir-to-trace'-shift` lemma by induction on IR. Mostly mechanical.
     Key cases: pair (3+ slot offsets), curry (2 slot offsets +
     body), apply (2 slot offsets), compose (recursive shift through
     f and g traces).
   - `exec-shift-trace-correct`: the translation-invariance lemma.
     States that running `shift-trace p t` on alloc with `next-slot =
     p` produces final state where register values and output value
     match running `t` on alloc with `next-slot = 0`, modulo the
     slot-translation in memory positions.
   - **Gate**: lemmas typecheck, no new postulates introduced.

3. **Phase C — discharge `ir-to-trace-correct-compose`**:
   - Structure: `ir-to-trace' n 0 (g ∘ f) = (n2, l2, ft ++
     mov-to-input ∷ gt, fb ++ gb)` where ft = `ir-to-trace' n 0 f`
     and gt = `ir-to-trace' n1 0 g` with n1 = post-f frontier.
   - IH on f at frontier `n` gives correctness of ft.
   - IH on g at frontier `n1` gives correctness of gt.
   - Compose by chaining the two state transformations through the
     `mov-to-input` bridge.
   - Reference: `run-compose` in `Once.CCC.Machine.IR.ComposeWF` —
     mirror its structure.

4. **Phase D — discharge pair / curry / apply**:
   - Each follows the same pattern: open the trace structure, use
     IH on body sub-IRs, transport through the slot-store/load
     instructions.
   - `run-pair` / `run-curry` / `run-apply` from
     `Once.CCC.Machine.IR.{PairWF2,CurryWF,ApplyWF}` provide the
     correspondence templates.

## Out of scope

- Any change to `compile`'s public signature (Option 3). Public
  interface stays as `compile : IR A B → Program`.
- Any change to `ir-to-trace`'s public signature. Stays as
  `ir-to-trace : IR A B → AbstractTrace = ir-to-trace' 0 0 ir`.
  Frontier handling is internal to the proof side.
- The unrelated closure-realm ABI bug (returned closures dangle past
  `addq %rsp; ret`). That's tracked in
  `0.2.4.5-morphism-realm-split.md` under "Closure-realm ABI fix
  open"; current frontend doesn't reach it.

## Acceptance

- Net postulate count in `IRTraceCorrect.agda`: 0 in the
  `ir-to-trace-correct-*` family. Other postulates in the file
  (sigop value-flow, codegen-faithful) untouched.
- `make compiler-x86-64` green.
- Three Layer 0 binaries continue to exit correctly.
- Optional: stress with a deeper/wider Layer 0 program to confirm
  the new theorem covers a richer class.
