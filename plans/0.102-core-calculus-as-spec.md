# Plan 0.102 — The Spec is a core calculus (the first rung of the OCP-0009 kernel); the bidirectional judgment is its surface

## 0. The diagnosis

Once's semantics is categorically clean: types are objects, derivations denote morphisms
`⟦Γ⟧ → T⟦A⟧` of a Kleisli/Freyd category, subtyping is coercions (D226), `Void` is initial.
At the level of MEANINGS the metatheory is nearly free: substitution is composition, let = def
is the same composite, narrowing to `0` is precomposition with `¡`.

But the Spec's typing judgment is the bidirectional, mode-structured, syntax-directed ALGORITHM
over named raw syntax, with a primitive rule per combinator. Asking the algorithm for the
category's properties turns each property into a per-rule obligation, multiplied by
primitives × modes × {plain, `Void`, grade}. Plan 0.94 is the record:

| property (free in the model) | what it cost on the algorithmic Spec |
|---|---|
| `compose`'s middle object | a new mode `⊢ᵈ`, two routes, a mode-agreement theorem |
| substitution / let = def | a context relation, named-syntax scoping, capture premises, the cleared algebra context |
| narrowing to `0` | an ex falso variant of every eliminator, usage of dead code, a clash with the spine |
| grade narrowing | blocked by `effApp`'s suspended result (D229 β) |

Standard practice splits the two: a small DECLARATIVE CORE is the language definition, and the
bidirectional checker is a SURFACE that elaborates into it, sound and complete relative to
annotated programs.

## 1. This is OCP-0009's plan, applied to the compiler first

OCP-0009 states the principle ("the expressive power lives in surface sugar while the
metatheory lives in a small, uniform core") and its POC plan §9 prescribes the landing shape for
the dependent kernel:

* **`Spec/Kernel`** — the kernel AS DATA: term syntax, the typing judgment `Γ ⊢ t : A`, the
  equality judgment `Γ ⊢ A ≈ B` (unoriented), the conversion rule. Pure inductive definitions,
  zero algorithms.
* **`Spec/IR`** — the IR's syntax and equational theory, with one blessed meaning `⟦_⟧`.
* **The bridge** — elaboration kernel → IR, proven, not trusted.
* "Orientation, strategy, NbE, `nf`, **bidirectional checking**: all IMPLEMENTATION, outside the
  spec, proven sound+complete against it. Today the POC's kernel is de facto the algorithm —
  that inversion is the point of the breakout."

The compiler has the SAME inversion today (its Spec is the bidirectional judgment). This plan
performs the breakout on the compiler side, for the non-dependent language, so that the
dependent kernel later EXTENDS the same judgment instead of arriving as a second one. The design
choices below are therefore taken from the POC wherever it already decided them:

| choice | POC decision | consequence here |
|---|---|---|
| binding | de Bruijn, strict substitution (K0 — the semantic CwF was killed by Beck–Chevalley) | core terms are well-scoped de Bruijn |
| typing style | EXTRINSIC: raw terms + a judgment `_⊢_∷_` (the dependent kernel needs terms in types) | the core is `Tm n` + `Γ ⊢[ρ] t ∷ A`, not the intrinsic `Surface.Expr` |
| grading | variable-based QTT, usage vectors (§7 fork (b); the compiler's own choice) | the judgment carries `ρ`, the same `{0,1,ω}` semiring |
| term formers | a graded λ-calculus (`NbEPQTTJ`); the point-free CCC lives in `Spec/IR` | λ/app/let and the type formers' intro/elim are the core; every CCC combinator is a DEFINITION (§4 A) |
| recursion | generic `μ F` with its eliminator (never one former per datatype); `ν` a former, type-level corecursion banned | `cata`/`ana` as today; the eliminator is the non-dependent instance of `ind` |
| equality | an equality judgment next to typing, unoriented, one row per former × {β, η}, each row with its model-soundness lemma | introduced here with the non-dependent rows; it is also what discharges the optimizer's normalization postulates |
| usage at elaboration | must NOT be discarded (ARCHITECTURE §3's "architecture bug") | the core judgment keeps `ρ`, so the linear bridge (`Lq⟦_⟧`) can later start from it |

## 2. History — why the Spec is where it is

* D060 had one meaning with two presentations, `⟦_⟧ˢ` over the intrinsically typed surface
  `Expr` — a core in all but name.
* OCP-0006 (plan 0.58) moved the meaning onto typing DERIVATIONS (`⟦_⟧ᵈ`, "no `Surface.Expr`"),
  because core terms were produced by the elaborator, which must not be trusted.
* D134 names the bidirectional judgment "the declarative judgment"; D072 keeps the "kernel"
  bidirectional — after the proof assistants, whose kernels however judge a small core.

The core-as-Spec split was never considered on the compiler side (OCP-0009 §9 recorded it for
the dependent kernel only). The reason for dropping the core is met by stating the elaboration
as a RELATION in the Spec; its functional form already exists (`realize`), and `MeaningBridge`
already proves the two meanings equal.

## 3. What changes and what does not

* **Accepted programs** — unchanged: the surface judgment is today's.
* **Meaning** — unchanged: the core's meaning is today's `⟦_⟧ˢ` / `⟦_⟧ᵈ`, already proven equal.
* **Runtime** — unchanged: compilation keeps its path (`fst` still emits `IR.fst`). The compiler
  never goes THROUGH the core term; its obligation is semantic — the emitted IR means what the
  core term the Spec assigns means. Defining a combinator as a λ-term costs one model lemma
  (`⟦IR.fst⟧ = ⟦λp. π₁ p⟧`), not a runtime translation or an optimizer dependency (D044/D045
  stay intact).
* **Theorems** — move: substitution, let = def, narrowing (as coercion substitution) become core
  theorems; the surface keeps soundness, completeness relative to annotation, and coherence.

## 4. Phases

**A. Write the core (`Spec/Core`), simply typed and graded.**
  * `Tm n` (de Bruijn) and `Γ ⊢[ρ] t ∷ A` over Once's `Type` (graded arrows, `μ`/`ν`, base
    types, `Void`), with explicit coercions (`coerce p t`, `absurd t`) instead of a subsumption
    rule, and definitions as a telescope (so let = def is β).
  * The equality judgment `Γ ⊢ t ≈ u ∷ A`, one row per former × {β, η}, each with its
    model-soundness lemma — the POC's grid discipline.
  * **Effects are settled, not reopened**: effects live on arrows (D032), one graded arrow
    `A ⇒[q π] B` (D046), the grade a checked, erased refinement with pure ⊑ eff as subsumption
    (D068), grades read off the denotation (D222: `pair` shares one π, `curry`'s outer arrow is
    effect-free), an effectful arrow into `Void` halts (D225/D227). The core's λ/app carry that
    grade; the POC is silent only because its dependent kernel is effect-free. One LOCAL
    question inside the arrow model: `effApp`'s suspended result `Unit ⇒[eff] B`, which blocks
    grade narrowing (D229 β).
  * **The CCC combinators are definitions, not formers** (D-entry): `id`, `compose`, `fst`,
    `snd`, `pair`, `terminal`, `inl`, `inr`, `case`, `initial`, `curry`, `apply` are core
    λ-terms (`initial` via the `Void` eliminator; `compose f g = λx. g (f x)` at the graded
    arrow); `In`/`Out`/`cata`/`ana` are `μ`/`ν`'s formers and eliminators. The surface keeps
    them as syntax; the elaboration relation maps each to its definition. Consequence: they
    leave the typing judgment (the per-rule × per-mode multiplication of plan 0.94 goes with
    them) and the Spec gains NO trusted combinator table — their meaning is derived.
  *Gate*: the core written, the decisions recorded, postulate-free. (Not `--safe`: that flag
  is coinfective and the project's `Once.Type`/`Denotation` tier is not built with it.)

**B. Core metatheory.** Substitution (and its typing lemma), let = def, narrowing to `Void` as
substitution of `coerce ¡ x`, usage algebra. *Gate*: postulate-free.

**C. The bridges.**
  * core → meaning: `⟦_⟧` on core derivations (today's `⟦_⟧ᵈ`, restated over the core);
  * surface → core: the elaboration RELATION (from `realize`), soundness (every surface
    derivation elaborates to a core derivation), coherence (A4 becomes a surface property);
  * core → IR: the compiler's `elaborate` (surface → IR, its path unchanged), proven to mean
    what the core term means; per combinator this is ONE model lemma
    `⟦IR.c⟧ = ⟦definition of c⟧`, mode-independent. The grade is kept.
  *Gate*: the three bridges proven; `MeaningBridge` retargeted.

**D. Move the Spec door.** `Once.Spec` gains `Spec/Core` (syntax, typing, equality);
`Spec.Meaning` is the core's meaning; the surface judgment + elaboration relation become
`Spec.Surface`; `CorrectCompiler` is restated over the core. *Gate*: `Certified` green; the
Spec closure shrinks (the mode structure and the derivation denotation leave it).

**E. Retire what the core makes redundant.** `LetIsDef`/`Unfold` (plan 0.94) shrink to core
lemmas; A′'s ex falso rules are re-evaluated (surface sugar or retracted — narrowing no longer
needs them); plan 0.101 becomes a core change (an algebra is an ordinary core term in context).

**F. Hand-off to OCP-0009.** The dependent kernel lands by ADDING formers (Π, Σ, universes,
`Id`/`Hom`, indexed `μ`) and the conversion rule to `Spec/Core`'s judgment — same syntax
discipline, same grading, same equality grid — and its NbE becomes the implementation of that
judgment's conversion. *Gate*: a written mapping POC module → `Spec/Core` extension (the POC's
`_⊢_∷_` / `Γ ⊢ A ≈ B` onto this plan's judgment), so no second kernel is ever introduced.

## 5. Risks

* The telescope (phase A) touches plan 0.58's definition machinery and the resolver.
* Restating `CorrectCompiler` touches the apex; the extraction gate and exit tests must stay
  green throughout.
* Extrinsic core vs. the compiler's intrinsic `Surface.Expr`: the correspondence (every typed
  core derivation ↔ an intrinsic term) is a real lemma; keep `Surface.Expr` as the
  implementation-side representation until it is proven redundant.
* `effApp`'s suspension (D229 β) may need its own small plan inside the arrow model.

## 6. Progress

**Phase A — landed 2026-09-26 (D231).** `Once.Spec.Core.{Syntax,Typing,Meaning,Derived}`,
each green and postulate-free:

* `Syntax`: `Tm n` (20 formers), renaming/substitution, `Value`, the arithmetic as
  saturated `prim` (17 Pure SigOps).
* `Typing`: `Γ ⊢[ Ψ ] t ∷ A ! π`, 25 rules. Terms carry an EFFECT GRADE. This was forced
  by the combinator decision: a λ-defined `compose` has an effectful body. It is D032's
  arrow discipline as a λ-calculus (D231 §3).
* `Meaning`: one clause per rule into the existing model (`⟦Γ ↾ Ψ⟧ → T⟦A⟧`). Every clause
  is the surface clause without modes. The shared semantic operations are still imported
  from `Once.Denotation.Meaning`; phase D gives them their own module.
* `Derived`: every combinator as a λ-term, arms bound by `let` (evaluated once, eagerly,
  in today's order; linear per D127), plus the functor action `mapᶜ`.

Deviations from §4, stated:
* The EQUALITY JUDGMENT is not written in A. Top-down: nothing consumes it yet. It
  lands with its first consumer, either the combinators' defining equations in C or
  the optimizer's normalization postulates.
* Two gaps are now visible (D231): `ν-type` is ungraded, so `out` is `eff`; an FFI
  arrow's grade is trusted.
