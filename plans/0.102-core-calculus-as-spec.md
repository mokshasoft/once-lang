# Plan 0.102 — The Spec is a core calculus; the bidirectional judgment is its surface

## 0. The diagnosis

Once's semantics is categorically clean: types are objects, derivations denote morphisms
`⟦Γ⟧ → T⟦A⟧` of a Kleisli/Freyd category, subtyping is coercions (D226), `Void` is initial.
At the level of MEANINGS the metatheory is nearly free: substitution is composition, let = def
is the same composite, narrowing to `0` is precomposition with `¡`.

But the Spec's typing judgment is the bidirectional, mode-structured, syntax-directed ALGORITHM
over named raw syntax, with a primitive rule per combinator. Asking the algorithm for the
category's properties turns each property into a per-rule obligation, multiplied by
primitives × modes × {plain, `Void`, grade}. Plan 0.94 is the record:

| property (free in the model) | what it cost on the algorithmic Spec |
|---|---|
| `compose`'s middle object | a new mode `⊢ᵈ`, two routes, a mode-agreement theorem |
| substitution / let = def | a context relation, named-syntax scoping, capture premises, the cleared algebra context |
| narrowing to `0` | an ex falso variant of every eliminator, usage of dead code, a clash with the spine |
| grade narrowing | blocked by `effApp`'s suspended result (D229 β) |

Standard practice splits the two: a small DECLARATIVE CORE is the language definition (it is the
internal language of the structure), and the bidirectional checker is a SURFACE that elaborates
into it, sound and complete relative to annotated programs.

## 1. History — why the Spec is where it is

* D060 had one meaning with two presentations, `⟦_⟧ˢ` over the intrinsically typed surface
  `Expr` (well-scoped, de Bruijn, usage-indexed — a core calculus in all but name).
* OCP-0006 (plan 0.58) built the Spec door and moved the meaning onto typing DERIVATIONS
  (`⟦_⟧ᵈ`): "no `realize`, no `evalᴰ`, no `Surface.Expr`". The reason: core terms were produced
  by the elaborator, and the elaborator must not be trusted.
* D134 names the bidirectional judgment "the declarative judgment" — declarative relative to the
  deciders it removed, but still the algorithm's mode structure.
* D072 keeps the "kernel" bidirectional after the proof assistants — whose kernels, however,
  judge a small core, with the bidirectional layer as the checked elaborator.

The core-as-Spec split was never considered. The reason for dropping the core (don't trust the
elaborator) is met by putting an elaboration RELATION in the Spec — which already exists in
functional form as `realize : derivation → core term`, with `MeaningBridge` proving the two
meanings equal.

## 2. The target

    Spec  = Core     : intrinsically typed core terms (today's `Surface.Expr`, audited)
                       + their meaning ⟦_⟧ˢ
                       + the core metatheory: substitution, let = def, narrowing as
                         coercion substitution — theorems about typed terms, no modes
          + Surface  : what may be written (the bidirectional judgment over `RawExpr`, as today)
                       + the elaboration RELATION  raw ⇝ core  (from derivations; `realize`)
    Correct = compiled trace ≡ ⟦ core ⟧ˢ for the core term the program elaborates to

The accepted programs, their meanings and the generated code are unchanged: the surface
judgment is today's, `⟦_⟧ˢ` is already proven equal to `⟦_⟧ᵈ` (`MeaningBridge`), and compilation
already runs through `Surface.Expr`.

## 3. Phases

**A. Audit the core.** Decide what `Surface.Expr` must lose or gain to be the core:
  * name references (`poly`, `closure`, `sigOp` of own definitions) → a real definition
    mechanism (a telescope of typed definitions), so let = def is β for definitions;
  * explicit coercions (`coerce`, `absurd`) stay term formers — narrowing is substitution of
    `coerce ¡ x`;
  * combinator term formers (`comp'`, `copair'`, `fork'`, `curry'`): keep as primitives or
    define from λ/application — decided on codegen impact (a DECISION, not assumed);
  * effects: keep `effApp`'s suspension or move to value/computation separation (CBPV) — a
    DECISION; not required for this plan.
  *Gate*: a written core definition, each decision recorded.

**B. Core metatheory.** Substitution (typed, by construction), let = def, narrowing to `Void`
as coercion substitution, over the core. *Gate*: postulate-free.

**C. Move the Spec door.** `Once.Spec.Syntax` gains the core; `Once.Spec.Meaning` becomes
`⟦_⟧ˢ` on core terms; the surface judgment + the elaboration relation stay under
`Once.Spec.Typing`. `CorrectCompiler` is restated over the core term. *Gate*: `Certified`
green; the Spec closure shrinks (the derivation denotation leaves it).

**D. Surface theorems.** Soundness (every derivation elaborates to a core term — `realize`) and
completeness relative to annotated programs (today's `check-complete`); coherence (A4,
`realize-invariant`) becomes a property of the SURFACE relation.

**E. Retire what the core makes redundant.** Plan 0.94's surface-level metatheory
(`LetIsDef`, `Unfold`) relocate or shrink to core lemmas; A′'s ex falso rules are re-evaluated
(sugar on the surface, or retracted — narrowing no longer needs them); plan 0.101 becomes a
core change (algebras are ordinary core terms in context).

## 4. Risks

* The core's definition mechanism (phase A) touches the telescope machinery of plan 0.58 and
  the resolver.
* Restating `CorrectCompiler` touches the apex; the extraction gate and exit tests must stay
  green throughout.
* Phase A's two DECISIONS (primitive combinators; effect representation) can each grow into
  their own plan — they are listed, not presumed.
