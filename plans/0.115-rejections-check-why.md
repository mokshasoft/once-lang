# Plan 0.115 — A rejecting test checks why it rejects

## Summary

Many of the compiler's tests check that a bad program is refused, but not why it is refused. Such a
test keeps passing when the compiler refuses the program for some unrelated reason, so it can stop
testing the rule it was written for without anyone noticing. This has already happened: 15 of the 84
refusal tests are refused for a reason other than the one they name. The plan makes every refusal
test name its reason, fixes the tests that were passing by accident, and makes "a refusal names its
reason" the rule for new tests.

## 1. Why

`PuritySpec`, `TelescopeSpec`, `QttSpec`, `TypeErrorSpec` and others asserted only `isLeft`: ANY
rejection passed. D258 turned the String tests into tests that pass for a different reason (an unknown
type, then a parse error, instead of the old type error), and nobody noticed. A rejection test is
evidence about the Spec only if it names the rule that rejects.

## 2. Where we are

### 2.1 The helper (done, step 2)

`compiler/test/Rejection.hs`: `assertRejects what reason r` passes only if `r` is a rejection whose
error text contains `reason`. The reason is a fragment of the elaborator's structured error
(`formal/Once/TypeCheck/Error.agda`, `renderError`) or the message of the stage that rejected (lexer,
parser, import resolution, the driver's signature checks). Errors reach the tests as text, from
`once check` (stdout + stderr), so text is what can be matched.

Every rejecting assertion in `compiler/test/*.hs` now goes through it: the `assertBool … (isLeft r)`
sites, the `rejects` helpers of `TypeErrorSpec` (also used by `FloatSpec`) and `GeneratorSpec`, and
`ParseSpec.assertParseError`. All still pass `""` as the reason (matches anything), so behaviour is
unchanged; the suite passes (566 tests).

`Rejection.hs` carries a TEMPORARY inventory hook: with `ONCE_REJECT_LOG=<file>` each rejection
appends its outermost call site and its error. Remove it in step 3's last commit.

### 2.2 The inventory (done, step 1, 2026-11-02): 84 rejection sites

reject for another reason**:

`InrInInferMode`, `InitialInInferMode` may be unreachable.

Plan 0.113's earlier hand check found two more that were already fixed then (`fst (swap 5)`, an inline
`compose` arm under `pair`).

## 3. Decisions

- **D1, the matching level.** Recommended: match a stable fragment of the rendered error (the rule's
  words, e.g. `Case branches have different types`), not the full text and not the program's own
  names. Alternative: export structured errors through a `once check --json` mode and match
  constructors. Open; the recommendation needs no compiler change.
- **D2, the five "unbound builtin" diagnostics** (§2.2, last five rows). Either fix the elaborator so
  it reports the real rule (an Agda change in `Once.TypeCheck.Elaborate`, re-extraction), or pin the
  current text and leave the diagnostic to a later plan. Recommended: pin now, record the finding, and
  fix the diagnostic in its own commit only if it is local. Open.

## 4. Steps

1. ✅ Inventory every rejecting assertion with its actual error (§2.2).
2. ✅ One helper, `Rejection.assertRejects`, used by every rejecting assertion (§2.1).
3. Fix the 15 wrong-reason tests: rewrite each program so it reaches the rule it names (D258 tests:
   use a type and a value the current Spec has, e.g. `Unit`/`Int`, or a sum); where the program is
   right and the diagnostic is wrong, follow D2. Each fix is checked by giving it its reason.
4. Give the other 69 sites their reason (the fragments are in the inventory). Checked by
   `cabal test`; then flip one reason per file by hand to see the test fail.
5. Remove `isLeft`, the old `rejectsWith`, and the inventory hook. `rejects` takes the reason as an
   argument.
6. Rule for new tests (MERGE.md, the test section): a rejection names its reason.

## 5. Done when

No rejecting assertion in `compiler/test/` passes on an arbitrary error; every one names its reason
and passes; the 15 wrong-reason tests reach the rule they name (or their diagnostic finding is
recorded); MERGE.md states the rule.
