# Plan 0.155 — Once has buffers and strings: contiguous bytes, a meaning of lists, nothing special

## Summary

Once programs cannot hold text today: they read and write one character at a time. This plan adds a
`Buffer` type (a sequence of bytes stored contiguously in memory) and a `String` type built on it (a
sequence of Unicode characters stored as UTF-8). To the mathematics a buffer is just a list of bytes and
a string a list of characters; how they are laid out is the compiler's business, and the layout is
chosen so that handing a buffer to the operating system costs nothing. Buffers get no special
treatment: like every other value, a buffer used once is updated in place, and a buffer used twice is
copied. The design follows Rust's `Vec<u8>` / `String`, the line that Haskell's long search for fast
strings (`String`, `Text`, `ByteString`, lazy variants, builders) ends up pointing at.

## 1. Why

GOAL.md asks for servers and interactive programs on bare metal; without text and byte buffers they
cannot speak any real protocol, and every effect test asserts bytes written by `putc`. D258 removed
`Str` and `Buffer` (plan 0.106) because the machine did not model their content, so a SigOp's string
argument could not be decoded and its proof obligation was refutable. Plan 0.146's linear core is the
first machine that holds content: cells with sizes, layouts from `Spec.ABI`, a free per allocation,
one region. That lifts D258's blocker.

The design must not repeat Haskell's mistake, which was to fix a layout through a type
(`String = [Char]`) and then add a new type for every layout found to be faster. Here a type fixes a
meaning, the layout is chosen once for performance, and the boundary to the world is that same layout.

## 3. Decisions (the user, 2026-11-21/22)

1. **A type fixes a meaning; a layout is chosen per type** (no layout chosen per use). A second
   layout for the same meaning is a second nominal type (plan 0.147 §3.5.2), e.g. `List a` (linked)
   and, later, `Array a` (packed).
2. **`Buffer`'s meaning is `List Byte`** (the free monoid on `Byte`): `++` is its monoid operation,
   `==` is automatic (plan 0.147 §3.5.1), its fold is a fold over the sequence. It is neither a base
   type in the Spec's sense (its meaning is built from `Byte`) nor an ordinary inductive type (its
   layout is not one cell per node): a built-in nominal type whose meaning is a list and whose layout
   is packed. Its operations (`length`, `index`, `slice`, `++`, `set`, `push`, the fold) are
   compiler-minted pure SigOps whose contracts are the list functions, as the arithmetic blocks are
   (D391–D398). `Buffer` is the vehicle for `String` now and `Array a` later. D010 superseded.
3. **The layout is Rust's**: an owned buffer is (pointer, length, capacity), contiguous bytes. Length
   and capacity are run-time data the compiler cannot know, so GOAL.md allows them.
4. **The internal layout is the boundary layout.** At a SigOp a buffer is passed as (pointer,
   length), so passing it costs no copy. The observable is still the meaning (D058: the event records
   the byte sequence); the boundary layout is `Spec.ABI`'s, and the proof obligation is D257 §g's:
   decoding the ABI layout gives the meaning.
5. **No special treatment.** An update (`set`, `push`, `++` into its left operand) is in place exactly
   when the buffer is linear at that use, a fact the compiler knows statically; otherwise `dup` makes
   a deep copy first (D420 point 3). No copy-on-write or any other run-time ownership information
   (D402). Programs that want speed keep buffers linear. Borrowing (plan 0.154) refines copies later.
6. **`String`'s meaning is `List Char`**, `Char` a Unicode scalar value; its layout is UTF-8. `String`
   is `abstract` over `Buffer` (plan 0.147 §3.1.4) with the invariant "the bytes are valid UTF-8".
   The encoding is a layout, not a type parameter: D011's `String : Encoding -> Type` is superseded.
   Another encoding (UTF-16 for Windows) is a boundary-ABI question. Consequences: no O(1) indexing
   by character; `bytes : String -> Buffer` (meaning: UTF-8 encoding; cost: none);
   `fromUtf8 : Buffer -> Maybe String` (validates in O(n), copies nothing when its input is linear).
7. **`Byte` and `Char` are base types.** `Byte` is ℤ/2⁸, a commutative ring like `Int` (D409); `Char`
   is a Unicode scalar value (no arithmetic, a total order by code point). **ASCII is not a type**:
   ASCII is a subset of Unicode and ASCII text is valid UTF-8; protocol code works on `Buffer`/`Byte`
   with byte literals (`b"GET"`) and `isAscii`. An `abstract type Ascii` can come later if wanted.
8. **Literals** live in the read-only data section. A use that only reads (passing to `write`) reads
   them there (a lend); a use that owns one copies it into a cell, which is `dup` from a constant
   (D450). Linear code never writes into a literal. A `String` literal is checked as UTF-8 when the
   program is compiled.
9. **SigOp signatures are plain values; the memory protocol is the boundary ABI.**

   ```
   write : Act (Fd * Buffer) Int     -- the bytes go out; the answer is a count
   read  : Act (Fd * Int) Buffer     -- at most n bytes come back
   ```

   - A buffer argument is passed by pointer and is **lent** for the call: the Interpretation reads
     it, does not write it, and keeps no pointer to it after the call returns. If it was the
     argument's last use, the core frees it after the call.
   - A buffer answer is written into a block the caller supplies (D382, extended): for `read`, the
     ABI ties the block's capacity to the `Int` argument; the world fills k ≤ n bytes and the length
     becomes k. The block is fresh, so it is linear by construction: writing needs ownership, and it
     has it. A server reusing one read buffer every round is plan 0.154's reuse (a dying buffer of the
     right size becomes the answer's block), not a signature.
   - These promises (no write to an argument, no pointer kept, at most the capacity written) join the
     environment hypothesis (GOAL.md), stated in the Spec with the Interpretation's ABI obligation
     (plan 0.111).
   - An answer with no bound known in advance (a line of any length) is a stream of bounded reads
     (a loop, or a `ν` of buffers): no new type.
   - **Foreign memory is copied in.** Memory a library or kernel allocated (a `char*` from C,
     `getline`) never reaches the program: the Interpretation copies it into the answer block and
     releases the original itself. So no `Foreign Buffer` type is needed for expressiveness.
     *Later, zero-copy, if measurements ask for it (large `mmap`'d files, zero-copy networking, seL4
     shared frames, DMA), and still without surface syntax*: a nominal type declared in the
     Interpretation's own module (an ordinary `abstract type`), whose `drop` the Interpretation's ABI
     routes to its release SigOp. The core inserts the drop at the value's last use, so an affine core
     (D276) releases it exactly once with no must-use types. Not a flag on `Buffer`: the origin of a
     buffer after a `case` join is run-time ownership information (D402).
10. **The allocator uses size classes** (amends D384 and D428 for buffers). A buffer's block is taken
    from the pool of the smallest class that fits; its capacity is that class, so `free` finds the
    pool from the stored capacity. Appending to a linear buffer fills its spare capacity; when it is
    full the contents move to a larger class and the old block returns to its pool (amortised O(1)
    per byte, Rust's `Vec` growth with free lists). The space claim keeps its form, Σ c · peak_c over
    the classes, for any class set fixed when the program is compiled. Invisible in the surface
    language. Class spacing and growth factor are compiler parameters, not necessarily powers of two:
    the default is powers of two (simple to measure); tuning per program or per use site after
    profiling is later (plan 0.130). Chunked buffers (fixed-size cells, a rope) were rejected: they
    keep every block size static, but break contiguity, so every SigOp call would copy.
11. **Ordering**: after plans 0.146 (correctness needs the core's cells), 0.147 (`abstract`, nominal
    types, monoid `++`) and 0.154 (performance needs reuse and borrowing; correctness does not).

### Open (decided during the work, each with a recommendation)

- **O1. Byte access in the machines.** The flat machine and its lowering are word-addressed (to be
  measured, step 1). Buffers need byte loads and stores (or word operations with masks); each arch
  has them, and each needs its CPU-semantics hypothesis extended. Recommendation: byte load/store
  instructions in the abstract machine, as the arch hypotheses already cover their real counterparts.
- **O2. The width of length and capacity**: one machine word each (as Rust's `usize`).
- **O3. The fold over a buffer**: a compiler-minted loop SigOp with the list fold as its contract, or
  the cata generator at a packed layout. Recommendation: the SigOp first (no change to the cata
  codegen), measured against the second.
- **O4. Slices** (`slice : Buffer * Int * Int -> Buffer`): a copy now; a lent view (no copy) is plan
  0.154's borrowing. No shared slices (they need a GC or run-time ownership information).
- **O5. `compare` on `String`**: bytewise order on UTF-8 is code-point order, so the lexicographic
  order of `List Char` is a byte comparison: no decoding. To be proved once in Agda.
- **O6. Literal syntax**: `"…"` is a `String` (UTF-8 checked), `b"…"` a `Buffer`, `'c'` a `Char`;
  escapes as Haskell/Rust. The lexer token exists (D258).

## 4. Spec changes this plan needs (each a patch the user approves)

1. **Types**: base types `Byte`, `Char`; the built-in nominal type `Buffer` with
   `⟦Buffer⟧ = List ⟦Byte⟧`; its primitives with their contracts as list functions.
2. **`Spec.ABI`**: a buffer's boundary layout (pointer, length); a buffer argument lent for the call;
   a buffer answer in a caller-supplied block whose capacity the signature's ABI ties to an argument;
   the Interpretation's promises (§3.9) in its ABI obligation (plan 0.111).
3. **Surface**: string, byte-string and character literals (O6); D328's "no string-literal
   expressions" and D258's language-state line withdrawn.
4. **`String`** (strata, not the Spec): `abstract` over `Buffer`, the UTF-8 invariant certified
   off-line as plan 0.147 §3.5.6 certifies laws; its meaning `List Char` through decoding.

## 5. Steps

Each step: `formal/scripts/agda-safe.sh certified`, `cabal test`, the exit tests on three arches,
`tests/codegen-measure.sh compare`.

1. **Measure.** What D258 deleted (plan 0.106's commits) and what of it is reusable; byte access in
   the abstract and flat machines (O1); `Spec.ABI`'s argument/answer layouts and D382's answer buffer;
   the region allocator's pools (`Region`, `AllocRun`) and what size classes change in their proofs;
   how D450's literal payloads are materialised. Record in §2.
2. **`Byte` and `Char`** (§4.1, first half): base types, literals, `Byte`'s ring (D409's table),
   `Char`'s order, conversions (`toByte`/`fromByte`, `ord`/`chr` into `Maybe`).
3. **`Buffer` in the Spec** (§4.1, second half): the type, its meaning, its primitives' contracts; the
   front end's typing; tests including each named rejection.
4. **`Buffer` in the linear core**: a buffer cell with (length, capacity) and its bytes; size
   classes in the region (§3.10) with `rinv`/`space`/`peak` restated over classes; `dup` a copy,
   `drop` a free; in-place `set`/`push`/`++` at a linear use; growth into a larger class. `NoLeak` and
   the space claim over the new cells.
5. **Lowering and the machines**: byte loads and stores (O1), the copy loop, the primitives' code on
   x86-64, x86-32, riscv64; the simulation lemmas for buffer cells.
6. **SigOps** (§4.2): a buffer argument lent and decoded from memory (D257 §g; the residual D258 could
   not discharge, now a theorem); answers into caller-supplied blocks; Linux `write`/`read` on three
   arches. Effect tests that assert the bytes (D220).
7. **Literals** (§4.3): the read-only data section, lent reads, copy on own; `b"…"`.
8. **`String`** (§4.4): the abstract type, `bytes`, `fromUtf8`, UTF-8 checked `"…"` literals, `'c'`,
   decoding to `Char`s as a fold; the invariant certificate; `==`, `compare` (O5), `<>`.
9. **The strata library and examples**: `Buffer` and `String` operations; hello world with one
   `write`; an echo server reusing its buffer each round (a gate test: no leak, no growth); `putc`/`getc`
   kept only where they are what a program means.
10. **Documents**: `docs/design/buffers.md` rewritten from §3; decision-log entries (D010, D011
    superseded; D258 lifted; D384/D428 amended for classes; D382 extended); the decision state.

Later, each its own plan when wanted: `Array a` over `Buffer` (flat elements first; elements that own
cells need `dup`/`drop` per element); zero-copy foreign memory (§3.9); class tuning by profile; seL4
IPC buffers (plan 0.148).

## 6. Done when

1. A program reads bytes with `read` into a `Buffer`, builds a `String`, and writes it with one
   `write`, on x86-64, x86-32 and riscv64; the trace records the bytes, and `print "hello"` and
   `print "goodbye"` have different meanings.
2. `NoLeak` and the space claim hold postulate-free over buffer cells and size classes; the echo
   server runs forever in bounded memory.
3. A linear buffer is updated in place and a shared one is copied, with no run-time ownership
   information in the emitted code.
4. No postulate added; the Interpretation's new promises are stated in its ABI obligation, not
   assumed elsewhere.
5. No regression: `cabal test`, the exit tests on three arches, `make merge-gate`; the cost measured.
