# Plan 0.154 — Every module imports only what it uses, and the back end never sees the parser

## Summary

Plan 0.152 made every proof check fit in a small amount of memory, partly by making modules import
only what they use, and by separating the part of the compiler that reads programs (the front end)
from the part that produces machine code (the back end). Two pieces were left. A few modules still
import "everything except these names" instead of "exactly these names". And six of the heaviest
proofs, the ones that show the machine code is correct for each processor, still depend on the
part that reads programs, so any change to the reader rechecks them. This plan finishes both:
afterwards every import names what it uses, and changing how programs are read never rechecks
the processor proofs.

## 1. Why

- **`hiding` is a wholesale import.** `open import M hiding (x)` brings in all of `M`'s scope but
  `x`. It does not leak further (unlike `public`, which D418 removed), but the importing module
  scope-checks all of `M`, and a name later added to `M` can clash. D418's rule is "copy what is
  used"; `using (…)` says that.
- **The back end reaches the front end in 6 modules.** D419 says the back end does not depend on
  the front end; `make layer-gate` ratchets it at a baseline of 6. These 6 are the per-arch
  correctness roots, the heaviest modules in the tree, so a front-end edit (parser, type checker,
  surface syntax) rechecks them. Taking the gate to 0 makes the rule hold without exceptions.

## 3. Decisions

- **D1. Order: after plan 0.146.** (Recommended by the agent, 2026-11-21; the user asked for the
  plan on its own branch.) 18 of the 25 `hiding` sites and 5 of the 7 files in the layer fix
  (`ArchCorrectness`, `X86-64`, `FlatFromObs`, `FnLayout`, `ImageUnique`) are files 0.146 changes;
  doing this first would only add conflicts to 0.146's rebase, and 0.146's gain from it is small
  (most of its edits are in the back end, which rechecks the arch roots either way). If 0.146
  restates the arch theorems over its linear core, step B is done there and this plan keeps only A.
- **D2. What the arch theorems start from** (open; recommendation): the IR program the compiler
  hands the back end, i.e. the block table and `main`'s IR together with the facts the proofs use
  of them (linkedness, distinct names). The resolved module → IR step (`BT`/`TP`/`LK`) and the
  front-end fact that extracted names are distinct move to the apex, where front and back end
  already meet (`Once.Certified` or a composition module beside it). This is proof-only: what the
  compiler emits and what the CLI runs are unchanged, so there is no runtime or performance
  effect; the Spec is untouched (`once-certified` is stated over source text). To confirm when
  the work starts.

## 4. Steps

**A. `hiding` → `using`.**

1. For each of the 25 sites, replace `hiding (…)` with `using (…)` naming what the module uses
   from that import (the fork's `--remove-dead-imports` reports unused names; check by hand).
   Where `hiding` resolved a clash between two imports, the `using` list shows which side each
   name comes from; keep that explicit.
2. Check each touched module (`formal/scripts/agda-safe.sh`), then `make certified-per-module`.
3. Add a ratchet: a `hiding` count in `make public-gate` (or beside it) that may only fall, at 0.

**B. The back end without the front end (layer gate 6 → 0).**

1. Restate the per-arch correctness (`ArchCorrectness` and the RiscV64 / X86-32 / X86-64 roots)
   over the IR program (D2), with linkedness and distinct names as hypotheses instead of being
   derived from a `P.Resolved`.
2. Split `ImageUnique`: the back-end fact (`image-cl`, `fn-unit-nf`, over a table with distinct
   names) stays on the back-end side; the front-end fact (the parser's extracted names are distinct)
   moves to a front-end module.
3. Compose at the apex: `BT`/`TP`/`LK` and the front-end distinctness discharge the new hypotheses
   where `once-certified` meets the arch theorems.
4. `make layer-gate` reports 0; empty `formal/scripts/layer-gate.baseline`.
5. Gates: `make certified-per-module`, the exit tests on the three arches, the AST dump (the trust
   base and RUNS ∖ PROVED unchanged).

## 5. Done when

- `grep -rnE "(import|open).*hiding" formal/Once` finds nothing, and a gate keeps it so.
- `make layer-gate` reports 0 of the back-end modules reaching the front end, with an empty

- `once-certified` and the trust base are unchanged; the exit tests pass on all three arches.
