# Plan 0.53 — Bring X86-32 / RiscV64 to X86-64's Level in the Adequacy Apex (and retire the legacy backend island)

## Correction (2026-07-01) — the premise changed after investigation

This plan was first written to "mirror the X86-64 Plan 0.32 flat stack
(`FlatSimulation`/`CompileCorrectFlat`) to the other two arches and delete
`DirectSimulation`." **That target turned out to be legacy.** Ground-truth
investigation established:

- The live top-level theorem is `Once/Compiler.agda` → `Once.Adequacy` →
  `Once.Adequacy.ArchCorrectness.arch-correctness`. Its checked closure is 162
  modules. It is **green** (post-0.36, confirmed by the standing MAlonzo
  re-extraction that is downstream of the 0.36 `lea-indexed` commit).
- x86-64's witness `x86-64-correct` is discharged through the **`IRObsCorrectFlat`
  observable-trace theorem** (`ir-obs-correct → cata-correct`, Plan 0.36/0.44) —
  **not** the Plan 0.32 flat stack.
- The old backend correctness formulation — `EntryPointCCC`, per-arch
  `CCC.Target.*.Correct` / `.CompileCorrect`, the entire Plan 0.32 flat stack
  (`CompileCorrectFlat`/`FlatSimulation`/`FlatComposition`/`FlatSim`/`ExecCompose`/
  `FlatCorrespondence`/`StepLemmas`), and `DirectSimulation` (x86-32 + riscv64) —
  is an **orphaned island**, reached by **none** of the 162 live modules. It had
  drifted **red** (0.36's `lea-indexed` broke `FlatComposition.headView`; a
  `NatTr`/`Fuse` refactor broke `RecCoreWF`) with no gate catching it, because
  the Makefile's `compiler-x86-64` target still pointed at a renamed-away file
  (`Once/Compile/EndToEnd.agda`, gone in the 0.47/0.48 restructure).

So "retire DirectSimulation" needs **no porting**: the whole legacy island is
dead code relative to the apex. And "bring the other arches to x86-64's level"
means discharging their **Adequacy postulates through `IRObsCorrectFlat`**, not
building a per-arch flat stack.

## The real structure (`Once/Adequacy/ArchCorrectness.agda`)

```
postulate
  x86-32-correct  : ArchCorrect x86-32  (arch-semantics x86-32)   -- whole-record postulate
  riscv64-correct : ArchCorrect riscv64 (arch-semantics riscv64)  -- whole-record postulate

arch-correctness x86-64  = x86-64-correct    -- = x86-flat-from-obs ir-obs-correct  (DISCHARGED via IRObsCorrectFlat)
arch-correctness x86-32  = x86-32-correct     -- postulate
arch-correctness riscv64 = riscv64-correct    -- postulate
```

x86-64's `ArchCorrectness.X86-64` builds `x86-64-correct` from the FS-generic
`IRObsCorrectFlatness {x86v3-frame-semantics}` module via a single **named**
bridge postulate `x86-flat-from-obs` (+ `program-bound`). That is "x86-64's
level": the record is *constructed* from `ir-obs-correct`, with a named,
explicit residual postulate — not a whole-record black box.

## Phase 4 — runtime parity check under QEMU (riscv64 chosen)

Confirm the *emitted* binaries run under user-mode emulation. Findings 2026-07-01:

**Toolchain wiring — SOLVED.** `once build --exe --target riscv64` +
`AS/LD/OBJCOPY = riscv64-unknown-linux-gnu-*` produces a valid **static riscv64
ELF**, and `qemu-riscv64` executes it. (Fixed en route: the 5 `Linux/*.riscv64`
Strata impls used `//` comments that GNU `as` rejects — converted to `#`,
committed `bc922984`.)

**Blocker — the riscv64 runtime backend is incomplete (never executed).**
`exit 42` SIGSEGVs immediately (`si_addr=NULL`, zero syscalls). Root cause:
`Once/Target/RiscV64.agda` is an **83-line stub** emitting only the function
symbol; it lacks the `_start` runtime harness that `Once/Target/X86-64.agda`
(183 lines) emits:
- `.section .bss` + `once_heap_pos` (heap bump-pointer storage);
- `.globl _start` / `_start:` that inits the heap register, calls `once_main`,
  and falls through to `sys_exit(0)`.
So the riscv64 binary has an **undefined `_start`** (entry fell back to
`once_4main`), the heap register and frame pointer `s0` are never initialized,
and main's first `sd a0,0(s0)` writes to null.

**Remaining work (backend feature, not harness wiring):**
1. Implement the riscv64 `_start` in `Once/Target/RiscV64.agda`, mirroring
   x86-64: `.bss`/`once_heap_pos`, `_start:` heap-reg init (`la` the base),
   `call once_main`, exit via `li a7,93; li a0,0; ecall`.
2. Confirm/emit the main frame prologue (riscv64 main uses `s0`-relative slots
   but nothing sets `s0`/`sp`; x86-64 main self-reserves via `sub %rsp`). Decide
   whether `_start` sets `s0` or `AbstractToRiscV` emits the prologue.
3. `make malonzo` re-extraction + `cabal build exe:once`; re-test under
   `qemu-riscv64`; then wire the exit-test harness (Phase 4b).

The proof-side apex is unaffected (it is value-level; this is a target-emission
gap). This is genuinely "implement the riscv64 runtime," a distinct effort from
the verification parity delivered in Phases 1–3.
