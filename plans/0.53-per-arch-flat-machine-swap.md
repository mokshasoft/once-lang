# Plan 0.53 — Bring X86-32 and RiscV64 to the X86-64 Flat-Machine Level (retire DirectSimulation)

## The claim

Plan 0.32 swapped X86-64 from the loop-blind `DirectSimulation` bridge to the
real flat-machine correspondence (`FlatSimulation`/`FlatSim`/`CompileCorrectFlat`)
and **deleted** `Target/X86-64/DirectSimulation.agda`. X86-32 and RiscV64 were
never migrated. This plan replicates that swap for the remaining two arches, so
all three backends prove the cata loop over the same real machine, and
`DirectSimulation` disappears from the tree entirely.

This is the concrete work behind **0.48 Phase ∞** ("delete `DirectSimulation`,
only that") — deletion is currently blocked *only* because X86-32/RiscV64 still
reach it.

## Why now / why this is worth it

`Target/{X86-32,RiscV64}/DirectSimulation.agda` are each ~1,250 lines carrying
**11–12 `postulate` blocks + 10 `!!` each** (~20 `!!` + ~23 postulate blocks
total). Worse than the volume: they are **loop-blind and holed** — `exec-prog`
is a straight-line walk, `instr-sim (instr-ctrl _) = !!`, `instr-sim
(instr-loop _) = !!` — so their `trace-sim` correspondence is **vacuous exactly
where the live cata emits jumps**. Both are reachable from the top-level
`EntryPointCCC`, so the grand theorem currently rests on a vacuous machine-side
for two of three arches.

The X86-64 flat stack replaced all of that with **0 `!!`** and exactly **3
clearly-provable named postulates** (`block-step-all` / `flat-no-halt` /
`end-corr`), and it actually runs the loop. Bringing the other two arches to
that level is pure net-positive verification debt reduction, fully orthogonal to
the frontend proof-gap work.

## Current reachability (ground-truth 2026-07-01)

- `Target/X86-64/DirectSimulation.agda` — **already deleted** (Plan 0.32).
- `Target/X86-32/DirectSimulation.agda` — imported by `X86-32/CompileCorrect`
  (`trace-sim`) + `X86-32/Correct`. Reachable from `EntryPointCCC`.
- `Target/RiscV64/DirectSimulation.agda` — imported by `RiscV64/CompileCorrect`
  (`trace-sim`) + `RiscV64/Correct`. Reachable from `EntryPointCCC`.
- No `FlatSimulation`/`FlatSim`/`CompileCorrectFlat` exists for X86-32 or RiscV64.

`AbstractTo<arch>`. Shared/arch-generic (already present, reused as-is):
`Machine.Flat` (`exec-flat`), `Machine.SMCore`, `Codegen.*`, `AbstractTrace`,
`CompiledCorr`.

## Per-arch cost split

- **X86-32 — largely a mechanical port.** Same instruction *shapes* as X86-64
  (mov/add/sub/cmp/je/jmp/lea, flags), 32-bit widths and register names
  (`eax`/`ebp`/`esp`). `StepLemmas`/`FlatComposition`/`FlatSimulation` port
  near line-for-line against `X86-32.Syntax`/`Semantics`. A `SimulationInterface`
  stub already exists to reuse. **Est. 3–5 days.**
- **RiscV64 — genuine re-derivation.** Load/store ISA (`ld`/`sd`/`addi`/`mv`),
  `jalr`/`jal`/branch control, no flags. Every `block-step` case is re-proved
  against RV64 semantics. Mitigants: RV64 already emits the **Plan 0.34 portable
  conditional-branch unit** (no flags x86-ism to model), and RISC step semantics
  are more uniform. **Est. 5–8 days.**
- **Rewire + delete.** `EntryPointCCC` X86-32/RiscV64 branches → route the
  extracted correctness to `CompileCorrectFlat`; trim `Correct.agda` /
  `CompileCorrect.agda` machine-side; delete both `DirectSimulation.agda`;
  clean stale references (`RuntimeContract`, `Adequacy`, comments). **Est. 1–2 days.**

## Refinements folded in (2026-07-01)

Investigation of X86-64's residual postulates (`block-step-all` / `flat-no-halt`
/ `end-corr` in `CompileCorrectFlat`) established:

- The per-instruction `block-step-*` lemmas (21 of them) are **fully proven**
  (0 `!!`) for the cata-loop instruction subset (mov variants, `reg-op`,
  `instr-ctrl` jmp/label/branch, `load-tag-lit`, load/store-indirect). That
  proven layer IS the port recipe; the module skeleton is already legible.
- `flat-no-halt` + `end-corr` are **mechanical** (a case-split + a terminal
  case). They should be *proven inline per arch*, not postulated — tightening
  the trust surface below X86-64's current level.
- `block-step-all` is a **totality obligation over all 17 `AbstractInstr`
  families**, of which ~10 (alloc-heap → 0.35 M6; stack-ops; closure; sigop;
  const) are genuinely unproven and **out of scope / shared downstream**.
  Fully discharging it is NOT a prerequisite — it drags in 0.35 and the
  closure/sigop tracks. Instead, refactor it into a **total dispatcher** that
  case-splits all 17 constructors: proven families → the `block-step-*` lemmas,
  pending families → **named per-family sub-postulates**. This exposes exactly
  what is covered (a per-arch checklist), matches the 0.9 no-silent-catchall
  discipline, and gives the ports a legible skeleton to mirror.

**Consequences for the phases below:**
- New **Phase 0** (X86-64, warmup): dispatcher refactor of `block-step-all`.
- Phases A/C **prove `flat-no-halt` + `end-corr` inline** (drop those two
  postulates per arch); only the per-family `block-step-*` sub-postulates for
  the ~10 pending families remain — the *same* trust bar as X86-64 post-Phase-0.

## Phases

Do X86-64 Phase 0 first (clarify the skeleton), then X86-32 (cheaper port,
de-risks the recipe), then RiscV64, then delete.

### Phase 0 — X86-64 `block-step-all` total-dispatcher refactor (warmup)
0. In `Target/X86-64/FlatSim.agda` (or a small new `FlatDispatch` module),
   replace the opaque `block-step-all` postulate with a **total function**
   `block-step-all : ∀ prog → BlockStepAll prog` that pattern-matches the fetched
   `AbstractInstr`:
   - cata families → existing proven `block-step-*` lemmas (no new content);
   - the ~10 pending families → one **named** `block-step-<family>` postulate
     each (no `!!`, no catch-all), documented with its downstream owner
     (alloc-heap = 0.35 M6, etc.).
   Build green. `make postulates` now lists the pending families explicitly.
   This is the skeleton every arch mirrors.

### Phase A — X86-32 flat stack
1. `StepLemmas` → `FlatComposition` → `ExecCompose` → `FlatCorrespondence`
   (mirror X86-64, retype against `X86-32.Syntax`/`Semantics`). Build green
   after each (all 0-postulate).
2. `FlatSimulation` — port every `block-step` case; the with-pattern structure
   should transfer since `compile-abstract` is the same 1-to-1 shape.
3. `FlatSim` (fuel lift) + `CompileCorrectFlat`. **Prove `flat-no-halt` +
   `end-corr` inline** (mechanical); mirror the Phase-0 dispatcher for
   `block-step-all`. Only the per-family pending sub-postulates remain. Green.

### Phase B — X86-32 rewire
4. `EntryPointCCC` X86-32 branch: `compile-extracted` correctness ←
   `X86-32.CompileCorrectFlat.compile-correct-flat` (mirror the X86-64 branch,
   `EntryPointCCC` line ~145). Drop the `trace-sim` machine-side from
   `X86-32/CompileCorrect` + `X86-32/Correct`.

### Phase C — RiscV64 flat stack
5. Same 7 modules against `RiscV64.Syntax`/`Semantics`. Re-derive `block-step`
   per RV64 instruction (the real work). Reuse the Plan 0.34 branch unit.

### Phase D — RiscV64 rewire
6. `EntryPointCCC` RiscV64 branch → `RiscV64.CompileCorrectFlat`. Trim
   `RiscV64/{CompileCorrect,Correct}` machine-side.

### Phase E — delete (0.48 Phase ∞ discipline)
7. Re-run reachability (`grep -rln DirectSimulation formal --include=*.agda`).
   With both arches migrated, the two `DirectSimulation.agda` files are
   unreachable → **delete them + the `X86-32/SimulationInterface` stub if now
   orphaned**. Clean stale comments in `Correct.agda` (×3) and `RuntimeContract`.
   Full build green. This is a mechanical leftover, never a mid-way judgment.

## Success criteria

- `find formal -name DirectSimulation.agda` → empty.
- All three arches' extracted correctness routes through `CompileCorrectFlat`
  over `exec-flat` + real `Semantics.exec` (the loop-running correspondence).
- Trust surface per arch = the named per-family `block-step-<family>`
  sub-postulates for the ~10 pending instruction families (same bar as X86-64
  post-Phase-0); `flat-no-halt` + `end-corr` **proven inline**; **0 `!!`**.
- Net: ~2,500 lines of loop-blind sim + ~20 `!!` removed; ~1,940 lines/arch of
  real correspondence added.
- `make` green; `make postulates` shows only the shared 3-per-arch named set.

## Risks / notes

- **RV64 block-step is the real cost.** If a case resists (e.g. `jalr`
  return-address semantics), the fallback is a *named clearly-provable*
  postulate matching the X86-64 trust bar — never a silent `!!` or catch-all.
- The 3 `flat-sim` inputs remain postulated for X86-64 too; discharging them is
  out of scope here (shared downstream: alloc-heap = 0.35 M6, stack-ops, jump
  resolution). This plan brings the other arches *to parity*, not past it.
- Orthogonal to the active frontend track (0.49/0.52) and does not touch the
  cata/trace/denotation files (0.36/0.44/0.46) beyond consuming their stable
  `exec-flat`/`CompiledCorr` interface.
