# Plan 0.2.4.2: Closure Codegen Lifetime Fix

## Context

End-to-end testing of `main = exit 42` exposes a cluster of codegen
bugs in the closure / apply machinery. The SigOp framework itself is
correct (Plan 0.11): integer literals codegen to `mov $N, %rax` via
`const`, the Linux `exit` syscall via `call once_exit` linked
against `Strata/Interpretations/Linux/Syscalls.x86_64`, and the
build driver assembles + statically links those impl files. The
compiled program no longer traps on `ud2`.

What breaks: `main : IO Unit` (which desugars to `Eff Unit Unit`)
elaborates to a closure (per `t-effApp` + `Surface.elaborate.effApp`).
`once_main`'s body is the **closure-construction trace** (per
`ir-to-trace' n (curry _ _)`). The actual body of the suspended
action — `apply ∘ ⟨ exit, 42 ⟩` — is the inner curry, which is
emitted as a sub-trace whose code-pointer slot ends up holding
`&slot[1]` (a stack address pointing at itself), not a real code
address. After `_start` calls `once_main`, it gets a closure record
back, but invoking it (`call [r12+8]`) jumps into stack data.

Three overlapping defects, each shippable as its own change:

### B1. Stack-frame lifetime violation

`once_main` builds the closure record on its own stack slots and
returns a pointer into that frame in `%rax`. The pointer is dangling
once `once_main` returns. Even if escape analysis caught this in
principle, the codegen ignores `AllocMode` (B3 below).

### B2. Code-pointer slot is set to its own address

`ir-to-trace' n (curry _ _)` emits:

```agda
lea-slot (suc closure-slot) ∷         -- Output := &closure[1]
store-at-slot (suc closure-slot) ∷    -- closure[1] := &closure[1]
```

The intent (per the surrounding comments) is "closure[1] = code
pointer to the function body". The code emits "closure[1] = address
of the closure[1] slot" — a self-reference to stack data. There's no
abstract instruction in `AbstractInstr` for "load the address of a
code label", so the codegen has nothing to use.

### B3. `AllocMode` ignored in curry

```agda
ir-to-trace' n (curry _ _) = …          -- ← _ discards Stack vs Heap
```

The IR carries `AllocMode` (escape analysis's output: `Stack` for
non-escaping closures, `Heap` for escaping). The codegen
pattern-wildcards the mode, producing the same allocation regardless.

### B4. Apply ABI verification

`apply`'s codegen via `instr-call-closure` lowers to `call [r12+8]`
on x86-64 (assuming `r12` = closure pointer, code pointer at +8).
The `apply` setup-trace places (closure, arg) at slots before
calling, but never sets `r12`. Whoever calls into a closure must
ensure `r12` is set first.

## Goal

Fix closure lifetime and the related codegen bugs so programs using
effectful closures (`curry` / `apply` / `effApp`) actually run.
Canonical test:

```once
signature exit : Eff Int Unit
main : IO Unit
main = exit 42
```

must compile and produce exit code `42`.

## Locked architectural decisions

These decisions emerged from a 2026-04-29 architectural review after
Plan 0.10 / 0.11 reshaped the codegen pipeline (IR → AbstractTrace →
per-arch Program). They supersede earlier per-Phase guidance.

### D1: Closure bodies are inline local labels

Each `curry` IR node has a static **body** (the inner IR
`f : IR (Γ * B) C`). At runtime, multiple distinct closures may
point at the same body with different captured envs. The body label
is therefore *static-per-IR-occurrence* and *shared across all
closures created from that curry*.

Bodies are emitted as **local labels (`.L_thunk_<N>`) inside the
parent function's symbol**, after the parent's `ret`. They are not
`.globl`'d. Reachability is via `lea .L_thunk_<N>(%rip)` from the
parent's curry-construction trace.

Rejected:
- (b) top-level symbols per closure body — pollutes the global
  symbol table for things that are not standalone functions; doesn't
  match closures' "dynamic, env-parameterized" nature.
- (c) separate `.text.thunks` section — same as (b) at link layout.

### D2: Closure body has its own stack frame

Body codegen emits a standard SysV prologue/epilogue
(`push %rbp; mov %rsp, %rbp; …; leave; ret`). The body's slots count
from 0 of its own frame; env is reached via `%r12`, arg via `%rdi`.

This composes: any function (or any closure body) can call any other
closure without coordinating slot frames.

### D3: AllocMode dispatch — Stack on parent frame, Heap in static pool

`ir-to-trace' n (curry f Stack) = …` allocates the closure record
on the parent's stack slots (current behavior). Lifetime ends with
the parent function's `ret`. **Sound only if the closure does not
escape**; escape analysis (Once.Escape, Once.Escape.Correct) is
trusted to catch escapes and force `Heap` mode.

`ir-to-trace' n (curry f Heap) = …` allocates the closure record
in a static `.bss` bump pool (size: 64KB for now; trap on
exhaustion). Pointer survives the parent's `ret`.

Both modes share the **same body label** in the parent function's
`.L_*` namespace. Only the record-allocation differs.

### D4: Calling convention — r12 = closure, rdi = arg

Locked by existing `instr-call-closure` lowering: `call [r12+8]`,
`r12` holds the closure pointer, code pointer is at offset
`slot-size` (= 8 on x86-64). Body reads env via `[r12]`, arg via
`rdi`.

Apply's setup-trace must place the closure pointer in `r12` before
the indirect call. Currently the trace stores closure/arg into
slots and uses `mov-to-input`; the `r12` setup is the missing piece
(part of B4).

### D5: Label naming — stateful counter local to parent function

The `Label` is a `ℕ`. Each parent function's codegen carries a
counter; each `curry` traversed bumps the counter and emits a body
labeled `.L_thunk_<N>`. Counter resets per parent function.

Stateful within `ir-to-trace`/`compile-trace` for one function;
stateless across functions. No global naming concerns.

Rejected: structural-path labels (more verbose, less readable in
the asm dump for a non-verifier). Verification-wise, ℕ + emission
order is easy to reason about ("the Nth closure body in this
function").

### D6: Two-pass codegen within each function

`compile-trace` for a single function returns `(main-prog ,
[(Label, body-prog)])` instead of just `main-prog`. The function
emitter emits:

```
parent-prologue
main-prog
parent-epilogue
ret
.L_thunk_0:  body0-prologue body0-prog body0-epilogue ret
.L_thunk_1:  body1-prologue body1-prog body1-epilogue ret
…
```

Bodies after `ret` are unreachable by fall-through; reachable only
via `lea (%rip)` + indirect `call`.

### D7: New AbstractInstr — `instr-load-code-addr : ℕ → AbstractInstr`

```agda
instr-load-code-addr : ℕ → AbstractInstr  -- Output := address of .L_thunk_<N>
```

Per-arch lowering:
- x86-64: `lea .L_thunk_<N>(%rip), %rax`
- x86-32: PIC-style trampoline (call/pop trick or load via GOT)
- riscv64: `auipc + addi` to compute label address

Mirrors the `instr-load-const` extension landed in Plan 0.11. Same
blast radius (~10 modules to update with one clause each: SMCore,
SMPrimitives, IRToTrace, per-arch AbstractTo<arch>, per-arch
DirectSimulation, Optimize family, Escape family, Fusion family,
IR/Size, IR/Stack).

### D8: `_start` applies main's returned closure

```asm
_start:
    movq %rsp, %rbp
    subq $4096, %rsp
    call once_main          ; %rax = closure ptr
    movq %rax, %r12         ; closure ABI: r12 = closure
    xorq %rdi, %rdi         ; arg = () (Unit)
    callq *0x8(%r12)        ; call closure body
    movq $60, %rax          ; sys_exit fallback
    xorq %rdi, %rdi
    syscall
```

`_start` knows the closure ABI; falls out of D4. Lives in
`Once.Target.X86-64.x86-64-asmHeader` (Agda-side, part of the
formal output).

### D9: Verification deferred (per Plan 0.11 trusted-base discipline)

This plan does **not** prove correctness of the new codegen. The
new postulates added are:

- `instr-load-code-addr-codegen-faithful` (per arch) — the lowering
  produces a value of `Output` that points to the correct body.
- `curry-trace-correct` per AllocMode (Heap-vs-Stack lifetime).
- `bump-pool-allocation` axioms — the static pool is well-defined.

These go into `Once.TrustedBase.Pending` once Plan 0.11 lands a
trusted-base module; until then they live as named per-file
postulates, audit-visible via `make postulates-grep`.

## Scope

**In scope:**

- D1–D8 implementation (closure bodies as local labels, AllocMode
  dispatch, lea-of-label, `_start` applies closure).
- A `.bss` static bump pool for Heap-mode closures with a trap on
  exhaustion.
- The canonical Layer 0 regression test (`main = exit 42` exits
  with code 42).
- X86-64 only. X86-32 / RiscV64 stubs continue to emit `ud2` /
  `unimp` for the new `instr-load-code-addr` until separately
  scoped.

**Out of scope:**

- Formal correctness proofs (per D9).
- Garbage collection / pool reclamation.
- Region-typed closures (would type-enforce no-escape; significant
  IR addition).
- Escape-analysis verification (trusted to be correct; Layer 0
  tests are written so closures don't escape).
- X86-32 and RiscV64 mirrors of D7's per-arch lowering.

## Implementation phases

### Phase A — `instr-load-code-addr` infrastructure

1. Add the ctor to `AbstractInstr` (SMCore).
2. Cascade through SMPrimitives (11 coverage clauses).
3. Add per-arch `compile-abstract` and `instr-sim` clauses (X86-64
   only for now; X86-32/RiscV64 trap with ud2/unimp).
4. Add the local-label `lea` X86 syntax variant if needed.
5. Add coverage clauses across Optimize/Escape/Fusion families.
6. `make compiler-all` green.

Verify: a unit test trace `[instr-load-code-addr 0]` codegens to
`lea .L_thunk_0(%rip), %rax`.

### Phase B — Two-pass per-function codegen

1. Refactor `compile-trace`'s signature to return main-program +
   list of (label, body-program).
2. Refactor `compileFunWithTarget` to emit:
   ```
   parent-prologue
   main-prog
   parent-epilogue ret
   for each (label, body): label-decl body-prologue body body-epilogue ret
   ```
3. Update Plan 0.10's `compile-trace-correct` shape to handle the
   new return type. (Minimal change: the main-prog correctness
   carries through; bodies are independently correct, which is
   what the per-instruction simulation already gives.)
4. `make compiler-all` green.

Verify: a curry-containing program emits both the parent and a
`.L_thunk_0:` body label.

### Phase C — Stateful counter + curry emission

1. Thread a `ℕ` counter through `ir-to-trace` for closure-body
   labels.
2. `ir-to-trace' n (curry f Stack)`:
   - Emit closure record allocation on the parent's slots
     (existing pattern) — `closure-slot`, `closure-slot+1`.
   - Emit `instr-load-code-addr <N>` for the body label.
   - Recursively emit the body's IR-to-trace as a separate
     `(N, body-trace)` pair.
3. `ir-to-trace' n (curry f Heap)`:
   - Emit bump-pool allocation: `mov pool-pos, %rax; add 16,
     pool-pos; ...`. (May need a new AbstractInstr `instr-bump-alloc`
     OR inline it in compile-abstract.)
   - Same body emission as Stack.
4. `make compiler-all` green.

### Phase D — `_start` + `.bss` heap pool

1. Update `Once.Target.X86-64.x86-64-asmHeader` per D8.
2. Add `.bss` declaration: a 64KB scratch + a global pointer
   `once_heap_pos` initialized to the start of the scratch.
3. `_start` initializes `once_heap_pos`.
4. Re-extract MAlonzo, rebuild compiler.

### Phase E — Regression test

1. Add `compiler/test/layer0-exit-42.once`.
2. Add `Layer0ExitSpec.hs` (or extend `Layer0Spec`) asserting exit
   code 42.
3. Wire into `make test-x86-level0`.

## Risks

1. **Stateful codegen breaks Plan 0.10's verification**. The
   `compile-trace : AbstractTrace → Program` signature becomes a
   stateful traversal. Per-instruction simulation lemmas may need
   restructuring. Mitigation: keep `compile-trace` pure by
   pre-allocating labels in the IR-to-trace pass; codegen reads
   from a pre-built map instead of generating labels itself.

2. **`AbstractInstr.instr-load-code-addr` semantics is opaque**.
   The abstract machine doesn't model "code addresses" (similar to
   why `instr-load-const` for primitives needs `encode-const`).
   Mitigation: postulate `encode-code-addr : ℕ → ValueLocation FS`
   in the same family; per-arch lowering must agree (trusted base).

3. **Static pool exhaustion**. Programs allocating > 64KB / 16
   bytes per closure exhaust the pool and trap. Layer 0 programs
   don't allocate enough to hit this. Mitigation: document; future
   plan replaces with a real allocator.

4. **Escape analysis verification debt**. We *trust* escape
   analysis to mark non-escaping closures as Stack and escaping
   ones as Heap. If this is wrong (and the codegen uses the wrong
   AllocMode), Stack closures escape into dangling memory. No
   runtime check. Mitigation: Layer 0 tests are designed to not
   escape closures; an unverified Stack annotation in user code is
   a known gap.

5. **X86-32 / RiscV64 stay stubbed**. The new `instr-load-code-addr`
   produces `ud2` / `unimp` on those arches until separately
   scoped. Mitigation: documented; same status as `instr-load-const`
   for non-int primitives.

## Author's note (2026-04-29)

This is the rewrite of the original April plan after IR-to-trace
landed. The bug analysis (B1–B4) is unchanged; their *locations*
are now in `ir-to-trace' n (curry _ _)` rather than `compile-ir' n
(curry _ _)`. The fix structure is the same shape (AllocMode
dispatch, real code-pointer setup, working `_start`).

The major new architectural decision since April: **closures bodies
are inline local labels, not separate top-level functions** (D1).
This is forced by closures being dynamic constructors at runtime —
the body is static-per-IR-occurrence, but each IR occurrence may
produce many closures with different envs. Top-level symbols would
suggest each closure is a distinct function, which it isn't.
