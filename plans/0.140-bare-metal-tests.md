# Plan 0.140 — The tests run on bare metal, not only under Linux

## Summary

Every test program today runs as a Linux process, either natively or through QEMU's Linux emulation.
So Linux is quietly part of every test: it starts the program, prints its output and reports how it
ended. Once is meant to run on bare metal with no operating system. This plan adds a second way to run
the same tests: on an emulated bare machine, with a minimal "host" layer that starts the program, writes
output to a serial port and reports the end to the emulator. When it is done, the test suite shows the
compiler's programs work without Linux, and the host layer it builds is the first step toward small
boards.

## 1. Why

A Host (D320) is how a platform runs a program: `enter ; main ; leave`. The compiler knows no platform;
only the Host does (D349). But the test suite runs only under `Strata/Hosts/Linux` (the seL4 Host is
exercised by `examples/seL4` alone), and every test observation goes through Linux system calls:
- **exit tests** (`tests/run-exit-tests{,-x86_32,-riscv64}.sh`, 176 programs) run a static ELF natively or
  under `qemu-i386` / `qemu-riscv64` *user mode*, and read the process exit status;
- **trace tests** (`compiler/test`, `Backend.Common.buildAndRunTrace`, `traceCases`) import
  `I.Test.Emit`, whose `emit` is a Linux `write` (`Strata/Interpretations/Test/Emit.<arch>`), and read
  stdout;
- the end of a run is Linux's: `once_leave` is `exit_group(0)`, and on the heap branch `once_exhausted` is
  `SIGABRT`.

So the claim "Once runs without an OS" is untested, and the test suite exercises the Host contract through
one implementation, which makes it easy for Linux assumptions to leak into it unnoticed.

## 2. Where we are (checked 2026-11-25 on master `8aa064525`)

- `once build --host <H>` exists (D320): it assembles `Strata/Hosts/<H>/Host.<arch>` and links it; the
  default is `Linux`, and `examples/seL4` builds with `--host SeL4` (`compiler/src/Once/CLI.hs`:
  `hostFile`, `assembleHost`). The Host's object is named `<output>.Host.<H>.o`, so a host name with a
  `/` needs that name sanitised.
- `Strata/Hosts/Linux/Host.<arch>`: `_start` (the region in `.bss`, 8 MiB; frontier register at its
  bottom, stack pointer at its top; `j once_main`), `once_leave` (`exit_group(0)`), `once_exhausted`.
- Interpretation code is found as `<module>.<arch>` beside the signature (`assembleImplFiles`).
- Tests: 25 programs import `I.Test.Emit` (`emit` writes the argument's machine word to stdout with
  `write`); 116 test or example programs import `I.Linux.Syscalls` (102 in `compiler/test` as `S`, for
  `exit@S`). Runners: the three exit-test scripts; `compiler/test/Backend/Common.hs` (`archRunPrefix`:
  native, `qemu-i386`, `qemu-riscv64`; `archToolEnv` for the cross binutils).
- `qemu-system-riscv64`, `qemu-system-x86_64`, `qemu-system-i386` (QEMU 10.1.2) are on the PATH of the
  dev shell.

## 3. Decisions

Taken by the user, 2026-11-25, in discussion.

1. **A Host is the layer directly beneath the program**: what starts it, ends it and gives it its
   region. An OS hides the platform, so an **OS Host** is one name keyed by arch (`Linux`, `SeL4`;
   one that ever needs per-board code nests the same way, `SeL4/Virt`). With no OS nothing hides the
   platform, so a **bare-metal Host names its platform under `Bare`**:
   `Strata/Hosts/Bare/<Platform>/Host.<arch>`, with the platform's linker script beside it. There is no
   single `--host bare`: bare metal depends on the platform (boot protocol, memory map, console and exit
   devices), not only on the CPU.
2. **The first platforms (was D1)**, under QEMU system emulation:
   - `Bare/Virt` (riscv64; aarch64 later): RAM at `0x8000_0000`, the 16550 UART at `0x1000_0000`, the
     SiFive test finisher at `0x10_0000`; booted by `-bios none -kernel`.
   - `Bare/PC` (x86_32 and x86_64): Multiboot by `-kernel`, the COM1 UART at `0x3F8`, `isa-debug-exit`;
     x86_64 enters long mode in its Host.
   Real boards come later, each one more `Bare/<Board>`.
3. **Portable Interpretations; a Host may supply their code.** An Interpretation's `.once` signature is
   its meaning and never depends on the platform. One that belongs to one environment (`Linux/*`,
   `SeL4/*`) keeps its `.<arch>` code beside its signature. A **portable** one has only its signature in
   `Strata/Interpretations`; each Host supplies its code in
   `Strata/Hosts/<host>/Interpretations/<path>/<Module>.<arch>`. Lookup: the Host's directory first, then
   beside the signature; otherwise a link error naming the Interpretation, the Host and the arch. (A
   device driver's code depends on the platform and on the OS that maps the device, so it is a Host's.)
   Which environment an Interpretation belongs to is read from its path: one under
   `Interpretations/<E>/…`, where `Hosts/<E>` is a Host, belongs to `<E>` and links only under it
   (`I.Linux.Syscalls` under `Bare/Virt` is refused, naming both); every other one is portable or pure
   (`Test/Emit`, `Math/*`).
4. **Portable in this plan: `Test/Emit` and `halt`** (the user: "Emit (+ exit) only"; revised with the
   user 2026-11-25, see 5). `Test/Emit`'s code moves from beside its signature to
   `Hosts/Linux/Interpretations/Test/`; `Bare/Virt` and `Bare/PC` write to their UART. The new portable
   `I.Halt` has one operation, `halt : Act Unit Void`: the run ends `halted` (D225/D227). Linux's code is
   `exit_group(2)`, a bare Host's is its exit device. There is **no portable `exit n`**: `exit` stays in
   `I.Linux.Syscalls`, as Linux's process exit status, which is a Linux observable and not a Spec one.
   The tests that observed a value through `exit@S n` observe it through `emit` and return (step 3). A
   portable console (`putc`/`getc`), and seL4 code for `Emit`/`halt`, are later plans.
5. **What is observed (was D2)**: **the end of a run is a kind and carries no value; values go in the
   trace.** The trace goes to the UART, framed exactly as Linux's `emit` writes it to stdout, so the
   expected traces are shared. The Spec has three ends, `returned`, `halted` and `exhausted` (D374), and
   each exit device has a fixed table of exactly those, written in the Host and decoded by the runner:

   | end | Linux | `Bare/Virt` (finisher) | QEMU's status |
   |---|---|---|---|
   | returned | `exit_group(0)` | `0x5555` | 0 |
   | exhausted | `SIGABRT` | `(1 << 16) \| 0x3333` | 1 |
   | halted | `exit_group(2)` | `(2 << 16) \| 0x3333` | 2 |

   `isa-debug-exit`'s table (status `(v << 1) | 1`, never 0) is fixed in step 5. A **trap is not an end**:
   the program's run never faults (`FlatFromObs.start-sound`) and division is total (D055), so a trap
   can only be a defect of the trusted base (a Host, an Interpretation's code, the platform). A bare
   Host's trap handler stops the run with a status outside the table (255 on `Bare/Virt`), as Linux
   reports a broken Interpretation with `SIGSEGV`; a runner reads any status outside the table as "the
   trusted base is broken", not as an end. Encoding a value into the status (an earlier draft had
   `exit n` = n + 2) is rejected: the status is one byte, and the tests already expect codes up to 255.
6. **Which tests run where (was D3)**: `ONCE_TEST_HOST=linux|bare`, `bare` meaning `Bare/Virt` on riscv64
   and `Bare/PC` on x86; trace tests and exit tests run under both; a test that needs Linux (files, argv)
   says so and is skipped on `bare` with its reason. `qemu-system-<arch>` runs with a wall-clock cap.
7. **Later, not here**: `emit` of a buffer or string, one write per event, once Once has buffers (plan
   0.155).

### Open (defaults proposed; decided in the step named)

- **O1. The region on bare metal** (step 1): in `.bss` inside the image, as on Linux (default), or all RAM
  above the image from the platform's memory map. Whoever loads the image need not zero `.bss`, so the
  Host's `_start` zeroes what the program's start requires.
- **O2. Booting x86_64** (step 5): Multiboot's loader takes a 32-bit ELF, so the image is converted
  (`objcopy` to ELF32) with a 32-bit entry stub that enters long mode (default), or PVH, which also enters
  in 32-bit mode.
- **O3. The Host contract per Host** (step 6): D320 point 4 asks for each Host's model (its start state is
  what the compiler's proved start requires); each bare Host's is stated, and a decision entry records
  the plan.
  *Decided (step 6):* the proved start requires (D376) that on entry to `once_main` the frontier register
  is the region's bottom and the stack pointer its top, on a machine that executes the arch's
  instructions as the target model does. Every bare Host's `_start` states how it gets there:
  `Bare/Virt` hart 0, machine mode, the FPU on (`mstatus.FS`), traps to `once_fault`; `Bare/PC` x86_32 its
  own flat GDT and an IDT of 32 exception gates, x87 and SSE on; x86_64 the same in long mode, with the
  first 1 GiB identity-mapped by 2 MiB pages. The region is 8 MiB of `.bss`, zeroed by the loader
  (QEMU's ELF and Multiboot loaders). The decision is D489.

## 4. Steps

Each step: `cabal test`, the exit tests on three arches under Linux (no regression), and the new runs.

1. **`Bare/Virt` on riscv64.** `Strata/Hosts/Bare/Virt/Host.riscv64` (`_start`: stack and region (O1),
   `.bss` zeroed, `once_main`; `once_leave` and `once_exhausted` through the finisher table, §3.5) and its
   linker script. The CLI: a host name with `/` (the Host object's name sanitised), the link passes the
   Host's linker script (`-T`) when it has one. Check: a program with no effects boots under
   `qemu-system-riscv64 -machine virt -bios none -kernel` and ends with the `returned` code; one that runs
   out of memory ends `exhausted`.
2. **Interpretation code per Host** (§3.3): the lookup in `assembleImplFiles`; `Test/Emit`'s code moved to
   `Hosts/Linux/Interpretations/Test/`; `Bare/Virt`'s writes the same bytes to the UART. Check: the trace
   tests unchanged under Linux; one trace test byte-identical under `Bare/Virt`.
3. **`halt`, and values observed in the trace** (§3.4, §3.5): `I.Halt`'s signature, Linux's code,
   `Bare/Virt`'s. The tests that end `exit@S v` emit `v` and return instead (a scripted edit, then
   read): `-- Expected: exit N` becomes `-- Expected: trace [v]`; the exit-test scripts check the
   trace and the end `returned`; the Haskell `exitCases` becomes `valueCases` (trace `[v]`, end
   `returned`) and `traceCases` takes the end. `halt-ends-trace` uses `halt`. A value the old exit code
   read modulo 256 (for example `-1` as 255) is now read whole. Check: every converted test passes
   under Linux on three arches; a `halt` ends `halted` under `Bare/Virt`.
4. **The runners** (§3.6): `archRunPrefix` and the exit-test scripts take `ONCE_TEST_HOST`; serial output
   to stdio with QEMU's own messages kept out of the trace; the end decoded from the exit status; the
   Linux-only tests named with their reason. Check: everything that does not need Linux passes on riscv64
   bare.
5. **`Bare/PC`** on x86_32, then x86_64 (O2): Multiboot header, protected-mode / long-mode entry, COM1,
   `isa-debug-exit` and its end table; `Emit` and `exit` code. Check: as step 4 on both x86 arches.
6. **Docs and record**: the Host contract (D320/D349) lists the Hosts and states each bare Host's model
   (O3); `README`/test docs say how to run `ONCE_TEST_HOST=bare`; a decision entry for §3.

## 5. Done when

The trace tests and the exit tests that do not need Linux pass under `ONCE_TEST_HOST=bare` on all three
arches, with the same expected outputs as under Linux, and the CI/test docs say how to run them.
