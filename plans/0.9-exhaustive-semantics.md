# Plan 0.9: Enforce Exhaustive Semantic Case-Splits

## Context

During Phase D of plan 0.2.4.1 (SigOp framework end-to-end test), a
concrete codegen bug surfaced: `curry-closure-setup` in
`Once.CCC.Target.X86-64.CodeGen.Compile` emitted
`lea r9 (rip+disp 4)` when the correct offset was `10`. The
compiled closure's code pointer was therefore pointing into the
middle of an instruction. Every program using closures would
execute garbage at closure-invocation time.

The bug was real. The type checker accepted it. `make postulates`
found nothing. No TERMINATING pragma was involved. Every proof in
the `compile-correct` chain succeeded. The code shipped against a
clean audit surface.

The bug hid in `Once.CCC.Target.X86-64.DirectSimulation`:

```agda
-- lea-slot: lea rax, [rbp + disp] → rax' = &stack[frame, slot]
exec-x86 (lea rax (base+disp rbp d)) xs frame =
  record xs { rax-val = slotLoc frame (disp-to-slot d) }

-- ... explicit clauses for ~15 instructions ...

exec-x86 _ xs _ = xs    -- ← catch-all: unmodeled instrs = identity
```

`lea r9 (rip+disp n)` has no explicit clause and falls through to
the catch-all, which models the instruction as a no-op. Since the
abstract semantics doesn't constrain what `r9` holds afterwards,
downstream proofs have nothing to contradict — the wrong offset
is invisible at the model level.

This is a class of silent under-specification that is **not
currently catchable by top-level audit**: no postulate is emitted,
no pragma is used, no proof fails. The specification is under-
constrained, so the proof is vacuously valid. Readers would have
to audit the definition of every semantic function to find such
gaps — infeasible, and defeats the point of top-level claims.

## Goal

Enforce, **mechanically**, that every function giving meaning to
a datatype matches every constructor explicitly — no silent catch-
all absorption. Any intentional catch-all becomes an explicitly
named, greppable marker, on par with `postulate` in audit surface.

The mechanism already exists in the Agda compiler: the
`--exact-split` flag plus the `{-# CATCHALL #-}` pragma.

| Mechanism        | Effect                                                               |
|------------------|----------------------------------------------------------------------|
| `--exact-split`  | Emit warning `CoverageNoExactSplit` for any clause that would be a catch-all. |
| `-W error=CoverageNoExactSplit` | Promote the warning to a hard error.                  |
| `{-# CATCHALL #-}` | Silence the warning for a specific deliberate catch-all clause.    |

Combining the three turns silent catch-alls into compile errors
unless the author *explicitly* marks the clause. The marker is
code-visible, grep-audit-visible, and cannot be introduced by
accident.

## Decision

Enable `--exact-split` and promote its warning to an error
**project-wide**. Every existing catch-all is either rewritten as
exhaustive constructor enumeration or explicitly marked `CATCHALL`
with a justification comment. The `CATCHALL` pragma count becomes
a new audit number alongside the postulate count.

This is not policy. It is compiler enforcement. Forgetting to
mark a new catch-all means the code does not typecheck.

## Scope

**In scope:**

- All `.agda` files under `formal/`.
- Global enable via `formal/*.agda-lib` or `{-# OPTIONS #-}` at
  module heads (whichever is the project convention).
- Audit and classify every existing catch-all as either
  "exhaustive-enumerate" (fix) or "intentionally-catchall" (mark).
- Fix the concrete `exec-x86` catch-all in
  `Once.CCC.Target.X86-64.DirectSimulation` (the bug's hiding place).
- A new Makefile target (e.g. `make catchalls`) that lists every
  `{-# CATCHALL #-}`-marked clause across the tree. Parallels
  `make postulates-grep`.
- A new Makefile target (`make exact-split-clean`) that runs the
  whole build with the flag and fails on any un-marked catch-all.

**Out of scope:**

- Converting semantic functions to record-based dispatch (Option 4
  from the design discussion). `--exact-split` is a mechanical
  safety net; records are a higher-effort refactor that can land
  later. This plan does not preclude or require it.
- Fixing the lea-offset bug itself (that landed in commit
  f00e8126 as part of 0.2.4.1 Phase D residuals). This plan
  addresses the *class* of bug, not the individual fix.
- Other classes of silent under-specification:
  - `⊤`-valued predicates that pretend to constrain.
  - Abstract state representations that omit relevant fields.
  - `refl` proofs where both sides reduce to a trivial form.
  - Rename-drift in postulates.
  Each needs a separate mechanism; this plan is scoped only to
  catch-alls in pattern matches.

## Locked architectural decisions

### D1: Global `--exact-split` + error promotion

Enable in one place (`.agda-lib` preferred; per-module
`{-# OPTIONS #-}` fallback) so every module inherits. No opt-in.
Hard error (warnings promoted) so a catch-all cannot compile
without a visible marker.

### D2: `{-# CATCHALL #-}` is an audit artifact, not a convenience

Every instance carries a mandatory justification comment
explaining **why** the catch-all is intentional. Convention:

```agda
-- Expected unreachable by <precondition>, documented in <proof or plan>.
{-# CATCHALL #-}
f _ = <absurd-or-default>
```

Reviewers and tooling treat `CATCHALL` the same way they treat
`postulate`: small named audit surface that must be finite and
justified.

### D3: No "transitional policy"

Rejected: "enable the flag in new modules only; older modules are
grandfathered." Transitional policies never finish. The plan
enables globally on day one; catch-alls that are costly to fix
are CATCHALL-marked with a TODO comment rather than skipped.

## Implementation phases

Each phase ends with `make compiler` + `make malonzo` green.

### Phase A — Census and classification

1. Run `make` with a temporary local `--exact-split` option
   (e.g. injected via `AGDA_CMD`) to collect all existing
   `CoverageNoExactSplit` warnings. Do not promote to errors yet.
2. For each warning, classify into three buckets:
   - **fix**: exhaustive enumeration is feasible and correct
     (most cases).
   - **catchall-justified**: the catch-all is unavoidable
     (e.g. optimizer view functions that deliberately pass through
     all non-interesting constructors).
   - **catchall-todo**: complex enough to defer; still marked but
     with TODO.
3. Produce a report (census count + file map).

Estimated: 1–2 hours.

### Phase B — DirectSimulation fixes

Convert `exec-x86` in all three target simulators to exhaustive
enumeration. For every `Instr` constructor, either:
- give it an explicit semantic clause, or
- emit a `postulate exec-x86-<instr>` and wire the clause through
  it, with a `{-# CATCHALL #-}`-free call.

Result: the silent gap that hid the lea-offset bug becomes either
a real clause or a named postulate visible in `make postulates`.

Estimated: 1–2 hours per target. Three targets.

### Phase C — Optimizer + view functions

Apply the same treatment to:
- `Once/Optimize.agda` views (`pairView`, `coprodView`, …).
- `Once/Optimize/Shape.agda`.
- `Once/Optimizer/Normal.agda`.

Most of these are legitimate `CATCHALL` — the view's whole point
is "this one constructor of interest vs. everything else." Add
the pragma with a justifying comment.

Estimated: 1 hour.

### Phase D — Everywhere else

Sweep the remaining files flagged in Phase A. One-per-file
tolerance; should be mostly mechanical.

Estimated: 2–4 hours depending on census.

### Phase E — Promote to error, add `make catchalls`

1. Flip `.agda-lib` to treat `CoverageNoExactSplit` as error.
2. Add `catchalls` Makefile target:
   ```makefile
   catchalls:
       @grep -rn "{-# CATCHALL #-}" formal/ --include="*.agda" | sort
   ```
3. `make frontend` + `make compiler` must pass cleanly.

Estimated: 30 min.

### Phase F — Documentation and decision log

- Decision log entry **D049**: Exhaustive semantic case-splits
  enforced via `--exact-split`.
- Short doc in `docs/formal/guides/exhaustive-semantics.md`: what
  `CATCHALL` means, when to use it, how to audit it.
- Update `plans/README.md`: mark 0.9 complete.

Estimated: 30 min.

## Success criteria

- `--exact-split` + `-W error=CoverageNoExactSplit` enabled project-wide.
- `make frontend` + `make compiler` + `make malonzo` pass under
  the enforced flag.
- `make catchalls` lists every deliberate catch-all with its file
  and line; count is finite and each has a justification comment.
- `Once.CCC.Target.X86-64.DirectSimulation.exec-x86` has no silent
  catch-all — every `Instr` constructor is either explicitly
  modeled or routed through a named postulate.
- Adding a new `Instr` constructor becomes a compile-time error in
  every semantic function that wasn't updated.
- Decision log D049 written.

## Risks

1. **Large census surface.** Many existing catch-alls may turn
   out to exist, especially in optimizer / view-function code.
   Mitigation: CATCHALL-mark liberally in Phase C/D; focus fix
   effort on Phase B (the high-stakes DirectSimulation bugs).

2. **`CATCHALL` abuse.** Developers mark catch-alls to make the
   build pass without real justification. Mitigation: justification
   comment is mandatory by convention; reviewers treat CATCHALL
   like postulate. Tooling: `make catchalls` is compared against
   PR baseline in CI (future follow-up).

3. **Flag interactions.** `--exact-split` may interact with other
   Agda options (cubical, rewriting, universe polymorphism). We
   don't use those heavily but an unexpected interaction could
   surface. Mitigation: discover early in Phase A.

4. **Third-party `.agda-lib` dependencies (stdlib).** stdlib may
   have catch-alls. We don't control stdlib. Mitigation:
   `--exact-split` only affects OUR code; stdlib warnings don't
   promote to errors if scoped to our library's .agda-lib.

5. **Plan drift.** Phase A census might reveal the surface is far
   bigger than estimated, making this a multi-session plan.
   Mitigation: commit per-phase; stop after Phase B if Phase A
   shows the fix surface is >1 day.

## Non-goals

- Replacing semantic functions with records (Option 4). Good idea
  for the future; orthogonal to this plan.
- Formalizing the ISA (Sail-style). The real cure for "spec ≠
  reality" is a formally specified ISA. This plan does not attempt
  that. It addresses a strict subset of gaps — those caused by
  silent pattern-match catch-alls — and leaves spec-reality-
  alignment as a separate concern.
- Auditing other silent-underspecification patterns. Each has its
  own plan shape; see the next section.

## Related silent-gap classes (each needs its own plan)

This plan closes one specific class: **catch-all absorption in
semantic pattern matches**. Several adjacent classes share the
same "proof is valid, model is silently too weak" character but
need different mechanisms. Catalogued here so the follow-on
plans don't have to re-discover the landscape.

### Gap class A: `⊤`-valued predicates pretending to constrain

Example:
```agda
WellFormed : T → Set
WellFormed _ = ⊤
```
Looks like a proof obligation; inhabited trivially. Any downstream
proof that asks for `WellFormed x` gets vacuous evidence.

**What closing it buys:** every predicate-valued name means
something; no cosmetic proof obligations. Callers relying on the
predicate can trust they're paying for real work.

**Mechanism candidates:** lint rule "predicate body must not
reduce to `⊤`"; reflection-based audit that rejects
`data P where triv : P` single-constructor predicates; review
discipline enforced by a named audit query.

### Gap class B: under-modeled abstract state

Example: `X86State` has no field for `r9`, so even an explicit
clause for `lea r9 …` is forced to be identity — there's nowhere
to write the value. The lea-offset bug had *both* this (no r9
field) AND a catch-all (no explicit clause). Closing just 0.9
would have forced an identity clause here; closing B would have
flagged the missing field but still allowed a catch-all to absorb
it.

**What closing it buys:** you can't claim to model an instruction
without also tracking the entities it affects. The abstract
machine's state type is complete with respect to the instruction
set it claims to simulate.

**Mechanism candidates:** for each architectural entity used in
codegen (every `Reg`, every `Mem` variant, every syscall-relevant
memory region), assert the state record has a field for it. A
reflection-based check that enumerates constructors of `Reg` and
verifies each has a read/write helper.

### Gap class C: `refl` proofs that only prove shape

Example:
```agda
theorem : f a ≡ f b
theorem = cong f (lemma a b)
```
If `f` reduces both sides to the same trivial form (e.g.
`f = const tt`), the theorem is true regardless of `lemma`. The
proof is valid; the statement is tautological.

**What closing it buys:** theorems say something. A proof's
normal form uses the variables the theorem's statement quantifies
over.

**Mechanism candidates:** hard to mechanize fully. Reflection-
based check "normalize the proof term; does it mention the
parameters the theorem quantifies over?" Alternatively: review
discipline for theorem statements.

### Gap class D: partial-result defaults (`Maybe`/`Sum`)

Example:
```agda
compile-result name with lookup name table
... | just v  = real-compilation v
... | nothing = trivial-default
```
Analogous to catch-all but on `Maybe`. `nothing` is treated as
"reasonable fallback" rather than "prove this can't happen."

**What closing it buys:** every partial-result branch discharges
a proof of absurdity, raises a typed error, or is an explicitly
named postulate. No trivia silently swallows real failure modes.

**Mechanism candidates:** grep-based lint — flag `... | nothing =
<non-⊥>` in specific function families; wrapper type
`Total : Maybe A → Set` that requires proof `just` always
results; review discipline backed by greppable audit.

### Gap class E: laundered / nested postulates

Example:
```agda
big-theorem : P
big-theorem = … where
  lemma : Q
  lemma = some-postulate      ← local, may escape top-level audit
```
Postulates inside `where`, `private`, or anonymous modules may
not surface in `make postulates` depending on how the grep is
written.

**What closing it buys:** the finite postulate audit surface is
truly finite — no hidden axioms in `where` blocks.

**Mechanism candidates:** strengthen `make postulates-grep` to
recurse into nested definitions; policy "all postulates at top
level, named, with justification comment"; reflection-based check
that enumerates every `postulate` declaration regardless of
nesting.

### Gap class F: specification drift via rename

Example: `foo : T → State` is renamed to `foo-v2` and semantically
reworked. Re-export from the old name still points at a stub or
at the new function with subtly different behavior. Proofs that
depended on `foo`'s old behavior may now be vacuous or wrong.

**What closing it buys:** a rename is either a true alias (same
semantics) or a break (new semantics, old name dropped). No
"gradual migration" via subtly-different same-named symbols.

**Mechanism candidates:** git-aware audit "this symbol's callers
have not been re-reviewed since its body changed"; reviewer
discipline; stronger naming discipline (version suffixes).
Hard to fully mechanize.

### Gap class G: hard-coded constants unchecked by the model

Example: the lea-offset bug itself. `lea r9 (rip+disp 4)` has a
literal `4` representing byte-arithmetic that the abstract
machine doesn't perform. Even with exhaustive case-splits (0.9)
and full state representation (B), if the semantics doesn't
*compute* RIP-relative addresses, the constant is unconstrained.

**What closing it buys:** concrete constants in emitted code are
derived by the compiler (or checked by the model), not written
by hand. No free parameters that readers must verify against
instruction-byte tables.

**Mechanism candidates:** model RIP-relative arithmetic in the
abstract semantics (high cost); derive the constant from a
length-computation function (`length setup-instrs` rather than
`4`); Sail-style ISA integration (large).

### Gap class H: trivial termination arguments

Example: a `step : T → T` function that only reduces cases
already in normal form. Trivially terminating; proofs about it
terminate but don't imply anything about reduction of
non-normal terms.

**What closing it buys:** termination proofs imply the claimed
computational behavior, not just "this function happens to
return on its trivial inputs."

**Mechanism candidates:** audit termination witnesses for "does
this function recurse non-trivially on the inputs it claims to
handle?"; wrapper type that demands evidence of progress.

### Summary

| Gap class | Mechanism | What it closes | Status |
|---|---|---|---|
| Catch-all in semantic pattern | **`--exact-split` + `CATCHALL`** | functions silently absorbing unmodeled constructors | **0.9 (this plan)** |
| A — `⊤`-predicates | predicate-body audit | vacuous proof obligations masquerading as real ones | future plan |
| B — under-modeled state | state-field coverage | instructions that change register X when X isn't in the state | future plan |
| C — `refl` on trivia | proof-normal-form audit | theorems vacuously true because both sides trivialize | future plan (hard) |
| D — `Maybe` defaults | `nothing`-branch discipline + lint | partial lookups pretending to be total | future plan |
| E — laundered postulates | strengthen postulate grep | postulates escaping audit via `where` / `private` | small follow-on |
| F — rename drift | git-aware audit | subtly-renamed symbols with unaudited reverse deps | future plan (hard) |
| G — hard-coded constants | model derivation or Sail-ISA | hand-written constants the model doesn't verify | future plan (large) |
| H — trivial termination | termination-witness audit | termination proofs that don't imply computational progress | future plan |

Each row is an independent audit surface. Closing any one is
independent of the others. Closing all of them is the full story
of "model faithfulness as a mechanical invariant." 0.9 is a
surgical first step: close the row that hid the lea-offset bug,
and leave the catalogue visible for whoever tackles the next row.

## Author's note

This plan converts a latent discovery (one bug that hid behind a
catch-all) into a permanent mechanical invariant. The lea-offset
bug will not come back in this class — or any new bug in this
class — because the compiler will refuse to build unless each
catch-all is explicitly named. The named-catchall list becomes
a finite, greppable audit surface of the same shape as the
postulate audit.
