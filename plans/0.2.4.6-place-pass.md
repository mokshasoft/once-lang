# Plan 0.2.4.6: Place pass (allocation placement + lifetime analysis)

## Context

Plan 0.2.4.5 makes IRs *stupid receivers* of destinations: every IR
takes a `ValueLocation` parameter saying where to write its output.
Someone has to *decide* those destinations. That someone is the
`Place` pass.

The decision per allocation site is two-part:
- **Which Allocator?** Stack (frontier-bump, frame-bound) or Dynamic
  (runtime alloc/free SigOps).
- **For Dynamic**: which specific allocator function (mempool, malloc,
  arena) — by symbol name. Place picks the symbol statically.

For each Dynamic-allocated value, Place additionally inserts:
- An `alloc` SigOp before the value's first use.
- A `free` SigOp after the value's last use.

`Once.Escape` (today's escape analysis) does part of this — decides
whether a value escapes its lexical scope. The Place pass subsumes
this question and goes further: lifetime endpoints, allocator
selection, alloc/free SigOp insertion.

## Goal

A static analysis pass `Once.Place` that walks an IR, decides each
allocation site's Allocator and lifetime, and produces a "placed IR"
where every IR has a destination annotation and Dynamic allocations
are bracketed by alloc/free SigOps.

## Locked decisions

### D1: Pipeline position

```
parse → typecheck → elaborate → desugar → optimize → place → codegen
```

After optimize, before codegen. Place sees the post-optimised IR;
codegen sees the placed IR.

### D2: `Place` is a verb (matches existing pipeline naming)

`Once.Place` (or `Once.Place.Run` for the pass entry point). Avoids
clash with runtime `Allocator` name. Matches verb-form of parse,
typecheck, elaborate, optimize.

### D3: Place is the smart layer; IR + Allocator are stupid

- **IR**: receives destination, writes there. No context awareness.
- **Allocator**: returns memory when called. No proof obligations.
- **Place**: walks IR, sees lifetimes, decides destinations,
  inserts alloc/free. Carries the proofs that placement is sound.

A buggy Place (returning Stack for an escaping closure) is caught at
the Place-correctness level: `Place-correct` requires that no Stack-
allocated value is read after its frame pops. That predicate lives
in a `Place.Correct` module — separate from IR codegen and runtime.

### D4: Subsume `Once.Escape`, or use it as input — TBD

Two options for how Place relates to today's `Once.Escape`:

- **(a) Subsume**: Place absorbs escape analysis as a sub-step. The
  escape question (does this value escape its lexical scope?) is one
  of several Place answers.
- **(b) Use as input**: `Once.Escape` stays a separate pass; Place
  consumes its results plus does additional work (lifetime
  endpoints, allocator selection, alloc/free insertion).

Pick when scoping the Place implementation. (a) is cleaner if
escape analysis is small enough to fold in; (b) preserves the
existing structure.

### D5: Layer 0 Place is trivial

For Layer 0 every IR's output goes Stack (next free slot in caller's
frame); register-resident primitives ride in registers when a
consumer reads them immediately (no destination needed). No Dynamic
allocation. No alloc/free SigOps inserted. Just a slot allocator
walking the IR.

Layer 1+ adds compound types. Place still picks Stack as long as
escape analysis says so. Mempool routing is a Place-time policy.

Layer 5+ closures may escape — Place picks Dynamic, inserts alloc/free.

## Scope for this plan

**In scope:**

- Define `Once.Place` module: walks an IR, produces a placed IR.
- Define the placed-IR shape: regular IR + destination annotations on
  each IR + Dynamic-bracket alloc/free SigOps.
- Layer 0 Place implementation: trivial bump-allocator over caller's
  frame slots, no Dynamic allocation.
- `Place.Correct` module: the predicate Place must satisfy. Layer 0
  proof discharged.

**Out of scope:**

- Layer 1+ allocation (compound types under Place).
- Layer 5+ allocation (escaping closures, recursive μ-cells).
- Specific Dynamic allocator runtime implementations.
- Mempool routing policy decisions.
- Subsume-vs-input decision for `Once.Escape` — pick when scoping
  the actual implementation.
