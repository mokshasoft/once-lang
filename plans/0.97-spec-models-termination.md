# Plan 0.97 — The Spec must model termination

## 0. The one property

> **A program that calls a halting SigOp stops, and the Spec must say so.**

Today it does not. `T X = ℕ → List SigOpEvent × X` (TraceMonad:46) has no
channel for "this computation ended"; `_>>=T_` (:58) unconditionally runs the
continuation; and `emit-eff` (TraceDenote:63) / `emit-D` (ValueDomain:323)
treat `Halts` IDENTICALLY to `Emits` — one event, value `tt`, carry on. So the
denotation of `exit 0; print "x"` emits BOTH events. The machine, correctly,
emits one.

## 1. The measurement — verified 2026-09-22

`Once.Probe.HaltsRefute` (untracked) typechecks. It proves that for a `Halts`
SigOp NO `MachineRefinesObsF` witness exists at all:

  * `exec-sigop-halts-of (Halts _) ≡ true` — the instruction sets the flag;
  * `ValueRealized.live` demands `halted (floc settle) ≡ false`;
  * `at-end` demands `fpc settle ≡ 1 + base`, which only executing that
    instruction reaches.

Zero steps leaves the pc at `base`; one step sets the flag; two steps need the
flag clear to take the second. All three branches close.

`Halts` is not hypothetical: `Elaborate.agda:1953`/`:2006` build `haltsV refl`
from an `se-halts` declaration, which is how `exit` is declared.

### What this is and is not

It is NOT a compiler bug. For `main = exit 0` the EVENTS already agree. It is
an unsatisfiable side-condition: `live` was written to match a Spec that says
programs never stop, so no exiting program — i.e. no program — can satisfy it.

## 2. The encoding, and why this one

    T X = ℕ → List SigOpEvent × Stopped × X          (Stopped = Bool)

`Halts` already forces `B ≡ Unit`, so the VALUE after a halt is `tt`
regardless — nothing has to become optional. Only the EVENTS must stop.

Rejected: `T X = ℕ → List SigOpEvent × Maybe X`. It retypes `valueT`, and
`TM.valueT (evalᴰ ir x) k` appears in the `ResultPlace` of every discharged
clause. The flag leaves `valueT`'s TYPE alone, so those sites are untouched.

`projTrace` and `valueT` KEEP THEIR TYPES; only their definitions move. 50
modules import `TraceMonad`, and that is what keeps the ripple to the ~52
sites that destructure a `T` result directly rather than through an accessor.

## 3. The obligation gets STRONGER, not weaker

`ValueRealized.live : halted (floc settle) ≡ false` becomes

    halted (floc settle) ≡ stoppedT (evalᴰ n l ir x) k

— the machine halts EXACTLY when the Spec stops. The present field is the
`false` case of this one. `comp-obs-correct` then matches structurally: if `f`
stopped, `g` does not run, on either side.

### Stage C, as it actually landed

Stage C's guess in the table above was wrong in one respect, and the
typechecker said so at `Comp.agda:425` before any of it was written: `live`
and `at-end` are not the only fields a stopped fragment cannot supply.
**`place` is the third.** `>>=T` keeps a value field in the stopped case only
because `T X` has no empty value — when `f` stops in `g ∘ f`, the composite's
`valueT` is `g`'s value of `f`'s, and the machine never computed it. A
producer must not be asked to place it. So the record has FOUR conditioned
fields, not two:

```agda
live  : stoppedT (evalᴰ ir x) k ≡ false → halted (floc settle) ≡ false
at-end: stoppedT (evalᴰ ir x) k ≡ false → fpc settle ≡ length (emitted n l ir) + base
stops : stoppedT (evalᴰ ir x) k ≡ true  → halted (floc settle) ≡ true
place : stoppedT (evalᴰ ir x) k ≡ false → ResultPlace …
```

`CalleeRun` took the same four (`returned` in place of `at-end`) — and there
it is not a technicality: a called closure whose body ends in a halting SigOp
never reaches its `c-ret`.

### Stage D, as it actually landed

Four combinators, not one. Each takes the boolean as an ARGUMENT with its own
equation rather than `with`-abstracting it — the `where` blocks these proofs
are stated against are far too large for a `with` to abstract a projection of
a matched field out of.

| module | split | the stopped run |
|---|---|---|
| `Comp` | on `f` | the composite's run IS `f`'s; `join-es true es _ = es` |
| `CaseArmL` | on the arm | the row to the join label never executes |
| `CaseArmR` | on the arm | the `c-jmp` and the join label never execute |
| `PairAssemble` | on `f`, then on `g` | THREE outcomes: prologue+`f`; prologue+`f`+mid+`g`; the full five segments |

`PairChain.WithF` and `.WithG` take the equation as a MODULE PARAMETER —
everything in `WithF` is about what happens after `f` (the mid rows, `g`'s
entry state, `g`'s run, the tail), so a caller cannot instantiate it without
deciding. That is what makes the three-way split structural rather than a
case analysis bolted on at the end.

`PairPres` gained `mem-pres-to-fsF` / `mem-pres-to-gs` / `frame-pres-to-gs`:
the same legs `mem-pres-pair` already spends, named at the two earlier
segment boundaries instead of re-proved. `PairTrace` gained `innerT` (the
inner bind, which could stay implicit only while the outer `++` was
unconditional), `denot-split-of`, `pair-traces-stopped` and
`pair-traces-stopped-g`.

## 5. The gate — FIRED 2026-09-22, and it corrected the design

Stage A was implemented far enough to break, and it broke on something §3 had
not considered. Recorded because the correction is the design:

**THE FLAG MUST NOT BE BUDGET-GATED.** The first attempt let stoppedness be
observed like an event, so `stoppedT m 0` was `false` for every computation —
nobody has seen the halt yet at budget zero. But the machine's `halted` is
budget-FREE: the run halts whether or not an observer was watching. So
`halted (floc settle) ≡ stoppedT (evalᴰ n l ir x) k` is FALSE at small `k`,
and §3 as first written could not be proved.

The fix is a definitional choice, not a restructuring: the EVENTS are capped
by the budget (`sig1`/`capN`), the FLAG is not. `evalᴰ (SigOp si)` reports
`true` for `Halts` at EVERY budget, and `halt-join` propagates it. Agda is
total, so the continuation is evaluated and its flag computed regardless of
how much budget is left — the budget only ever gated the event list.

With the flag constant in `k`, §3 is well-formed again and the sequencing
proof stays easy: in the stopped branch the composite's trace IS `m`'s, so
`Bounded`/`Saturating`/`Coherent` come straight from `m`'s own.

**REVISED COST.** `PrefixFamily` gains a fourth field,

    stop-fix : ∀ k → stoppedT m (suc k) ≡ stoppedT m k

— `refl` at every leaf, a small proof for `bindAt`. But
`DenotPrefix.evalᴰ-good` must then supply it for EVERY constructor, and that
module carries 8 postulates of its own. That is the part stage C's original
estimate missed; it is mechanical but it is not free.

The original stage-C guess — "each clause supplies `false ≡ false`" — SURVIVES
the correction, because `stoppedT` still reduces to `false` for every
non-SigOp constructor.

## 5b. THE SECOND COST SURPRISE — `StopFixed` is not enough

Attempting stage A a second time (correct design, flag budget-free) got as far
as `T`/`returnT`/`_>>=T_`/`halt-join`/`fmapT`/`tell`/`valueT`/`stoppedT`/
`bindAt`/`bindAt-cong` and `PrefixFamily.stf` — all accepted, leaves supply
`stf` by `refl`. It stopped at `>>=T-pf`, and the reason is structural rather
than fiddly:

**`StopFixed` is NOT preserved by bind, and neither is monotonicity.** When
`m`'s flag is false the composite's flag is `f`'s, read at the SHIFTED budget
and at the VALUE `m` produced at that budget:

    stoppedT (m >>=T f) k  =  stoppedT (f (valueT m k)) (k ∸ lm k)

For `k` and `suc k` these differ in two ways at once — the budget shifts, and
`valueT m k` need not equal `valueT m (suc k)` while `m` is still spending.
A computation whose value oscillates with the budget could hand `f` a halting
argument at even budgets and a non-halting one at odd, so the composite's flag
oscillates too. Nothing currently forbids that.

The missing invariant is that **the budget is a LENS, not a parameter**: it
truncates the view of a computation, it does not change what the computation
IS. Stated, that is a second new field,

    vfx : ∀ k → valueT m (suc k) ≡ valueT m k

which is true of every `evalᴰ` (leaf values ignore the budget, and bind's
value is a leaf's by induction) but is nowhere written down.

### Revised cost, second time

`PrefixFamily` gains TWO fields, and `DenotPrefix.evalᴰ-good` must supply both
at EVERY constructor — a module that still carries 8 postulates of its own.
This is no longer "a Spec tweak, then follow the typechecker": it is a
strengthening of the Spec's central invariant, and it deserves to be costed
and agreed before more code is written. Stage A was reverted; the tree is
green. The design above is settled and correct — what is not settled is
whether `PrefixFamily` should carry the lens property, or whether `T` should
be reshaped so it holds by construction.

## 6. The fork, decided 2026-09-22

`Behavior` (Behavior.agda:126) is `at : ℕ → List SigOpEvent` with
`extends`/`bounded`/`saturating`. It has NO termination channel, so a program
that halts and one that hangs emitting nothing are the SAME behaviour today.
That is a real gap — termination vs divergence is observationally
distinguishable — but closing it changes what `_≋_` means, and therefore what
the apex's `correct` claims. Two decisions, so two changes:

  * THIS PLAN puts stoppedness inside `T` only. That is what 0.88's `Halts`
    row needs, and it is not a regression: `Behavior` cannot distinguish halt
    from hang today either.
  * A FOLLOW-ON row (not this plan) lifts it into `Behavior` and `_≋_`.

Deciding it this way also settles the budget question: internally the flag is
budget-FREE. The events are capped because an observer watches a prefix;
"did it stop" is a fact about the run, not about how long anyone watched.

## 7. What NOT to do

Do not encode stoppedness as a synthetic event in the list. The event list is
the observable; a marker in it would be observable too, and `obs` would then
distinguish programs by how they ended rather than by what they did.
