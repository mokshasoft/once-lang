## 1. Phase A — `pair`/`curry` become grade-polymorphic

### The verdict: RATIFICATION, not new semantics

Researched 2026-09-19 with citations. The denotation, the emitter and the
correctness proof **already** implement a left-first effectful pair:

* `evalᴰ fmt ⟨ f , g ⟩ a = evalᴰ f a >>=T λ b → evalᴰ g a >>=T λ c → returnT (b , c)`
  (`DenotTrace.agda:134`) — `_>>=T_` concatenates `m`'s events first
  (`TraceMonad.agda:52-63`), so this is `f` then `g`.
* `Meaning.agda:258-260` writes the source-level clause in the same Kleisli
  style, already, even though the rule it interprets is pure-fixed.
* `IRToTrace.agda:795-817` runs `f`'s trace, restores the input, then `g`'s.
* `obs-correct-pair-proof` (`PairAssemble.agda:102-104`) is stated over
  **arbitrary** `f g : IR`, not effect-free ones, and is a PROOF — D211, zero
  postulates in `Pair.agda`/`PairAssemble.agda`.
* `⟦ A ⇒[ mk-kind q π ] B ⟧ᴰ` ignores `π` (`ValueDomain.agda:222-224`), so the
  clause's TYPE is unchanged when `π` goes free.

So **an effectful pair already has a meaning and a verified lowering.** The
pure-fixing is a typing restriction over a semantics that already supports it.

### Phase A′ — `apply` at an effectful closure. NOT a widening; a NEW RULE.

A curried effectful closure can now be BUILT (gate 3) and not ELIMINATED:
`t-apply-check` and `t-apply-app-infer` both fix their arrow to `pure`, so
`apply` will not take one. That is a dead end introduced by Phase A, and it
belongs here rather than in a later plan.

**It is not `{π}`.** Once keeps effects on ARROWS: `t-effApp` at an eff arrow
concludes `Unit ⇒[eff] B` — a SUSPENSION — not `B`. So `apply` splits the same
way `t-app`/`t-effApp` do:

    pure closure:  ⊢ᵢ apply p ∶ B
    eff  closure:  ⊢ᵢ apply p ∶ (Unit ⇒[ mk-kind Many eff ] B)

The CONCLUSION'S SHAPE differs between the two, so a single rule with a free `π`
cannot state it. The work is a new rule + its `checkApply` clause + completeness
+ `agree-check-RApp` — the shape `t-effApp` already has, transcribed.

Gate: `apply (pair (curry (compose emit@E fst)) 5)` runs and emits.

## 2. Phase B — the cata folds the wrong way (D221)

`node(leaf 40, leaf 2)` emits `[2, 40]`; `node(node(leaf 1, leaf 2), leaf 3)`
emits `[3, 2, 1]`. The spec says `[40, 2]` and `[1, 2, 3]` via
`seqF (G ⊗ H) = seqF G x >>=T λ u → seqF H y >>=T …`
(`ValueDomain.agda:135`). `Layer5Spec.hs:73` documents the spec order.

**Which side is wrong is NOT yet decided**, and Phase A is what settles it.
Three independent left-first choices already exist — `seqF`, the `⟨f,g⟩`
denotation+emitter (proved agreeing, D211), and D056's discharged *"effectful
`∘` sequences effects in source order"*. The right-to-left fold is the odd one
out, so the presumption is that the CODEGEN is wrong. The cata codegen has not
been read; that is step B1.

### B1 — DONE 2026-09-19. It is a codegen bug at TWO NAMED CLAUSES, not a
### forced constraint, and the codegen's own comment states the intended order

The Tier-2 branching cata (`cata-strategy F | suc (suc _) = strat-branching F`,
`IRToTrace.agda:184-190`) is a flatten-then-rebuild over two linked stacks. The
two walks disagree at the product, by exactly one inversion:

```agda
visit-walk todoSlot tv tb (F ⊗ G) s lb =            -- IRToTrace.agda:165-169
  (mov-to-output ∷ store-at-slot s ∷ load-indirect-suc ∷ mov-to-input ∷ []) ++
  visit-walk todoSlot tv tb G (s +ℕ 4) (lb +ℕ lsize F) ++     -- G (RIGHT) first
  (restore-input s ∷ load-indirect ∷ mov-to-input ∷ []) ++
  visit-walk todoSlot tv tb F (s +ℕ 4) lb                     -- F (LEFT) second

-- REBUILD walk: … popping one value-stack result per Id position, LEFT-to-RIGHT.
rebuild-walk valSlot tv tb (F ⊗ G) s lb =           -- IRToTrace.agda:181-189
  (mov-to-output ∷ store-at-slot s ∷ load-indirect ∷ mov-to-input ∷ []) ++
  rebuild-walk valSlot tv tb F (s +ℕ 4) lb ++                 -- F (LEFT) first
  (store-at-slot (suc s) ∷ restore-input s ∷ load-indirect-suc ∷ mov-to-input ∷ []) ++
  rebuild-walk valSlot tv tb G (s +ℕ 4) (lb +ℕ lsize F)       -- G (RIGHT) second
```

**`rebuild-walk`'s own comment says LEFT-to-RIGHT.** So the intended order is the
spec's; the delivered order is its mirror.

Measured — the divergence is an EXACT MIRROR at every shape, which is what a
single product-order inversion against a LIFO stack looks like, and rules out a
structural defect:

    node(leaf 40, leaf 2)                     spec [40, 2]      machine [2, 40]
    node(node(1,2), leaf 3)                   spec [1, 2, 3]    machine [3, 2, 1]
    node(leaf 1, node(2, 3))                  spec [1, 2, 3]    machine [3, 2, 1]
    node(node(1,2), node(3,4))                spec [1,2,3,4]    machine [4,3,2,1]

**Verdict: the MACHINE is wrong.** Reasoning from principle, not vote-count:
an effectful cata needs a TRAVERSAL of `F` over `T` (`F(cata alg)` is not
functorial action when `cata alg` is Kleisli), a traversal of a product must
choose an order, and `seqF` IS that choice — hence part of the spec. The spec is
internally coherent (the same `⊗` is left-first in `seqF` and in `evalᴰ ⟨f,g⟩`,
the latter PROVED to match its emitter, D211). Fixing the machine breaks nothing
proved; changing `seqF` would falsify D211 and contradict D056.

    B1b. read `push2`/`pop2` to determine WHICH of the two clauses to swap —
         the fix is one clause, and the stack discipline says which.
    B2. swap the clause B1b names; re-measure all four shapes above
    B3. `cata-correct` stops being a postulate-that-is-false and becomes an

## 4. The rule this plan exists to install

**A recursion scheme is not tested until it is tested at a functor with TWO
recursive positions, asserting the TRACE rather than an exit code.**

One recursive position cannot order anything, so it cannot falsify an ordering
claim — the list test is green and correct and always was. D199 named the same
blind spot at ν (*"both use `Nu (K Int)` — a functor with NO recursive
position"*); the μ side had it one position deeper, and a vacuous test on top.
