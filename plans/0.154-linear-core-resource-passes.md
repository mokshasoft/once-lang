# Plan 0.154 — The linear core's resource passes: layers in place, free at last use, reuse, borrowing

## Summary

After plan 0.146 the compiler runs every program through a linear core whose memory behaviour is
proved: what is allocated is freed exactly once. That plan keeps the code simple so the proofs stand on
something stable. This plan makes the code cheaper without changing what any program means or how it
uses memory: values built straight into their final place instead of being copied there, memory freed as
early as the program allows, a dying value's memory reused for its replacement, and values read where
they lie instead of copied. Each improvement is a separate step, proved not to change the program's
meaning or its memory guarantee, and kept only when the measurements show it pays.

## 1. Why

GOAL.md: "memory is managed by the compiler from the program's structure". Plan 0.146 makes that true
and proved (`NoLeak`, the space claim), but at a cost: plan 0.123's merge made every program dearer
(over 112 programs: instructions 40380 → 60904, heap cells 4932 → 8344), and plan 0.146 §5 item 6 only
re-measures it. D466 places the fix: optimizations over resources are passes in the linear core (L2),
after the bridge from the Spec's calculus, each proved against the core's meaning and its memory claim.
D453 decided one of them for plan 0.146 (B1.8, layers in place); the user moved it here (2026-11-22)
so plan 0.146 proves its claims once over the simpler lowering and this plan's passes preserve them.

## 2. Where we are

- The linear core and its lowering: `formal/Once/LinCore/` (plan 0.146). A μ node is a cell: `lIn`
  builds the layer in frame slots and moves it into a fresh cell (`Lower.lowP … lIn`, `mvSP`); `lOutμ`
  moves it back (`mvPS`) and frees the cell; an observation (`kobs`) likewise (`Lower.agda`, lines
  around `lowP ds (lIn …)` and `view-in`).
- Reuse already exists for shape-preserving folds: `Events.r-cata-reuse` (no move, no event).
- Plan 0.146 §5 item 4 keeps the emitted code free of ownership information and of anything that would
  stop a later in-place update: the hook these passes need.
- Measurement: `tests/codegen-measure.sh compare` (instructions, heap cells, `.text` per arch).

## 3. Decisions

1. **Where a pass lives** (decided by D466, the user 2026-11-19): resource passes are in the linear
   core or at its lowering, each proved to keep the core's meaning and `NoLeak`; nothing in the Spec's
   calculus knows about cells.
2. **Layers in place: how far** (open). D453 asks for destination passing: the layer's fields written
   into the cell directly. In general that gives the lowering a destination per result (a frame area or
   a cell) and changes every simulation lemma. The cheaper reading is a fusion at the image: `lIn`
   after the instructions that build its layer writes their words to the cell (and `lOutμ` before its
   consumer reads them there), where the producer is a known shape (a constructor, a pair of values in
   slots). Recommendation: measure first (step 1); take the fusion if it recovers most of the moves.
3. **Order of the passes** (open): by measured pay-off (step 1).

## 4. Steps

1. **Measure.** `tests/codegen-measure.sh compare` against plan 0.123's merge and against plan 0.146's:
   which programs pay for layer moves, early frees, missing reuse, copies a borrow would avoid.
2. **Layers in place** (D453, D467; was plan 0.146 B1.8). `lIn` writes the layer's fields into the cell;
   `lOutμ` / an observation reads them from the cell where it can. Events unchanged (one alloc, one free
   per node); only the moves go. The lowering's simulation lemmas and `NoLeak` over the new image.
3. **Free at last use** (D428): a value's cells freed at its last use, not at its scope's end.
4. **Reuse beyond `r-cata-reuse`**: a dying node's cell for the new node of the same size.
5. **Borrowing** (D420 point 3: lending and sharing as proved refinements of `dup`'s deep copy).
6. Each step: `make certified`, the exit tests on three arches, `codegen-measure compare`, kept only
   when it pays.

## 5. Done when

1. Each pass kept is proved to preserve the core's meaning and `NoLeak` (and the space claim's bound).
2. The emitted cost is measured against plan 0.123's merge, every program still above its pre-0.123
   cost named with the reason.
3. No regression: `cabal test`, the exit tests on three arches, `make merge-gate`.
