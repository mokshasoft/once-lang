# Plan 0.58 — `Once.Spec`: a minimal, IR-free language definition (OCP-0006, north star)

Implements **OCP-0006**. The re-export first cut landed (`Once.Spec.*` exist), but it
enshrined a NON-minimal boundary: the "meaning" re-exports `Realize` + `DenotTrace`,
which drags **`Once.IR`** and the compiler-side `evalᴰ` into the trust surface. This
plan makes the spec **genuinely minimal**: the reference MEANING becomes a denotation
of typing DERIVATIONS, IR-free and elaborator-free.

## North-star target

The reference meaning is
```
⟦_⟧ᵈ : (Γ ⊢ e ∶ A) → ⟦Γ⟧ᴰ → T ⟦A⟧ᴰ        -- recursion on the DERIVATION
```
No `Surface.Expr`, no `realize`, no `evalᴰ`, no `Once.IR` anywhere in the spec surface.

Final trust boundary (`Once.Spec.*`), each importing only spec + shared semantic-domain
vocabulary (never the compiler, never `Once.IR`):

```
Once.Spec.Type      -- the Type + Functor GRAMMAR (inductive defs only)
Once.Spec.Syntax    -- RawExpr — the program you write & the rules judge
Once.Spec.Typing    -- ⊢ᵢ/⊢ᶜ/⊢ᵍ/⊢ᵐ + Typed        (Judgment, whole)
Once.Spec.Meaning   -- Behavior + semantic domain (⟦_⟧ᴰ, T) + ⟦_⟧ᵈ
Once.Spec.Correct   -- CorrectCompiler                (record, proof-free)
```

Demoted to IMPLEMENTATION (checked against the spec, not trusted): `Surface.Syntax`
(`Expr`), `Once.Denotation.Realize` (`realize`/`realize-global`/`realize-morph`),
`Once.Denotation.DenotTrace.evalᴰ`, all of `Once.IR`, the elaborator, the parser, codegen.

## Why the IR leak == the `Surface.Expr`/`realize` machinery (the key insight)

`SourceDenote` touches IR in exactly TWO places:
```
⟦ lift-morphism ir ⟧ˢ = returnT (evalᴰ ir)
⟦ morph-app ir e ⟧ˢ   = ⟦ e ⟧ˢ >>=T λ v → evalᴰ ir v
```
i.e. `Surface.Expr` embeds a pre-built CCC **morphism as an opaque `IR`**, because the
morphism realm `⊢ᵐ` is represented AS IR (`realize-morph : ⊢ᵐ → IR`). Denoting `⊢ᵐ`
**directly** — recursion on `m-id`/`m-fst`/`m-compose`/`m-curry`/`m-cata`/… straight to
a function `⟦A⟧ᴰ → T⟦B⟧ᴰ = ⟦A ⇒ B⟧ᴰ` — removes the IR entirely. The value realm
`⊢ᵍ` (`realize-global : ⊢ᵍ → IR`) goes the same way. Everything else in `SD` is already
IR-free (`⟦_⟧ᴰ`/`inject`/`forget`/`emit-D` are the semantic domain; cata/ana are already
`⟦alg⟧ˢ`-based, not `evalᴰ`).

## Strategy: a bridge, NOT re-proving adequacy

`⟦_⟧ᵈ` is the FUSION of `realize` (deriv→Surface) and `SD` (Surface→meaning) with the IR
intermediate replaced by a direct morphism denotation. So:
- Prove ONE bridge: `⟦ deriv ⟧ᵈ  ≈  SD.⟦ realize deriv ⟧ˢ`. For the non-morphism rules the
  fused denotation computes identically ⇒ mostly `refl`; the real content is the `⊢ᵐ`
  cases (`m-cata`/`m-named`/`m-const`), where the direct morphism semantics must agree
  with `evalᴰ ∘ realize-morph`.
- The existing green apex (which relates `exec bytes ≈ SD∘realize`, incl. the freshly
  proven `main-extract`/`main-realize-agrees`) then LIFTS to the new meaning by composing
  with the bridge. We do NOT re-derive the correctness proof.

## Option B decision (Surface-free) — the judgment refactor is CONTAINED

The typing judgment references `Surface.Expr`: `t-var-local` carries
`{eE : SExpr (debruijn ctx) Ψ A}` from `lookupLocal`. BUT `lookupLocal-go` always
produces `var i` (`Surface.var zero` / `weaken`), never arbitrary surface content. So
the fix is faithful and contained: **`lookupLocal` returns the de-Bruijn INDEX into
`NamedCtx.debruijn` instead of the `var i` SExpr.** Then `t-var-local` carries an index,
`realize` rebuilds `var i` from it (impl), and `⟦ t-var-local ⟧ᵈ dγ = returnT (lookupᴰ … i dγ)`
— Surface-free AND IR-free. `const`/value lift is the EASY part (already IR-free in P1;
the `= realize-global` identity is a bridge lemma, not spec).

### Design decision to settle first: the bridge's equality
`⟦ d ⟧ᵐ` and `evalᴰ (realize-morph d)` are FUNCTIONS `⟦A⟧ᴰ → T⟦B⟧ᴰ`; `m-compose`/`m-pair`

the apex's existing style instead: state the bridge OBSERVATIONALLY (the `_≈_` up-to-`n`
prefix `Once.Adequacy` already uses), so no funext and it composes directly with the existing
`exec ≈ SD∘realize` chain. (Settle before writing the bridge.)

## Bridge discharge — the `forget`-equality obstruction + the way past (2026-07-04)

State: `MeaningBridge` STATES the fundamental lemma (bridge-c/i/m/g) + `RelEnv`
(green, scaffolded bodies). Discharging the env-free realms (`bridge-m`/`bridge-g`)
is structural (`RelT-bind`/`RelT-return` + IH) EXCEPT the sigop cases (`m-named`/
`m-named-resolved`), which surfaced a genuine subtlety.

### The obstruction
`bridge-m (m-named x)` reduces to `RelV (A⇒B) F F` for `F = evalᴰ (SigOp (value-info
(bare x)))` (since `named-sem (bare x) ≡ F` definitionally). `RelV` at arrows is a Π:
`∀ related a b → RelT B (F a) (F b)`. A sigop's denotation is
`F a = λ n → (emit-D si (forget a) , inject (semM si (forget a)))`, so relating `F a`
and `F b` wants `forget a ≡ forget b`. `forget` at ARROW types runs the closure
(`forget {A⇒B} clo = λ va → forget (valueT (clo (inject va)) 0)`), so for related-but-
unequal HIGHER-ORDER `a`,`b` that equality needs **funext**. `m-named`'s domain is
unconstrained (`{A B : Type}` from `lookupImport … ≡ just (A ⇒[…] B)`), so a higher-
order imported function reaches this case in general.

### KEY INSIGHT — the trace is already funext-free (`mkEvent` drops non-`Int` args)
`Once.Denotation.Trace.mkEvent`:
```
mkEvent-name nm (just refl) arg = mk-event nm (just arg)   -- D ≡ Int  → keep arg
mkEvent-name nm nothing     arg = mk-event nm nothing        -- D ≢ Int  → DROP arg
mkEvent si arg = mkEvent-name (name si) (isInt? D) arg
```
So a sigop's EVENT depends on `forget a` only when the domain is `Int` (first-order,
`RelV Int = ≡`, so `forget a ≡ forget b` by `cong` — funext-free). For every non-`Int`
(incl. all higher-order) domain the event is argument-independent. **The apex observable
is the trace (`projTrace`), so the obstruction dissolves where it actually matters.**

### Remaining question — the VALUE component
`RelT` also tracks the value `inject (semM si (forget a))`, and `semM : SigOpInfo A B →
M.⟦A⟧ → M.⟦B⟧` DOES consume the argument. So the value half at a higher-order-domain
sigop still wants `forget a ≡ forget b`. This is bookkeeping for the induction (the apex
only observes the trace), so it should be dischargeable, but isn't yet closed.

### Options to finish (pick on pickup)
1. **`isInt?`-domain case-split (RECOMMENDED — likely fully funext-free).** Mirror
   `mkEvent`: split the sigop bridge case on `isInt? A`. `Int` → `forget a ≡ forget b`
   by `cong` (`RelV Int = ≡`). non-`Int` → event is `refl` (arg-independent); discharge
   the value half either by (a) showing higher-order-domain named `semM` is arg-opaque
   in practice, or (b) weakening `RelT`'s value component to a trace-adequate relation
   (track only what downstream emits observe — which is `Int`-based). Needs a focused
   proof but hits NO funext on the trace.
2. **Localized funext for `rel→forget-eq` arrow case only.** Prove `rel→forget-eq`
   funext-free at first-order/product/sum; funext ONLY at its arrow clause (one lemma).
   Denotation + rest stay funext-free. Smallest diff; contradicts the funext-free goal
   in exactly one proof lemma.
3. **Enforce first-order sigop domains.** Typing-side invariant that named/sigop domains
   are ground; makes `forget`-equality `cong`-only. Larger; may not hold for genuinely
   higher-order imports.

### REFINEMENT (2026-07-04) — the boundary is `FitsInReg`, not `Int`
`Once.Type.FitsInReg = {Int, Float}` (one-word, register-passable scalars). `mkEvent`'s
`isInt?` is a current UNDER-approximation (records only `Int`; even `Float` args are
dropped). The principled boundary is `FitsInReg`:
- `FitsInReg` domains are first-order scalars ⇒ `RelV = ≡` ⇒ `forget a ≡ forget b` by
  `cong` — funext-free for BOTH the trace event AND the `semM` value. No value-component
  gap (unlike the `isInt?`-only split, where non-`Int` first-order codomains lingered).
- non-`FitsInReg` domains (compound / higher-order) are NOT register-passable; `IR.SigOp`
  allows them formally (`∀ {A B}`), but the adequacy chain only runs on VALID sigops
  (`valid-primitive-wf` / `ValidPrimitive`, already required upstream), and the register
  machine passes sigop args in registers ⇒ a valid sigop's domain is `FitsInReg`.

**Cleanest funext-free close:** in the `bridge-m` sigop case, extract `FitsInReg A` from
the sigop's validity witness (the derivation already carries what the adequacy needs),
then `forget a ≡ forget b` is `cong` from `RelV A a b = a ≡ b`. No funext, no value gap,
no new typing constraint — it reuses the existing `FitsInReg`/validity machinery. The
open task is to thread the `FitsInReg`-domain fact from the sigop validity to the bridge
(check `valid-primitive-wf` exposes it; if effectful sigops aren't yet `FitsInReg`-gated,
that gate is the one small addition, and it is physically forced anyway).

# DECISION (2026-07-11) — SigOps are an FFI boundary: CONCRETE types only
# ============================================================

The sigop leaves (2/3/4 above) reduce to `forget a ≡ forget b` + `RelV`-reflexivity
at a sigop's domain/codomain — funext-free ONLY when those types are arrow-free
(first-order). The current spec does NOT enforce this: `SigOpInfo (A B : Type)` takes
arbitrary types and `lookupImport` maps names to arbitrary `Type`. `generic-semM` (the
named-primitive value) is a `postulate` — the spec deliberately leaves a primitive's
returned value abstract over arbitrary types.

Restricting sigop types to first-order is therefore NOT a proof-convenience gate
(which top-down forbids). It is a JUSTIFIED SPEC REFINEMENT: a SigOp **is** an FFI
boundary (reused by the compiler for its own primitives), and an FFI/register-ABI
boundary genuinely only passes CONCRETE values — never a Once closure or a live
recursive value. The current spec is UNDER-constrained (it admits programs the target
cannot faithfully run); adding the condition makes the language definition more honest.

## The decision (settled with the user)
- **Predicate = `IsBaseType`** (`Unit/Void/Int/Float/Str/Buffer`, closed under `×`/`+`):
  concrete scalars + by-value structs. EXCLUDES arrows and `μ`/`ν` (an FFI takes a
  `Buffer`/pointer, not a closure or heap value). Same predicate `WellFormedF` uses for
  functor `K`-positions ⇒ the already-green `base-rel→eq` discharges the bridge leaves.
- **Enforce BY CONSTRUCTION on `SigOpInfo`/`value-info`** — require `IsBaseType A` and
  `IsBaseType B` to build a SigOp, so a bad SigOp value is unrepresentable. Because
  `value-info` is generic and its callers get `A`/`B` from typing derivations, the SAME
  witness must reach the derivation anyway ⇒ this SUBSUMES gating the typing rules:
  - `SigOpInfo`/`value-info` can't be built at non-concrete types (interface honesty);
  - typing rules (`m-named`, `t-var-qualified/resolved/import`, poly) CARRY the witness
    ⇒ no program is well-typed with a bad SigOp;
  - the import boundary PRODUCES the witness from the declared signature.
  One shared `IsBaseType` witness, threaded down.

## DEEP ANALYSIS (2026-07-11) — carrier restriction REJECTED (not principled)
Constraining the cata carrier `A` with `IsConcrete` is a SHIM: no FFI boundary (cata is
pure internal compute), and `Val.⟦A⇒B⟧ = Val.⟦A⟧→Val.⟦B⟧` (the machine model represents
higher-order fns), so no representability constraint either. The real obstacle is in the
TOOL, not the language:
- Every other bridge case THREADS the input relation to the output. Cata is the only fold;
  its input `RelV(μF) a b = a ≡ b` carries no relational content, so the output `RelT A`
  must come entirely from the algebra, threaded through the fold.
- But `RelV` is **funext-free** (a Π at arrows: `RelV(A⇒B) f g = ∀ related-inputs → RelT`),
  hence **NOT reflexive** at arrow types. Reconstructing the `⟦A⟧ᴰ`-level relation from the
  fold's `Val`-level carrier needs `inject∘forget = id` at `A` — true first-order, FALSE at
  genuinely-higher-order carriers (a fn OF a fn). Checked: NOT rescued by funext (funext is
  about fn EQUALITY, not `RelV` reflexivity), NOT by a Val-level relation (`RelV`'s inputs
  are related-but-UNEQUAL; their `forget`s differ at higher-order, breaking any pointwise
  reconstruction). It's a structural property of the funext-free `RelV`.

## DECISION (2026-07-11, with user) — OPTION 1: redesign `RelV` (the principled fix)
Don't restrict the language to fit the relation; **fix the relation**. Replace the current
funext-free-but-non-reflexive `RelV` with a proper logical relation that carries a
FUNDAMENTAL LEMMA (reflexivity/parametricity theorem): *every semantically-produced value
is related to itself*. Reflexivity is FALSE for arbitrary higher-order values but TRUE for
REALIZABLE ones (built from combinators/morphisms that preserve the relation) — the
standard logical-relations move. With the fundamental lemma in hand, the cata output
reflexivity is a corollary and `cata-bridge` (plus, we expect, other leaves) FALLS OUT.
This is architectural — it touches `Once.Adequacy.MeaningRelation` and every `bridge-*`
case — so it is its own focused effort. Guiding principle (user): find the abstraction that
makes ALL the proofs fall out; principle over expedience.
