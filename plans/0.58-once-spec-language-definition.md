# Plan 0.58 — `Once.Spec`: a minimal, IR-free language definition (OCP-0006, north star)

Implements **OCP-0006**. The re-export first cut landed (`Once.Spec.*` exist), but it
enshrined a NON-minimal boundary: the "meaning" re-exports `Realize` + `DenotTrace`,
which drags **`Once.IR`** and the compiler-side `evalᴰ` into the trust surface. This
plan makes the spec **genuinely minimal**: the reference MEANING becomes a denotation
of typing DERIVATIONS, IR-free and elaborator-free.

## North-star target

The reference meaning is
```
⟦_⟧ᵈ : (Γ ⊢ e ∶ A) → ⟦Γ⟧ᴰ → T ⟦A⟧ᴰ        -- recursion on the DERIVATION
```
No `Surface.Expr`, no `realize`, no `evalᴰ`, no `Once.IR` anywhere in the spec surface.

Final trust boundary (`Once.Spec.*`), each importing only spec + shared semantic-domain
vocabulary (never the compiler, never `Once.IR`):

```
Once.Spec.Type      -- the Type + Functor GRAMMAR (inductive defs only)
Once.Spec.Syntax    -- RawExpr — the program you write & the rules judge
Once.Spec.Typing    -- ⊢ᵢ/⊢ᶜ/⊢ᵍ/⊢ᵐ + Typed        (Judgment, whole)
Once.Spec.Meaning   -- Behavior + semantic domain (⟦_⟧ᴰ, T) + ⟦_⟧ᵈ
Once.Spec.Correct   -- CorrectCompiler                (record, proof-free)
```

Demoted to IMPLEMENTATION (checked against the spec, not trusted): `Surface.Syntax`
(`Expr`), `Once.Denotation.Realize` (`realize`/`realize-global`/`realize-morph`),
`Once.Denotation.DenotTrace.evalᴰ`, all of `Once.IR`, the elaborator, the parser, codegen.

## Why the IR leak == the `Surface.Expr`/`realize` machinery (the key insight)

`SourceDenote` touches IR in exactly TWO places:
```
⟦ lift-morphism ir ⟧ˢ = returnT (evalᴰ ir)
⟦ morph-app ir e ⟧ˢ   = ⟦ e ⟧ˢ >>=T λ v → evalᴰ ir v
```
i.e. `Surface.Expr` embeds a pre-built CCC **morphism as an opaque `IR`**, because the
morphism realm `⊢ᵐ` is represented AS IR (`realize-morph : ⊢ᵐ → IR`). Denoting `⊢ᵐ`
**directly** — recursion on `m-id`/`m-fst`/`m-compose`/`m-curry`/`m-cata`/… straight to
a function `⟦A⟧ᴰ → T⟦B⟧ᴰ = ⟦A ⇒ B⟧ᴰ` — removes the IR entirely. The value realm
`⊢ᵍ` (`realize-global : ⊢ᵍ → IR`) goes the same way. Everything else in `SD` is already
IR-free (`⟦_⟧ᴰ`/`inject`/`forget`/`emit-D` are the semantic domain; cata/ana are already
`⟦alg⟧ˢ`-based, not `evalᴰ`).

## Strategy: a bridge, NOT re-proving adequacy

`⟦_⟧ᵈ` is the FUSION of `realize` (deriv→Surface) and `SD` (Surface→meaning) with the IR
intermediate replaced by a direct morphism denotation. So:
- Prove ONE bridge: `⟦ deriv ⟧ᵈ  ≈  SD.⟦ realize deriv ⟧ˢ`. For the non-morphism rules the
  fused denotation computes identically ⇒ mostly `refl`; the real content is the `⊢ᵐ`
  cases (`m-cata`/`m-named`/`m-const`), where the direct morphism semantics must agree
  with `evalᴰ ∘ realize-morph`.
- The existing green apex (which relates `exec bytes ≈ SD∘realize`, incl. the freshly
  proven `main-extract`/`main-realize-agrees`) then LIFTS to the new meaning by composing
  with the bridge. We do NOT re-derive the correctness proof.

## Option B decision (Surface-free) — the judgment refactor is CONTAINED

The typing judgment references `Surface.Expr`: `t-var-local` carries
`{eE : SExpr (debruijn ctx) Ψ A}` from `lookupLocal`. BUT `lookupLocal-go` always
produces `var i` (`Surface.var zero` / `weaken`), never arbitrary surface content. So
the fix is faithful and contained: **`lookupLocal` returns the de-Bruijn INDEX into
`NamedCtx.debruijn` instead of the `var i` SExpr.** Then `t-var-local` carries an index,
`realize` rebuilds `var i` from it (impl), and `⟦ t-var-local ⟧ᵈ dγ = returnT (lookupᴰ … i dγ)`
— Surface-free AND IR-free. `const`/value lift is the EASY part (already IR-free in P1;
the `= realize-global` identity is a bridge lemma, not spec).

### Proof reuse (why this is mostly re-composition)
- **Insulated / untouched:** the whole BACKEND (`IR → machine → targets`, all codegen /
  simulation / arch / arith / flat-machine proofs — 100+ modules; `elaborate` still emits
  identical IR). Also `Once.Adequacy`, the semantic domain, and `SD`/`realize` (kept as impl).
- **Re-composition:** define `⟦_⟧ᵈ` + prove ONE bridge `⟦_⟧ᵈ ≈ SD∘realize`, then COMPOSE with
  the existing `exec ≈ SD∘realize` apex (incl. the just-landed `main-extract`). Not re-derived.
- **Genuinely reworked (contained):** `lookupLocal`→index + `t-var-local`; a mechanical
  index-instead-of-`var i` pass over the 8 files matching `t-var-local` (`Judgment`,
  `Elaborate`, `Soundness`, `Completeness`, 3× `Canon*`, `Realize`) — apex-touching, ends
  with `certified`; and building `⟦_⟧ᵈ` fresh.

## METHOD (non-negotiable): TOP-DOWN, apex-first, no islands

Mirror how `main-extract` was discharged. Do NOT grow `Once.Denotation.Meaning` bottom-up
as an unused island. Instead: **wire the GOAL at the apex first.** State the re-pointed
reference meaning (`⟦_⟧ˢ ← ⟦_⟧ᵈ`) with `⟦_⟧ᵈ` and the bridge as TEMP POSTULATES, re-point
the instance, and get `certified` green — this proves the re-composition architecture and
lets the typechecker PIN the exact shapes of `⟦_⟧ᵈ` and the bridge. THEN discharge downward
(build `⟦_⟧ᵈ`'s realms, prove the bridge), shapes known. Every module stays connected to the
apex; no leaf is built speculatively. (The P1 morphism/value realms already exist — they get
CONNECTED via the bridge, not left standalone.)

### Design decision to settle first: the bridge's equality
`⟦ d ⟧ᵐ` and `evalᴰ (realize-morph d)` are FUNCTIONS `⟦A⟧ᴰ → T⟦B⟧ᴰ`; `m-compose`/`m-pair`
bind the sub-morphism as a `>>=T` function argument, so a raw `≡` bridge needs funext. Match
the apex's existing style instead: state the bridge OBSERVATIONALLY (the `_≈_` up-to-`n`
prefix `Once.Adequacy` already uses), so no funext and it composes directly with the existing
`exec ≈ SD∘realize` chain. (Settle before writing the bridge.)
