# Plan 0.13.1: Layer 2 sums — coordinated proof + codegen design

## Problem

Layer 2 (`inl`, `inr`, `case`) is fully stubbed in `IRToTrace.agda`:

```agda
ir-to-trace' n l (inl _)    = n , l , [] , []
ir-to-trace' n l (inr _)    = n , l , [] , []
ir-to-trace' n l (case _ _) = n , l , [] , []
```

Every Layer 2 program exits 0 regardless of intent. But the gap is
deeper than missing codegen — the **proof model itself doesn't
represent runtime tag values**:

- `valid-inl-wf` and `valid-inr-wf` (in `ClosureWellFormed.agda`)
  carry only the *payload pointer*, not a tag. The constructor name
  ('valid-inl-wf' vs 'valid-inr-wf') stands in for the tag at the
  *meta* level.
- `run-case` (in `SumRecWF.agda`) dispatches by **pattern matching
  on `inj₁` vs `inj₂` at the spec level**. The trace it produces
  for an `inj₁`-valued scrutinee is unconditionally `f-trace`; for
  `inj₂`, unconditionally `g-trace`. There is no runtime
  comparison instruction, no conditional branch.

This works for the *proof* (the metavalue determines which trace is
correct) but **cannot be implemented as actual code** — the runtime
sees memory at the sum location and can't tell `inl` from `inr`
without an actual tag.

`AbstractInstr` has no conditional branch primitive. The whole
abstract step model is sequential.

## Coordinated fix (across all three layers)

The codegen, abstract trace, and proofs must all model an explicit
runtime tag.

### Layer A — `ValueLocation` + new instructions

New `ValueLocation` constructor for tag literals:
```agda
data ValueLocation FS where
  ...
  TagLit : ℕ → ValueLocation FS   -- sum-tag literal (0 = inl, 1 = inr)
```

Two new `AbstractInstr` constructors:
```agda
data AbstractInstr where
  ...
  instr-load-tag-lit  : ℕ → AbstractInstr
    -- exec: regs[Output] := TagLit n
  instr-case-on-tag   : AbstractTrace → AbstractTrace → AbstractInstr
    -- exec: read tag at *Input1; if TagLit 0 → exec-trace f-trace
    --       else if TagLit 1 → exec-trace g-trace; else halt
```

`exec-abstract` clauses:
```agda
exec-abstract (instr-load-tag-lit n) s alloc =
  record s { regs = writeReg (regs s) Output (TagLit n) } , alloc

exec-abstract (instr-case-on-tag f g) s alloc with
    readLoc s (readReg (regs s) Input1)
... | just (TagLit 0) = exec-trace f s alloc
... | just (TagLit 1) = exec-trace g s alloc
... | _               = record s { halted = true } , alloc   -- malformed sum
```

### Layer B — Validity refinement

Add tag-witness fields to `valid-inl-wf` / `valid-inr-wf`:
```agda
valid-inl-wf : ∀ {m A B} {a : ⟦ A ⟧} {alloc} {sum-loc payload-loc} {s} {mA} →
  readLoc s sum-loc          ≡ just (TagLit 0) →   -- NEW: tag at slot[0]
  readLoc s (sucLoc sum-loc) ≡ just payload-loc →
  BeforeFrontier alloc payload-loc →
  BeforeFrontier alloc (sucLoc sum-loc) →
  ValidAtWF mA alloc a payload-loc s →
  ValidAtWF m alloc {A + B} (sem-inl a) sum-loc s

valid-inr-wf : … readLoc s sum-loc ≡ just (TagLit 1) → …
```

`decomposeInlWF` / `decomposeInrWF` extract the new tag-eq witness
alongside the existing payload-eq.

### Layer C — `SumRecWF` updated `run-X`

`run-inl` trace becomes (5 instructions):
```
instr-load-tag-lit 0 ∷            -- Output := TagLit 0
store-at-slot sum-slot ∷          -- slot[N]   := TagLit 0
mov-to-output ∷                    -- Output := Input1 (payload pointer)
store-at-slot (suc sum-slot) ∷     -- slot[N+1] := payload pointer
lea-slot sum-slot ∷ []             -- Output := &slot[N]
```

`run-inr` is identical with `instr-load-tag-lit 1`.

`run-case` dispatches via the new instruction. The two clauses
(meta-split on `inj₁` / `inj₂`) still exist for the *correctness*
proof, but they share a single unified trace shape:
```
case-trace = instr-case-on-tag f-dispatch-trace g-dispatch-trace
  where
    f-dispatch-trace = load-indirect-suc ∷ mov-to-input ∷ f-trace
    g-dispatch-trace = load-indirect-suc ∷ mov-to-input ∷ g-trace
```

Correctness for `(inj₁ a)`: `valid-inl-wf` gives the tag-eq
`readLoc s sum-loc ≡ just (TagLit 0)`. Combined with `rdi-eq`
(`Input1 = sum-loc`), `exec-abstract instr-case-on-tag` reduces
via the `TagLit 0` branch and runs `f-dispatch-trace`. Similarly
for `(inj₂ b)`.

### Layer D — `IRToTrace.agda`

Replace stubs:
```agda
ir-to-trace' n l (inl _) =
  let sum-slot = n
      next     = suc (suc sum-slot)
  in next , l ,
     (instr-load-tag-lit 0 ∷
      store-at-slot sum-slot ∷
      mov-to-output ∷
      store-at-slot (suc sum-slot) ∷
      lea-slot sum-slot ∷ []) ,
     []

ir-to-trace' n l (inr _) = … instr-load-tag-lit 1 …

ir-to-trace' n l (case f g) =
  let (n1 , l1 , ft , fb) = ir-to-trace' n  l  f
      (n2 , l2 , gt , gb) = ir-to-trace' n1 l1 g
      f-dispatch = load-indirect-suc ∷ mov-to-input ∷ ft
      g-dispatch = load-indirect-suc ∷ mov-to-input ∷ gt
  in n2 , l2 , (instr-case-on-tag f-dispatch g-dispatch ∷ []) , (fb ++ gb)
```

### Layer E — Per-arch `compile-abstract`

Two new instructions need lowering. Per-arch needs labels for
the conditional branch.

x86-64:
```
instr-load-tag-lit n
  → mov $n, %rax

instr-case-on-tag f-trace g-trace
  → mov (%rdi), %rax        ; load tag from *Input1
    cmp $0, %rax
    je .L_case_inl_<k>
    <compile-trace g-trace>
    jmp .L_case_end_<k>
  .L_case_inl_<k>:
    <compile-trace f-trace>
  .L_case_end_<k>:
```

The label counter `k` is unique per-case; threaded similarly to the
thunk-label counter (Plan 0.12 fix).

Same shape for x86-32 / RV64 with the appropriate cmp/branch idioms.

## Implementation order

1. **Phase 1** — `ValueLocation` + AbstractInstr extensions:
   - Add `TagLit : ℕ → ValueLocation FS`.
   - Add `instr-load-tag-lit` / `instr-case-on-tag` to AbstractInstr.
   - `exec-abstract` clauses.
   - `readLoc` / `writeLoc` / `BeforeFrontier` etc. coverage for
     `TagLit` (it's a value, not a memory location, so most should
     pass-through or be undefined-but-unused).
   - Gate: `make typecheck` + `make compiler-x86-64` green.

2. **Phase 2** — Validity refinement:
   - Add tag-eq fields to `valid-inl-wf` / `valid-inr-wf`.
   - Update `decomposeInlWF` / `decomposeInrWF`.
   - Cascade through any callers (probably just `SumRecWF`).
   - Gate: typecheck green; expect a couple `?` holes that we then
     close.

3. **Phase 3** — `SumRecWF` traces:
   - Update `run-inl`, `run-inr` traces (5-instruction form).
   - Update `run-case` to emit `instr-case-on-tag` and use the
     new tag-eq for trace-correctness.
   - Gate: typecheck green.

4. **Phase 4** — `IRToTrace.agda`:
   - Replace the three stubs with real lowerings.
   - Gate: typecheck green.

5. **Phase 5** — Per-arch lowering:
   - Add `instr-load-tag-lit` and `instr-case-on-tag` cases to
     `compile-abstract` for X86-64 (priority); X86-32 / RV64 can
     stub with `ud2` / `ebreak` for now.
   - Thread case-label counter through `Compile.agda` (already
     have thunk-label threading; reuse the mechanism or add a
     parallel counter).
   - Gate: `make compiler-x86-64` green.

6. **Phase 6** — Layer 2 tests:
   - Write `compiler/test/layer2-{inl-extract,inr-extract,case-bool}.once`.
   - Wire into `Layer2Spec.hs`.
   - Run; if exit codes are wrong, drill into the postulate hiding
     the bug per the user's methodology.

7. **Phase 7** — DirectSimulation update:
   - Update X86-64 DirectSimulation to model `instr-load-tag-lit`
     and `instr-case-on-tag`.
   - Discharge `ir-to-trace-correct-non-layer0` for sums.

- **Phase 1** ✅ DONE — `instr-load-tag-lit` added to AbstractInstr;
  `exec-abstract` clause writes `SV-Tag n` to Output. SMPrimitives
  coverage clauses mirror `instr-load-const`'s pattern.
  `instr-case-on-tag` still halts at the abstract level (deferred —
  Phase 1.5).
- **Phase 4** ✅ DONE — IRToTrace.agda inl/inr/case stubs replaced
  with real 5-instr sum-payload trace for inl/inr and
  `instr-case-on-tag` wrapping per-branch dispatch traces for case.
- **Phase 5** ✅ DONE — x86-64 codegen for `instr-load-tag-lit n`
  (mov $n, %rax) and `instr-case-on-tag f g`
  (cmpq $0, (%rdi); je .L<inl>; <g>; jmp .L<end>; .L<inl>: <f>;
  .L<end>:). `compile-trace-cnt : ℕ → AbstractTrace → ℕ × Program`
  threads case-label counter through trace; `x86-64-irToAsm` and
  `emit-thunk-body` propagate the counter for global uniqueness.
  X86-32 / RV64 stubbed with ud2 / unimp.
- **Phase 6** ✅ DONE — Frontend support via existing `destruct e of
  { Left x -> e1 ; Right y -> e2 }` surface syntax (parser already
  accepts; `RDestruct` in RawExpr; `c-e-destr` ConcreteExpr;
  Soundness.agda has sound-RDestruct). No new elaborator work
  needed for direct-annotated sums. Polymorphic categorical
  `case f g x` is a separate path (bbc-case + specCase + 150 lines
  in Elaborate.agda) — deferred since `destruct` is sufficient.
- **Phase 7** ✅ DONE — Layer2Spec.hs wires two tests:
  - destruct on inl selects Left branch (exit 42).
  - destruct on inr selects Right branch (exit 99).
  Both PASS. Layer 0 + 1 + 2 codegen tests all pass sequentially.
- **Phase 1.5** ⏸️ DEFERRED — Lift ~12 SMPrimitives lemmas
  (TraceNoHeapWrites, instr-writes-slot, InstrPreservesFrame, etc.)
  to instruction-or-sub-trace shape so `instr-case-on-tag` can be
  tag-aware at the abstract level (currently halts placeholder).
  When this lands, the `case-codegen-faithful` named postulate in
  SumRecWF.run-case can be dropped — the abstract dispatch matches
  the runtime dispatch exactly.
- **Phase 2 (validity)** ⏸️ NOT YET DONE — `valid-inl-wf` /
  `valid-inr-wf` currently carry only the payload pointer, not the
  tag. Refinement needed for the proof model to match Phase 1.5's
  tag-aware abstract semantics.

**Known gap (out of scope for this plan):** sums returned from
user-defined functions (e.g. `mkSum x = inl x : Int + Int`) don't
round-trip through destruct correctly. Function-call results go
through `apply` which wraps in a closure that breaks the
tag-at-offset-0 layout `instr-case-on-tag` expects. Tracked
separately as a layer 4+ (functions returning sums) issue.

**Runtime/proof correspondence:** Phase 1 + 4 + 5 + 6 + 7 establish
that the runtime executes case dispatch correctly for direct sum
values. The proof side (SumRecWF.run-case) still meta-dispatches;
the gap is bridged by `case-codegen-faithful` (named postulate,
visible in `make postulates`). Phase 1.5 closes the gap.

## Out of scope

- Static-sized inline payloads (per `ir-stack-layout.md` table).
  All sums are referenced via pointer for now (matches existing
  validity model). Static-sized inline as an optimisation comes
  later.
- Sum types with > 2 cases. Once doesn't have N-ary sums; binary
  `+` is the universal coproduct.
- Recursion-scheme codegen (Layer 5/6 — `In`/`Cata`/`Para`/`Out`/
  `in-ν`/`Ana`/`Hylo`/`Fuse` all stubbed). Separate plan.
- Closure-realm ABI fix (Layer 1+4 user fns). Independent of this
  plan.
