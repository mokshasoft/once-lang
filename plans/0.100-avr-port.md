# Plan 0.100 — Port Once to the AVR ATmega328P (Arduino Uno)

## 0. Why this target

The three existing targets agree on almost everything that matters to the
compiler's architecture: 32/64-bit registers, one address space, hardware
floats, an OS with syscalls, generous memory. The ATmega328P disagrees on all
of them:

| today (x86-64, x86-32, riscv64) | ATmega328P |
|---|---|
| register = word = pointer = Int | 8-bit registers, 16-bit pointers (register PAIRS X/Y/Z) |
| one address space | Harvard: flash (code, word-addressed) and SRAM are separate |
| hardware float | none |
| Linux: `_start`, syscalls, exit code | bare metal: reset vector, I/O registers, no exit |
| 64 KiB `.bss` heap | 2 KB SRAM in total (stack + heap), SRAM starts at 0x100 |

A port therefore forces the target-dependent assumptions into the open, as
explicit per-target parameters. That is the point of doing it: the compiler's
correctness story becomes more honest, not just more portable.

No maintained formal AVR ISA model is known to us (not in Sail, CompCert or
HolBA; to be confirmed by a literature search). Once does not need one: it defines
its own per-target semantics (`CCC/Target/<A>/Semantics.agda`) and proves the
correspondence against it. The trusted assumption becomes "our AVR model matches
the datasheet", checked by differential testing against simavr.

## 1. Where the assumptions live (survey, 2026-09-25)

**One width for everything.** `FrameSemantics.frame-word` (`CCC/FrameSemantics.agda`
l.118) is the slot size; `fs-numerics` (l.262) DERIVES `int-bits = 8 * frame-word`.
`StoredValue` (`CCC/Machine/SMCore.agda` l.219: `SV-Ptr | SV-Tag | SV-Lit | SV-Code`)
puts exactly one value in every cell and register; pairs and closures are 2 slots
(`CCC/IR/Stack.agda`), so a code pointer must fit a slot. `FitsInReg`
(`Type.agda` l.428) is GLOBAL: Int and Float, each "one register". There is no
separate pointer width anywhere.

**Registers are whole words.** `EngineInterface.Machine.rreg : State → Reg → ℕ`
(`Adequacy/ArchCorrectness/FlatCore/EngineInterface.agda` l.110); `FlatCore/RegRoles`
maps 7 roles (sp, clos, heap, out, in1, scratch, count) injectively to physical
registers.

**Frames are sp-relative.** `slot-addr-linear` (`base + k*frame-word`, l.131) and
`shift-base`. AVR has no sp-relative addressing: frames go through Y (or Z) with
`ldd`/`std` displacement 0–63, so frames over ~31 two-byte slots need address
arithmetic.

**Calls.** `link-claim` (EngineInterface l.120) and `CallRoom` describe where the
return address lives; AVR `call` pushes 2 bytes with post-decrement.

**Memory.** One flat `Addr = ℕ` (`Memory/MemoryLayoutSemantics.agda`); heap bumps up
from `hfront`, stack grows down to `lo` (`FlatCorrespondence` `HeapView`). Code is
ALREADY separate in the model (`pc` indexes an instruction list, code addresses
are `SV-Code LabelId`) and literals are always immediates — so Harvard is less of a
problem than it looks. Open: how code labels map to word-addressed flash
(`mov-code`, `icall`).

**Floats.** `float-format` per target (`Float/Dyadic.agda`: binary32/64), but no
opt-out: `FitsInReg Float` is global; the only per-arch gate
(`Denotation/Admissible.agda`, `AdmissibleM arch`) only range-checks Int literals.

**OS.** Every SigOp lowers to one `call-sym` (the `sigop-lowering` law,
EngineInterface l.155–159); the runtime is hand-written assembly per
`Strata/Interpretations/<I>/<M>.<arch>`, renamed by `objcopy`. Each `asmHeader`
(`Target/<A>.agda`) hardcodes `_start`, a 64 KiB `.bss` heap and `sys_exit`.

**Resource bounds** (`Adequacy/ArchCorrectness/<A>/ResourceBounds.agda`: HeapRoom,
StackRoom, CallRoom, AddrNoWrap, LitFits, …) are RELATIVE (heap frontier vs sp, vs
`modulus`); there is no absolute memory size and no whole-program stack bound.

**Cost of a target today:** ~25–29 arch-specific Agda files (~5.5k lines of
adequacy + arith) and 6 shared files with per-arch splits (`Target/Arch`, `Compile`
`archTarget`, `Adequacy/CPU`, `Adequacy/ArchCorrectness`, `Compiler`, `Certified`);
the Haskell driver (`compiler/src/Once/CLI.hs`: `parseTarget`, `assemble`, `link`,
`archImplExtension`; `Compile/Bridge.hs`) and the test harness
(`compiler/test/Backend/Common.hs`: qemu-user + exit codes).

## 2. The decisions this plan owes (settle in phase A, record as D-entries)

1. **Value width vs register width.** Keep one slot width and set `frame-word = 2`
   (16-bit Int, 16-bit pointers), modelling AVR register PAIRS as the machine's
   registers and expanding each operation into byte-wise `adc`/`sbc` sequences in the
   emitter — or split slot width from register width in the core. The first keeps
   the core intact; the second is the general answer. Measure both in phase A.
2. **`Int` width decoupled from `frame-word`?** `int-bits = 8*frame-word` is derived,
   not chosen. Whether that derivation should become a per-target parameter.
3. **Float on a float-less target.** An arch-indexed `FitsInReg` (the type system
   refuses Float), an admissibility gate, `binary16`, or soft-float behind SigOps.
4. **Bare-metal SigOps.** SigOps lower to calls into an interpretation
   (`Strata/Interpretations/Bare/*.avr` or similar) that touches I/O registers;
   `exit : Eff Int Void` becomes "halt" (`cli; sleep` / a loop).
5. **Memory budget.** The heap size becomes a target parameter (not 64 KiB), and the
   2 KB SRAM budget enters the concrete initial state, so HeapRoom/StackRoom are
   discharged against it. Whether a static whole-program stack bound is required.
6. **Staging.** Straight to AVR, or a bare-metal Cortex-M0 first (isolates "no OS"
   and "no float" from "8-bit + Harvard + 2 KB").

## 3. Phases

**P0. Probe the flagged RuntimeContract.** The survey found `Memory/RuntimeContract.agda`
puts the stack at `[0, stack-upper]` and the code at `[0, code-upper]` — both contain
address 0 — while `intervals-disjoint` is part of the postulated per-arch contract
(`CCC/Target/*/RuntimeParams.agda`), and `prog-fits : ∀ prog-len → prog-len ≤
code-upper` looks false for large `prog-len`. Typecheck `⊥` from it (a throwaway
probe). If it is inconsistent, that is a trusted-base defect on the EXISTING targets
and gets its own fix before any porting. *Gate*: a verdict, with the probe.

**A. Decide the value model** (§2.1–2.3) with measurements: what `frame-word = 2`
does to `StoredValue`, `FitsInReg`, `LitFits`, `AddrNoWrap` and the arith lowering;
what splitting slot/register width would touch. *Gate*: D-entries for §2.1–2.3.

**B. Generalise the core, targets unchanged.** Make the implicit parameters explicit
(heap size, float availability, int width if decided, bare-metal header shape),
with x86-64/x86-32/riscv64 instantiating them to today's values. *Gate*: `Certified`
green on all three; exit tests unchanged (nothing moves).

**C. AVR semantics POC.** `CCC/Target/AVR/{Syntax,Semantics}.agda` for the handful
of instructions the simplest program (`main = exit@S 0`) emits; register pairs as
the modelled registers; Y-based frames. *Gate*: the POC program runs to its halt
in the model; simavr agrees on it.

**D. Emitter + lowering + adequacy.** `AbstractToAVR`, `Emit`, `FrameInstantiation`,
the FlatCore engine instance, `ResourceBounds` against the 2 KB budget, the
`Certified` wiring. *Gate*: `Certified` green on four arches.

**E. Driver + tests.** `avr-as`/`avr-ld -mmcu=atmega328p`, vector table,
`avr-objcopy -O ihex`; a simavr harness with an exit convention (e.g. a write to a
reserved I/O address) so the exit tests run. *Gate*: the exit tests that fit the
target pass under simavr; the rest are documented as out of budget.

## 4. Risks

* The one-width model is the load-bearing assumption; §2.1 decides the size of
  the whole port.
* Word-addressed flash vs byte-addressed code labels (`icall`, `mov-code`).
* 2 KB is small enough that heap-mode closures and the linked heap stacks of
  `cata` may simply not fit realistic programs; the port may need stack-mode
  defaults or a static bound, which is a language-level question.
