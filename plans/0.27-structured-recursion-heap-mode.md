# Plan 0.27: Structured recursion in heap mode — real codegen + proofs for μ/ν schemes, trace-ready

## Do we need to define `List` (or tree/list primitives) first? — No.

`Functor` is already a **reified polynomial functor** (`Once.Type:242`):

```agda
data Functor : Set where
  K   : Type → Functor              -- constant
  Id  : Functor                     -- recursive position
  _⊕_ : Functor → Functor → Functor -- sum
  _⊗_ : Functor → Functor → Functor -- product
```

`μ-type F` / `ν-type F` are `Type`s for any `F` (`Once.Type:260`), and
the concrete inductive types are **derived instances**, already
typechecking (`Once.Type:317–325`):

```agda
NatF      = K Unit ⊕ Id                 -- Nat  = μ NatF
ListF A   = K Unit ⊕ (K A ⊗ Id)         -- List = μ (ListF A)
TreeF A   = K A ⊕ (Id ⊗ Id)             -- Tree = μ (TreeF A)
```

Every recursion-scheme IR constructor is **generic over `F`**
(`In`/`out-μ`/`Cata`/`Para`/`Out`/`in-ν`/`Ana`/`Hylo`/`Fuse`, all
`∀ {F} → WellFormedF F → …`, `Once.CCC.IR.agda:170–246`). So structured
recursion is **already typed and generic**; what is missing is the
*heap representation and execution* of a functor node `⟦ F ⟧T X`. We do
**not** add `List`/`Tree` as primitives — we implement the generic node
machinery once and pick the smallest concrete `F` as the proving
vehicle:

- **`NatF = K Unit ⊕ Id`** — the minimal μ (one nullary + one unary
  constructor). Proving vehicle; `NatCataProof.agda` already targets it.
- **`ListF A`** — the first "interesting" `F` (a `K A ⊗ Id` payload):
  exercises a constant field *and* a recursive field in one node. The
  end-to-end test program.

> Per `feedback_top_down_spec`: the spec is "correct over all of CCC +
> structured recursion." Picking `Nat`/`List` is a choice of *proving
> witness*, not a narrowing of the theorem — every lemma is stated
> `∀ {F} → WellFormedF F → …`.

## The gap (why this plan exists)

Structured recursion is **not actually compiled or verified** — the
abstract trace is a stub:

- `ir-to-trace'` emits **`[]`** for `In`/`Cata`/`Para`/`Ana`/`Hylo`/
  `Fuse` (`IRToTrace.agda:410–421`). The abstract machine never builds a
  μ-node nor folds one.
- `rec-scheme-semantic` (`RecSchemePostulates.agda:76`) is the postulate
  papering over it. Its own comment (lines 58–72) is explicit: *"the
  abstract machine model doesn't capture recursive execution. The
  abstract traces are stubs that don't actually compute recursion
  schemes."* The named exits are (A) extend the machine with recursive
  trace execution, or (B) direct structural proof.
- The **runtime** does work (Dispatcher → worklist loop code; `_start`
  bump allocator, per `project-heap-mode-layer2`), but the **verified**
  side is the stub + postulate. So the compiler is **not verified for
  the recursion schemes** — the headline target.

Consequences this plan must fix:

1. **Correctness.** "Verified over CCC + structured recursion" is vacuous
   while `Cata`/`Ana` are `[]`-stubs covered by a blanket postulate.
2. **Trace (Plan 0.24).** A SigOp inside a fold's algebra emits **no
   event** at the abstract level, because the fold isn't executed. Bridge
   1 for the recursion schemes is therefore *impossible* until execution
   is real. 0.27 is the prerequisite 0.24 declares.

## The principle (fight the definition, not the proof)

The defect is two *definitions*: the `[]`-stub abstract trace and the
blanket `rec-scheme-semantic` postulate. Fix the definitions; don't
prove around the stub.

> **Heap-mode μ-node = tagged heap record.** `⟦ F ⟧T X` lays out
> generically by recursion on `F`: `K t` → the slots of `t`; `Id` → one
> pointer slot (to a child μ-node); `_⊕_` → a tag slot + the selected
> branch's payload; `_⊗_` → concatenation of the two layouts. `In`
> allocates such a record on the heap (reusing the **existing heap
> product/sum producers** — a node is a heap pair of a tag-sum and a
> payload); `out-μ` reads it back (Lambek inverse).
>
> **`Cata`/`Para` execution = structural fold over the finite μ-value**,
> proven by induction on the μ-value — extending the existing
> `MuValidity` / `NatCataProof` / `RecTrace` machinery from "value" to
> "value + emitted events." `Ana`/`Hylo` = productive unfold, fuel-
> bounded. The worklist loop stays as the *concrete realization*,
> bridged by the existing operation-aligned `Corresponds`.

This is option **B** (direct structural proof) for the *spec/abstract*
side, with the runtime worklist loop as the concrete realization — the
existing Star-based architecture (`RecCoreWF`, `MuValidity`) is already
built for exactly this induction.

## Trace-readiness — the "right shape" requirement (load-bearing for 0.24)

Everything new in this plan must be shaped so Plan 0.24 can thread events
through it **without re-proving**:

1. **Execution returns events.** The abstract execution of a recursion
   scheme returns `(LocState , AllocState , List SigOpEvent)` (or carries
   an `evs` field in its `IRResult`), not just `(state , alloc)`. Today
   the algebra is SigOp-free so `evs ≡ []`, but the **channel exists**
   and is threaded through every sub-fold (`evs = evs-children ++
   evs-node`). This mirrors `obs`'s `List SigOpEvent × …` result shape.

2. **Visitation order is fixed and matches `obs`.** The fold visits
   children then applies the algebra (for `Cata`) in a defined
   left-to-right order; `obs`'s effectful-`Cata` case (Plan 0.24 Phase D)
   is written to the *same* order. The bridge is then one structural
   induction, not an order-reconciliation.

3. **The marker slots in without changing state semantics.** Plan
   0.24's `instr-trace-mark` is emitted at the algebra-SigOp call site
   *inside* the fold; because the fold's correctness is proven over the
   μ-value with an `evs` accumulator already threaded, adding the marker
   appends to `evs` and is identity on the state the induction reasons
   about.

4. **`WellFormedF F` carries enough to drive layout.** The node-layout
   recursion on `F` must be available in the proof (not just at runtime),
   so the per-node `ValidAtWF` obligation is discharged generically by
   induction on `F`.

State these as explicit fields/lemmas now; leave the event content empty
until 0.24 fills it. This is the concrete meaning of "add everything
necessary to get the right shape in the proofs."

## Dependencies / sub-structure

A heap μ-node is built from the **heap product and heap sum** producers:
a `Cons` cell is a heap pair `(head , tail-pointer)`; the constructor
tag is a heap sum. So `In`'s codegen composes `PairAllocWF` +
`SumInl/InrAllocWF`. Per `project-heap-mode-layer2`, those still carry
~20 `SMP.!!` semantic obligations (`*-valid-final/cont`, `*-rax-eq`,
`trace-twf`, `mem-preserved-before`, `alloc-correct`). 0.27 must either
discharge the ones `In` depends on or reuse them as black boxes with a
clear note. **Folding a sum-functor μ (e.g. `NatF`) inherently requires
tag-dispatch** — the same mechanism `case` needs — so this plan also
makes `instr-case-on-tag` dispatch (the deferred Plan 0.13.1 Phase 1.5),
since `Cata` over `K _ ⊕ _` cannot fold without it.

## Phases

### Phase A — Generic functor-node heap layout
Define `node-layout : Functor → …` (slots, which are pointers) by
recursion on `F`. Define the abstract heap representation of a `μ F`
value as a pointer to such a node. POC on `NatF`. **Gate:** layout
computes for `NatF`/`ListF`; `WellFormedF` exposes the recursion needed
by proofs.

### Phase B — `In` / `out-μ` heap codegen + Lambek validity
**Key correction (verified 2026-05-30):** the existing `run-In`
(`SumRecWF.agda:1012`) is **stack-era** — it stores its input at a stack
slot (`result-loc = AtStack …`, a 4-instr `rec-scheme-trace-4`) and
papers over validity with the blanket `In-trace-valid` postulate
(`LambekValidity.agda:166`). In clean **heap** mode `In`/`out-μ` are
**pure pointer-identity**: the F-layer node (already heap-allocated by
the heap pair/sum producers, at an `AtDynamic` loc) *is* the μ-value —
same pointer. So `In Heap`/`out-μ Heap` emit `mov-to-output` (pass the
pointer), result-loc = input-loc; **no stack slot, no copy, no
allocation in `In` itself** (the node was allocated by the layer
producers). This aligns `In` with `out-μ` (which already emits
`mov-to-output`); the current `In → []` in `IRToTrace.agda:410` is the
stub to fix.

Validity is then **real, not postulated**: the forward correspondence
`layer→μlayer` (POC-1, **landed** — see below) + `valid-μ-wf` discharges
`In`; the symmetric reverse (`μlayer→layer`) + `valid-μ-wf` inversion
discharges `out-μ`. The `BeforeFrontier` for the node comes from the
heap producer's allocation evidence (`heap-before`), so no
`sucLoc`-monotonicity lemma is needed on the heap path. **Gate:** a
concrete `Nat` value builds on the heap and `out-μ ∘ In ≡ id` (Lambek
round-trip); `In-trace-valid`/`out-μ-trace-valid` promoted from
postulate to proof for single-slot-`K` functors; `make malonzo` green.

> **POC-1 forward — LANDED (commit a61b51d9).** `layer→μlayer` in
> `LambekValidity.agda` proves `ValidAtWF {⟦F⟧T(μ G)} → μLayerValid` by
> structural induction on `WellFormedF F`: `μlayer-inl/inr/prod` share
> the exact `sucLoc` offsets + pointer chains of `valid-inl/inr/pair-wf`;
> `BeforeFrontier` threads via the parent constructors' premises; the
> `Id` case wraps via `valid-μ-wf` (with `wf-irrel`/`isbase-irrel`
> singletons). Compiles clean. This is the kernel that makes `In`
> representational-identity validity a theorem.

### Phase C — `Cata` real execution + structural proof + tag-dispatch
Make `instr-case-on-tag` **dispatch** (Plan 0.13.1 Phase 1.5 — lift the
~12 SMPrimitives lemmas to instruction-or-trace shape). Replace `Cata`'s
`[]`-stub with real node-visiting execution that returns
`(state, alloc, evs)`. Prove correct by induction on the μ-value,
generic over `F` — generalize `NatCataProof` via `RecTrace`/`MuValidity`.
**Discharge `rec-scheme-semantic` for `Cata`** (no longer a postulate).
Thread the (empty) `evs` accumulator. **Gate:** `Cata` over `Nat`
(e.g. a depth count) verified and runs; `rec-scheme-semantic` unused for
`Cata`.

### Phase D — `Para`, `Ana`/`Hylo`/`Fuse`
`Para` (paramorphism) by derivation from `Cata`. `Ana`/`Hylo` — the
productive case: fuel-bounded unfold returning `(…, evs)`; `Fuse` the
μ-anchored fusion. Discharge the remaining `RecSchemePostulates` /
`AnaWF` / `ParaWF` obligations structurally. **Gate:** all recursion
schemes verified generic over `F`; `rec-scheme-semantic` eliminated.

### Phase E — `IRTraceCorrect` / `compile-correct` bridge for the schemes
Thread the recursion-scheme constructors through `IRTraceCorrect` and
hence `compile-correct` (today it covers only id/fst/snd/terminal/initial
+ the heap pair/sum producers per `project-heap-mode-layer2`). **Gate:**
`compile-correct` holds for an IR containing `In`/`out-μ`/`Cata`.

### Phase F — End-to-end test vehicle
A `List`/`Nat` program: build a structure on the heap, `Cata` it to an
`Int`, `linux.exit` the result (e.g. `length [a,b,c]` → exit 3, or
`sum`). Build → run → exit code, exercising heap node allocation + a real
fold at runtime. If a SigOp-in-algebra program is expressible, add one to
pre-exercise the trace-`evs` channel (otherwise leave the channel proven-
empty for 0.24 to fill). **Gate:** runtime exit code matches; trace-shape
fields in place.

## Correctness statement & TCB

**Discharged here (was postulate/stub, now proven):**
- `rec-scheme-semantic` (`RecSchemePostulates.agda:76`) — replaced by
  structural induction on μ/ν, generic over `F`.
- `LambekValidity`'s per-operation postulates — proven by induction on
  `F`.
- The `[]`-stub abstract traces for `In`/`Cata`/`Para`/`Ana`/`Hylo`/
  `Fuse` — replaced by real node-allocating / node-visiting execution.

**Trusted base unchanged:** assembler + `programToText`, the ISA model,
external SigOp effects (the irreducible TCB per Plan 0.24). The bump
allocator's missing bounds check (`project-heap-mode-layer2` open #3)
remains a Layer-2 limitation, not a proof gap.

## Risk & blast radius (and the POC gates)

Per `feedback_load_bearing_lemma_poc` — POC the load-bearing claims and
separately estimate integration cost before committing the phases:

- **POC-1 (Phase A/B) — forward LANDED (commit a61b51d9).** The node
  layout is *already* formalized: `MuValidity.μLayerValid`/`μValid`
  (0 postulates) describe exactly the heap pair/sum producers' layout,
  and `ValidAtWF` already wraps it via `valid-μ-wf`. `layer→μlayer`
  proves the forward correspondence. **Reverse** (`μlayer→layer`, for
  `out-μ`) is the symmetric induction; see the `μlayer-K` limitation
  below.
- **POC-2 (Phase C, the big one):** `Cata`'s structural execution proof
  generic over `F` (generalize `NatCataProof`). This is where
  `rec-scheme-semantic` actually dies; if the induction doesn't lift from
  `Nat` to generic `F`, the phase plan is wrong.
- **Integration cost:** (a) ~20 `SMP.!!` on heap pair/sum that `In`
  depends on; (b) `instr-case-on-tag` dispatch = the ~12-lemma lift
  (Plan 0.13.1 Phase 1.5); (c) `PairAllocWF`'s construction-vs-runtime
  alloc-alignment blocker (`project-heap-mode-layer2`) if `In` routes
  through it. Budget these explicitly — they are not "fight the proof"
  shortcuts but real machine-definition completions.

Per `feedback_blast_radius_not_a_constraint`: the size is the principled
price of compiling structured recursion for real; the alternative is the
`rec-scheme-semantic` postulate indefinitely.

## Known limitation — `μlayer-K` and `K`-of-compound (documented, not a blocker)

`MuValidity.μlayer-K` stores only `BeforeFrontier alloc loc`, discarding
the `K` payload's structure. This is **mode-independent** (not a stack
artifact) and affects only the **reverse** transfer (`out-μ`, and reading
fold sub-results in `Cata`):

- **Single-slot / primitive `K`** (`Unit`/`Int`/`Float`/`Str`/`Buffer`)
  reconstructs fine — `valid-unit-wf` (no premise) and
  `valid-int/float/str/buffer-wf` (need only `BeforeFrontier`). `Id`
  positions wrap via `valid-μ-wf`. So **all planned vehicles** — `Nat`
  (`K Unit`), `List Int`/`Tree Int` (`K Int`) — and the whole Plan 0.24
  trace goal are covered with **no `μlayer-K` change**.
- **`K`-of-compound** (`base-Prod`/`base-Sum`, e.g. `List` of pairs:
  `K (Int * Int)`) cannot rebuild `valid-pair-wf`'s pointer chain from
  `BeforeFrontier` alone. The reverse transfer is **not provable** for
  these from `μlayer-K` as-is.

**Decision deferred (no blocker now):** when `K`-of-compound is needed,
the principled fix (per `feedback_consequence_form_invariants`) is to
strengthen `μlayer-K` to carry the payload's full `ValidAtWF` rather than
just `BeforeFrontier` — which ripples through `MuValidity`'s ~16
`μLayerValid` preservation lemmas + the `valid-μ-wf` wrapper. Until then,
the verified recursion schemes are stated/used over functors whose `K`
constants are single-slot, and `K`-of-compound falls through to a
narrow, documented residual (never hit by the planned vehicles).

## What this plan does **not** do
- Does not add `List`/`Tree`/`Nat` as primitive `Type`s — they stay
  derived `μ F` instances.
- Does not strengthen `μlayer-K` for `K`-of-compound (see limitation
  above) — deferred until a compound-payload functor is needed.
- Does not thread actual SigOp events through the schemes (that is Plan
  0.24 Phase D, using the `evs` channel this plan installs).
- Does not add a bump-allocator bounds check, or RiscV64/X86-32 heap
  codegen (X86-64 only, per `project-heap-mode-layer2`).
