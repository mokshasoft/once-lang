# Plan 0.119 — How a server loop is typed, and what it means

## 0. Why

A server is an unbounded loop of effectful rounds. The Spec has to say which loops are programs, what
they mean, and what a correct compiler preserves. The drafted Spec (plan 0.118) does it with a request
functor `Req` and a `request` term (D314, option D). The user rejected both: "very specific
non-categorical things … user-level code only"; a core `serve` was rejected too ("the same problem with a
new name").

This plan lists what the solution must give (§1), then three solutions, each argued against by a
devil's advocate (§2–§4), compares them (§5) and says what to try first (§6).

## 1. What we want

**Fixed (not up for discussion).**

- **P1. Static typing, subject reduction.**
- **P2. Structured recursion only** (GOAL.md, D241). No general recursion, no self-reference. A round of a
  loop is finite: it may contain folds and other finite effectful code, never another loop (an `ana` is
  never another `ana`'s coalgebra; that would lose the outer loop's productivity).

**Wanted.**

- **P3. Productivity.** Every pure computation terminates; every round of a loop is computed in finite time.
- **P4. Servers and REPLs are expressible** (GOAL.md).
- **P5. Server and REPL LIBRARIES are writable.** "A canary of the language: if you can't write a server
  library something is wrong with your abstractions." A generic `serve`, `forever`, a REPL driver; the
  receive action is a parameter and may be a composite (`recvLine = decode ∘ recvBytes`).
- **P6. A round is any finite effectful block.** A `cata` may sit inside a round; a round performs any
  number of events — so "exactly one event per round" is ruled out as well.
- **P7. Subsumption is the implicit lift** along the monad morphisms `Id ⇒ T ⇒ T∞`
  (`A -> B <: Act A B <: Eff A B`). Types are UPPER bounds — an order — and nothing else. The meaning is
  independent of the subsumption derivation (coherence: the lifts compose and commute with bind).
- **P8. `main` is declared at its principal type** and used at `Eff Unit Unit` up to `<:` (D315). The
  declared type states termination: `Unit -> Unit` terminates and emits nothing; `Act Unit Unit`
  terminates after finitely many events; `Eff Unit Unit` may run forever. The same reasoning applies to
  the round of a loop: a pure round fits by subsumption.
- **P9. Principal types are exact.** `echoOnce = writeLine ∘ readLine : Act Unit Unit`; a signature is
  the principal type (D314, D007). No guardedness in types.
- **P10. Nothing non-categorical in the Spec.** No `Req`, `request`, `serve`: those are user code.
- **P11. A categorical reader recognises the Spec** (GOAL.md): canonical objects, one meaning per
  judgment, `cata`/`ana` dual.
- **P12. Equational reasoning is valid.** Equal morphisms behave the same: fusion, unrolling, moving pure
  work between rounds. The production rate is not observed (D179).
- **P13. Correctness is the trace of observable effects** (GOAL.md), stated constructively in `--safe`
  Agda, as simply as today's `behaviour src n ≡ behaviour bin n`.
- **P14. A server blocked forever on a read is correct.** Its trace ends at the read; the rest is the world's.
- **P15. Busy-waiting is not expressible.** Waiting on a condition needs an operation, which is an event.
- **P16. Substitution holds both ways.** Replacing a name by its definition never changes acceptance
  (D243: a definition is typed once).
- **P17. The surface accepts today's texts** (D316, amended).
- **P18. No checker in the dependent-types future.** OCP-0009 §5 lists a guardedness checker among the
  mechanisms Once avoids; the kernel should need only μ, ν and their (co)recursors.
- **P19. The compiler proof stays feasible.**
- **P20. (Nice to have.) Likely bugs are caught**, e.g. a server that forgot its `read`.

## 2. Solution G — Guarded iteration

`T X = μY. X + H_Σ Y`, `T∞ X = νY. X + H_Σ Y` (the free completely iterative monad). No silent step
(D311.2): every continuing round performs at least one event. Two additions enforce that:

- a judgment `Guarded t` on core terms (every path that continues performs an operation first),
  consulted only by the loop rule;
- a type `Op X R <: Act X R` of the signature's operations, so a library can take its receive action as
  a parameter and the guard can see it.

`correct` stays as today: the first `n` events, a total function.

**Devil's advocate.**

1. Only BARE operations can be passed. `recvLine = decode ∘ recvBytes` is `Act`, not `Op`, so a line
   server library cannot take it (P5). Every further abstraction (grade polymorphism, a passed handler)
   wants another `Op`-like type.
2. `Guarded` looks inside terms; it is the one judgment that is not compositional by type, and it is
   invisible through abstraction — the reason `Op` exists.
3. Substitution holds one way only (P16): `forever act` at `Act Unit Unit -> …` is rejected although
   `forever echoOnce` written out is accepted.
4. It is a guardedness checker (P18).
5. A bare operation's principal type becomes `Op`, which ripples through the typing rules.
6. Pure `unfold` into `ν (B + Id)` builds a delay — a computation that may never produce its `B` — but
   no loop may run it: the language builds silent computations it is not allowed to execute.
7. cata/ana asymmetry (P11): `cata` takes any algebra; the loop takes only a guarded coalgebra.

**For it.** `T` and `T∞` are the least and greatest fixed points of the same functor. `correct` is
unchanged. Every loop's equation has exactly one solution. A server that forgot its `read` is rejected (P20).

## 3. Solution E — Elgot iteration

Allow silent rounds. `T∞` is the free Elgot monad on `H_Σ`: the free completely iterative monad on
`H_Σ + Id`, with finitely many silent steps identified (Goncharov–Schröder–Rauch–Piróg, "Unifying guarded
and unguarded iteration"). The loop takes any finite round (pure or `Act`, by subsumption). `behaviour`
counts ROUNDS: the events within the first `n` rounds. `correct`: every event prefix of either side is
matched by a prefix of the other, and both end the same way (return, halt, never) — weak bisimilarity.

A silent loop — a pure round given to the loop — is a NOP SERVER: a correct program whose trace is the
events so far and then nothing, never exiting. It is not busy-waiting (P15): a silent round observes
nothing, so it can never wait for anything.

**Devil's advocate.**

1. GOAL.md as written: "non-termination, non-productive streams … almost always bugs". A nop loop spins
   a core forever with nothing to observe; productive per round, not to an observer. GOAL.md must say so.
2. A server that forgot its `read` is accepted (P20). A compiler warning can recover this, outside the Spec.
3. `correct` becomes a ∀∃ statement (P13), and the compiler proof gets the stuttering problem (P19).
4. Unique solutions only for loops whose rounds perform an operation; silent loops are reasoned about
   with the Elgot laws (uniformity, dinaturality).
5. `T∞` needs an extra silent summand and a quotient: it is no longer the ν of `T`'s functor (P11).
6. Quotienting by weak bisimilarity needs countable choice to stay a monad (Chapman–Uustalu–Veltri); it
   must stay a relation, never a quotient type — in the Spec and in a future dependent kernel.

**For it.** The loop takes any coalgebra (P5, P6, P11 for morphisms). No `Op`, no `Guarded`, no `Req`.
Substitution holds both ways (P16). No checker (P18). Library lemmas lose their side conditions:
`forever act` performs `act`'s events forever, and if `act` performs none that is silence forever.
For programs that are never silent, denotations and proofs are those of solution G.

## 4. Solution R — Resumptions

Solution E built so that its two blemishes (devil's points 3 and 5) go. A round is a finite effectful
BLOCK, so the infinite object is ν OVER `T`, not ν of `T`'s functor:

```
T  X = μY. X + H_Σ Y        -- a finite block: finitely many events, then a result
T∞ X = νY. T (X + Y)        -- blocks forever: each block returns or continues
```

This is the coinductive resumption monad over `T` (Moggi; Piróg–Gibbons, "The coinductive resumption
monad") and literally GOAL.md's "the final coalgebra of `T ∘ F`", with `F = X + −`. Programs and effects
have the same shape: pure folds (μ) inside rounds inside a loop (ν); events inside blocks (`T = μ`),
blocks inside `T∞ = ν`. The loop is the PLAIN `ana` of this ν: any coalgebra `A → T (B + A)`, as `cata`
takes any algebra. A silent round is an empty block — no extra summand, no quotient in the meaning.

Observation keeps today's shape, with the possibility of never made explicit in the codomain:

```
behaviour : Program → Interp → ℕ → Delay (List Event)      -- Delay A = νY. A + Y  (Capretta)
correct   : ∀ n → behaviour src ι n ≈ behaviour bin ι n
```

`≈` is the delay monad's standard equivalence: both arrive at the same list, or neither ever arrives; the
number of steps is ignored (D179). For a program that always reaches its next event the delay is finite
and the statement is today's. For the nop server, `behaviour … 5` is "never" on both sides. `behaviour`
is the monad morphism from `T∞` into `Delay` with an event log that the Interpretation determines — the
Interpretation is a handler; and `Delay` is `T∞` for the empty signature.

Two meanings are the same when they behave the same against every Interpretation:
`m ≈ m′ = ∀ ι n → behaviour ι n m ≈ behaviour ι n m′`. Block boundaries are not observable, so unrolling
and fusion hold (P12).

**Devil's advocate.**

1. GOAL.md (as E.1): a silent loop is a correct, useless program; the compiler warns when it emits a
   round that performs no event. One sentence in GOAL.md.
2. A forgotten `read` is caught only by that warning (P20), not by the type checker.
3. Equality of ν-elements is too fine — it sees block boundaries — so the Spec's equivalence is the
   observational one above, not structural bisimilarity. Proofs about programs work up to it.
4. Unique solutions only for loops whose rounds perform an operation (as E.4).
5. The compiler proof still relates steps on two sides; the target is the standard `≈` on `Delay`, where
   the stuttering technique is textbook (P19), but it is new work in our proofs.
6. μ inside ν in `--safe` Agda: `bind` and the loop's meaning recurse corecursively UNDER `T`'s map,
   which the guardedness checker may reject. Unverified (§6, step 1).

**For it.** Everything E has, plus: objects are canonical (μ inside ν, P11); no quotient in the meaning;
`correct` keeps its one-line shape (P13); the observation lives in the same structure as the program.

## 5. Comparison

| | G — Guarded iteration | E — Elgot iteration | R — Resumptions |
|---|---|---|---|
| P5 libraries (composite receive) | ❌ bare operations only | ✅ | ✅ |
| P6 any finite block per round | ✅ if it calls on every continuing path | ✅ | ✅ |
| P9 exact principal types | ✅ (bare operations become `Op`) | ✅ | ✅ |
| P10 no extra constructs | ❌ `Op`, `Guarded` | ✅ | ✅ |
| P11 objects | ✅ μ/ν of one functor | ❌ extra summand, quotient | ✅ μ inside ν |
| P11 cata/ana dual | ❌ guarded coalgebras only | ✅ | ✅ |
| P12 equations | ✅ | ✅ up to silent steps | ✅ up to observation |
| P13 `correct` shape | ✅ unchanged | ❌ ∀∃ | ✅ unchanged, codomain `Delay` |
| P15 no busy-wait | ✅ | ✅ (silent ≠ waiting) | ✅ (silent ≠ waiting) |
| P16 substitution both ways | ❌ | ✅ | ✅ |
| P18 no checker | ❌ | ✅ | ✅ |
| P19 compiler proof | ✅ as today | ❌ stuttering, ∀∃ | 🟡 stuttering into `Delay`'s `≈` |
| P20 forgotten `read` | ✅ rejected | 🟡 warning | 🟡 warning |
| GOAL.md text | ✅ | ❌ one sentence | ❌ one sentence |

Already rejected, for the record: `Req`/`request` (option D) and a core `serve` (user-level);
guardedness as a grade, `eff⁺`/`Act⁺`/interval grades (an ideal encoded as a point of the order: no
meet, and it breaks P9); a dedicated round former; guard checking at call sites (breaks D243, D314);
whole-program guard checking (no modularity, still inexact, needs a normaliser in the Spec); observing
rounds as ticks (breaks P12, binds the compiler to the round structure); "exactly one event per round"
(breaks P6).
