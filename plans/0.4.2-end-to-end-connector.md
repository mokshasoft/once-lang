# Plan 0.4.2: End-to-End Frontend ↔ Backend Connector

## Context

Plans 0.3 and 0.4 cover frontend correctness. Each target (X86-64 /
X86-32 / RiscV64) has a backend `compile-correct` theorem. These two
sides are **not composed** into a single `Surface → machine state`
theorem — five structural gaps prevent composition.

This plan closes those gaps so that, for any accepted source program
`p` and input `x`, we can state and prove

```
exec (compile p) (encode x) ≡ encode (evalSurface p x)
```

modulo the specific target's runtime contract.

## Scope

In scope:
- `formal/Once/Semantics/` consolidation (the `eval′` vs `eval primSem`
  split).
- `formal/Once/Compile.agda` + `formal/Once/Compile/Correct.agda` —
  align the actual compile path with the proved pipeline.
- `formal/Once/Target/*.agda` + `formal/Once/CCC/Target/*/Emit.agda` —
  the final `programToText` step.
- `formal/Once/Compile/EndToEnd.agda` (to be created) — the composed
  theorem.

Out of scope:
- Per-target postulate discharge (`runtime`, `frame-ops`, `primSem`,
  `escape-survives`, `prim-proof` in `EntryPointCCC.agda`) — those
  belong to layer-specific plans (0.2.4 Layer 0, 0.2.7 Layer 1, etc.).
  0.4.2 treats them as assumed parameters of the composed theorem, to
  be discharged independently per layer/target.

## The Gaps

### C0 — Raw-source semantics + tcInfer behavioral preservation (NEW, 2026-04-30)

**Discovered while finishing T0 (Plan 0.4 globalized soundness).**
The current `tcInfer-sound` says
```
tcInfer ctx e ≡ success A Ψ eE d f  ⟹  ctx ⊢ e ∶ A ⨾ Ψ
```
The judgment relation `_⊢_∶_⨾_` mentions `(ctx, e, A, Ψ)` — type and
usage — but **not** the produced `Surface.Expr eE`. Two valid
elaborations of the same source with different `eE` shapes (e.g.
`id arg` vs `id (id arg)`) both pass soundness, even though they
compute differently.

For end-to-end correctness this means the chain starts one link too
late. `compile-correct-surface` (C4) currently composes:
```
evalSurface p x  ≡  eval' (elaborate p) x  ≡  ...  ≡  exec ...
```
The **leftmost** term `evalSurface p x` *is the typechecker's
chosen `eE`'s eval*, not "the source's intended meaning". Without
an external definition of source semantics, the typechecker is its
own oracle and a buggy elaboration is invisible.

**Goal**: define `evalRaw : RawExpr → ⟦Result⟧` (a relational or
small denotational semantics over `RawExpr` directly, independent
of the typechecker), and prove

```agda
tcInfer-preserves-meaning :
  ∀ (ctx : NamedCtx) (e : RawExpr) {A Ψ eE d f}
  → tcInfer ctx e ≡ success A Ψ eE d f
  → evalRaw e ≡ evalSurface eE
```

After C0, a buggy elaborator that returns the right type/usage but
wrong IR shape breaks `tcInfer-preserves-meaning` because
`evalSurface eE'` ≠ `evalRaw e` for the wrong `eE'`.

**Strategy**:
1. **Define `evalRaw`** as a small functional / relational semantics
   on `RawExpr`. Mirror `evalSurface`'s shape but operate on
   `RawExpr` directly. RVar lookup via context, RApp via β-reduction
   on the result, etc. ~150-300 lines.
2. **State and prove `tcInfer-preserves-meaning`** by mutual induction
   on `RawExpr` (mirroring T0's `infer-sound`/`check-sound` shape).
   Each case shows that the elaborator's chosen `eE` evaluates to
   the same value as `evalRaw e`. ~400-600 lines.
3. **Wire into `VerifiedTypeChecker`** as a record field, so the
   build enforces the property.

**Relationship to T0 (Plan 0.4)**: T0 proves type/usage soundness
(value-independent). C0 proves behavioral soundness (value-tracking).
They're SIBLINGS — both about typechecker correctness, different
properties. T0's structural work (global theorem dispatching to
per-shape lemmas, bridge lemmas for `classifyAppHeadView`) is
reusable for C0; the per-shape behavioral lemmas have the same
case-split structure. Recommended: finish T0's structural work
first (small, well-bounded, supports C0), then build C0 on top.

**Alternative consolidation**: instead of two theorems (T0 type/usage
+ C0 behavioral), strengthen the JUDGMENT to track `eE`:
`ctx ⊢ e ⤳ eE ∶ A ⨾ Ψ`. Then a single soundness theorem catches
both classes of bug. Cleaner spec, but bigger spec change. Defer
the call until after T0's current frame is in place.

**Entry cost**: ~600-1000 lines (evalRaw definition + behavioral
soundness proofs for all RawExpr shapes).

**Why it goes first in the new ordering**: without C0 the composed
end-to-end theorem (C4) starts from `evalSurface` rather than from
the source. The user's question was sharp: "we keep missing the
ball" — C0 closes the leftmost link of the chain.

### C1 — Semantics consolidation (LARGEST, prerequisite)

**Current state**: two denotational semantics exist for the same IR:

| Module | `⟦ A ⇒ B ⟧` | `⟦ Int ⟧` | Used by |
|---|---|---|---|
| `Once.Semantics.IR.eval′` | `Closure` record with `env-addr : Word` | `ℤ` | Frontend correctness (elaborate, desugar, optimize, escape, fusion, `compile-preserves-semantics`) |
| `Once.CCC.Eval.eval primSem` | plain Agda functions `⟦A⟧ → ⟦B⟧` | `ℕ` | Backend `compile-correct` per target |

These are incompatible. `compile-preserves-semantics` cannot compose
with `compile-correct` because the middle `⟦_⟧` doesn't match.

**Goal**: one portable denotational semantics. Proposed architecture
from `docs/proposals/semantics-consolidation-plan.md` (2026-03-18):

```
Once.Semantics  (THE portable denotational semantics, no postulates)
├── ⟦_⟧ : Type → Set                -- plain functions
├── PrimSem record                  -- parameterized primitives
├── eval : PrimSem → IR A B → ⟦ A ⟧ → ⟦ B ⟧
└── Semantic laws

Once.Backend.Encoding (encoding for backends, separate module)
├── ⟦_⟧ₑ : Type → Set               -- with Closure records
├── encode / decode
└── encode-* postulates or theorems
```

**Strategy**:
1. Consolidate `Once.Sem` + `Once.SemanticBase` + `Once.Semantics` +
   `Once.CCC.Eval` into a single `Once.Semantics` using plain-function
   interpretation.
2. Move memory-layout concerns (`Closure`, `env-addr`, `encode-*`)
   into `Once.Backend.Encoding`.
3. Rewire all frontend correctness proofs to the new `Once.Semantics`
   (they currently use `Once.Semantics.IR.eval′`).
4. Rewire all backend correctness proofs (they currently use
   `Once.CCC.Eval.eval primSem`) — their signature changes minimally
   since `eval primSem` → `eval primSem` under the new module name.
5. Where the backend genuinely needs the encoding (closures stored as
   `Word` addresses), invoke `Once.Backend.Encoding` explicitly.

**Entry cost**: ~800-1500 lines across ~30 files. Mostly import
rewrites + a few theorem signature changes.

**Why it's largest**: touches every correctness proof in the
codebase; high blast radius. Worth a separate session / subplan.

### C2 — Pipeline-path mismatch

**Current state**: `compileFunBody` in `Once.Compile.agda:124` runs
```
Expr → elaborate → IR → optimize → IR
```
skipping `desugar` and `escape`. Meanwhile `compile-preserves-semantics`
in `Compile/Correct.agda:61` proves correctness of
```
SurfaceIR → desugar → IR → optimize → IR → escape → IR
```
— a **different** pipeline. The PROOF covers a pipeline the CODE
doesn't run.

**Root cause**: `desugar` + `SurfaceIR` were introduced for a
two-stage IR (D035: MAlonzo extraction) that's been partially
superseded by the direct `Expr → IR` elaborator. One branch is
live; the other is proved.

**Goal**: either (a) the active compile path applies the proved
pipeline (call `escape` after `optimize`), or (b) the proved
pipeline targets the active path (drop `desugar`, prove
`optimize-correct` + `escape-correct` composed with
`elaborate-correct` instead).

**Strategy**: option (b) is cleaner — `desugar` may be dead. Audit
whether `SurfaceIR` has any active producer besides the unused
`pipeline` function. If dead, delete. Then add `escape` to
`compileFunBody`, prove a `compile-preserves-semantics` over
`escape ∘ optimize ∘ elaborate`.

**Entry cost**: ~50-200 lines plus dead-code cleanup if `SurfaceIR`
goes away.

**Dependency**: C1 first (the proof statement changes phrasing once
semantics is consolidated).

### C3 — `programToText` is unproven

**Current state**: `x86-64-irToAsm ir = programToText (compile-ir ir)`.
`compile-ir : IR → Program` has a correctness theorem
(`compile-correct`). `programToText : Program → String` has no
theorem — it's a raw pretty-printer to assembly text.

**What could fail**: a bug in operand formatting (wrong operand
order), register name rendering (`%rax` vs `rax`), instruction
encoding (missing prefix), or immediate printing (signed vs
unsigned) would slip through every proof above.

**Goal**: either
- (a) Prove `programToText` injective / invertible: `∃ parser,
  parser (programToText p) ≡ just p` — an assembler round-trip.
- (b) Prove that assembly-level execution of `programToText p`
  matches `Program`-level execution of `p` via a formal
  assembler semantics.

Option (a) is lighter. Option (b) is the "real" fix but requires
an assembly semantics model which is out of scope today.

**Strategy**: land option (a). Define `parseAsm : String → Maybe
Program` (inverse of `programToText`). Prove round-trip. This
catches formatting bugs without needing an assembly-level semantic
model.

**Entry cost**: ~500-1000 lines (symmetric to the grammar /
pretty-printer work in plan 0.3's G1).

**Scope note**: per target. Doing it once for x86-64 establishes
the pattern; RISC-V and x86-32 would mirror.

### C4 — Composed end-to-end theorem

**Current state**: building blocks exist but never composed:
- `elaborate-correct`: `evalSurface ρ e ≡ eval′ (elaborate e) _`
- `optimize-correct`: `eval′ (optimize f) x ≡ eval′ f x`
- `escape-correct`: `eval′ (escape f) x ≡ eval′ f x`
- target `compile-correct`: `Represents (eval primSem ir x) ...`

No `compile-correct-surface : evalSurface p x ≡ Represents ... (exec
...)`. The old `EndToEnd.agda` that did this was lost pre-5fac68bb
(per the `EntryPointCCC.agda:20` historical note).

**Goal**: one named theorem, something like
```agda
compile-correct-surface :
  ∀ (p : Expr ∅ _ (Eff Unit A)) (input-state : MachineState)
  → exec (compile-all p) input-state
    ≡ encode (evalSurface ε p) in final state
```
(exact phrasing depends on C1 / C3 outcomes).

**Strategy**: trivial composition after C1, C2, C3. `trans` /
`cong` chain through the sub-theorems.

**Entry cost**: ~50-100 lines once prerequisites land.

**Dependency**: C1, C2, C3 all.

---

### C5 — Fusion integration

**Current state**: `Once.Fusion.fusion` + `fusion-correct` exist.
`Once.Compile.compileFunBody` does NOT call `fusion`. Users who want
deforestation have to invoke `fusion` manually; if they do,
`compile-preserves-semantics` doesn't cover it.

**Goal**: either (a) wire `fusion` into the main compile path with
`fusion-correct` added to the chain, or (b) delete `Fusion.agda` +
`Fusion/Correct.agda` as dead code.

**Strategy**: decide based on whether fusion has value at the
default optimization level. If it's fire-and-forget (no performance
regression on non-deforestable programs), (a). Otherwise (b).

**Entry cost**: (a) ~100 lines; (b) ~0, just deletion.

**Dependency**: none. Can land independently of C1-C4.

## Phase Ordering

**Updated 2026-04-30** — added C0 (Raw-source semantics +
typechecker behavioral preservation). C0 is prerequisite for C4
to actually start the chain at "source meaning".

1. **C5** first (tiny; clears one gap and clarifies whether
   Fusion.agda is in or out).
2. **Plan 0.4 T0 finish** — global type/usage soundness
   (`tcInfer-sound`, `tcCheck-sound`). Currently in progress on
   branch `plan-0.4-T1`; 22/26 cases proven, 4 RApp-related gaps
   remain. T0's dispatch infrastructure (global theorem +
   bridge lemmas) is reused by C0.
3. **C0** — define `evalRaw` and prove `tcInfer-preserves-meaning`.
   Closes the leftmost link of the chain.
4. **C1** (semantics consolidation — touches everything downstream).
   The heaviest single item. Budget 1-2 sessions.
5. **C2** (align main compile path with proved pipeline). Small
   after C1 lands.
6. **C3** (programToText round-trip). Can be parallelized with C2.
7. **C4** (composed theorem). Small, last. Depends on C0, C1, C2, C3.

**Done condition** (the loop terminates here):
`compile-correct-end-to-end` typechecks against `evalRaw` with only
named, audit-visible trusted-base axioms (CPU model,
assembler/linker, MAlonzo extraction, `extensionality`). The list
of axioms IS the trust budget. Everything else is proven.

## Expected Outcome

After 0.4.2:

- **One CompCert-style end-to-end correctness theorem** of the form
  ```agda
  end-to-end-correct :
    ∀ source binary
    → compile source ≡ just binary
    → ∀ inputs → executeRaw source inputs ≡ executeBinary binary inputs
  ```
  connecting *the source's intended meaning* (via `evalRaw`) to
  *what the CPU actually does* with the produced bytes — with no
  unverified link in between.
- **One denotational semantics** used uniformly across frontend
  and backend.
- The main compile path and the proved pipeline are the same code.
- The final `IR → assembly text` step has a formal round-trip
  guarantee (modulo assembly semantics, which is deferred).
- **A finite, named, audit-visible postulate set** as the trust
  budget. Every link not on that list is proven.

Combined with 0.4 (frontend completeness) and layer plans (backend
postulate discharge per target + layer), the result is a compiler
where every accepted program provably compiles to assembly whose
execution matches the source semantics — and the verification
loop demonstrably terminates: `end-to-end-correct` typechecks.

## Deferred Items

- **Assembly-level semantic model** (option (b) of C3). Would close
  C3 more fully but requires modeling the x86-64 ISA at Agda level.
  Out of scope.
- **Per-target postulate discharge** (`runtime`, `frame-ops`,
  `primSem`, `escape-survives`, `prim-proof` in
  `EntryPointCCC.agda`). These are layer-specific; belongs to
  0.2.4 (Layer 0) and successors.
- **MAlonzo-extracted code correctness**. The Haskell generated by
  MAlonzo is trusted to preserve Agda's semantics. Out of formal
  scope.

## Risks & Open Questions

1. **C1 blast radius**: every correctness proof depends on
   `Once.Semantics.IR.eval′`. A mid-consolidation break could
   regress dozens of theorems simultaneously. Mitigation: consolidate
   module-by-module, commit per module, keep old module as a
   re-export shim until the last consumer migrates.
2. **C2 option (a) vs (b)**: deleting `SurfaceIR` is destructive if
   any legitimate consumer exists. Audit before acting.
3. **C3 option (a) vs (b)**: a full assembler semantic model (option
   b) is out of scope but arguably the "real" fix. The round-trip
   (option a) catches pretty-printing bugs but not semantic bugs in
   the instruction encoding.
4. **Nondeterminism in composed proof**: if C1 results in a
   different eval function signature, every theorem's type changes.
   Expect a large diff touching most correctness files.

## Non-Goals

- Changing the CCC IR datatype or its optimizations.
- Reworking the target architectures.
- Adding new language features.
- Closing layer-specific postulate gaps (those are layer plans).
