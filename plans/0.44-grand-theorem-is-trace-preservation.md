# Plan 0.44 — The grand theorem IS SigOp-trace preservation (definition-first, top-down)

> **One sentence.** Redefine the apex observable to be the SigOp trace, commit
> *only* that definition change so the build breaks, and then drive the repair
> strictly top-down — reconnecting the pieces we already have until the build is
> green again — so that "correct" finally *means* what it must mean and we can
> never again slip into a middle-out proof.

## Why this plan exists (the mistake we are correcting)

Correctness for Once was *redefined* to be trace-shaped already — `obs`
(Plan 0.24), the `IRObsCorrect`/`MachineRefinesObs` encoding (Plan 0.36). But
the redefinition was applied **at the wrong altitude**: it landed at the cata
leaf (`IRObsCorrectFlat`, an island consumed only by cata helpers) while the
**apex** — `Once.Verified.Compile.correct`, via `compile-correct-flat` — stayed
**value-shaped** (`ValidAtWF` headline, `StraightIR` gate) and the **observable
stayed `Behavior = Maybe ℕ`** (an exit code). So we kept building `value-realized`
*under* an apex that still means the old, wrong thing. That is middle-out, and it
is the same shifting-definition disease Plan 0.36 was written to kill — applied,
ironically, to 0.36 itself.

This plan fixes the altitude: **change the definition at the top, first, alone.**

## What correctness IS (from first principles, not from the machinery)

A Once program is `main : Eff Unit Unit`. **It returns nothing.** The only thing
observable is the ordered sequence of SigOp invocations it makes — name +
arguments, in order. There is no value channel and no final-state channel.

- **Programs do not produce an "exit code."** `linux.exit N` is just a SigOp,
  like `linux.write` or `arith.add.int`; `N` is the *argument* of that call,
  an event argument in the trace. "Exit code" is *Linux's interpretation* of that
  argument — outside the compiler's concern (`Behavior.agda`'s own boundary:
  the compiler proves the *same SigOp calls*; what they *do* is the
  interpretation's job). So **no `exitCodeOf`, no `Maybe ℕ`** in the spec.
- **Values / states are internal.** `ValidAtWF`, `CompiledCorr`, register and
  heap contents are never observable, so they can never *be* correctness — only
  *devices* used to prove the trace matches. `ValidAtWF` survives solely as the
  internal "the value the next SigOp reads is right" lemma.
- **Full generality from line one.** Effectful algebras, arbitrary functors, and
  **non-terminating programs (server loops, `Ana`)** are all in scope. A value
  theorem *cannot even state* correctness of a server loop (no final state). The
  trace is represented step-indexed — a possibly-infinite trace = its family of
  finite prefixes (Plan 0.24's take-lemma shape) — so `∞` is expressible without
  coinduction.

> **Correctness = the compiled program, run on the real CPU, makes exactly the
> SigOp-call sequence the source denotes.**

## The redefinition (the only thing Phase 1 commits)

In `Once.Verified.Behavior` (and the immediate `⟦_⟧` / `exec` retypes):

```agda
-- WAS:  Behavior = Maybe ℕ            -- the exit code (a value — wrong frame)
-- NOW:  the SigOp trace, STEP-INDEXED — the finite prefix observed within n steps.
Behavior : Set
Behavior = ℕ → List SigOpEvent
```

**Why step-indexed, not a coinductive `Colist`.** A coinductive trace needs a
*productive monadic bind* to sequence effects; that is not definable under plain
`--guardedness`, and would force `--sized-types` (rejected — has bitten this
project before). Representing a (possibly infinite) trace as **the family of its
finite prefixes** and proving correctness **"up to an arbitrary `n`"** reduces
everything to ordinary induction on `n` (the take-lemma) — no co-data, no bind,
no funext. This is the settled Plan 0.24 choice; this plan keeps it.

- `⟦_⟧ : Source → Behavior` — the source's intended trace (`λ n → proj₁ (obs n …)`;
  `obs` is *already* `ℕ`-indexed, so this is a natural retype, not a rebuild).
- `exec : Arch → List Byte → Behavior` (`ArchSemantics.exec-bytes`) — the target's
  emitted trace as a function of observation depth.
- `Once.Verified.Compile.correct` is stated **pointwise in `n`** (avoids funext):
  ```agda
  correct : ∀ (arch) (src) (bytes) → compile arch src ≡ just bytes
          → ∀ (n : ℕ) → exec arch bytes n ≡ ⟦ src ⟧ n
  ```
  i.e. for every observation depth the target's SigOp-trace prefix equals the
  source's. This is the "correct up to arbitrary `n`" form.
- **Delete** `Maybe ℕ` / `exitCodeOf` / any exit-code projection from the spec.

Nothing else changes in this commit. The build breaks. **That is the point** —
the breakage is the typechecker handing us the exact, honest work-list, and
committing it alone makes backsliding into middle-out impossible.

## What the redefinition EXPOSES (the work-list, discovered top-down)

These are *forced by the spec*, not chosen — each surfaces as a typecheck failure
once `Behavior` changes:

1. **The CPU model must PRODUCE a trace.** Today `ArchSemantics.exec-bytes`
   returns `Maybe ℕ`, and the x86 `execInstr … syscall` / `call-sym` is *modeled
   as halt* — the target emits no event stream and stops at the first SigOp.
   Under the spec the target semantics must *record the SigOp invocation and
   continue* (Plan 0.24's `instr-trace-mark` / emit-and-continue idea, now
   demanded top-down). This is the deepest forced change.
2. **`StraightIR` deletion** on `compile-correct-flat` — loops/catas are in the
   apex; `flat-sim` is already a general `∀ fuel` induction, so it is the device,
   not a blocker.
3. **Two internal bridges, composed to discharge the apex:**
   - *source ↔ flat* — `flat-events (exec-flat …) ≡ obs …` (the abstract machine
     emits the source trace). Already the shape of `MachineRefinesObs.traces-agree`.
   - *flat ↔ target* — the real CPU's SigOp trace equals the flat machine's
     (`flat-events`), ridden across by `flat-sim`/`CompiledCorr` (the markers are
     state-identity, so the trace is preserved field-by-field).
4. **`value-realized` / `ValidAtWF` demoted** from conclusion to internal device.

## Goal & phases (strictly top-down; no middle-out)

The plan's goal is **to close the connection** — connect the pieces that already
exist so the redefined apex is provable for the fragment we *already* claimed
"proven correct" (straight-line / Layer-0), and then **link cata** into the same
apex. It is **not** to discharge cata's deep internals (that is the paused
Plan 0.36 work, resumed only *after* the connection is proven to close).

- **Phase 1 — Break the build (this is the commit the discipline rests on).**
  Commit *only* the `Behavior`/`⟦_⟧`/`exec` redefinition + the `correct`
  retype + deletion of `Maybe ℕ`/`exitCodeOf`. Nothing else. Build is red.
  The set of red modules = the authoritative top-down work-list.

- **Phase 2 — Reconnect what we already "have."** Follow the typechecker down,
  using only pieces that already exist (`obs`, `flat-events`, `exec-flat`,
  `flat-sim`/`CompiledCorr`, the value-shaped `compile-correct` demoted to a
  device), to re-establish trace-preservation for the **straight-line /
  terminating fragment** we currently cover. Where a genuinely-new device is
  forced (the trace-producing CPU model, item 1), introduce it as a *named*
  obligation — never a catchall, never a parallel structure. Green for the
  fragment ⇒ the architecture is proven to close.

- **Phase 3 — Link cata.** Route `Cata` through the same apex: the existing
  `cata-correct` (`IRObsCorrectFlat`, currently an island) becomes the named hole
  *under the redefined top*, with `traces-agree`/`value-realized` plugging into
  the source↔flat bridge. Only here does the paused 0.36 cata work become safe to
  resume — against a definition that will not move under it again.

## Discipline (the anti-middle-out contract)

- **Definition first, alone.** Phase 1 commits the spec change and nothing else.
- **Follow the typechecker.** The red modules dictate order; we do not pre-build
  devices on a hunch (the error that produced `IRObsCorrectFlat`-as-island).
- **No parallel structures.** One apex, one trace observable; every module is
  consumed by the theorem above it; obligations are named/visible, never sinks.
- **Value is internal-only.** `ValidAtWF` may appear as a device; it may never be
  a conclusion of any correctness statement.
- **Full generality.** Step-indexed traces, effectful algebras, non-terminating
  programs — defined once, at the top, never narrowed-then-widened.

## Non-goals

- Discharging `cata-correct`'s internals (`value-realized` machine-state
  induction, `build-layer` validity) — paused (Plan 0.36), resumed post-Phase-3.
- The effectful-cata point-free extraction (`extract-morph-eff`) — Plan 0.43.
- A full coinductive trace semantics — step-indexed prefixes are the chosen,
  `--safe`-compatible representation (Plan 0.24, settled).
