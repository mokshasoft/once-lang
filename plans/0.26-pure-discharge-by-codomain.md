# Plan 0.26: Discharge Pure-SigOp postulates by codomain — primitive `B` becomes proof-free

## The gap (why this plan exists)

Plan 0.25 reduced the SigOp-machine postulate set from three blanket axioms to two **Pure-confined** ones:

- `pure-sigop-output : ∀ {A B} → SigOpInfo A B → LocState FS → StoredValue FS`
- `pure-sigop-respects-semM : ∀ {A B} (si : SigOpInfo A B) … → ∃ mOut, result-loc, ValidAtWF mOut alloc (semM si x) result-loc post-state`

They live inside CCC (in `SMCore` and `IRTraceCorrect` respectively) and fire for any SigOp with `effect = Pure` — that is, for every actually-running Layer-0 Pure SigOp (`arith.{add,sub,mul,neg,div,mod,lt,le,gt,ge,eq,ne}.int`, `lit.int.<n>`, `str.lit.<s>`, `arith.block.<digest>`).

A first instinct is to refine `EffectShape` with a `PurePrim` constructor carrying a `PrimitiveCodomain B` proof. **That's wrong.** It leaks a CCC-internal property (whether `B`'s `ValidAtWF` is location-only) into the producer contract, and conflates "observable effect shape" (`Pure | Emits | Halts`) with "proof-tractability tag" — adding constructors that differ only in what proofs work is fighting the proof, not the definition.

## The principle

> The producer's `EffectShape` says **what** the SigOp does (semantic shape). Whether CCC can mechanically discharge `respects-semM` for that SigOp is **CCC-internal**, dispatching on `B`'s structure. The two are orthogonal; the dispatch lives entirely inside CCC.

## Why primitive `B` discharges trivially

`Once.CCC.Machine.ClosureWellFormed:217–239` defines `ValidAtWF` for the primitive types as **location-only**:

```agda
valid-int-wf    : ∀ {m} {n : ⟦Int⟧}    … → BeforeFrontier alloc loc → ValidAtWF m alloc {Int}    n loc s
valid-float-wf  : ∀ {m} {x : ⟦Float⟧}  … → BeforeFrontier alloc loc → ValidAtWF m alloc {Float}  x loc s
valid-str-wf    : ∀ {m} {x : ⟦Str⟧}    … → BeforeFrontier alloc loc → ValidAtWF m alloc {Str}    x loc s
valid-buffer-wf : ∀ {m} {x : ⟦Buffer⟧} … → BeforeFrontier alloc loc → ValidAtWF m alloc {Buffer} x loc s
valid-unit-wf   : ∀ {m alloc loc s}          →                          ValidAtWF m alloc {Unit}  tt loc s
```

**The value `n`/`x`/`tt` is unconstrained.** The predicate at the abstract level says only "this is a well-formed primitive location" — value content lives at the per-arch concrete level (via the Simulation lemma). So for any Pure SigOp with primitive codomain, picking `result-loc := input-loc` (which is `BeforeFrontier alloc input-loc` by the caller's hypothesis) and applying `valid-{prim}-wf` discharges `respects-semM` regardless of what's in `Output`.

This is exactly the same structural pattern Plan 0.25 used for `Halts`/`Emits` (`valid-unit-wf` via the `B ≡ Unit` coherence). It generalises to **every primitive codomain**.

## Design

**No producer-side change. No `EffectShape` change.** The dispatch on `B` happens internally.

### `SMCore.pure-sigop-output` becomes a `B`-dispatching definition

```agda
pure-sigop-output : ∀ {A B} → SigOpInfo A B → LocState FS → StoredValue FS
pure-sigop-output {A} {Int}    _ _  = unit-storedvalue
pure-sigop-output {A} {Float}  _ _  = unit-storedvalue
pure-sigop-output {A} {Unit}   _ _  = unit-storedvalue
pure-sigop-output {A} {Str}    _ _  = unit-storedvalue
pure-sigop-output {A} {Buffer} _ _  = unit-storedvalue
pure-sigop-output {A} {B}      si s = structured-pure-sigop-output si s   -- catch-all for compound B

postulate
  -- Narrower: only for compound-codomain Pure SigOps.
  structured-pure-sigop-output : ∀ {A B} → SigOpInfo A B → LocState FS → StoredValue FS
```

Content of the primitive cases is irrelevant for the abstract-level discharge (`ValidAtWF` doesn't read it); `unit-storedvalue` is just a canonical placeholder. The concrete machine's actual primitive value is established by the per-arch Simulation lemma, not by this.

### `IRTraceCorrect.pure-sigop-respects-semM` becomes a `B`-dispatching definition

```agda
pure-sigop-respects-semM : … (signature unchanged)
pure-sigop-respects-semM {A} {Int}    si … before _ _ = _ , input-loc , valid-int-wf    before
pure-sigop-respects-semM {A} {Float}  si … before _ _ = _ , input-loc , valid-float-wf  before
pure-sigop-respects-semM {A} {Unit}   si …      _ _ = _ , input-loc , valid-unit-wf
pure-sigop-respects-semM {A} {Str}    si … before _ _ = _ , input-loc , valid-str-wf    before
pure-sigop-respects-semM {A} {Buffer} si … before _ _ = _ , input-loc , valid-buffer-wf before
pure-sigop-respects-semM {A} {B}      si … = structured-pure-sigop-respects-semM si …

postulate
  structured-pure-sigop-respects-semM :
    ∀ {A B} (si : SigOpInfo A B) … → ∃ mOut, result-loc,
      ValidAtWF mOut alloc (semM si x) result-loc
        (mkLocState (writeReg … (structured-pure-sigop-output si s))
                    (stackMem s) (heapMem s)
                    (exec-sigop-halts-of Pure si s))
```

The catch-all `{B}` clause fires only when `B` is a compound type (Sum/Pair/μ/ν/→). Layer-0 sums (`Unit + Unit` from comparisons) hit it; everything else discharges.

## Phases

### Phase A — `SMCore`: case-split `pure-sigop-output` on `B`
- Promote `pure-sigop-output` from postulate to definition with primitive-`B` clauses + structured catch-all.
- Add `structured-pure-sigop-output` postulate (narrower).
- **Exit gate:** `SMCore` typechecks; existing IR tests still pass (the change is value-content-only, and abstract `ValidAtWF` for primitives doesn't read content).

### Phase B — `IRTraceCorrect`: case-split `pure-sigop-respects-semM` on `B`
- Export `valid-int-wf`, `valid-float-wf`, `valid-str-wf`, `valid-buffer-wf` from `ClosureWellFormedDef` (add to `using` list).
- Promote `pure-sigop-respects-semM` from postulate to definition with primitive-`B` clauses + structured catch-all.
- Add `structured-pure-sigop-respects-semM` postulate (narrower; same shape but only fires for compound `B`).
- **Exit gate:** `IRTraceCorrect` typechecks (via `make malonzo`).

### Phase C — Verify
- `make malonzo` green.
- All 3 arith runtime tests pass (`arith-simple` → 13, `arith-lambda-1` → 10, `arith-lambda-2` → 42).
- `Once.Verified.TraceTests.obs-exit-13` still holds.

## Correctness statement & TCB

**Discharged here (was Pure-confined postulate, now proven for primitive B):**

- `pure-sigop-output` for `B ∈ {Int, Float, Unit, Str, Buffer}` — definition.
- `pure-sigop-respects-semM` for `B ∈ {Int, Float, Unit, Str, Buffer}` — definition via `valid-{prim}-wf`.

**Trusted base after this plan (CCC SigOp axioms):**

- `structured-pure-sigop-output` — per-name discharge target for Pure SigOps with compound codomain (Sum/Pair/μ/ν/→). Layer-0 hit: comparisons (`Unit + Unit`).
- `structured-pure-sigop-respects-semM` — same scope.

**Net:** all currently-running Layer-0 Pure SigOps (arith.*, arith.block.*, lit.int, str.lit) become **fully postulate-free** at the SigOp-machine boundary. The remaining two postulates fire only for compound-codomain Pure ops — much narrower scope, and each future structured codomain (e.g. a hypothetical `Pair → Pair` Pure op) is a separately-named per-name obligation rather than a blanket axiom.

## Risk & blast radius

- **`pure-sigop-output` body change:** content of primitive-B output changes from "whatever the postulate said" to `unit-storedvalue`. Abstract-level proofs that read this content would break — but `valid-{prim}-wf` is content-free, so no abstract proof can depend on it. (If any does, that's an existing soundness bug, surfaced.)
- **Case-on-`Type` coverage:** Agda must accept `{Int}/{Float}/{Unit}/{Str}/{Buffer}/{B}` as a covering pattern set. Standard; if it complains, enumerate remaining `Type` constructors explicitly.
- **Structured-pure postulates:** name change from `pure-sigop-*` to `structured-pure-sigop-*` for the catch-all postulates. No external call sites name these directly (only the unified `exec-sigop-respects-semM` / `exec-sigop-output` are called).

## What this plan does **not** do

- Does not discharge `structured-pure-sigop-output` / `structured-pure-sigop-respects-semM`. Those need real per-name discharges that produce well-formed wrappers for compound codomains (allocator-aware), and a hypothetical `valid-sum-{inl,inr}-wf` from a per-name codegen. Deferred to a layer that actually has a producer needing it.
- Does not touch `Plan 0.24` Phase D (bridge 1). Still pending.
- Does not unblock `T0`.
