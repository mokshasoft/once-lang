# Plan 0.26: Discharge Pure-SigOp postulates via `FitsInReg`

## The gap (why this plan exists)

Plan 0.25 reduced the SigOp-machine postulate set from three blanket axioms to two **Pure-confined** ones:

- `pure-sigop-output : ∀ {A B} → SigOpInfo A B → LocState FS → StoredValue FS`
- `pure-sigop-respects-semM : ∀ {A B} (si : SigOpInfo A B) … → ∃ mOut, result-loc, ValidAtWF mOut alloc (semM si x) result-loc post-state`

They live inside CCC (in `SMCore` and `IRTraceCorrect` respectively) and fire for any SigOp with `effect = Pure` — that is, for every actually-running Layer-0 Pure SigOp.

## Why `FitsInReg` is the right classifier

`FitsInReg` already exists at `Once.Type:349`:

```agda
data FitsInReg : Type → Set where
  fits-int   : FitsInReg Int
  fits-float : FitsInReg Float
```

Per the documentation there (lines 338–342), `Unit`, `Str`, `Buffer` are **deliberately excluded** — Unit is erased, Str/Buffer are 2-slot fat compounds. The intent is exactly the abstraction we want: "single-slot, register-resident value." And `ClosureWellFormed:261` already exposes:

```agda
valid-primitive-wf : ∀ {m} {B} {v : ⟦B⟧} → FitsInReg B → BeforeFrontier alloc loc →
                     ValidAtWF m alloc {B} v loc s
valid-primitive-wf fits-int   bf = valid-int-wf bf
valid-primitive-wf fits-float bf = valid-float-wf bf
```

This is precisely the dispatch helper we need. `valid-primitive-wf fitness before` discharges `ValidAtWF` for any value of any `FitsInReg`-classifiable type, regardless of `Output` content. Just like `valid-unit-wf` for Halts/Emits (Plan 0.25), but value-agnostic per `FitsInReg`-witness rather than type-equality-witness.

## Layer-0 coverage

`FitsInReg` covers exactly `Int` and `Float`. For Layer-0 Pure SigOps:

| Op | Codomain | FitsInReg? |
|---|---|---|
| `arith.{add,sub,mul,neg,div,mod}.int` | `Int` | ✓ |
| `lit.int.<N>` | `Int` | ✓ |
| `arith.block.<digest>` | `Int` | ✓ |
| `arith.{lt,le,gt,ge,eq,ne}.int` | `Unit + Unit` | ✗ (structured anyway) |
| `str.lit.<s>` | `Str` | ✗ (declared Pure, but lowered via different codegen — `instr-sigop` for str.lit never fires) |
| `linux.exit` | `Unit` | (Halts; discharged via Plan 0.25 coherence) |

**Net at runtime:** every actually-running Layer-0 Pure SigOp discharges. The residual postulate (for structured-or-Unit-or-Str Pure) exists but is dead code in Layer 0.

## Design

**No producer-side change. No `EffectShape` change. No new type-constructor case-splits in CCC.**

### Add a decider

In a small CCC-internal module (or appended to `Once.Type`):

```agda
fits-in-reg? : (B : Type) → Maybe (FitsInReg B)
fits-in-reg? Int   = just fits-int
fits-in-reg? Float = just fits-float
fits-in-reg? _     = nothing
```

This is the **single point** in the codebase that pattern-matches on `Type` constructors for this purpose; SMCore and IRTraceCorrect import only `FitsInReg` and `fits-in-reg?`.

### `SMCore.pure-sigop-output` dispatches on `fits-in-reg?`

```agda
pure-sigop-output : ∀ {A B} → SigOpInfo A B → LocState FS → StoredValue FS
pure-sigop-output {A} {B} si s with fits-in-reg? B
... | just _  = unit-storedvalue                        -- content irrelevant (ValidAtWF is location-only)
... | nothing = structured-pure-sigop-output si s       -- narrower per-name postulate

postulate
  structured-pure-sigop-output : ∀ {A B} → SigOpInfo A B → LocState FS → StoredValue FS
```

### `IRTraceCorrect.pure-sigop-respects-semM` dispatches on `fits-in-reg?`

```agda
pure-sigop-respects-semM : … (signature unchanged)
pure-sigop-respects-semM {A} {B} si mIn x input-loc s alloc valid before nh rdi-eq
  with fits-in-reg? B
... | just fitness = _ , input-loc , valid-primitive-wf fitness before
... | nothing      = structured-pure-sigop-respects-semM si mIn x input-loc s alloc
                       valid before nh rdi-eq

postulate
  structured-pure-sigop-respects-semM : … (same shape; fires only when ¬ FitsInReg B)
```

CCC's type knowledge is: `FitsInReg` (existed) + `fits-in-reg?` (one new decider). Both live with `FitsInReg` itself. **SMCore and IRTraceCorrect never pattern-match on `Type` constructors.**

## Correctness statement & TCB

**Discharged here (was Pure-confined postulate, now proven for `FitsInReg B`):**

- `pure-sigop-output` for `FitsInReg B` (= `Int`, `Float`) — definitional.
- `pure-sigop-respects-semM` for `FitsInReg B` — via `valid-primitive-wf fitness before`.

**Trusted base after this plan (CCC SigOp axioms):**

- `structured-pure-sigop-output` — per-name discharge target for Pure SigOps whose codomain is **not** `FitsInReg` (i.e. `Unit` / `Str` / `Buffer` / structured compounds).
- `structured-pure-sigop-respects-semM` — same scope.

**Layer-0 effect:** every actually-running Layer-0 Pure SigOp (arith.*, arith.block.*, lit.int) is `FitsInReg`-classified → **fully postulate-free**. `str.lit` is Pure-Str but isn't lowered as `instr-sigop` in practice (the codegen handles string literals via a different path); comparisons are Pure-`Unit + Unit` (structured). Both fall through to the narrower postulate, which never fires at runtime in Layer 0.

## Risk & blast radius

- **`fits-in-reg?` is the only new `Type`-pattern-match** in the codebase. It lives next to `FitsInReg` itself, concentrating CCC's type knowledge.
- **`pure-sigop-output` body change** for the `FitsInReg B` branch: content shifts to `unit-storedvalue` (canonical sentinel). No abstract-level consumer reads `Output` content for primitive types (`valid-primitive-wf` is content-free), so no propagating breakage.
- **Narrower `structured-pure-sigop-*` postulates** are renames of the Plan-0.25 catch-all targets; not externally called by name.

## Adding `List` later (and other structured types)

`List A` doesn't satisfy `FitsInReg` (it's a heap-allocated structure). So a Pure SigOp returning a list falls through to `structured-pure-sigop-*` — the per-name discharge target. **No changes to `fits-in-reg?` or to SMCore/IRTraceCorrect.** When `List` is added, the structured discharge gets a per-name lemma; the dispatch architecture is unchanged.

## What this plan does **not** do

- Does not discharge `structured-pure-sigop-output` / `structured-pure-sigop-respects-semM`. Those need real per-name discharges for compound codomains.
- Does not extend `FitsInReg` to include `Unit` / `Str` / `Buffer` — that would conflict with `FitsInReg`'s deliberate exclusion of those (per `Once.Type:338–342`). If broader coverage is needed later, the principled move is a sibling predicate, not an extension.
- Does not touch Plan 0.24 Phase D (bridge 1). Does not unblock T0.
