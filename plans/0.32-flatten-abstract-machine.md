# Plan 0.32 — Flatten the abstract machine (align with the target, reverse M1)

## Diagnosis (the root of every correspondence headache)

The abstract machine models control flow at a **different level** than the
target, so abstract↔target is NOT 1-to-1:

| | abstract machine | target (`Semantics.exec`) |
|---|---|---|
| straight-line | `exec-trace` (list fold) | pc walks the program |
| **loop** | `exec-loop` — **structured fuel recursion** | `label`/`cmp`/`je`/`jmp` + pc + `find-label` + fuel |
| **branch** | `exec-case-dispatch` — **structured** | `cmp`/`je` |

Straight-line instructions correspond 1-to-1 and are trivial. **Only the
structured control-flow constructs are hard** — precisely because the
abstract machine invented its own control model no target shares. That is
the "fighting the abstraction" the difficulty was pointing at.

This traces to **Plan 0.29 M1**, which chose the structured `exec-loop`
specifically to avoid making `exec-trace` pc-based ("43 consumers"). That
trade bought a small blast radius and paid for it in correspondence
complexity (the `instr-sim` `!!` holes, the `CataDescendCompiledInduction`
fuel gymnastics, the 3 parallel Cata structures). **Reverse it.**

## Target design — a generic flat-fuel CPU

The abstract machine becomes a **target-independent `Semantics.exec`**:
**flat control flow** (pc + `label`/`je`/`jmp` + `find-label` + fuel),
**typed values** (`StoredValue` stays — keeps the codegen-correctness
proofs clean; values are where the abstract machine *should* stay richer
than the untyped-`ℕ` target).

- `AbstractInstr` gains flat control: `a-label`/`a-cmp`/`a-je`/`a-jmp`
  (over abstract registers/conditions). `instr-loop` / `instr-case-on-tag`
  are **removed** — the codegen lowers structured recursion to these flat
  jumps directly (it already does for the target in `compile-trace-cnt`;
  now it does so one level earlier, into the abstract ISA).
- Execution becomes `exec-abstract : ℕ → AbstractProgram → MachineState →
  Maybe MachineState` (fuel, pc, `find-label`) — structurally identical to
  `Semantics.exec`, just over `AbstractInstr`/`StoredValue`.

**Correspondence then = 1-to-1 instruction relabel + a uniform
`StoredValue → Word` value encoding.** No structured↔flat bridge. Adding an
architecture = define its instruction relabel + reuse the value encoding.

## How this unifies with the SigOp-trace fuel

The SigOp-trace proofs already run over `Semantics.exec` — flat, pc, fuel.
Today the abstract machine's `exec-loop` fuel is a **second, parallel**
fuel in a structured model. Flattening makes the abstract machine share
the **one** flat-fuel model: straight-line codegen, recursion-scheme
loops, and SigOp effect traces all bound by the same fuel and proved by
the same induction principle. Fuel becomes the single universal currency,
which is the coherence the SigOp pivot was reaching for.

## Blast radius — the 43 `exec-trace` consumers

Categories (to confirm during M0 audit):
- **WF proof layer** (~20: `PairStackWF/*`, `ComposeWF`, `ApplyWF`,
  `CataLayer`, `RecTrace`, `Sum*WF`, `Curry*WF`, `ClosureWellFormed`, …)
  — prove an IR's trace yields `ValidAtWF`. These reason about
  `exec-trace`'s *reduction*; the deepest migration.
- **SigOp** (`Helper`, `Faithful`, `Proofs`, `RelaxedContract`, …) — these
  are ALREADY fuel/`Semantics.exec`-aligned; should get *simpler*.
- **Correctness/DirectSimulation** (×3 targets) — the correspondence;
  becomes the 1-to-1 relabel.
- **Examples** — collapse (`AbstractCataFoldInduction` +
  `CataDescendCompiledInduction` → one proof over the flat abstract CPU).

## M0 AUDIT RESULT (de-risks the cascade)

The structured control execs `exec-loop`/`exec-case-dispatch` appear in
only **8 files**: `SMCore`, `SMPrimitives`, the 3 `DirectSimulation`, and
our 3 Examples — **NOT the WF proof layer**. The 43 `exec-trace` consumers
use the **sequential interface** + reduction lemmas (`exec-trace-cons` ×11,
`exec-trace-append` ×7) — left-to-right list composition, independent of
how a single control-flow instruction executes internally.

Consequence: the deep "structured → flat control" change is contained to
~8 files. The WF layer keeps working through a **preserved sequential
`exec-trace`** whose `cons`/`append` lemmas hold for non-jump instructions.
`exec-trace` survives as the straight-line composition view; the flat
`exec` (pc/fuel/`find-label`) is the real model and the correspondence
target. Migration is far smaller than "43 sites".

## Staging (validate on the hard case BEFORE the big migration)

- **M0 — audit:** categorize all 43 consumers (interface-only vs
  reduction-dependent); decide whether `exec-trace` survives as a derived
  straight-line view or is fully replaced. Output: a migration table.
- **M1 — flat core (parallel):** new `Machine/Flat.agda` — `AbstractInstr`
  + flat control + `exec` (pc/fuel/`find-label`), built ALONGSIDE the
  current machine. No consumer touched yet.
- **M2 — prove Cata on it:** codegen the cata to flat abstract jumps;
  prove the fold over the flat abstract `exec` (one proof, replacing both
  current fold proofs); prove the **1-to-1 correspondence** to x86-64
  `Semantics.exec` for the loop. This validates the whole thesis on the
  hard case before migrating anything.
- **M3 — migrate consumers:** move the WF layer + correctness chain onto
  the flat machine; retire `exec-loop`/`exec-case-dispatch`/`exec-trace`
  as needed. This is the 43-site cascade.
- **M4 — collapse:** delete the superseded structured proofs + (now
  unblocked) `compile-ir`; one live, proven path.

## Key risks / decisions

- **Does `exec-trace` survive?** If many WF proofs only need
  "trace → final state" (interface), keep a total straight-line
  `exec-trace` wrapper to shrink the cascade; the *correspondence* still
  uses the flat `exec`. Decide in M0 — but beware re-creating two models;
  the end-state is ONE flat `exec`.
- **Shared core vs mirror?** M1 mirrors `Semantics.exec`'s shape in a
  separate module (less coupling, correspondence still 1-to-1). A later
  refactor could parameterize a single core instantiated for abstract +
  each target (true CompCert/CakeML shared framework) — out of scope for
  0.32, revisit after M3.
- **Heap-only value model** stays; the `StoredValue→Word`/`HeapLocation→ℕ`
  encoding is the value-correspondence (simple, uniform, proven once).

**DESIGN RULE — `with`-free `exec`.** The flat machine's `step` /
`execInstr` / jump resolution must NOT use `with`/`case`-on-scrutinee:
each routes through a top-level helper taking the decision value (fetched
instr, `find-label` result, `zf`, encoded read) as an explicit argument —
the SMCore `exec-load-via-resolved`/`-with-value` pattern (Plan 0.27).
`with` freezes reduction behind a case tree, which is exactly the friction
the 1-to-1 correspondence proofs must avoid (they reduce under the
value-encoding hypotheses). ([[feedback_with_clauses_painful]],
[[feedback_with_abstraction]], [[catchall_preserves_reductions]].)
