# Plan 0.38 — Per-producer SigOp contracts (co-located, per SigOp × target)

> **Re-triggered 2026-06-17** by the clean-semantics `faithful` proof: its last
> obligation `build-pure` is *false* under the `classify-name` string-match (see
> "Re-triggered" section below). Milestone 0 (`0.38-core`) is now on the critical
> path; M1–M2 remain deferred design.
>
> Originally drafted while diagnosing the Plan 0.36 effectful-cata bug (a SigOp
> minted for an internal function laundered its meaning through the postulated
> `generic-sem`). This plan removes the *class*: a SigOp may only exist with its
> contract discharged by its producer, and the genuine-external contracts live
> where their subject lives — next to the implementation.

## What a SigOp actually is (corrected understanding, 2026-06-09)

A `SigOp` is **just the morphism `A → B`** — nothing more. It is an escape from
**CCC structure**, NOT from soundness. It is defined by Once *because it carries
a contract its producer must follow*. It is used:
- **externally** (syscalls — `linux.exit`, a real `emit`): behavior Once cannot
  derive *internally*, so the contract is discharged by the interpretation —
  **postulated** for an unverified kernel (Linux), or **proven** for a verified
  one (seL4, connected to its refinement theorems). Discharge is per
  interpretation × target, NOT "external ⟹ axiom";
- **internally-but-non-CCC** (the arith compiler's `arith.block.<digest>`):
  Once-generated subroutines that leave CCC; the contract is **proven** (the
  arith compiler discharges emit-correspondence + `PreservesCCC`).

So the soundness unit is: **a SigOp is sound iff its producer discharged its
contract.** Internal producers prove it; external producers postulate it. The
Plan 0.36 bug was a producer (an extraction in the cata path) minting a SigOp
**without discharging the contract** — permitted only because the contract is
decoupled from construction and a generic catch-all supplies it.

## Two trust boundaries, one of them currently invisible

For an external SigOp like `linux.exit`:
1. **Agda-level contract** — `PreservesCCC` + semI/semM coherence. Today:
   postulated/discharged somewhere downstream (per-name, partly via the generic
   pure path).
2. **Implementation ⊨ semantics** — does the linked `once_exit` asm actually do
   what `semM` says? **Today this is nowhere** — `Syscalls.x86_64` is linked at
   the end; nothing in the proof connects it to `semM`. Not even a postulate —
   an unstated assumption outside the verified boundary.

Boundary #2 is the real gap: the trust sits *away from its subject* (the asm),
so it can't be audited.

## The design

**Co-locate the contract with the implementation, at (SigOp × target)
granularity.**

- The `.once` interface file (`Syscalls.once`) declares only signatures.
- Each target implementation (`Syscalls.x86_64`, `Syscalls.riscv64`, …) is the
  asm that must satisfy the contract.
- Therefore each (interface-file × target) gets a paired **Agda contract
  module** holding the per-SigOp contract postulates for that file's ops on that
  target — e.g. `Strata/Interpretations/Linux/Syscalls/X86-64/Contract.agda`
  postulating `once_exit ⊨ linux.exit-contract`, `once_write ⊨ …`, etc.
  (Granularity of the *obligation* is per SigOp × target — honest, since the
  trust is per-asm; the *module* is per interface-file × target, mirroring the
  `Syscalls.once` ↔ `Syscalls.<target>` pairing.)
- These postulates ARE the external trusted base — genuine axioms (you cannot
  prove a syscall). They feed Plan 0.11's `TrustedBase` as the *confined,
  per-producer* external axioms.

**Internal producers prove, never postulate.** Arith already does; a cata that
ever genuinely emits a SigOp (rare — its algebra is normally CCC code) would
have to prove its contract too. No internal producer touches the external
contract modules.

**Eliminate the generic catch-all.** `generic-info : String → SigOpInfo A B`
(materialising postulated `generic-sem` for *any* name) is the laundering
vector — it lets a producer mint a SigOp for a name with no real contract. A
SigOpInfo should only be constructible **with** its contract (from the
producer's contract module / a proof), so a contractless SigOp is a type error
(this is Plan 0.11's "obligation local to construction"). The opaque external
semantics survive only behind a **genuine-external token** that a Strata
signature + its contract module can mint and internal code cannot forge.

## Relationship to 0.11

0.11 parameterizes the trusted base and bans `postulate` outside `TrustedBase`.
0.38 says *what the SigOp entries of that base are*: not one `generic-sem`
catch-all, but a set of per-(SigOp × target) implementation-contract axioms,
co-located with their impls and surfaced into `TrustedBase`. 0.11 makes them
visible; 0.38 makes them honest (per-asm) and unforgeable (no catch-all).

## Re-triggered (2026-06-17) — the `faithful`/`build-pure` forcing function

The clean-semantics `faithful` proof (elaborated-IR denotation `⟦_⟧ᴰ` ≡ source
denotation `⟦_⟧ˢ`) was completed for **all** `Expr` constructors including
`cata`/`ana`, modulo ONE lemma: `build-pure` — *building a closed arrow-typed
value emits nothing at construction* (effects are deferred into the closure body
and fire only on application, where the fold trace captures them; this is what
justifies the IR rebuilding the algebra per fold-layer matching the denotational
build-once). **`build-pure` is provably FALSE under the current
`classify-name`** — exactly this bug class:

```
classify-name {Unit} "linux.exit" = Halts refl   -- effect from STRING, not type/contract
classify-name _                   = Pure
```

so a NON-arrow `sigOp {Unit} "linux.exit"` is "effectful" and emits at *build*
(reachable via `app f (sigOp{Unit} "linux.exit") : arrow`), and the IR would
re-emit it per fold-layer (adequacy break). This is the **third appearance** of
the parallel-truth disease the clean-semantics work has been killing (after the
ℤ proof-model and the parallel pure-`eval` value-model inside `⟦_⟧ᴰ`): a second
source of "is this effectful," decoupled from the type/contract. Top-down work
re-derived 0.38's motivating bug from a completely different direction — a proof
this way of working detects the problem automatically.

**Consequence for sequencing:** `build-pure` (and thus a postulate-free meaning
layer) is blocked until a SigOp's effect comes from its contract, not
`classify-name`. That does NOT require all of 0.11 — the external contracts can

## Two compile times — and why the core is interpretation-AGNOSTIC (2026-06-17)

Contract resolution does **not** happen inside the `once` compiler. There are two
distinct times:

1. **Once program-compile-time** — the extracted `once` binary compiling a user's
   `.once`. It has **no Agda in it** and does **not** know which interpretation
   will be linked; it sees only declared signatures + effects. It cannot check
   contract proofs.
2. **Interpretation-verification-time** — *off-line*, in Agda, when an
   interpretation is authored: each SigOp's contract is discharged (proof OR
   postulate). **All interpretations are equal — none is special, NOT Linux.**
   There is no "built-in interpretation verified when we build Once." Linux,
   seL4, and a user's own interpretation are all verified off-line by their
   authors, identically.

⟹ The verified core (`elaborate`/`⟦_⟧ˢ`/`⟦_⟧ᴰ`/`faithful`/compile-correctness)
must be **parameterized over an ABSTRACT `Interpretation`**, with no concrete
interpretation baked in. `classify-name`/`generic-info`/`generic-semM` were a
hardcoded stand-in for that parameter (and gave Linux special treatment *inside*
the compiler — the bug). This is the **SigOp slice of Plan 0.11's `TrustedBase`
parameterization**.

## Milestone 0 — `0.38-core` (unblocks `build-pure`)

Parameterize the core over an abstract interpretation and delete the catch-all.

- **M0.1 — `Interpretation` parameter.** An abstract record/module providing, per
  external name, its `SigOpInfo` (`semM` + `EffectShape`), plus a **well-formedness**
  property the core needs (a non-arrow / bare-value op is `Pure` — effects are
  deferred onto arrows; so nothing emits at *build*). The core is agnostic to how
  each instance discharges its contracts (proof/postulate) — that's off-line.
- **M0.2 — Thread it** through the `SigOp`-building points (`elaborate`,
  `⟦_⟧ˢ`/`⟦_⟧ᴰ`) and the proof chain (module parameter, 0.11-style). Delete
  `generic-info`/`classify-name`/`generic-semM` — the SigOp's info comes from the
  `Interpretation` parameter, never a `String` catch-all.
- **M0.3 — Discharge `build-pure`** relative to the abstract interpretation's WF
  (no closed expr emits at build), close `faithful` postulate-free, delete the
  `build-pure` postulate.

**Deliverable:** `faithful` total and postulate-free w.r.t. construction-purity;
the core has no concrete interpretation and no `String → SigOpInfo` catch-all.

**NOT core:** concrete interpretation instances (Linux, seL4) and dog-fooding a
user-proven interpretation are off-line, equal, and **deferred** (M1). The
existing `Once/Strata/Interpretations/Linux/Syscalls.agda` is one such *example*
instance — the core must not import it.

## Milestone 1 — external contracts co-located (`per (SigOp × target)`)

Per the design above: `Strata/Interpretations/<plat>/Syscalls.once` declares
signatures; `…/Syscalls/<target>/Contract.agda` discharges `once_<op> ⊨
<op>-contract` for that target. The genuine-external **token** (a SigOpInfo for
an external op is constructible only from such a contract module; internal code
cannot forge it). Closes trust-boundary #2 (impl ⊨ semantics).

**Discharge is proof-OR-postulate, per interpretation × target — NOT "external ⟹
axiom" (2026-06-17).** A SigOp's contract is a producer-discharged *obligation*;
*how* it is discharged is the interpretation's concern and depends on that
platform's verification status:
- **Linux** — the kernel is not formally verified, so its `Contract.agda`
  **postulates** `semM`/`EffectShape`/`impl ⊨ semM` (genuine, irreducible axioms).
- **seL4** (or any verified target) — the contract **can be proven**, connected to
  the kernel's refinement theorems; no postulate needed.
- **Internal** (arith) — proven (already).

The compiler-side mechanism is **discharge-agnostic**: it only requires that *a
contract exists* (the genuine-external token witnesses one), never that it be a
proof or a postulate. So `TrustedBase` shrinks automatically as targets become
verified — the Linux axioms are confined to Linux's contract module, and a seL4
build carries none of them.

## Milestone 2 — fold into 0.11's `TrustedBase`

Once 0.11 lands the `TrustedBase` parameterization, the per-(SigOp × target)
contract postulates become the SigOp slice of that base — confined, per-producer,
no catch-all. This is the convergence point of 0.11 + 0.38.

## Sequencing (revised 2026-06-17)

`0.38-core` (M0) FIRST — small, unblocks `build-pure`/`faithful`, no `TrustedBase`
needed (external contracts as plain co-located postulates). Then full 0.11
