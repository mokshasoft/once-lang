## Why it must be TYPE-indexed (the three walls, verified 2026-08-02)

1. **Not pc-free.** "Input1 always holds a pointer" is FALSE at most pcs (the
   D074 entry filler is a tag; literal fragments leave `SV-Lit` in
   Input1/Output). Unlike `StackPtrWF`/`FlatPtrBounds`, the facts are
   per-site, so the invariant must be pc-indexed.
2. **Not type-free.** A syntactic per-pc dataflow analysis (shapes
   Ptr/NonPtr/Any over registers+slots) dies on the cata DESCEND loop: the
   next iteration's scrutinee is LOADED FROM THE HEAP (`load-indirect-suc` of
   the current node), and type-free analysis gives heap loads `Any`. Knowing
   the loaded child is a node pointer requires heap typing ("a sum node's
   payload cell holds a node pointer").
3. **The tag conjunct is load-bearing.** `tag-zf` is `false` on every
   non-tag, while the concrete `cmp [rdi],0` compares the RAW encoding with 0
   (`enc-sv (SV-Lit fits-int 0) = 0`) — a non-tag cell flips the branch
   decision between the machines. And telling sum nodes (tag in cell 0) from
   pair nodes (pointer in cell 0) is type information.

Consequence: the theorem is the SHAPE-LEVEL ERASURE of value correctness —
`ValidAtWF` with the semantic value dropped and exact-value equations turned
into existentials. It overlaps the eventual `obs-correct-rest` discharge (it
IS that theorem, values erased); build it so the value layer subsumes it
(`ValidAtWF → ShapeAt` must be a projection).

## The design

### Shape layer (M1)

`Once.CCC.Machine.ShapeAt` (mirrors `ClosureWellFormed.ValidAtWF`):

- `ShapeAt : IRTy → AllocState → ValueLocation → LocState → Set` — the
  location holds a shape-correct representation of the type: products = two
  written pointer cells whose targets are `ShapeAt` of the components; sums =
  written `SV-Tag` cell 0 + payload per branch; μ = node form per functor;
  Int/Float = `SV-Lit`; Unit = ⊤; closures = code+env cells. Existential
  where `ValidAtWF` is exact.
- `RegShapeOf : IRTy → StoredValue → … → Set` — the register-resident form
  (`InputAt`'s three routes, shape-only: pointer-to-`ShapeAt` / literal /
  unit-any).
- **Gate G1 (POC before anything else):** `valid→shape : ValidAtWF m alloc x
  loc s → ShapeAt A alloc loc s`. If the erasure is not a projection, the
  domain is wrong — stop and redesign.

### Static expectation table (M2)

`Once.CCC.Codegen.ShapeTable`: a typed re-walk of `ir-to-trace'` emitting a
per-pc expectation table for the WHOLE trace (not just discipline sites —
the preservation induction needs every pc to carry something):

- `Expect = record { e-in1 e-in2 e-out : RegExpect ; e-slots : Slot → SlotExpect ; … }`
  over a small expectation language (ptr-to-node / ptr / lit / tag / any),
  interpreted against the state by `Meets : Expect → FlatState → Set`
  (registers via `RegShapeOf`, heap reads via `ShapeAt`).
- `ir-to-shapes : IR A B → List Expect` with the ALIGNMENT invariant
  `length (ir-to-shapes ir) ≡ length (ir-to-trace ir)` and a fetch-aligned
  `Zip`-style walk (the `AllocMin`/`FrameFreeTrace` mold, but carrying the
  IR TYPES through the recursion — this is where "type-indexed" lives).
- The DISCIPLINE-SITE lemma (by construction of the table): at a pc whose
  instruction is `load-indirect{,-suc}` / `c-branch-tag-zero`, the table
  entry's `e-in1` is `ptr`/`ptr-to-sum-node` respectively.
- **Gate G2:** the table for the cata skeletons — the entries at the loop
  labels (`ld-top`/`f-top`/`g-top`) ARE the loop invariants ("Input1 = node
  ptr", "todo/eval stack slots hold node-stack pointers"). Write these
  concretely for `cata-trace-nat` FIRST and check they close under the
  back-jump transfer by hand before mechanising.

### Preservation (M3 — the bulk)

`TableConsistent tbl fs = Meets (tbl ! fpc fs) fs`, and the step theorem:
one `flat-exec-instr` step from a consistent state of an emitted program is
consistent at the successor pc — straight-line = local transfer; `c-jmp` /
branches = the table AGREES at label targets (a per-label fact the table
construction must provide, like `find-label-corr` provides offsets); stores
must preserve heap `ShapeAt` (initialization discipline: codegen fills every
allocated node's cells before the next alloc — verified true of every
pattern 2026-08-02). Run induction mirrors `run-wf-ptr-bounds` (carry
`FlatWF` + `PtrBounds` alongside as needed).

### Wiring (M4)

`run-shape : RunAt prog fs → TableConsistent (shape-table-of (run-ir r)) fs`;
the three residual postulates become theorems (site lemma + consistency) and
are DELETED. Census target: ConcFlatSim 10 → 7.

## M2b — `emitted-shape-check` (THE NEXT ITEM)

    emitted-shape-check : ∀ (ir : IR Unit Unit) → HeapModed ir
                        → Σ LabelEnv (λ env →
                            check-shapes env (entry-expect Unit) (ir-to-trace ir) ≡ true)

The `FrameFreeTrace`/`AllocMin`-mold induction over `ir-to-trace'`, but
carrying the IR TYPES (`ir-to-trace' n l (ir : IR A B)` starts at
`entry-expect A` and must end at an `e-repr B`-ish post-state). Shape:

1. Generalize to a per-fragment statement — `∀ {A B} (ir : IR A B) n l st`
   with `sub-reg (e-in1 st) (e-repr A) ≡ true` ⇒ the fragment checks from
   `st` and its post-state's `e-out` entails `e-repr B`. `check-++` splices
   the clauses; `post-++` composes the post-states.
2. `LabelEnv`: the `case` clause needs `l-inl ↦ (state at the branch, in1
   refined to inl)` and `l-end ↦ the join`; the cata skeletons need the G2
   invariants (`ld-top ↦ in1 = e-repr (μ F)`, and for linear/branching the
   payload-stack slot claims). Build the env COMPOSITIONALLY (each clause
   extends the sub-fragments' envs on its own fresh label range — labels
   are already collision-free by construction, plan 0.54 item 6).
3. Known friction points, in order of expected cost: the cata skeletons'
   slot bookkeeping (the `e-slot` assoc list must survive the loop bodies —
   a low-slot FRAME property, piggyback `SlotBudget`'s frontier
   discipline); `apply`/`instr-call-closure` (the transfer already scrubs
   to `e-any`, so it should check trivially); the Int-payload sum wrinkle
   (a literal in a payload cell — `MeetsCell` is PTR-only, mirroring
   `valid-inl-wf`; if a fragment fails there it is a REAL finding about the
   value layer too — write it up, do not paper over it).

## M3 — `run-meets`

    run-meets : ∀ prog fs → RunAt prog fs → (env : LabelEnv)
              → check-shapes env (entry-expect Unit) prog ≡ true
              → Meets (state-at env (entry-expect Unit) prog (fpc fs)) fs

Induction on `Reachable` (the `run-wf-ptr-bounds` mold, carrying `FlatWF`
alongside — the alloc case needs `wf-fresh` for the unwritten-cell facts):
- entry: the D074 all-tag state meets `entry-expect Unit` (`rs-unit` — a
  unit input has no residence, which is exactly why D074 was needed);
- step: the per-instruction transfer soundness. Bricks already proven:
  `shape-uw`/`meets-cell-uw`/`read-uw` (stores), `sub-expect-sound`
  (control), `site-load-ptr`/`site-branch-tag` (the site facts). Remaining:
  the register-write transport (`readReg-write` enumeration from
  FlatStackPtr — the `go` pattern over the four `Meets` components), the
  `FreshAt` progression at its own store, and the `state-at` bookkeeping
  (`state-at env st prog (suc pc) ≡ step-expect env (state-at env st prog
  pc) i` at a fetched `i` — a `scan`-style lemma, mirrors `check-at`).

## Gate G2 — the `strat-nat` descend loop, hand-checked (2026-08-02): CLOSES

Expectation language needed: `RegExpect ::= e-any | e-lit | e-tag |
e-ptr A` ("pointer to a `ShapeAt A` representation"), with PATH-SENSITIVITY
at tag branches (fall-through refines the scrutinee to the inr shape, the
target to inl — the tag test IS the case analysis on the sum shape).

The descend loop (`ld-top … c-jmp ld-top`), invariant at `ld-top`:
`Input1 : e-ptr (μ Nat-F)` — a pointer to a sum node with a WRITTEN TAG.

- Established at loop entry: the fragment's input shape (the root μ value).
- `c-branch-tag-zero ld-inl` — THE branch discipline site: implied directly
  by the invariant (`shape-inl`/`shape-inr` both carry the written tag cell).
- Fall-through (inr) arm: `load-indirect-suc` — the load discipline site,
  implied by the invariant; its RESULT shape comes from the HEAP half of the
  sum shape: the inr payload cell holds `e-ptr (μ Nat-F)` (the child node).
  `mov-to-input` moves it to Input1 → invariant RE-ESTABLISHED. This is
  wall 2 resolving exactly as designed: the load's precision comes from
  `ShapeAt`, not from syntax.
- `ld-inl` arm: Input1 unchanged (still a μ-node pointer) → invariant holds.
- Join at `ld-de`: both arms agree (`e-ptr (μ Nat-F)`); `c-jmp ld-top`
  matches the head expectation. CLOSED.

Ascend: `build-layer` CONSTRUCTS the `[tag, pair-ptr]` layer node and loads
it into Input1, so the algebra splice's entry expectation
(`Input1 : e-ptr (⟦F⟧ A)`) is established by construction; the algebra's own
table comes from the recursive `ir-to-shapes alg` (compositional, like every
other splice). No payload stack in `strat-nat` — the linear/branching stack
invariants ("todo/eval slots hold node-stack pointers") are M3 content, not
G2.

CONSEQUENCE for M2: `ir-to-shapes` needs (i) `e-ptr A` over IRTy, (ii)
branch path-sensitivity, (iii) the per-label join stated as table AGREEMENT
at label pcs (the loop head's entry is the join of the back-jump arm and the
fall-in arm). Both gates (G1, G2) are now cleared — M2 mechanisation may
start.
