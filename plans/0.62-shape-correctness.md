# Plan 0.62 — Type-indexed shape correctness for codegen

**STATUS: DESIGNED 2026-08-02, not started.** Successor of Plan 0.54 rung D's
"per-site register-shape invariant". Discharges the three remaining dataflow
disciplines of the flat↔x86-64 correspondence:

- `branch-tag-scrutinee-wf` — at an emitted `c-branch-tag-zero` site, `Input1`
  holds a heap pointer to a WRITTEN TAG cell;
- `load-indirect-target-ptr` / `load-indirect-suc-target-ptr` — at an emitted
  load site, `Input1` holds a pointer.

## Why it must be TYPE-indexed (the three walls, verified 2026-08-02)

1. **Not pc-free.** "Input1 always holds a pointer" is FALSE at most pcs (the
   D074 entry filler is a tag; literal fragments leave `SV-Lit` in
   Input1/Output). Unlike `StackPtrWF`/`FlatPtrBounds`, the facts are
   per-site, so the invariant must be pc-indexed.
2. **Not type-free.** A syntactic per-pc dataflow analysis (shapes
   Ptr/NonPtr/Any over registers+slots) dies on the cata DESCEND loop: the
   next iteration's scrutinee is LOADED FROM THE HEAP (`load-indirect-suc` of
   the current node), and type-free analysis gives heap loads `Any`. Knowing
   the loaded child is a node pointer requires heap typing ("a sum node's
   payload cell holds a node pointer").
3. **The tag conjunct is load-bearing.** `tag-zf` is `false` on every
   non-tag, while the concrete `cmp [rdi],0` compares the RAW encoding with 0
   (`enc-sv (SV-Lit fits-int 0) = 0`) — a non-tag cell flips the branch
   decision between the machines. And telling sum nodes (tag in cell 0) from
   pair nodes (pointer in cell 0) is type information.

Consequence: the theorem is the SHAPE-LEVEL ERASURE of value correctness —
`ValidAtWF` with the semantic value dropped and exact-value equations turned
into existentials. It overlaps the eventual `obs-correct-rest` discharge (it
IS that theorem, values erased); build it so the value layer subsumes it
(`ValidAtWF → ShapeAt` must be a projection).

## The design

### Shape layer (M1)

`Once.CCC.Machine.ShapeAt` (mirrors `ClosureWellFormed.ValidAtWF`):

- `ShapeAt : IRTy → AllocState → ValueLocation → LocState → Set` — the
  location holds a shape-correct representation of the type: products = two
  written pointer cells whose targets are `ShapeAt` of the components; sums =
  written `SV-Tag` cell 0 + payload per branch; μ = node form per functor;
  Int/Float = `SV-Lit`; Unit = ⊤; closures = code+env cells. Existential
  where `ValidAtWF` is exact.
- `RegShapeOf : IRTy → StoredValue → … → Set` — the register-resident form
  (`InputAt`'s three routes, shape-only: pointer-to-`ShapeAt` / literal /
  unit-any).
- **Gate G1 (POC before anything else):** `valid→shape : ValidAtWF m alloc x
  loc s → ShapeAt A alloc loc s`. If the erasure is not a projection, the
  domain is wrong — stop and redesign.

### Static expectation table (M2)

`Once.CCC.Codegen.ShapeTable`: a typed re-walk of `ir-to-trace'` emitting a
per-pc expectation table for the WHOLE trace (not just discipline sites —
the preservation induction needs every pc to carry something):

- `Expect = record { e-in1 e-in2 e-out : RegExpect ; e-slots : Slot → SlotExpect ; … }`
  over a small expectation language (ptr-to-node / ptr / lit / tag / any),
  interpreted against the state by `Meets : Expect → FlatState → Set`
  (registers via `RegShapeOf`, heap reads via `ShapeAt`).
- `ir-to-shapes : IR A B → List Expect` with the ALIGNMENT invariant
  `length (ir-to-shapes ir) ≡ length (ir-to-trace ir)` and a fetch-aligned
  `Zip`-style walk (the `AllocMin`/`FrameFreeTrace` mold, but carrying the
  IR TYPES through the recursion — this is where "type-indexed" lives).
- The DISCIPLINE-SITE lemma (by construction of the table): at a pc whose
  instruction is `load-indirect{,-suc}` / `c-branch-tag-zero`, the table
  entry's `e-in1` is `ptr`/`ptr-to-sum-node` respectively.
- **Gate G2:** the table for the cata skeletons — the entries at the loop
  labels (`ld-top`/`f-top`/`g-top`) ARE the loop invariants ("Input1 = node
  ptr", "todo/eval stack slots hold node-stack pointers"). Write these
  concretely for `cata-trace-nat` FIRST and check they close under the
  back-jump transfer by hand before mechanising.

### Preservation (M3 — the bulk)

`TableConsistent tbl fs = Meets (tbl ! fpc fs) fs`, and the step theorem:
one `flat-exec-instr` step from a consistent state of an emitted program is
consistent at the successor pc — straight-line = local transfer; `c-jmp` /
branches = the table AGREES at label targets (a per-label fact the table
construction must provide, like `find-label-corr` provides offsets); stores
must preserve heap `ShapeAt` (initialization discipline: codegen fills every
allocated node's cells before the next alloc — verified true of every
pattern 2026-08-02). Run induction mirrors `run-wf-ptr-bounds` (carry
`FlatWF` + `PtrBounds` alongside as needed).

### Wiring (M4)

`run-shape : RunAt prog fs → TableConsistent (shape-table-of (run-ir r)) fs`;
the three residual postulates become theorems (site lemma + consistency) and
are DELETED. Census target: ConcFlatSim 10 → 7.

## Milestones and honest sizes

- **M1** ShapeAt + RegShapeOf + G1 projection — 1 session. Wire G1 as a
  consumed lemma (e.g. restate `entry-witness`'s shape side through it) or
  keep uncommitted until M4 per the MERGE.md no-island rule.
- **M2** table + alignment + site lemma + G2 (nat-cata loop invariant by
  hand) — 1–2 sessions.
- **M3** preservation — the CompCert-typing-pass part: 2–4 sessions
  (straight-line sweep mechanical; cata loops + store/heap-shape evolution
  are the content).
- **M4** wiring + census — 0.5 session.

## Non-goals

- No semantic values anywhere (no `eval`, no `⟦_⟧` elements) — shapes only.
- `store-indirect{,-suc}-bad`, `load-const-float`, `events-running-call` are
  NOT touched (separate model gaps).
- No new machine semantics; the model is fixed (D073/D074).
