# Plan 0.68 — discharge `ir-obs-correct`: the abstract machine against the denotation

**Status**: OPEN. Written 2026-08-09, immediately after D099/D100.

**Root**: `Once.CCC.Codegen.IRObsCorrectFlat`. Apex consumer:
`ArchCorrect.ir-flat-correct` (`flat-trace mir n ≡ ⟦ mir ⟧IR n`), on all three
arches.

## Why this plan exists

On 2026-08-06 the emitter shipped a binary the assembler refused (`symbol
.L_thunk_once_4main_10 is already defined`, 61 exit tests, three arches). D100
diagnosed it and added the missing precondition — `DistinctLabels`, threaded
into each arch's `loader-faithful`.

**That fix was placed one layer too low, and the postulate is what put it
there.** The duplicate is not primarily an assembler problem:

- `cata-trace-nat` builds `I₁ ++ at ++ (I₂ ++ at ++ I₃)` as ONE trace;
- the flat machine's `find-label` scans the WHOLE trace, first match wins;
- so the second copy's `c-jmp end` resolves backwards into the FIRST copy.

The abstract machine executes a program that is not the cata. `as` refusing to
assemble it was the only component in the entire stack that noticed — and it
noticed for an unrelated reason (a name collision in a symbol table it builds
and we do not model).

The statement that a duplicate-label trace falsifies already exists:
`ir-flat-correct`, against `⟦_⟧IR`, which knows nothing about labels. It did not
break because it is not proved. `ir-obs-correct` is a total dispatch, but every
constructor routes to one of two blanket postulates:

    postulate cata-correct     : … → IRObsCorrectF (Cata wf alg)
    postulate obs-correct-rest : ∀ ir → IRObsCorrectF ir     -- CATCH-ALL

and `cata-correct` is exactly the constructor whose emitter duplicates the
labels. **So `cata-correct` is not a deferred proof; it is a false postulate on
the apex path.** The ledger's row understates it and must be corrected.

The general lesson, which is the reason for this plan's shape:

> A top-level postulate does not merely leave work undone. It **misleads the
> next repair**: with the theorem assumed, the only evidence available is the
> external symptom, so the fix lands wherever the symptom appeared.

## The claim this plan tests

> If the abstract machine is correct against the denotation, and the
> correspondence between the arch and the abstract machine is proven, then the
> assembled binary is correct and the assembler axiom does not need to change.

Sound, with two qualifications that this plan carries as explicit obligations:

1. **Keep the D100 premise; discharge it, don't delete it.** Once uniqueness is
   forced by step 2 below, `program-labels-distinct` becomes a *proved* side
   condition on `loader-faithful` rather than a residual. A proved side
   condition is strictly better than none — it records what we rely on `as` for.
   It is already wired (commit `b343d342`); nothing here removes it.
2. **The arch's own labels are outside this theorem.** `compile-trace-cnt`
   allocates further labels (case/loop expansion) that never appear in the
   abstract trace, so nothing in `ir-obs-correct` constrains them. They live in
   the concrete↔abstract correspondence — whose label lemmas (`find-label-corr`,
   `find-thunk-corr`) are proved, in `FlatComposition`'s own words, with "no
   label-uniqueness argument anywhere", i.e. blind in exactly the way we just
   found. That walk is LINEAR, so it is the easy half, but it stays owed after
   this plan closes. **Named here so it cannot be assumed away** — see step 5.

## STEP 1 — classes A and B (no control flow)

### IN PROGRESS. 7 of 13 discharged 2026-08-09: `id`, `terminal`, `initial`,
### `free-heap`, `out-μ`, `Out`, `const`. One BLOCKED (`In`) on a spec gap.

Two reusable pieces came out of it, both needed by every remaining class-A/B
constructor:

- **`exec-flat-stop`** — the missing half of `Flat`'s with-free step API.
  `exec-flat-step` peels a FETCHED instruction; nothing peeled the final fetch
  that runs off the end of the trace and halts. Needed because after one step
  the inner `halted (floc fs₁)` is no longer a syntactic occurrence in the goal,
  so a second `rewrite nh` cannot reach it — only a lemma stated over an OPAQUE
  `fs` with both decisions as hypotheses can. (This is the same discipline the
  x86 `StepLemmas` follow, applied to the flat machine.)
- **`reg-write-readLoc`** — a register write is invisible to `readLoc`.
  `ValueLocation` is `AtStack`/`AtDynamic` only; there is NO register location,
  so every memory-side invariant (`ValidAtWF` via `validityWF-mem-preserved`,
  `BeforeFrontier` which does not mention the state at all) survives
  `mov-to-output` definitionally, and `validAtWF-set-halted` covers the `forced`
  at the end.

The value half is the pleasant surprise: `Output := Input1` means **the result's
residence IS the input's residence**, so the three `InputAt` shapes map onto the
three `ResultPlace` shapes one-for-one — `in-loc → at-loc`, `in-reg → at-reg`,
`in-unit → unit-result`. Expect the same for the five other constructors that
compile to `mov-to-output ∷ []`.

The three that followed `id` cost one round each, no new machinery:
`terminal` (emits `[]`; `unit-result` asserts nothing about the state, exactly
because a unit result has no residence — D074), `initial` (VACUOUS: `⟦Void⟧ᴵ` is
`⊥`, and `evalᴰ initial ()` is itself an absurd pattern, so the two sides agree
by having no input), `free-heap` (`IR Unit Unit`, `unit-result` again).

`out-μ` and `Out` cost one new one-liner, `ν-layer-iso` (the ν twin of the
existing `μ-layer-iso`): `valid-μ-wf`/`valid-ν-wf` CARRY the layer's own
`ValidAtWF` (Plan 0.27 Option 3), so destructing one yields exactly what
`at-loc` wants. Both are also DOMAIN-RESTRICTED in a way that kills two of the
three input residences outright — `in-reg` carries `FitsInRegI (μ-type F)` and
`FitsInRegI` has only `fits-int`/`fits-float`, while `in-unit` claims
`μ-type F ≡ Unit`, absurd by constructor disjointness. Only the pointer
residence survives.

`const` is the first REGISTER-resident result: `exec-abstract
(instr-load-const fitˢ v)` writes `SV-Lit fitˢ v`, which is definitionally the
`prim-sv fit v` that `at-reg` claims. Domain `Unit`, so no input is read.

### `In` IS BLOCKED, AND ON A SPEC GAP — not a missing lemma

`In`'s domain is `⟦ F ⟧TI (μ-type F)`, a STUCK application. Unlike `out-μ`/`Out`
neither off-pointer residence can be refuted: `⟦ K Unit ⟧TI X` really is `Unit`,
so the `in-unit` case is live. There the input has NO residence (D074), so after
`mov-to-output` nothing is known about `Output` — and `ResultPlace` has no shape
to offer: `at-loc`/`at-reg` both demand an `Output` equation, and `unit-result`
needs the CODOMAIN to be syntactically `Unit`, which `μ-type F` is not. The
`ValidAtWF` half is free (`valid-μ-wf … valid-unit-wf`); it is the RESIDENCE
that has no witness.

**`ResultPlace` is missing the dual of `InputAt`'s `in-unit`** — "an erased
result, no residence claimed". D074 added that case on the INPUT side and never
on the output side. Adding it is a spec change, and per this plan's own gate the
discharge dictates it rather than a guess made ahead of time; the case is named
in the source at the postulate. Resolve it when `fst`/`snd` (which read through
a residence) have shown whether they want the same shape.

NEXT: `fst`/`snd` (`load-indirect` READS memory, so the value comes out of the
pair's `valid-pair-wf` — the first genuinely new shape), then class B (the
allocation/frontier thread), then the `ResultPlace` decision for `In`.


The cheap half, and the template validation. Two worked examples already exist
to copy: `obs-correct-sigop` (a constructor discharged directly, zero new
postulates) and `comp-obs-correct` (a constructor discharged by composing IHs
through one named `comp-step`).

Order: A before B. A needs only `flat-events-[]`-shaped reasoning plus
`value-realized` at a `ResultPlace`; B adds the allocation/frontier thread
(`BeforeFrontier`, `next-slot`) that A does not exercise.

Gate: **no new postulate may be introduced by a class-A constructor.** If one
seems necessary, the machinery is missing, not the fact — stop and name it.

## STEP 2 — `curry`: where the label discipline arrives

The insight step, and the reason this plan exists. `ir-to-trace' (curry body m)`
emits, in one literal list:

    … instr-load-code-addr (ℓ o this) … c-jmp end ∷ c-thunk (ℓ o this) bb ∷
    body ++ c-ret bb ∷ c-label end ∷ []

To match `⟦curry⟧` the proof must show the parent **skips the body** — i.e. that
`find-label` returns the position of *this clause's* `c-label end`, not some
other definition of the same name. That direction does not exist yet:

- `find-label-sound` (Flat.agda) — what the scan finds carries that label.
  SOUND only, true of the first match whether or not it is the right one.
- the CONVERSE — the definition at position `j` is what the scan returns — is
  FALSE without uniqueness and is exactly what this step needs.

Started, unverified, on this branch: `Once/CCC/Codegen/EmittedResolve.agda`
(`find-label-complete` + `find-thunk-complete`, each taking
`AllPairs _≢_ (labels-def t)`). **Do not land it as a standalone lemma** — finish
it as part of this step, driven by the goal that consumes it. That is the whole
point of working top-down.

Expected outcome: the uniqueness premise arrives as an obligation the proof
cannot dodge, and `EmittedWF.labels-unique` acquires its real consumer (the
emitter's correctness, not the assembler's precondition).

`apply` (class E) follows immediately: it consumes the code address a `curry`
defined, so it needs `find-thunk-complete` and the same discipline.

## STEP 4 — `Cata`

Last, and the payoff. Two obstacles, in this order:

1. **The goal is unprovable while the double splice stands.** `cata-dispatch`
   uses the algebra's IH TWICE at the same label range, so the two copies carry
   the same labels and step 2's discipline fails. Fixing it is the CATA FORK —
   D089's splice `path` vs. re-generating the algebra at successive counters
   (in flight on `fix/cata-label-duplication`, 6/8 walks done). Either satisfies
   the discipline; decide with the proof obligation in hand, not before.
2. **Base and ascend must be rebuilt.** `5088e571` deleted
   `CataNatAscend`/`CataNatValue`/`CataNatTrace` on 2026-06-17 as "dead — no
   live importers", four days after `IRObsCorrectFlat` named them as this
   discharge's route. Only DESCEND survives. This is a project in its own right.

**This is the step that would have caught D099 before the exit tests did.** Say
so in the decision-log entry when it lands.

### THE FORK IS DECIDED (2026-08-09): re-generate at successive counters

Three options were on the table, not two:

  A. **Re-generate the algebra at successive label counters** — same
     instructions twice, names fresh by construction. In flight since
     `e26fef05`.
  B. **D089's splice `path`** — generate once, distinguish the copies by a path
     component in the label identity. `Label.path` EXISTS but is dead
     (`ℓ o n = mkLabelId o [] n`), so this is unbuilt.
  C. **Emit the algebra ONCE and call it** — no duplication at all. Newly
     possible: D092 modelled the call, so the machinery exists.

**A is chosen**, and the reason is proof-side, not convenience. Whichever option
is taken, the `traces-agree` discharge needs the SAME lemma — "the algebra's
behaviour does not depend on the label counter it was generated at" — because
the loop applies the algebra at two points and the two instances must be tied to
one IH. A and B need that lemma identically; B additionally needs `Label.path`
built and every label-ordering argument taught about paths. C avoids the lemma
but is a codegen redesign (return addresses through a fuel-driven loop), and it
would change the machine the arch ports are generic over — the thing D092 just
finished settling. C stays on the table for a later size/speed pass; it is not
the way to get the invariant true now.

### WHERE IT STANDS (`fix/cata-label-duplication`, RED by design)

    e26fef05  6 of 8 walks: IRToTrace, CataIRSlotStable, FrameFreeTrace,
              AllocMin, SlotBudget, LabelRange
    a33af0b9  7 of 8: `Pieces2` disjointness + the copy swap

Two design decisions landed in `a33af0b9`, both taken with the obligation in
hand rather than guessed:

- **`Pieces2`'s skeleton relation was too strong.** It asked `b ≤ c` — "every
  embedded window sits ABOVE the skeleton's". True for `case` (join labels
  allocated first, branches after) and FALSE for `cata`, which allocates its
  algebra copies first and its own six labels last. The datatype only ever needs
  the two windows DISJOINT, so `p2cons` now takes `(b ≤ c) ⊎ (d ≤ a)` and the two
  clash sites factor through one `disj-clash`. The DESCENT along the trace
  (`d ≤ hi`, recursing at `c`) — which is what gives pairwise disjointness
  between the embedded windows — is untouched.
- **The cata splices the HIGHER-numbered copy FIRST**, so windows descend along
  the emitted trace. Descent is exactly the shape `Pieces2` needs, and it is how
  `case` already emits its two branches.

**The remaining red is a CASCADE, not a shape problem.** With the two copies at
successive counters, each per-walk Cata witness needs the SECOND copy's witness
at `(n1, l1)` beside the first's at `(n, l)`. First site: `SlotBudget:957`
(`slots-below alg n l`, where the goal now wants the copy generated at `n1`).
Then `cata-{nat,lin,br}-pieces` move from `Pieces` to `Pieces2` — taking
per-copy neutrality / `SegAgree` / `LabelsIn`, exactly as `case-pieces` already
does — and `seg-agree`'s Cata case routes to `pieces2-agree`. Then re-extract
and run the exit tests: that is the measurable payoff (61 regressed tests).

Note the ORDER this establishes for step 4: the emitter fix makes
`program-labels-distinct` (D100, residual #14) TRUE and `cata-correct` no longer
false FOR LABEL REASONS. `cata-correct` itself remains owed, and its own blocker
is unchanged — base and ascend have to be rebuilt.

## STEP 5 — the leftovers, named not assumed

- **Class G** (`Para`, `Ana`, `Hylo`, `Fuse`, `in-ν` compile to `[]`) — a

- **The arch's own labels** (qualification 2) — a `LabelRange`-shaped freshness

  no uniqueness argument at all.
- **`cata-correct`'s ledger row** — reclassify from "deferred proof" to
  **false as stated**, with the counterexample. Do this at STEP 0, not at the
  end; the inventory must not overstate its own health while the work runs.

## Gates

- **Top-down, always.** Make the top-level change first and let the typechecker
  find the ripple. No supporting lemma before the obligation that consumes it
  exists — `EmittedResolve` is this plan's own instance of the temptation.
- **Fix the model in the flat machine, not in a premise.** If a constructor's
  obligation is false because the machine models something wrongly, change the
  machine (D090/D092/D096 are three precedents on this branch alone).
- **A stub is not an invariant.** Class G is undefined codegen; do not dress it
  as a hypothesis.
- **The postulate count is not the metric.** Splitting one false bundle into
  fifteen named obligations raises the count and is correct. `MERGE.md`'s
  "explainable residual by residual" is the test.
- Land green commits, record decisions in the decision log, push.

## Not in scope

- Remodelling label resolution as a symbol TABLE rather than a first-match scan
  (the faithful model of what an assembler does), and giving `assemble` a
  failure mode (`String → Maybe (List Byte)`). Both are the right long-term
  repair of the toolchain boundary — see the residual ledger's "THE ASSEMBLER
  BOUNDARY" section — but this plan tests whether the abstract-machine theorem
  makes them unnecessary. Revisit only if step 2 or step 4 shows it does not.
- The duplicate `once_arith.block.<digest>` global symbol (ledger: live gap,
  same class as D099 one level up). Independent of this cone.
