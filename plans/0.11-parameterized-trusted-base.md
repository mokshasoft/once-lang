# Plan 0.11 — Honest assumptions are hypotheses; proof gaps are proved

## Goal

`once-certified`'s TYPE lists everything the claim rests on, and nothing in its cone is a
`postulate`. Then:

* the correspondence cone builds under `--safe` (Agda rejects every postulate there: D087);
* a false assumption makes the theorem VACUOUS, not the development INCONSISTENT — a postulate of an
  empty type is `⊥`, usable by every proof downstream (this happened twice: `RuntimeContract`,
  plan 0.100 P0; `as-faithful-<arch>`, D272);
* each assumption has a MODEL on the apex (`Once.Certified.Models`, D302), so non-vacuity is a type
  obligation, not a probe someone has to remember to run.

This is CakeML's shape: the machine and loader assumptions are hypotheses of the top-level
theorem, the logic has no axioms, and the theorem is instantiated for concrete targets and,
through the bootstrap, a concrete program. HOL additionally refuses a constant "satisfying P"
without a proof of `∃x. P x`; in Agda the models are how we get that back.

## The rule that decides each entry

An assumption may become a hypothesis only if it is about the OUTSIDE WORLD — the CPU, the
assembler, the loader, the OS, the FFI, a finite resource. A fact about our own code (emitter,
IR, typechecker, arith lowering) is a PROOF GAP: it is proved, never turned into a hypothesis —
that would be a shim (MERGE.md §1): an obligation hidden by making the claim conditional on it.

Data (a type, a function between inhabited types: `decode`, `assemble`) is harmless as an
assumption. A PROPOSITION (an equation, a "faithful" law, a record with laws) can be empty, and
owes a model.

## Phases

**A — Models on the apex (DONE, D302, on `plan-0.91-program-facts`).** `CertifiedBuild.nonvacuous :
NonVacuous` with `an-interp` (the interpretation that declares nothing) and `runtime-model`.

**B — `ArchModel`.** One record per arch (or one record over `Arch`) holding the 30 CPU-model and
loader entries; `Once.Certified` takes three of them, beside the `ResourceBounds`. Top-down
(MERGE.md, "top-down: change first"): change `Certified`'s parameters first, follow the red down
to each `postulate` site, delete it. Expect the parameter to thread through `Compiler`, the three
`ArchCorrectness.<arch>` clusters and `Adequacy/CPU/<arch>`; bundle, do not split, the telescope
(the mutual-block OOM lesson: many module parameters → bundle them in one record).

**C — World and resources.** `external-sigop-contract` becomes a field of what an interpretation
promises (next to `Interp`'s `Impl`, where D061 put the contracts); `conc-fuel` joins
`ResourceBounds`.

**D — Models for every new hypothesis record.** `ArchModel` needs a model of its propositional
fields: for `as-faithful` this means a toy decode/assemble/print triple that is faithful, for
`step-budget-adequate` a trivial machine. If a model cannot be built, the field is FALSE as
stated — that is the finding, fix the statement (D272 is the precedent).

**E — `--safe` on the correspondence cone.** Once only proof gaps remain as postulates, they are
the only `--no-safe` sites; move each into one `Once.Pending` module (visible, counted) and mark
the cone `--safe`. A `pragma-gate`-style ratchet keeps it there.

**F — One concrete instance (the real non-vacuity witness).** A concrete Once program, a
concrete interpretation, and a proof that every hypothesis — the three `ArchModel`s, the
`ResourceBounds`, `BlockRunsHyp` — holds FOR IT, with `once-certified` applied. This is the
analogue of CakeML's bootstrap and replaces the per-type models in `NonVacuous`: per-type models
show each hypothesis inhabited, only an instance shows them satisfiable TOGETHER.

## Lessons kept from the 2026-04 version (its addenda)

* Visibility is necessary, not sufficient: a visible but catch-all axiom (`generic-sem` over any
  `String`) is still a laundering vector. Every assumption must be reachable only by its genuine
  producer (plan 0.38 / D061 did this for SigOps; keep it true for `ArchModel` — no field
  quantified over arbitrary code that the emitter never produces).
* A conversion that could be unsound carries its faithfulness proof in its type; a bare value
  with no relation to its input is the smell.
* `--safe` does not catch trivial bodies (a wildcard clause producing a trivial value): only
  top-down derived theorems do.
