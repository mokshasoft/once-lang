# Plan 0.10: Close the Verification Gap (Option A)

## Context

Today's compiler verification has a structural disconnect: the *verified*
function (`Once.CCC.Target.X86-64.Correct.compile-correct`) and the
*extracted* function (`Once.Compile.compile = compile-ir`) are different
functions. The `compile-correct` theorem is about a path through the
verified Dispatcher → AbstractTrace → arch-Program; the extracted
binary's behavior is governed by a parallel direct `compile-ir : IR →
Program`. There is no theorem connecting the two — `Correct.agda`
admits this in its header:

```
--   ⊕ Full theorem: CONNECTED via ir-to-x86-correctness
```

`ir-to-x86-correctness` is referenced in comments but has never been
written. Practically: we could change `compile-ir` to `_ = ud2 ∷ []`
and the proof would still go through, because the proof talks about a
function we don't extract.

This is "Gap 1" in the verification-gap analysis (the most important
gap, more important than Plan 0.9's catch-all-class). Plan 0.9 made the
*abstract semantics* honest. This plan makes the *extracted compiler*
be the *verified compiler*.

## Goal

Make the extracted `compile : IR A B → Program` definitionally and
provably equivalent to the verified path:

```agda
compile = compile-trace ∘ ir-to-trace
```

where:
- `ir-to-trace : IR A B → ℕ → ℕ × AbstractTrace` — pure-data IR
  lowering to AbstractTrace, structurally identical to the trace
  emitted by `Dispatcher.run-ir-wf` (just with proofs erased from
  the signature).
- `compile-trace : AbstractTrace → arch-Program` — already exists
  per-arch (`AbstractToX86`, `AbstractToX86-32`, `AbstractToRiscV`).

After this plan, all three target archs share the same shape:

```
                shared (verified once)
                        ↓
    IR  ──ir-to-trace──▶ AbstractTrace
                        │
            ┌───────────┼───────────┐
            ▼           ▼           ▼
   compile-trace  compile-trace  compile-trace
      (X86-64)      (X86-32)      (RiscV64)
            │           │           │
            ▼           ▼           ▼
          Program     Program     Program
```

Per-arch porting cost reduces to: `Syntax.agda`, `DirectSimulation.agda`,
`compile-trace`, `Emit.agda`. No per-arch IR-to-instructions, no per-arch
correctness proof of pair/curry/apply.

## Methodology: Top-Down with Explicit Postulates

We do NOT prove bottom-up. We write the **top-level theorem first**,
with `postulate`s filling every sub-obligation. The proof typechecks
immediately. Then we incrementally discharge each postulate, working
from the top down.

This methodology has three properties we want:

1. **The architecture is in place from day one.** Every refactor after
   the first commit is "discharge a postulate" — no architectural
   surprise, no half-built scaffolding.
2. **Gaps are visible.** `make postulates-grep` lists every unproven
   obligation. The audit surface shrinks monotonically as proofs land.
3. **Layer 0 ships before all postulates are gone.** The binary works
   as soon as the data flow is wired (Phase 3); proofs harden behind it.

## Phase A — Top-Level Theorem with Postulates

The grand statement: *the binary's runtime state corresponds to
`eval ir x`*. Since assembler/loader/CPU are outside the formal system,
the proof boundary is `compile`. We state:

```agda
-- For every IR term, every input value, every initial machine state
-- that represents the input value: executing the compiled Program
-- transitions the machine state to one that represents eval(ir, x).
postulate
  compile-correct :
    ∀ {A B} (ir : IR A B) (x : ⟦ A ⟧)
    → (initial : ArchState)
    → InitialRepresents initial x
    → let final = exec-arch (compile ir) initial
      in FinalRepresents final (eval ir x)
```

This is a single postulate at the top. Everything below decomposes it.

**Decomposition** — `compile = compile-trace ∘ ir-to-trace`:

```agda
postulate
  ir-to-trace-correct :
    ∀ {A B} (ir : IR A B) (x : ⟦ A ⟧)
    → (abs-init : AbstractState)
    → AbsInitialRepresents abs-init x
    → let abs-final = exec-abstract (ir-to-trace ir) abs-init
      in AbsFinalRepresents abs-final (eval ir x)

postulate
  compile-trace-correct :
    ∀ (trace : AbstractTrace) (abs-init : AbstractState)
    → (arch-init : ArchState)
    → ArchAbstractCorresponds arch-init abs-init
    → let abs-final  = exec-abstract trace abs-init
          arch-final = exec-arch (compile-trace trace) arch-init
      in ArchAbstractCorresponds arch-final abs-final
```

`compile-correct` is then derivable by composition:

```agda
compile-correct ir x init init-repr =
  let abs-init = abstract-of-arch init
      abs-final = exec-abstract (ir-to-trace ir) abs-init
      arch-final = exec-arch (compile ir) init
      _ : ArchAbstractCorresponds arch-final abs-final
      _ = compile-trace-correct (ir-to-trace ir) abs-init init ⋯
      _ : AbsFinalRepresents abs-final (eval ir x)
      _ = ir-to-trace-correct ir x abs-init ⋯
  in transfer-correspondence ⋯
```

(Schematic — actual signatures will need `Frame`, `AllocState` etc.;
the existing `Corresponds` machinery from `Once.CCC.Target.X86-64.DirectSimulation`
provides the relations.)

**Phase A deliverable:** the file `Once.CCC.Codegen.CompileCorrect.agda`
typechecks. It contains 2 postulates (`ir-to-trace-correct` +
`compile-trace-correct`) and the derivation of `compile-correct`. Zero
new code in any other module. Zero behavior change.

## Phase B — Wire ir-to-trace into the Extraction

`ir-to-trace` (the data function) currently exists as
`Once.CCC.Codegen.IRToTrace.ir-to-trace` (from the multi-arch work),
covering only the simple-IR subset. Extend it to the full Layer 0
subset:

- **`curry f mode`**: emit closure construction via `instr-push-frame` /
  slot-store / `lea-slot` for the closure address. Mirror the trace
  shape that `Once.CCC.Machine.IR.CurryWF.curry-trace` emits.
- **`apply`**: emit "consume (closure, arg) pair" via
  `load-from-slot` / `load-indirect` / `instr-call-closure`. Mirror
  `Once.CCC.Machine.IR.ApplyWF.apply-full-trace`.
- **`⟨ f , g ⟩ m`**: mirror `Once.CCC.Machine.IR.PairWF2.pair-trace`.
- **`SigOp si`**: see Phase B' below.
- **`case`, `inl`, `inr`**: mirror `SumRecWF` (post-Layer-0).
- **`Cata`, `Para`, `Out`, `in-ν`, `Ana`, `Hylo`, `Fuse`**: mirror
  `RecCoreWF` etc. (post-Layer-0).

**State threading:** `ir-to-trace : IR A B → ℕ → ℕ × AbstractTrace`.
The `ℕ` is the slot frontier — the running `next-slot` counter.

**Phase B':** SigOp dispatch. Add an `instr-sigop : SigOpInfo A B →
AbstractInstr` constructor to `Once.CCC.Machine.SMCore.AbstractInstr`.
Each arch's `compile-abstract` decodes by name (`exit`, `lit.int.<N>`,
etc.). Update `Once.CCC.Target.<arch>.AbstractTo<arch>.compile-abstract`
accordingly.

**Phase B deliverable:** `ir-to-trace` is total over the Layer 0 IR
subset. The pair/curry/apply emissions are syntactically identical to
`PairWF2`/`CurryWF`/`ApplyWF` (set up to make Phase D's equivalence
proof a `refl`-chain, not a `cong`-tree).

## Phase C — Switch X86-64 to the AbstractTrace Path

Today: `Once.Target.X86-64.x86-64-irToAsm ir = programToText (compile-ir ir)`.

After Phase C: `x86-64-irToAsm ir = programToText (compile-trace (proj₂ (ir-to-trace ir 0)))`.

`compile-trace` for X86-64 is `Once.CCC.Target.X86-64.AbstractToX86.compile-trace` (already exists; Plan 0.9 Phase B made its DirectSimulation honest).

**Phase C deliverable:** the X86-64 binary is now generated by the
verified path. The lea-offset bug class is closed by construction
(closure construction goes through `instr-call-closure` /
`instr-push-frame`, not the bespoke `lea r9 (rip+disp 4)`). Layer 0
binaries should run.

`Once.CCC.Target.X86-64.CodeGen.Compile` (the bespoke path) becomes
unused. Move to `Once.CCC.Target.X86-64.Legacy.DirectCompile` with a
deprecation comment, OR delete outright.

**Phase C is the Layer-0-shipping milestone.** After C: `make
test-x86-level0` passes. Plan 0.2.4 (Categorical Layer 0) closes.

## Phase D — Discharge `compile-trace-correct`

`compile-trace : AbstractTrace → Program` is per-arch; its correctness
is per-arch. The structure already exists:

- `Once.CCC.Target.X86-64.DirectSimulation.trace-simulation` is a
  per-AbstractInstr simulation lemma (semi-complete, structure done).
- Same for X86-32, RiscV64 (DirectSimulation files exist; Plan 0.9
  Phase B closed their bug-hiding catch-alls).

`compile-trace-correct` is built by induction over `AbstractTrace`,
delegating to per-instruction simulations. For each `AbstractInstr`,
the existing `exec-x86-<instr>` clause is matched against the
arch-Program emission of `compile-abstract`.

**Phase D deliverable:** the per-arch `compile-trace-correct`
postulate is replaced by a real proof. Done independently per arch;
X86-64 first.

## Phase E — Discharge `ir-to-trace-correct`

`ir-to-trace-correct` says: the trace `ir-to-trace` emits, when
executed abstractly, simulates `eval ir`. The cleanest proof:

1. Show `ir-to-trace ir frontier` produces the SAME trace as
   `Dispatcher.run-ir-wf <ir> <frontier> <required-proofs> = trace`.
   By structural induction on IR, with `refl` per case if the trace
   expressions match.
2. Use `Dispatcher.run-ir-wf`'s existing correctness (encoded in
   `IRResultAWF.trace-correct`) to lift to `ir-to-trace`.

**Connection lemma:**

```agda
ir-to-trace-agrees-with-dispatcher :
  ∀ {A B} (ir : IR A B) (frontier : ℕ) (proofs : ⋯)
  → let (frontier' , trace) = ir-to-trace ir frontier
        result = Dispatcher.run-ir-wf … ir frontier proofs …
        dispatcher-trace = IRResultAWF.trace result
    in trace ≡ dispatcher-trace
ir-to-trace-agrees-with-dispatcher id frontier _ = refl
ir-to-trace-agrees-with-dispatcher (g ∘ f) frontier _ = ⋯  -- cong
ir-to-trace-agrees-with-dispatcher (⟨ f , g ⟩ m) frontier _ = ⋯
… etc per IR constructor
```

If Phase B's emissions match `*WF` modules' shapes exactly, each
clause is `refl` or a short `cong`-chain.

**Phase E deliverable:** the `ir-to-trace-correct` postulate is
replaced by a real proof. Independent of arch.

## Phase F — Audit + Documentation

After E and D land for at least one arch:

1. `make postulates-grep` lists what's left.
2. The remaining postulates are exactly the *un-formalized parts of the
   trusted base*: RuntimeContract, FrameOps, sigOp-proof,
   escape-survives, plus assembler/loader/CPU (which are external).
3. Document the trusted-base postulates in `docs/compiler/trusted-base.md`
   with what each represents and how to discharge it.
4. Decision log entry: **D050: compile-correct is now a theorem about
   the extracted `compile`** — single sentence with the architectural
   change.

|---|---|---|---|
| Today (pre-plan) | ~5 | runtime, frame-ops, escape-survives, sigOp-proof, ir-to-x86-correctness (TODO comment) | — |
| Phase A | 7 | + ir-to-trace-correct, compile-trace-correct | — |

| Phase C | 7 | — | — (Layer 0 ships here) |
| Phase D (per arch) | 6 | — | − compile-trace-correct (one per arch as it lands) |

| Final (after D for all 3 archs + E) | ~4 | — | runtime/frame-ops/escape-survives/sigOp-proof remain (trusted base) |

The 4 trusted-base postulates are RuntimeContract / FrameOps /
escape-survives / sigOp-proof. Each is a separate plan. They represent
"the things outside the verified system" — calling-convention
contracts, escape-analysis correctness for stack allocation, syscall
semantics. They're documented, not eliminated, in this plan.

## Risks

1. **Phase E's syntactic-equivalence proof might not be `refl`.** If
   `ir-to-trace`'s emissions don't exactly match `*WF` modules' trace
   shapes, the lemma needs `cong`-chains and Agda's pattern unification
   may struggle. Mitigation: design Phase B's emissions to mirror the
   `*WF` modules verbatim (same operator order, same slot arithmetic,
   same intermediate variables). This is mechanical but requires
   discipline.

2. **`Dispatcher.run-ir-wf` requires proof state to call.** To get the
   trace out, we'd need to construct dummy proof state. Alternative:
   factor the trace-emission out of `run-ir-wf` into a pure helper
   (`run-ir-trace-only`) that `run-ir-wf` then wraps with proofs. Phase
   B can build `ir-to-trace` from `run-ir-trace-only` directly, making
   the agreement lemma trivial.

3. **SigOp `instr-sigop` extension** affects every existing
   `compile-abstract` (3 archs × 1 new clause), every DirectSimulation
   (3 archs × 1 new clause), and the `IRResultAWF` machinery (need a
   trace-correctness clause for SigOp). Could be its own sub-plan.
   Alternative: skip SigOp from `ir-to-trace` and route it via a
   per-arch hook (less uniform but smaller blast radius).

4. **X86-64 `compile-ir` legacy use.** If anything outside
   `Once.Target.X86-64` still calls the bespoke `compile-ir`, Phase C
   leaves stale references. Audit before removing.

## Implementation phases (ordered)

### Phase A — Top-level theorem with postulates (1 commit, ~half day)

1. Create `Once.CCC.Codegen.CompileCorrect`. Define:
   - `compile-correct` derived from two postulates.
   - The two postulates `ir-to-trace-correct` and `compile-trace-correct`.
2. Wire it into `Once.CCC.EntryPointCCC.X86-64.compile-correct` (re-export).
3. Verify `make compiler` is green.

**End state:** the top-level theorem typechecks. `make postulates-grep`
shows two new postulates. Behavior is unchanged (no extraction
changes).

### Phase B — Complete `ir-to-trace` (2-3 commits, 1-2 days)

1. Per IR constructor not yet handled by `IRToTrace.agda`, add the
   trace emission, mirroring the `*WF` module's `trace = …` field
   exactly. State: `ℕ → ℕ × AbstractTrace`.
2. Add `instr-sigop : SigOpInfo A B → AbstractInstr` to `SMCore.agda`.
3. Add `compile-abstract (sigop si)` to all three `AbstractTo<arch>`
   modules (per arch, dispatch by `SigOpInfo.name`).
4. Update each `DirectSimulation.exec-<arch>` to handle the new
   `sigop` clause (initially via named postulate per Plan 0.9
   discipline, since SigOp semantics is per-arch and unmodeled
   abstractly).
5. Verify `make compiler-all` green; smoke-test that `ir-to-trace
   exit-ir` produces a non-trivial trace.

### Phase C — X86-64 switches to AbstractTrace path (1 commit, half day)

1. Change `Once.Target.X86-64.x86-64-irToAsm` to use `compile-trace
   ∘ ir-to-trace`.
2. Remove import of `Once.CCC.Target.X86-64.CodeGen.Compile`.
3. Move `Once.CCC.Target.X86-64.CodeGen.*` to `Once.CCC.Target.X86-64.Legacy.*`
   (or delete; nothing else depends on it).
4. Re-extract MAlonzo, rebuild cabal.
5. Run `make test-x86-level0`. **Layer 0 binaries should pass.**

This is the Layer-0-shipping milestone.

### Phase D — `compile-trace-correct` per arch (1 commit per arch)

For each arch:
1. Create `Once.CCC.Target.<arch>.CompileTraceCorrect`.
2. Prove `compile-trace-correct` by induction on `AbstractTrace`,
   delegating to existing per-instruction simulations.
3. Replace the postulate in `CompileCorrect.agda` with the proof for
   that arch.

X86-64 first (most complete DirectSimulation), then X86-32, then
RiscV64.

### Phase E — `ir-to-trace-correct` (multi-commit, depends on Phase B
shape choices)

1. Choose strategy: factor `Dispatcher.run-ir-wf` (recommended) OR
   prove equivalence by `cong`-chains.
2. If factoring: introduce `run-ir-trace-only : IR → ℕ → ℕ ×
   AbstractTrace` in `Dispatcher.agda` such that `run-ir-wf = wrap
   run-ir-trace-only with proofs`. Update Phase B's `ir-to-trace` to
   re-export `run-ir-trace-only`.
3. Prove `ir-to-trace-correct` by structural induction, leaning on
   Dispatcher's existing per-IR-construct correctness lemmas
   (`SimpleWF.run-id-correct`, `PairWF2.run-pair-correct`, etc.).
4. Replace the postulate in `CompileCorrect.agda`.

### Phase F — Audit + decision log (half day)

1. Run `make postulates-grep`. Confirm the remaining postulates are
   the trusted-base ones.
2. Write `docs/compiler/trusted-base.md` listing them.
3. Decision log **D050: Verified compile = extracted compile**.
4. Update `plans/README.md` — close 0.10.

## Success criteria

- `compile-correct` typechecks, in the same module as the actual
  extracted `compile`, with the same `compile` arg.
- `Once.CCC.Target.X86-64.CodeGen.Compile.compile-ir` is no longer
  called from any extracted code path.
- `make postulates-grep` lists exactly the trusted-base postulates +
  whatever is still in flight.
- `make test-x86-level0` passes (Layer 0 binaries exit with expected
  codes).
- `make compiler-all` + `make malonzo` + `cabal build` clean.

## Relationship to other plans

- **Supersedes** the architectural intent of plan 0.2.4.2 (closure
  codegen fix). Phase C closes the lea-offset bug class by
  construction, since the bespoke `curry-closure-setup` is gone.
- **Builds on** Plan 0.9 (exact-split). The constraint `exec-x86`'s
  honesty is what makes `compile-trace-correct` provable rather than
  vacuously true.
- **Builds on** the Multi-arch work that just landed. The architecture
  it sets up — three archs sharing `ir-to-trace` and `compile-trace` —
  is fully realized after Phase C of this plan.
- **Independent of** 0.6 / 0.6.1 (user polymorphism). User
  polymorphism is a frontend concern; this plan is the codegen-
  correctness backbone.

## Author's note

This plan is the proof-architecture's keystone. After it lands, every
gap in the compiler-correctness story is *named* — either it's a
remaining postulate (visible to `make postulates-grep`) or it's a
documented trusted-base assumption. The combinator "we have a
verified compiler" stops being aspirational and becomes precisely
checkable.

The top-down methodology means **the architecture is in place after
Phase A**, before any actual proof work. Layer 0 ships at Phase C,
before the deepest proofs land. Subsequent phases are pure
risk-reduction: each one shrinks the trusted base by one item, and
every `make compiler` run between phases is fully green.
