# Plan 0.105 — An FFI contract's meaning is a parameter, not a postulate

## 0. The property

> **The Spec says what a program means relative to the contracts of what it imports. It never
> invents a value for a contract.**

D061 decided this on 2026-06-17: "the core is parameterized over an abstract `Interpretation`
… `classify-name` / `generic-info` / `generic-semM` are deleted". Plan 0.38 M0.1 landed,
M0.2 (threading the parameter) did not, and since then every plan that touched the area
removed one *use* and left the postulate:

* D225 (plan 0.98) removed its use at `Void` on the effectful path;
* D244/D246 (plan 0.103) took internal calls off it, since an internal call now means its
  callee;
* D231 rejects a pure FFI arrow into `Unit`/`Void` (`HonestFFI`).

## 1. The measurement (verified 2026-10-02)

* **The apex is inconsistent.** `generic-semM : ∀ {A B} → String → TargetNum → M.⟦ A ⟧ →
  M.⟦ B ⟧ᵍ` (`Arith/SigOp/Builders.agda:216`) is in `Once.Certified`'s import cone, and

      bot : TargetNum → ⊥
      bot fmt = generic-semM {Unit} {Void} "x" fmt _

  typechecks. It has been on master since plan 0.2.4.1.
* **The Spec uses it.** The core rule `⊢sigop` means `GradedOps.sigOpRefᵛ`, which goes through
  `value-info` / `arrow-info` to `generic-semM`. D246's "import environment" is the
  environment of imported ONCE modules; FFI contracts are not in it.
* **Restricting the type cannot fix it.** `HonestFFI (μ-type _) = ⊤`, and a μ-type can be
  empty (`μ X. X`, `μ (K Void)`). Any postulate "a value at every honest type" stays
  inconsistent, so there is no cheap stopgap.
* **Sites** (code uses, not comments): `Arith/SigOp/Builders`, `Denotation/{GradedOps, Meaning,
  SourceDenote, Realize}`, `Adequacy/{SourceFaithful, MeaningBridge}`, `Surface/{Desugar,
  Elaborate}`, `TypeCheck/{Elaborate, ElaborateProofs}`.

## 2. The second defect, in the same rows

An `eff` arrow into a DATA codomain (not `Unit`, not `Void`) falls to `arrow-info-eff`'s last
clause, `value-info`. So `read : Eff Unit Int` is specified as SILENT and as a fixed function
of its argument. That is false of every real input op. The fix needs a decision, not just a
proof (§4, decision 2).

## 3. The encoding

**One environment per program, indexed by its FFI declarations.** The core program already
lists them: a `bffi` entry extends the scope, and a reference to it elaborates to `sigop c A`
(`Spec.Elaboration.importE`). Let `Imports p` be that list of `(c , A , HonestFFI A)`.

    FFIEnv : Imports → Set        -- one contract RESULT per declared import
    runProgram : TargetNum → (p : Program) → FFIEnv (imports p) → ℕ → List SigOpEvent

* **The environment supplies results, never events.** The observable of a call is fixed by
  the Spec: one `mk-event c A arg` (D058). An effectful contract at `Unit` emits and returns
  `tt`; at `Void` it emits and stops (`Res`, D225). Only the RESULT at a data codomain (and
  a pure contract's value) comes from the environment. So no environment can make the
  compiler look correct by inventing events.
* **The core rule's meaning reads it.** `⟦ ⊢sigop c k h g ⟧` looks `c` up in the environment,
  exactly as `ref d` looks up the definitions environment. `sigOpRefᵛ`, `value-info` and
  `generic-semM` are deleted.
* **The IR reads the same environment.** `evalᴰ`'s `SigOp` clause, for an FFI info, reads it,
  just as `Call` reads the table (D244). The `SigOpSem` constructor for an FFI contract
  carries the NAME and its declared type, not a value.
* **The apex quantifies over it.** `correct : ∀ ι → exec (linked with an implementation of
  ι) ≋ ⟦ p ⟧ ι`. The arch-level `external-sigop-contract` becomes a HYPOTHESIS about the
  linked library ("the code at symbol `c` implements `ι c`"), which is exactly D061 point 3
  (proof-or-postulate per SigOp × target, supplied off-line by the interpretation's author).
* **Consistency by construction.** A program importing an uninhabited contract has no `ι`, so
  the theorem says nothing about it. That is correct: no library implements such a contract.
  Nothing proves ⊥.

## 4. Decisions to record before Phase B (decision-log entries)

1. **The encoding of §3** (supersedes the `generic-semM` half of D061's implementation note).
2. **The result of an effectful data contract.** The options:
   * (a) a function of the argument: `ι c : ⟦A⟧ → Res ⟦B⟧`. Simple, but two reads with the same
     argument return the same value, which no input op satisfies.
   * (b) a function of the event history so far (a world STRATEGY): `ι c : List SigOpEvent →
     ⟦A⟧ → Res ⟦B⟧`. Faithful to input: what `read` returns may depend on everything the
     program has done. `Behavior` becomes "for every world, a trace". This is the
     game-semantics / interaction-tree reading of D058.
   * (c) defer: keep (a) for pure contracts and REJECT `eff` arrows into data codomains in
     `HonestFFI` until (b) is designed. The language loses input until then.

   Recommendation: (b). The events already ARE the interaction; (b) only lets the answer
   depend on them, and the per-program quantifier of §3 is the same quantifier either way.
   Cross-check against plan 0.96 (IO is not a construct) before deciding.

## 5. Phases (top-down)

**0. Probes, before any edit.**
* `arith-sigop-contract` (`ConcFlatSim`, x86-64 and riscv64) concludes `env (once-symbol-path
  name) ≡ just pl` for ANY `effect si ≡ Pure`, and a pure FFI op is `Pure`. Probe whether it
  is refutable for a program with one pure FFI call. If it is, it is a second inconsistency on
  this path, and Phase D must split the arith contract from the FFI one by the `SigOpSem`
  constructor (D255's `primV` already identifies arith by meaning).
* Grep the Haskell side for `generic` / interpretation stand-ins in `compiler/`, since the
  extracted compiler must not change behaviour (the compiler never reads `semM`, per D061's
  update).

**A. The Spec.** `FFIEnv`, the `⊢sigop` meaning clause, `runProgram`'s new argument, the
`CorrectCompiler` statement quantified over `ι`. Then follow the red.

**B. The meaning layer.** `GradedOps`, `Meaning`, `SourceDenote`, `Realize`: the FFI
reference reads `ι`. `value-info` / `arrow-info`'s FFI clauses and `generic-semM` are
deleted, and the comparison postulates in the same block are NOT touched (separate defect,
below).

**C. The IR and the bridges.** `SigOpSem`'s FFI constructor, `evalᴰ`'s SigOp clause,
`SourceFaithful`, `MeaningBridge`, `CoreBridge`/`TeleWalk` (one more environment threaded,
agreeing at every scope, as `σR` does).

**D. The backend.** `external-sigop-contract` (×3 arches) becomes the per-`ι` library
hypothesis on the apex, next to `BlockRunsHyp`. Decide with the Phase-0 probe whether
`arith-sigop-contract` needs the constructor split.

**E. Gate.** Certified green; `generic-semM` has zero references; the `⊥` probe no longer
typechecks; the extraction run (MAlonzo + `cabal test`) with no change to emitted code.

## 6. Out of scope, recorded

* `lt-semM … ne-semM` are still postulated, pending a Bool-encoding decision (the comment at
  `Builders.agda:98`). They are consistent (the codomain is inhabited) but they are not
  definitions, and D055 says the primitives are DEFINED. A follow-on row, the same shape as
  the div/mod change in plan 0.103 (D255).
* Lifting stoppedness into `Behavior` (plan 0.97 §6's follow-on row).

## 7. Risks

* Threading one more environment through the telescope walk and the meaning bridges is wide
  but mechanical: it is the `σR` / call-environment pattern a third time.
* Decision 2(b) changes what `Behavior` is. If it is taken, `_≋_` and every Behavior law
  (`behavior-by`) gain the world quantifier. Cost it after Phase A, before committing to B.
