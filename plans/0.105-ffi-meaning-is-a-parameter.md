# Plan 0.105 — An FFI contract's meaning is a parameter, not a postulate; `Eff` means an interaction tree

## 0. The property

> **The Spec says what a program means relative to the contracts of what it imports. It never
> invents a value for a contract.**

D061 decided this on 2026-06-17: "the core is parameterized over an abstract `Interpretation`
… `classify-name` / `generic-info` / `generic-semM` are deleted". Plan 0.38 M0.1 landed,
M0.2 (threading the parameter) did not, and since then every plan that touched the area
removed one *use* and left the postulate:

* D225 (plan 0.98) removed its use at `Void` on the effectful path;
* D244/D246 (plan 0.103) took internal calls off it, since an internal call now means its
  callee;
* D231 rejects a pure FFI arrow into `Unit`/`Void` (`HonestFFI`).

## 1. The measurement (verified 2026-10-02)

* **The apex is inconsistent.** `generic-semM : ∀ {A B} → String → TargetNum → M.⟦ A ⟧ →
  M.⟦ B ⟧ᵍ` (`Arith/SigOp/Builders.agda:216`) is in `Once.Certified`'s import cone, and

      bot : TargetNum → ⊥
      bot fmt = generic-semM {Unit} {Void} "x" fmt _

  typechecks. It has been on master since plan 0.2.4.1.
* **The Spec uses it.** The core rule `⊢sigop` means `GradedOps.sigOpRefᵛ`, which goes through
  `value-info` / `arrow-info` to `generic-semM`. D246's "import environment" is the
  environment of imported ONCE modules; FFI contracts are not in it.
* **Restricting the type cannot fix it.** `HonestFFI (μ-type _) = ⊤`, and a μ-type can be
  empty (`μ X. X`, `μ (K Void)`). Any postulate "a value at every honest type" stays
  inconsistent, so there is no cheap stopgap.
* **Sites** (code uses, not comments): `Arith/SigOp/Builders`, `Denotation/{GradedOps, Meaning,
  SourceDenote, Realize}`, `Adequacy/{SourceFaithful, MeaningBridge}`, `Surface/{Desugar,
  Elaborate}`, `TypeCheck/{Elaborate, ElaborateProofs}`.

## 2. The second defect: the meaning of `Eff` cannot receive

An `eff` arrow into a DATA codomain (not `Unit`, not `Void`) falls to `arrow-info-eff`'s last
clause, `value-info`. So `read : Eff Unit Int` is specified as silent and as a fixed function of
its argument: two `getLine`s are equal. The language does not say so — D250 makes only PURE
arrows referentially transparent — but the Spec's model of `Eff` cannot say otherwise.

The cause is the trace monad. `T X` is a budget-indexed trace plus a `Res X`: a WRITER. It can
record what a computation emits, and nothing can flow back in. A Writer coincides with the right
model only when every operation answers `Unit`.

## 3. The design: a computation is an interaction tree

**The general statement (D250 is its pure instance).**

> A computation of grade π means an INTERACTION TREE over the operations π permits: either done
> with a value, or a call `op(arg)` with a continuation awaiting the operation's answer.

* **pure** permits no operations, so its tree is a value. This is D250, unchanged.
* **eff** permits the program's SigOps. `read` is a call whose continuation receives the answer,
  so two reads are two calls with independent answers.
* **Halting needs no flag.** An operation answering `Void` (`exit`) has a continuation that can
  never be invoked; 0.98's `stopped` is that case.
* **Effects stay arrows and stay composable.** This is algebraic effects, not world-passing:
  programs never see a world, and `>>=` grafts continuations.

**The contract (what an interpretation's author owes).** The compiler knows only each import's
NAME and declared type. An interpretation answers calls. The compiler's theorem is

    ∀ interpretation ι that meets its contract →
      the binary, linked against ι's implementation, makes the same calls as ⟦ p ⟧ and continues
      with the same answers

What `getLine` does, or a read from `/dev/urandom` or a bare-metal port, is the interpretation's
business. D061 point 3 holds: per SigOp × target, the implementation is proved (a verified
kernel) or postulated (Linux), off-line, by the interpretation's author.

**Pure contracts are values, not calls.** A pure import is referentially transparent (D250), so
it is a fixed function supplied by the interpretation, never a node of the tree. This keeps the
optimizer and the arith rewrite free to move pure calls and never effectful ones.

**The observable is derived.** D058 stands: correctness is the sequence of effectful SigOp events.
Running a tree against an interpretation yields that sequence (the calls made). Answers are not
observed separately; they are determined by the interpretation and the calls before them.

**Consistency by construction.** A program importing an uninhabited pure contract has no
interpretation, so the theorem says nothing about it. That is correct (no library implements
such a contract), and nothing proves ⊥. `generic-semM` is deleted.

## 4. Decisions to record (decision-log entries)

1. **`Eff` means an interaction tree; `T` is replaced** (§3). This generalizes D250 and subsumes
   0.98's `stopped`. Supersedes the Writer reading of `T` (plans 0.97/0.98).
2. **FFI contracts are the program's parameter** (supersedes the `generic-semM` half of D061's
   implementation note): pure imports are values the interpretation supplies; effectful imports
   are operations it answers.
3. **The world answers; it does not stop.** An effectful call at a data or `Unit` codomain always
   gets an answer; stopping happens exactly at a `Void` codomain. An input that can fail is a sum
   the program sees (`Eff Unit (Int + Err)`), not a hidden stop.

  not change behaviour (it never reads `semM`, per D061's update).

*Phase 0 result (2026-10-02).*
* Both contracts are FALSE as stated, read off their consumer (`FlatCore.EventDispatch.sigop-step`,
  which dispatches on `effect si` alone):
  * `arith-sigop-contract` is taken for EVERY `Pure` SigOp, and a pure FFI op (`pureV`) is `Pure`.
    Its symbol is not in the arith environment, so the promised payload does not exist.
  * `external-sigop-contract` is stated for EVERY `si` and concludes `env sym ≡ nothing`. That
    is false for an arith block, whose symbol IS in the environment.
  Both are the "state premise, program conclusion" shape. Phase 4 splits the dispatch by the
  `SigOpSem` constructor: `primV` is arithmetic, and every FFI operation (pure or effectful) is
  external. No formal ⊥ term was built: constructing a reachable `CompiledCorr` state costs more
  than it would tell.
* Haskell: no interpretation stand-ins (`compiler/src` never reads `semM`).

**1. The tree, as a POC (the gate for the whole plan).** In a spike module, outside the apex:
* the tree type over an operation signature, its `return`/`>>=`, and the monad laws;
* infinite programs: `main` never returns (plan 0.97), so trees are infinite. Decide the
  representation by the typechecker: a coinductive/guarded tree, or a depth-indexed one in the
  style of today's budget (D058's prefix family). The budget view must survive as the observable;
* running a tree against an interpretation to the depth-`n` event prefix, and the prefix-family
  laws (`extends`/`bounded`/`saturating`) for the result;
* 0.98's `Res` and the halting rows as the `Void`-answer instance.
*Gate:* the laws hold, postulate-free. If the representation fights the budget view, stop and
decide before touching the Spec.

*Phase 1 result (2026-10-02): GATE PASSED.* `Once.Spike.ITree` (12 s, postulate-free beyond the
standing `extensionality`) has:
* the tree, its monad laws, and the run of a bind as the runs of its parts with the history threaded;
* the budget observable `take n` of a run's events, with the prefix-family laws (bounded, extends,
  saturating);
* the instances: no operations is a value (`pure-iso`), operations answering `⊤` give the same run
  under every interpretation (today's Writer), and a halting operation ends the run.
Two findings:
* **The tree is INDUCTIVE.** Once is total, and every trace in the development is `capN n` of a finite
  list. Coinduction stays where it already is, in `νᵈ`'s layers.
* **Halting is its own node, `halt o a`, with no continuation.** Interpretations then answer every
  answering call totally (they are never asked a halting one). With `Res`-returning interpretations
  a world could stop at any call, contradicting decision 3; with total answers a `Void`-answering
  call would have no interpretation at all, making every halting program vacuous. The node is read
  off the declared codomain (`Void`), as `haltsV` already is.

*Integration estimate.* `T` appears in 61 apex modules, about 2200 occurrences (`SourceFaithful` 422,
`TraceMonad` 279, `CoherenceLaws` 162, `SourceDenote` 128, …). The sweep, top-down:
* `T X = Tree OnceSig X`, with ONE universal signature: an operation is a SigOp key (canonical name and
  declared types), its argument the machine value, its answer the codomain's value (`⊤` for `Emits`);
  `Halts` operations are `halt` nodes. `returnT` is `ret`, `>>=T` the tree bind, emitting a call
  answered by `⊤`.
* Pure FFI values come from the interpretation's pure half, a parameter of the meaning (not calls).
* Observables gain the interpretation: `projTrace ι t n = take n (events of run ι t)`; the apex
  quantifies over `ι`.
* Phase 4: the flat machine's SigOp step reads the same oracle for an answering call's result.

*Phase 2 design (2026-10-02; one sweep, the user chose "all at once" over a staged swap).*
* **`T` is the tree** (`Denotation.TraceMonad`): `ret`, `call` (answering), `halt`; the monad laws
  are equalities; the observable is a run against an interpretation, which makes every
  observable a prefix family (`projTrace-pf`).
* **First-order values only cross the domains.** `forget`/`inject` exist at base types only
  (`forgetᵇ`/`injectᵇ`); the functor coercions take `WellFormedF`. There is no erasure of an
  effectful closure or stream: it would have to run, and a run needs answers.
* **FFI contracts are first-order** (forced by the ABI: a library returns a register value, never a
  Once closure). `IsConcrete`'s arrow case takes base domain AND base codomain, and
  `SigOpInfo.conB` becomes `IsBaseType B`. All 187 signatures in the repo already comply.
* **`SigOpSem`** keeps `pureV`/`primV` (internal, computed), `emitsV`/`haltsV`, and gains `ffiV`
  (a pure FFI contract: its value is the interpretation's) and `callsV` (an effectful FFI contract
  answering data: a `call` node). `generic-semM` is deleted.
* **`semM` takes an answer function** (`CanonicalName → (A B : Type) → M.⟦A⟧ → M.⟦B⟧`): internal
  operations ignore it; FFI operations ask it. The machine builds it from the interpretation and
  its event log; the meaning never calls `semM` for FFI operations.
* **The meaning's FFI values come from the call environment.** `CallEnv` becomes a record:
  internal calls plus the interpretation's pure half. An `ffiV` SigOp means the pure half at its
  argument (a value, so referential transparency holds by type); a `callsV` SigOp is a `call`.
* **An unlinked call halts** on a reserved operation (the environment must be total; linked
  programs never reach it). The tree has no silent stop.
* **The machine** (Phase 4, in this sweep): the flat state gains an event log; an answering
  call's result is the interpretation's answer at that log; the concrete contracts refer to the
  log through the correspondence. `FrameSemantics` instances become functions of the
  interpretation.
* **The Spec**: `runProgram`, `⟦_⟧` and `CorrectCompiler` take the interpretation; correctness
  quantifies over it.

*Phase 4 decision (2026-10-02): the CONCRETE machine writes the answer; no apex hypothesis.*
The text above is superseded. Two ways to say what an external call does to the binary's state:
* (a) **the machine model writes the answer.** `ArchSemantics.run-trace` takes the interpretation;
  the shared concrete loop (`RunTraceCore`) threads the binary's own event log, and its external-call
  step logs the event, writes `answer ι log op arg` into the arch's return register and returns.
  The only trust is the ABI contract ("a called function returns its result in the return
  register and preserves sp and the callee-saved registers"), stated once, as a definition, in
  the machine semantics that is already the trusted CPU/OS model (`decode`, `assemble`,
  `run-trace`). Everything on our side stays PROVED: the argument is where the callee reads it,
  the result is read from where the callee leaves it, the logs agree, the states still correspond.
  Each arch restates its `external-sigop-contract` against the defined step. (Correction,
  2026-10-02: the contract is a POSTULATE on all three arches, riscv64 included — its
  `conc-flat-sim` is a proof modulo the two SigOp contracts — so nothing proved is re-proved;
  what changes is that the contract now speaks about a DEFINED step, which is what makes it
  checkable and dischargeable later.)
* (b) an apex hypothesis "after any external call the concrete state corresponds to the flat one".
  Less to prove, but `CompiledCorr` is the COMPILER's invariant (register layout, sp, frame), so a
  bug in how our code passes the argument or reads the result would hide in the assumption — the
  D161/D165 fault (compiler logic inside a toolchain axiom), in the "state premise, program
  conclusion" shape — and on riscv64 it would replace an existing proof with an assumption.

**Chosen: (a)** (user, 2026-10-02). At a non-register codomain the flat machine writes its unit
sentinel (`call-sigop-val … nothing`); the concrete step writes the same, so the two agree there
and the value obligation stays `obs-correct-sigop-rest`'s.

*FOUND (2026-10-03): `Interp` was EMPTY, so the apex was vacuous* (resolved below). Machine-checked:
`Once/Probe/InterpEmpty.agda` proves `Interp → ⊥` (`answer ι [] (callOp n Unit base-Unit Void) tt`).
The universal signature asks every interpretation to answer EVERY `(name, dom, cod)`, including
uninhabited codomains; `FFIAnswers` has the same hole. Every `FrameSemantics` carries an `Interp`,
so every module parameterized by one is vacuous too. Options:
* **(A) Interpret the PROGRAM's contracts (recommended).** `Interp σ` is indexed by the program's
  import signature `σ` (each imported name with its declared types) and answers only those. The
  §3 sentence then holds literally: a program importing an uninhabited contract has no
  interpretation, and only THAT program's claim is vacuous. Spec: `Interpretation` indexed by the
  program's signature (read off `Typed`), `exec` at an interpretation of the binary's imports.
  Cost: the index threads where `Interp` already threads (`FrameSemantics.fs-interp`, `CallEnv`,
  the three CPUs, the obligation layer). It is wide, but it follows the existing ι paths.
* **(B) Keep one universal signature, restrict it to inhabited codomains.** `CallOp`/`FFIAnswers`
  carry an inhabitation witness (a Void-free base type), and a contract whose codomain is
  uninhabited is classified as halting, or rejected by `HonestFFI`. Smaller, but it is a new
  language rule ("an uninhabited codomain halts"), and `Void * Int` codomains need a verdict.
* (C) Partial answers (`Maybe`). Rejected: it contradicts decision 3 (the world answers).
*RESOLVED (2026-10-03, with the user): D061 already says it — three times.* Neither (A) as first
built (29/n: a world PROVIDES contracts, the run decides membership) nor (B) is the principle.
D061 separates:
1. **building the compiler** — the apex is proved once, over an ABSTRACT interpretation; no
   interpretation (Linux, seL4, a user's) is built in, all are equal;
2. **compiling a user program** — the extracted `once` binary has no Agda, does not know which
   interpretation will be linked, sees only the DECLARED signatures and effects, trusts them, and
   cannot check a contract proof;
3. **off-line, per interpretation** — its author discharges each SigOp's contract, proved or
   postulated per SigOp × target.
The FORM of a contract is the COMPILER's decision (`semM` + the `EffectShape` read off the declared
type, D225): interpretations follow the compiler, and the compiler never looks inside one.

**The design.** The core is parameterized over an interpretation in TWO parts, matching times 2
and 3:
* its **declared signatures** `Σ` (each SigOp's canonical name and declared FFI type) — what time 2
  sees. A program is TYPED against `Σ`: `⊢sigop c A` requires `(c , A) ∈ Σ`.
* an **implementation** `Impl Σ` in the compiler's contract form — what time 3 proves: a value
  for each pure member, an answer (given the calls before it) for each answering member; an
  emitting or halting member owes no value. It is TOTAL on `Σ`.
The apex: for every `Σ`, every program typed against `Σ`, every `Impl Σ`, the binary behaves as the
meaning. The `Σ` of a program is the signatures it was compiled against (its signature
declarations, inlined from the interpretation's modules); an interpretation declaring more
restricts to it.

**Why the probe failed, and why this fixes it.** `Interp → ⊥` came from making one interpretation
answer EVERY conceivable SigOp. An author who declares an unimplementable one (an answering call
into `Void * Int`) cannot discharge it at time 3: their failure, and no compiler claim becomes
false. `Impl Σ` is inhabited exactly when `Σ` is implementable.

**Consequences for the code (supersede 29/n's provision machinery).**
* `TraceMonad`: `Σ`, `Impl Σ`; the interpretation the IR and the machines read is a `Σ` with an
  `Impl Σ`. The SPEC meaning reads `Impl Σ` by membership, with no decision and no fallback.
* The IR evaluator is a total function on UNTYPED IR, so it reads contracts by name; a SigOp outside
  `Σ` is unlinked — the twin of D244's internal calls (`tableCalls [] = unlinkedT`), unreachable
  for a program linked against `Σ` (`Linked`'s SigOp case). The flat machine and the concrete
  resolver likewise (a sentinel word there).
* The Spec core: `Sig` carries `Σ`; `⊢sigop` carries its membership; the meaning's environment is
  `Impl Σ`; `sigOpRefᵛ` reads it. The surface meaning means every import reference by its
  import entry (as `t-var-import` already does).
* Naming: a reference must resolve to the SigOp's canonical name in `Σ` (the user's rule: a SigOp's
  identity is its RESOLVED canonical name). Today one FFI declaration has three names (entry
  `bare x`, qualified `bare "alias.name"`, resolved `cn`); `CoreEnv` proves each kind consistent,
  but membership in `Σ` needs one. Canonicalize at the first level that has the information.

**Phases (top-down).** a. `TraceMonad`/`Info`: `Σ` + `Impl Σ`, restructuring 29/n. b. Spec core:
`Σ` in `Sig`, `⊢sigop` membership, `Impl Σ` environment, `sigOpRefᵛ`. c. Surface meaning: references
mean their entries. d. FFI identity canonical where membership needs it (follow the red). e. IR,
`Linked`, bridges. f. Spec record: the trace conjunct for programs linked against an
interpretation's `Σ`. g. `decode-unread`/`decode-boxed` (below). Then §5.

Once `Interp` is inhabited, a second hole surfaces: `SMCore.decode-unread : IsBaseType A →
StoredValue → ⟦ A ⟧` gives `⊥` at `base-Void`, and `decode-boxed` decodes a boxed argument from
the pointer alone (memory-independent, so it is refutable by two states sharing a pointer). The
principled fix is the same in both: decode from MEMORY (`readTyped`, with `readTyped-adequate`),
never from the register value alone.

**5. Gate.** Certified green; `generic-semM` has zero references; the `⊥` probe no longer
typechecks; the extraction run (MAlonzo + `cabal test`) with no change to emitted code; an
input-reading test program (two reads that differ) in the exit tests.

## 7. Risks

* **`T` is the most-used structure in the development.** Every `T` law, `RelT`, `behavior-by`,
  `CataErased`/`AnaErased`, the IR meaning and the obligation layer's traces are written against
  it. Phase 1 exists to price this before the Spec changes; budget it as a top-down sweep, not a
  refactor.
* **Infinite trees and the budget.** The observable is indexed by event count. A coinductive tree
  must still give a prefix family; if guardedness fights it, the depth-indexed tree is the fallback.
* Threading the interpretation through the telescope walk is the `σR` / call-environment pattern
  a third time: wide but mechanical.
