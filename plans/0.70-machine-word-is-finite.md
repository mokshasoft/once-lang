# Plan 0.70 — The Machine Word Is Finite

**Status**: not started. Written 2026-08-13, out of plan 0.65's G2 port.
**Blocks**: nothing. **Blocked by**: nothing. Resume 0.65 G2 after this.

## Why

All three target semantics say

    Word   = ℕ
    Memory = Word → Maybe Word
    add    = _+_          sub = _∸_        (truncated)

Real registers are fixed-width and modular. So the models are not a coarser
view of the machine, they are a DIFFERENT machine — D103's phrase, and this is
the same class of defect one layer down.

`add` diverges only past 2^64. **`sub` diverges at small values**: `3 ∸ 5 = 0`
in the model, `2^64 − 2` on hardware. Truncated subtraction is not modular
subtraction, and the gap opens at the first subtraction that would go negative.

D054 ALREADY DECIDED AGAINST THIS for the language: Once's `Int` denotes a
modular `Once.Word` (carrier `ℕ` in `[0, modulus)`, ops `⊕ ⊖ ⊗ ⊝` via `norm`,
width-parameterised). The tree therefore carries both notions, meeting at
`FlatCore.FlatCorrespondence.lit-word : Carrier → Word` — a modular value
injected into an unbounded one, with nothing checking the seam.

### Why nothing has caught it

The ABSTRACT flat machine uses the same arithmetic — `sv-pred (SV-Tag 0) =
SV-Tag 0` clamps exactly as `∸` does — so both sides diverge from hardware
TOGETHER and agree with each other. The correspondence is TRUE. The divergence
lands in `<arch>-loader-faithful`, which is precisely where D103's
code-address defect was hiding. Two gaps, one hiding place; that is a fact
about the axiom, not a coincidence.

## THE DECISION THAT COMES FIRST — addresses are not values

Do not start by replacing `ℕ` with `Once.Word` everywhere. Measure first (this
was measured 2026-08-13, numbers below), because the correspondence uses the
machine word for TWO different jobs and they want different treatments.

**As a VALUE** (register contents, what `Int` computes) the word is modular.
That is D054, and it is not in dispute.

**As an ADDRESS** the model relies on ORDER and CANCELLATION, and modular
arithmetic supplies neither:

    lemma            uses   survives modularly?
    m≤m+n             17     NO   — `x ⊕ 1` can be BELOW `x`
    <-transˡ          14     the transitivity survives; the ORDER does not
    m∸n+n≡m            4     YES, and improves: `(x ⊖ y) ⊕ y ≡ x` always
    +-monoʳ-<          4     NO
    +-cancelˡ-≡        3     YES — `⊕` is cancellative in ℤ/nℤ
    *-cancelʳ-≡        3     **NO, and this one is load-bearing**

`slot-addr-inj` is `*-cancelʳ-≡ k slot slot-size (+-cancelˡ-≡ …)`: distinct
slots get distinct addresses by cancelling `* slot-size`. Modularly that is
FALSE — `slot-size` is 8, not a unit mod 2^64, and `8 * 0 ≡ 8 * 2^61`, so slot
`0` and slot `2^61` would share an address. Every stack window argument rests
on this.

And the layout separation (`hfront ≤ lo ≤ %rsp`, the virgin region
`[hfront, lo)`, `dom-below`) is an ORDER-THEORETIC argument. There is no total
order on `ℤ/2^64ℤ` compatible with `⊕`.

**So the answer is not "make addresses modular".** It is the one CompCert
reaches for: addresses stay ORDERED and BOUNDED, and the boundedness becomes an
explicit carried invariant — the program's memory lives in a region that does
not wrap. That is TRUE of every real program (the loader hands you a contiguous
region well inside the space) and it is exactly what today's proofs assume
silently.

    VALUES    modular `Once.Word`   — wrapping is the semantics
    ADDRESSES ordered ℕ + a NO-WRAP invariant — wrapping is a precondition
                                       violation the invariant excludes

Today one type does both jobs, which is why the question looks harder than it
is.

## Phases

### A — SPLIT THE TWO JOBS, no semantics change yet

Give the target semantics two names: `Word` (register/memory CONTENT) and
`Addr` (what `Memory` is indexed by, what `effectiveAddr` returns, what the
layout is ordered by). Both `= ℕ` for now, so this phase is definitionally a
no-op and must land with four clusters green and the ledger untouched.

The value is the TYPE ERROR it creates later: once they are distinct names,
"this proof treats a value as an address" stops being invisible. Expect the
split to be non-obvious in exactly the interesting places — `lit-word`,
`instr-load-code-addr` (a code ADDRESS in a register), `SV-Ptr`'s encoding, and
the return addresses in `RetAddrs`.

GATE: no proof changes at all. If a proof needs editing, the split is in the
wrong place — that is the phase's own test.

### B — THE NO-WRAP INVARIANT for addresses

Carry `region-fits : hfront ≤ lo ≤ %rsp < 2^bits` (the exact shape falls out of
`HeapView`'s existing fields — it already carries `front-lo` and `lo-le`, so
this is one more conjunct, not a new structure).

Then every ordering lemma above is REJUSTIFIED rather than deleted: `m≤m+n`
holds because the sum stays in the region. `slot-addr-inj` holds because
`base + k * slot-size < 2^bits` makes the multiplication injective on the range
that occurs.

This is where the `fits`/`room` premises that already exist to tame `∸` get
GENERALISED rather than removed — they are the same statement, currently made
one site at a time.

GATE: four clusters green; the resource-bound PARAMETERS (D087) may gain
conjuncts, which is a ledger-visible change to their types — no row added or
weakened.

### C — VALUES BECOME MODULAR

`Word = Once.Word.Width bits .Word`, `add = _⊕_`, `sub = _⊖_`, and `∸`
disappears from the three semantics.

Then fix the ABSTRACT side to match: `sv-pred (SV-Tag 0) = SV-Tag 0` is the
clamp that makes today's correspondence true, and it has to become the wrap.
**Do not fix only the machine** — that would make the correspondence FALSE
rather than the model faithful, which is the D090 lesson ("fix the model in the
flat machine, not in a premise") pointed the other way.

GATE: four clusters green AND the three exit-test suites still 55/0, on all
three arches. Phase C is the one that can change what a compiled program does.

### D — CLOSE THE SEAM

`lit-word : Carrier → Word` becomes the identity (both sides modular at the
same width), and `word-eq`-style equations tie the target's `bits` to the
frame semantics' word size. The residual ledger's "THE UNBOUNDED-REGISTER
MODEL" section is deleted, not reworded.

## What this will break, stated up front

Phase B and C will break proofs, and that is the content rather than the cost:
**every break marks a place the current proof quietly assumes an infinite
register file.** Expect them concentrated in

- the window/frame arithmetic (`win-at`, `windows-*`, `StackWindows`),
- `slot-addr-inj` and everything downstream of it,
- `descend-view` / `untouched` (the virgin region is an interval),
- `sim-alloc-stack` / `sim-thunk` / `sim-call`, whose `fits` premises are the
  ∸-taming ones.

If a break cannot be repaired by the region invariant, that is a REAL
divergence and belongs in the ledger, not in a workaround.

## Order and scope

A is safe and mechanical. B is the substantial one and can land alone. C
changes the machine and should not be attempted until B is green, because
without the region invariant the ordering proofs have nothing to stand on.

**Do NOT do this inside plan 0.65.** 0.65 is extracting an arch-generic core
and its gate is "the ledger diff is empty"; this plan changes what the machine
IS and will move the ledger. Finish 0.65's G2/G3 first — the extraction makes
this plan cheaper anyway, since after it there is ONE correspondence to change
instead of three.

## Relationship to D054 and D103

- **D054** decided values are modular and moved the LANGUAGE off `ℤ`. This is
  the same decision applied one layer down, to the MACHINE MODEL, which D054
  did not touch.
- **D103** found a model that was a different machine and repaired it. This is
  the same shape at a different scale: there the value was a code address, here
  it is every arithmetic result.
- Both were shielded by `<arch>-loader-faithful`. A worthwhile side effect of
  this plan is that the axiom gets narrower for a second time.
