# Plan: Prove encode-is-betanf without OOM

## Goal
Prove that all encoded terms are in beta-normal form:
```agda
encode-is-betanf : ∀ {A B} (t : Term A B) → IsBetaNormalForm (encode t)
```

Where `IsBetaNormalForm t = ∀ {u} → ¬ (t ⟶β u)`

## Key Insight
Every encoding has form `In ∘ body` where `body` is built from `{inl, inr, terminal, ⟨_,_⟩}` and nested encodings. None of the beta-redex patterns match this structure.

## Beta Rules to Rule Out

**Top-level patterns** (head doesn't match `In`):
- `id ∘ f`, `f ∘ id` - head is `id`
- `fst ∘ ⟨f,g⟩`, `snd ∘ ⟨f,g⟩` - head is `fst`/`snd`
- `[f,g] ∘ inl`, `[f,g] ∘ inr` - head is `[_,_]`
- `apply ∘ ⟨curry f, g⟩` - head is `apply`
- `cata F alg ∘ In` - head is `cata`
- `Out ∘ In` - head is `Out`
- `⟨fst, snd⟩`, `[inl, inr]` - exact forms, not `In ∘ ...`

**Only pattern with `In` as head**:
- `In ∘ Out` - but encodings have `In ∘ inl/inr ∘ ...`, never `In ∘ Out`

**Congruence rules** - must show subterms also have no beta-redexes:
- Subterms of encodings are also encodings (recursive)
- Type encodings (`⌜_⌝Ty`, `⌜_⌝Func`) also have no beta-redexes

## OOM Prevention Strategy

Based on codebase patterns:

1. **Use `abstract`** for main proof to prevent term expansion
2. **Separate helper lemmas** for:
   - `In-not-redex-head`: `In` doesn't match most beta heads
   - `In-Out-mismatch`: `In ∘ inl/inr` ≠ `In ∘ Out`
   - `data-constructors-stable`: `inl`, `inr`, `terminal` have no redexes
   - `type-encode-betanf`: type encodings are beta-normal
3. **Case analysis on `_⟶β_`** derivation, not on term structure
4. **Use `where` clauses** for local private helpers

## Proof Structure

**Key observation**: `encode t = In ∘ body` where body is `inl/inr ∘ ... ∘ payload`

Case analysis on `encode t ⟶β u`:

1. **β-in-out** (`In ∘ Out`): body is `inl/inr ∘ ...`, not `Out` - contradiction
2. **β-∘-l** (In reduces): `In` is atomic, has no reductions - contradiction
3. **β-∘-r** (body reduces): Need to show body has no reductions (recursive)
4. **All other rules**: Require head `id/fst/snd/[]/apply/cata/Out`, not `In` - contradiction

For β-∘-r, body is built from `{inl, inr, terminal, ⟨_,_⟩}` and nested encodings:
- Atoms (`inl`, `inr`, `terminal`) have no direct beta rules
- `⟨ f, g ⟩` could have β-eta-pair (`⟨fst,snd⟩→id`) but encoding pairs are never `⟨fst,snd⟩`
- β-pair-l, β-pair-r require subterms to reduce - recursive call

```agda
-- Mutual induction for type/func/term encodings
mutual
  abstract
    type-encode-betanf : ∀ (A : Ty) → IsBetaNormalForm (⌜ A ⌝Ty)
    type-encode-betanf A = ... -- same structure as term encoding

    func-encode-betanf : ∀ (F : Func) → IsBetaNormalForm (⌜ F ⌝Func)
    func-encode-betanf F = ... -- same structure

    encode-is-betanf : ∀ {A B} (t : Term A B) → IsBetaNormalForm (encode t)
    encode-is-betanf t {u} step with step
    ... | β-in-out F = In≠inl/inr contradiction
    ... | β-∘-l In-reduces = In-atomic contradiction
    ... | β-∘-r body-reduces = body-no-redex body-reduces
    ... | β-id-left = In≠id contradiction  -- etc for other rules
```

**Helper to show atoms don't reduce**:
```agda
private
  In-no-reduce : ∀ {F u} → ¬ (In {F} ⟶β u)
  In-no-reduce ()  -- no beta rule matches bare In

  inl-no-reduce : ∀ {A B u} → ¬ (inl {A} {B} ⟶β u)
  inl-no-reduce ()

  -- etc for inr, terminal
```
