# Plan 0.144 — No module needs more memory than the machine has to spare

## Summary

Checking the proofs takes more memory than this machine can comfortably give. Every few days a check
runs out of memory, and the work stops while we raise limits and retry. We now have a measurement of
every proof file: how long it takes and how much memory it needs, each on its own. A small group of
files causes almost all of the trouble. This plan rewrites those files, using a few techniques that have
already worked in this project, until each one fits with room to spare. When it is done, a full check
runs at the default limits, and a new file that is too heavy is noticed when it is added, not weeks
later.

## 1. Why

On 2026-11-05/06 the merge gates of plan 0.143 ran out of memory four times: the backstop needed its cap
raised to 6G, and the AST dump needed 12G, after `Resusp.Id`, `Laws.Combinators` and `Laws.Categorical`
each exhausted the heap in turn. None of these modules was changed by 0.143. The same has happened on
earlier merges (`ConcFlatSim` in `run-ast-dumps.sh`'s header). Each time the limit was raised and the
cause left in place, so the margin shrinks with every new module. Running out of memory also costs
time far beyond the module: a kill means hours of rechecking, and a night lost when it happens unattended.

## 2. Where we are (measured 2026-11-06)

`formal/scripts/agda-profile.py --ref master` (`3c8a5ddd8`): 787 modules (every module the backstop
checks), each checked in its own Agda process with its imports already built, from a staged tree with an
empty `_build`. Results: `~/.cache/once-profile/master/profile.tsv`; `make -C formal profile-report`.

**Group B — heavy because of what they import** (live / imported modules / lines):

group B is lower priority: watched, not targeted.

**Why the gates still run out although every module fits alone:** `make certified`, the backstop and the
AST dump check many modules in ONE process, which keeps what it has checked. The heaviest modules then
run on top of an already large heap. Making group A light helps every gate; checking bottom-up in
separate processes (as the profiler does) is the other lever, for the gates themselves (step 5).

## 3. Decisions

- **B1, the target — DECIDED 2026-11-06:** every module at most **3 GB peak RSS** alone (about 1.5 GB
  live), so two Agda sessions can run side by side on this machine.
- **B2, the ratchet — DECIDED 2026-11-06:** NO profile data is committed. `make profile-gate` profiles only
  the modules a branch changes (against the merge base) and fails when one exceeds the B1 target. A merge
  gate (MERGE.md §5) only with the user's approval of the wording.
- **B3, the order — DECIDED 2026-11-06:** it does not matter; every module above the target is fixed.
  The steps below group them by shared pattern.

## 4. Steps

Each fix is measured the same way: `agda-profile.py --root <module>` on a committed state, before and
after, numbers in the commit message. Proofs do not change meaning: no postulate, no pragma, no
weakened statement; the module's exported types stay as they are (its consumers do not change).

1. **The `Resusp` family.** Apply the `Pair/Pres` pattern: `abstract` around the step lemmas whose
   consumers need only their type (the `trans` chains `hr10`, `ns10`, `sf10`, `hru10`, `nsu`, `sfu`,
   the `cf*`/`mem*`/`nh*` families, `result`); share the nine-row build through `NineStepPres` where
   `SumR`/`SumL` still unfold it by hand. Measure which blocks move the peak; keep only those.
2. **`CataBr.FoldRound`, `FoldPre`, `ToFold`, `CataConst.Call`, `IterRounds`.** Same pattern; where
   one term chains many steps, split it into typed pieces (as `Resusp.Id`'s `srC`/`srB`/`sr`).
3. **`Metatheory.Laws`: `MapV`, `Categorical`, `LetCase`, `Combinators`.** Profile first what is slow
   (these allocate 400–640 GB: unfolding of `⟦_⟧` or the derived combinators during conversion is the
   likely cause); then `abstract`/`opaque` the definitions the laws only need by their equations, or
   state intermediate lemmas with their types so Agda does not re-derive them.
4. **`Pair`** (739 s, 1.46 TB allocated) and **`TypeCheck.SpecWitness`.** Find the term that unfolds
   (Agda's `-v tc.decl:10` / profiling options on the one module), then the same patterns.
5. **The gates.** With group A under the target, rerun `make certified`, the backstop and the AST dump at
   their DEFAULT limits. If one still runs out, change the gate, not the limit: the backstop and the dump
   check bottom-up in separate processes (the profiler's order), so no gate holds more than one module's
   work.
6. **The ratchet** (B2): `make profile-gate` (the modules changed since the merge base, profiled with
   their imports built; fails above 3 GB), and the heap notes in `run-ast-dumps.sh` and `agda-safe.sh`
   updated to the new numbers.

## 5. Done when

Every module is at most the B1 target alone (`make profile-report` on master); `make certified`, the
backstop and the AST dump pass at their default limits on a quiet machine; and a branch that adds a
module above the target is caught by `make profile-gate` (B2). After the 13 modules above 3 GB, the
heaviest today are `CataBr.ToFold` (3.07 GB peak, 1.4 GB live, 51 s, at the line) and
`Adequacy.CoherenceS` (2.9 GB, 1.1 GB live, 111 s, 192 GB allocated): a fix that lands above them has
not finished.
