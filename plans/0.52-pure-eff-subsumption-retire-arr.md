## One-line

The grade (purity, later capabilities) is a **checked, runtime-erased typing
refinement**. The pure→eff direction is **subsumption** (`pure ⊑ eff`, a check),
never a **coercion term**. `arr` — the last pure→eff coercion — is retired.

## Why (the principle, see D068)

- `evalᴰ apply` is kind-polymorphic; `evalᴰ arr f = returnT f` (identity). The
  grade is a **phantom IR index**: present in the *type*, ignored by codegen
  (the IR is grade-erased, D046; `realize-morph` ignores `π`, D066).
- D065 already dropped **bare** `arr` (type error) and made bare morphisms
  grade-free. The only `arr` left is **applied `arr f`** (the closure lift,
  `t-arr-app-check`): a pure function *value* used at an eff arrow.
- That last `arr f` is a **no-op coercion** (`⟦arr f⟧ = ⟦f⟧`). OCP-0007's rule is
  "annotation is a **check, never a coercion**"; the QTT discipline (the
  `Zero/One/Many` quantity is already QTT's `{0,1,ω}` semiring) is that grade
  annotations are **tracked, checked, erased** — adjusted by subsumption, not
  coercion terms. `arr` is the pure/eff analogue of an explicit `0→ω` coercion,
  exactly what QTT avoids.

## Monotone, not free (the D066 guardrail)

Subsumption is **one-directional**: `pure ⊑ eff` (use a pure thing where eff is
allowed) is sound; `eff ⊑ pure` is **UNSOUND** (D066 — the optimizer drops pure
SigOps, so tagging an effectful SigOp pure drops effects). So this is *monotone*
subsumption up the grade lattice — which is precisely OCP-0007's **attenuation**
(authority only ever relaxes downward; you never fabricate it). The grade stays
load-bearing in the surface type for the effect/capability analysis; only the
*adjustment mechanism* changes (check, not term).

(a) as "irrelevant Kind field."

### M2 conceptual grounding (why `arr` is retirable, and why (b) is forced)

**`arr` is an identity morphism wearing two type-indices — `const` is a real morphism.**
This is the distinction that makes `arr` retirable and `const` permanent:
- `const` (`m-const`, Judgment:466): `⊢ᵍ e ∶ B → ⊢ᵐ e ∶ A ⇨[π] B` (value → function).
  Denotation `⟦ m-const gv ⟧ᵐ = λ _ → returnT ⟦ gv ⟧ᵍ` (Meaning:133) — a GENUINE constant
  function `λ_→b`. Real denotational content; must have a spec; never erasable.
- `arr` (`arr'`): `(A ⇒[pure] B) → (A ⇒[eff] B)` (function → function, same space).
  Spec denotation `⟦ arr' f ⟧ˢ dγ = ⟦ f ⟧ˢ dγ` (SourceDenote:150) — literally the
  IDENTITY. Carries zero information; changes only the grade INDEX in the type.

**`arr` DOES have a spec — the spec is that it does nothing.** The lift (a pure function
used at an eff arrow) is NOT surface syntax; it is the typing rule `t-subsume` (a
derivation node the elaborator inserts, like a silent subtyping coercion). Its meaning
is pinned by `realize (t-subsume d) = arr' (realize d)` (Realize:156) + `⟦arr' x⟧ˢ=⟦x⟧ˢ`,
so `⟦ t-subsume d ⟧ˢ = ⟦ d ⟧ˢ`. The implementation inserts one trivial `returnT` (empty
trace); `faithful (arr' f) = cong₂ _,_ (++-identityʳ _) refl` (SourceFaithful:154) proves
that empty-trace return is invisible. So the lift is REAL at the type level, IDENTITY at
the value level — the textbook "checked, erased refinement."

**`IR` is a Hom; `arr` is a categorical wart.** `IR : Type → Type → Set` is a category
(objects = Types, morphisms = IR). Today `A ⇒[pure] B` and `A ⇒[eff] B` are DISTINCT
objects joined by `arr`, a non-`id` constructor that denotes as `id`. Ungraded `IRTy`
collapses them to ONE object (`⌊A⌋ ⇛ ⌊B⌋`), so `arr ≡ id` (removable) and the
identity/coherence laws hold DEFINITIONALLY. This is why (b) helps the categorical /
directed-type (dHoTT: morphisms = directed paths) foundation, not just proof size:
`Hom(X,X)` gets `id` as THE identity, no parallel identity-in-disguise.

### FORM DECISION — architecture (b) separate `IRTy` (settled 2026-07-14)

Forced by the OCP roadmap, not just proof convenience:
- **OCP-0009** mandates a **two-language split** — expressive graded surface elaborating
  to a **small, fixed, erased runtime core** ("runtime core stays fixed the whole way
  up… zero runtime cost") — and its **Rung 5 QTT erasure invariant** (index/proof/grade
  is multiplicity-0 erased, "erasable-by-construction"). `IRTy` IS that total core.
- **OCP-0007** keeps the grade `Kind = Quantity × Purity × Capabilities` on the SURFACE
  arrow as "a compiler-side label… a check, never a coercion." The grade lives ABOVE the
  object language and is erased below — exactly the surface(graded)/IRTy(ungraded) split.
- **(a) grade-irrelevant field is independently ruled out**: the surface checker DECIDES
  purity (`≟k`/`≟p`), and an irrelevant field is not decidable; since IR objects = surface
  `Type`, you cannot have the grade relevant (surface) and irrelevant (IR) on one field.

So M2 is the concrete realization, for the purity component, of OCP-0009's erasure
invariant. M3 then swaps surface purity for the OCP-0007 capability lattice — the SAME
"grade on the surface Kind, erased into IRTy" mechanism, generalized.
