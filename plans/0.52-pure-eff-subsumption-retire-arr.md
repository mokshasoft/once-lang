# Plan 0.52 — retire `arr`; pure→eff is monotone subsumption, not a coercion

status: scoped (2026-06-30). NOT started. Enables OCP-0007; aligns with QTT for a
dependent-types future. Decision: D068.

## One-line

The grade (purity, later capabilities) is a **checked, runtime-erased typing
refinement**. The pure→eff direction is **subsumption** (`pure ⊑ eff`, a check),
never a **coercion term**. `arr` — the last pure→eff coercion — is retired.

## Why (the principle, see D068)

- `evalᴰ apply` is kind-polymorphic; `evalᴰ arr f = returnT f` (identity). The
  grade is a **phantom IR index**: present in the *type*, ignored by codegen
  (the IR is grade-erased, D046; `realize-morph` ignores `π`, D066).
- D065 already dropped **bare** `arr` (type error) and made bare morphisms
  grade-free. The only `arr` left is **applied `arr f`** (the closure lift,
  `t-arr-app-check`): a pure function *value* used at an eff arrow.
- That last `arr f` is a **no-op coercion** (`⟦arr f⟧ = ⟦f⟧`). OCP-0007's rule is
  "annotation is a **check, never a coercion**"; the QTT discipline (the
  `Zero/One/Many` quantity is already QTT's `{0,1,ω}` semiring) is that grade
  annotations are **tracked, checked, erased** — adjusted by subsumption, not
  coercion terms. `arr` is the pure/eff analogue of an explicit `0→ω` coercion,
  exactly what QTT avoids.

## Monotone, not free (the D066 guardrail)

Subsumption is **one-directional**: `pure ⊑ eff` (use a pure thing where eff is
allowed) is sound; `eff ⊑ pure` is **UNSOUND** (D066 — the optimizer drops pure
SigOps, so tagging an effectful SigOp pure drops effects). So this is *monotone*
subsumption up the grade lattice — which is precisely OCP-0007's **attenuation**
(authority only ever relaxes downward; you never fabricate it). The grade stays
load-bearing in the surface type for the effect/capability analysis; only the
*adjustment mechanism* changes (check, not term).

## Scope / milestones

- **M1 — surface subsumption.** In `checkElabV`, when checking a value/closure of
  pure arrow `A ⇒[pure] B` against an eff arrow `A ⇒[eff] B`, accept it directly
  (the `pure ⊑ eff` check) instead of requiring `arr`. Retire surface `arr`
  (both the name and `t-arr-app-check`); `m-arr` and the `arr` IR constructor go
  with it. Soundness obligation: `pure ⊑ eff` subsumption is denotation-preserving
  — **trivial** (`⟦_⟧` is grade-blind), one identity lemma replacing the
  `arr'`/`ahv-arr` coercion-correctness lemma.
- **M2 — kill the kind-splits (optional, big proof win).** Investigate erasing the
  `mk-kind q π` index from the IR exponential **object** (not just `realize-morph`).
  Codegen already ignores it (`apply` kind-poly). If purity tracking for the
  optimizer rides on SigOp contracts (D061), not arrow grades, the object index is
  removable — collapsing every `mk-kind Many/One/Zero × pure/eff` case-split in the
  agree/codegen proofs (apply, ahv-arr, the RVar mirror). VERIFY the optimizer
  soundness (Plan 0.39) does not read purity off the arrow object before doing this.
- **M3 — generalize to the lattice (OCP-0007).** Once `pure ⊑ eff` subsumption is
  in, swap the two-point `{pure,eff}` for the capability lattice; subsumption
  becomes attenuation (`S ⊑ S'`), inferred bottom-up by union, checked top-down.

## Consequences

- **Proofs:** deletes `arr` codegen + `arr'`/`ahv-arr` lemma + `m-arr` + the `arr`
  bbc machinery; M2 deletes pervasive kind-splits. Correctness spec stays grade-free
  (it already is); grade soundness is a separate, smaller static-analysis property.
- **Programs:** drop `arr f` (rare); strictly more programs accept (subsumption).
  No expressiveness change (`arr` is denotationally identity).
- **Spec:** already grade-blind; no observable change.
- **Re-extract MAlonzo** (touches the live elaborator).

## Relationship to the RVar work (Plan 0.51 residual)

The check-mode RVar bbc value cases (`check-agreeV-todo` = {RVar}) carry the
`mk-kind` kind-splits this plan's M2 removes. Either (a) finish RVar first against
the graded objects and let M2 simplify it later, or (b) do M1/M2 first so RVar is
written once against erased objects. `bbc-other`'s poly path is blocked on
`bbc-other-poly-witness` regardless (orthogonal — poly-instantiation completeness).
