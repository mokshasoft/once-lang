# Plan 0.110 — The start state assumes less

## 0. The property

> **The proof assumes only what a loader or a reset handler actually guarantees: `pc` at the
> entry point, `sp` in a stack region, `.bss` zeroed. Every other register (and the flags) holds
> an UNSPECIFIED value, and the compiler's `_start` establishes whatever the correspondence needs.**

## 1. The measurement (2026-10-05)

* `initialState` (`Adequacy/CPU/<arch>`) is `initStateAt entry`, which is
  `mkstate (writeReg emptyRegFile <sp> stack-top) emptyMemory initFlags entry false`. ALL other
  registers are 0, and so are the flags.
* `stack-top` is already the right shape: an opaque postulated `Word` (inhabited type, no axiom
  about it), so every theorem holds whatever its value.
* The correspondence at pc 0 (`entry-corr`, `ArchCorrectness/<arch>.agda`, ×3) proves six register
  equalities by `refl`: input, closure, output, scratch, count, and the heap frontier. Each holds
  only because the register is 0 and the flat entry value (a filler, or the empty frontier)
  encodes to 0.
* **The `lea` is decorative.** `_start` lowers to `lea <heap-reg>, once_heap_base; sub sp, slots`
  (x86-64 `AbstractToX86.agda:278`, x86-32 `AbstractToX86-32.agda:286`, riscv64 the `lla`
  form). The proof's own comment says "emptyRegFile's %r15 ≡ 0 ≡ the entry frontier": the
  frontier corresponds BEFORE the `lea` runs. If the emitter dropped the `lea`, the apex would stay
  green. That is D261's class of bug (start code the proof does not constrain).
* On bare metal the registers really are garbage at reset. Under Linux, `exec` zeroes most of them,
  but that is a property of one OS, and Once targets both (0.107 §2½).

## 2. The design

1. **Unspecified, not zero.** Per arch, `boot-regs : RegFile` and `boot-flags : Flags` (riscv64:
   no flags) are opaque postulates, exactly like `stack-top`, and
   `initStateAt e = mkstate (writeReg boot-regs <sp> stack-top) emptyMemory boot-flags e false`.
   The Spec is untouched.
   *Rejected alternative:* make `initialState`/`exec` take the register file and state `correct`
   `∀ regs`. That is equivalent in strength (nothing about an opaque postulate is provable), but it
   changes `Once.Spec.Correct`'s `exec`, so it would need a decision-log entry for no extra
   guarantee. Revisit only if the Spec should name the environment explicitly.
2. **`_start` sets what the correspondence reads.** `c-start`'s lowering keeps the heap-register
   `lea` and the frame reservation, and also zeroes the other registers the correspondence constrains
   (input, closure, output, scratch, count: `xor r, r` / `mv r, zero`, per arch). This is the honest
   start code for bare metal.
3. **The correspondence starts in two halves.**
   * `StartCorr` at pc 0: pc, sp (the entry frame base), memory (virgin region / `untouched`), code
     map, and the empty ghost return stack. **No register equalities.**
   * `block-step-c-start` (×3) goes from `StartCorr` to the full `CompiledCorr` after the block:
     each register equality now holds BECAUSE of an instruction the block executed (the `lea` for the
     frontier, the zeroing for the rest).
   * `events-agree-start` already starts the engine one step in, so its shape is unchanged; only
     its premise changes from `entry-corr` to `StartCorr`.

## 3. Steps (top-down)

a. **The change first.** `boot-regs`/`boot-flags` in the three `Semantics.agda`; follow the red into
   `entry-corr` (×3). Expected red: exactly the six `refl` register fields, and the flags if any
   step reads them before writing.
b. **`StartCorr` + the two-half start.** Replace `entry-corr` by a `StartCorr` proof; restate
   `block-step-c-start`'s premise; its proof now needs (c).
c. **The emitter.** Extend `compile-abstract (instr-ctrl (c-start b))` per arch with the zeroing
   instructions; prove the block step's register readouts (premise-free step lemmas, as for every
   other block).
d. **The regression probe.** On a scratch copy, delete the `lea` from x86-64's `c-start` lowering:
   the apex must go RED. Today it stays green.
e. **Gate.** Apex + backstop green, extraction, `cabal test`, exit tests ×3 (binaries change by a
   few instructions in `_start`).

## 4. Risks

* **The flags.** If a block reads a flag before any instruction sets it (it should not: every
  `jcc` follows a `cmp`/`test`), (a) will show it as red. Treat it as a finding, not a nuisance.
* **Memory is still "empty".** `.bss` zeroing is a real loader/startup guarantee, but the stack
  region's contents below `sp` are not. The virgin-region invariant (`untouched`) reads it.
  Weakening that is a separate, smaller follow-up; record it, do not fold it in.
* **riscv64's register file** is larger (a0–a7, t*, s*). Only the registers the correspondence
  constrains need zeroing; the rest stay unspecified and unread.
