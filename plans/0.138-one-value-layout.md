## 0. Decided (the user, 2026-11-01)

1. **The layout of concrete values is stated once, for both boundaries**: FFI in (a client calling a library
   export, plan 0.137) and FFI out (Once calling an Interpretation's operation, plan 0.111). It is the
   layout of the C type that represents the value under the target's standard procedure-call standard.
2. **Once's internal layout of those values IS that layout.** Not a conversion at the boundary: an invariant
   the compiler keeps everywhere, so a value crosses a boundary as it is.
3. **The invariant belongs to an IMPLEMENTATION Spec**, not to `Once.Spec`: a claim that constrains the
   compiler but is invisible to the denotational meaning (which has no bytes), stated beside `correct` like
   plan 0.123's `NoLeak` ("every allocation is freed exactly once", `Once.Adequacy.NoLeak`, named in
   `Once.Certified` as `once-no-leak`, on branch `0.123-heap`).

## 1. The two claims

- **Spec (boundary).** `Spec.ABI` (new, per target): `layout : (A : Ty 0) → IsConcrete-base A → Layout`, and
  `encode`/the cells a value `v : ⟦A⟧` occupies at an address. With plan 0.111's callee clause it is the
  whole boundary contract, read by an Interpretation's author and by a library's client. It is in the Spec
  because both of them rely on it and it is all they need to know.
- **Implementation Spec (inside).** For every program and library the compiler accepts, in every reachable
  state of the flat machine's run of its image: every value of a concrete type that the run holds at an
  address occupies exactly `Spec.ABI`'s cells for it. Stated over the same runs as `NoLeak`.

How it is proved, top-down: the value relation's concrete cases are DEFINED by `Spec.ABI` (D364 made
`ValidAtWF` a function on the type, so `A * B` at concrete `A`, `B` becomes "the cells of `layout (A * B)`"
instead of `PairV` over two pointers). Then the invariant is what the correspondence already carries, and the
codegen change is what makes the correspondence hold again.

## 2. The layout (proposal for the Spec patch)

- `Int`: one target word (8 bytes on x86-64/riscv64, 4 on x86-32). `Float`: the target float (D113; x86-32
  has no float code yet, D-log "x86-32 keeps its `ud2`").
- `Unit`: no bytes (C has no empty struct: a `Unit` field is omitted, a `Unit` argument is not passed).
- `A * B`: `A`'s cells, then `B`'s at the next offset aligned for `B` (a C struct, inline, flat).
- `A + B`: a tag word (0 = `inl`, 1 = `inr`), then the payload at the alignment of the larger alternative;
  the size is the larger alternative's, so `Bool = Unit + Unit` is one word.
- `Void`: no value exists; a product containing it is never built.
- Every scalar is word-sized on the current targets, so every layout is a sequence of words; the alignment
  rules are stated anyway, for a target where they are not.

## 3. What changes in the compiler

- **Concrete products and sums are flat**: built in place, not as cells of pointers. Their size is static,
  which is exactly plan 0.123 D7's pop heap: values whose size the type fixes, reserved by the caller before
  the callee runs (destination passing, D147). So this plan and 0.123 B's pop heap are one codegen change;
  §5 Q2.
- **Non-concrete values stay as they are**: closures, `μ`/`ν` structures, cells with pointers. A flat struct
  may hold a pointer field to one (inside Once only; it never crosses a boundary).
- **Operations read structs**: an Interpretation's operation taking or returning a product or sum reads or
  writes the `Spec.ABI` layout. Today it gets a pointer to nested 2-word cells
  (`Strata/Interpretations/Linux/Syscalls.x86_64`: "Once tuple layout (nested pairs)"); the per-arch
  Interpretation code changes with this plan.
- **Copying**: building a pair copies its parts instead of sharing them. Bounded by the type's size; plan
  0.123 D6 already copies borrowed parts that a result keeps.

## 4. Steps (top-down)

- **S0 — Measure.** Per arch: how each concrete type is represented now (cells, tags, where sums put their
  payload); where concrete values are built and read (IR constructs, emitters); which Interpretation
  operations take or return a product or sum; what D364's value relation says per type, and what plan 0.123
  D7's pop heap already sizes. Record here.
  **Recorded 2026-11-03 (branch `0.123-heap-2`, `702f6c128`).** The three arches agree except for the word
  (`slot-size` 8 / 4 / 8) and registers.
  - **Every block is one 2-word cell**: all 21 allocation sites in `IRToTrace` are `instr-alloc-heap 2`
    (`AllocMin`: `2 ≤ n`). A component cell holds a pointer or the value inline (`CellAtP`, D187; inline only
    for Int, Float, Unit).
  - **Per type**: Int and Float are one word, in a register or a cell, never boxed alone. Unit has no
    residence. `A * B` is `[A, B]`, right-nested. `A + B` is `[tag 0/1, payload]` (Bool: `Unit + Unit`, true =
    `inr`, D263). A closure is `[env, code]`. A μ node is its layer's blocks (`MuRep`, D366: a `K Int` or
    `K Float` layer boxed, `K Unit` an empty block). ν is `[seed, code]`.
  - **Built** by `⟨_,_⟩`, `curry`, `apply`, `inl`, `inr`, comparisons, `In` (box and unit), `in-ν`, `Ana` and
    its re-suspension, `Iter` (one per round), and the cata machinery (closure record, one per algebra call,
    the walk's push and wrap blocks). **Read** by `fst`/`snd`, `case`, `out`, `apply`, `Iter` and the cata walk.
  - **Interpretations taking a product**: Linux `Syscalls` (`fd_dup2`, `fchmod`, `ftruncate`, `lseek`, `kill`,
    `socket`, `listen`, `shutdown`; x86-64 and riscv64 only), `Math.Int` (17) and `Math.Float` (13), and most
    seL4 operations. Their assembly reads nested pairs and assumes an Int component is stored inline, which
    `CellAtP` does not promise (it allows a pointer). The seL4 IPC assembly builds result tuples on the stack,
    against D364's heap-only values.
  - **D364's value relation** (`ValueRel`, `ValidAtWF` a function on the type): every location inside a value
    is on the heap (`Live (AtStack _ _) = ⊥`); per type as above, μ by `ValidFO`, ν coinductive.
  - **Static sizes**: exactly the base types (`IsBaseTypeI`: Unit, Void, Int, Float, and products and sums of
    them); μ, ν and closures are not. No function computes a type's size in words yet.
- **S1 — Spec patch (user approval): `Spec.ABI`'s layout**, §2. Proof-free. Plan 0.111 S1 adds its callee
  clause to the same module (together or after).
- **S2 — The implementation Spec**: its home (§5 Q1) and the layout claim, stated; type-checked and visible in
  `Once.Certified` beside `once-no-leak`, assumed by nothing until proved (plan 0.123 B.0.7's treatment).
- **S3 — The value relation follows `Spec.ABI`** at concrete types. Follow the red: the emitters build flat
  values (with 0.123 D7), the correspondence proofs re-prove the concrete cases.
- **S4 — Interpretations**: the per-arch operation code reads and writes the layout; their headers say so.
- **S5 — The claim proved**, from S3's relation; it becomes a field of `CertifiedBuild`.
- **S6 — Gate**: apex, backstop, extraction, `cabal test`, exit tests ×3; `codegen-measure` for the cost
  (fewer allocations, more copies), recorded.

## 5. Decided, and a note

- **Home of the implementation Spec (the user, 2026-11-01).** One statements-only module outside `Once.Spec`
  (e.g. `Once.Implementation`; check the name is free), collecting the claims that constrain the compiler and
  not the meaning: `NoLeak`, this layout claim, later others. Imported by `Once.Certified`; its own gate, like
  `spec-gate` (statements only, proof-free).
- **Order (the user, 2026-11-01).** After the "calls proved" branch merges (it rewrites the value relation,
  D364). S3 is done together with plan 0.123 B's pop heap (D7), not as a competing rewrite.
- **Note for S0/S3 (not a design question): D364's "values are heap-only".** It requires every location inside
  a value to be in Once's heap, so a callee's frame pop cannot kill a value. A library call reads arguments
  from the client's memory and works in a region the client gives (plan 0.137 §2.3). The invariant is
  restated as "inside the memory this run was given": for a program the heap `_start` sets up, for a library
  call the client's region, plus the read-only argument memory. A restatement in the proofs, not a change to
  the design.
