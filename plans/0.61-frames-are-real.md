## WHERE IT ACTUALLY LANDED (read this first)

Following the red showed the cascade lands entirely in the **legacy structured
layer** (`ApplyWF`, `ComposeWF`, `PairAllocWF`, `CurryStackWF` — `check-all`
only, NOT in the certified cone), while the semantics of record is the FLAT
machine (`exec-flat`; see plan 0.32/0.33's "flatten the abstract machine"), and
the flat codegen path never even emits the frame ops that the structured layer
reasons about.

So the discipline was put in `flat-exec-instr` (commit `d94284ad`), exactly
where control flow already lives, and `exec-abstract` was left on its degenerate
model. Consequences:

* stage 2 became MOOT — `SMPrimitives`' frame-invariance family is about
  `exec-abstract` and is untouched;
* stage 3 is DEFERRED — it re-truths the structured layer when that layer is
  retired (nothing on the apex path needs it);
* stage 4 LANDED (`18774c6f`): stack pointers have real addresses and `lea-slot`
  is routed.

The stage-1/4 descriptions below are as-built (the `FrameSemantics` additions,
`AllocState.saved-frames`, `enter-frame`/`leave-frame`, `rsp-eq`, the addressing
laws) except that the four `%rsp`-moving clauses live in `flat-exec-instr`
rather than `exec-abstract`.

### Still open in this plan

  `haddr (offsetHL hl i) ≡ haddr hl + i·8` from `haddr-suc` by induction on `i`

  `branch-scratch-nontag`) so `sv-tag-val` matches `%rbx`.
* stage 3 (above), whenever the structured layer is retired.

# Plan 0.61 — Frames are real (fix the abstract stack model)

## The defect

`exec-abstract` never changes `current-frame`. `instr-push-frame` only resets
`stackSlot`; `instr-pop-frame` is the identity, with the comment *"Frame identity
restoration is external"*. So a callee's slot `k` and its caller's slot `k` are
**the same abstract cell** `AtStack (current-frame alloc) k`, while the hardware
keeps them at different addresses (the prologue moved `%rsp`).

An abstraction that identifies two things the machine distinguishes cannot be
mapped into the machine. Everything below is a symptom of this ONE defect:

| symptom | where |
| --- | --- |
| `enc-sv (SV-Ptr (AtStack f k)) = 0` — a FALSE claim about a register's value | `X86-64/FlatCorrespondence` |
| `store-output-not-stackref` — false the moment `lea-slot` runs | `X86-64/ConcFlatSim` |
| `stack-eq` goes vacuous after `push-frame` (the model loses the caller's slots) | `sim-push-frame` |
| `lea-slot` / `lea-indexed` unroutable in `events-running-fetch` | rung D catch-all |
| `apply` passing `&pair` into a callee is unmodellable | `IRToTrace` / `ApplyWF` |

It is NOT a codegen defect: `compile-abstract` is correct (`lea-slot n → lea rax,
[rsp+8n]`, `push-frame → push rbp; mov rbp,rsp; sub rsp,8·cap`), and
`exec-abstract` is spec-only (19 proof modules, nothing on the compiler's
execution path), so **no emitted assembly and no extracted-binary behaviour
changes**.

## The fix

Frames MOVE with the stack pointer. `FrameSemantics` already has the right
shape for this (`frame-base`, `slot-addr f k`, the ordering `≺`); only
`exec-abstract` punts. Once frames move:

* `enc-sv (SV-Ptr (AtStack f k)) = slot-addr f k` — a PURE function; the stack
  needs no carried map at all (unlike the heap, cf. `HeapView`), because
  `FrameSemantics` already provides exact per-frame addressing;
* the correspondence invariant is just `readReg rsp ≡ frame-base (current-frame)`;
* caller slots stay related across a call (different `Frame`), so `stack-eq`
  stops being vacuous after `push-frame`;
* `store-output-not-stackref` is deleted; `lea-slot`/`lea-indexed` route.

## Stage 1 — semantics + interface (WRITTEN AND TYPECHECKED 2026-07-27)

Verified green: `FrameSemantics`, all three `FrameInstantiation`s, `SMCore`.
Patch saved during the session; it is small enough to re-type:

1. `Once/CCC/FrameSemantics.agda` — one new field:
   ```agda
   -- | The frame `n` slots further in the growth direction (callee side).
   -- The way BACK is not an address computation — the machine restores the
   -- caller's frame from `AllocState.saved-frames`.
   shift-frame : Frame → ℕ → Frame
   ```
2. `Once/CCC/Target/{X86-64,RiscV64,X86-32}/Layout.agda` — the unconditional
   downward closure (the existing `stack-sub-preserves` carries an unused
   `k ≤ a` premise):
   ```agda
   stack-sub-preserves' : ∀ a k → InStack a → InStack (a ∸ k)
   stack-sub-preserves' a k (lower≤a , a≤upper) = (z≤n , ≤-trans (m∸n≤m a k) a≤upper)
   ```
3. The three `FrameInstantiation`s (`Frame = StackPointer = StackAddr` in all
   three), e.g. x86-64:
   ```agda
   x86-shift-frame : X86Frame → ℕ → X86Frame
   x86-shift-frame f n =
     stack-addr (sp-addr f ∸ n * word-size)
                (stack-sub-preserves' (sp-addr f) (n * word-size) (in-stack f))
   ```
4. `SMCore.AllocState` gains `saved-frames : List Frame` (the frame stack).
   ONLY ONE construction site in the whole CCC world
   (`FlatFromObs.entry-alloc`) — record-update syntax is additive.
5. `SMCore.exec-abstract` — the four `%rsp`-moving instructions:
   ```agda
   restore-frame : AllocState {FS} → AllocState {FS}     -- pop the frame stack
   restore-frame alloc with saved-frames alloc
   ... | []       = alloc                                -- malformed epilogue
   ... | (f ∷ fs) = record alloc { current-frame = f ; saved-frames = fs }

   instr-alloc-stack n  → current-frame := shift-frame cf n        , push cf
   instr-dealloc-stack n→ restore-frame
   instr-push-frame cap → current-frame := shift-frame cf (suc cap), push cf
   instr-pop-frame      → restore-frame
   ```
   (`alloc-stack` must shift too: the frameless convention puts the function's
   slot 0 at the POST-`sub` `%rsp`, so `frame-base cf` is only equal to `%rsp`
   after the reservation. `exec-loop` needs no change — it already restores
   `current-frame` explicitly each iteration, so its frame lemma stays
   unconditional.)

## Stage 2 — the frame-invariance family (`SMPrimitives`)

`exec-abstract-preserves-frame` is deliberately TOTAL today ("all instructions,
no predicate needed!"). It must take the existing `InstrPreservesFrame i`
premise (already `⊥` for push/pop-frame; extend to `⊥` for
alloc-stack/dealloc-stack), discharging those clauses by `⊥-elim`. Same for
`exec-trace-preserves-frame` (premise `TracePreservesFrame tr`, the predicate
already exists at SMPrimitives:1398) and `exec-case-dispatch-preserves-frame`.
`exec-loop-preserves-frame` is unaffected.

## Stage 3 — the IR WF modules (THE substantive part)

15 call sites assume frame invariance and must thread the frame instead:
`exec-abstract-preserves-frame` × 8 (ComposeWF, PairAllocWF ×2, ApplyWF ×2,
SMPrimitives/Heap, …) and `exec-trace-preserves-frame` × 7 (ComposeWF ×2,
PairAllocWF, ApplyWF ×3 — including `apply-setup-trace`, which CONTAINS
`instr-alloc-stack`, so its `TracePreservesFrame` is now false and the proof
must carry the shift). Expect the locations recorded before a shift to be
re-expressed against the OLD frame — which is the truthful statement (they do
point at the caller's slots).

**Stages 1–3 are NOT separable**: stage 1 alone makes a total lemma false, and
stage 2's restatement immediately propagates to stage 3's consumers. Nothing
can be committed green until stage 3 is finished. Budget accordingly; these are
the OOM-sensitive modules (see the PairWF2 history), so keep per-module checks
under the 30 s cap and split where needed.

## Stage 4 — the correspondence (the payoff, rung D)

* `enc-sv (SV-Ptr (AtStack f k)) = slot-addr f k` (needs an `Addr → Word`
  identification; for x86-64 both are ℕ);
* `FlatCorr` gains `rsp-eq : readReg rsp ≡ frame-base (current-frame (falloc fs))`;
  re-established at the four frame ops via `shift-frame`'s address law
  (`frame-base (shift-frame f n) ≡ frame-base f ∸ n · word-size` — add it to
  `FrameSemantics` when this stage consumes it);
* `stack-eq` can then be stated against `slot-addr` and survives calls;
* route `lea-slot` + `lea-indexed`; delete `store-output-not-stackref`.
