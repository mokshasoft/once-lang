# Plan 0.158 — Checked terms keep their variables' source names, so later diagnostics can name them

## Summary

When the compiler has checked a program, it works on a form of the program in which variables have
lost their names and are known only by position. Any message produced after that point (the new
"not linear: a copy here" warning, for one) can only say "variable #0". This plan keeps each
binder's source name in the checked program as a label that no meaning or proof depends on, so every
later warning, dump and debugging aid can say `xs` instead of `#0`.

## 1. Why

D500's warning names the definition and the kind of site but only the variables' de Bruijn indices
(`compiler/test/LinearSpec.hs`). A programmer cannot act on "#0" in a larger definition. The same gap
will hit every diagnostic computed on the checked `Expr` (resource warnings, `--require-linear`,
`once dump-ir`, future debug info), so the fix belongs in the term, once, not in each warning.

## 2. Where we are (checked 2026-11-27)

- `Once.Surface.Syntax`: `lam`, `let'`, `case'` bind without a name; the raw syntax has them
  (`Spec/Surface/Syntax.agda:40`, `RLam : String → Expr → Expr`), and the elaborator's `NamedCtx`
  holds them while it checks (`TypeCheck/Elaborate.agda:1368`).
- About 40 modules import `Once.Surface.Syntax`. Most only MATCH the binders (unaffected by an
  implicit argument). The ones that BUILD them:
  - the elaborators: `TypeCheck/Elaborate.agda`, `Surface/Elaborate.agda`;
  - `Denotation/RealizeS.agda` (`realize⇐ (u-lam …) = lam q ≤p …`), from usage derivations that
    carry no names;
  - `TypeCheck/SpecWitness.agda` (lines 267–355): `realize⇐ sh w ≡ <the elaborated term>`, so the
    realized term must carry the same names as the elaborated one;
  - the coherence laws: `Adequacy/CoherenceLaws.agda`, `CoherenceLawsWrap.agda`, `CoherenceHet.agda`
    (`lam-cong`, `let-cong`, `case-cong`, `lam-coerce`), `Adequacy/CoherenceS.agda:339,389`
    (two derivations' realizations are `≅`).
- Names are not in `Spec.Context` (the trust base) and need not be.

## 3. Decisions

1. **Where the name lives.** (a) an implicit `{x : String}` on the three binders of
   `Once.Surface.Syntax` (patterns untouched; builders supply it); (b) a side table beside the term
   (no proof change, but it must be kept in step with every rewrite). Recommendation: (a). Open.
2. **Names in the usage derivations.** `realize` must produce the elaborated term, so `u-lam`,
   `u-let`, `u-case` take the name from the raw expression they are indexed by. Recommendation: yes
   (the alternative weakens SpecWitness's equality to one up to names). Open.
3. **Equivalences ignore names.** `≈ˢ`/`≅` relate binders with different names (a name is not
   semantics); `lam-cong` and friends generalize over both names. Recommendation: yes. Open.

## 4. Steps

1. The implicit name on `lam`/`let'`/`case'`; every builder supplies one (Agda lists each as an
   unsolved implicit). Generated binders (rewrites, `RealizeS` defaults) use a fixed `_`.
2. The usage derivations carry the raw name; `realize` passes it; `SpecWitness` checks again unchanged.
3. The coherence laws generalized over names (step 3 of §3).
4. `LinCore.Linear`: a site's variables by name (the context's names along the walk); the warning
   prints `xs`, not `#0`; `LinearSpec` asserts the name.
5. Gate: `make certified`, the exit tests on all three arches, `cabal test`, perf compare (no code change expected).

## 5. Done when

`once check` on `compiler/test/LinearSpec.hs`'s twice-owned program prints
`not linear (a copy here): main: the two components of a pair (xs)` (the definition the site lands in once callees are inlined), and the certified build and
the whole gate are green.
