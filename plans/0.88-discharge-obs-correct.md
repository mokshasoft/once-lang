# Plan 0.88 — Discharge `obs-correct-*`, the 17 live postulates

## 0. The one measurement that defines this plan

The import closure of `Once.Certified` is 335 modules. Every `*WF` handler is
OUTSIDE it. The live path is

    correct -> correctd -> correctR-sound -> correct-gm -> codegen-asm-correct
            -> ArchCorrect.ir-flat-correct -> ir-flat-correct-of
            -> ir-obs-correct -> obs-correct-{pair,inl,curry,apply,...} POSTULATE

So progress is measured in ONE number: how many of the 17 postulates in
`Once.CCC.Codegen.IRObsCorrectFlat` are gone. Green WF modules are not
progress; they have been green a long time and the number has not moved.

## 1. FIRST: fix the interface (D152)

`IRObsCorrectF` as it stands is NOT the principled obligation. It is stated
only at frontier 0 (`next-slot alloc == 0`, and `MachineRefinesObsF` speaks
about `ir-to-trace ir = ir-to-trace' 0 0 ir`), while the emitter emits every
sub-IR at a NONZERO frontier. The composition case cannot be proven against
it, which is why `comp-step` is a postulate.

So stage A is not "discharge obs-correct-fst". It is:

  A0. Re-index the obligation the way the emitter is indexed --

        IRObsCorrect ir = forall n l -> ... -> next-slot alloc == n -> ... ->
          MachineRefinesObs (trace-of (ir-to-trace' n l ir)) ir x s alloc

      with `n = l = 0` as the entry instance `ir-flat-correct-of` consumes.
  A1. PROVE `comp-step` against it. If it will not go through, the re-indexing
      is still wrong and nothing below is worth starting.

Only then do the per-constructor postulates mean anything: discharging one
against a non-composing interface buys nothing.

## 2. The interface as it currently stands (for reference)

    IRObsCorrectF ir =
      ir-size ir < program-bound ->
      forall mIn x input-loc s alloc -> next-slot alloc == 0 ->
      ValidAtWF mIn alloc x input-loc s -> BeforeFrontier alloc input-loc ->
      halted s == false -> InputAt x input-loc s ->
      MachineRefinesObsF ir x s alloc

Fixed from above by `ir-flat-correct`. Note `next-slot alloc == 0`: the live
interface ALREADY treats the frontier as construction-time, threaded from
zero -- independent confirmation of D150.

`ir-obs-correct` is the dispatcher and already recurses structurally, so a
handler gets its sub-IR results by calling `ir-obs-correct` on them. There is
no dispatcher to build and no `RecDispatcherWF` parameter to thread.

## 3. Vocabulary: what stays, what retires

    LIVE, keep     ValidAtWF, ResultPlace (at-loc/at-reg/unit-result),
                   InputAt (in-at-loc/in-at-reg/in-unit), ShapeAt,
                   MachineRefinesObsF, ir-obs-correct
    ISLAND, retire IRResultAWF, RecDispatcherWF, AllocBump, IRStackBudget,
                   IRHeapBudget, InputPlace, trace-is-ir-to-trace

`InputPlace` and `InputAt` are the same idea twice. The live one wins.

## 4. Stages

| # | Content |
|---|---------|
| A | Re-index per section 1 (A0), then PROVE `comp-step` (A1). The composition case is the test of whether the interface composes at all. |
| A2 | Only now: discharge one small constructor (`obs-correct-fst`) to calibrate per-postulate cost. |
| B | Salvage: for each island handler decide what transfers. Trace shapes, slot arithmetic and validity transports are reusable; the `IRResultAWF` scaffolding is not. |

## 5. What NOT to do

Do not repair, extend or re-green a `*WF` module before its content is known
to transfer. Nine modules are green and discharge nothing; a tenth green
module is not progress. The failure mode of bottom-up construction is not a
red build -- it is a green one that nothing reaches.
