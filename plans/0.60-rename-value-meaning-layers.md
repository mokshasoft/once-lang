# Plan 0.60 — Rename the value/meaning layers (kill the `Semantics`/`Denotation`/`Spec` name-clash)

## Why

Three module trees read as "the meaning of a program," and nothing in the names
tells them apart:

- `Once.Spec.*`      — the TRUSTED, IR-free language definition.
- `Once.Denotation.*`— the (monadic, trace-carrying) behavioural MEANING.
- `Once.Semantics.*` — the PURE, executable VALUE MODEL.

A reader cannot tell which is the trusted spec, which is the mathematical meaning,
and which is the machine value model. This actively caused confusion during Plan
0.52 M2 ("is `Once.Semantics` part of the Spec? did the 0.58 migration forget to
delete `Once.Denotation`?" — no to both, but the names invite the questions). The
confusion is NOMINAL, not structural — the layering is clean (verified: `Once.Spec/*`
imports 0 from `Once.Semantics`/`Once.IR`). This plan fixes the names.

## What each layer actually is (ground truth)

| Tree | What it is | Key type | Trusted? |
|---|---|---|---|
| `Once.Spec.*` (5 mods) | canonical IR-free language definition (Type/Syntax/Typing/Meaning/Correct) | `⟦_⟧ᵈ` derivation denotation | YES (trust boundary) |
| `Once.Denotation.*` (10 mods) | behavioural meaning + IR↔meaning bridge. Split by 0.58 P5: 4 spec-side vocab modules (`ValueDomain`/`Behavior`/`Meaning`/`MainMeaning`) are re-exported by `Once.Spec.Meaning`; the rest (`Realize`/`SourceDenote`/`DenotTrace`/`Trace`/…) are the adequacy bridge | `⟦_⟧ᴰ` (monadic, into `T`) | NO (impl) |
| `Once.Semantics.*` (`Value`/`Machine`/`Functor`/`Coherence`/`ValueIR`) | pure executable VALUE MODEL: `⟦_⟧ : Type → Set` (Int = machine `Word`, functions = Agda functions), the target of the IR evaluator `CCC.Eval.eval` | `⟦_⟧` (pure `Set`) | NO (impl) |

The essential distinction the names must carry: **`Once.Semantics` is a VALUE model
(sets of values, no trace); `Once.Denotation` is a MEANING (behaviour/trace).** They
are two DIFFERENT denotations by design — the compiler proves the value model refines
the meaning (adequacy).

## Renames

### Primary (highest value, lowest risk): `Once.Semantics` → `Once.Value`
It IS the value model. After this rename, `Value` vs `Denotation` vs `Spec` are already
three clearly-distinct words — this single rename removes most of the confusion.
- `Once.Semantics.Value`     → `Once.Value.Domain`   (`⟦_⟧ : Type → Set`)
- `Once.Semantics.Machine`   → `Once.Value.Machine`  (the `Word`-instantiated re-export)
- `Once.Semantics.Functor`   → `Once.Value.Functor`  (`SFunctor`, `μS`/`νS`)
- `Once.Semantics.Coherence` → `Once.Value.Coherence`
- `Once.Semantics.ValueIR`   → `Once.Value.Ungraded` (the IRTy value model, from 0.52 M2)
- Umbrella `Once.Value` (`Once/Value.agda`) re-exporting `Domain` for convenience (optional).
- Blast radius: **61 importers** of `Once.Semantics`.

### Secondary — `Once.Denotation`: pick one
- **(A) KEEP `Once.Denotation`** (RECOMMENDED — minimal churn). Once `Semantics→Value`,
  "Denotation" is unambiguous (it is genuinely the denotational meaning). Stop here.
- **(B) SPLIT for maximal clarity** (more churn, ~42 importers):
  - Move the 4 spec-side modules physically under `Once.Spec/` (Spec becomes the HOME,
    not a facade) — `Once.Spec.ValueDomain`/`Behavior`/`Meaning`/`MainMeaning`.
  - Rename the 6 bridge modules `Once.Denotation.{Realize,SourceDenote,DenotTrace,Trace,
    TraceDenote,TraceMonad}` → `Once.Bridge.*` (the IR↔meaning adequacy bridge).
  - Net: no `Once.Denotation` tree; every module is clearly Spec (trusted) or Bridge (impl).

Default: (A). Escalate to (B) only if the split is judged worth the churn.

## Method — pure, mechanical rename (verified by a green build)

1. Rename file + `module` declaration per module; `git mv` to keep history.
2. Follow the typechecker: update every importer (the rename is the top-level change;
   red = the importer list). No shared-name hazards — new names don't collide.
3. `make check-all` green; re-extract MAlonzo (mangled module names change — see
   [[feedback_malonzo_cabal_sync]]); `cabal test` green; `certified` exit 0.
4. Confirm `Once.Adequacy`/`Once.Spec.Correct` records are byte-identical (only import
   paths move) — this is a rename, the correctness theorem is untouched.
