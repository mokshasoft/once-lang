# Plan 0.153 — No termination pragma is left in the compiler

## Summary

Once allows only recursion that visibly ends, and the proof assistant checks that for every function,
except where a pragma turns the check off. Two parts of the compiler still turn it off: the parser for
type expressions, with its correctness proof, and the step that spots arithmetic and compiles it to
machine arithmetic (an important optimization). Each pragma is an unchecked promise: "this terminates,
trust me". This plan replaces those promises with checked termination arguments. When it is done, no
part of the verified compiler turns the termination check off, and the trust base loses four entries.

## 1. Why

D242: structured recursion is correct by construction, and the pragma gate (`formal/scripts/pragma-gate.sh`)
guards it: a pragma that disables termination, positivity, coverage or universe checking in the closure of
the apex (`Once/Certified.agda`) or the extracted compiler (`Once/Extract/Root.agda`) fails the gate, and
the pragmas that predate the gate sit in `formal/scripts/pragma-gate.baseline`, counts that "may only go
DOWN. Each is a residual to remove". Every one of them is a trust-base entry (an obligation in the AST
dump), and a non-terminating parser or recogniser would make the compiler hang, or, through the proofs
that reason about them, make an unsound proof check.

The work is chosen to run beside plan 0.146: it touches no file that 0.146's branch changes (§2).

### 2a. The parser (`Once/Parser/Generic/Parser.agda:38`, `Sound.agda` ×14)

- `module Make (alg : TyAlg)` defines one mutual block under one pragma: `atomP prodP sumP typeP`,
  `prodTailP sumTailP arrowTailP`, the functor parsers `fAtomP fProdP fSumP fProdTailP fSumTailP`,
  `atomKw`, and the `Nu` helpers `nuP nuTryP nuActWith nuCloseActP`. Every recursive call is on a
  strict suffix of the input token list, but through `with` and helper functions, which Agda's
  termination checker cannot see.
- The header explains why it is bound-free: "With no bound in the parser there is no
  bound-dependency, so `with`/`rewrite` abstract the classifier cleanly — soundness and completeness
  both reduce" (plan 0.7-2). The length bound is recovered in the relation (`atomShrink`, `sumShrink`).
- `Sound.agda` proves soundness by recursion on `Acc _<_ (length toks)` already, but 14 functions still
  carry `TERMINATING`: calls such as `sound-prod toks (acc rec)` → `sound-atom toks (acc rec)` pass the
  same `Acc` (no decrease), and the call graph through the `with`-generated auxiliaries has cycles that
  the checker does not see decreasing.
- `Complete.agda` has no pragma. The parser reaches the Spec's grammar through `Parser/Generic/PolyInst`
  (`Spec.Surface.Type`), `Parser/PolyType`, `Grammar/PolyTypeBridge`, `Parser/Relation/{Decl,OpDecl,
  Signature}` and `Adequacy/SpecGrammar/{SigTypes,Decl}`. The Spec itself is not touched.
- `Once/Parser/AccIrrelevant.agda` (plan 0.3 task #40) proves any two `Acc _<_ n` equal, using

### 2b. The arithmetic recogniser (`Once/Arith/Machine/Recognise.agda:233,306`)

- One pragma per mutual block: the integer one (`recognise-body`, `recognise-binop`, `recognise-prim`,
  `rb-at`, `binop-at`, `rbin-at`) and its float twin (`recognise-body-float`, …, `binop-at-float`,
  `rbinf-at`, which also calls the integer `recognise-body` at `arith.i2f`).
- Two calls do not decrease structurally:
  - **re-association** (D163): `rb-at … (v-reassoc f g h) = recognise-body sh (f ∘ (g ∘ h))`, and the same
    in `rbin-at`. The size of the term is unchanged; its LEFT-NESTING drops by one (the comment at
    `rb-at` already gives this argument).
  - **distribution** (D163): `binop-at sh true a b h = pair-of (recognise-body sh (a ∘ h))
    (recognise-body sh (b ∘ h))`, from `⟨ a , b ⟩ ∘ h`. `a ∘ h` is not a subterm, but it is strictly
    SMALLER by node count: `|a ∘ h| = |a| + |h| + 1 < |a| + |b| + |h| + 2 = |⟨ a , b ⟩ ∘ h|`.
  Every other call (`SigOp si ∘ e` → `e`, `⟨ a , b ⟩` → `a`, `b`) is on a subterm. So the
  lexicographic measure (node count, left-nesting depth) decreases on every call. (To be confirmed in
  step 3: the left-nesting of `f ∘ (g ∘ h)` must be checked against what the next re-association reads.)
- The recogniser's results feed proofs (`Arith/Machine/Rewrite`, `Adequacy/LiftSound`) that unfold its
  clauses by `with`, so the shape of `recognise-body`'s definition matters, not only its result (§3 D2).

## 3. Decisions

- **D0 (decided, the user, 2026-11-20) — no `with`, no `rewrite`.** They cause proof problems (plan
  0.7-2's completeness wall was a `rewrite` that could not abstract `isStar toks`) and performance
  problems. Dispatch goes through top-level helpers that take the classifier's RESULT as a parameter
  (`f x = f-aux x (g x) (lemma x)`; a consequence of the result is passed as a function of it, never as a
  self-referential `refl`); proofs are lemmas about the helper for a VARIABLE result, matched `refl`, then
  instantiated. Destructuring by a local function of explicit type or `case_of_`.
- **D1 (decided, the user, 2026-11-20, after the step 1 spike) — the parser's termination
  argument.** Fuel is rejected (the user, 2026-11-20). The design, now checked: `Acc _<_ (length toks)`-indexed parsers whose results carry their shrink
  (`length rest < length toks`, `≤` for the tails), and the public functions as the bound-forgetting
  map of `atomP′ toks (<-wellFounded _)`, so `Complete`/`Sound`'s statements and every downstream user
  (`PolyInst`, `Parser/PolyType`, `Grammar/PolyTypeBridge`, `Parser/Relation/*`, `Adequacy/SpecGrammar/*`)
  are unchanged. Every call cycle of the parser passes through a call on a strictly shorter suffix
  (`atom → type` on the paren's inside, the tails on `drop1`/`drop2` and on the returned rest), so the
  `Acc` decreases structurally. Completeness is stated for EVERY `Acc` (so the induction hypothesis meets
  whatever `Acc` the definition passes: no irrelevance lemma, no `extensionality`), by induction on the
  relation through D0's helper lemmas. Plan 0.7-2's reason for dropping the bound was the `rewrite`; D0
  removes it. Two more views make soundness enumeration-free: `HeadV` (the head token: a word, `(`, or
  other) for `atomKw`/`fAtomA`, and `CloseV` (a `)` or other) for `parenK`/`nuClose`; the keyword chains
  are views too (`KwV`, `FKwV`, the catch-all carrying its value). The fallback (`Acc` with one
  propositional unfolding lemma per clause) was not needed.
- **D2 (decided, by the constraint in §2b) — the recogniser keeps its interface.** `recognise-body`,
  `recognise-binop` and the float twins keep their types and their observable clauses as equations, so
  `Rewrite`, `LiftSound`, `RewriteLinked`, `RewriteOwned` (which 0.146 edits) are untouched, or touched
  only where they now reduce a clause definitionally and will use the clause's unfolding lemma. The
  arithmetic compiler is kept as it is: this plan changes how its termination is checked, not what it
  recognises.
- **D3 (decided, the user, 2026-11-20) — the recogniser recurses well-founded on `sz`.** `sz`
  (`Adequacy/LiftSound.agda:193`; the left factor of `∘` counts twice) moves into `Recognise`; the
  recursion is on `Acc _<_ (sz ir)`. Every call decreases it: re-association (`reassoc-<`, already proved
  in `LiftSound`), distribution (`sz (a ∘ h) = 1 + 2·sz a + sz h < sz (⟨ a , b ⟩ ∘ h)`), and the
  subterm calls. The views (`RBView`, `BView`) are data, so each decrease proof comes from a view
  constructor, not from an equation of a `with`. One unfolding lemma per public function
  (`recognise-body sh ir ≡ rb-at sh ir (rb-view ir)`, the same for `recognise-binop` and the float twins),
  via `Acc` irrelevance proved by induction on `Acc` (no `extensionality`). Checked 2026-11-20: in
  stdlib 2.3, `<-wellFounded n` reduces to `acc _` for an open `n`, so the first step computes.
  Fuel was rejected (the user: fuel has been problematic).
