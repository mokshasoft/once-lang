# Plan 0.72 — `Float`'s representation is a PARAMETER, as `Int`'s already is

**Status**: P1–P3 LANDED 2026-08-18 (`20d7cb22`, `91229986`, `f5a27e56`); P4 measured and parked; P5 open. **Supersedes plan 0.71's F5/F6** and
completes D109's fix. Decision: **D112**.

## The defect, in four lines

    Once/Semantics/Value.agda:129   ⟦ Int ⟧   = IntRep      -- a PARAMETER
    Once/Semantics/Value.agda:130   ⟦ Float ⟧ = AgdaFloat   -- hardcoded, 64-bit
    Once/IRTy.agda:239              ⟦ IntRep ⟧-baseI Int   = IntRep
    Once/IRTy.agda:240              ⟦ IntRep ⟧-baseI Float = AgdaFloat

`Int`'s representation is arch-relative and EXPLICIT: a parameter, instantiated
at the width-free `Carrier` (= ℕ), with the target's width applied at the
machine by `norm` (D054 — modular at the machine width, `Width 32` on x86-32 and
`Width 64` elsewhere). Every step of that is visible and checkable.

`Float`'s representation is arch-relative and IMPLICIT. It is nailed to Agda's
double at both levels, and the target-relativity is smuggled in one layer down:

    Once/Type.agda:383              fits-float : FitsInReg Float   -- no arch, no premise
    FlatCorrespondence.agda:286     enc-sv-at am (SV-Lit fits-float v) = fenc v

So on x86-32 a value whose DENOTATION is a 64-bit double is claimed to fit a
32-bit register, and `enc-sv` is *defined* as the target's (lossy) encoder — so
the abstract and concrete sides agree by construction and no gate can see the
loss. **There is no postulate to point at.** Nothing is named, nothing is
counted, no probe can refute it. That is strictly worse than an axiom, and it is
how a 64-bit double "fits" in a 32-bit word today.

## The rule

**`Float` follows `Int`.** Its representation becomes a parameter of the value
domain and the IR carrier, instantiated at a WIDTH-FREE EXACT carrier, with the
target's format applied at the machine — the same three-step shape `Int` has:

|                     | `Int` (today)              | `Float` (today)          | `Float` (this plan)          |
|---------------------|----------------------------|--------------------------|------------------------------|
| denotation          | `IntRep` — parameter       | `AgdaFloat` — hardcoded  | `FloatRep` — parameter       |
| IR payload          | `Carrier` (ℕ) — width-free | `AgdaFloat` — 64-bit     | dyadic `(m , e)` — width-free|
| target application  | `norm` at the target width | `fenc`, lossy + unstated | `fenc` at the target FORMAT  |
| literal obligation  | `lit-fits` (parameter)     | `float-fits` (parameter) | representability (0.71 F4)   |
| encoder range bound | `norm`'s, provable         | assumed                  | **provable**                 |

The carrier is a non-negative dyadic rational `m / 2^e` with `m e : ℕ`, mirroring
`Carrier = ℕ`: exact, width-free, and closed under nothing — it is a payload, not
an arithmetic domain (float arithmetic is SigOps, and stays so).

### What this buys, precisely

- The impossibility disappears rather than being absorbed: a double is not
  claimed to fit a 32-bit register, because the denotation at that target is not
  a double.
- `float-bits` and `float-bits-single` are **deleted**, not justified. No
  `primFloatToWord`, no NaN-encodes-as-0 edge, no unprovable faithfulness claim.
- `LitFits.float-fits` becomes provable from the encoder's construction (the
  parts are bounded by the format's fields), so a residual is DELETED.
- An 8-bit target is no longer a special case: it instantiates a narrow
  `IntRep` AND a narrow `FloatRep`. A target with no float format at all simply
  has no `Float` — a reportable fact, not a silent re-encoding.

## Phases

### P1 — the carrier and the formats

`Once/Float/Dyadic.agda`: the carrier `(m , e)`, and `FloatFormat` (significand
bits, exponent bits/bias). `encode : FloatFormat → Dyadic → ℕ` as ℕ arithmetic,
with `encode-fits : encode F d < 2 ^ (width F)` PROVED. Single and double are
two values of `FloatFormat`, not two functions.

### P2 — the denotation and the IR carrier

`⟦ Float ⟧ = FloatRep` in `Semantics/Value.agda`; `⟦ IntRep ⟧-baseI Float` takes
the dyadic carrier. `CCC/Eval`'s float clause follows. **Measure before
starting**: `fits-float` spans 36 files / 140+ sites, and this is the step that
touches them.

### P3 — the machine layer — **DONE** (`f5a27e56`)

`float-fits` moved out of `record LitFits` into a top-level theorem on all three
arches, proved `<-≤-trans (encode-fits F v) (^-monoʳ-≤ 2 (n≤1+n k))`. The proof
uses NONE of the family's premises — the bound holds for every dyadic, not just
the reachable ones, which is what distinguishes a discharged residual from a
relocated one. `Once/Semantics/FloatBits.agda` is deleted (it was red and
imported by nothing; still listed in `compiler/once.cabal:308`).


`fenc` becomes `encode (format-of target)`; the three emitters lower a literal
through it; `float-fits` is discharged and removed from `LitFits`.

### P4 — `FitsInReg` gains the arch (D109's option (a)) — **MEASURED, NOT CHEAP**

The plan called this cheap. Measured 2026-08-18 it is not: `fits-float` has 124
mentions and `FitsInReg` 82, across the IR, codegen and all three machines —
comparable to P2's sweep.

More importantly it is **no longer load-bearing**. The impossibility D109 found
was "a 64-bit double in a 32-bit register", and P1–P3 dissolved it at the root:
`Float` no longer MEANS a 64-bit double, so the unconditional `fits-float` is
backed at each target by `float-fits` rather than papering over a loss. What P4
still buys is a target with NO float format being able to REFUSE `Float`, which
matters the day such a target exists and not before.

So P4 is parked behind 0.71's F3b/F4/F7 (the tests the float work exists for),
not cancelled. Ordering is the user's call.


With the format a target property, "a Float fits a register" is decidable per
target rather than asserted globally.

### P5 — rejoin 0.71

0.71's F4 (representability) is now the analogue of `lit-fits` and states
against the target's FORMAT. F5 is trivial (the payload is already dyadic) and
F6 is done (P3). F7's tests follow.

## Done means

`⟦ Float ⟧` mentions no Agda `Float`; `float-bits`/`float-bits-single` are gone;
`float-fits` is a theorem; and the sentence "a 64-bit double fits in a 32-bit
register" is not derivable anywhere, because nothing says it.
