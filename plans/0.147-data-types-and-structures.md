# Plan 0.147 — Named data types and lawful structures, with no new mathematics

## Summary

Programmers expect to declare their own data types with named constructors, to write recursive functions
over them the way Haskell allows, and to use `==`, `<` and `+` on many types. This plan decides how Once
offers all of that while staying a language whose programs are mathematics. Data types are names for
initial algebras (and codata for final coalgebras) that Once already has; recursive definitions are a
convenient way of writing folds and unfolds, so every program still terminates or stays productive;
and an operator such as `+` or `<` may only be used on a type that really has the laws mathematicians
expect of it, with those laws proved. Floating-point numbers keep their own, honest operators. Everything
that dependent types will give for free (GADTs, indexed families, proofs inside the language, higher
kinds) waits for them; everything decided here is designed so that dependent types extend it rather than
replace it.

## 1. Why

GOAL.md asks for two things that pull in different directions here. The programmer should find a surface
that "feels like Haskell or Agda", and today's surface has only anonymous sums and products, positional
`destruct`, `Fix (Unit + A * X)` for lists, and no way to recurse except by writing `cata` by hand. The
mathematician should find a Spec that "looks principled", which rules out Haskell's unlawful, globally
searched type classes and general recursion. The decisions below were taken from principle (the
categorical reading of each construct), not from the current implementation.

## 2. Where we are (2026-11-03)

- **Data types are structural.** `Strata/Derived/Initial.once` declares `type Bool = Unit + Unit`,
  `type Maybe A = Unit + A`, `type Nat = Fix (Unit + X)`, `type List A = Fix (Unit + A * X)`. A `type` is
  an abbreviation; there are no constructor names, and `destruct` branches are positional
  (`docs/decisions/language.md` §11, D042).
- **The functor grammar** is `Fun ::= K A | Id | F ⊕ G | F ⊗ G` (`formal/Once/Spec/Type.agda:41`): a
  constant cannot mention the recursive position, so `data Rose a = Node a (List (Rose a))` is not
  expressible.
- **Polymorphism is rank 1** with kinds `base` and `any` (D238). No higher kinds.
- **A type's functor action** `mapᶜ` exists (D369, `Once.Spec.Metatheory`).
- **Structures are explicit record values** (D307, plan 0.112); OCP-0010 R7: no instance search.
- **Operators** (OCP-0002): `+ - * / % < <= > >= == !=` are built in and overloaded over the number
  types; D331 lets a definition be named by an operator.
- **Principal types** (D007, D323) are argued from "no type classes" among other things.
- **The meaning is a function of the judgment** (D310, D308).
- **Polymorphism is parametric** (D371: the abstraction theorem and naturality): nothing in the core
  inspects a type variable.
- **No self-reference** (D241): a definition never sees itself; recursion is `cata`/`ana` written by hand.
- **Float** (D113): the target's representation; arithmetic is the target's IEEE operation.
- **Polymorphic definitions are monomorphised** ("a schema is instantiated at its uses and never emitted",
  plan 0.136 §1). Library exports are concrete types only (plan 0.137).
- **Concrete values become flat** (plan 0.138).

## 3. Decisions (the user, 2026-11-03 to 2026-11-06)

Each records what was chosen and why. Rejected options are named where the reason matters later.

### 3.1 Data types

1. **`data` is surface sugar over μ of a polynomial functor.** `data List a = Nil | Cons a (List a)`
   names `F X = 1 + a × X` and its initial algebra. Constructors are the components of
   `in : F(μF) → μF`, matching is `out` followed by `case`, recursion is `fold`. The core and the meaning
   do not change. (2026-11-03)
2. **Nominal.** A declaration makes a new type whose meaning is its representation's (`⟦T⟧ = ⟦μF⟧`); only
   the typing changes. Its theorem is representation independence, a corollary of parametricity.
   Structural types were rejected: they print as structure (`Unit + Unit`, not `Bool`), make constructor
   names ambiguous, and cannot tell two structures on one carrier apart. (2026-11-03)
3. **Types are formed relative to a signature of declarations** (Coq/Agda/Lean, and the DT kernel's D081
   telescope with D082 projections). A declaration enters the signature with its type former, its
   constructors (introduction) and its fold (elimination); positivity is checked on entry. A name relates
   only to itself under `<:` and joins and is never converted implicitly to or from its representation.
   Under dependent types the same shape gains indices. (2026-11-04)
4. **One `abstract` attribute, for every declaration, written at the declaration** (OCP-0010 R1), not
   export lists:
   - `abstract data T = …`: outside its module, `T` has no constructors, no fold and no `==` (§3.5);
   - `abstract type Celsius = Int`: a zero-cost nominal wrapper (`newtype`), no separate construct;
   - `abstract f = …`: under dependent types, `f`'s body does not unfold in conversion outside its module
     (Agda `abstract`/`opaque`, Lean `irreducible`).

   An abstract type is an existential package (Mitchell–Plotkin): under dependent types abstract types
   and lawful structures become one mechanism (a record with a type field). Transparent-only would be a
   dead end for dependent types, which need opacity anyway. (2026-11-04)
5. **Keywords `data` / `codata`** (Haskell-familiar; Charity, the categorical language of folds and
   unfolds without general recursion, used the same pair). The Spec and the documentation call them
   inductive and coinductive types. (2026-11-04)
6. **`codata` is declared by its destructors** (a coalgebra, maps out of the carrier), the dual of
   `data`'s constructors (an algebra, maps into it). Corecursion uses copatterns (§3.3). (2026-11-04)

   ```
   data   List a   = Nil | Cons a (List a)
   codata Stream a = head : a | tail : Stream a
   ```

7. **`record`**: a nominal product defined by its projections (`p.x`), with η (in a CCC a product is
   determined by its projections). Under dependent types a record with a type field is the Σ-package for
   theories, models and abstract types. Fields on a single-constructor `data` were rejected. (2026-11-04)
8. **`type` stays** as the structural abbreviation. (2026-11-04)

### 3.2 Matching

1. **`match` replaces `destruct`.** `inl`/`inr` are the constructors of the built-in `+`, so one named
   `match` covers declared and anonymous sums: `match e | inl x -> … | inr y -> …`,
   `match xs | Nil -> … | Cons x r -> …` (D042's bar syntax kept). Positional `destruct` is retired (D029:
   one way to write a construct). `destruct` was not kept even with named branches: next to `codata`'s
   destructors it would name the dual operation. `case f g` stays the point-free coproduct generator.
   (2026-11-04)
2. **Nested patterns in the first version** (`Cons x (Cons y r)`): pattern compilation to nested `case`
   and exhaustiveness checking (Maranget-style) are in the first surface patch. (2026-11-04)
3. **Exhaustiveness** is a type error, not a run-time failure (matching elaborates to `case`).
4. **Positivity**: a non-strictly-positive declaration is rejected with a named reason (plan 0.139).

### 3.3 Recursion: self-reference is surface sugar (2026-11-04, extended 2026-11-06)

A definition may call itself in the surface; the core never sees self-reference and has no `fix`.
Totality and productivity stay core theorems, untouched.

**What changes in the Spec, and what does not.**
- Unchanged: the core, the meaning, the core metatheorems (T+P, an effectful stream emits), the fold's and
  unfold's universal properties.
- Changed: the surface grammar and the surface judgment (D316); D241 in the decision state and GOAL.md's
  "no definition that refers to itself", reworded openly: the CORE has no self-reference; the SURFACE may
  use a definition's own name only as the head of a structural call or a guarded corecursive call.
- A recursive definition needs a signature, an exception to D323's optional signatures.
- The elaborated term is an ordinary core term, checked again by the core rules: no surface rule, even a
  wrong one, can produce a non-terminating or non-productive program. (Unlike Coq's guard condition,
  soundness does not rest on the check.)

**The rule is a scoping rule, not an analysis.** Inside its own body `f` is never a term. Matching a
constructor puts each recursive-position variable into the context twice: the subterm (`xs : List a`) and
a **call slot** (`xs ↦ r`): the form `f … xs …` is available and stands for `r`, the fold's result at that
position. A call `f a₁ … xs … aₙ` elaborates to `r a₁ … aₙ`. Anything else is rejected with a named reason
(`f (tail xs)`, `f (f xs)`, `f` passed as a value, a structural argument that is not slotted, a call on a
deeper subterm of a nested pattern). "You may recurse on what the pattern gave you."

| Surface | Core |
|---|---|
| `length (Cons _ xs) = 1 + length xs` | catamorphism |
| `xs` used beside `f xs` | paramorphism (a fold into `List a × B`) |
| `go acc (Cons x xs) = go (acc + x) xs` | a fold into a function type: `r : Int → Int`, the call becomes `r (acc + x)` |
| `size (Node l _ r) = size l + 1 + size r` | one slot per position |
| **mutual group** over mutual types (§3.4): `size (Node _ f) = 1 + sizeF f`, `sizeF (Cons t f) = size t + sizeF f` | one fold over the nested μ (Bekić), its algebra handling every type of the group |
| **nested position** (§3.4), form (i): `size (Node _ ts) = 1 + sum (map size ts)` | `map f ts` (the inner type's own `map`, `f` the function defined) IS the slot: the list of results |
| nested position, form (ii): a helper over `List (Rose a)` in the mutual group | the same fold; a nested type is a mutual one (Bekić) |

**The equations are theorems**: the fold satisfies the user's clauses and, by the fold's universal property
(D307; `fold-in`, `fold-unique`, proved), is the only function that does.

**Corecursion, with copatterns**:

```
head (nats n) = n
tail (nats n) = nats (n + 1)
```

the self-call must be the whole right-hand side of a destructor whose result is the codata type; its
arguments become the next seed of an `ana`, each destructor clause a component of the coalgebra (the form
OCP-0009 §4 names: unfolding guarded by observation). A **server**, `loop s = …; loop s'`: the call in tail
position of an effectful round; the definition is the anamorphism into `Eff` (D318). A non-tail call is a
round containing a loop, rejected as D318 requires.

**Not tail recursion.** Tail recursion is a criterion on a call's position and guarantees a constant stack,
nothing about termination; structural recursion is a criterion on the argument (termination); guarded
corecursion on position (productivity). `go x = if p x then x else go (step x)` is rejected: the `while`
loop GOAL.md excludes. Calls on deeper subterms would be a histomorphism (course-of-values recursion):
structural, a possible later extension.

**Run-time cost.** The accumulator form, compiled naively, builds n closures before applying any, with no
GC. The optimizer compiles "a fold into a function type, applied at once" as a loop (§7 step 7). Until
then such programs are correct but slow; the sugar may land first.

### 3.4 The functor grammar (2026-11-06)

1. **G1, nested positive occurrences, in this plan.** A `data` field may apply a declared type to an
   argument that mentions the recursive position, provided that type is strictly positive in that
   parameter (`List (Rose a)`; Coq's nested inductive types). Each declaration records its variance per
   parameter (as the DT kernel's `Spec/Variance` does). Polynomial functors are closed under composition
   and parameterised initial algebras (inductive containers), so μ stays well defined. The fold over a
   nested type uses the inner type's functor action (`mapᶜ`). Designed as a fragment of the DT kernel's
   `Desc`, so dependent types extend it, never replace it. Needed for every tree with a list of children
   (syntax trees: a compiler written in Once). The plan's largest proof patch: every recursion over `Fun`,
   the meaning of μ, the fold proofs, the cata codegen.
2. **G3, mutual `data` declarations, in this plan**, as surface sugar over G1: by Bekić's lemma a mutual
   fixed point is a nested one, so `Tree`/`Forest` elaborate to nested μ with no new functor former. The
   mutual function groups over them are §3.3's rule extended across the group.
3. **G2, function-typed recursive fields** (`Lim (Nat -> Ord)`, W-types), **postponed to dependent types**:
   rare in programs, and the DT kernel's descriptions have function-typed fields.

### 3.5 Structures: equality, theories, operators (2026-11-04 to 2026-11-06)

From principle: an operation is either **property-like** (determined by the object: unique when it
exists) or **structure** (a choice made on the object).

1. **Equality is a property.** `==` on `A` is `χ_Δ : A × A → 1 + 1`, the classifier of the diagonal. It
   exists exactly where the diagonal is decidable, and is then unique, so nobody declares it: it is
   available on `Unit`, `Int`, `Float` (§3.6), `+`, `*`, and every first-order `data` and `record` type;
   not on function types or codata (a type error); not on an abstract type outside its module unless the
   module exports it (representation independence). Its kind is `Eq` (item 4).
2. **Structure belongs to the type, as in mathematics** ("ℤ" means the ring with its order). A type's
   declaration states which theories it models; a theory's operator symbols resolve through the operand's
   type to that declaration. Exactly one candidate per type, so coherence holds by construction: no
   search, no coherence theorem, D310 kept. A second structure on one carrier is a second nominal type
   (`Down Int`, `Sum Int`).
3. **A symbol carries its theory's laws.** An overloaded (type-resolved) operator symbol is bound to
   exactly one theory, bound at most once in a program; seeing `a + b` licenses `a + b = b + a`. So
   `"hello" + " world"` is not allowed: concatenation is a monoid (`<>`/`++`). Other operators are plain
   definitions with one meaning (D331). `==` is always `χ_Δ`. Which theories the strata provide and their
   symbols (`+ - 0` an abelian group, `<>` a monoid, `< <= > >= compare` a total order, …) is a library
   decision made once under 3.6.
4. **A kind names a theory.** `∀(a : Ord). List a -> List a` ranges over the models of `Ord` (the category
   of models, natural in it), extending D238's kinds. `Eq` is the kind whose model is automatic. D371's
   relational reading extends to theory-kinded variables, interpreted by structure-preserving relations
   (for `Eq`: relations respecting equality).
5. **Explicit structure values remain** for choices that are not the type's own (`sortBy f`, a `Map`
   storing the order it was built with). No instance search; implicit dictionaries are not planned.
6. **Laws are proved off-line, in the strata, until dependent types** (L1, like Interpretations'
   contracts): theories and hand-written models live in the strata; each theory's laws are stated once in
   Agda over the meaning of its record type; each model's Agda certificate embeds the model's source text
   verbatim and proves the laws of that text, parsed by the verified front end; the strata (or plan 0.137
   library) build checks that the embedded text matches the file, so an edited model fails the gate. No
   digest (Agda cannot hash cheaply), no new syntax, no check in `once` compiling a program. Assumed models
   in any module (L2) were rejected: built now, replaced by dependent types.
7. **The optimizer does not use structure laws** (C-i): the compiler's correctness never depends on them,
   so they add no hypothesis to GOAL.md. With dependent types the laws are proved in Once and the
   optimizer may use them (§5: laws as directed paths).
8. **A user's own type may declare only derived structure** before dependent types, lawful by construction
   with laws proved once, generically, in Agda: transport along the declaration's iso (`abstract type
   Meters = Float` with Float's structure), products of models (a record of monoids is a monoid), the
   lexicographic order (constructors in declaration order). Hand-written models wait for dependent types.

### 3.6 Numbers, from principle (2026-11-06)

- **`Int` (ℤ/2ⁿ)** is a commutative ring, and separately a total order (the signed order, D263): **not an
  ordered ring**, since overflow breaks `a < b ⇒ a + c < b + c`. Total `/` (`a/0 = -1`) is its own
  operation, not field division.
- **`Float`**: IEEE 754 values (D113: the target's representation), which IEEE itself distinguishes
  (`+0`/`−0`, NaN payloads).
  - **`==` is identity (`χ_Δ`)**: reflexive; structural equality, keys and round-trips work over
    float-carrying data. Rust's choice (no `==` on floats) was rejected: it loses structural equality
    wherever a float appears. The compiler **warns when `==` is written directly at `Float`** in source
    (identity, not numeric comparison); generic uses never warn.
  - **`<`, `compare` are IEEE `totalOrder`**, the only order agreeing with identity `==` (Java's
    `Double.compareTo` semantics): `−0.0 < 0.0`, NaNs at the ends.
  - **IEEE comparison and arithmetic have their own symbols**: `==. <. <=. >. >=.` and `+. -. *. /.`
    (OCaml's convention), plus `isNaN`. IEEE `+` is not associative (rounding), so it cannot carry `+`'s
    laws; no cheap runtime makes floats a ring (any finite number system with rounding fails
    associativity; `-ffast-math` shows the cost of pretending).
  - **Float's theory is RoundedField**: the field operations conjugated by rounding (`Float` a retract of
    the extended reals, `x +. y = r(e x + e y)`), with the standard error bound
    `e(x +. y) = (e x + e y)(1 + δ)`, `|δ| ≤ u`, as its law, and commutativity of `+.`/`*.`.
  - **NaN results are canonical** in the Spec (a change to D113): one quiet NaN, the same on every target.
    Free on riscv64 (hardware); on x86 the compiler canonicalises only
    where bits are observed (`==`, `<`, bit casts, SigOp arguments, stores leaving the program). NaNs from
    outside keep their payload until an operation touches them.
- **Ring laws live in the exact types**: `Int` now; a fixed-point type (a lawful additive group) and exact
  rationals are possible library types later.

### 3.7 Scope rules (2026-11-03 to 2026-11-06)

1. **`Once.Spec` is about meaning only.** How polymorphism runs (layout passing, specialisation) is the
   implementation Spec's, beside `NoLeak` and plan 0.138's layout invariant; it reaches the Spec only at
   the boundary (`Spec.ABI`, if a polymorphic definition is exported). A nominal type needs no run-time
   representation.
2. **Type arguments are parametric**; no typecase before dependent types.
3. **This plan does everything that dependent types will not redo**; what they solve naturally waits
   (§4).
4. **Higher kinds are postponed** (E1): recursive types do not need them (`List a` is used fully applied),
   effects are arrows so effectful code needs no `Monad`, and `Type → Type` is a function type under
   dependent types. What waits is abstraction over monads on data.
5. **Polymorphic code generation** (F): one compiled body per definition with layouts passed, plus
   specialisation as an optimization, after plans 0.138 and 0.137 (§7 step 9). Monomorphisation until then.

## 4. Postponed to dependent types (OCP-0009)

- **GADTs and indexed families**: inductive families with indices at quantity 0, erased at run time.
- **Nested types** in the polymorphic-recursion sense (`data Nest a = Nil | Cons a (Nest (a × a))`):
  rank-2 algebras, polymorphic recursion (no monomorphisation possible), Kan-extension folds; most uses are
  indexed families with an erased index. (Distinct from G1's nested positive occurrences, decided.)
- **G2**, function-typed recursive fields (W-types).
- **Laws proved in Once**: law fields at quantity 0; a model that cannot prove them states a named
  postulate; the Agda certificates of §3.5.6 move into Once; hand-written models by users.
- **Higher kinds**; **intensional type analysis**; **refinement types**.
- **Implicit structure arguments** are not planned at all (§3.5.5); a future proposal needs evidence from
  real code.

## 5. What the dependent-type kernel implies (branch `plan-ref`, `bootstrap/DirectedHoTT/`, read 2026-11-04)

Handed to the DT work in `bootstrap/DirectedHoTT/INPUT-DATA-AND-STRUCTURES.md` (in the `plan-ref`
checkout, not yet committed there).

- **One datatype former over levitated descriptions** (`IMu I D i`, `D : Desc I`, a `Fin n` constructor
  tag). A `data` declaration is a signature entry whose body is a description; G1 and Bekić's mutual
  types are designed as a fragment of `Desc`.
- **The signature is a telescope (D081), a reference a projection (D082)**: §3.1.3.
- **Nominality needs opaque entries.** `δref` unfolds every entry, so data types there are structural
  today. Nominal `data T`: the type entry never unfolds; abstract: its constructor and fold entries are
  invisible outside the module's segment; `abstract f`: no unfolding outside the segment. A δ side
  condition scoped by segment, like `d <ˢ size`.
- **K-free pattern matching**: with `Id` and a directed `Hom`, matching over indexed families must
  elaborate without axiom K (Cockx–Devriese–Piessens).
- **No codata in the kernel**, consistent with OCP-0009: `codata` and copatterns stay in the runtime
  fragment.
- **Theories become records over the universe, structured types Σ-packages**; the surface of §3.5 is kept.
- **Laws as directed paths (to evaluate)**: `Hom t u = t ⟶* u`; a law stated as a `Hom` is an oriented
  rewrite with an in-language certificate, the candidate for laws the optimizer may use.
- **Layout**: an n-constructor `data` elaborates to nested binary sums in the Spec (same meaning); its
  implementation layout may use one tag word (plan 0.138, implementation Spec).

## 6. Spec changes this plan needs (each a patch the user approves)

1. **Types**: the signature of declarations; nominal names; `abstract`; `record`; variance per parameter;
   the functor grammar extended by G1 (§3.1, §3.4).
2. **Kinds**: kinds that name theories, `Eq` automatic; structure declarations on types; the resolution
   rule (an operator symbol resolves through its operand type's declaration) (§3.5). D238 extended.
3. **Surface**: `data`/`codata`/`record` declarations, constructors and destructors, `match` (D042
   superseded), nested patterns, exhaustiveness, positivity; clause definitions with call slots, mutual
   groups, the nested-position forms, copattern corecursion, servers (§3.2, §3.3).
4. **Numbers**: canonical NaN (D113 amended); the IEEE operator family `+. -. *. /. ==. <. …`;
   `Float`'s identity `==` and `totalOrder` (§3.6).
5. **Wording outside the Spec**: GOAL.md's "no definition that refers to itself" and D241 (the core has no
   self-reference, the surface may); OCP-0002's operator table; R7 unchanged (no search).

1. **Measure.** How polymorphic definitions are compiled (where monomorphisation happens); how

   codegen tiers); which Strata and example types become `data`; where `==`/`<`/`+` on `Float` are used

2. **Types patch** (§6.1, user approval), then follow the red: signature, nominal names, `abstract`,
   `record`.
3. **Surface patch for data and matching** (§6.3, first half): declarations, `match`, nested patterns,
   exhaustiveness, positivity; elaborator proved against it; tests including each named rejection;
   `Strata/Derived/Initial.once` rewritten with `data`; `destruct` retired.
4. **G1 and G3** (§3.4): the functor grammar, the meaning of μ and the fold proofs, the cata codegen;
   mutual declarations by Bekić.
5. **Recursion sugar** (§6.3, second half; §6.5 wording): call slots, para, accumulator folds, mutual
   groups, nested-position forms, copatterns, servers; tests; Strata in clause form.
6. **Structures** (§6.2): theory-kinds, structure declarations, resolution; the first theories in the
   strata (Eq automatic; TotalOrder, Monoid, AbelianGroup, Ring, RoundedField) with their Agda law

   products, lexicographic) with its generic Agda proofs; D371's relational reading for kinded variables.
7. **Optimizer: a fold into a function type compiles as a loop** (plan 0.129's optimizer, trace-preserving,

8. **Numbers** (§6.4): canonical NaN per target (riscv64 none, x86 at observation
   points), the IEEE operator family, `Float`'s `==` and `totalOrder`, the direct-`==` warning; OCP-0002
   updated.
9. **F**: after plans 0.138 and 0.137, a separate plan for layout passing and specialisation.

## 8. Done when

- A program declares `data`, `codata` and `record` types (nominal, optionally `abstract`, nested and
  mutual) and matches on them with `match` and nested patterns, exhaustiveness a type error; the core and
  the meaning are unchanged.
- A definition calls itself structurally, mutually, through nested positions, and corecursively by
  copatterns; it elaborates to fold/unfold; the core has no self-reference; an accumulator fold runs as a
  loop.
- `==` works on every type with decidable equality; `+`, `<`, `<>` work exactly on types that model their
  theories, each model's laws certified in the strata; user types derive structure lawfully.
- `Float` has identity `==`, `totalOrder`, the dotted IEEE operators and canonical NaN on every target.
- Every item of §4 is recorded as waiting for OCP-0009, and the DT kernel has §5's requests.
