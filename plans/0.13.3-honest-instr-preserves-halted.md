## Update 2026-05-10 — Option U chosen

`IRResultAWF.trace-preserves-halted` becomes a *universal* contract:

```agda
trace-preserves-halted :
  ∀ (s' : LocState FS) →
  halted s' ≡ false →
  TraceWF s' alloc trace →
  halted (proj₁ (exec-trace trace s' alloc)) ≡ false
```

i.e. "for any state where the IR-compilation invariant holds at trace
entry, this trace preserves halt." `TraceWF s' alloc trace` is a
state-threaded chain of per-instruction preconditions that resolves
exactly the conditional halt paths (`load-indirect`, `load-indirect-suc`,
`load-from-slot`, `restore-input`, `worklist-pop`, `store-indirect`,
`store-indirect-suc`).

Why universal-over-`s'` not specialized to construction `s`:
`compose-frontier-stable` and similar consumers reuse the field at a
fresh state matching the same input invariants. Specialised-to-`s`
(option Z) would force a separate transfer lemma at every reuse;
universal-over-`s'` gives consumers the contract directly.

Compared to option Z, this surfaces the IR-compilation invariant as a
type-level contract on every IR result rather than 30+ ad-hoc local
discharges. Aligns with the broader "explicit-trust / postulate-free
compile" direction (CPU semantics, two's-complement int, float later).



# Plan 0.13.3: Drop `iph-load-indirect` and friends from `InstrPreservesHalted`

## Why

The `InstrPreservesHalted` data type today contains constructors
that *should not exist* — they assert "this instruction always
preserves halted=false" for instructions that genuinely have a
runtime halt path:

```agda
data InstrPreservesHalted : AbstractInstr → Set where
  …
  iph-load-from-slot     : ∀ {slot} → InstrPreservesHalted (load-from-slot slot)
  iph-load-indirect      : InstrPreservesHalted load-indirect
  iph-load-indirect-suc  : InstrPreservesHalted load-indirect-suc
  iph-restore-input      : ∀ {slot} → InstrPreservesHalted (restore-input slot)
  iph-worklist-pop       : ∀ {slot} → InstrPreservesHalted (worklist-pop slot)
  …
```

Each of these is "backed" by a postulate explicitly marked unsound:

```agda
-- Sound because IR compilation guarantees loads are from valid locations.
load-indirect-preserves-halted : ∀ s alloc →
  halted s ≡ false →
  halted (proj₁ (exec-abstract load-indirect s alloc)) ≡ false
load-indirect-preserves-halted = !!
```

The lemma as stated is **provably false** — counterexample: any state
where `Input1` register holds a non-pointer value (under Plan 0.13.2's
StoredValue lift, this is e.g. `SV-Tag 0`), `exec-abstract load-indirect`
halts. Pre-StoredValue the analogous failure mode existed too
(memory cell missing); the postulate hand-waved it away with the
"IR compilation guarantees" comment.

The user's call (2026-05-09):

> If this is true, it should be provable. I've tripped at these
> things before, believing that something is true, then when trying
> to prove it you find why it's not.

Right. The lemma is conditionally true (under the IR-compilation
invariant) but unconditionally stated. The fix is to stop pretending
the unconditional version is sound, and propagate the conditionality
through the proof structure.

## Decision: drop the unsound iph-* constructors

Remove from `InstrPreservesHalted`:

- `iph-load-from-slot`
- `iph-load-indirect`
- `iph-load-indirect-suc`
- `iph-restore-input`
- `iph-worklist-pop`

(Likely also `iph-store-indirect` / `iph-store-indirect-suc` once
Plan 0.13.2's StoredValue refactor lands the new halt path for
non-pointer Input1.)

The corresponding `*-preserves-halted` postulates also go.

## What replaces them

`InstrPreservesHalted` continues to exist for the *unconditionally*
halt-preserving instructions:

- `iph-mov-to-output`, `iph-mov-input2-to-output`, `iph-mov-to-input`,
  `iph-mov-output-to-input2` — register moves never halt.
- `iph-store-at-slot` — writes a slot, no read failure path.
- `iph-lea-slot` — computes an address, no read.
- `iph-alloc-stack` / `iph-dealloc-stack` / `iph-reclaim-to` /
  `iph-push-frame` / `iph-pop-frame` — stack-pointer management,
  no halt.
- `iph-call-closure` — abstract no-op.
- `iph-worklist-init`, `iph-worklist-push`, `iph-worklist-check` —
  no halt.
- `iph-instr-save-closure-reg`, `iph-instr-load-const`,
  `iph-instr-load-code-addr`, `iph-instr-sigop` — register writes,
  no halt.
- (Phase 1) `iph-instr-case-on-tag` — halts at abstract level (the
  Phase 1 placeholder), but unconditionally.

For instructions that DO have a halt path (loads-and-stores via
register pointers, slot-based loads), the trace-level claim
"this trace preserves halted" must be discharged via *trace
well-formedness*, not via per-instruction marker constructors.
Concretely:

1. The validity predicate (`ValidAtWF`) already asserts the input
   register holds an `SV-Ptr` at trace entry.
2. The WF spec for each IR (`run-id`, `run-fst`, `run-pair`, etc.)
   already preserves this invariant clause-by-clause.
3. The composed claim "running this trace from a valid input
   doesn't halt" follows from threading the per-step validity.

So the trace-level halt-preservation moves into a new predicate:

```agda
-- "Running this trace from a state where the validity invariant
-- holds preserves halted."
TraceHaltsOnlyOnInvalidInput : AbstractTrace → Set
TraceHaltsOnlyOnInvalidInput trace =
  ∀ (s : LocState FS) (alloc : AllocState FS) →
  halted s ≡ false →
  TraceWF s trace →    -- trace-input precondition (validity-supplied)
  halted (proj₁ (exec-trace trace s alloc)) ≡ false
```

Where `TraceWF s trace` is the per-step witness chain that loads
read valid memory and indirect operations target valid pointers.

## Cascade

**Files affected** (~10-15 in proof layer):

- `SMPrimitives.agda`: remove the unsound iph-* constructors and
  their backing postulates. Update `exec-abstract-preserves-halted`
  to handle removed cases (probably becomes itself state-dependent
  via a new precondition).
- `TraceNoHeapWrites` and similar trace predicates that compose
  iph-* witnesses: lift to handle the conditional case too, OR
  introduce parallel "conditional" predicates.
- `SimpleWF`, `PairWF2`, `CurryWF`, `ApplyWF`, `ComposeWF`,
  `SumRecWF`: every WF spec that constructs a trace and claims
  halt-preservation must now thread the validity invariant
  through. Today this is implicit in the iph-witness chain;
  tomorrow it's explicit in a TraceWF chain.
- `IRTraceCorrect.agda`: discharge sites that compose iph-witnesses.

**Estimate: 3-5 days focused work.**

## Why this is worth doing

1. **Removes unsound postulates.** The `*-preserves-halted = !!`
   lines are lies that the codebase has been carrying. Each one
   removed is a real audit improvement.
2. **Surfaces the actual invariant.** The IR-compilation invariant
   ("traces only ever load from valid locations") moves from a
   comment into the type system. Future authors can see what
   actually has to hold.
3. **Aligns with Plan 0.13.2's StoredValue refactor.** The new halt
   paths from the StoredValue split are real; they need real
   reasoning. (A')'s "add precondition to the postulate" doesn't
   actually fix the problem — the iph-* constructors would still
   be lies at the marker level.
4. **The validity machinery already exists.** `ValidAtWF` and the
   per-IR WF specs already maintain the pointer invariant —
   threading it through trace composition is plumbing, not new
   architecture.
