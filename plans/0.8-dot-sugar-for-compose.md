# Plan 0.8: `.` as Sugar for `compose`

## Status: already implemented

Discovered during the follow-up session: `.` is already wired as
sugar for `compose` in `Once.Parser.Expr.parseCompTailWF` (left-
associative at the composition-precedence tier below arithmetic).
The rewrite `f . g ↦ RApp (RApp (RVar "compose") f) g` produces
exactly the shape that plan 0.6 Phase C.3's `expandBuiltins` +
`betaReduceApps` consume, so the sugar works end-to-end as of
commit `b32f8d0e` (plan 0.6 Phase C.3 landing).

Verified:

```once
swap : a * b -> b * a
swap = pair snd fst

firstSwapped : Int * Int -> Int
firstSwapped = fst . swap               -- Typecheck OK

triplehop : Int * Int -> Int
triplehop = fst . id . id               -- Typecheck OK

fullChain : Int * Int -> Int
fullChain = fst . swap . id             -- Typecheck OK
```

## Associativity note

The existing parser is **left-associative** (`f . g . h` parses as
`(f . g) . h`). The original plan sketched right-associativity
following Hask convention, but composition is associative so both
forms are semantically equivalent — no runtime difference. Left-
associativity was already in-tree and works; no change needed.

## Deferred sub-items (not currently blocking)

- **Printer round-trip for `.`** — the expression printer currently

- **Sections (`(. g)`, `(f .)`)** — out of scope; Once has no
  operator sections in general.
