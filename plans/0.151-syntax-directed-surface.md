# Plan 0.151 — The surface typing has one rule per form, and the generators are a table

## Summary

The language definition says which programs are accepted with a list of typing rules. Today most of
that list repeats one pattern: each of the language's dozen building blocks (`id`, `fst`, `inl`, `compose`,
`cata`, …) has its own rule, often three times over, once per way of checking. Some programs also match
more than one rule. This plan rewrites the list so that each kind of expression has exactly one rule, and
the building blocks are described once, in a table, instead of rule by rule. The accepted programs and
their meaning were meant not to change; in the end a few did, by the user's choice (§9). When it is done, the definition is shorter and reads as mathematics, and a
rejected program fails exactly one identifiable rule. That last property is what plan 0.149 needs in order
to explain every rejection with a proved reason.

## 1. Why

A category theorist reading `Spec/Surface/Typing.agda` would recognise the core (D231: the typed λ-calculus
as the internal language, the generators defined in it, `Core/Derived`) and be puzzled by the surface:

- **The generators are rules, not data.** 38 of the 65 rules are about one named generator in one mode
  (`c-fst`, `d-fst`, `s-fst-app`, …). A generator is a morphism with a type schema. Its typing should be one
  rule ("instantiate the schema") over a table, as plan 0.150 does for the numeric operators.
- **Some expressions have more than one rule.** The mode switches (`c-sub`, `d-infer`) apply wherever a more
  specific rule also applies (`c-pair-lit`, `d-lam`, `d-compose`, …), and some forms have alternative routes
  (`c-compose-g` / `c-compose-f`, D230; `s-app` / `s-app-spine`). A program that is rejected then has no
  single rule it breaks, so an error message cannot be a proved fact about the Spec (plan 0.149).

D316's amendment already asked for "generic rules where the per-generator ones only repeat them". This plan
carries that out and adds the second half: rule choice determined by the expression and the mode.

The options as first written:

- **E1, modes.** (a) Keep the three modes (D316's amendment); the cleanup is inside the bidirectional
  judgment. (b) Mode-free: a language change with full inference. Recommended: (a). Open.
- **E2, the generator table.** Each generator gets one entry: its type schema, the types of its arms if it
  takes any (`compose`, `case`, `pair`, `curry`, `cata`, `ana`), which of its type variables the expected
  type or domain determines (what decides the mode it can be used in), and its `Core/Derived` definition.
  The per-generator rules become one rule per mode over the table. Open points: the generators whose rule
  depends on the grade or the type, not just the schema (`apply` / `apply-eff`, `Out` / `Out-act`,
  `ana` / the loop, D317), and whether they are separate table entries or one entry with a type-directed
  case. Open.
- **E3, one rule per form and mode.** For each overlap, either (a) the Spec rule is restricted so that only
  one applies (a mode switch only for forms with no rule of their own in that mode; one route for
  `compose`), or (b) the Spec keeps the overlap where it reads as a definition, and the implementation's
  algorithmic judgment is syntax-directed, proved equivalent. Recommended: (a) wherever the restricted
  rule still reads as a definition, decided per overlap from the inventory; (b) only when (a) needs an
  algorithmic side condition. The property itself is stated as a metatheory claim (rule choice is a
  function of the form, the mode and the head of the given type), so a later rule cannot reintroduce an
  overlap unnoticed. Open.
- **E4, what must not change.** The same texts are accepted, and each elaborates to the same core term, so
  `Core`, `Meaning` and everything after elaboration are untouched. Proved as an equivalence between the
  old and new judgments during the branch; the old one is then deleted. Open, recommended.
- **E5, scope.** Surface typing first. Resolution, `Surface.Program` and the grammar (unambiguous by
  construction, the parse-error counterpart of one rule per form) are reviewed in the same step 1, and the
  user decides whether they join this plan or get their own. Open.

The overlaps differ in their core terms: (`app tf tx` with `x` coerced, against `coerce`d `tf`),
(`pair (coerce …) (coerce …)` against `coerce (… * …) (pair …)`), so the judgment as an elaboration is not
a function today, though the meaning of both terms is the same.

Other findings:

- (‡) **Four per-generator rules are already derivable**: `s-id-app`, `s-fst-app`, `s-snd-app` and
  `s-terminal-app` are `s-app-spine` with `d-id`, `d-fst`, `d-snd`, `d-terminal`, with identical core terms.
  They exist only because `SpecialHead` keeps those heads out of the spine. Taking `id`, `fst`, `snd`,
  `terminal` out of `specialGenerators` makes them redundant, with no change of accepted texts or terms.
- (§) **Type-directed pairs**: one form, two rules, chosen by the head of a type: `s-app` / `s-effApp` and
  `s-apply-app` / `s-apply-eff-app` (by the grade of a premise's synthesized arrow), `s-Out-app` /
  `s-Out-act-app` (by `ν`'s grade), `c-ana` / `c-loop` (by the given arrow's grade). They are disjoint, but
  the first three are decided by a *premise's synthesized* type, not the given type. The claim of §3 E3 ("a
  function of the form, the mode and the head of the given type") must also allow the synthesized types of
  the sub-expressions, or each pair becomes one rule with a type-directed conclusion (E2's open point).
- (†) **Rules with a free choice**: `s-let`'s `q` and `s-case`'s `ql qr` are not determined by the
  expression; the core judgment accepts one. Rule *choice* is still unique; the instance is fixed only
  after usage checking. E4's equivalence carries the quantities over unchanged.
- (*) **Name disjointness lives outside the judgment**: `s-sigop` and `s-def` are disjoint because a
  definition's name is a single word and `ModuleDenotes.def-not-sig` (D249); `s-sigop`'s `NotGenerator`
  covers only the 9 generators with a bare rule (`genNames`), not `compose`, `pair`, `case`, ….
  A one-rule-per-form claim stated over the judgment alone needs these as hypotheses, or a `Name` view
  (generator / signature op / definition / local) that the rules dispatch on.
- **Forms with no rule in a mode** are rejections that have no rule to name: in checking, `let` and
  `destruct` only through `c-sub` (their bodies are never checked against the given type, so
  `let x = 1 in \y -> y` is rejected); bare `apply`, `In`, `Out`, `curry`, `cata`, `ana` have no rule in any
  mode (only applied); `inl`, `inr`, `In`, `initial` applied do not synthesize; `inl`, `inr`, `curry`, `ana`
  have no domain-given rule. Keeping texts unchanged (E4) keeps these gaps. Plan 0.149 needs each as a
  named reason ("this form does not synthesize").

| `case` | `A + B ⇒ C` | `A ⇒ C`, `B ⇒ C` | – | `c-`, `d-` (join) |
| `pair` | `A ⇒ B * C` | `A ⇒ B`, `A ⇒ C` | – | `c-`, `d-` |
| `curry` | `A ⇒ (B ⇒ C)` | `A * B ⇒ C` | – | `c-` |
| `cata` | `μF ⇒ A` | `⟦F⟧A ⇒ A` | – | `c-`, `d-` (arm synthesized) |
| `ana` | `A ⇒ νF f` / `A ⇒⟨eff⟩ B` | `A ⇒ ⟦F⟧A` / `A ⇒⟨act⟩ B + A` | by the given grade (§) | `c-ana`, `c-loop` |

The ten without arms then need three generic rules: checked at a full arrow of the schema (today's `c-`),
from a domain (today's `d-`, when the domain determines the codomain), and applied (one rule per direction:
synthesized when the domain determines, checked when the codomain does; this absorbs the 11 `-app` rules).
`unit` and `toFloat` are ground: they read as constants with a type, like a signature operation. The six
with arms do not share one rule shape: `compose` needs the intermediate object (O2), `d-case` a join,
`d-cata` a synthesized arm, `ana` two meanings. Each is one table entry with its own rule per mode, which
still removes the generator name from the rule (the rule reads the entry).

### 6.6 Resolution, `Surface.Program`, the grammar (for E5)

- **Resolution** (`Surface/Resolution.agda`): syntax-directed by construction. `r-local` / `r-name` split on
  `x ∈ bound`; `rn-gen` / `rn-import` / `rn-own` on `GenWord x` and `FirstAt` / `Absent`; `r-qual` /
  `r-qual-path` on `FirstAt` / `Absent`; `r-this` by `a ≢ "this"`. No overlap. A failure names one rule
  (`main` referenced: `rn-own`'s `x ≢ "main"`).
- **`Surface.Program`**: `Walk`'s `w-skip` / `w-sig` / `w-nosig` are split by the declaration form. A
  `DTypeSig` without its `DFunDef` has no rule. `w-sig`'s `Principal` is a universal condition, so its
  failure is a counterexample (a smaller type that checks), not a failed premise. `ModuleDenotes`'s fields
  (`distinct`, `sig-distinct`, `def-not-sig`, `mains`) are named conditions.
- **The grammar** (`Surface/Grammar.agda`): every alternative is guarded by its first token or a negative
  lookahead (`¬ Starts`, `¬ ArgStart`, `¬ NumeralStart`, `¬ QualSuffix`, `¬ Reserved`), so it reads as
  unambiguous. No Spec claim states that (`Parses text m → Parses text m′ → m ≡ m′`); the parser's
  soundness and completeness are proved, its uniqueness is not.
  (Not checked here: `Surface/Lexing.agda`.)

None of the three has an overlap to remove. What E5 decides is only whether their uniqueness claims
(resolution and parsing are functions) are stated and proved in this plan or in their own.

## 7. The decisions, worked out (step 2, 2026-11-15)

### 7.1 O1 and O2 without a negative premise

**O1** (`s-app` / `s-app-spine`). Split application heads by FORM into two classes:

- *checking heads*, the forms that never synthesize: `RLam`, a definition with type variables, a bare
  generator other than `unit` and `toFloat`, and a generator applied to its arms (`compose f g`, `case f g`,
  `pair f g`, `cata a`, `curry f`, `ana c`);
- *synthesizing heads*: every other form.

`s-app` takes synthesizing heads, `s-app-spine` checking heads. Nothing accepted is lost: a synthesizing
head has no domain-given rule but `d-infer`, so the spine for it needs the head to synthesize, and then
`s-app` accepts too (the argument synthesizes `X <: A`, so it checks at `A` by `c-sub`). A checking head
never synthesizes, so `s-app` never applied to it. Where both applied, the elaborator took `s-app`, which
the split keeps (same core term). The class reads the name's declaration (arity), as `s-def` and `c-poly`
already do.

**O2** (`c-compose-g` / `c-compose-f`). Split by the form of the inner arm `g`: when `g` has a domain-given
rule (a synthesizing form, by `d-infer`, or one of the `d-` forms, `d-poly`'s occurrence condition included)
the `g` route; otherwise (`inl`, `inr`, `In`, `curry f`, `ana c`, `initial e`, a definition failing the
occurrence condition, …) the `f` route. Load-bearing claim, to POC before the Spec patch: when `g ⇐ A ⇒ B′`
and `g` has a domain-given rule, then `g ↦ B` from `A` with `B <: B′`, so whenever `c-compose-f` accepts,
`c-compose-g` does too (`f`'s synthesized `B′ ⇒ C′` checks at `B ⇒ C` by `c-sub`). If it fails for a form,
that form is a text the split would reject: then back to the user.

**Result (2026-11-15): the claim is FALSE; O2 is open again.** The domain-given mode is weaker than
checking for two forms, so a domain-class `g` can check at `A ⇒ B′` while `g ↦` fails:

- `d-case` joins the branches' codomains in `<:ᶜ` (domains kept), while `c-case` only needs a common
  supertype in `<:`. Confirmed on the compiler (Oct 31 build), all `once check`:

  ```
  f1 : Unit -> Int -> Int
  g1 : Unit -> (Int + Unit) -> Int
  h  : (Void -> Int) -> Int
  t : Unit + Unit -> Int
  t = h . case f1 g1                       -- accepted, by c-compose-f only
  t3 = (case f1 g1) ((inl () : Unit + Unit))  -- rejected: d-case has no join
  ```
- `d-cata` needs the algebra to synthesize exactly `⟦ F ⟧F A ⇒ A`; `c-cata` accepts a subtype
  (`boom : Unit + Int -> Void` as an algebra of `K Unit ⊕ Id` at codomain `Int`). On paper only.

(The other domain-class forms pass with a recursive class: `RLam` iff its body is synthesizing, `compose`,
`case`, `pair` iff their arms are, `RPair` iff both parts are.) So no split of O2 keeps the accepted texts:
by `g`'s class it rejects `t` above; by `f`'s class it fails because checking is not closed upward
(`c-cata`, `c-poly` are exact in the domain). One declarative rule with an existential middle object accepts
MORE (`compose inl inl`) and needs inference. Options in §8.

### 7.3 The table by structure (the user's question, 2026-11-15)

Asked whether categorical structures help the Spec as they do the proofs (plan 0.112). Two uses fall
inside E2, and neither changes what is decided, only how the table and the merged rules are written:

- **The table is grouped by universal property**: category (`id`, `compose`), products (`fst`, `snd`,
  `pair`, `terminal`), coproducts (`inl`, `inr`, `case`, `initial`), exponentials (`apply`, `curry`), the
  initial algebra (`In`, `cata`) and the final coalgebra (`Out`, `ana`). Each group is a structure map and a
  mediating morphism, which explains the "determines" column instead of listing it: a map OUT of the
  universal object (`fst`, `snd`, `apply`, `Out`) is fixed by its domain, a map INTO one (`inl`, `inr`,
  `In`) by its codomain; a mediator out of a colimit (`case`, `cata`) has a domain-given rule, a mediator
  into a limit (`curry`, `ana`) only checks. The exceptions read off the same structure: `pair` and
  `terminal` have domain-given rules because their arms share the domain and `Unit` is constant; `initial`'s
  codomain is free, so `d-initial` picks `Void`.
- **The grade-indexed rules are one rule over a family of type formers** `T π` (plan 0.112 decision E: a
  family of monads with monad morphisms): `T pure B = B`, and `T π B = Unit ⇒⟨π⟩ B` for an effectful `π`.
  Application is then one rule: `f ⇒ A ⇒⟨π⟩ B`, `x ⇐ A` gives `f x ⇒ T π B`; `apply` and `Out` the same.
  `ana` is ONE universal property, the mediator into a final coalgebra (corrected 2026-11-15 by the user;
  the first draft said two), at two functors: `T f ∘ ⟦ F ⟧` with final coalgebra `ν F f` (for `f = pure`
  the ordinary stream of a pure coalgebra), and `T act ∘ (B + −)` with final coalgebra `T∞ B`, which Once
  presents as the arrow grade `eff` (`Eff A B` is `A → T∞ B`, D317). There is no separate loop: "the loop"
  is only the name of `ana`'s core term at the second functor (`loopᶜ`, built on `iter`). One table entry,
  one rule per mode; the given type selects the functor.

Outside this plan: stating the laws the Metatheory already proves as named structures (`<:` a preorder,
thin by `<:-unique`; `⊔` a partial join; `Quantity` a semiring) changes no rule and belongs to plan 0.112.
Reading the surface judgment as the presentation of the free such category (`Meaning` as the functor out
of it) is the meaning side, plan 0.120 / D318, not this plan.

### 7.4 No "loop" (the user, 2026-11-15)

The name misleads: it suggests a construct of its own, while it is `ana` at the functor `T act ∘ (B + −)`.

### 7.5 O2 decided: option II (the user, 2026-11-15)

The discussion: a category theorist's rule is `∃ B. g : A → B, f : B → C`; the two routes only say where
`B` comes from, which is the annotation question (E1's trade-off, local to one form). Decided:

- **One rule per form of `g`**: when `g`'s form has a domain-given rule (the recursive class of §7.1), `B` is
  the codomain `g ↦` gives from `A`; otherwise `B` is `f`'s synthesized domain. A text where `g` has a
  domain-given form but no domain-given type (`h . case f1 g1`, whose branches meet only at `Void -> Int`)
  is rejected; an annotation on `g` recovers it. Accepted texts change only there.
- **`d-cata` gives the least codomain**: the algebra synthesizes `A₁ ⇒ A₂` with `⟦ F ⟧F A₂ <: A₁`, codomain
  `A₂`, coerced (today: exactly `⟦ F ⟧F A ⇒ A`). Accepts slightly more (an algebra into `Void`).
- **`d-case` keeps its join in `<:ᶜ`** (parametricity, `Spec.Sub`).
- E4 becomes: the same texts except these, each with the same core term as today where it was accepted.
- **No follow-up plan**: inferring the middle object is rejected; see §7.6.

### 7.6 Why option II is the right rule, not a stopgap (the user, 2026-11-16)

Option II is what D321/D322 already decided for `case`, applied to `compose`. `case` was solved by:
(1) local inference, each branch giving its least codomain from its given domain; (2) where two types meet,
a lattice operation (the join), each branch coerced; (3) the join in `<:ᶜ` only, never meeting domains,
so typing commutes with type substitution (parametricity, `Spec.Sub`); (4) a branch with no domain-given
type falls back to checking against a type from outside.

For `compose f g : A → C` the middle `B` is bounded from both sides: `g` gives the lower bound `B_g`
(its least codomain from `A`), `f` the upper bound `B_f` (its synthesized domain), and any `B` with
`B_g <: B <: B_f` denotes the same map (D226). One lower and one upper bound need no join, only
`B_g <: B_f`, which is subsumption; the canonical choice is the least, `B = B_g` (D321). So:

| `case` (D322) | `compose` | rule |
|---|---|---|
| each branch gives its least codomain locally | `g` gives `B_g` | `c-compose-g` |
| no domain-given type → check against an outside type | `g` checks against `f`'s domain | `c-compose-f` |
| no join → annotate | `g` has no domain-given type → annotate `g` | the rejection |

The one text II newly rejects is a `case` question, not a `compose` one: `h . case f1 g1` and
`(case f1 g1) x` fail at the same point, the join of `Unit → Int → Int` and `Unit → (Int + Unit) → Int`,
which does not exist because a join keeps domains (point 3). Master accepted the first only because
`compose`'s second route bypassed `case`'s rule; II makes the two uniform. If that rejection ever matters,
the change belongs to the join, not to `compose`.

Options considered and rejected (2026-11-16):
- **Full inference of `B`** (the declarative `∃ B` rule): the cleanest statement, but it needs constraint
  solving under subtyping (an untrusted solver as D072, a completeness proof for it, unclear decidability
  with λs on both sides; algebraic subtyping would be a redesign), and a rejection becomes "no `B`
  satisfies these constraints" instead of one rule's premise (plan 0.149). It is also not how `case` was
  solved: type inference stays local.
- **A dual mode** (greatest domain from a given codomain, for `inl`, `inr`, `In`) as a third source of `B`:
  it needs a priority among three sources, every fixed order loses texts another accepts (§7.1), and
  `case` never needed it.

The user's working note on D321 (`principal-types-inl.md`, untracked) is folded into D321/D322 and deleted.
