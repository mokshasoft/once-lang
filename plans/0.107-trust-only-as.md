# Plan 0.107 — Trust only `as`

## 0. The property

> **The only thing trusted about turning a program into bytes is that `as` does what it should:
> it assembles the canonical text of an assembly program into bytes that decode to that program.**

    as-faithful : ∀ (F : File) → decode (assemble (print F)) ≡ just (program F)

Everything from `Source` to the `File` is PROVED; the emitted text IS `print F`. A compiler
decision can then never hide inside a trust point: if the text and the verified program
disagree, the proof that `compile m ≡ Built (print (emit m))` — or the theorem replacing
`<arch>-loader-faithful` — fails to typecheck.

**Image, not IR.** The axiom sits where the proof ends and `as` begins: the per-arch concrete
instruction program (`RVS.Program` etc. — the very syntax `compile-abstract` lowers the verified
image to). IR → flat → concrete is already proved (`compile-abstract`, `ConcFlatSim` ×3).

## 1. The measurement (2026-10-04)

* `ArchCorrect.asm-trace-correct` is discharged per arch by `<arch>-loader-faithful`, quantified
  over `∀ m asm → compileFromModule … m ≡ Built asm → … → asm-sem asm ≡ conc-trace image`. Its
  LHS is whatever TEXT the compiler emitted, so it trusts every piece of code that builds the
  text: `irToAsm`'s frame, `functionPrologue`, `asmHeader` (`_start`, `.bss`/`.data`),
  `emitArithBlocks`, and `Compile.agda`'s concatenation. D261's bug lived there.
* The text is not a print of one program: the arch syntax (`RVS.Instr` …) has no directives
  (`.globl`, sections, `.skip`, `.quad`), and the arith blocks are emitted as separate text
  (`emit-arith-blocks`) whose instructions the model finds through a POSTULATED map
  (`arith-env-<arch>`).
* Further per-arch postulates in the CPU instances sit on the same boundary: `ev-<arch>` (which
  SigOp a label is), `call-at-<arch>` (which answering call), `step-budget-<arch>`.
* Postulates of the same too-wide shape (quantified over the compiler's OUTPUT, not over a
  program): `program-symbols-resolvable` (FALSE — a comparison does not link), `program-labels-
  distinct`, `Compile.opt-trace`, and six in `FlatCore/RunWF` (`call-site-shape`,
  `ret-site-owes`, `emitted-thunk-guarded`, `emitted-code-addr-has-body`, `ret-budget-matches`,
  `run-meets`).

**The deeper root (found while scoping, 2026-10-04): TWO PARALLEL WALKS.** The proofs reason
about `ProgramImage.program-image` (main's unit first, then each table entry behind `c-entry`,
lowered by `compile-trace-cnt o 0`). The emitter folds `compileFunWithTarget` over the
`CompiledFun` list in MODULE order — per-function `irToAsm` text + `functionPrologue`, its own
label counter (`l₁ ⊔ l₂`). Nothing makes the two agree except the loader axiom. D261 aligned one
detail (the entry frame); the fix is ONE walk: the emitted program IS the lowering of
`program-image`. Consequence: function ORDER in the binary changes (main first), so the gate is
"exit tests + `cabal test` unchanged", not byte-identity.

**Missing syntax (riscv64; x86 to be measured the same way).** No `ecall`, no data labels
(`once_heap_base`/`once_heap_pos` are `lla`'d by `_start`), no section/`.globl`/`.skip`/`.quad`
directives. The arith blocks are `XInstr`, a separate instruction language, run by the model
through the postulated `arith-env-<arch>` label map and emitted as text by `emit-arith-blocks`.

## 2. What stays trusted, stated

* `as-faithful` (per arch) — the assembler, and the arch's canonical text syntax `print` (read
  clause by clause against the GNU syntax, as `run` is read against the ISA manual).
* The CPU model: the ISA semantics `run` (hardware) and `decode` (only through `as-faithful`).
* The OS loader's initial state (`initialState`; facts like `stack-top-in-stack`) — what the
  kernel guarantees at `exec`. Not the compiler; recorded so it is never mistaken for it.

## 2½. Platform-general (user, 2026-10-04: Once is also for bare metal)

Nothing in the compiler's runtime may assume an OS:
* `_start` = `c-start B` at pc 0 (a new `FlatCtrl`: flat semantics `do-thunk B`, reserving the
  OUTERMOST frame; per arch it lowers to heap-register init — the `.bss` heap's address — plus
  the frame reservation), then `main`'s unit linked by `link-top done` (main's body ends in a
  SILENT STOP `c-label done; c-jmp done` instead of `c-ret`), then the table. So
  `program-image o p = c-start B ∷ link-top (top-done o p) (ir-to-unit main) ++ fns-image (suc L)
  table`. (An earlier draft — a concrete-only stub calling `main` — is impossible: `CompiledCorr`
  pins the concrete code to `compile-trace prog`, and `SegWF` lets a body entry be reached only by
  a call. The start is therefore ABSTRACT code, proved like every other instruction.)
  The run begins OUTSIDE every frame: `Reachable prog 0`, `mkSeg 0 []`. No exit syscall: the observable is the SigOp trace
  (programs don't return a value), so after `main` returns there are no more events — the same
  meaning on bare metal and on Linux. An exit code is the argument of an interpretation's exit
  SigOp, never the compiler's.
* The environment contract (`initialState prog`) is "pc at `_start`, `sp` in a stack region" —
  what a kernel's `exec` OR a bare-metal reset/linker script provides.
* The heap is a `.bss` reservation (a linker-script section on bare metal).
* `main` gets its own `c-entry` like every function (the emitter's hand-written main prologue was
  the third gap the loader axiom absorbed: `FlatFromObs.entry-s` documents that the proofs start
  AFTER a reservation that existed only in the emitted text).

## 3. Phases (top-down: the trust statement first, follow the red)

a. **The trust boundary.** `ArchSemantics` gains the assembly FILE syntax (`File`: sections +
   the instruction program + directives), `print : File → String`, and the single law
   `as-faithful`. `ArchCorrect` loses `asm-sem`/`assemble-correct`/`asm-trace-correct`; the
   compiler's result is the `File`, the text its `print`. Follow the red.
b. **The emitter produces a `File`.** `_start`, the heap `.bss`/`.data`, `.globl`s, function
   entries (already `c-entry`'s lowering, D261), the linked image, the arith blocks as
   instructions in the file. `Compile.agda`'s string concatenation is deleted.
c. **The run of the file is the run of the image.** Per arch, a THEOREM replacing
   `<arch>-loader-faithful`: the file's `_start` runs, enters `main`, and from there the
   concrete run is the image's (`conc-trace`). `arith-env-<arch>`, `ev-<arch>`, `call-at-<arch>`
   become DEFINITIONS read off the file (label lookup; label provenance).
d. **The other too-wide postulates**, one by one: stated over the program/IR and proved, or
   narrowed the same way. `program-symbols-resolvable` becomes the arith recogniser's
   completeness (the comparison case becomes a TYPE ERROR until plan 0.108 lands — so 0.108
   follows directly).
e. **Gate.** `Once.Certified` green; extraction + `cabal test`; exit tests 72/0/0 ×3 (binaries
   change only by function order and label numbering — one walk replaces two). AND THE REGRESSION
   PROBE (user, 2026-10-04): reintroduce D261's entry-style riscv64 prologue on a scratch copy
   and confirm it is a TYPE ERROR, not a green apex.

## 4. Risks

* `File`/`print` per arch must cover every directive used today; the exit tests on three
  arches are the guard.
* The arith blocks: either lower `XInstr` into each arch's syntax (and prove the lowering
  against the `XInstr` semantics the arith proofs use), or give the `File` an arith section the
  model runs as `XInstr`. Decide when phase b reaches them (top-down).
* The `_start` stub becomes proved code on three arches (small, but new correspondence work).
* `call-sym` (calls to interpretation symbols by name) keeps an external boundary: the linked
  interpretation object. Its contract is D061's (the interpretation's), not the compiler's.

## 6. Phase d, decomposed (2026-10-05, after 0.108/D264)

`FileWF.file-wf` is ONE statement over the file; it is proved in three layers, top-down:

1. **The file's symbols ARE the image's.** Per arch, the lowering is label-faithful:
   `label-defs (compile-trace t) ≡ adefs t` and `refs (compile-trace t) ≡ arefs t`, where `adefs`/
   `arefs` read the ABSTRACT image (arch-independent: `c-label` / `c-entry` define; `c-jmp`,
   `c-branch-*`, `c-call-fn`, `instr-load-code-addr`, `c-start`'s heap, `instr-sigop` reference).
   Mechanical: one clause per instruction, ×3 arches (the image is `NoNested`, so
   `compile-trace-cnt` is `compile-trace`).
2. **The image is closed and its labels distinct.** Jump targets are labels of their own unit
   (`LabelScope`), direct calls name table entries (`CallsLinked`, `Linked`), code addresses name
   laid-out bodies (`ThunkScope`), every SigOp is a block the rewrite registered (D264: bare
   primitives lift, comparisons register theirs) or a declared interpretation symbol (`externsOf`).
   Labels: one counter threaded through the whole image (`fns-image`), so indices are distinct.
3. **Symbols are injective where they meet.** `labelSym` separates provenances by prefix
   (`.Lonce_`, `.L_thunk_`, `once_`); within `.Lonce_` the decimal index after the LAST `_`
   decides (digits contain no `_`); function vs block symbols by `once-symbol-path-injective`;
   `once_heap_base` and `_start` by their first characters after the prefix.

`entry-in` is immediate (the image starts with `c-start`, which lowers to ≥ 1 instruction).

## 7. Status of phase d (2026-10-05)

* Layer 1 PROVED ×3 (`Target.<arch>.FileSymbols`); `FileWF.file-wf` is a THEOREM over the image.
* Layer 2, references: `RefsClosed` (every local reference closes in its unit) and `ImageResolved`
  (the program image's references resolve) PROVED; `ImageWF.prog-resolved` is no longer a postulate.
  It rests on `prog-sigops`: every SigOp names a block or a declared extern.
* **`prog-sigops` is FALSE today, for every program that calls an interpretation.** Measured on
  `arith-bare-op.once` (x86-64): `main` calls `once_15Interpretations_5Linux_8Syscalls_4exit` —
  the RESOLVED canonical name, and the symbol the interpretation object defines (`nm`) — while
  `externsOf` and the primitive's own table entry use `bare (funName fi)` =
  `once_38InterpretationszdLinuxzdSyscallszdexit`. The file also DEFINES those table entries, whose
  bodies call themselves (dead, since references go to the resolved name). `ld` links only because
  the interpretation object happens to supply the resolved spelling.
  This is the FFI-identity decision left open at plan 0.105's close ("one FFI decl has three names;
  the cleanup is separate — the import table keyed by `CanonicalName`"). It is a design decision,
  so it is a principled blocker for `prog-sigops`. A fix in the direction already recorded:
  (1) a primitive is the interpretation's, not a table entry (no emitted body); (2) its identity is
  the resolved `CanonicalName` (`showCanonical cn` is already its key); (3) `externsOf` = the
  symbols of those names. Then `prog-sigops` follows from linkedness (`⊢sigop` membership).
* Remaining, unblocked: uniqueness (`prog-unique`, `lib-unique`), the library's references.
