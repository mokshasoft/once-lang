# Plan 0.33 — Label provenance & namespacing (collision-free labels across the compile-time boundary)

## Problem

`find-label` resolves a jump by scanning the program for a `label` whose
number equals the target. This is only correct if **no two distinct jump
targets share a label number**. The flat cata emits its own loop labels
(`ld-top … la-end`), and the abstract↔x86 composition's load-bearing
lemma `find-label-pres` (Plan 0.32 Phase D, Stage 1b) needs: *the cata's
target appears exactly once in the compiled program* (so the x86
`find-label` lands at the block-offset image of the flat target).

The hard part is **two different compile times**:

1. **Compiler-compile-time** — when the verified Once compiler is built.
   Its own label emitters (cata / case / loop) are known here; a single
   monotonically-increasing counter makes them mutually distinct.
2. **Once-program-compile-time** — when a `.once` program is compiled.
   **SigOps are resolved here**, by code the verified compiler never sees.
   It can constrain them *only* through the `PreservesCCC` contract.

A shared monotonic counter **cannot span this boundary**: the compiler
can't thread its counter into SigOp codegen that doesn't exist at
compiler-compile-time. So the counter solves within-compiler uniqueness
but not compiler-vs-SigOp collision. SigOps **should** be allowed to use
labels (internal control flow: division loops, bignum, inlined ops), so
"forbid SigOp labels" is too limiting, and "prove the SigOp assembly has
no labels" is unprovable (the assembly is opaque to the verified
compiler).

## Design — provenance-typed labels + namespace contract

Make `Label` carry **provenance** instead of being a bare `ℕ`:

```agda
data Label : Set where
  once  : ℕ → Label            -- compiler-allocated (counter-distinct)
  sigop : String → ℕ → Label   -- SigOp-allocated; String = the SigOp's name
```

- **Cross-provenance disjointness is DEFINITIONAL.** `once n` vs
  `sigop name m` are unequal by constructor, so a cata jump (target
  `once X`) scanning a SigOp's `sigop "arith.div" k` never matches — no
  shared counter, no freshness lemma, no postulate. `find-label-pres`'s
  cross-namespace obligation becomes free.
- **Within `once`:** the monotonic counter keeps its (correct, bounded)
  role — it makes all `once X` mutually distinct (cata vs case vs loop).
- **Within `sigop name`:** the SigOp's own responsibility; across SigOps
  the `name` disambiguates (SigOp names are unique dispatch keys).
- **Emit** renders `once n → .Lonce_n`, `sigop nm k → .Lsigops_<nm>_k` —
  the string prefixes, typed rather than munged. (Assembly-level `.L`
  distinctness within a file falls out of the rendering.)

### The contract (`PreservesCCC`)

One structural obligation added: **a SigOp's codegen emits only
`sigop <its-own-name> _` labels** (equivalently: no `once _`). Checkable
and discharged per-SigOp when it is provided — not an opaque "emits no
labels", not a compiler-invented postulate. Honest boundary split: the
compiler proves its half (`once` labels distinct via the counter), the
SigOp provider proves theirs (stays in its namespace).

### Why this is the right shape

- Today SigOps are invoked via `call-sym` to a *separate* symbol, so
  semantically their labels aren't even in the caller's `Program` that
  `find-label` scans — isolated by the call boundary. The namespace
  becomes load-bearing the moment a SigOp is **inlined** (and for
  assembly-level distinctness). So the payoff is "we can safely allow
  label-using, possibly-inlined SigOps" — a capability we keep open.
- It is the typed realization of [[feedback-injectivity-not-lockstep]]:
  injective *encodings* (here, injective label provenance) are what the
  proof needs; nothing about execution lockstep.

## Relationship to Plan 0.32 (composition)

`find-label-pres` needs "the cata target appears once." With bare `ℕ`
labels this is dischargeable *today* (live `compile-sigOp = call-sym …`
and `compile-const` emit no labels; the only labels in a compiled cata
program are its own distinct `c-label`s). With provenance labels it
becomes **structural** for any future program (label-using SigOps, nested
catas), not "true because today's SigOps happen to be label-free."

## Staging

- **S0 — finish the composition on bare ℕ labels first (Plan 0.32 Phase
  D).** Validates the fuel-induction machinery end-to-end; discharge
  `find-label-pres`'s side-condition via the current "cata labels distinct
  + rest label-free" fact. (Does not block on this plan.)
- **S1 — introduce `Label` provenance.** New datatype; `label`/`c-label`/
  `jmp`/`je`/`jne`/`find-label`/`find-label-go` take `Label`. Compiler
  codegen emits `once X` (X from the existing monotonic counter). Emit
  renders the two constructors. Decidable equality on `Label`.
- **S2 — `PreservesCCC` namespace clause.** Add the obligation that SigOp
  codegen stays in `sigop <name> _`; thread it so `find-label-pres`'s
  side-condition is discharged structurally (cross-provenance by
  constructor; within-`once` by the counter monotonicity lemma).
- **S3 — within-`once` distinctness lemma.** Formalize "every compiler
  label `< counter`, counter monotone ⟹ all `once` labels distinct" from
  the threaded counter (ir-to-trace `l`, compile-trace-cnt `n`).

## Blast radius

`Label` flows through `Syntax` (Instr: `label`/`jmp`/`je`/`jne`),
`SMCore` (`FlatCtrl.c-label`/`c-jmp`/`c-je`), `Semantics`
(`find-label`/`find-label-go`/`execInstr` jumps), `Emit`,
`AbstractToX86` (`compile-abstract` control lowering), `IRToTrace`
(cata label allocation → `once`), the flat machine `Flat`
(`find-label`/`fl-go`), `FlatComposition` (`has-label`/skip lemma →
keyed on `once` target), and `PreservesCCC` (+ the SigOp contract). The
3 backends (x86-64/x86-32/RISC-V) mirror the control lowering.

DESIGN RULE carried over: keep `find-label` / scanners with-free where
they already are; provenance is a constructor split, not a `with`.
