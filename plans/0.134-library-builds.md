status: OPEN on branch `library-builds` (opened 2026-10-31). §3 A DONE (groundwork, decision-free).

## 1. Why, and what is true today (measured 2026-10-31)

The apex covers `build` of a PROGRAM only: `Adequacy.Compile.compile-mir` returns `nothing` when `moduleToIR`
finds no `main`, so `CorrectCompiler` says nothing about what `build` writes for a library. That is the
long-standing "library gap". Measured:

- **What a library build writes.** `assemblyFromModule`'s text, the same function `build` uses for a program,
  minus the link. For `tests/lib-multi.once`: `once_7firstOf:`, `once_8secondOf:`, `once_6dupInt:`, a
  `once_heap_base` `.bss` block. For `tests/lib-test.once` (only `swap`, a schema): just the heap block, because
  a schema is instantiated at its uses and never emitted.
- **Nothing can call it.** No symbol is `.globl`. The functions use Once's internal convention: the argument in
  `rdi`, and the heap bump pointer in `r15`. Nothing initialises `r15` for an outside
  caller. Values are Once's heap representation (pairs are cells, closures are code+env cells), not a C ABI's.
  No C backend exists (D008's `.h`/`.c` output is long gone). So a library `.s` assembles and is linked by
  nobody.
- **Who uses `build --lib`.**
  - As a TYPE-CHECK stand-in, 56 call sites: `PuritySpec`, `TelescopeSpec` and `SpecMatrixSpec.checkLib`. They
    use it because `once check` has no `--strata` and those tests resolve imports against the test strata.
  - `examples/Makefile` (`LIBRARIES := categorical swap`) and `tests/Makefile` (`test-lib`): "it builds".
  - No program, test or tool consumes the emitted file.

So the gap is real, but what fills it is a design question first: today's library output has no meaning a
caller could rely on, verified or not.

## 2. Decision needed (yours)

What is a library build?

- **(B) Not offered until it means something. Recommended now.**
  - `build` of a module without `main` is an error: "a library is checked (`once check`), not built".
  - `--lib` goes. `--exe` goes too, since it is the default and only mode.
  - A library's guarantee is D355's: `once check` decides `_⊢ᴹ_`.
  - Everything `build` writes is then on the apex (`CorrectCompiler`), and nothing it writes is unverified.
  - Same move as `--alloc` (D352): remove a mode that promises what nothing delivers.
  - Reversible: (A) adds it back as a real feature.
- **(A) A verified library.**
  - A library build exports each monomorphic definition at a declared external convention.
  - The Spec states what a call from outside means: argument in, the definition's meaning (`teleSem`) out, its
    trace in the caller's world.
  - The apex gains a library conjunct.
  - This needs, in the Spec:
    1. an external value representation for each first-order type (D061's concreteness is the natural
       boundary: only concrete types cross);
    2. a calling convention per target, the mirror of plan 0.111's obligation, here the compiler's side;
    3. an init/teardown for the runtime state the code assumes (heap pointer, heap block).

    In the compiler it needs exported symbols, an entry shim per export, and the correspondence for a call
    entering mid-image (plan 0.89's units, plan 0.93's `BlockRuns`).
  - Large, and it overlaps 0.111/0.89/0.93; its own plan stack.
- **(C) Keep the unverified mode, labelled.** `build --lib` stays and prints that its output is outside the
  verified claim; `runs-unproved.allow` gains the link-less path. Recorded for completeness; it keeps the gap
  and only names it.

Recommendation: (B) now, and (A) as a later plan when a consumer exists (FFI from C, or Once-to-Once separate
compilation; a Once module can import only another module's `signature`s today, not its definitions).
