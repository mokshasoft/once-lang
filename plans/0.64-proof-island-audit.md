# Plan 0.64 — the proof-island audit: wire or delete, 82 modules

**Status**: OPEN. Written 2026-08-06, after the D090 branch surfaced two island
clusters by accident (`CataAtRelocate`'s missing import, `StraightTrace`'s silent
catch-all) and one of them turned out to be a stale pointer from a live
postulate.

## Why this plan exists

Two things happened on `plan-0.54-rung-d` that a green tree could not have told
us:

- `IRObsCorrectFlat` named `CataNat*` as `cata-correct`'s discharge on
  2026-06-13. On 2026-06-17 commit `5088e571` deleted two thirds of `CataNat*`
  as "dead — no live importers". The comment kept pointing at the amputated
  route for seven weeks. **Reachability said "dead"; content said "owed".**
- `StraightTrace.StraightIR` let `case` and `curry` fall into a catch-all
  claiming `⊤`. The flip made both FALSE. The module sat there proving a false
  statement, in no cluster, silently.

Neither is a defect in a proof. Both are defects in the *inventory*. This plan
fixes the inventory.

## The rule (do not relax it)

> **The test for deleting an island is CONTENT — does it prove something the
> apex only postulates? — never reachability.** A green backstop is silent
> about an island you deleted, so "nothing broke" is not evidence.

Corollary, learned the hard way: **before deleting, grep the reachable tree for
the module's name.** A comment naming it is a claim someone is relying on, and
deleting the module turns that claim into a lie rather than an error.

## The inventory

Method: transitive imports from the four typecheck roots —
`Once.Certified` (the apex) and `Once.Target.{X86-64,X86-32,RiscV64}` (the three
backend clusters). `Once/Compiler.agda`, the MAlonzo extraction root, is inside
the apex cone, so it adds nothing.

    394 modules under formal/Once/
    312 reachable
     82 ISLANDS  (49 of them imported by nothing at all)

`make check-all` already exists as the rot backstop (it synthesises
`Everything.agda` over the whole tree). It catches *rot*; it cannot catch a
false statement or a stale pointer. That is what the content test is for.

## STEP 0 — the verdicts that need a typecheck first

Deliberately NOT run when this plan was written (the 30s-cap / no-long-runs
rule). Whoever executes a group runs the probe for **that group only**:

    for m in <the group's leaders>; do
      timeout 60 formal/scripts/agda-safe.sh agda MODULE=$m; echo "$m EXIT=$?"
    done

Record green/red per module in the group's table below before deciding
anything. A RED island cannot be wired without repair, and repairing it is only
worth doing if the content test says wire.

# Group B — the abstract-machine IR WF cluster (24). VERDICT: DECIDE. Biggest block.

    IR.{ApplyWF ComposeWF CurryAllocWF CurryStackWF FunctorDispatch
        LambekValidity MuSize MuValidity NatCataProof PairAllocWF

        SumInrAllocWF SumRecWF}

             SizeBoundLemma TraceEvaluator SMPrimitives.Heap
             Memory.TypeSlots ProofObligation

~8,000 lines — by far the largest island block, and the only one where the
answer is genuinely unknown.

**What makes it hard**: these prove `WellFormedF` / `trace-correct` over
`Once.CCC.Eval`'s `exec-trace` — the STRUCTURED machine. The reflex is to call
them fossils of the pre-flatten era. **That reflex is wrong**: `Once.CCC.Eval`
is still REACHABLE from the apex, so the semantics they target is on the
certified path. Whether their content is owed is a real question, not a
formality.

**Known damage, both of which must be fixed together to typecheck any of them**:
1. Plan 0.52 M2 rot (`Type` → `IRTy`, `⟦_⟧T` → `⟦_⟧TI`, `WellFormedF` →
   `WellFormedFI`, `⟦_⟧` → `⟦_⟧ᴵ`).
2. The D089 sweep gave `ClosureWellFormedDef` an `o` parameter. That edit was
   made and then REVERTED on the rung-D branch precisely because it was
   unverifiable while the M2 rot stood.

**Postulate load** (an island that ASSUMES rather than proves is a delete
candidate, not a wire candidate): `SumRecWF` 8, `ComposeWF` 3,
`ProofObligation` 1.

**Do this before any repair** — repair is expensive and must not be speculative:
1. For each of `IRObsCorrectFlat`'s live postulates (`cata-correct`,
   `obs-correct-rest`), ask whether any theorem in this cluster is its content
   *at the flat machine*. Not "resembles" — is convertible-after-porting.
2. If YES for some subset: repair only that subset (both fixes), wire it, delete
   the rest.
3. If NO: the cluster proves things about a semantics nothing downstream
   consumes. Delete it — and in the same commit, correct every comment in
   `ClosureWellFormed`, `IRToTrace`, `Allocation`, `SMPrimitives` and
   `AbstractInstance` that names one of these modules (they all do; see the
   stale-pointer list below).

**Task**: sequence this AFTER the CPU-model definitions (ledger rows #3, #4,

the stub.

# Group E — optimizer correctness (9). VERDICT: DECIDE. A real gap, not a fossil.

    Optimizer.{Cost Depth IRReducible Normal PairCaseNormal}
    Optimize.{Correct Shape}   Fusion   Fusion.Correct

**The finding**: `Once.Optimize` is REACHABLE — the optimizer runs on the
certified path — while `Once.Optimize.Correct` and `Once.Optimize.Shape` are
ISLANDS. The transformation is in the pipeline; its correctness proof is not
wired to it. That is exactly the shape of the bug that once shipped a broken
optimizer observable through a retired-constructor catch-all.

`Optimizer.Normal` carries **13 postulates** and is 1,174 lines — it assumes far
more than it proves, and its header still lists its three key properties as
"to prove". Treat `Optimizer.*` and `Optimize.*` as two different things:

- `Optimize.Correct` / `Optimize.Shape` — about the LIVE optimizer. Content test
  likely passes. **Wire**, or state explicitly in the decision log that the
  optimizer is outside the verified loop (the honest alternative, and the same
  status the resolver once had).
- `Optimizer.*` + `Fusion*` — a separate, older normal-forms development.
  Postulate-heavy, no live consumer. **Delete** unless a specific theorem
  survives the content test.

## Suggested order

1. **Group G** (3 modules) — cheapest, already green, removes the class of bug
   that caused this plan.
2. **Group E, the `Optimize.*` half** — a live subsystem with unwired
   correctness is the highest-risk finding here.
3. **Group C** — one decision, six modules, unblocks a whole subsystem question.
4. **Group F** — mechanical once the name question is resolved.
5. **Group B** — the big one. Do the content test before any repair.
6. **Group D** — only after the CPU-model definitions land.
7. **Group A** — its own rebuild plan; not island work.

## Gate

Every group's commit must state, per module, WHICH test decided it (content or
an explicit subsystem decision) — never "unreachable". A commit that deletes an
island without saying what content test it failed is the thing this plan exists
to prevent.
