# Plan 0.92 — Stop shooting ourselves in the foot with `public`

## 0. The one measurement

    grep -rn 'public$' --include=*.agda formal/Once/ | wc -l     →  345
    files containing at least one                                →  131

Classified:

| kind                                              | count | defensible |
|---------------------------------------------------|-------|------------|
| `open import M <args> … public` (parameterised)    |    31 | MAYBE — see §2 |
| `open import M public` (plain)                     |   136 | no |
| `open <local module> … public`                     |   136 | no |
| other                                              |    42 | case by case |

Progress is that number going down, and NOTHING going red that was green.

## 1. Why — the failure mode, from the incident that opened this plan

Adding TWO lines to `IRObsCorrect/Prelude.agda` broke two modules that had
nothing to do with the change:

* `All`'s `[]` / `_∷_` collided with `Data.List`'s and with `FlatStepsAPI`'s.
* `List` collided with a LOCAL `open import Data.List using (List)` **1600
  lines into `Pair.agda`**, in a `where`-block.

Agda reports `[AmbiguousName]` even though both entries are *literally*
`Agda.Builtin.List.List` — it is two scope entries, not two types. And it
reports them ONE AT A TIME, each behind a full typecheck of everything before
it.

**A `public` name is scoped against every local import in the entire cone.**
There is no way to see that blast radius before making the change, and the
compiler will not enumerate it for you. That is the whole problem: the cost is
paid by modules the author never looked at.

## 2. The ONLY argument for keeping any of them

Not encapsulation. A facade over well-structured modules hides nothing Agda
would have hidden anyway — there is no access control here, and "clients should
not name the members" is a preference, not a property.

The real argument is **instantiation sharing**, and it is measurable rather
than stylistic. A parameterised module applied twice is ELABORATED twice. When
`Prelude o` carries `open import X o public`, clients get the already-applied
names; without it every client re-applies `X o` and pays for its own
instantiation. This project has already been hurt by exactly that — the PairWF2
OOM was nine module instantiations in one `where`-block (2026-05-21).

So the rule to land:

> **Re-export ONLY to avoid re-instantiating a parameterised module. Never to
> hide structure.** And even then, export the TYPE and the lemmas, never the
> CONSTRUCTORS until something actually constructs.

That rule keeps at most the 31, and each of those must JUSTIFY itself with a
measurement, not an assertion — see §4.

## 3. TOP-DOWN ONLY

Same rule as plan 0.91, and for the same reason (D214):

> Change a TYPE — here, a module's export list — never blank a body. Removing a
> name from a `public` list makes every consumer fail AT ITS OWN IMPORT with a
> `[NotInScope]` naming the missing name. That list IS the work-list, and it is
> free. Deleting the module or holing its contents destroys it.

Do NOT pre-emptively add `open import` lines to consumers "so they keep
working". Remove the export, read the red, add exactly the imports the red asks
for. Anything else is guessing at the dependency set.

## 4. Steps

### S0 — Freeze the surface
Add a lint to `formal/scripts/lint-imports.sh` (it exists) that FAILS on a new
`public` outside an allowlist, and seed the allowlist with all 345. Nothing is
fixed yet; the number can now only go down.
*Creates:* the ratchet. Do this first or the count drifts up while the cleanup
runs.

### S1 — The 136 plain `open import M public`
Mechanical and independent per module. For each: delete the `public`, typecheck,
add the imports the red asks for at the sites that asked.
*Expect:* the consumer import lists to get LONGER and more honest. That is the
trade — the dependency becomes visible where it is used.
*Gate:* root green + 746 + 65/0/0 after each batch, not after all of them.

### S2 — The 136 `open <local module> … public`
Same, but these often re-export a module the file itself opened for its own use.
Check whether the consumer wants the module or just two names; prefer naming the
two.

### S3 — The 42 `other`
Read individually. Some will be `renaming`/`hiding` forms that the classifier
did not parse; some may be genuine interface modules.

### S4 — Justify or kill the 31 parameterised ones
Each must show its instantiation-sharing claim is REAL: remove it, and measure
the typecheck time and peak RSS of the cone with and without
(`formal/scripts/agda-safe.sh` reports RSS). If removing it costs nothing
measurable, it was convenience too — kill it.
*Creates:* the honest list of re-exports this project actually needs, with a
number attached to each.

### S5 — Write the rule down
`docs/compiler/` + `MERGE.md`: the §2 rule, the incident that produced it, and
the lint that enforces it.

## 5. GATES

* No step lands with a module red. Batch by batch, not big-bang.
* No behaviour change: 65/0/0 exit tests and 746 `cabal test` at every commit.
  This plan touches NO semantics — a test movement means something is wrong.
* The allowlist in S0 only ever shrinks. A PR that grows it needs the §2
  justification with a measurement.

## 6. Note on sequencing

This is independent of plan 0.91 and can run whenever. It is deliberately NOT
scheduled against it: 0.91 is mid-flight (S3–S5 open, `block-runs` still live),
and a 131-file scope sweep underneath it would make every 0.91 failure
ambiguous.
