# Plan 0.50 follow-up — close the no-clash codegen-faithfulness gap

## The gap (which postulate papered over it)

`assemble-correct` (ArchCorrect, the GNU-`as` trust point) takes `DistinctSymbols m`
as an OPAQUE precondition — never tied to the actual `.globl` labels in the emitted
asm. So `funSymsOf`/`DistinctSymbols` could range over the WRONG set (it did: ALL
`extractFunctions` funNames, including imported PRIMITIVES that are never emitted —
`compileFunWithTarget` skips `cfIsPrimitive`) and the proof + apex stayed green.
Demonstrated: `funSymsOf m = []` would also typecheck. The mismatch only surfaced at
RUNTIME — the guard rejected `arith-simple.once` ("ill-formed top-level definition
name") because it validated imported primitive names too.

## Proper close (typechecker-forced, not hand-asserted)

Define the symbol set THROUGH the codegen's real output so a wrong set is a type error:

1. **Guard → `emittedNames`** (Parser): `extractFunctions` guard checks
   `namesDistinct ∧ allValidIdentB` over NON-PRIMITIVE funNames only
   (`emittedNames = map funName ∘ filter (not ∘ funIsPrimitive)`). Forced by step 4.
2. **`caf-syms` bridge** (the crux, template = `MainIRForm.caf-go-find-form` /
   `AcceptSound.caf-go-sound`): induct on `compileAllFuns-go … ≡ inj₂ cfs` through the
   mutual `caf-go-rf-aux`/`caf-go-cf-aux`/`caf-go-wrap`. `caf-go-wrap` builds
   `mkCompiledFun (bare (funName fi)) … (funIsPrimitive fi)`, so on success cfs are 1:1
   with funs, `cfName = bare ∘ funName`, primitiveness preserved. Conclude
   `emittedSyms cfs ≡ map once-symbol-own (emittedNames funs)`.
   - `emittedSyms : List CompiledFun → List String` = `once-symbol-path ∘ cfName` over
     non-primitive cfs (recursive, matches `compileFunWithTarget`'s emission).
3. **`DistinctSymbols` over the codegen** (NameClash): `DistinctSymbols mod =
   AllPairs _≢_ (moduleSyms Heap false mod)` where `moduleSyms = [inj₁→[], inj₂→emittedSyms]
   (compileResolvedModule …)` — the EXACT cfs `compileFromModule` renders. No
   `extractFunctions` re-derivation.
4. **Re-prove `program-no-clash`**: peel `compileResolvedModule = compileResolvedModule-aux
   (extractFunctions …)`; on inj₂ funs + `compileAllFuns ≡ inj₂ cfs`, use `caf-syms` to
   rewrite `emittedSyms cfs → map once-symbol-own (emittedNames funs)`, then the guard
   evidence (distinct+valid over `emittedNames funs`) + `map-allpairs-own`. The proof now
   REQUIRES the guard be over `emittedNames` (step 1) — that's how the typechecker forces it.
5. Rebuild apex → re-extract (`agda-safe.sh malonzo`) → `cabal build` → confirm
   `arith-simple.once` exits 13 on x86_64.

## Residual trust (narrowed, honest)

`assemble-correct` still trusts "asm's `.globl` labels = `moduleSyms m`" — but
`moduleSyms` is now codegen-DEFINED (via `compileResolvedModule`'s cfs +
`compileAllWithTarget`'s literal `.globl once-symbol-path(cfName)` emission), so this is
a narrow rendering-faithfulness, not the broad "DistinctSymbols means something" gap.
Fully closing it = formalising "labels of the asm String = emittedSyms cfs" (String
parsing); deferred — inherent B2 assembler trust.
