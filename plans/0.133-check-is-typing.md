# Plan 0.133 — `once check` decides the Spec's typing

status: OPEN on branch `check-is-typing` (opened 2026-10-30). Next step: §2 decision (a Spec change), then §3 A;
meanwhile the Spec-free work of §6 and §3 C.

relates: D352 (`Once.Inspect.check`), D115 (admissibility is `build`'s), `Spec.Source._⊢_`,
`Spec.Surface.Program.Denotes`, `Adequacy.AcceptSound.crm-sound`, `Adequacy.ModuleComplete.moduleToIR-complete`,
D353 (its census lists `check` as a gap: §6).

## 1. Why, and what is missing today

`once check` prints "Typecheck OK" when `Inspect.check` accepts: `compileResolvedModule Heap false` succeeds on the
module the import resolver produced. No theorem says what that verdict means.

It is not a gap in the compiler's correctness: the apex is about `compile` (what `build` emits), and `check`
is a tool beside it. It is a gap in what the CLI tells its user, of two kinds:

- **Programs** (a module with `main`): both directions are nearly proved already, for other purposes.
  `crm-sound` turns acceptance into `ModuleTyped m` (the checker's typed telescope); the apex's soundness
  carries a program's acceptance to `src ⊢ tp`; `moduleToIR-complete` gives `compileResolvedModule` success from
  `ModuleTyped` plus a valid `main`. The theorem is mostly assembly.
- **Libraries** (no `main`): the verdict has NO meaning in the Spec. `Spec.Source._⊢_` is defined through
  `Denotes`, whose field `entry` requires `main`; the Spec has no notion of a well-typed module without one.
  `check` accepts libraries anyway, and so does `build --lib`: the apex's `compile` is `nothing` for a module
  without `main` (`Adequacy.Compile.compile-mir`), while the CLI emits library assembly (`emitLibrary`). Library
  output is outside the apex today. This plan fixes the typing half; the compile half is §5.

## 2. Decision needed (a Spec change: needs approval)

Split the Spec's typing of a module from its being a program:

    Module typing    src ⊢ᴹ tm   — the texts parse, the module's signature and definitions are typed
                                    (`Denotes` without `entry`)
    Program typing   src ⊢ tp    — src ⊢ᴹ tm and the telescope has `main` at `Eff Unit Unit` (as today)

`_⊢_` keeps its meaning (the apex statement does not change); `_⊢ᴹ_` is new and is what `check` decides. The
alternative — state `check` only for programs and say nothing about libraries — leaves `check`'s most common use
(a library under development) without a meaning, and leaves §5 with nothing to stand on.

## 3. Steps

**A. Spec.** `Denotes` factors into `ModuleDenotes` (all fields but `entry`) and `Denotes = ModuleDenotes + entry`;
`_⊢ᴹ_` in `Spec.Source`. Every `Denotes` consumer reads through the factoring (no behaviour change). One approved
patch (Spec rule).

**B. Soundness.** `check (resolve src) ≡ inj₂ tt → Σ tm. src ⊢ᴹ tm`, from `crm-sound` and the bridge from
`ModuleTyped` to the Spec's walk (plan 0.81's, which today goes through the program). Generalise the bridge where
it assumes `main`.

**C. Completeness.** `src ⊢ᴹ tm → check (resolve src) ≡ inj₂ tt`: `ce-find-complete` without its `main`
premises (the induction is the same; `findMain` drops out).

**D. On the apex.** `VerifiedInspector` (D352) gains `check-decides` (both directions), stated over `Source`
(parse + resolve, as `compile`), so the Haskell import I/O is the only unproved part, as for `build`.
Arch-free by design: whether a literal fits is `build`'s to refuse (D115), and the theorem says so by not
mentioning `Admissible`.

**E. Closing.** Decision entry + `internal.md` line; `language.md` (what "a module typechecks" means); `check` leaves
the census's gaps (`formal/scripts/ast-compare.py --census`).

## 4. Done when

`once check` accepts a source exactly when the Spec types its module, for programs and libraries, and the apex
carries it.

## 5. Not in this plan

- **Library builds.** With `_⊢ᴹ_`, a correctness statement for `build --lib` becomes statable (the emitted
  definitions behave as the Spec's, at every call from outside). That changes `CorrectCompiler`'s domain — its own
  plan and its own Spec decision; plan 0.89 (relocatable compilation units) is the nearest.
  The user wants this gap closed (2026-10-30); its plan follows this one's §2 decision.
- **Warnings.** `check --target` prints `warningsFor`; their correctness (the reported literal does round) is
  separate; D353 declares the warnings a report (`runs-unproved.allow`).
