# Plan 0.40 — One realm: finish the composition migration, unblock the eff cata

## Where we actually are (read D043 → D044 → D045 first)

The "two realms" worry is mostly already resolved in the log:

- **D043** desugared `compose`/`case`/`pair` at the parser into `λx.f(g x)`
  (closure realm), relying on the optimizer's β/η to fuse back.
- **D044** reversed plan-0.3 G2 and added the **classifier route** — bare +
  applied builtins elaborate to **direct `IR.compose`/`IR.pair` via `spec*`**,
  no optimizer dependency, NT-named diagnostics.
- **D045** removed the parser desugaring **entirely** (`Parser.Inline` empty,
  −891 LoC) and added **`composeArgB`** + `PolyCtx` so the classifier recurses
  into polymorphic bodies without a desugaring fallback.

So the morphism realm is already the composition path, and the optimizer-
dependent closure desugaring is gone. (This *strengthens* with Plan 0.39: the
optimizer turned out unsound, so "no optimizer dependency" was the right call.)

What remains are **residuals** that D044/D045 scoped as future work or that the
effectful path never received — and they are exactly what blocks Plan 0.36's
eff cata `main`. This plan finishes that line (recorded as **D056**), it does
**not** re-open D044/D045.

## The residuals (and how each blocks the cata)

1. **`composeArgB` doesn't handle *value*-typed defs.** It recovers the middle
   type `B` from poly schemas, bare-builtin canonical types, and arrow-typed
   imports — but returns `nothing` for a value-typed name. So
   `compose emitAll xs` with `xs : Mu` (a value, not an arrow) →
   `BuiltinTypeMismatch "compose"`. This is the literal error on the eff cata's
   `main`. Fix: wire **D018's value-lift** into `composeArgB` (a value `v : B`
   used where a morphism is expected is the const morphism `const v : Unit → B`,
   codomain `B`), and into the point-free check-mode path that consumes it.
2. **Eff `compose`/`case` are a *separate, incomplete copy* of the pure path.**
   The pure path is `checkComposeWithB`/`checkComposeWithBg` (classifier +
   `composeArgB` + fuse-or-`spec*`); the eff path is its own clause that only
   fuses (`extract-morph-eff`) with **no fallback**. The IR is **grade-erased**
   (`eff ∘` *is* `pure ∘`), so per **D046** there should be **one grade-poly
   path**, not a pure one and an eff one. Fix: make `checkComposeWithB`/`checkCase`
   grade-polymorphic and route eff through them; delete the bespoke eff clauses.
3. **First-order functions become `curry`-closures.** `seven u = 7` is
   categorically `const 7` (a morphism), but lambda-elaboration emits
   `curry(lit 7)` (a closure), so `arr seven` isn't morphism-realm. `curry`/`apply`
   must stay as **exponentials** (higher-order / partial application — D053
   calling convention), but a *first-order* lambda whose body needs no
   exponential should elaborate as a morphism. Fix (scoped, may be partial):
   prefer the value-as-def form (gap 1) where possible; treat genuine
   first-order-lambda-as-morphism as the deeper, separable item.
4. **(Facet 3 of the eff cata, separate) eff sigop applied in a function body.**
   `emitLeaf n = emit@E n` fails `Eff Unit Unit ≠ Unit` — the `effApp`
   suspension surfacing in a user-function body. This is *not* a realm issue;
   it's the eff-application semantics. Note it; the point-free path (gaps 1–2)
   avoids it, so it is out of scope for unblocking the cata but recorded so the
   `leaftree-emit` style is understood.

## Unblocking the eff cata (the payoff)

With gaps 1 + 2, the eff cata's `main` — point-free, values lifted —
elaborates in the morphism realm:

```
main = compose exit@S (compose 7 (compose emitAll xs))   -- or with explicit arr-lifts
```

`emitAll` fuses `emit` by construction (already landed: qualified externals →
`lift-morphism (SigOp …)`); `exit@S`/`7`/`xs` inject as morphisms via D018 +
`composeArgB`; composition is one grade-poly classifier path. No closure
fallback, no second structure. Then the binary runs: **exit 7, with `emit`
firing in fold order** — runtime-validated via `tests/run-exit-tests.sh`
(`--alloc heap --no-optimize`), per the "formal-green ≠ runtime-correct" lesson.

The property to discharge **by proof** (not assumed from any doc): eff `∘`
**sequences effects in source order** (run `g`, then `f`), against the trace
semantics. That is the load-bearing fact `main` relies on.

## Phasing

- **A — `composeArgB` value-lift (gap 1).** Smallest unblocker; gives the cata's
  `main` its middle types. Validate: the eff cata `main` gets past
  `composeArgB`.
- **B — grade-poly `compose`/`case` (gap 2).** Make `checkComposeWithB`/`checkCase`
  grade-polymorphic; delete the eff clauses; one path. Validate: pure suite
  39/39 unchanged; eff cata `main` elaborates.
- **C — runtime-validate the eff cata.** Build + run; **exit 7**, `emit` order
  correct; add the eff cata test to the suite (un-PEND `list-emit`). Discharge
  the eff-`∘`-sequencing lemma.
- **D — first-order-lambda-as-morphism (gap 3).** Deeper; separable. Only if A+B
  don't already cover the needed value-injection.
- **(facet 3 / gap 4)** tracked separately (eff-application-in-body).
