# Plan 0.148 — Each program on seL4 has its own spaces and its own IPC buffer

## Summary

Several Once programs run together on seL4, but today they trust each other: they share one address
space and one set of capabilities, so a bug in one can damage another. They also pass only a few words
per message. When this plan is done, each program can touch only its own memory and the capabilities
it was given, and a program can send a whole message.

## 1. Why

Isolation is what seL4 is for, and the examples do not use it yet. The message limit is a second gap:
a started program has no IPC buffer, so it can send and receive only the words that fit in registers.
This plan waits for buffers in Once itself, because a message longer than the registers needs a value
to hold it.

## 2. Where we are

Checked 2026-11-08 on branch `0.125-nixpkgs`.

- `Strata/Hosts/SeL4/Host.<arch>`: an image holds at most four programs, each with a 1 MiB region in
  the root task's address space.
- `examples/seL4/Echo/Root.once`: every thread is configured with the root task's CNode and VSpace and
  no IPC buffer.
- Register words for a started program: four on x86_64 and riscv64, two on x86_32. The root task has a
  buffer. It sends all four words of `seL4_Send` and `seL4_Call` on every architecture.
- On x86_32 the root task's words 2 and 3 go through the IPC buffer (`once_sel4_ipc_buffer` in
  `Host.x86_32`). No test exercises that path.
- An object invocation (`once_sel4_invoke`) needs the root task's buffer, so only the root task can
  invoke kernel objects.
- `once_sel4_self` finds the calling program from its stack pointer, which assumes the shared address
  space.
- The Host's regions are per-program `.bss` in one ELF. Separate address spaces need the root task to
  map frames for each program.

## 3. Decisions

1. Open: how a message longer than the registers looks in Once, once Once has buffers.
2. Open: what a program may do with objects. Recommendation: keep invocations in the root task until
   a program has a buffer, then let a program invoke what it holds.
3. Open: a CNode per program first, a VSpace per program second, or both at once. Recommendation:
   CNode first, because it is smaller and needs no frame mapping.

## 4. Steps

1. Give each started program an IPC buffer frame, mapped and named in its TCB. Check: a test sends more
   words than fit in registers, on every architecture, and exercises x86_32's words 2 and 3.
2. Give each program its own CNode holding only the capabilities it needs. Check: a program that names
   a capability it was not given gets a capability fault, delivered to its monitor.
3. Give each program its own VSpace, with frames mapped by the root task. `once_sel4_self` and the
   per-program tables become per-address-space. Check: a program that writes outside its memory gets a
   VM fault, delivered to its monitor.

## 5. Done when

The echo example runs with each program in its own CNode and VSpace, a program sends a message longer
than the registers, and the isolation tests in step 2 and 3 pass on every architecture.
