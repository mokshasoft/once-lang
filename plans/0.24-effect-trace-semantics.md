# Plan 0.24: Effect-trace semantics — define `⟦_⟧` so "correct" means something

## The gap (why this plan exists)

`Once.Verified.Compile.correct` claims `exec arch bytes ≡ ⟦ src ⟧`. But
`⟦_⟧ : Source → Behavior` is a **postulate** (`Once/Verified/Behavior.agda:113`),
so the grand theorem is currently a *well-shaped shell*: it compares the
compiled program against an **undefined** specification. The compiler
*runs* and emits correct binaries operationally, but it is **not yet a
*verified* compiler**, because "verified against what?" has no answer.

This plan defines that answer.

### Why exit-code is the wrong observable

`Behavior` is presently `Maybe ℕ` — the argument of the final
`linux.exit` SigOp. This is a deliberately coarse Layer-0 projection,
and it fails as a general definition of correctness:

- It collapses **every** program that exits `0` to "the same behaviour"
  — no distinction between programs with completely different effects.
- A **productive non-terminating** program (e.g. a webserver) never
  calls `linux.exit`, so its behaviour is `nothing` — **no correctness
  statement exists for it at all.**

`Behavior.agda` already names the right answer (its "option (a)") and
defers it: the observable is the **SigOp effect trace** — the sequence
of SigOp calls and their arguments — of which the exit code is just a
finite projection (`Behavior.agda:62–70`). The memory note
`feedback_programs_dont_return` and the boxed preamble
(`Behavior.agda:7–55`) make the framing canonical: **compiler
correctness is TRACE PRESERVATION**; *what each SigOp does* is the
separate interpretation layer's job.

### Why it must be coinductive

A reactive program's trace is **infinite**. The CCC IR already has the
coinductive machinery that lets such programs exist (`ν-type`, the
`CoIn`/`CoOut` / `Ana` schemes — OCP-0003, `docs/design/categorical-foundations.md`,
`docs/design/time.md`). So the trace denotation that *observes* them must
be coinductive too. This is exactly what `Behavior.agda:105–110` means by
"a richer effect-tracking interpreter (free monad over SigOp) —
substantive new work." This plan is that work.

## What already exists (build on, don't reinvent)

- **The CCC IR is mathematically defined and self-describing**:
  `SigOp : SigOpInfo A B → IR A B` (`CCC/IR.agda:277`) — every effect
  node carries its name + `semI`/`semM`.
- **A value-level structural evaluator**: `eval : IR A B → ⟦A⟧ → ⟦B⟧`
  (`CCC/Eval.agda`), with `eval (SigOp si) x = semM si x`. It is fully
  structural over the IR but *discards* the "this was a SigOp call"
  event — that is precisely the information the trace semantics must
  keep.
- **Coinductive IR infrastructure** (`ν-type`, `Ana`/`CoIn`/`CoOut`)
  for reactive programs.
- **Trace-construction groundwork** for codegen: `instr-sigop` +
  per-arch dispatch (Plan 0.10 Phase B'). That is the *codegen* trace
  (instruction lowering); this plan is the *denotational* trace (the
  spec). They meet in `module-to-asm-correct`.

So the spec is ~structurally read off the IR. The genuinely new piece
is the **effect-recording reinterpretation of arrows + coinduction**:
the current Core semantics interprets `⟦ A ⇒[ eff ] B ⟧ = ⟦A⟧ → ⟦B⟧`
(effects invisible); the trace semantics interprets effectful
computations in a **free monad / resumption over SigOps**.

## Goal

Replace the `⟦_⟧` postulate with a real **coinductive SigOp-trace
denotation** of the source program, making `correct` a genuine
trace-preservation statement that is meaningful for terminating *and*
reactive programs. Exit-code becomes a projection, not the definition.

User-observable signals:

1. `Once/Verified/Behavior.agda` has **no `postulate ⟦_⟧`**: `⟦_⟧` is a
   real definition (the trace denotation of the elaborated source).
2. `Behavior` is the (coinductive) trace; `exitCode : Behavior → Maybe ℕ`
   is the Layer-0 projection (so existing Layer-0 tests still phrase
   their expectation as an exit code).
3. `correct` (`Verified.Compile`) is re-stated as trace preservation;
   the per-stage lemmas (`gmoduleToModule-correct`, `module-to-asm-correct`)
   are about traces.
4. The Layer-0 fragment (programs whose only SigOp is `linux.exit`)
   gets a *finite, total* trace and a discharged `⟦_⟧` end-to-end.

Non-goals: discharging `module-to-asm-correct` (the grand
trace-preservation theorem — gated by the open T0 obstacle, its own
plan); the in-Agda assembler (assembler stays in the TCB per decision);
defining the *interpretation* of each SigOp (what `linux.exit` *does* —
separate per-impl, per `Behavior.agda`'s compiler/interpretation split).

## Design

### D-trace-1: `SigOpEvent` and the trace type

```agda
record SigOpEvent : Set where
  field name : String
        -- the argument value handed to the SigOp at the call site
        arg  : Σ Type ⟦_⟧        -- (or a serialised/observable form)
```

The trace is a **resumption / free monad over SigOps**, coinductive so
reactive programs are representable:

```agda
-- codata (sized or --guardedness)
data/codata Eff (A : Set) : Set where
  ret  : A → Eff A
  call : (si : SigOpInfo D R) → ⟦ D ⟧ → (⟦ R ⟧ → ∞ (Eff A)) → Eff A
```

`call` records the event *and* its continuation (so SigOps that return
data — `linux.read` — drive subsequent control flow; the trace is a
*tree* indexed by responses, linear when there is no input). The
**observable** is the event projection of `Eff` (a `Colist SigOpEvent`,
or bisimilarity on `Eff`).

`Behavior := Eff ⊤` (for `main : Eff Unit Unit`), with:
```agda
exitCode : Behavior → Maybe ℕ   -- find the linux.exit event's argument
```

### D-trace-2: the trace denotation of the IR

```agda
⟦_⟧tr : IR A B → ⟦ A ⟧ → Eff ⟦ B ⟧
```

Structural, reusing `eval`'s shape, but:
- `⟦ SigOp si ⟧tr x = call si x (λ r → ♯ ret r)` — **record the event.**
- `⟦ g ∘ f ⟧tr x = ⟦ f ⟧tr x >>=Eff λ y → ⟦ g ⟧tr y` — sequence (monadic
  bind on `Eff`).
- pure structure (`id`, `fst`, `pair`, `inl/inr`, `case`, `terminal`,
  `Cata`, …): thread `Eff` through; no events.
- `ν`/`Ana`/`CoIn`: **corecursive** — produces a productive (possibly
  infinite) `Eff`. This is the coinductive heart.

`⟦ src ⟧ := ⟦ elaborate src ⟧tr tt` (the trace denotation of the
elaborated source's IR). Discharges the `Behavior.agda` postulate.

### D-trace-3: trace equality is bisimilarity

Propositional `≡` on coinductive `Eff` is too strong for infinite
traces. Define `_≈_ : Eff A → Eff A → Set` (bisimilarity). `correct`
and the per-stage lemmas are stated up to `≈`. For the finite Layer-0
fragment, `≈` collapses to `≡`.

### D-trace-4: Layer-0 stays finite + total

Layer-0 programs call only `linux.exit` and terminate, so `⟦ src ⟧` is a
*finite* `Eff` (`call linux.exit n (ret tt)` essentially). The
coinductive type accommodates them with no productivity obligation, and
`exitCode ⟦ src ⟧ = just n`. This is what lets the discharge land for
**today's** programs before the reactive machinery is exercised.

## Phases

### Phase A — `Eff` / `SigOpEvent` / `exitCode`
Define the (coinductive) trace type, the event projection, and
`exitCode`. New module `Once/Verified/Trace.agda`. Decide the
coinduction mechanism (sized types vs `--guardedness`) consistent with
the IR's existing `ν` machinery.

### Phase B — `⟦_⟧tr` over the IR (the substantive piece)
Define the trace denotation structurally over `IR`. Inductive
constructors first (id/∘/products/sums/`Cata` — covers all of Layer 0);
then the coinductive ones (`ν`/`Ana`). `>>=Eff` (monadic bind) is the
sequencing combinator. Reuse `Once.Semantics.Core` for the value parts.

### Phase C — re-anchor `Behavior` + discharge `⟦_⟧`
`Behavior := Eff ⊤`; `⟦_⟧ := ⟦ elaborate _ ⟧tr tt`; remove the
postulate in `Behavior.agda`. Provide `exitCode` so Layer-0 specs are
unchanged in spirit.

### Phase D — re-state `correct` as trace preservation
Update `Verified.Compile`: `correct` and the per-stage lemmas
(`gmoduleToModule-correct`, `module-to-asm-correct`) phrased as `≈` on
traces. `module-to-asm-correct` stays postulated (the grand theorem),
but now it is the *honest* trace-preservation obligation.

### Phase E — Layer-0 end-to-end check
For the arith/exit test programs, show `⟦ src ⟧` computes the expected
finite trace and `exitCode ⟦ src ⟧ = just n`. Confirms the discharge is
non-vacuous for real programs.

## Risks / open questions

1. **Coinduction mechanism.** Sized types vs `--guardedness`; must
   match the IR's `ν` infrastructure and stay `--safe`-compatible.
   Phase A decides.
2. **`>>=Eff` productivity.** Monadic bind on a coinductive resumption
   must be productive (guarded). Standard (interaction-trees style) but
   needs care in Agda.
3. **Event argument representation.** `arg : Σ Type ⟦_⟧` is heavy;
   a flattened/serialised observable form may be cleaner for `≈`.
4. **`elaborate` reuse.** `⟦ src ⟧` routes through the existing
   elaboration (GModule → IR). Ensure no circular dependency with
   `Verified.Compile` (elaboration already exists in the front end).
5. **Relation to `gmoduleToModule-correct`.** With trace semantics
   defined, this becomes "elaboration commutes with the GModule→Module
   conversion ⇒ equal traces" — likely the next dischargeable proof
   after this plan (its own follow-up).

## Why this is the right next step

- It is the **one thing that makes `correct` non-vacuous** — without a
  defined `⟦_⟧`, every downstream proof compares against nothing.
- It is **independent of the hard T0 blocker** (that gates the
  *proof* `module-to-asm-correct`, not the *definition* of the spec).
- It captures **reactive/non-terminating** programs, which exit-code
  semantics structurally cannot — the correct general notion of "what a
  Once program does."
