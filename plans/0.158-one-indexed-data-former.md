# Plan 0.158 — One indexed data former, shared by the Spec and the dependent kernel

## Summary

Once lets a program declare its own data types: lists, trees, syntax trees. Some of these come in
groups that refer to each other, such as a tree and the list of its subtrees. Today the plan for
such groups (plan 0.147) encodes them through a mathematical trick (Bekić's lemma), and the
dependent-type work on the POC line does something different: it treats a group as one family
with a "which member" index. This plan makes both lines use one and the same construct, the one
mathematicians use as the definition of a data type: a family of types indexed by a set of sorts.
Programs keep writing ordinary `data` declarations. Mutual types become first-class, nested types
keep sharing the library functions of the types they nest (the children of a tree stay a real
list), the compiled code and memory layout do not change, and dependent types later extend this
construct instead of adding a second one.

## 1. Why

- **Two designs for one thing.** Plan 0.147 §3.4 decides G1 (nested positive occurrences,
  `data Rose a = Node a (List (Rose a))`) and G3 (mutual declarations) "as surface sugar over G1: by
  Bekić's lemma a mutual fixed point is a nested one". The DT kernel makes a mutual group ONE family
  indexed by sort (D494, `Lib/Sorted`, `Examples/Mutual`, green). The two lines must merge
  (`POC/DirectedHoTT/MASTER-DT-ABSTRACTIONS.md`), so one of them moves.
- **A claim in plan 0.147 is false today.** §3.4.1 says G1 is "designed as a fragment of the DT
  kernel's `Desc`". The DT kernel's descriptions cannot apply a declared type to the recursive
  position: a recursive field `dρ j C` names an INDEX, never a family
  (`POC/DirectedHoTT/Spec/Syntax.agda:180-182`). So nesting has no image in the kernel yet.
- **The erasure stance makes master's grammar the target.** The DT kernel keeps no run-time
  information (MASTER-DT-ABSTRACTIONS §0): its data erase to master's data. Master's data grammar
  should therefore be exactly the erasable part of the kernel's descriptions, stated as a theorem, not
  a separate design that happens to agree.

## 3. The Spec change, three ways

### 3.1 Through a category theorist's eyes

- A data type is the initial algebra of a polynomial functor. A MUTUAL group of `k` types is the
  initial algebra of a polynomial endofunctor on `Set^k`, the category of `k`-sorted families:
  `F : Set^k → Set^k`, `μF : Set^k`, and type `j` of the group is `(μF) j`. Presenting `F` by its
  fibres, one functor code per sort, is the definition (Gambino–Kock's polynomial functors
  `I ← B → A → I`, read fibrewise). The single-sorted `μ` of today is the case `k = 1`.
- **Bekić's lemma becomes a theorem about the former**, not an encoding: the `k`-sorted fixed point
  agrees with the iterated single-sorted one. Today's 0.147 design builds the mutual type BY the
  lemma; here the lemma relates two presentations of one object.
- **Nesting is composition.** `List (Rose a)` is the field `List ∘ X`: polynomial functors are
  closed under composition, and a parameterised initial algebra `μY. 1 + X × Y` is a functor in `X`,
  strictly positive. A nested field needs one fact about the inner type: it is covariant in the
  parameter that carries the recursive position. That fact is the ONE polarity judgment of plan
  0.147's Types patch (§3.4.1, §6.1; the DT kernel's `Pos`), which also decides where `mapᶜ` exists
  and why arrows are contravariant in `Spec/Sub`. The fold over a nested field uses `mapᶜ` exactly
  where the judgment says the parameter is covariant.
- Nothing else changes: `ν` is the dual (final coalgebras on `Set^k`), and folds and unfolds keep
  their universal properties, now sorted.

A categorist would prefer this to the old Spec: one definition instead of a single-sorted former
plus an encoding, the encoding as a theorem, and the same definition the dependent kernel uses
with richer indices.

### 3.2 For the programmer

```
data Tree a   = Node a (Forest a)          -- a mutual group: both types are first-class
data Forest a = Nil | Cons (Tree a) (Forest a)

size  : Tree a -> Nat                      -- a mutual function group, one sorted fold
size  (Node _ f)  = 1 + sizeF f
sizeF : Forest a -> Nat
sizeF Nil         = 0
sizeF (Cons t f)  = size t + sizeF f

data Rose a = Node a (List (Rose a))       -- nesting: the children ARE a List
count : Rose a -> Nat
count (Node _ cs) = 1 + sum (map count cs) -- List's own `sum` and `map` apply
```

- **What is new to write.** Nothing at the surface beyond 0.147: `data`, `match`, mutual groups and
  nested positions are 0.147's surface (§3.2, §3.3).
- **What is easier.** `Forest a` is a type in its own right: it is printed as `Forest a`, has its
  own constructors, and functions over it are written and exported like any other (under Bekić it is
  a component of `Tree`'s functor). Error messages name the types the programmer declared.
- **Abstraction power.** One fold per group; generic structure (`==`, `map`, derived order, 0.147
  §3.5) is defined once over sorted codes and works for single, mutual and nested types alike. Under
  dependent types the same former gains value and type indices (GADTs, `Vec a n`), so nothing a
  program writes now is redone then.

### 3.3 At run time

- **Layout: unchanged.** A value of sort `j` is a value of `(μF) j`; its cells are the constructors
  of sort `j`, as under Bekić. A sort index is static at every use (`Tree a` is always `Tree a`), so
  it costs no tag and no word. Plan 0.138's one tag word per constructor stands.
- **Heap allocations: unchanged.** The same constructors are allocated.
- **Folds: one specialised body per sort.** The sorted fold dispatches on a statically known sort;
  codegen must specialise it per sort at compile time (a known `case` on a constant), or it pays a
  run-time `case`. With specialisation, the code is what a hand-written mutual group compiles to.
- **Code size.** Equal to the mutual group's functions. Nesting by composition REUSES the inner
  type's compiled functions (`map` on `List` is one body); the alternative (§4 D2 (b)) would copy them
  per instance.
- **`LinCore`.** `LF` gains a sort index on `Idf` (the recursive position at sort `j`) and `μt` a sort;
  `lcata` takes one algebra per sort. The comonoid and the lent context are unaffected. Measured
  before and after with plan 0.130's instrumentation and the perf comparison of plan 0.146.

### 3.4 Alignment with the dependent kernel

- Master's indices are finite sorts. The kernel's are codes in the context (D492), fibred (D493).
  Restricted to a finite sort index whose fibre function is a case on the sort (D494–D496), the
  kernel's descriptions ARE master's sorted codes, up to `dσ` over a finite tag being `⊕` and a
  non-dependent `dσ` being `⊗`/`K`.
- **Erasure.** A kernel family whose index is erased erases to master's codes by the case-tree rule
  (MASTER-DT-ABSTRACTIONS §5): the erased type is the tagged union of the fibres. A sort index closed
  at every use erases to the sort. So master's grammar is the erasure image, as a theorem (§5 step 7).
- **The DT kernel owes a nesting former** (D2 (a)): a description field of a declared family applied
  to the recursive family, with `Pos` as its premise. That is DT-side work, tracked in
  `POC/DirectedHoTT/` (PLAN-GRADED or its own plan), not here.

## 4. Decisions

- **D1. Mutual types: a sorted former (recommended) or Bekić over G1 (0.147 §3.4.2).** Recommended:
  the sorted former. It is the definition (§3.1), it is what the kernel does (D494), every member is
  first-class (§3.2), and Bekić becomes a validating theorem. Cost: the indexing touches every
  recursion over `Fun`; G1 touches all of them anyway, so doing both in one patch pays the cost once.
  Open (the user).
- **D2. Nesting: (a) native composition (recommended) or (b) nested elaborated to mutual.** (b)
  turns `List (Rose a)` into a fresh sort `Forest a`: no nesting former anywhere, but `List`'s
  functions no longer apply to the children (each needs a copy, more code, or a conversion that is
  free only when layouts agree). (a) keeps the children a `List`, and needs a nesting former in the
  kernel (§3.4). Recommended: (a), for the programmer and for code size. Open (the user).
- **D3. Master's index: finite sorts only (recommended).** Type and value indices (GADTs, indexed
  families) need equality refinement in `match`, which is what dependent types provide; they stay in
  0.147 §4. Open (the user).
- **D4. Codata: sorted ν as well (recommended).** `ν` is defined over `Fun` too; sorting both keeps the
  grammar one, and mutual codata (two interleaved streams, a server and its sub-servers) comes for free.
  Open (the user).

## 5. Steps

1. **Measure.** Every recursion over `Fun` and `LF` (Spec, Metatheory, `mapᶜ`, the fold proofs, Core
   typing of μ, `LinCore`, the cata codegen tiers): list and count them. Which Strata and example
   types are mutual or nested today, and how they are encoded. Record in §2.
2. **Spec patch: sorted codes** (user approval). `Fun m k` with the recursive position `Id j`
   (`j : Fin k`); `μ` and `ν` take a sort family of codes and a sort; `⟦_⟧F` over `k`-sorted families;
   `WFFun`. `k = 1` is today's grammar, so existing types elaborate unchanged.
3. **Follow the red.** Metatheory, `mapᶜ`, the fold proofs, the core typing of introduction and
   elimination, the meaning. Gate: `formal/scripts/agda-safe.sh certified`.
4. **Bekić as a theorem.** The `k`-sorted fixed point is isomorphic to the iterated single-sorted one,
   with the folds commuting. It validates the patch against 0.147's encoding and is the bridge for any
   code written against it meanwhile.
5. **Nesting (G1) on the sorted grammar**, per D2: a field `Ap T F` (a declared type applied to a code
   that mentions the recursive positions). Its premise is the polarity judgment of plan 0.147's Types
   patch, which therefore lands first. 0.147 §7 step 4
   becomes this plan's steps 2–5.
6. **`LinCore` and codegen.** Sorted `LF` and `lcata`, per-sort specialisation, `NoLeak` re-checked.
   Measure code size, allocations and run time on mutual and nested examples (plan 0.130; plan 0.146's
   perf comparison). Done when equal to the Bekić encoding or better.
7. **The alignment statement.** In `POC/DirectedHoTT/`: master's sorted codes as the image of the
   kernel's erasure on finite-sort, case-tree descriptions. A theorem on the DT side; master's side is
   unchanged by it.
