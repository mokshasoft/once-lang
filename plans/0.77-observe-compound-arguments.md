# Plan 0.77 — Observe COMPOUND SigOp Arguments (discharge `decode-unread`)

**Decision:** D114. **Status:** plan (2026-08-30), not started.
**Residual:** `Once.Adequacy.FlatEvents.decode-unread`.

    signature print : Eff (String) Unit

    print "hello"   and   print "goodbye"

still have the same `Behavior` *as far as the correspondence proves it*. The
spec-side observable no longer narrows — D114 fixed that — but the MACHINE side
cannot yet READ a compound argument off the machine, so the equality between
the two sides is postulated for those shapes.

---

## 0. What is actually open

`FlatEvents.decode-arg` reads a SigOp's argument at its own base type:

```agda
decode-arg : ∀ {A} → IsBaseType A → StoredValue FS → ⟦ A ⟧
decode-arg base-Int   (SV-Lit fits-int   v) = v
decode-arg base-Float (SV-Lit fits-float v) = v
decode-arg b          sv                    = decode-unread b sv
```

The two real clauses are the SCALAR ones, and they are why `exit@S n` and
`emitF x` are genuinely observable. Everything else — `String`, `Buffer`,
`_*_`, `_+_` — falls into the postulate.

The reason is structural, not a proof fight: a scalar argument sits IN
`Input1`, so the machine reads it off a register. A compound one does not; the
register holds a POINTER, and recovering the value is a HEAP WALK.

**Classification:** deferred-proof, not an axiom. It is a hole in what we can
prove about arguments the compiler already passes correctly in practice; it is
not a claim about the world that could be false.

## 1. Why this is a heap-model plan, not a front-end one

The reader already exists — `SMCore.readTyped` — and it is already related to
the memory model by `ReadTypedAdequate.readTyped-adequate`:

```agda
readTyped : (A : Type) → ValueLocation FS → LocState FS → Maybe ⟦ A ⟧
readTyped Unit    loc s = just tt
readTyped Int     loc s = readTyped-int (readLoc s loc)
readTyped (A * B) loc s = readTyped-pair … (readLoc s loc) (readLoc s (sucLoc loc))
readTyped _       loc s = nothing          -- ← Float, Str, Buffer, sums
```

So the work is in three parts, in this order, and the FIRST one is where the
design risk is:

- **A. Widen `readTyped`** past `Unit`/`Int`/`_*_`. `Float` should be the same
  shape as `Int` (it is a scalar in a register — check whether it belongs in
  `decode-arg`'s scalar clauses instead, in which case it never reaches here).
  `_+_` needs the tag discipline; `Str`/`Buffer` need the pointer-to-payload
  walk, which is the real content.
- **B. Extend `readTyped-adequate`** to the new cases — `Readable` gains
  constructors and each needs its `ValidAtWF` premise to materialise the value.
- **C. Replace `decode-unread`** with `readTyped` at the SigOp's base type, and
  prove the source/machine agreement for the widened shapes.

## 2. The two questions to answer BEFORE writing code

**Q1 — is `Str` a value or a location in `⟦_⟧`?** `decode-arg`'s codomain is
`⟦ A ⟧`, the observable's value domain. If `⟦ Str ⟧` is already "the bytes",
the walk has to produce them and the plan is a real heap read. If it is a
pointer, then `print "hello"` vs `print "goodbye"` is observable only if the
POINTED-TO bytes are, and the observable itself needs a decision first — in
which case this plan starts with a D-entry, not with Agda.

**Q2 — which `FrameSemantics` instances must support the walk?** `decode-arg`
is `{FS : FrameSemantics}`-generic. If the walk needs facts only heap-mode
supplies, the widened clauses are conditional on the instance and the plan must
say what stack-mode observes instead.

Answer Q1 and Q2 first. If Q1's answer is "the observable needs a decision",
STOP and write it — the D114 lesson is that shaping an observable to fit a
proof is exactly the failure this residual replaced.

## 3. Gate

`decode-unread` disappears from `make postulates`, and a test asserts what the
whole plan is for:

    print "hello"   and   print "goodbye"   have DIFFERENT Behaviors

as a trace-level test on all three arches, the way `FloatEmitSpec` reads
arithmetic results back out of the effect trace today.

## 4. Relation to other plans

- **0.76** is independent — it is a front-end/typing redesign and touches
  nothing here.
- The heap-mode Layer 2 work (`readTyped`'s neighbourhood, `AllocWF`,
  `ValidAtWF`) is the layer this plan builds on; check its state before
  starting, since part B lands squarely in it.
